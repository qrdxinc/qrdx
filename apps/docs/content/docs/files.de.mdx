Gehostete Seiten können Dateien zeigen, die du zu QRdx hochlädst: eine Speisekarte oder Broschüre als PDF, eine Fotogalerie, Musik oder einen Podcast oder ein Video. Hochgeladene Dateien findest du in der Seitenleiste unter **Dateien**. Sie gehören zu dem Workspace, in dem du sie hochlädst, und jede hat einen stabilen Link, der weiterhin funktioniert, wenn du die Datei ersetzt. Nutze sie, wenn die Datei sonst nirgends liegt oder wenn du zum Beispiel die Speisekarte der nächsten Saison austauschen willst, ohne die Seite anzufassen.

<Callout type="info" title="Tarife">
  Kostenlos enthält 50 MB Speicher pro Workspace mit Dateien bis 10 MB; Pro 5 GB und 100 MB; Business 50 GB und 250 MB. Siehe [Tarife und Limits](/docs/plans-and-limits).
</Callout>

## So funktioniert es [#how-it-works]

<Diagram id="file-delivery" />

Dein Browser lädt die Datei direkt in den Storage-Bucket hoch. Danach prüft QRdx sie (ihre Größe und ob die ersten Bytes wirklich zu einer Datei dieses Typs gehören), kopiert die geprüfte Version an den eigenen Speicherort der Datei und vergibt einen Link: `https://qrdx.dev/api/files/<id>`. Seiten und Codes verwenden diesen Link, deshalb ändert sich für sie nichts, wenn du die Datei ersetzt.

## Was du hochladen kannst [#what-you-can-upload]

| Art | Formate |
| --- | --- |
| PDF | PDF |
| Bilder | JPEG, PNG, WebP, GIF, AVIF |
| Audio | MP3, M4A, AAC, Ogg, WAV |
| Video | MP4, WebM, MOV |

MP4 mit H.264-Video läuft in jedem Browser. MOV-Dateien von Smartphones lassen sich meist auch abspielen, konvertiere sie aber in MP4, wenn ein Browser sie nicht abspielen kann. SVG, HTML, Archive und Office-Dokumente können nicht hochgeladen werden, damit nichts, was aus dem Speicher ausgeliefert wird, im Browser eines Besuchers Code ausführen kann.

Jeder Upload wird vor der Verwendung geprüft: Seine Größe muss der angekündigten entsprechen, und seine ersten Bytes müssen wirklich zu einer Datei dieses Typs gehören (eine HTML-Seite, die in `.pdf` umbenannt wurde, wird abgelehnt). Abgelehnte Uploads werden aus dem Speicher gelöscht und als **Blockiert** aufgeführt.

## Dateien auf einer Seite verwenden [#use-files-on-a-page]

Fünf Blöcke zeigen Dateien. Jeder kann eine hochgeladene Datei oder einen Link zu einer woanders gehosteten Datei verwenden:

- **PDF** zeigt ein hochgeladenes Dokument auf Tablets und Computern direkt auf der Seite an, mit **PDF öffnen** (auf Smartphones ein Vollbild-Viewer) und einem optionalen Download-Button. Ein PDF, das von einer anderen Website verlinkt ist, bekommt den Button **PDF öffnen**.
- **Galerie** zeigt Fotos in einem Raster mit 1 bis 3 Spalten. Tippen auf ein Foto öffnet es im Vollbild; wische oder nutze die Pfeiltasten zum Blättern.
- **Audio** spielt Titel mit Cover und Playlist ab; wenn ein Titel endet, startet der nächste. Ein Download-Button ist optional.
- **Videodatei** spielt ein hochgeladenes MP4 oder WebM ab, optional stumm und als Schleife wie ein GIF. Für YouTube, Vimeo oder Loom nutze stattdessen den Block **Video**: Er bettet das Video ein und lädt nichts von der Videoseite, bevor jemand auf Play tippt.
- **Downloads** listet Dateien auf, die Leute speichern können, jede mit eigener Beschriftung.

Die Seitentypen **PDF**, **Bilder**, **MP3 / Audio**, **Video** und **Playlist** unter **Neuer Code** starten mit diesen bereits eingesetzten Blöcken.

Wähle in einem Block **Hochladen**, um eine Datei von deinem Gerät hinzuzufügen, **Aus deinen Dateien**, um eine früher hochgeladene Datei wiederzuverwenden, oder füge einen Link ein.

## Datei ersetzen oder löschen [#replace-or-delete-a-file]

Öffne **Dateien** in der Seitenleiste und nutze das Menü neben einer Datei:

- **Link kopieren** kopiert den eigenen Link der Datei (`https://qrdx.dev/api/files/<id>`). Du kannst ihn auch als Ziel eines dynamischen QR-Codes verwenden.
- **Datei ersetzen…** lädt neuen Inhalt hinter demselben Link hoch, zum Beispiel die Speisekarte der nächsten Saison. Seiten und Codes, die die Datei verwenden, zeigen die neue Version innerhalb einer Minute. Eine Datei kann nur durch eine Datei derselben Art ersetzt werden (ein PDF durch ein PDF).
- **Löschen** entfernt die Datei endgültig. Wenn noch Seiten oder Codes sie verwenden, listet QRdx sie vorher auf; nach dem Löschen zeigen diese Seiten „Datei nicht verfügbar“ an der Stelle der Datei.

<Shot id="files-page" />

Mitglieder können die Dateien ersetzen und löschen, die sie selbst hochgeladen haben; Inhaber und Admins können alle Dateien im Workspace verwalten.

## Gemeldete Dateien [#reported-files]

Jede gehostete Seite hat einen Link **Missbrauch melden**. Wenn eine Datei gegen die Regeln verstößt oder ein Urheberrechtsinhaber ihre Entfernung verlangt, kann QRdx sie sperren. Eine gesperrte Datei wird innerhalb einer Minute auf jeder Seite und über ihren QRdx-Link nicht mehr ausgeliefert (Seiten zeigen „Datei nicht verfügbar“), und identische Kopien (bis 25 MB) können nicht erneut hochgeladen werden.

## Limits und Tarife [#limits-and-plans]

| Tarif | Speicher pro Workspace | Größte Datei |
| --- | --- | --- |
| Kostenlos | 50 MB | 10 MB |
| Pro | 5 GB | 100 MB |
| Business | 50 GB | 250 MB |

Ein Workspace nutzt den besten Tarif unter seinen Inhabern und Abrechnungsmitgliedern. Limits stoppen nur neue Uploads: Nach einem Downgrade oder wenn ein Workspace über seinem Speicherlimit liegt, wird jede bereits hochgeladene Datei weiterhin auf jeder Seite ausgeliefert, die sie verwendet. Lösche nicht mehr benötigte Dateien (oder wechsle auf einen höheren Tarif), um neue hochzuladen. Ein Upload, der nie abgeschlossen wird, zählt nach zwei Stunden nicht mehr zum Speicher.

## Für Entwickler [#for-developers]

Dateien werden im Dashboard hochgeladen und verwaltet. Auf der API-Seite kann das Design eines Codes ein hochgeladenes Logo über seine Datei-ID verwenden: siehe [Logos im Stil eines Codes](/docs/developers/rest-api#code-logos).

## Speicher einrichten (Self-Hosting) [#set-up-storage-self-hosting]

Datei-Uploads nutzen [Cloudflare R2](https://developers.cloudflare.com/r2/). Ohne R2 meldet die Seite „Dateien“, dass Uploads nicht verfügbar sind, die Upload-API antwortet mit `503` und „Storage not configured on this server.“, die fünf Upload-Seitentypen werden in der Auswahl ausgeblendet, und Blöcke können weiterhin Links zu woanders gehosteten Dateien verwenden.

1. Öffne im Cloudflare-Dashboard **R2** und erstelle einen Bucket, zum Beispiel `qrdx-files`.
2. Erstelle unter **R2** → **Manage API tokens** ein Token mit **Object Read & Write** für diesen Bucket.
3. Setze diese Umgebungsvariablen und starte neu:

   ```bash title="apps/app/.env.local"
   R2_ACCOUNT_ID=your-cloudflare-account-id
   R2_ACCESS_KEY_ID=token-access-key-id
   R2_SECRET_ACCESS_KEY=token-secret-access-key
   R2_BUCKET=qrdx-files
   # Optional: serve files from a public bucket URL or custom domain
   R2_PUBLIC_BASE_URL=https://files.example.com
   ```

4. Füge dem Bucket eine CORS-Richtlinie hinzu (**Settings** → **CORS policy**). Browser laden direkt zu R2 hoch, daher muss der Bucket `PUT`-Anfragen mit einem `Content-Type`-Header vom Origin deiner App akzeptieren:

   ```json title="R2 bucket CORS policy"
   [
     {
       "AllowedOrigins": ["https://qrdx.example.com", "http://localhost:3000"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["Content-Type"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

   Ersetze `https://qrdx.example.com` durch den Origin, über den Leute dein Dashboard öffnen (Schema und Host, ohne abschließenden Schrägstrich). Behalte `http://localhost:3000` nur, wenn du von einem lokalen Entwicklungsserver hochlädst.

### Öffentliche Dateien oder Presigned Links [#public-files-or-presigned-links]

Besucher öffnen Dateien immer über `/api/files/<id>`, was auf das gespeicherte Objekt weiterleitet:

- Ist `R2_PUBLIC_BASE_URL` gesetzt (eine mit dem Bucket verbundene eigene Domain oder seine `r2.dev`-URL, die Cloudflare mit einem Ratenlimit versieht und nur für Tests empfiehlt), leitet es auf die öffentliche URL weiter. Objektschlüssel enthalten eine zufällige ID, daher lassen sich Dateien weder auflisten noch erraten.
- Ohne diese Variable bleibt der Bucket privat, und jede Weiterleitung ist ein Presigned Link, der nach einer Stunde abläuft.

In beiden Fällen wird eine ersetzte, gelöschte oder gesperrte Datei innerhalb einer Minute nicht mehr über ihren QRdx-Link ausgeliefert. Eine gesperrte Datei verschwindet außerdem sofort von ihrer öffentlichen URL: Ihr Objekt wird unter einen `quarantine/`-Schlüssel mit zufälligem Anteil verschoben (damit ein Admin es wiederherstellen kann), und ihr QRdx-Link antwortet mit `410 Gone`.

Browser laden unter einen `staging/`-Schlüssel hoch. Sobald der Upload geprüft ist, kopiert QRdx genau die geprüfte Version an den eigenen Schlüssel der Datei, sodass ein noch gültiger Upload-Link eine geprüfte Datei nicht ersetzen kann.

<Callout type="info" title="Abgebrochene Uploads aufräumen">
  Ein Upload, der nie abgeschlossen wird, zählt nach zwei Stunden nicht mehr zum Speicher und wird beim nächsten Upload in diesen Workspace aufgeräumt. Füge dem Bucket eine Objekt-Lifecycle-Regel hinzu (**Settings** → **Object lifecycle rules**), die Objekte mit dem Präfix `staging/` nach einem Tag löscht, damit auch Reste abgebrochener Uploads verschwinden.
</Callout>
