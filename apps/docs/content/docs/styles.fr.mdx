Cette page présente toutes les formes proposées par la bibliothèque, avec le nom de l'option et la valeur à copier dans `bodyPattern`, `cornerEyePattern`, `cornerEyeDotPattern` ou `frame.style`. Servez-vous-en pour choisir un style avant d'écrire du code. Chaque vignette est dessinée par le même moteur de rendu que vos téléchargements, puis décodée dans votre navigateur avec jsQR, une à la fois : le badge **Scans** est donc un résultat en direct.

Chaque valeur est aussi testée dans le package (`packages/qrdx/tests/catalog-*.test.ts`) : elle est décodée avec un modèle de caméra de téléphone (perte de contraste et flou d'un quart de module) à 4, 6 et 9 pixels par module, associée à chacun des autres corps, yeux et centres, aux niveaux de correction d'erreur L, M, Q et H, à 148 px et 1024 px, en clair sur fond sombre, avec des couleurs de marque et avec un logo au centre. Quelques associations fonctionnent mal ensemble ; voir [Associations à éviter](#pairs-to-avoid).

## Motifs de corps [#body-patterns]

La forme des modules de données (`bodyPattern`, `circle` par défaut). Les styles connectés (`liquid`, `classy`) fusionnent les modules voisins en un seul contour. `random-dots` et `mosaic` varient d'un module à l'autre mais sont déterministes : une même valeur dessine toujours le même code.

<QrCatalog kind="body" />

## Cadres d'œil [#eye-frames]

L'anneau extérieur des trois repères d'angle (`cornerEyePattern`, `gear` par défaut). `leaf`, `leaf-reverse`, `drop` et `petal` orientent chaque œil vers le coin du code. Chaque vignette associe l'œil à son centre recommandé.

<QrCatalog kind="eye" />

## Centres d'œil [#eye-centers]

Le centre plein de chaque repère d'angle (`cornerEyeDotPattern`, `circle` par défaut), affiché à l'intérieur d'yeux carrés.

<QrCatalog kind="dot" />

## Cadres [#frames]

Les cadres d'appel à l'action sont dessinés autour du code : le code et sa zone de silence ne sont donc jamais recouverts, et l'image téléchargée s'agrandit pour les contenir. Chaque cadre intégré ci-dessous est une spécification de cadre, dessinée par le même moteur que les [cadres officiels et communautaires](/docs/features/frames). Chaque cadre accepte `text` (24 caractères maximum), `color`, `textColor` et `fontScale` (de 0.5 à 1.5). `banner-top-bottom`, `circle` et `menu-card` affichent aussi `secondaryText` ; `gradient-border` va de `color` à `secondaryColor`.

<QrCatalog kind="frame" />

```tsx title="components/framed-code.tsx"
import { QRCode } from "qrdx";

export function FramedCode() {
  return (
    <QRCode
      value="https://example.com"
      bodyPattern="liquid"
      cornerEyePattern="leaf"
      cornerEyeDotPattern="leaf"
      frame={{ style: "circle", text: "Scan me", secondaryText: "example.com" }}
    />
  );
}
```

## Associations à éviter [#pairs-to-avoid]

Quelques associations de formes qui se scannent bien séparément échouent ensemble dans les tests de décodage du package. Le playground ne permet pas de les choisir ensemble, et le score de scan les signale (`style-pair`) :

- Les corps `diamond` avec des yeux `square`, `pacman` avec `rounded`, et `small-square` avec des yeux `square` ou `rounded` ne sont pas lus de près.

Les yeux `circle` sont lus par les deux décodeurs utilisés dans les tests (jsQR et ZXing), mais sont marqués **prudence** : certaines applications de scan les manquent. Ces associations sont fournies dans le package sous le nom `WEAK_BODY_EYES`, et `getStylePairRisk(props)` renvoie l'avertissement correspondant à un style.

## Formes retirées [#retired-shapes]

Les yeux `curly` et les centres `diamond`, `star` et `banner` ont été retirés car ils ne se scannent pas de façon fiable : ZXing (le décodeur de la plupart des applications de scan Android) manque les yeux curly et les centres diamond et star à distance de téléphone, et jsQR manque les centres banner dans tous les rendus nets. Les codes enregistrés avec ces formes se chargent et s'affichent toujours exactement comme avant, et l'Image API les dessine encore pour les liens existants, mais aucun sélecteur, préréglage ou thème IA ne les propose. Leurs noms sont conservés uniquement comme valeurs obsolètes (`RETIRED_CORNER_EYE_PATTERNS`, `RETIRED_CORNER_EYE_DOT_PATTERNS`).
