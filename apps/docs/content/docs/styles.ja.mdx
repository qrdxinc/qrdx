このページでは、ライブラリが提供するすべての図形を、オプション名と、`bodyPattern`、`cornerEyePattern`、`cornerEyeDotPattern`、`frame.style` にコピーして使える値とともに表示します。コードを書く前に、デザインを選ぶ際の参考にしてください。各タイルは、ダウンロードされる画像と同じレンダラーで描画され、ブラウザー上で jsQR により1つずつデコードされます。そのため、**Scans** バッジはリアルタイムの結果です。

すべての値はパッケージ内でもテストされています(`packages/qrdx/tests/catalog-*.test.ts`)。テストでは、スマートフォンのカメラを想定したモデル(コントラストの低下と、モジュールの4分の1幅のぼかし)で、1モジュールあたり4、6、9ピクセルの条件で、他のすべてのボディ、アイ、センターと組み合わせてデコードします。誤り訂正レベルは L、M、Q、H、サイズは 148 px と 1024 px、さらに明色on暗色、ブランドカラー、中央ロゴ付きの場合も確認しています。一部の組み合わせは相性がよくありません。[避けるべき組み合わせ](#pairs-to-avoid)をご覧ください。

## ボディパターン [#body-patterns]

データモジュールの形です(`bodyPattern`、デフォルトは `circle`)。連結型のスタイル(`liquid`、`classy`)は、隣り合うモジュールを1つの輪郭に結合します。`random-dots` と `mosaic` はモジュールごとに変化しますが、結果は決定的です。同じ値であれば、常に同じコードが描画されます。

<QrCatalog kind="body" />

## アイフレーム [#eye-frames]

3つのコーナーマーカーの外側のリングです(`cornerEyePattern`、デフォルトは `gear`)。`leaf`、`leaf-reverse`、`drop`、`petal` は、各アイをコードの角に向けて回転させます。各タイルには、アイと推奨のセンターを組み合わせて表示しています。

<QrCatalog kind="eye" />

## アイセンター [#eye-centers]

各コーナーマーカーの中心にある塗りつぶし部分です(`cornerEyeDotPattern`、デフォルトは `circle`)。四角いアイの内側に表示されます。

<QrCatalog kind="dot" />

## フレーム [#frames]

コールトゥアクションフレームはコードの周囲に描画されるため、コードとクワイエットゾーンが隠れることはなく、ダウンロードされる画像はフレームに合わせて大きくなります。以下の組み込みフレームはそれぞれフレーム仕様であり、[公式フレームとコミュニティフレーム](/docs/features/frames)と同じエンジンで描画されます。すべてのフレームで `text`(最大24文字)、`color`、`textColor`、`fontScale`(0.5〜1.5)を指定できます。`banner-top-bottom`、`circle`、`menu-card` では `secondaryText` も表示されます。`gradient-border` は `color` から `secondaryColor` へのグラデーションになります。

<QrCatalog kind="frame" />

```tsx title="components/framed-code.tsx"
import { QRCode } from "qrdx";

export function FramedCode() {
  return (
    <QRCode
      value="https://example.com"
      bodyPattern="liquid"
      cornerEyePattern="leaf"
      cornerEyeDotPattern="leaf"
      frame={{ style: "circle", text: "Scan me", secondaryText: "example.com" }}
    />
  );
}
```

## 避けるべき組み合わせ [#pairs-to-avoid]

単独ではスキャンできる図形でも、組み合わせるとパッケージのデコードテストで失敗するものがあります。Playground ではこれらを同時に選べないようになっており、スキャンスコアでも警告が表示されます(`style-pair`)。

- `diamond` のボディと `square` のアイ、`pacman` と `rounded`、`small-square` と `square` または `rounded` のアイの組み合わせは、近距離でも読み取れません。

`circle` のアイは、テストで使用する2つのデコーダー(jsQR と ZXing)のどちらでも読み取れますが、**caution** と表示されます。一部のスキャナーアプリでは読み取れない場合があるためです。これらの組み合わせはパッケージに `WEAK_BODY_EYES` として含まれており、`getStylePairRisk(props)` はスタイルに対する警告を返します。

## 廃止された図形 [#retired-shapes]

`curly` のアイと、`diamond`、`star`、`banner` のセンターは、確実にスキャンできないため削除されました。ZXing(多くの Android スキャナーのデコーダー)は、スマートフォンでの一般的な距離では curly のアイと diamond、star のセンターを読み取れず、jsQR はシャープに描画された場合の banner のセンターをすべて読み取れません。これらを使って保存したコードは、これまでどおり読み込まれて同じように描画され、Image API も既存のリンク向けには引き続きこれらを描画します。ただし、ピッカー、プリセット、AIテーマのいずれにも表示されません。名前は非推奨の値としてのみ残されています(`RETIRED_CORNER_EYE_PATTERNS`、`RETIRED_CORNER_EYE_DOT_PATTERNS`)。
