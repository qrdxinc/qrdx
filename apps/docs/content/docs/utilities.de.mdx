Diese Helfer sind die kleinen Funktionen, die der Renderer und der Scan-Score verwenden. Sie werden für deine eigene UI exportiert: eine repräsentative Farbe auswählen, den Kontrast prüfen, eine Download-Größe validieren und Canvas-Features erkennen. Sie laufen überall, außer wo etwas anderes steht.

| Funktion | Rückgabe | Hinweise |
| --- | --- | --- |
| `getSolidColor(color, fallback?)` | `string` | Eine Farbe, die für eine `ColorConfig` steht: der String, die `color` einer einfarbigen Füllung, der erste Farbstopp eines Verlaufs, die `underlay` einer Bildfüllung, sonst `fallback` (`"#000000"`) |
| `getContrastRatio(a, b)` | `number` | Das WCAG-Kontrastverhältnis zwischen zwei CSS-Farben, 1 bis 21. Durchscheinende Farben werden zuerst über Weiß gelegt. Gibt 1 zurück, wenn eine Farbe nicht gelesen werden kann |
| `getContrastLevel(ratio)` | `{ level, warning, message }` | `AAA` ab 7, `AA` ab 4.5, `AA Large` ab 3 (mit `warning: true`), `Fail` unter 3 |
| `getLuminance(r, g, b)` | `number` | Relative Luminanz einer sRGB-Farbe, 0 bis 1 |
| `hexToRgb(hex)` | `{ r, g, b } \| null` | Liest Hex mit 3, 4, 6 und 8 Stellen und verwirft Alpha. `null` für alles andere |
| `validateSize(width, height)` | `{ isValid, error? }` | Die Regel, die jeder Download anwendet: 50 bis 5000 px und quadratisch |
| `SUPPORTS_PATH2D` | `boolean` | Ob der Canvas dieser Umgebung `Path2D` mit `addPath` unterstützt |

## Farben [#colors]

```ts title="lib/colors.ts"
import { getSolidColor, hexToRgb } from "qrdx";

getSolidColor({
  type: "linear",
  angle: 45,
  stops: [
    { color: "#ff6b6b", offset: 0 },
    { color: "#4ecdc4", offset: 100 },
  ],
});
// "#ff6b6b": the first stop

getSolidColor({ type: "image", src: photo, underlay: "#111111" }); // "#111111"
getSolidColor(undefined, "#ffffff"); // "#ffffff"

hexToRgb("#ff6b6b"); // { r: 255, g: 107, b: 107 }
hexToRgb("#f00"); // { r: 255, g: 0, b: 0 }
hexToRgb("red"); // null
```

Verwende `getSolidColor`, wenn du eine einzelne Farbe für ein Farbfeld, einen CSS-Hintergrund oder einen Fallback brauchst. Der Renderer nutzt sie dort, wo ein Format keinen Verlauf zeichnen kann, etwa bei `QRCodeCanvas` und beim Zeichnen des Canvas-Rahmens.

## Kontrast [#contrast]

```ts title="lib/contrast.ts"
import { getContrastLevel, getContrastRatio, getLuminance } from "qrdx";

getContrastRatio("#000000", "#ffffff"); // 21
getContrastRatio("#1d4ed8", "#f8fafc"); // 6.4
getContrastRatio("rgba(29, 78, 216, 0.5)", "#ffffff"); // the blue over white, so lower

getContrastLevel(4.5);
// { level: "AA", warning: false, message: "Good contrast" }

getContrastLevel(2);
// { level: "Fail", warning: true, message: "Poor contrast - QR code may not scan properly" }

getLuminance(255, 255, 255); // 1
```

Der Scan-Score lässt einen Code ab einem Verhältnis von 4.5 durch (`SCAN_CONTRAST_MIN`), zieht darunter Punkte ab und lässt ihn unter 1.5 durchfallen. Bilder brauchen mehr: `SCAN_IMAGE_CONTRAST_MIN` liegt bei 7 für eine Bildfüllung in den Modulen und bei 12 für eine hinter den Modulen. `getScanContrast(props)` führt die eigene Prüfung des Scan-Scores für ein ganzes Design aus, einschließlich aller Verlaufsstopps und Eye-Farben; siehe [Rahmen, Scan-Score und Druckdateien](/docs/features/frames#will-it-scan).

Ein Live-Kontrastprüfer braucht ein Dutzend Zeilen:

```tsx title="components/contrast-checker.tsx"
"use client";

import { getContrastLevel, getContrastRatio } from "qrdx";
import { useState } from "react";

export function ContrastChecker() {
  const [fgColor, setFgColor] = useState("#000000");
  const [bgColor, setBgColor] = useState("#ffffff");
  const ratio = getContrastRatio(fgColor, bgColor);
  const level = getContrastLevel(ratio);

  return (
    <div>
      <input
        aria-label="Module color"
        type="color"
        value={fgColor}
        onChange={(event) => setFgColor(event.target.value)}
      />
      <input
        aria-label="Background color"
        type="color"
        value={bgColor}
        onChange={(event) => setBgColor(event.target.value)}
      />
      <p>
        {ratio.toFixed(2)}:1, {level.level}. {level.message}
      </p>
    </div>
  );
}
```

## Validierung [#validation]

```ts title="lib/sizes.ts"
import { validateSize } from "qrdx";

validateSize(1024, 1024); // { isValid: true }
validateSize(40, 40); // { isValid: false, error: "Size must be at least 50x50 pixels" }
validateSize(6000, 6000); // { isValid: false, error: "Size must not exceed 5000x5000 pixels" }
validateSize(400, 300); // { isValid: false, error: "Width and height must be equal for QR codes" }
```

`downloadQRCode`, `getQRCodeDataUrl` und `copyQRCodeToClipboard` werfen denselben `error`-Text, wenn eine Größe nicht passt. Ein Formular kann sie also vorher prüfen.

## Feature-Erkennung [#feature-detection]

```ts title="lib/features.ts"
import { SUPPORTS_PATH2D } from "qrdx";

if (SUPPORTS_PATH2D) {
  // draw module paths with Path2D
}
```

`SUPPORTS_PATH2D` wird einmal beim Laden des Moduls berechnet und ist deshalb auf einem Server `false`.

## Weitere Helfer [#other-helpers]

- `getColorString(color)` und `normalizeColorConfig(color)` wandeln die Formen von `ColorConfig` ineinander um; `isGradient(color)` und `isImagePaint(color)` unterscheiden sie.
- `sanitizeFrameText(text)` und `isLatin1Text(text)` wenden die Regeln für Rahmenbeschriftungen an (24 Zeichen; Latin-1 für PDF und EPS).
- `decodePNGPixels(bytes)` liest ein 8-Bit-PNG ohne DOM in RGBA-Pixel ein, für `createQRArtImage`, `createQRSilhouette` oder `scanQRPixels` in Node.
- `rgbToCmyk(color)` ist die Umrechnung, die die CMYK-Druckdateien verwenden.
