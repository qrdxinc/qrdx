连接账户后,二维码编辑器可以使用存放在您其他工具中的链接:在 Bitly、Rebrandly 或 Short.io 中管理的短链接,或 Dropbox 等云盘中文件的分享链接。二维码编码的就是这个链接,因此您可以继续使用已有的工具。如果您的链接必须保留在该工具的数据分析中,或者希望二维码打开存放在云盘中的文件,就可以这样做。

<Callout type="info" title="所有套餐">
  已连接的账户归属于您的用户账户,在所有套餐中均可使用。如果您希望在 QRdx 内部直接修改目标地址并查看扫描分析,请改用[动态二维码](/docs/dynamic-qr-codes)。
</Callout>

## 工作原理 [#how-it-works]

在[设置 → 集成](/settings/integrations)中连接账户后,它会出现在二维码编辑器的 **URL** 类型中,位于 **Website address** 字段旁的 **Use a link from…** 菜单里。在 **Your accounts** 下,每个服务都会说明自己的用途:

- **Shorten**:Bitly、Rebrandly 或 Short.io。在 **Create new** 下创建链接,或在 **Use existing** 下选择已有链接。二维码编码的是该短链接,因此之后您可以在该服务中修改它指向的地址,该服务也会统计点击量。
- **File**:Dropbox<IfAvailable integration="onedrive">、OneDrive</IfAvailable><IfAvailable integration="box">、Box</IfAvailable><IfAvailable integration="notion">、Notion</IfAvailable>。浏览或搜索,然后选择文件或文件夹。QRdx 会创建该项目的分享链接,二维码编码的就是它。

同一菜单还列出您其他已连接的内容来源,例如付款和预订链接。尚未连接的服务位于菜单底部的 **Connect an account** 中。

<Shot id="use-a-link-from" />

令牌和 API 密钥均加密存储,您可以随时断开连接。

## 短链接 [#short-links]

| 服务 | 连接方式 | 域名 | 后半部分 |
| --- | --- | --- | --- |
| Bitly | 使用 Bitly 登录,或粘贴通用访问令牌(Settings → Developer settings → API) | bit.ly 和您的品牌域名 | 由 Bitly 指定 |
| Rebrandly | 粘贴 API 密钥(Account → API keys) | rebrand.ly 和您的品牌域名 | 您自己的 slashtag,或随机生成 |
| Short.io | 粘贴私密 API 密钥(Integrations & API → API) | 您的 Short.io 域名 | 您自己的路径,或随机生成 |

每个集成的设置页面都会显示您的域名,并可让您为新链接选择默认域名。您仍然可以为每个链接单独选择其他域名。

<Callout type="info" title="之后修改目标地址">
  链接由 QRdx 创建;修改它指向的地址需要在 Bitly、Rebrandly 或 Short.io 中进行。Bitly 仅允许付费套餐修改链接的目标地址。
</Callout>

## 文件选择器 [#file-pickers]

**Dropbox** 编码的是共享链接(新创建的,或复用已有的)。任何拥有该链接的人都可以打开,除非您的团队只允许团队链接。

<IfAvailable integration="onedrive">

**OneDrive** 编码的是仅可查看的分享链接。任何拥有该链接的人都可以打开;如果管理员关闭了“任何人”链接,则只有您的组织内部成员可以打开。

</IfAvailable>

<IfAvailable integration="box">

**Box** 编码的是该项目的共享链接,权限设为“拥有链接的人”。任何拥有该链接的人都可以打开;如果管理员有此要求,则只有您的公司内部成员可以打开。

</IfAvailable>

<IfAvailable integration="notion">

**Notion** 编码的是页面的“发布到网络”链接。页面发布后,任何人都可以打开。

</IfAvailable>

如果链接无法被所有人打开,QRdx 会在您选择之后立即提示,避免印刷出来的二维码把人引到登录页面。

<IfAvailable integration="notion">

**Notion 页面。** QRdx 只能看到您与其共享的页面:连接时 Notion 会询问要共享哪些页面。之后若要添加更多页面,请在 Notion 中打开该页面,点击 **•••** → **Connections** 并添加 QRdx(或重新连接并选择这些页面)。Notion 的 API 无法发布页面。请自行发布(**Share** → **Publish** → **Publish to web**),然后重新选择该页面,让 QRdx 使用公开链接。

</IfAvailable>

### 托管页面上的文件 [#files-on-hosted-pages]

托管页面也可以使用云端文件:PDF、音频、视频和下载区块中,当 Dropbox 是您唯一连接的云盘时,上传按钮旁会显示 **From Dropbox** 按钮;连接了多个云盘时则显示 **From cloud storage**<IfAvailable integration="onedrive">,其中包括 OneDrive</IfAvailable><IfAvailable integration="box">,其中包括 Box</IfAvailable>。对于 Dropbox<IfAvailable integration="box">和 Box</IfAvailable>,页面区块会获得文件的直接链接,因此音频和视频播放器以及 PDF 查看器都能加载它。<IfAvailable integration="onedrive"> OneDrive 分享链接会打开 OneDrive 的查看器,因此区块会将其显示为链接。</IfAvailable>

## 断开连接 [#disconnecting]

断开连接会删除已存储的令牌。对于 Dropbox<IfAvailable integration="box">、Box</IfAvailable><IfAvailable integration="notion">、Notion</IfAvailable>,QRdx 还会在该服务端撤销令牌。对于 Bitly、Rebrandly 和 Short.io,如果您不再使用,也请在该服务中删除密钥<IfAvailable integration="onedrive">;对于 OneDrive,请在您的 Microsoft 账户的应用权限中移除 QRdx</IfAvailable>。

您已创建的二维码仍然有效:它们保存的是短链接或分享链接,而不是您的令牌。

## 限制与套餐 [#limits-and-plans]

已连接的账户本身没有套餐限制。从 QRdx 的角度来看,它们创建的链接是静态的:QRdx 既不统计这些链接的扫描次数,也无法修改它们指向的地址。您能在该服务中对链接做什么,取决于该服务自己的套餐。

## 自托管 [#self-hosting]

Rebrandly 和 Short.io 不需要在服务器上做任何配置。其他集成需要在各服务中创建一个应用,并把它的客户端 ID 和密钥放入环境变量;没有这些配置时,该集成在生产环境中会被隐藏(本地开发时会显示 **Needs setup** 徽章)。Bitly 即使没有这些配置,仍可通过粘贴访问令牌使用。

| 集成 | 变量 | 重定向 URI |
| --- | --- | --- |
| Bitly(登录) | `BITLY_CLIENT_ID`, `BITLY_CLIENT_SECRET` | `<app url>/api/integrations/bitly/callback` |
| Dropbox | `DROPBOX_CLIENT_ID`, `DROPBOX_CLIENT_SECRET` | `<app url>/api/integrations/dropbox/callback` |
| OneDrive | `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET` | `<app url>/api/integrations/onedrive/callback` |
| Box | `BOX_CLIENT_ID`, `BOX_CLIENT_SECRET` | `<app url>/api/integrations/box/callback` |
| Notion | `NOTION_CLIENT_ID`, `NOTION_CLIENT_SECRET` | `<app url>/api/integrations/notion/callback` |

`<app url>` 在开发环境中是 `http://localhost:3000`,其他情况下是您的生产环境 URL。在生产环境中,每个集成还需要 `INTEGRATION_ENCRYPTION_KEY`,用于加密已存储的令牌和密钥。

需要申请的权限范围:

- **Dropbox:** `account_info.read`, `files.metadata.read`, `sharing.read`, `sharing.write`
- **OneDrive:** `offline_access`, `Files.ReadWrite`(Microsoft Graph 需要写入权限才能创建分享链接)
- **Box:** 读取和写入所有文件和文件夹(`root_readwrite`)
- **Bitly、Notion:** 无需权限范围;Notion 会询问用户要共享哪些页面

参见[自托管](/docs/self-hosting#optional-services)。
