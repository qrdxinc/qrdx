每个[动态二维码](/docs/dynamic-qr-codes)都会在不使用 Cookie 的情况下记录扫描。跟踪功能更进一步:在你的二维码所打开的托管页面上加载你自己的像素,并把你网站上的购买等转化归因到带来该访客的那次扫描。当二维码流量需要出现在团队已在使用的工具中,或者你需要知道哪些二维码能带来收入时,就可以使用它。

<Callout type="info" title="像素在 Pro,转化在 Business">
  跟踪像素包含在 Pro 和 Business 中;转化跟踪包含在 Business 中。两者都在二维码的**设置**标签页中配置。参见[套餐与限制](/docs/plans-and-limits)。
</Callout>

时间紧?[查看你的扫描](/docs/help/dynamic-codes/scans)介绍了所有套餐都具备的分析功能。

## 工作原理 [#how-it-works]

<Diagram id="tracking-paths" />

二维码要么打开托管页面,要么重定向到你的网站,两条路径各有对应的工具。在托管页面上,QRdx 控制 HTML,因此可以在访客同意后加载你的像素。在你的网站上,QRdx 无法控制任何内容,因此它会在 URL 中把一个已签名的扫描 id 交给你的网站,并由你的网站在访客转化时回报。

## 每个二维码都有的分析 [#analytics-on-every-code]

除了随时间变化的扫描量、国家、城市、设备、操作系统、浏览器和来源页之外,每个二维码的**分析**标签页还会显示:

- **扫描时间:**按一天中的小时和按星期几统计的扫描量,可使用 UTC 或你自己的时区。
- **语言:**每位访客的浏览器首选语言(浏览器未发送时显示“未知”)。
- **A/B 分流:**每个[A/B 分流规则](/docs/smart-routing#ab-tests)下各变体的扫描量。
- **页面活动**(托管页面):页面浏览量、独立访客数、点击次数,以及点击最多的链接和按钮。
- **转化**(如果该二维码有转化)。

<Shot id="when-people-scan" />

侧边栏中的**二维码** → **分析**会汇总工作区内的所有二维码:总量、随时间变化的扫描量、热门二维码、国家、设备、语言、扫描时间,并支持最多 4 个二维码并排对比。机器人和链接预览不计入统计,“独立”访客按每人每天计一次,且从不存储 IP 地址。

## 托管页面上的跟踪像素 [#tracking-pixels-on-hosted-pages-pro]

对于打开托管页面的二维码,二维码**设置**标签页中的**跟踪像素**面板会在该页面上加载你自己的标签:

| 服务商 | ID 格式 |
| --- | --- |
| Google Analytics 4 | `G-` 后跟 4 到 20 个字母和数字 |
| Meta (Facebook) 像素 | 6 到 20 位数字 |
| TikTok 像素 | 10 到 30 个字母和数字 |
| LinkedIn Insight Tag | 合作伙伴 ID,3 到 12 位数字 |

<Shot id="pixels-panel" />

像素只有在你设置后才会加载。除了你的像素之外,托管页面上唯一的脚本是 QRdx 自己的页面活动计数器,它只向 QRdx 报告浏览和点击,不会报告给任何其他方。

<IfAvailable feature="customDomains">

**Google Tag Manager**(`GTM-` 后跟 4 到 12 个字母和数字)仅在页面通过你的某个[自定义域名](/docs/custom-domains)打开时才会加载。容器可以运行任意脚本,因此它绝不会在 qrdx.dev 上运行,因为访客可能已登录 QRdx。

</IfAvailable>

### 同意 [#consent]

在访客同意之前,像素绝不会加载:

- **在要求同意的地区(欧盟、欧洲经济区、英国、瑞士、位置未知)**,这是默认选项:这些地区的访客以及位置未知的访客会看到一个简短的横幅,其中列出你的服务商,并可选择**接受**或**拒绝**。该选择会针对该页面被记住,访客可通过 **Cookie 设置**更改。在其他地区,像素会立即加载,但发送 Global Privacy Control 信号的浏览器除外。
- **对所有访客:**每个人都会先看到横幅。

你仍需对自己的隐私政策以及你如何使用像素收集的数据负责。直接打开你自己网站的二维码会直接跳转到该网站,因此请把像素添加到你的网站上。

## 转化跟踪 [#conversion-tracking]

转化跟踪会告诉你哪些扫描带来了销售、注册或其他目标,并包含收入。它适用于打开你网站的二维码。

1. 在二维码的**设置**标签页中,开启**转化跟踪**。此后每次扫描都会打开你的 URL,并附加一个已签名的 `qrdx_sid` 参数,例如 `https://shop.example/?qrdx_sid=…`。
2. 将代码片段添加到用户的落地页以及发生转化的页面:

```html title="Your website (before </body>)"
<script async src="https://qrdx.dev/conversions.js"></script>
<script>
  window.qrdx = window.qrdx || function () {
    (window.qrdx.q = window.qrdx.q || []).push(arguments);
  };
  // Where the conversion happens, for example your order confirmation page:
  qrdx("conversion", { name: "purchase", value: 49.99, currency: "USD", id: "ORDER-1234" });
</script>
```

该脚本会把 `qrdx_sid` 以第一方 Cookie 的形式保存在你的域名下 30 天(在 script 标签上添加 `data-storage="session"` 可仅在浏览器会话期间保留),并将其从地址栏中移除。只有从扫描进入的访客才会发送转化,因此其他访客绝不会被跟踪。

| 字段 | 含义 |
| --- | --- |
| `name` | 发生了什么,例如 `purchase` 或 `signup`(默认为 `conversion`) |
| `value` | 金额,最多 2 位小数(可选) |
| `currency` | ISO 4217 代码,如 `USD`;提供金额时默认为 `USD` |
| `id` | 你的订单或事件 id:同一个 id 发送两次只会记录一次 |
| `metadata` | 最多 20 个额外的键值对(可选) |

### 限制 [#limits]

- 一次扫描在发生后 30 天内可以被归因。
- `qrdx_sid` 是经过签名的,因此无法被猜测,也无法被修改为指向其他二维码。
- 浏览器上报要求该二维码已开启转化跟踪,且每次扫描每小时最多可上报 10 次转化。使用令牌从你的服务器上报则没有这两项限制。
- 如果工作区不再使用 Business,转化将停止记录;已有的转化会保留在你的分析中,并且随时都可以关闭跟踪。

## 面向开发者 [#for-developers]

若要从你的后端上报转化(比浏览器更可靠),请将 `qrdx_sid` 与订单一起保存,并使用 [API 密钥](/docs/developers/api-keys)或具有 `codes:write` 范围的 OAuth 令牌调用 [`POST /v1/conversions`](/docs/developers/api/create-conversion):

```bash title="Terminal"
curl -X POST https://api.qrdx.dev/v1/conversions \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sid": "<qrdx_sid>", "name": "purchase", "value": 49.99, "currency": "USD", "id": "ORDER-1234"}'
```

对于新的转化,API 返回 `201`;当 `id` 已被记录过时,返回 `200` 并带有 `"duplicate": true`。使用令牌时,如果扫描未知,你也可以发送 `"code": "<code id>"` 来代替 `sid`。
