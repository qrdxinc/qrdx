Setelah mengikuti halaman ini, URL yang Anda kendalikan akan menerima `POST` bertanda tangan dalam beberapa menit setelah setiap peristiwa yang Anda pilih, server Anda memverifikasi bahwa setiap permintaan berasal dari QRdx, dan Anda memahami cara kerja percobaan ulang, duplikat, dan log pengiriman.

Webhook mengirimkan peristiwa dari sebuah workspace ke server Anda saat peristiwa itu terjadi: perbarui CRM saat seseorang mengisi formulir, kirim pesan ke alat internal saat sebuah kode melewati 1.000 pemindaian, atau simpan salinan data pemindaian Anda sendiri.

<Callout type="info" title="Paket Business">
Webhook, hook Zapier dan Make, serta peringatan Slack dan Discord termasuk dalam paket **Business**. Peringatan email dan ringkasan mingguan termasuk dalam Pro; lihat [Notifikasi](/docs/notifications). Bandingkan paket di [Paket dan batas](/docs/plans-and-limits).
</Callout>

## Sebelum memulai [#before-you-start]

- URL `https://` publik yang menjawab permintaan `POST`. Alamat IP, `localhost`, dan nama host yang mengarah ke jaringan privat akan ditolak, dan pengalihan tidak diikuti. Untuk pengembangan lokal, gunakan tunnel yang memberi Anda nama host publik.
- Peran pemilik atau admin di workspace. Anggota dapat melihat endpoint beserta log pengirimannya, tetapi tidak dapat menambah atau mengubahnya.

## 1. Tambahkan endpoint [#1-add-an-endpoint]

1. Buka [Pengaturan → Webhook](/dashboard?to=settings/webhooks) di workspace yang peristiwanya ingin Anda terima. Tautan ini membuka workspace yang terakhir Anda gunakan; pilih workspace lain di pengalih workspace dan Anda tetap berada di halaman yang sama.
2. Pilih **Tambah endpoint**, masukkan **URL endpoint** dan centang **Peristiwa** yang Anda inginkan, lalu pilih **Tambah endpoint** di dialog. QRdx terlebih dahulu meminta Anda [mengonfirmasi bahwa ini Anda](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), dan meminta lagi setiap kali Anda mengubah URL endpoint; mengubah peristiwanya atau menonaktifkannya tidak memerlukan konfirmasi.
3. Salin **Rahasia penandatanganan** yang ditampilkan setelah penyimpanan. Pemilik dan admin dapat menampilkannya lagi, atau merotasinya, dari halaman **Pengiriman** endpoint.
4. Pilih **Kirim tes**. QRdx mengirim peristiwa `ping` bertanda tangan dan menampilkan status respons di log pengiriman.

## 2. Pilih peristiwa [#2-pick-the-events]

| Peristiwa | Kapan | Catatan |
| --- | --- | --- |
| `scan.created` | Kode dinamis dipindai | Dikelompokkan: paling banyak satu permintaan per menit untuk setiap endpoint, dengan hingga 100 pemindaian dan `count` yang tepat |
| `scan.milestone` | Pemindaian ke-1 sebuah kode, lalu 10, 100, 500, 1.000, 5.000, 10.000, 50.000, 100.000, 500.000 dan 1.000.000 pemindaian, lalu setiap sejuta | Terpicu sekali untuk setiap tonggak |
| `code.created` | Kode dinamis dibuat, di dasbor atau melalui API | Satu peristiwa per kode, termasuk pada pembuatan massal |
| `code.updated` | Tujuan, judul, desain, atau domain tautan pendek sebuah kode berubah | `changes` mencantumkan kolom yang berubah |
| `form.submitted` | Seseorang mengirim formulir di halaman yang di-hosting | Menyertakan jawabannya |
| `ping` | Anda memilih **Kirim tes** | |

Pemindaian oleh bot, pratinjau tautan, dan prefetcher, serta pengulangan cepat dari satu pengunjung, tidak dihitung dan tidak memicu peristiwa, persis seperti pada [analitik pemindaian](/docs/dynamic-qr-codes#scan-analytics).

## 3. Baca payload [#payloads]

Setiap permintaan adalah `POST` dengan isi JSON dan header berikut:

| Header | Nilai |
| --- | --- |
| `Content-Type` | `application/json` |
| `User-Agent` | `QRdx-Webhooks/1.0 (+https://qrdx.dev/docs/webhooks)` |
| `X-QRdx-Event` | Jenis peristiwa, seperti `code.created` |
| `X-QRdx-Delivery` | ID pengiriman: sama pada setiap percobaan ulang, sehingga Anda dapat mengabaikan duplikat |
| `X-QRdx-Timestamp` | Detik Unix saat percobaan ini ditandatangani |
| `X-QRdx-Signature` | `t=<timestamp>,v1=<hex HMAC-SHA256>` |

Isinya selalu berupa amplop dengan `id`, `type`, `created_at`, dan `data`:

```json title="code.created"
{
  "id": "evt_cm3x8c1a20001",
  "type": "code.created",
  "created_at": "2026-10-31T09:30:00.000Z",
  "data": {
    "code": {
      "id": "cm3x7q2l40000",
      "slug": "aB3dE5f",
      "title": "Spring menu",
      "short_link": "https://qrdx.dev/q/aB3dE5f",
      "destination_url": "https://example.com/menu",
      "status": "active",
      "scan_count": 0,
      "created_at": "2026-10-31T09:30:00.000Z",
      "updated_at": "2026-10-31T09:30:00.000Z"
    },
    "actor_id": "user_123"
  }
}
```

Satu kelompok `scan.created`:

```json title="scan.created"
{
  "id": "evt_cm3x9d0b10002",
  "type": "scan.created",
  "created_at": "2026-10-31T09:31:00.000Z",
  "data": {
    "window_started_at": "2026-10-31T09:31:00.000Z",
    "window_seconds": 60,
    "count": 2,
    "scans": [
      {
        "scan_id": "cm3x9d0b00001",
        "code": { "id": "cm3x7q2l40000", "slug": "aB3dE5f", "title": "Spring menu" },
        "scanned_at": "2026-10-31T09:31:00.000Z",
        "country": "DE",
        "region": "BE",
        "city": "Berlin",
        "device_type": "mobile",
        "os": "iOS",
        "browser": "Safari",
        "referer": null,
        "source": "qr"
      }
    ]
  }
}
```

Jika lebih dari 100 pemindaian masuk dalam satu menit, `scans` memuat 100 yang pertama dan `count` berisi total yang tepat. `source` bernilai `nfc` untuk ketukan pada [tag NFC](/docs/nfc) dan `qr` untuk pemindaian QR. Payload pemindaian tidak pernah menyertakan alamat IP atau hash pengunjung.

Peristiwa lainnya membawa:

- `scan.milestone`: `milestone`, `code` (`id`, `slug`, `title`, `scan_count`) dan `scan` yang mencapainya.
- `code.updated`: seperti `code.created`, ditambah `changes`, misalnya `["destination_url"]`.
- `form.submitted`: `response_id`, `page` (`id`, `title`), `code` (`id`, `slug`, atau `null`), `fields` (`name`, `label`, `value` sebagai teks) dan `submitted_at`.

Untuk melihat payload dari setiap peristiwa yang dibuat dari data Anda sendiri sebelum peristiwa nyata pertama tiba, panggil [Dapatkan contoh peristiwa](/docs/developers/api/get-hook-samples):

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/hooks/sample?event=scan.created" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

## 4. Verifikasi tanda tangan [#verify-signatures]

Hitung HMAC-SHA256 dari `<timestamp>.<raw body>` dengan rahasia penandatanganan Anda lalu bandingkan dengan `v1` di `X-QRdx-Signature`. Gunakan isi permintaan mentah, sebelum penguraian JSON apa pun, dan tolak timestamp yang lebih lama dari lima menit.

```ts title="lib/qrdx-webhook.ts"
import { createHmac, timingSafeEqual } from "node:crypto";

export function isFromQRdx(rawBody: string, header: string, secret: string) {
  const parts = Object.fromEntries(
    header.split(",").map((part) => part.trim().split("=", 2)),
  );
  const timestamp = Number(parts.t);
  if (!timestamp || Math.abs(Date.now() / 1000 - timestamp) > 300) return false;

  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const received = Buffer.from(parts.v1 ?? "");
  return (
    received.length === expected.length &&
    timingSafeEqual(received, Buffer.from(expected))
  );
}
```

```python title="qrdx_webhook.py"
import hmac
import hashlib
import time


def is_from_qrdx(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(part.strip().split("=", 1) for part in header.split(","))
    timestamp = int(parts.get("t", "0"))
    if not timestamp or abs(time.time() - timestamp) > 300:
        return False
    expected = hmac.new(
        secret.encode(), f"{timestamp}.".encode() + raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(parts.get("v1", ""), expected)
```

Rotasi rahasia berlaku segera: rahasia lama tidak lagi lolos verifikasi, jadi perbarui server Anda tepat setelah merotasi.

## 5. Beri respons, dan tangani percobaan ulang [#5-respond-and-handle-retries]

Beri respons dengan status `2xx` apa pun dalam 10 detik. Hal lain (status galat, pengalihan, waktu habis, host tidak dapat dijangkau) dihitung sebagai kegagalan, dan QRdx mencoba lagi dengan jeda yang makin panjang sekitar 1 menit, 4 menit, 16 menit, 1 jam, 4 jam, 17 jam, dan 24 jam. Setiap percobaan ulang dikirim dalam beberapa menit setelah jedanya berakhir. Itu berarti 8 percobaan selama kira-kira dua hari, setelah itu pengiriman ditandai gagal.

Pengiriman dapat tiba lebih dari sekali (percobaan ulang setelah respons lambat, percobaan ulang manual) dan tidak berurutan. Gunakan `X-QRdx-Delivery` atau `id` amplop untuk mengabaikan duplikat, dan kerjakan tugas Anda setelah menjawab `2xx` jika membutuhkan waktu lebih dari beberapa detik.

## Ubah nanti [#change-it-later]

Halaman **Pengiriman** setiap endpoint mencantumkan 50 pengiriman terakhir beserta peristiwa, status, jumlah percobaan, dan payload-nya. **Coba lagi sekarang** mengirim ulang pengiriman yang gagal atau tertunda saat itu juga; **Kirim lagi** mengirim ulang pengiriman yang sudah terkirim. Pengiriman disimpan selama 30 hari.

## Zapier, Make, dan n8n (REST Hooks) [#zapier-make-and-n8n-rest-hooks]

Alat otomatisasi dapat berlangganan dan berhenti berlangganan sendiri melalui REST Hooks API. Autentikasi dengan [kunci API](/docs/developers/api-keys) atau token akses OAuth: `codes:write` untuk berlangganan atau berhenti berlangganan, `codes:read` untuk menampilkan daftar. URL hook sering kali rahasia, jadi dengan `codes:read` saja `target_url` hanya menampilkan host (`https://hooks.zapier.com`). Permintaan dengan token bertindak pada workspace Anda sendiri; kunci bertindak pada workspace tempat kunci itu dibuat. Berlangganan dengan sesi browser Anda yang sedang masuk akan meminta Anda [mengonfirmasi bahwa ini Anda](/docs/help/privacy-and-security/two-step-verification#confirm-its-you) terlebih dahulu, dan menjawab `403 CONFIRMATION_REQUIRED` sampai Anda melakukannya dalam 10 menit terakhir. Langganan adalah endpoint biasa: langganan muncul di **Pengaturan → Webhook**, tempat Anda juga dapat menghapusnya.

| Metode | Path | Deskripsi |
| --- | --- | --- |
| `POST` | `/v1/hooks` | Berlangganan. Isi: `target_url` (atau `hookUrl` dari Zapier) dan `event` (atau array `events`). Mengembalikan `201` dengan `id` langganan dan `secret`-nya |
| `DELETE` | `/v1/hooks/{id}` | Berhenti berlangganan (`204`) |
| `GET` | `/v1/hooks` | Menampilkan daftar langganan dan endpoint |
| `GET` | `/v1/hooks/{id}` | Satu langganan |
| `GET` | `/v1/hooks/sample?event=<event>` | Contoh payload terbaru untuk `event`, sebagai array ("perform list" milik Zapier) |

```bash title="Terminal"
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://hooks.zapier.com/hooks/standard/123/abc/", "event": "form.submitted"}'
```

```json title="201 Created (fields)"
{
  "id": "<hook id>",
  "target_url": "https://hooks.zapier.com/hooks/standard/123/abc/",
  "events": ["form.submitted"],
  "event": "form.submitted",
  "active": true,
  "created_at": "<ISO 8601 time>",
  "secret": "whsec_<shown only here>"
}
```

Tanpa Business, panggilan berlangganan mengembalikan `402`:

```json title="402 Payment Required"
{"code":"PLAN_REQUIRED","message":"Webhooks and Zapier/Make hooks are part of the Business plan.","status":402}
```

Pengiriman `scan.created` adalah satu kelompok, jadi di Zapier gunakan item baris `data.scans` untuk menindaklanjuti setiap pemindaian. Di n8n, node QRdx Trigger dari [node QRdx untuk n8n](/docs/developers/n8n) melakukan panggilan ini untuk Anda dan memeriksa setiap tanda tangan; node Webhook biasa juga bisa digunakan, disiapkan seperti endpoint lainnya. Halaman referensinya adalah [Berlangganan peristiwa](/docs/developers/api/create-hook), [Daftar hook](/docs/developers/api/list-hooks), dan [Berhenti berlangganan](/docs/developers/api/delete-hook).

## Jika terjadi masalah [#if-something-goes-wrong]

### URL endpoint ditolak [#the-endpoint-url-is-refused]

Hanya nama host `https://` yang publik yang diterima: tidak boleh `http://`, alamat IP, `localhost`, atau nama yang mengarah ke jaringan privat. Gunakan tunnel dengan nama host publik selama pengembangan.

### Setiap pengiriman menampilkan status gagal [#every-delivery-shows-a-failed-status]

Server Anda menjawab dengan selain `2xx` dalam 10 detik, melakukan pengalihan, atau tidak menjawab. Buka detail pengiriman untuk melihat status HTTP atau galat yang tepat, perbaiki masalahnya, lalu pilih **Retry now**. Jika handler Anda lambat, jawab `2xx` terlebih dahulu dan proses setelahnya.

### Tanda tangan tidak lolos verifikasi [#signatures-dont-verify]

Pastikan Anda melakukan hash terhadap isi permintaan mentah, bukan objek JSON yang diserialisasi ulang, dan server Anda memakai secret yang terbaru: merotasinya langsung membatalkan secret lama. Periksa juga jam server Anda, karena pemeriksaan stempel waktu mengizinkan selisih lima menit.

### Event berhenti masuk [#events-stopped-arriving]

Workspace keluar dari paket Business (endpoint tetap disimpan tetapi dijeda), endpoint berstatus **Disabled**, atau Zap, skenario, atau alur kerja yang membuat langganan telah dimatikan dan berhenti berlangganan. Periksa **Settings → Webhooks**.

### `403 CONFIRMATION_REQUIRED` dari `POST /v1/hooks` [#403-confirmation_required-from-post-v1hooks]

Anda berlangganan dengan sesi browser. Konfirmasikan bahwa itu Anda di QRdx lalu coba lagi dalam 10 menit, atau berlangganan dengan kunci API dari server Anda.

## Hosting mandiri [#self-hosting]

Pengiriman dilakukan langsung; percobaan ulang dan batch pemindaian yang menitnya sudah berakhir dikirim oleh job terjadwal. QRdx menjalankannya setiap 5 menit dari workflow GitHub Actions, yang berfungsi di paket Hobby gratis Vercel, dan `apps/app/vercel.json` juga menjalankannya secara penuh sekali sehari. GitHub dapat memulai eksekusi terjadwal dengan terlambat, jadi perkirakan percobaan ulang dalam beberapa menit, bukan tepat waktu.

Untuk melakukan hal yang sama, salin `.github/workflows/webhook-worker.yml`, tambahkan `CRON_SECRET` Anda sebagai secret Actions dan URL job Anda sebagai variabel `WEBHOOK_WORKER_URL`. Atau panggil job dari penjadwal apa pun dengan `CRON_SECRET` yang Anda atur di environment:

```bash title="crontab (every 1 to 5 minutes)"
curl -H "Authorization: Bearer $CRON_SECRET" https://your-host/api/cron/webhooks
```

Dengan menambahkan `?source=github` pada URL, job lebih dulu memeriksa penanda kecil di Upstash Redis dan mengembalikan `{"skipped": true}` tanpa meng-query database bila tidak ada yang jatuh tempo, sehingga database yang menyusut ke nol dapat tetap tidur (tanpa Upstash, job selalu berjalan penuh). Pertahankan satu panggilan per hari tanpa parameter itu: eksekusi tersebut selalu menjalankan job penuh dan memperbaiki penanda. Job terjadwal lainnya tercantum di [Hosting mandiri](/docs/self-hosting#scheduled-jobs).
