इस गाइड के अंत तक QRdx आपके अपने URL पर चल रहा होगा: QR एडिटर, अकाउंट, स्कैन एनालिटिक्स वाले डायनेमिक QR कोड, होस्टेड पेज, वर्कस्पेस और सेव की गई थीम, सब आपके नियंत्रण वाले Postgres डेटाबेस पर। Docker Compose वाले तरीके में लगभग आधा घंटा लगता है, जिसका ज़्यादातर समय पहली इमेज बिल्ड में जाता है।

वेब ऐप AGPL-3.0 लाइसेंस के तहत ओपन सोर्स है। दो हिस्से ओपन सोर्स नहीं हैं: वर्कस्पेस सिंगल साइन-ऑन और ऑडिट लॉग `ee/` फ़ोल्डरों में हैं, जो QRdx के कमर्शियल लाइसेंस के तहत आते हैं और लाइसेंस की (`QRDX_EE_LICENSE`) सेट किए बिना बंद रहते हैं। प्रोडक्शन में इन्हें इस्तेमाल करने के लिए QRdx के साथ लिखित समझौता ज़रूरी है; देखें [LICENSING.md](https://github.com/qrdxinc/qrdx/blob/main/LICENSING.md)। [`qrdx` React लाइब्रेरी](/docs/getting-started) या [CLI](/docs/developers/cli) इस्तेमाल करने के लिए इनमें से कुछ भी ज़रूरी नहीं है: ये MIT लाइसेंस के तहत बिना बैकएंड के कहीं भी चलती हैं। [QRdx में ओपन सोर्स](/open-source-qr-code-generator) पेज पर रिपॉज़िटरी के हर हिस्से और उसके लाइसेंस की सूची है।

## शुरू करने से पहले [#before-you-start]

- Compose v2 और BuildKit वाला Docker (Docker Desktop और मौजूदा Docker Engine दोनों में ये शामिल हैं), या मैन्युअल सेटअप के लिए Node.js 22 (22.22.3 या बाद का) और [Bun](https://bun.com/docs/installation) 1.4।
- इमेज बिल्ड होते समय Docker के लिए कम से कम 8 GB मेमोरी।
- साइन इन करने का कोई तरीका, ताकि अकाउंट बन सकें: GitHub या Google OAuth ऐप, या ईमेल साइन-इन कोड के लिए [Resend](https://resend.com)। साइन-इन कोड ईमेल तभी भेजे जाते हैं जब `NEXT_PUBLIC_APP_URL` `localhost` न हो। `bun run dev` इन्हें टर्मिनल में प्रिंट करता है, लेकिन Docker इमेज ऐसा नहीं करती, इसलिए लोकल Docker टेस्ट के लिए GitHub या Google साइन-इन चाहिए।
- Postgres: `docker-compose.yml` में दिया गया कंटेनर, या [Neon](https://neon.tech) डेटाबेस।
- लोकल टेस्ट से आगे किसी भी काम के लिए, एक डोमेन और HTTPS टर्मिनेट करने वाला रिवर्स प्रॉक्सी।

डॉक्स सेल्फ-होस्ट किए गए इंस्टेंस का हिस्सा नहीं हैं। आपका इंस्टेंस हर डॉक्स लिंक (`/docs` और उसके तहत आने वाले पेज, उनकी Markdown कॉपियाँ और `/llms-full.txt`) को qrdx.dev के उन्हीं पेजों पर भेज देता है।

### डेटाबेस कनेक्शन कैसे काम करता है [#how-the-database-connection-works]

ऐप Neon के सर्वरलेस HTTP ड्राइवर से Postgres से बात करता है।

- **Neon:** सीधे काम करता है। `DATABASE_URL` में अपनी Neon कनेक्शन स्ट्रिंग डालें।
- **सामान्य Postgres:** इसके आगे Neon-संगत HTTP प्रॉक्सी चाहिए। `docker-compose.yml` एक प्रॉक्सी ([local-neon-http-proxy](https://github.com/TimoWilhelm/local-neon-http-proxy)) चलाता है और `DATABASE_HTTP_ENDPOINT` सेट करता है, ताकि ऐप अपनी क्वेरी वहीं भेजे।

स्कीमा `packages/database/schema.ts` से आती है और `drizzle-kit push` से लागू होती है। हाथ से चलाने के लिए कोई माइग्रेशन फ़ाइल नहीं है।

## Docker Compose से क्विक स्टार्ट [#quick-start-with-docker-compose]

### 1. रिपॉज़िटरी क्लोन करें [#1-clone-the-repository]

```bash title="Terminal"
git clone https://github.com/qrdxinc/qrdx.git
cd qrdx
```

### 2. एनवायरनमेंट कॉन्फ़िगर करें [#2-configure-the-environment]

example फ़ाइल को रिपॉज़िटरी रूट में कॉपी करें, जहाँ Compose उसे पढ़ता है, और सेशन सीक्रेट जनरेट करें:

```bash title="Terminal"
cp apps/app/.env.example .env
openssl rand -base64 32
# prints a 44-character string: paste it as BETTER_AUTH_SECRET below
```

`.env` खोलें और ये वैल्यू सेट करें। बाकी हर लाइन कमेंट में ही रह सकती है।

```bash title=".env"
NEXT_PUBLIC_APP_URL=https://qr.example.com
BETTER_AUTH_URL=https://qr.example.com
BETTER_AUTH_SECRET=<the string openssl printed>

# One sign-in provider. The callback URL for GitHub is
# <NEXT_PUBLIC_APP_URL>/api/auth/callback/github
GITHUB_CLIENT_ID=<client ID of your GitHub OAuth app>
GITHUB_CLIENT_SECRET=<its client secret>
```

हर वैल्यू कहाँ से मिलेगी:

| वैरिएबल | कहाँ से मिलेगा |
| --- | --- |
| `NEXT_PUBLIC_APP_URL` | आपके इंस्टेंस का पब्लिक URL, अंत में स्लैश के बिना। लोकल टेस्ट के लिए `http://localhost:3000` रहने दें। |
| `BETTER_AUTH_URL` | वही वैल्यू। लाइन से कमेंट हटाएँ। |
| `BETTER_AUTH_SECRET` | `openssl rand -base64 32` का आउटपुट। |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | एक [GitHub OAuth ऐप](https://github.com/settings/developers), जिसका callback URL `<your url>/api/auth/callback/github` हो। |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | GitHub की जगह: एक [Google OAuth क्लाइंट](https://console.cloud.google.com/apis/credentials), जिसका redirect URI `<your url>/api/auth/callback/google` हो। |

`DATABASE_URL` को जैसा है वैसा रहने दें: Compose ऐप को उसके अपने Postgres कंटेनर की ओर मोड़ता है और `.env` की वैल्यू को अनदेखा करता है। डेटाबेस पासवर्ड बदलना हो, तो पहली बार स्टार्ट करने से पहले `POSTGRES_PASSWORD` सेट करें।

### 3. स्टैक स्टार्ट करें [#3-start-the-stack]

```bash title="Terminal"
docker compose up -d --build
```

यह इमेज बिल्ड करता है, Postgres और प्रॉक्सी स्टार्ट करता है, एक बार चलने वाली `migrate` सर्विस (`drizzle-kit push`) चलाता है और फिर ऐप को पोर्ट 3000 पर स्टार्ट करता है। पहली बिल्ड में कई मिनट लगते हैं। पूरा होने पर चारों सर्विस ऐसी दिखती हैं:

```text title="docker compose ps (columns trimmed)"
NAME              SERVICE    STATUS
qrdx-db-1         db         running (healthy)
qrdx-db-proxy-1   db-proxy   running
qrdx-migrate-1    migrate    exited (0)
qrdx-app-1        app        running
```

`migrate` का बंद हो जाना सामान्य है: यह स्कीमा सिंक करके रुक जाता है। स्कीमा सिंक और ऐप का स्टार्ट होना देखने के लिए:

```bash title="Terminal"
docker compose logs -f migrate app
```

### 4. साइन इन करें [#4-sign-in]

ब्राउज़र में `NEXT_PUBLIC_APP_URL` खोलें और GitHub, Google या ईमेल कोड से साइन इन करें। आपका अकाउंट पहली बार साइन इन करने पर बन जाता है।

### 5. खुद को एडमिन बनाएँ [#5-make-yourself-an-admin]

स्टेप 4 में बनाए गए अकाउंट का ईमेल पता `.env` में जोड़ें:

```bash title=".env"
ADMIN_EMAILS=you@example.com
```

ऐप कंटेनर को दोबारा बनाएँ ताकि वह बदलाव पढ़ ले, फिर साइन इन करके `/admin` खोलें:

```bash title="Terminal"
docker compose up -d app
```

यह पता पहली बार `/admin` खोलने पर एडमिन बन जाता है। `ADMIN_USER_IDS` भी इसी तरह काम करता है, बस उसमें यूज़र id डाले जाते हैं।

## Neon या कोई और मैनेज्ड Postgres इस्तेमाल करें [#use-neon-or-another-managed-postgres]

आप साथ में आने वाले Postgres को छोड़कर सिर्फ़ ऐप इमेज चला सकते हैं। `.env` में `DATABASE_URL` को अपनी Neon कनेक्शन स्ट्रिंग पर सेट करें और `DATABASE_HTTP_ENDPOINT` को अनसेट रहने दें।

```bash title="Terminal"
docker build -t qrdx --build-arg NEXT_PUBLIC_APP_URL=https://qr.example.com .
docker run -d --env-file .env -p 3000:3000 qrdx
```

स्कीमा एक बार लागू करें, और हर अपडेट के बाद फिर से, migrator इमेज से:

```bash title="Terminal"
docker build --target migrator -t qrdx-migrate .
docker run --rm -e DATABASE_URL="<your connection string>" qrdx-migrate
```

## Node.js से मैन्युअल सेटअप [#manual-setup-with-nodejs]

```bash title="Terminal"
git clone https://github.com/qrdxinc/qrdx.git
cd qrdx
bun install

cp apps/app/.env.example apps/app/.env.local   # then edit it as in step 2

bun run db:push                                # apply the schema
bun run --filter app dev                       # http://localhost:3000
```

प्रोडक्शन के लिए ऐप बिल्ड करें और स्टार्ट करें:

```bash title="Terminal"
bun x turbo build --filter=app
bun run --filter app start
```

`bun run db:push` Neon के ड्राइवर से कनेक्ट होता है, इसलिए इसके लिए Neon डेटाबेस चाहिए। इसकी जगह लोकल डेवलपमेंट के लिए Docker वाला Postgres इस्तेमाल करना हो, तो उसे `docker compose up -d db db-proxy` से स्टार्ट करें, `docker compose run --rm migrate` से स्कीमा लागू करें, और `apps/app/.env.local` में ये सेट करें:

```bash title="apps/app/.env.local"
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/qrdx
DATABASE_HTTP_ENDPOINT=http://localhost:4444/sql
```

## एनवायरनमेंट वेरिएबल [#environment-variables]

[`apps/app/.env.example`](https://github.com/qrdxinc/qrdx/blob/main/apps/app/.env.example) में हर वेरिएबल की सूची है, और साथ में यह नोट है कि उसकी वैल्यू कहाँ से मिलेगी। ऐप शुरू होते समय हर वैल्यू जाँचता है। कोई ज़रूरी वैल्यू न हो या गलत हो, तो ऐप शुरू होने से मना कर देता है और उस वेरिएबल का नाम बताता है।

### ज़रूरी [#required]

| वेरिएबल | उद्देश्य |
| --- | --- |
| `NEXT_PUBLIC_APP_URL` | आपके इंस्टेंस का पब्लिक URL |
| `DATABASE_URL` | Postgres कनेक्शन स्ट्रिंग (Compose सेट करता है) |
| `BETTER_AUTH_SECRET` | सेशन और कुकी पर साइन करता है |

एक OAuth प्रोवाइडर (GitHub या Google) जोड़ें, या ईमेल साइन-इन कोड के लिए Resend जोड़ें, ताकि लोग साइन इन कर सकें।

### वैकल्पिक सेवाएँ [#optional-services]

हर वेरिएबल सिर्फ़ अपना फ़ीचर चालू करता है। खाली वैल्यू को अनसेट माना जाता है। अगर वैल्यू सेट है लेकिन गलत है (जैसे URL जो URL नहीं है, या बहुत छोटी key), तो ऐप उस वेरिएबल के नाम के साथ रुक जाता है।

| सेवा | वेरिएबल | इसके बिना |
| --- | --- | --- |
| GitHub साइन-इन | `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | GitHub साइन-इन उपलब्ध नहीं होगा |
| Google साइन-इन | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google साइन-इन उपलब्ध नहीं होगा |
| ऑथ बेस URL | `BETTER_AUTH_URL` | हर रिक्वेस्ट से अनुमान लगाया जाता है, और लॉग में चेतावनी आती है |
| एडमिन पैनल | `ADMIN_EMAILS`, `ADMIN_USER_IDS` | कोई भी `/admin` नहीं खोल सकेगा |
| वर्कस्पेस सिंगल साइन-ऑन | `QRDX_EE_LICENSE` | सिंगल साइन-ऑन बंद रहता है: **Sign in with SSO** नहीं दिखता, SSO सेटिंग नहीं होतीं, और इसके साइन-इन रूट मौजूद नहीं होते। SSO `ee/` फ़ोल्डरों में है, जो QRdx कमर्शियल लाइसेंस के तहत हैं, इसलिए प्रोडक्शन में इस्तेमाल के लिए QRdx के साथ लिखित अनुबंध चाहिए। देखें [सिंगल साइन-ऑन](/docs/help/teams/single-sign-on) |
| वर्कस्पेस ऑडिट लॉग | `QRDX_EE_LICENSE` | ऑडिट लॉग बंद रहता है: कुछ रिकॉर्ड नहीं होता और **Settings** → **Audit log** नहीं मिलता। सिंगल साइन-ऑन की तरह यह भी `ee/` फ़ोल्डरों में QRdx कमर्शियल लाइसेंस के तहत है। इसकी पंक्तियाँ {facts.auditLogRetentionDays} दिन रखी जाती हैं; [शेड्यूल्ड वेबहुक जॉब](#scheduled-jobs) पुरानी पंक्तियाँ मिटा देता है। देखें [ऑडिट लॉग](/docs/help/teams/audit-log) |
| AI थीम, प्रॉम्प्ट एन्हांसमेंट और AI QR आर्ट (Vercel AI Gateway) | `AI_GATEWAY_API_KEY` | AI रिक्वेस्ट फ़ेल हो जाती हैं और AI पेज नेविगेशन और साइटमैप से हट जाते हैं। एडिटर सामान्य रूप से चलता है। key अपने Vercel अकाउंट में बनाएँ (AI Gateway, API keys); इस्तेमाल का बिल उसी अकाउंट के AI Gateway क्रेडिट से कटता है, और आपके ऐप को Vercel पर चलना ज़रूरी नहीं है। हर काम का मॉडल `apps/app/lib/ai/models.ts` में तय होता है |
| शॉर्ट-लिंक ऑरिजिन | `NEXT_PUBLIC_SHORT_LINK_BASE_URL` | [डायनेमिक कोड](/docs/dynamic-qr-codes#self-hosting) `NEXT_PUBLIC_APP_URL` इस्तेमाल करते हैं |
| स्कैन प्राइवेसी सॉल्ट | `SCAN_HASH_SALT` | `BETTER_AUTH_SECRET` से निकाला जाता है |
| फ़ाइल स्टोरेज (Cloudflare R2) | `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `R2_PUBLIC_BASE_URL` | अपलोड बंद रहते हैं; पेज फिर भी कहीं और होस्ट की गई फ़ाइलों से लिंक कर सकते हैं। देखें [फ़ाइलें](/docs/files#set-up-storage-self-hosting) |
| ईमेल (Resend) | `RESEND_API_KEY`, `EMAIL_FROM` | ईमेल भेजे नहीं जाते, सिर्फ़ लॉग होते हैं, इसलिए ईमेल साइन-इन कोड नहीं भेजे जा सकते; टीम इनवाइट कॉपी करने लायक लिंक से होते हैं। देखें [नोटिफ़िकेशन](/docs/notifications#self-hosting) |

</Callout>

### शेड्यूल्ड जॉब [#scheduled-jobs]

दो रूट बार-बार होने वाला काम करते हैं: `/api/cron/webhooks` फ़ेल हुई वेबहुक डिलीवरी दोबारा आज़माता है और पुरानी ऑडिट लॉग पंक्तियाँ मिटाता है, और `/api/cron/digest` साप्ताहिक डाइजेस्ट भेजता है। Vercel पर `apps/app/vercel.json` इन्हें शेड्यूल करता है। कहीं और, जब तक आप खुद इन्हें कॉल नहीं करते, कोई इन्हें नहीं बुलाता। `CRON_SECRET` सेट करें और अपने शेड्यूलर से उसके साथ दोनों को कॉल करें:

```text title="crontab (times in UTC)"
0 4 * * *  curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://qr.example.com/api/cron/webhooks
0 9 * * 1  curl -fsS -H "Authorization: Bearer $CRON_SECRET" "https://qr.example.com/api/cron/digest?shard=all"
```

हेडर के बिना, प्रोडक्शन में ये रूट `401` देते हैं। डाइजेस्ट के `shard` पैरामीटर के बारे में [नोटिफ़िकेशन](/docs/notifications#self-hosting) में बताया गया है।

## Reverse proxy और HTTPS [#reverse-proxy-and-https]

ऐप को किसी reverse proxy (जैसे Caddy, nginx या Traefik) के पीछे रखें जो TLS को terminate करे, और port 3000 को सीधे इंटरनेट पर एक्सपोज़ न करें। Rate limiting, सुरक्षा ईमेल और [ऑडिट लॉग](/docs/help/teams/audit-log) क्लाइंट का IP पहले `X-Real-IP` से पढ़ते हैं, फिर `X-Forwarded-For` के पहले address से (Vercel पर इन दोनों के बीच `X-Vercel-Forwarded-For` आता है)। इसलिए proxy को ये headers सेट करने होंगे और ऐप तक पहुँचने का रास्ता सिर्फ़ proxy से होना चाहिए। Proxy से `X-Real-IP` उस address पर सेट करवाएँ जिससे उसे कनेक्शन मिला था। जो proxy सिर्फ़ `X-Forwarded-For` में जोड़ता है, उसमें क्लाइंट कोई भी address सबसे पहले डाल सकता है।

```nginx title="nginx server block (the relevant lines)"
location / {
  proxy_pass http://127.0.0.1:3000;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

Caddy ये headers डिफ़ॉल्ट रूप से सेट करता है। HTTPS चालू होने के बाद `NEXT_PUBLIC_APP_URL` और `BETTER_AUTH_URL` को `https://` वाले URL पर बदलें, OAuth callback URL अपडेट करें और rebuild करें।

### Content-Security-Policy [#content-security-policy]

Production build QRdx के अपने पेजों पर Content-Security-Policy भेजते हैं: साइन-इन किए हुए पेजों को हर request पर नया script nonce मिलता है, और prerender किए गए पेजों को script hosts की allowlist मिलती है। होस्टेड पेज (`/p`) पर ढीली policy लगती है, क्योंकि वे मालिक के pixels चलाते हैं और कहीं से भी मीडिया एम्बेड करते हैं। अगर आपका reverse proxy भी `Content-Security-Policy` सेट करता है, तो ब्राउज़र दोनों लागू करते हैं, इसलिए उसे proxy पर न रखें। नया setup जाँचते समय policy को report-only के रूप में भेजने के लिए `CSP_REPORT_ONLY=1` सेट करें; उल्लंघन `/api/csp-report` में लॉग होते हैं। Vercel के बाहर HTTPS पर चलाते समय `CSP_HTTPS=1` जोड़ें, ताकि ब्राउज़र किसी भी `http://` resource को अपग्रेड कर लें। दोनों वहीं पढ़े जाते हैं जहाँ ऐप चलता है, और prerender किए गए पेजों के header के लिए वहाँ भी जहाँ वह build होता है; Dockerfile इन्हें build को नहीं देता, इसलिए अगर prerender किए गए पेजों को इनकी ज़रूरत है तो इन्हें build arguments के रूप में भी जोड़ें।

## QRdx अपडेट करें [#update-qrdx]

पहले डेटाबेस का बैकअप लें (नीचे देखें)। फिर pull करें और rebuild करें। ऐप शुरू होने से पहले `migrate` सर्विस schema को फिर से sync करती है।

```bash title="Terminal"
git pull
docker compose up -d --build
```

मैन्युअल setup के लिए `git pull`, `bun install` और `bun run db:push` चलाएँ, फिर rebuild करके restart करें।

अगर किसी schema बदलाव से डेटा ड्रॉप होगा, तो `drizzle-kit push` पुष्टि माँगता है और `migrate` सर्विस ऐसे जवाब का इंतज़ार करती रहती है जो वह पा नहीं सकती। ऐसे में बदलावों को देखने और पुष्टि करने के लिए इसे टर्मिनल में चलाएँ:

```bash title="Terminal"
docker compose run --rm migrate
```

## बैकअप और restore [#back-up-and-restore]

QRdx जो कुछ भी स्टोर करता है वह Postgres में है, सिवाय अपलोड की गई फ़ाइलों के, जो आपके R2 bucket में हैं। हर अपडेट से पहले और तय समय पर डेटाबेस का dump लें:

```bash title="Terminal"
docker compose exec db pg_dump -U postgres qrdx > qrdx-backup.sql
```

खाली डेटाबेस में restore करने के लिए:

```bash title="Terminal"
docker compose exec -T db psql -U postgres qrdx < qrdx-backup.sql
```

Neon के साथ उसके अपने बैकअप और branching का इस्तेमाल करें।

## qrdx.dev से क्या अलग है [#what-is-different-from-qrdxdev]

- **Docs** qrdx.dev पर खुलते हैं। आपका instance हर docs URL को वहीं redirect करता है।
- **पेमेंट और प्लान** के लिए Polar चाहिए। इसके बिना हर अकाउंट पर फ़्री की सीमाएँ लागू रहती हैं और कोई अपग्रेड नहीं कर सकता। सीमाएँ खुद `apps/app/lib/plans.ts` में हैं, जिन्हें आप अपने instance के लिए बदल सकते हैं।
- **एफ़िलिएट प्रोग्राम, इनवॉइस से भुगतान के अनुरोध, नॉन-प्रॉफ़िट डिस्काउंट और enterprise संपर्क फ़ॉर्म** QRdx की अपनी सेल्स का हिस्सा हैं और सिर्फ़ वहीं चलते हैं जहाँ QRdx खुद चलता है। सेल्फ़-होस्ट की गई कॉपी में इनमें से कुछ नहीं होता।
- **स्कैन की लोकेशन:** देश, क्षेत्र और शहर Vercel के geo headers से आते हैं। Cloudflare के पीछे सिर्फ़ देश पढ़ा जाता है (`CF-IPCountry`); बाकी जगह लोकेशन अज्ञात दिखती है, और [एरिया नियम](/docs/precise-location#route-scans-by-area) सिर्फ़ उन स्कैन से मेल खाते हैं जिनमें लोकेशन शेयर की गई हो।
- **कस्टम डोमेन** DNS `TXT` रिकॉर्ड से verify होते हैं और आपका reverse proxy उन्हें route करता है, जब तक आप Vercel पर Domains API वेरिएबल सेट करके न चला रहे हों। **Set up with …** बटन के लिए आपका अपना Domain Connect template चाहिए: QRdx का template सिर्फ़ qrdx.dev पर काम करता है।
- **चैट बॉट और इंटीग्रेशन** में से हर एक के लिए उस सर्विस पर रजिस्टर किया हुआ आपका अपना ऐप चाहिए (ऊपर की तालिका देखें)।
- **एडमिन पेज** ऐप खुद सर्व करता है; qrdx.dev इनमें से कुछ को अलग console पर proxy करता है।

## समस्या निवारण [#troubleshooting]

### शुरू होते समय "Invalid environment variables" [#invalid-environment-variables-on-startup]

लॉग हर छूटे हुए या अमान्य वेरिएबल का नाम बताता है, फिर यह कि उसे कहाँ सेट करना है। या तो कोई ज़रूरी वैल्यू छूट गई है, या कोई वैकल्पिक वैल्यू अमान्य सेट है: ऐसा URL जो पूरा `http://` या `https://` address नहीं है, या बहुत छोटा secret। खाली वैल्यू को unset माना जाता है और वह ठीक है। `.env` में बताए गए वेरिएबल ठीक करें और `docker compose up -d app` से container दोबारा बनाएँ।

### OAuth `redirect_uri` मेल नहीं खाता [#oauth-redirect_uri-mismatch]

आपके OAuth ऐप में callback URL ठीक `<NEXT_PUBLIC_APP_URL>/api/auth/callback/github` या `/api/auth/callback/google` होना चाहिए। `BETTER_AUTH_URL` को `NEXT_PUBLIC_APP_URL` वाले ही base URL पर सेट करें।

### ऐप डेटाबेस तक नहीं पहुँच पाता (`fetch failed`) [#the-app-cant-reach-the-database-fetch-failed]

सादे Postgres के साथ `DATABASE_HTTP_ENDPOINT` चल रहे proxy की ओर इशारा करना चाहिए। देखें कि `docker compose ps db-proxy` उसे चलता हुआ दिखा रहा है।

### `migrate` कभी खत्म नहीं होता [#migrate-never-finishes]

`drizzle-kit push` पुष्टि का इंतज़ार कर रहा है। टर्मिनल में `docker compose run --rm migrate` चलाएँ और जवाब दें; देखें [QRdx अपडेट करें](#update-qrdx)।

### बदली हुई `NEXT_PUBLIC_*` वैल्यू का कोई असर नहीं होता [#a-changed-next_public_-value-has-no-effect]

इमेज rebuild करें: `docker compose up -d --build`।

### Port 4444 पहले से इस्तेमाल में है [#port-4444-is-already-in-use]

`docker-compose.yml` में `db-proxy` का port mapping बदलें। इसे सिर्फ़ host पर लोकल डेवलपमेंट इस्तेमाल करता है।

### "the --mount option requires BuildKit" [#the---mount-option-requires-buildkit]

आपके Docker में BuildKit नहीं है। `buildx` plugin इंस्टॉल करें, या Docker अपडेट करें।

### Build `Killed` या exit code 137 के साथ रुक जाता है [#the-build-stops-with-killed-or-exit-code-137]

Docker की मेमोरी खत्म हो गई। उसे कम से कम 8 GB दें (Docker Desktop: **Settings** → **Resources**) और `docker compose up -d --build` फिर से चलाएँ।

### "sign-in code email is off for this deployment" [#sign-in-code-email-is-off-for-this-deployment]

जब `NEXT_PUBLIC_APP_URL` `localhost` हो, तब ईमेल कोड नहीं भेजे जाते। लोकल टेस्ट के लिए GitHub या Google साइन-इन इस्तेमाल करें।

अब भी अटके हैं? `docker compose logs app` के आउटपुट के साथ, secrets हटाकर, [issue खोलें](https://github.com/qrdxinc/qrdx/issues)।
