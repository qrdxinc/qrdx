コードのコントロールは、[動的QRコード](/docs/dynamic-qr-codes)のスキャンを通すかどうかを決める機能です。一定期間だけ使えるコード（イベントやプロモーションなど）、特定の人だけが使えるコード（パスワード）、決まった回数だけ使えるコードにしたいときに使います。印刷済みのコードを刷り直さずに無効にしたいときにも便利です。

<Callout type="info" title="一時停止は無料、そのほかは Pro">
  一時停止はすべてのプランで使えます。パスワード、開始日と終了日、スキャン上限、フォールバックURLは Pro と Business の機能です。[プランと制限](/docs/plans-and-limits)をご覧ください。
</Callout>

お急ぎの方は、手順をまとめた短いページをご覧ください。[コードの一時停止、スケジュール、制限](/docs/help/dynamic-codes/pause-schedule-limit)と[パスワードでコードを保護する](/docs/help/dynamic-codes/password)です。

## 仕組み [#how-it-works]

コントロールはすべて、コードの **Settings** タブにある **Access & schedule** パネルで設定します（[Codes](/dashboard?to=codes)からコードを開きます）。スキャンのたびに、QRdx はリダイレクトの前にコントロールを順番に確認します。コードが一時停止中か、開始済みか、終了済みか、スキャン上限を超えていないか、パスワードが必要か、という順です。最初に失敗した確認によって、スキャンした人に表示される内容が決まります。変更は次のスキャンから反映され、コードを刷り直す必要はありません。

<Shot id="code-settings" />

| コントロール | スキャンした人に表示される内容 | プラン |
| --- | --- | --- |
| 一時停止 | フォールバックURL、または中立的な「This campaign is paused」ページ | すべてのプラン |
| パスワード | パスワード画面。正しいパスワードを入力するとコードが開きます | Pro と Business |
| 開始 | 開始前は「This campaign hasn't started yet」 | Pro と Business |
| 終了 | 終了後はフォールバックURL、または「This campaign has ended」 | Pro と Business |
| スキャン上限 | 上限に達すると、フォールバックURL、または「終了」ページ | Pro と Business |
| フォールバックURL | 一時停止中、終了後、上限超過のコードの転送先 | Pro と Business |

## 一時停止 [#pause]

**Pause code** をオンにするとコードを一時的に停止できます。たとえば、2つのイベントの間などに使えます。オフにすると再開します。コードの **⋯** メニューにも **Pause** と **Resume** があり、Codes一覧の一括操作では複数のコードをまとめて一時停止できます。コードの一時停止中にスキャンされると、フォールバックURLを設定している場合はそこへ移動し、設定していない場合はキャンペーンが一時停止中であることを示すシンプルなページが表示されます。

## パスワード [#password]

4〜64文字のパスワードを設定すると、コードをスキャンした人にはまずパスワード画面が表示されます。正しいパスワードを入力すると、そのブラウザは6時間ロック解除されたままになります。これは短縮リンクと、そこから開くホスト型ページの両方に適用されます。パスワードを変更すると、古いパスワードでロックを解除したすべてのブラウザが再びロックされます。パスワードを削除すると、コードは再びだれでも開けるようになります。

<Shot id="scan-password" />

パスワードは bcrypt ハッシュとして保存されるため、QRdx であとからパスワードを表示することはできず、置き換えることだけができます。同じ訪問者による誤入力の繰り返しは、入力の受け付けが遅くなります。パスワードはコードとは別の方法で共有してください。両方を知っている人はだれでもアクセスできます。

## 開始日と終了日 [#start-and-end-dates]

- **Starts:** 開始日時までは、スキャンすると「This campaign hasn't started yet. Please scan this code again later.」と表示されます。開始前にはフォールバックURLは使われません。
- **Ends:** 終了日時以降は、スキャンするとフォールバックURLへ移動するか、「This campaign has ended」と表示されます。

日時は使用しているタイムゾーンで入力し、正確な時刻として保存されます。そのため、コードはどこでも同じ瞬間に終了します。終了日時は開始日時より後にする必要があります。

## スキャン上限 [#scan-limit]

上限は、分析と同じ方法でスキャンを数えます。ボットとリンクプレビューは数えず、同じアドレスからの1分以内の繰り返しスキャンは1回として数えます。コードが上限に達すると、以降のスキャンはフォールバックURLまたは「終了」ページへ移動します。上限を引き上げるか解除すると、コードは再び使えるようになります。

## フォールバックURL [#fallback-url]

一時停止中、終了後、上限超過のコードの転送先となるアドレスです。たとえば、ホームページや次のキャンペーンのページを指定します。設定しない場合、スキャンした人には小さな中立的なページが表示されます。このページには広告、QRdx の宣伝、登録の案内は一切表示されず、キャンペーンの状態と **Report abuse** リンクだけが表示されます。フォールバックURLは、転送先と同じ安全性チェックを受けます。

## 制限とプラン [#limits-and-plans]

- 一時停止はすべてのプランで使えます。
- パスワード、日付、スキャン上限、フォールバックURLの設定や変更には Pro または Business が必要です。
- ダウングレードしても、コードが終了したりロックされたりすることはありません。Pro のときに設定したコントロールは設定どおりに動作し続け、どのプランでも削除できます。

## リンクの安全性チェック [#safety-checks-on-links]

QRdx は、転送先とフォールバックURLを保存するときにすべて確認します。

- [Google Web Risk](https://cloud.google.com/web-risk) にマルウェア、フィッシング、不要なソフトウェアとして登録されているリンクは拒否されます（サーバーに Web Risk キーが設定されている場合）。大量の一括処理などで Web Risk が時間内に応答できないときは、コードがいったん作成され、少し後にリンクが再確認されます。その時点で Web Risk に登録されていた場合、コードは無効になり、審査担当者が確認します。
- `javascript:`、`data:` などのウェブ以外のリンクは拒否されます。
- アカウント作成から最初の7日間は、URL短縮サービス、IPアドレスそのもの、似た文字を使った（ホモグリフ）ドメインを指すコードは、無効の状態で保存され、**審査待ち**になります。パネルにその旨が表示されます。お客様側での操作は不要で、問題がなければ審査担当者がコードを有効にします。
- 新しいアカウントが作成できる動的コードは1時間あたり最大30個です。有料プランのワークスペースでは {facts.newPaidAccountHourlyCodes} 個です。これを超えると、エラーメッセージに待つ必要がある分数が表示され、ダッシュボードからのインポートはその時間まで一時停止します。

だれでも [qrdx.dev/report-abuse](/report-abuse) からコードを報告できます。審査の結果として無効になったコードはすべてのユーザーに対して動作しなくなり、所有者が再び有効にすることはできません。[有害なQRコードを報告する](/docs/help/privacy-and-security/report-abuse)をご覧ください。

## 開発者向け [#for-developers]

REST API ではコードの作成、更新、削除はできますが、コントロールは設定できません。コントロールはダッシュボードで設定します。API レスポンスのコードの `status` は、コードが有効かアーカイブ済みかを示します。コントロールによってブロックされたスキャンはスキャンとして記録されないため、`scan.created` の[Webhook](/docs/webhooks)イベントとしては配信されません。

## セルフホスティング [#self-hosting]

- `WEB_RISK_API_KEY`: Web Risk API を有効にした Google Cloud の API キーです。設定しない場合、リンクは上記のオフラインルールだけで確認されます。
- `SAFETY_YOUNG_ACCOUNT_DAYS`、`SAFETY_YOUNG_ACCOUNT_DYNAMIC_PER_HOUR`、`SAFETY_RECHECK_BATCH`: それぞれ、7日間、1時間あたり30個、Web Risk の再確認の件数を変更します。
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` と `TURNSTILE_SECRET_KEY`: 公開の報告フォームで Cloudflare Turnstile を使うための設定です（任意）。
- ロック解除用のCookieは `BETTER_AUTH_SECRET` で署名されます。

[セルフホスティング](/docs/self-hosting#optional-services)をご覧ください。
