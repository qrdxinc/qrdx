호스팅 페이지에는 QRdx에 업로드한 파일을 표시할 수 있습니다. 메뉴판이나 브로슈어 PDF, 사진 갤러리, 음악이나 팟캐스트, 동영상 등이 해당합니다. 업로드한 파일은 사이드바의 **파일**에 모이고, 업로드한 워크스페이스에 속하며, 각 파일에는 파일을 교체해도 계속 동작하는 고정 링크가 있습니다. 파일을 따로 올려 둘 곳이 없을 때나, 페이지를 건드리지 않고 다음 시즌 메뉴판으로 바꾸고 싶을 때 사용하세요.

<Callout type="info" title="요금제">
  무료는 워크스페이스당 저장 용량 50 MB, 파일당 최대 10 MB를 제공합니다. Pro는 5 GB와 100 MB, Business는 50 GB와 250 MB입니다. [요금제와 한도](/docs/plans-and-limits)를 참고하세요.
</Callout>

## 작동 방식 [#how-it-works]

<Diagram id="file-delivery" />

브라우저가 파일을 저장소 버킷에 직접 업로드합니다. 그러면 QRdx가 파일을 검사합니다. 크기를 확인하고, 첫 바이트가 해당 형식의 파일이 맞는지 확인합니다. 검사를 통과한 버전은 파일 고유의 위치로 복사되고, `https://qrdx.dev/api/files/<id>` 링크가 부여됩니다. 페이지와 코드는 이 링크를 사용하므로 파일을 교체해도 달라지는 것이 없습니다.

## 업로드할 수 있는 파일 [#what-you-can-upload]

| 종류 | 형식 |
| --- | --- |
| PDF | PDF |
| 이미지 | JPEG, PNG, WebP, GIF, AVIF |
| 오디오 | MP3, M4A, AAC, Ogg, WAV |
| 동영상 | MP4, WebM, MOV |

H.264 동영상이 담긴 MP4는 모든 브라우저에서 재생됩니다. 휴대폰으로 촬영한 MOV 파일도 대개 재생되지만, 브라우저에서 재생되지 않으면 MP4로 변환하세요. SVG, HTML, 압축 파일, 오피스 문서는 업로드할 수 없으므로 저장소에서 제공되는 어떤 파일도 방문자의 브라우저에서 코드를 실행할 수 없습니다.

모든 업로드는 사용하기 전에 검사합니다. 크기가 알려 준 값과 일치해야 하고, 첫 바이트가 실제로 해당 형식의 파일이어야 합니다(`.pdf`로 이름만 바꾼 HTML 페이지는 거부됩니다). 거부된 업로드는 저장소에서 삭제되고 **차단됨**으로 표시됩니다.

## 페이지에서 파일 사용하기 [#use-files-on-a-page]

파일을 표시하는 블록은 다섯 가지입니다. 각 블록은 업로드한 파일 또는 다른 곳에 호스팅된 파일의 링크를 사용할 수 있습니다.

- **PDF**는 태블릿과 컴퓨터에서 업로드한 문서를 페이지 안에 바로 보여 주며, **PDF 열기**(휴대폰에서는 전체 화면 뷰어)와 선택 사항인 다운로드 버튼이 함께 표시됩니다. 다른 사이트의 PDF를 링크로 연결하면 **PDF 열기** 버튼이 표시됩니다.
- **갤러리**는 사진을 1~3열 그리드로 보여 줍니다. 사진을 탭하면 전체 화면으로 열리고, 스와이프하거나 화살표 키로 넘겨 볼 수 있습니다.
- **오디오**는 커버 이미지와 재생 목록이 있는 트랙을 재생하며, 한 곡이 끝나면 다음 곡이 시작됩니다. 다운로드 버튼은 선택 사항입니다.
- **동영상 파일**은 업로드한 MP4 또는 WebM을 재생하며, GIF처럼 음소거 상태로 반복 재생하도록 설정할 수도 있습니다. YouTube, Vimeo, Loom 동영상은 **동영상** 블록을 사용하세요. 누군가 재생을 탭하기 전까지는 동영상 사이트의 어떤 것도 불러오지 않고 영상을 삽입합니다.
- **다운로드**는 사람들이 저장할 수 있는 파일을 나열하며, 파일마다 별도의 라벨을 붙일 수 있습니다.

**새 코드**의 **PDF**, **이미지**, **MP3 / 오디오**, **동영상**, **플레이리스트** 페이지 유형을 선택하면 이 블록들이 미리 배치된 상태로 시작할 수 있습니다.

블록에서 **업로드**를 선택하면 기기의 파일을 추가하고, **내 파일에서 선택**을 선택하면 이전에 업로드한 파일을 다시 사용하며, 링크를 붙여 넣을 수도 있습니다.

## 파일 교체 또는 삭제 [#replace-or-delete-a-file]

사이드바에서 **파일**을 열고 파일 옆의 메뉴를 사용하세요.

- **링크 복사**는 파일 고유의 링크(`https://qrdx.dev/api/files/<id>`)를 복사합니다. 이 링크를 동적 QR 코드의 이동 주소로 사용할 수도 있습니다.
- **파일 교체…**는 같은 링크 뒤에 새 콘텐츠를 업로드합니다. 예를 들어 다음 시즌 메뉴판으로 바꿀 때 사용합니다. 해당 파일을 사용하는 페이지와 코드에는 1분 안에 새 버전이 표시됩니다. 파일은 같은 종류의 파일로만 교체할 수 있습니다(PDF는 PDF로만 교체).
- **삭제**는 파일을 완전히 제거합니다. 파일을 사용하는 페이지나 코드가 있으면 QRdx가 먼저 목록을 보여 줍니다. 삭제 후에는 해당 페이지에서 파일이 있던 자리에 "파일을 사용할 수 없음"이 표시됩니다.

<Shot id="files-page" />

멤버는 자신이 업로드한 파일을 교체하고 삭제할 수 있으며, 소유자와 관리자는 워크스페이스의 모든 파일을 관리할 수 있습니다.

## 신고된 파일 [#reported-files]

모든 호스팅 페이지에는 **악용 신고** 링크가 있습니다. 파일이 규칙을 위반하거나 저작권자가 삭제를 요청하면 QRdx가 해당 파일을 차단할 수 있습니다. 차단된 파일은 1분 안에 모든 페이지와 QRdx 링크에서 제공이 중단되고(페이지에는 "파일을 사용할 수 없음"이 표시됩니다), 동일한 사본(최대 25 MB)은 다시 업로드할 수 없습니다.

## 한도와 요금제 [#limits-and-plans]

| 요금제 | 워크스페이스당 저장 용량 | 최대 파일 크기 |
| --- | --- | --- |
| 무료 | 50 MB | 10 MB |
| Pro | 5 GB | 100 MB |
| Business | 50 GB | 250 MB |

워크스페이스에는 소유자와 결제 멤버 중 가장 높은 요금제가 적용됩니다. 한도는 새 업로드만 막습니다. 요금제를 낮춘 뒤이거나 워크스페이스가 저장 용량을 초과한 경우에도, 이미 업로드한 파일은 그 파일을 사용하는 모든 페이지에서 계속 제공됩니다. 새 파일을 업로드하려면 필요 없는 파일을 삭제하거나 요금제를 업그레이드하세요. 끝나지 않은 업로드는 두 시간 후부터 저장 용량에 포함되지 않습니다.

## 개발자용 [#for-developers]

파일은 대시보드에서 업로드하고 관리합니다. API에서는 코드의 디자인에 파일 ID로 업로드한 로고를 사용할 수 있습니다. [코드 스타일의 로고](/docs/developers/rest-api#code-logos)를 참고하세요.

## 저장소 설정(셀프 호스팅) [#set-up-storage-self-hosting]

파일 업로드에는 [Cloudflare R2](https://developers.cloudflare.com/r2/)를 사용합니다. R2가 없으면 파일 페이지에 업로드를 사용할 수 없다고 표시되고, 업로드 API는 "Storage not configured on this server."라는 메시지와 함께 `503`으로 응답하며, 업로드 관련 페이지 유형 다섯 가지는 선택 화면에서 숨겨집니다. 이 경우에도 블록에서 다른 곳에 호스팅된 파일의 링크는 사용할 수 있습니다.

1. Cloudflare 대시보드에서 **R2**를 열고 버킷을 만듭니다. 예: `qrdx-files`
2. **R2** → **Manage API tokens**에서 해당 버킷에 대한 **Object Read & Write** 권한이 있는 토큰을 만듭니다.
3. 다음 환경 변수를 설정하고 다시 시작합니다.

   ```bash title="apps/app/.env.local"
   R2_ACCOUNT_ID=your-cloudflare-account-id
   R2_ACCESS_KEY_ID=token-access-key-id
   R2_SECRET_ACCESS_KEY=token-secret-access-key
   R2_BUCKET=qrdx-files
   # Optional: serve files from a public bucket URL or custom domain
   R2_PUBLIC_BASE_URL=https://files.example.com
   ```

4. 버킷에 CORS 정책을 추가합니다(**Settings** → **CORS policy**). 브라우저가 R2에 직접 업로드하므로, 버킷은 앱의 오리진에서 오는 `Content-Type` 헤더가 포함된 `PUT` 요청을 허용해야 합니다.

   ```json title="R2 bucket CORS policy"
   [
     {
       "AllowedOrigins": ["https://qrdx.example.com", "http://localhost:3000"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["Content-Type"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

   `https://qrdx.example.com`은 사용자가 대시보드를 열 때 쓰는 오리진(스킴과 호스트, 끝에 슬래시 없음)으로 바꾸세요. `http://localhost:3000`은 로컬 개발 서버에서 업로드할 때만 남겨 두세요.

### 공개 파일 또는 프리사인드 링크 [#public-files-or-presigned-links]

방문자는 항상 `/api/files/<id>`를 통해 파일을 엽니다. 이 주소는 저장된 객체로 리디렉션됩니다.

- `R2_PUBLIC_BASE_URL`을 설정하면(버킷에 연결한 사용자 지정 도메인 또는 `r2.dev` URL. `r2.dev` URL은 Cloudflare가 요청 수를 제한하며 테스트용으로만 권장합니다) 공개 URL로 리디렉션됩니다. 객체 키에는 임의의 ID가 들어 있어 파일 목록을 조회하거나 주소를 추측할 수 없습니다.
- 설정하지 않으면 버킷은 비공개로 유지되며, 모든 리디렉션은 한 시간 후에 만료되는 프리사인드 링크로 이루어집니다.

어느 쪽이든 교체, 삭제 또는 차단된 파일은 1분 안에 QRdx 링크로 제공되지 않습니다. 차단된 파일은 공개 URL에서도 즉시 사라집니다. 해당 객체는 임의의 문자열이 포함된 `quarantine/` 키로 이동하고(관리자가 복원할 수 있도록 보관됩니다), QRdx 링크는 `410 Gone`으로 응답합니다.

브라우저는 `staging/` 키로 업로드합니다. 업로드 검사가 끝나면 QRdx가 검사를 통과한 버전 그대로를 파일 고유의 키로 복사하므로, 아직 유효한 업로드 링크로는 검사를 마친 파일을 교체할 수 없습니다.

<Callout type="info" title="중단된 업로드 정리">
  끝나지 않은 업로드는 두 시간 후부터 저장 용량에 포함되지 않으며, 다음에 누군가 해당 워크스페이스에 업로드할 때 정리됩니다. 버킷에 객체 수명 주기 규칙(**Settings** → **Object lifecycle rules**)을 추가해 접두사가 `staging/`인 객체를 하루 뒤에 삭제하도록 설정하면, 중단된 업로드의 잔여 파일도 함께 정리됩니다.
</Callout>
