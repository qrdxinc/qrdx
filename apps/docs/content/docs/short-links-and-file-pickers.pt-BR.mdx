As contas conectadas permitem que o editor de QR use links que ficam em outras ferramentas suas: um link curto que você gerencia no Bitly, Rebrandly ou Short.io, ou um link de compartilhamento de um arquivo no Dropbox ou em outro drive na nuvem. O QR code codifica esse link, então você continua usando a ferramenta que já conhece. Use isso quando seus links precisam continuar nas análises dessa ferramenta, ou quando o código deve abrir um arquivo que você guarda em um drive na nuvem.

<Callout type="info" title="Todos os planos">
  As contas conectadas pertencem à sua conta de usuário e funcionam em todos os planos. Se você prefere manter o destino editável no próprio QRdx, com análises de leituras, use um [QR code dinâmico](/docs/dynamic-qr-codes).
</Callout>

## Como funciona [#how-it-works]

Conecte uma conta em [Configurações → Integrações](/settings/integrations) e ela aparece no tipo **URL** do editor de QR, no menu **Usar um link de…** ao lado do campo **Endereço do site**. Em **Suas contas**, cada serviço indica o que faz:

- **Encurtar**: Bitly, Rebrandly ou Short.io. Crie um link em **Criar novo** ou escolha um que você já tem em **Usar existente**. O QR code codifica esse link curto, então você pode mudar depois, nesse serviço, para onde ele aponta, e o serviço conta os cliques.
- **Arquivo**: Dropbox<IfAvailable integration="onedrive">, OneDrive</IfAvailable><IfAvailable integration="box">, Box</IfAvailable><IfAvailable integration="notion">, Notion</IfAvailable>. Navegue ou pesquise e escolha um arquivo ou pasta. O QRdx cria o link de compartilhamento do item e o QR code o codifica.

O mesmo menu lista suas outras fontes de conteúdo conectadas, como links de pagamento e de agendamento. Os serviços que você ainda não conectou ficam em **Conectar uma conta**, no fim do menu.

<Shot id="use-a-link-from" />

Tokens e chaves de API são armazenados criptografados, e você pode desconectar a qualquer momento.

## Links curtos [#short-links]

| Serviço | Como conectar | Domínios | Parte final |
| --- | --- | --- | --- |
| Bitly | Entre com o Bitly ou cole um token de acesso genérico (Settings → Developer settings → API) | bit.ly e seus domínios personalizados | Escolhida pelo Bitly |
| Rebrandly | Cole uma chave de API (Account → API keys) | rebrand.ly e seus domínios personalizados | Seu próprio slashtag, ou aleatório |
| Short.io | Cole uma chave de API secreta (Integrations & API → API) | Seus domínios do Short.io | Seu próprio caminho, ou aleatório |

A página de configurações de cada integração mostra seus domínios e permite escolher o padrão para novos links. Você ainda pode escolher outro domínio em cada link.

<Callout type="info" title="Mudar o destino depois">
  O QRdx cria o link; para editar para onde ele aponta, use o Bitly, Rebrandly ou Short.io. O Bitly só permite que planos pagos mudem o destino de um link.
</Callout>

## Seletores de arquivos [#file-pickers]

O **Dropbox** codifica um link compartilhado (criado ou, se já existir, reaproveitado). Qualquer pessoa com o link pode abri-lo, a menos que sua equipe permita apenas links de equipe.

<IfAvailable integration="onedrive">

O **OneDrive** codifica um link de compartilhamento somente para visualização. Qualquer pessoa com o link pode abri-lo; só a sua organização pode, quando o administrador desativou os links "Qualquer pessoa".

</IfAvailable>

<IfAvailable integration="box">

O **Box** codifica o link compartilhado do item, definido como "Pessoas com o link". Qualquer pessoa com o link pode abri-lo; só a sua empresa pode, quando o administrador exige isso.

</IfAvailable>

<IfAvailable integration="notion">

O **Notion** codifica o link "Publicar na web" da página. Qualquer pessoa pode abri-lo depois que a página for publicada.

</IfAvailable>

Quando o link não pode ser aberto por todos, o QRdx avisa logo depois que você escolhe, para que um código impresso não leve as pessoas a uma página de login.

<IfAvailable integration="notion">

**Páginas do Notion.** O QRdx só enxerga as páginas que você compartilha com ele: o Notion pergunta quais quando você conecta. Para adicionar mais depois, abra a página no Notion, clique em **•••** → **Conexões** e adicione o QRdx (ou reconecte e escolha as páginas). A API do Notion não consegue publicar uma página. Publique você mesmo (**Compartilhar** → **Publicar** → **Publicar na web**) e escolha a página de novo para que o QRdx use o link público.

</IfAvailable>

### Arquivos em páginas hospedadas [#files-on-hosted-pages]

As páginas hospedadas também podem usar arquivos na nuvem: os blocos de PDF, áudio, vídeo e download ganham um botão **Do Dropbox** ao lado do botão de upload quando o Dropbox é o único drive conectado, ou **Do armazenamento na nuvem** quando você conectou mais de um<IfAvailable integration="onedrive">, incluindo o OneDrive</IfAvailable><IfAvailable integration="box">, incluindo o Box</IfAvailable>. Para o Dropbox<IfAvailable integration="box"> e o Box</IfAvailable>, os blocos da página recebem um link direto para o arquivo, de modo que os players de áudio e vídeo e o visualizador de PDF consigam carregá-lo.<IfAvailable integration="onedrive"> Os links de compartilhamento do OneDrive abrem o visualizador do OneDrive, então o bloco os mostra como um link.</IfAvailable>

## Desconectar [#disconnecting]

Ao desconectar, o token armazenado é apagado. Para o Dropbox<IfAvailable integration="box">, Box</IfAvailable><IfAvailable integration="notion">, Notion</IfAvailable>, o QRdx também o revoga no serviço. Para Bitly, Rebrandly e Short.io, apague também a chave nesse serviço se você não for mais usá-la<IfAvailable integration="onedrive">; para o OneDrive, remova o QRdx das permissões de aplicativos da sua conta Microsoft</IfAvailable>.

Os QR codes que você já criou continuam funcionando: eles guardam o link curto ou o link de compartilhamento, não o seu token.

## Limites e planos [#limits-and-plans]

As contas conectadas não têm limite de plano próprio. Do ponto de vista do QRdx, os links que elas criam são estáticos: o QRdx não conta as leituras deles nem pode mudar para onde apontam. O plano de cada serviço define o que você pode fazer com o link lá.

## Hospedagem própria [#self-hosting]

Rebrandly e Short.io não precisam de nada no servidor. As outras integrações precisam de um app em cada serviço, com o ID e o segredo do cliente no ambiente; sem isso, a integração fica oculta em produção (no desenvolvimento local aparece um selo **Requer configuração**). O Bitly continua funcionando sem isso, por meio de tokens de acesso colados.

| Integração | Variáveis | URI de redirecionamento |
| --- | --- | --- |
| Bitly (login) | `BITLY_CLIENT_ID`, `BITLY_CLIENT_SECRET` | `<app url>/api/integrations/bitly/callback` |
| Dropbox | `DROPBOX_CLIENT_ID`, `DROPBOX_CLIENT_SECRET` | `<app url>/api/integrations/dropbox/callback` |
| OneDrive | `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET` | `<app url>/api/integrations/onedrive/callback` |
| Box | `BOX_CLIENT_ID`, `BOX_CLIENT_SECRET` | `<app url>/api/integrations/box/callback` |
| Notion | `NOTION_CLIENT_ID`, `NOTION_CLIENT_SECRET` | `<app url>/api/integrations/notion/callback` |

`<app url>` é `http://localhost:3000` no desenvolvimento e a URL de produção nos outros casos. Toda integração também precisa de `INTEGRATION_ENCRYPTION_KEY` em produção, que criptografa os tokens e chaves armazenados.

Escopos a solicitar:

- **Dropbox:** `account_info.read`, `files.metadata.read`, `sharing.read`, `sharing.write`
- **OneDrive:** `offline_access`, `Files.ReadWrite` (o Microsoft Graph precisa de acesso de escrita para criar links de compartilhamento)
- **Box:** Read and write all files and folders (`root_readwrite`)
- **Bitly, Notion:** sem escopos; o Notion pergunta ao usuário quais páginas compartilhar

Veja [Hospedagem própria](/docs/self-hosting#optional-services).
