이 가이드를 마치면 QR 에디터, 계정, 스캔 분석이 포함된 동적 QR 코드, 호스팅 페이지, 워크스페이스, 저장된 테마까지 갖춘 QRdx가 직접 관리하는 Postgres 데이터베이스 위에서 내 URL로 실행됩니다. Docker Compose 방식은 약 30분이 걸리며, 대부분은 첫 이미지 빌드 시간입니다.

웹 앱은 AGPL-3.0 라이선스의 오픈 소스입니다. 다음 두 가지는 예외입니다. 워크스페이스 싱글 사인온(SSO)과 감사 로그는 QRdx 상용 라이선스에 따라 `ee/` 폴더에 있으며, 라이선스 키(`QRDX_EE_LICENSE`)를 설정하지 않으면 꺼져 있습니다. 프로덕션에서 사용하려면 QRdx와 서면 계약이 필요합니다. 자세한 내용은 [LICENSING.md](https://github.com/qrdxinc/qrdx/blob/main/LICENSING.md)를 참고하세요. [`qrdx` React 라이브러리](/docs/getting-started)나 [CLI](/docs/developers/cli)를 사용할 때는 이런 내용이 전혀 필요하지 않습니다. 둘 다 MIT 라이선스로 백엔드 없이 어디서든 실행됩니다. [QRdx의 오픈 소스](/open-source-qr-code-generator)에서 저장소의 각 부분과 라이선스를 확인할 수 있습니다.

## 시작하기 전에 [#before-you-start]

- Compose v2와 BuildKit이 포함된 Docker(Docker Desktop과 최신 Docker Engine에는 둘 다 포함되어 있습니다). 수동 설정에는 Node.js 22(22.22.3 이상)와 [Bun](https://bun.com/docs/installation) 1.4가 필요합니다.
- 이미지를 빌드하는 동안 Docker에 할당할 8GB 이상의 메모리.
- 계정을 만들 수 있도록 로그인할 방법: GitHub 또는 Google OAuth 앱, 또는 이메일 로그인 코드를 보내 주는 [Resend](https://resend.com). 로그인 코드는 `NEXT_PUBLIC_APP_URL`이 `localhost`가 아닐 때만 이메일로 발송됩니다. `bun run dev`는 코드를 터미널에 출력하지만 Docker 이미지는 출력하지 않으므로, 로컬에서 Docker로 테스트할 때는 GitHub 또는 Google 로그인이 필요합니다.
- Postgres: `docker-compose.yml`에 포함된 컨테이너 또는 [Neon](https://neon.tech) 데이터베이스.
- 로컬 테스트 이상의 용도라면 도메인과 HTTPS를 종료하는 리버스 프록시.

문서는 셀프 호스팅 인스턴스에 포함되지 않습니다. 인스턴스는 모든 문서 링크(`/docs`와 그 아래 페이지, Markdown 사본, `/llms-full.txt`)를 qrdx.dev의 같은 페이지로 연결합니다.

### 데이터베이스 연결 방식 [#how-the-database-connection-works]

앱은 Neon의 서버리스 HTTP 드라이버를 통해 Postgres와 통신합니다.

- **Neon:** 바로 사용할 수 있습니다. `DATABASE_URL`에 Neon 연결 문자열을 설정하세요.
- **일반 Postgres:** 앞단에 Neon 호환 HTTP 프록시가 필요합니다. `docker-compose.yml`은 프록시([local-neon-http-proxy](https://github.com/TimoWilhelm/local-neon-http-proxy))를 하나 실행하고, 앱이 쿼리를 그쪽으로 보내도록 `DATABASE_HTTP_ENDPOINT`를 설정합니다.

스키마는 `packages/database/schema.ts`에서 가져오며 `drizzle-kit push`로 적용합니다. 직접 실행해야 하는 마이그레이션 파일은 없습니다.

## Docker Compose로 빠르게 시작하기 [#quick-start-with-docker-compose]

### 1. 저장소 복제 [#1-clone-the-repository]

```bash title="Terminal"
git clone https://github.com/qrdxinc/qrdx.git
cd qrdx
```

### 2. 환경 설정 [#2-configure-the-environment]

예시 파일을 Compose가 읽는 저장소 루트로 복사하고 세션 시크릿을 생성하세요.

```bash title="Terminal"
cp apps/app/.env.example .env
openssl rand -base64 32
# prints a 44-character string: paste it as BETTER_AUTH_SECRET below
```

`.env`를 열어 다음 값을 설정하세요. 나머지 줄은 주석 처리된 채로 두어도 됩니다.

```bash title=".env"
NEXT_PUBLIC_APP_URL=https://qr.example.com
BETTER_AUTH_URL=https://qr.example.com
BETTER_AUTH_SECRET=<the string openssl printed>

# One sign-in provider. The callback URL for GitHub is
# <NEXT_PUBLIC_APP_URL>/api/auth/callback/github
GITHUB_CLIENT_ID=<client ID of your GitHub OAuth app>
GITHUB_CLIENT_SECRET=<its client secret>
```

각 값을 얻는 위치는 다음과 같습니다.

| 변수 | 값을 얻는 곳 |
| --- | --- |
| `NEXT_PUBLIC_APP_URL` | 인스턴스의 공개 URL이며 끝에 슬래시를 붙이지 않습니다. 로컬 테스트라면 `http://localhost:3000`을 그대로 두세요. |
| `BETTER_AUTH_URL` | 같은 값입니다. 해당 줄의 주석을 해제하세요. |
| `BETTER_AUTH_SECRET` | `openssl rand -base64 32`의 출력값입니다. |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | 콜백 URL이 `<your url>/api/auth/callback/github`인 [GitHub OAuth 앱](https://github.com/settings/developers)입니다. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | GitHub 대신 사용할 경우: 리디렉션 URI가 `<your url>/api/auth/callback/google`인 [Google OAuth 클라이언트](https://console.cloud.google.com/apis/credentials)입니다. |

`DATABASE_URL`은 그대로 두세요. Compose가 앱이 자체 Postgres 컨테이너를 사용하도록 설정하며 `.env`의 값은 무시합니다. 데이터베이스 비밀번호를 바꾸려면 처음 시작하기 전에 `POSTGRES_PASSWORD`를 설정하세요.

### 3. 스택 시작 [#3-start-the-stack]

```bash title="Terminal"
docker compose up -d --build
```

이 명령은 이미지를 빌드하고, Postgres와 프록시를 시작하고, 일회성 `migrate` 서비스(`drizzle-kit push`)를 실행한 다음 3000번 포트에서 앱을 시작합니다. 첫 빌드에는 몇 분이 걸립니다. 완료되면 네 개의 서비스가 다음과 같이 표시됩니다.

```text title="docker compose ps (columns trimmed)"
NAME              SERVICE    STATUS
qrdx-db-1         db         running (healthy)
qrdx-db-proxy-1   db-proxy   running
qrdx-migrate-1    migrate    exited (0)
qrdx-app-1        app        running
```

`migrate`는 종료되는 것이 정상입니다. 스키마를 동기화한 뒤 멈춥니다. 스키마 동기화와 앱 시작 과정을 보려면 다음을 실행하세요.

```bash title="Terminal"
docker compose logs -f migrate app
```

### 4. 로그인 [#4-sign-in]

브라우저에서 `NEXT_PUBLIC_APP_URL`을 열고 GitHub, Google 또는 이메일 코드로 로그인하세요. 처음 로그인할 때 계정이 만들어집니다.

### 5. 관리자로 지정하기 [#5-make-yourself-an-admin]

4단계에서 만든 계정의 이메일 주소를 `.env`에 추가하세요.

```bash title=".env"
ADMIN_EMAILS=you@example.com
```

변경 사항을 읽도록 앱 컨테이너를 다시 만든 뒤 로그인하고 `/admin`을 여세요.

```bash title="Terminal"
docker compose up -d app
```

이 주소는 처음 `/admin`을 열 때 관리자가 됩니다. `ADMIN_USER_IDS`도 사용자 ID로 같은 방식으로 동작합니다.

## Neon 또는 다른 관리형 Postgres 사용하기 [#use-neon-or-another-managed-postgres]

포함된 Postgres를 건너뛰고 앱 이미지만 실행할 수 있습니다. `.env`의 `DATABASE_URL`을 Neon 연결 문자열로 설정하고 `DATABASE_HTTP_ENDPOINT`는 설정하지 마세요.

```bash title="Terminal"
docker build -t qrdx --build-arg NEXT_PUBLIC_APP_URL=https://qr.example.com .
docker run -d --env-file .env -p 3000:3000 qrdx
```

마이그레이터 이미지로 스키마를 한 번 적용하고, 업데이트할 때마다 다시 적용하세요.

```bash title="Terminal"
docker build --target migrator -t qrdx-migrate .
docker run --rm -e DATABASE_URL="<your connection string>" qrdx-migrate
```

## Node.js로 수동 설정하기 [#manual-setup-with-nodejs]

```bash title="Terminal"
git clone https://github.com/qrdxinc/qrdx.git
cd qrdx
bun install

cp apps/app/.env.example apps/app/.env.local   # then edit it as in step 2

bun run db:push                                # apply the schema
bun run --filter app dev                       # http://localhost:3000
```

프로덕션에서는 앱을 빌드하고 시작하세요.

```bash title="Terminal"
bun x turbo build --filter=app
bun run --filter app start
```

`bun run db:push`는 Neon의 드라이버로 연결하므로 Neon 데이터베이스가 필요합니다. 로컬 개발에 Docker Postgres를 대신 사용하려면 `docker compose up -d db db-proxy`로 시작하고, `docker compose run --rm migrate`로 스키마를 적용한 뒤, `apps/app/.env.local`에 다음을 설정하세요.

```bash title="apps/app/.env.local"
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/qrdx
DATABASE_HTTP_ENDPOINT=http://localhost:4444/sql
```

## 환경 변수 [#environment-variables]

[`apps/app/.env.example`](https://github.com/qrdxinc/qrdx/blob/main/apps/app/.env.example)에는 모든 변수와 각 값을 어디서 얻는지 설명이 나와 있어요. 앱은 시작할 때 모든 값을 확인하고, 필수 값이 없거나 값이 올바르지 않으면 해당 변수 이름을 알려 주며 시작하지 않아요.

### 필수 [#required]

| 변수 | 용도 |
| --- | --- |
| `NEXT_PUBLIC_APP_URL` | 인스턴스의 공개 URL |
| `DATABASE_URL` | Postgres 연결 문자열 (Compose가 설정) |
| `BETTER_AUTH_SECRET` | 세션과 쿠키에 서명 |

사용자가 로그인할 수 있도록 OAuth 제공자(GitHub 또는 Google) 하나를 추가하거나, 이메일 로그인 코드를 위해 Resend를 추가하세요.

### 선택 서비스 [#optional-services]

각 변수는 해당 기능만 켭니다. 빈 값은 설정하지 않은 것으로 취급해요. 값이 설정되었지만 올바르지 않으면(URL이 아닌 URL, 너무 짧은 키 등) 앱이 해당 변수 이름과 함께 중단돼요.

| 서비스 | 변수 | 설정하지 않으면 |
| --- | --- | --- |
| GitHub 로그인 | `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | GitHub 로그인을 사용할 수 없어요 |
| Google 로그인 | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google 로그인을 사용할 수 없어요 |
| 인증 기본 URL | `BETTER_AUTH_URL` | 각 요청에서 추정하며 로그에 경고가 남아요 |
| 관리자 패널 | `ADMIN_EMAILS`, `ADMIN_USER_IDS` | 아무도 `/admin`을 열 수 없어요 |
| 워크스페이스 싱글 사인온 | `QRDX_EE_LICENSE` | 싱글 사인온이 꺼진 상태로 유지돼요. **Sign in with SSO**도, SSO 설정도 없고 로그인 경로도 존재하지 않아요. SSO는 QRdx 상용 라이선스가 적용되는 `ee/` 폴더에 있으므로, 프로덕션에서 사용하려면 QRdx와 서면 계약이 필요해요. [싱글 사인온](/docs/help/teams/single-sign-on)을 참고하세요 |
| 워크스페이스 감사 로그 | `QRDX_EE_LICENSE` | 감사 로그가 꺼진 상태로 유지돼요. 아무것도 기록되지 않고 **설정** → **감사 로그**도 없어요. 싱글 사인온처럼 QRdx 상용 라이선스가 적용되는 `ee/` 폴더에 있어요. 기록은 {facts.auditLogRetentionDays}일 동안 보관되며, [예약 웹훅 작업](#scheduled-jobs)이 그보다 오래된 기록을 삭제해요. [감사 로그](/docs/help/teams/audit-log)를 참고하세요 |
| AI 테마, 프롬프트 개선, AI QR 아트 (Vercel AI Gateway) | `AI_GATEWAY_API_KEY` | AI 요청이 실패하고 AI 페이지가 내비게이션과 사이트맵에서 빠져요. 에디터는 정상적으로 작동해요. 키는 본인의 Vercel 계정(AI Gateway, API keys)에서 만드세요. 사용량은 해당 계정의 AI Gateway 크레딧으로 청구되며, 앱이 Vercel에서 실행될 필요는 없어요. 작업별 모델은 `apps/app/lib/ai/models.ts`에서 설정해요 |
| 단축 링크 오리진 | `NEXT_PUBLIC_SHORT_LINK_BASE_URL` | [동적 코드](/docs/dynamic-qr-codes#self-hosting)가 `NEXT_PUBLIC_APP_URL`을 사용해요 |
| 스캔 개인정보 솔트 | `SCAN_HASH_SALT` | `BETTER_AUTH_SECRET`에서 파생돼요 |
| 파일 스토리지 (Cloudflare R2) | `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `R2_PUBLIC_BASE_URL` | 업로드가 꺼져요. 페이지에서 다른 곳에 호스팅된 파일은 계속 링크할 수 있어요. [파일](/docs/files#set-up-storage-self-hosting)을 참고하세요 |
| 이메일 (Resend) | `RESEND_API_KEY`, `EMAIL_FROM` | 이메일은 전송되지 않고 로그에만 기록되므로 이메일 로그인 코드를 보낼 수 없어요. 팀 초대는 복사 가능한 링크를 사용해요. [알림](/docs/notifications#self-hosting)을 참고하세요 |
| Vercel의 사용자 지정 도메인 | `VERCEL_API_TOKEN`, `VERCEL_PROJECT_ID`, `VERCEL_TEAM_ID` | Vercel이 아닌 환경에서는 설정하지 마세요. 이 경우 도메인은 DNS `TXT` 레코드로 확인해요. [사용자 지정 도메인](/docs/custom-domains#self-hosting)을 참고하세요 |
| 원클릭 DNS 설정 (Domain Connect) | `DOMAIN_CONNECT_PROVIDER_ID`, `DOMAIN_CONNECT_SERVICE_ID`, `DOMAIN_CONNECT_PRIVATE_KEY` | **Set up with …** 버튼이 없고, 사용자가 DNS 레코드를 직접 추가해요. 각 DNS 제공자가 승인한 자체 Domain Connect 템플릿과 DNS에 등록된 공개 키가 필요해요. [사용자 지정 도메인](/docs/custom-domains#self-hosting)을 참고하세요 |
| 예약 작업 | `CRON_SECRET` | 프로덕션에서 [주간 다이제스트 및 웹훅 재시도 경로](#scheduled-jobs)가 `401`로 응답하므로, 다이제스트가 전송되지 않고 실패한 웹훅이 재시도되지 않으며 {facts.auditLogRetentionDays}일이 지난 감사 로그 기록도 삭제되지 않아요 |
| 링크 안전 (Google Web Risk) | `WEB_RISK_API_KEY` | 목적지를 오프라인 규칙으로만 검사해요. [코드 제어](/docs/code-controls#safety-checks-on-links)를 참고하세요 |
| 남용 제한 | `SAFETY_YOUNG_ACCOUNT_DAYS`, `SAFETY_YOUNG_ACCOUNT_DYNAMIC_PER_HOUR`, `SAFETY_RECHECK_BATCH` | `apps/app/lib/safety/limits.ts`의 기본값이 적용돼요 (7일, 시간당 코드 30개, 재검사당 목적지 500개) |
| 폼 스팸 검사 (Cloudflare Turnstile) | `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` | 폼은 기본 제공되는 허니팟과 속도 제한에 의존해요. [메뉴, 쿠폰, 이벤트, 폼](/docs/forms-and-pages#self-hosting)을 참고하세요 |
| 결제 (Polar) | `POLAR_ACCESS_TOKEN`, `POLAR_WEBHOOK_SECRET`, `NEXT_PUBLIC_QRDX_PRO_MONTHLY_PRODUCT_ID`, `NEXT_PUBLIC_QRDX_PRO_YEARLY_PRODUCT_ID`, `NEXT_PUBLIC_QRDX_BUSINESS_MONTHLY_PRODUCT_ID`, `NEXT_PUBLIC_QRDX_BUSINESS_YEARLY_PRODUCT_ID` | 업그레이드가 작동하지 않고(제품 ID가 없는 플랜은 "Coming soon"으로 표시돼요), 모든 계정이 무료 한도를 사용해요 |
| 유로 가격 | `NEXT_PUBLIC_QRDX_EUR_PRICES=1`, 위의 모든 제품에 Polar의 EUR 가격이 설정된 후에만 설정하세요 | EU 및 EEA 방문자에게 US$ 가격이 표시되고 그 가격으로 청구돼요 |

<Callout type="info" title="NEXT_PUBLIC_* 값은 빌드 시점에 고정돼요">
  `NEXT_PUBLIC_*` 값은 앱을 빌드할 때 브라우저 번들에 포함되므로, 값을 바꾸려면 다시 빌드해야 해요. Docker 빌드는 `docker-compose.yml`에서 빌드 인수로 전달되는 여섯 개의 값만 `.env`에서 읽어요: `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`, `NEXT_PUBLIC_FEATUREBASE_APP_ID`, 그리고 Pro 제품 ID 두 개예요. Docker 이미지에서 다른 값(Business 제품 ID, `NEXT_PUBLIC_QRDX_EUR_PRICES`, `NEXT_PUBLIC_SHORT_LINK_BASE_URL`, Turnstile 사이트 키, Umami ID)을 설정하려면 `docker-compose.yml`의 `app` 서비스 `build.args`와 Dockerfile 빌드 단계의 `ARG`에 추가한 다음 `docker compose up -d --build`를 실행하세요. 수동 설정에서는 모든 값을 `apps/app/.env.local`에서 읽어요.
</Callout>

### 예약 작업 [#scheduled-jobs]

두 경로가 반복 작업을 처리해요. `/api/cron/webhooks`는 실패한 웹훅 전송을 재시도하고 오래된 감사 로그 기록을 삭제하며, `/api/cron/digest`는 주간 다이제스트를 보내요. Vercel에서는 `apps/app/vercel.json`이 이 작업들을 예약해요. 그 외의 환경에서는 직접 호출하기 전까지 아무것도 호출하지 않아요. `CRON_SECRET`을 설정하고 스케줄러에서 이 값을 사용해 두 경로를 모두 호출하세요.

```text title="crontab (times in UTC)"
0 4 * * *  curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://qr.example.com/api/cron/webhooks
0 9 * * 1  curl -fsS -H "Authorization: Bearer $CRON_SECRET" "https://qr.example.com/api/cron/digest?shard=all"
```

헤더가 없으면 프로덕션에서 경로가 `401`로 응답해요. 다이제스트의 `shard` 매개변수는 [알림](/docs/notifications#self-hosting)에서 설명해요.

## 리버스 프록시와 HTTPS [#reverse-proxy-and-https]

TLS를 종료하는 Caddy, nginx, Traefik 같은 리버스 프록시 뒤에 앱을 두고, 3000번 포트는 인터넷에 직접 노출하지 마세요. 요청 제한, 보안 이메일, [감사 로그](/docs/help/teams/audit-log)는 클라이언트 IP를 먼저 `X-Real-IP`에서 읽고, 없으면 `X-Forwarded-For`의 첫 번째 주소에서 읽습니다. Vercel에서는 그 사이에 `X-Vercel-Forwarded-For`를 읽습니다. 따라서 프록시가 이 헤더를 설정해야 하고, 앱은 프록시를 통해서만 접근할 수 있어야 합니다. 프록시가 연결을 받은 주소를 `X-Real-IP`로 설정하도록 하세요. `X-Forwarded-For`에 값을 덧붙이기만 하는 프록시에서는 클라이언트가 원하는 주소를 맨 앞에 넣을 수 있습니다.

```nginx title="nginx server block (the relevant lines)"
location / {
  proxy_pass http://127.0.0.1:3000;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

Caddy는 이 헤더를 기본으로 설정합니다. HTTPS가 동작하면 `NEXT_PUBLIC_APP_URL`과 `BETTER_AUTH_URL`을 `https://` URL로 바꾸고, OAuth 콜백 URL을 업데이트한 다음 다시 빌드하세요.

### Content-Security-Policy [#content-security-policy]

프로덕션 빌드는 QRdx 자체 페이지에 Content-Security-Policy를 보냅니다. 로그인한 상태의 페이지에는 요청마다 새로운 스크립트 nonce를 적용하고, 사전 렌더링된 페이지에는 스크립트 호스트 허용 목록을 적용합니다. 호스팅 페이지(`/p`)에는 느슨한 정책을 적용합니다. 소유자의 픽셀을 실행하고 어디서든 미디어를 삽입하기 때문입니다. 리버스 프록시도 `Content-Security-Policy`를 설정하면 브라우저가 둘 다 적용하므로, 프록시에서는 설정하지 마세요. 새 환경을 점검하는 동안에는 `CSP_REPORT_ONLY=1`을 설정해 정책을 보고 전용으로 보낼 수 있으며, 위반 사항은 `/api/csp-report`에 기록됩니다. Vercel이 아닌 곳에서 HTTPS로 서비스한다면 `CSP_HTTPS=1`을 추가해 브라우저가 `http://` 리소스를 업그레이드하게 하세요. 두 변수는 앱이 실행되는 곳에서 읽으며, 사전 렌더링된 페이지의 헤더를 위해 빌드되는 곳에서도 읽습니다. Dockerfile은 이 변수를 빌드에 전달하지 않으므로, 사전 렌더링된 페이지에 필요하다면 빌드 인수로도 추가하세요.

## QRdx 업데이트 [#update-qrdx]

먼저 데이터베이스를 백업하세요(아래 참고). 그런 다음 최신 코드를 가져와 다시 빌드합니다. 앱이 시작되기 전에 `migrate` 서비스가 스키마를 다시 동기화합니다.

```bash title="Terminal"
git pull
docker compose up -d --build
```

수동 설정이라면 `git pull`, `bun install`, `bun run db:push`를 실행한 뒤 다시 빌드하고 재시작하세요.

스키마 변경으로 데이터가 삭제될 수 있으면 `drizzle-kit push`가 확인을 요청하는데, `migrate` 서비스는 답할 방법이 없어 대기하게 됩니다. 이 경우 터미널에서 직접 실행해 변경 사항을 검토하고 확인하세요.

```bash title="Terminal"
docker compose run --rm migrate
```

## 백업과 복원 [#back-up-and-restore]

QRdx가 저장하는 모든 데이터는 Postgres에 있습니다. 업로드한 파일만 R2 버킷에 있습니다. 업데이트하기 전마다, 그리고 정기적으로 데이터베이스를 덤프하세요.

```bash title="Terminal"
docker compose exec db pg_dump -U postgres qrdx > qrdx-backup.sql
```

빈 데이터베이스로 복원하려면 다음과 같이 합니다.

```bash title="Terminal"
docker compose exec -T db psql -U postgres qrdx < qrdx-backup.sql
```

Neon을 사용한다면 Neon 자체의 백업과 브랜칭을 이용하세요.

## qrdx.dev와 다른 점 [#what-is-different-from-qrdxdev]

- **문서**는 qrdx.dev에서 열립니다. 인스턴스는 모든 문서 URL을 그곳으로 리디렉션합니다.
- **결제와 요금제**에는 Polar가 필요합니다. Polar가 없으면 모든 계정에 무료 한도가 적용되고 아무도 업그레이드할 수 없습니다. 한도 자체는 `apps/app/lib/plans.ts`에 있으며, 인스턴스에 맞게 변경할 수 있습니다.
- **제휴 프로그램, 청구서 결제 요청, 비영리 단체 할인, 엔터프라이즈 문의 양식**은 QRdx 자체의 영업 활동으로, QRdx가 직접 운영하는 곳에서만 동작합니다. 직접 호스팅한 사본에는 이 기능이 없습니다.
- **스캔 위치:** 국가, 지역, 도시는 Vercel의 지리 정보 헤더에서 가져옵니다. Cloudflare 뒤에서는 국가만 읽으며(`CF-IPCountry`), 그 밖의 환경에서는 위치가 알 수 없음으로 표시되고 [지역 규칙](/docs/precise-location#route-scans-by-area)은 위치를 공유한 스캔에만 적용됩니다.
- **커스텀 도메인**은 DNS `TXT` 레코드로 확인하고 리버스 프록시가 라우팅합니다. 단, Vercel에서 실행하면서 Domains API 변수를 설정한 경우는 예외입니다. **Set up with …** 버튼에는 직접 만든 Domain Connect 템플릿이 필요합니다. QRdx의 템플릿은 qrdx.dev에서만 동작합니다.
- **챗봇과 연동**은 각각 해당 서비스에 등록한 앱이 필요합니다(위의 표 참고).
- **관리자 페이지**는 앱이 직접 제공합니다. qrdx.dev는 그중 일부를 별도의 콘솔로 프록시합니다.

## 문제 해결 [#troubleshooting]

### 시작할 때 "Invalid environment variables"가 나와요 [#invalid-environment-variables-on-startup]

로그에 누락되었거나 잘못된 변수의 이름이 표시되고, 어디에 설정해야 하는지도 안내합니다. 필수 값이 없거나, 선택 값이 잘못 설정된 경우입니다. 예를 들어 전체 `http://` 또는 `https://` 주소가 아닌 URL이나 너무 짧은 시크릿이 해당됩니다. 빈 값은 설정하지 않은 것으로 취급되므로 문제가 없습니다. `.env`에서 표시된 변수를 수정하고 `docker compose up -d app`으로 컨테이너를 다시 만드세요.

### OAuth `redirect_uri` 불일치 [#oauth-redirect_uri-mismatch]

OAuth 앱의 콜백 URL은 정확히 `<NEXT_PUBLIC_APP_URL>/api/auth/callback/github` 또는 `/api/auth/callback/google`이어야 합니다. `BETTER_AUTH_URL`은 `NEXT_PUBLIC_APP_URL`과 같은 기본 URL로 설정하세요.

### 앱이 데이터베이스에 연결하지 못해요(`fetch failed`) [#the-app-cant-reach-the-database-fetch-failed]

일반 Postgres를 쓸 때는 `DATABASE_HTTP_ENDPOINT`가 실행 중인 프록시를 가리켜야 합니다. `docker compose ps db-proxy`로 프록시가 실행 중인지 확인하세요.

### `migrate`가 끝나지 않아요 [#migrate-never-finishes]

`drizzle-kit push`가 확인을 기다리고 있습니다. 터미널에서 `docker compose run --rm migrate`를 실행해 답하세요. [QRdx 업데이트](#update-qrdx)를 참고하세요.

### 변경한 `NEXT_PUBLIC_*` 값이 적용되지 않아요 [#a-changed-next_public_-value-has-no-effect]

이미지를 다시 빌드하세요: `docker compose up -d --build`.

### 4444번 포트가 이미 사용 중이에요 [#port-4444-is-already-in-use]

`docker-compose.yml`에서 `db-proxy`의 포트 매핑을 변경하세요. 이 포트는 호스트에서의 로컬 개발에만 사용됩니다.

### "the --mount option requires BuildKit" [#the---mount-option-requires-buildkit]

사용 중인 Docker에 BuildKit이 없습니다. `buildx` 플러그인을 설치하거나 Docker를 업데이트하세요.

### 빌드가 `Killed` 또는 종료 코드 137로 멈춰요 [#the-build-stops-with-killed-or-exit-code-137]

Docker의 메모리가 부족해졌습니다. 최소 8GB를 할당하고(Docker Desktop: **Settings** → **Resources**) `docker compose up -d --build`를 다시 실행하세요.

### "sign-in code email is off for this deployment" [#sign-in-code-email-is-off-for-this-deployment]

`NEXT_PUBLIC_APP_URL`이 `localhost`인 동안에는 이메일 코드가 전송되지 않습니다. 로컬 테스트에는 GitHub 또는 Google 로그인을 사용하세요.

여전히 해결되지 않나요? 시크릿을 제거한 `docker compose logs app` 출력과 함께 [이슈를 등록하세요](https://github.com/qrdxinc/qrdx/issues).
