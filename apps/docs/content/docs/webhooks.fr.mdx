À la fin de cette page, une URL que vous contrôlez reçoit un `POST` signé dans les minutes qui suivent chaque événement choisi, votre serveur vérifie que chaque requête provient bien de QRdx, et vous savez comment se comportent les nouvelles tentatives, les doublons et le journal des livraisons.

Les webhooks envoient les événements d'un espace de travail vers votre serveur au moment où ils se produisent : mettre à jour un CRM quand une personne remplit un formulaire, publier dans un outil interne quand un code dépasse 1 000 scans, ou conserver votre propre copie des données de scan.

<Callout type="info" title="Offre Business">
Les webhooks, les hooks Zapier et Make, ainsi que les alertes Slack et Discord font partie de l'offre **Business**. Les alertes par e-mail et le résumé hebdomadaire font partie de l'offre Pro ; voir [Notifications](/docs/notifications). Comparez les offres sur [Offres et limites](/docs/plans-and-limits).
</Callout>

## Avant de commencer [#before-you-start]

- Une URL publique en `https://` qui répond aux requêtes `POST`. Les adresses IP, `localhost` et les noms d'hôte qui pointent vers des réseaux privés sont refusés, et les redirections ne sont pas suivies. En développement local, utilisez un tunnel qui fournit un nom d'hôte public.
- Le rôle de propriétaire ou d'administrateur dans l'espace de travail. Les membres peuvent voir les points de terminaison et leurs journaux de livraison, mais pas les ajouter ni les modifier.

## 1. Ajouter un point de terminaison [#1-add-an-endpoint]

1. Ouvrez [Paramètres → Webhooks](/dashboard?to=settings/webhooks) dans l'espace de travail dont vous voulez recevoir les événements. Le lien ouvre le dernier espace de travail utilisé ; choisissez-en un autre dans le sélecteur d'espace de travail et vous restez sur la même page.
2. Choisissez **Ajouter un point de terminaison**, saisissez l'**URL du point de terminaison** et cochez les **Événements** souhaités, puis choisissez **Ajouter un point de terminaison** dans la boîte de dialogue. QRdx vous demande d'abord de [confirmer que c'est bien vous](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), et de nouveau chaque fois que vous modifiez l'URL d'un point de terminaison ; modifier ses événements ou le désactiver ne demande rien.
3. Copiez le **Secret de signature** affiché après l'enregistrement. Les propriétaires et les administrateurs peuvent l'afficher de nouveau, ou le renouveler, depuis la page **Livraisons** du point de terminaison.
4. Choisissez **Envoyer un test**. QRdx envoie un événement `ping` signé et affiche le statut de la réponse dans le journal des livraisons.

Un espace de travail peut avoir jusqu'à 20 points de terminaison et hooks au total.

## 2. Choisir les événements [#2-pick-the-events]

| Événement | Quand | Remarques |
| --- | --- | --- |
| `scan.created` | Un QR code dynamique est scanné | Par lots : au plus une requête par minute et par point de terminaison, avec jusqu'à 100 scans et le `count` exact |
| `scan.milestone` | Le 1er scan d'un code, puis 10, 100, 500, 1 000, 5 000, 10 000, 50 000, 100 000, 500 000 et 1 000 000 de scans, puis tous les millions | Se déclenche une fois par palier |
| `code.created` | Un QR code dynamique est créé, dans le tableau de bord ou via l'API | Un événement par code, y compris pour une création en masse |
| `code.updated` | La destination, le titre, le design ou le domaine du lien court d'un code change | `changes` liste les champs |
| `form.submitted` | Une personne envoie un formulaire sur une page hébergée | Inclut les réponses |
| `ping` | Vous choisissez **Envoyer un test** | |

Les scans effectués par des robots, des aperçus de liens et des systèmes de préchargement, ainsi que les répétitions rapides d'un même visiteur, ne sont pas comptés et ne déclenchent pas d'événements, exactement comme dans les [statistiques de scan](/docs/dynamic-qr-codes#scan-analytics).

## 3. Lire le contenu envoyé [#payloads]

Chaque requête est un `POST` avec un corps JSON et ces en-têtes :

| En-tête | Valeur |
| --- | --- |
| `Content-Type` | `application/json` |
| `User-Agent` | `QRdx-Webhooks/1.0 (+https://qrdx.dev/docs/webhooks)` |
| `X-QRdx-Event` | Le type d'événement, par exemple `code.created` |
| `X-QRdx-Delivery` | Identifiant de livraison : identique à chaque nouvelle tentative, ce qui permet d'ignorer les doublons |
| `X-QRdx-Timestamp` | Secondes Unix auxquelles cette tentative a été signée |
| `X-QRdx-Signature` | `t=<timestamp>,v1=<hex HMAC-SHA256>` |

Le corps est toujours une enveloppe contenant `id`, `type`, `created_at` et `data` :

```json title="code.created"
{
  "id": "evt_cm3x8c1a20001",
  "type": "code.created",
  "created_at": "2026-10-31T09:30:00.000Z",
  "data": {
    "code": {
      "id": "cm3x7q2l40000",
      "slug": "aB3dE5f",
      "title": "Spring menu",
      "short_link": "https://qrdx.dev/q/aB3dE5f",
      "destination_url": "https://example.com/menu",
      "status": "active",
      "scan_count": 0,
      "created_at": "2026-10-31T09:30:00.000Z",
      "updated_at": "2026-10-31T09:30:00.000Z"
    },
    "actor_id": "user_123"
  }
}
```

Un lot `scan.created` :

```json title="scan.created"
{
  "id": "evt_cm3x9d0b10002",
  "type": "scan.created",
  "created_at": "2026-10-31T09:31:00.000Z",
  "data": {
    "window_started_at": "2026-10-31T09:31:00.000Z",
    "window_seconds": 60,
    "count": 2,
    "scans": [
      {
        "scan_id": "cm3x9d0b00001",
        "code": { "id": "cm3x7q2l40000", "slug": "aB3dE5f", "title": "Spring menu" },
        "scanned_at": "2026-10-31T09:31:00.000Z",
        "country": "DE",
        "region": "BE",
        "city": "Berlin",
        "device_type": "mobile",
        "os": "iOS",
        "browser": "Safari",
        "referer": null,
        "source": "qr"
      }
    ]
  }
}
```

Quand plus de 100 scans arrivent en une minute, `scans` contient les 100 premiers et `count` le total exact. `source` vaut `nfc` pour un contact avec un [tag NFC](/docs/nfc) et `qr` pour un scan de QR code. Les données de scan n'incluent jamais d'adresses IP ni de hachages de visiteurs.

Les autres événements contiennent :

- `scan.milestone` : `milestone`, `code` (`id`, `slug`, `title`, `scan_count`) et le `scan` qui a atteint le palier.
- `code.updated` : comme `code.created`, plus `changes`, par exemple `["destination_url"]`.
- `form.submitted` : `response_id`, `page` (`id`, `title`), `code` (`id`, `slug`, ou `null`), `fields` (`name`, `label`, `value` sous forme de texte) et `submitted_at`.

Pour voir un exemple de contenu de chaque événement, construit à partir de vos propres données avant l'arrivée du premier événement réel, appelez [Obtenir des exemples d'événements](/docs/developers/api/get-hook-samples) :

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/hooks/sample?event=scan.created" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

## 4. Vérifier les signatures [#verify-signatures]

Calculez un HMAC-SHA256 de `<timestamp>.<raw body>` avec votre secret de signature et comparez-le à `v1` dans `X-QRdx-Signature`. Utilisez le corps brut de la requête, avant tout traitement JSON, et rejetez les horodatages vieux de plus de cinq minutes.

```ts title="lib/qrdx-webhook.ts"
import { createHmac, timingSafeEqual } from "node:crypto";

export function isFromQRdx(rawBody: string, header: string, secret: string) {
  const parts = Object.fromEntries(
    header.split(",").map((part) => part.trim().split("=", 2)),
  );
  const timestamp = Number(parts.t);
  if (!timestamp || Math.abs(Date.now() / 1000 - timestamp) > 300) return false;

  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const received = Buffer.from(parts.v1 ?? "");
  return (
    received.length === expected.length &&
    timingSafeEqual(received, Buffer.from(expected))
  );
}
```

```python title="qrdx_webhook.py"
import hmac
import hashlib
import time


def is_from_qrdx(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(part.strip().split("=", 1) for part in header.split(","))
    timestamp = int(parts.get("t", "0"))
    if not timestamp or abs(time.time() - timestamp) > 300:
        return False
    expected = hmac.new(
        secret.encode(), f"{timestamp}.".encode() + raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(parts.get("v1", ""), expected)
```

Le renouvellement du secret prend effet immédiatement : l'ancien secret ne permet plus de vérifier les signatures, mettez donc votre serveur à jour juste après le renouvellement.

## 5. Répondre et gérer les nouvelles tentatives [#5-respond-and-handle-retries]

Répondez avec n'importe quel statut `2xx` en moins de 10 secondes. Tout le reste (un statut d'erreur, une redirection, un délai dépassé, un hôte injoignable) compte comme un échec, et QRdx réessaie avec des attentes croissantes d'environ 1 minute, 4 minutes, 16 minutes, 1 heure, 4 heures, 17 heures et 24 heures. Chaque nouvelle tentative part dans les minutes qui suivent la fin de son attente. Cela fait 8 tentatives sur environ deux jours, après quoi la livraison est marquée comme échouée.

Les livraisons peuvent arriver plusieurs fois (nouvelle tentative après une réponse lente, nouvelle tentative manuelle) et dans le désordre. Utilisez `X-QRdx-Delivery` ou l'`id` de l'enveloppe pour ignorer les doublons, et effectuez votre traitement après avoir répondu `2xx` s'il dure plus de quelques secondes.

## Modifier ensuite [#change-it-later]

La page **Livraisons** de chaque point de terminaison liste les 50 dernières livraisons avec leur événement, leur statut, leurs tentatives et leur contenu. **Réessayer maintenant** renvoie immédiatement une livraison échouée ou en attente ; **Renvoyer** renvoie une livraison déjà remise. Les livraisons sont conservées 30 jours.

<Shot id="webhook-deliveries" />

Depuis le menu d'un point de terminaison, vous pouvez **Modifier** son URL et ses événements, **Désactiver le point de terminaison** (les nouvelles livraisons s'arrêtent ; **Activer le point de terminaison** les reprend), afficher ou **Renouveler** son **Secret de signature**, et le **Supprimer**, ce qui supprime aussi son journal. Si l'offre d'un espace de travail n'inclut plus les webhooks, les points de terminaison sont conservés mais rien n'est envoyé tant que l'espace n'est pas de nouveau sur Business. Vos QR codes continuent de fonctionner dans tous les cas.

## Zapier, Make et n8n (REST Hooks) [#zapier-make-and-n8n-rest-hooks]

Les outils d'automatisation peuvent s'abonner et se désabonner seuls grâce à l'API REST Hooks. Authentifiez-vous avec une [clé API](/docs/developers/api-keys) ou un jeton d'accès OAuth : `codes:write` pour s'abonner ou se désabonner, `codes:read` pour lister. Les URL de hook étant souvent secrètes, avec `codes:read` seul, `target_url` n'affiche que l'hôte (`https://hooks.zapier.com`). Les requêtes avec jeton agissent sur votre propre espace de travail ; une clé agit sur l'espace de travail dans lequel elle a été créée. S'abonner avec votre session de navigateur connectée vous demande d'abord de [confirmer que c'est bien vous](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), et renvoie `403 CONFIRMATION_REQUIRED` tant que vous ne l'avez pas fait dans les 10 dernières minutes. Les abonnements sont des points de terminaison ordinaires : ils apparaissent dans **Paramètres → Webhooks**, où vous pouvez aussi les supprimer.

| Méthode | Chemin | Description |
| --- | --- | --- |
| `POST` | `/v1/hooks` | S'abonner. Corps : `target_url` (ou `hookUrl` pour Zapier) et `event` (ou un tableau `events`). Renvoie `201` avec l'`id` de l'abonnement et son `secret` |
| `DELETE` | `/v1/hooks/{id}` | Se désabonner (`204`) |
| `GET` | `/v1/hooks` | Lister les abonnements et les points de terminaison |
| `GET` | `/v1/hooks/{id}` | Un abonnement |
| `GET` | `/v1/hooks/sample?event=<event>` | Exemples récents de contenu pour `event`, sous forme de tableau (le « perform list » de Zapier) |

```bash title="Terminal"
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://hooks.zapier.com/hooks/standard/123/abc/", "event": "form.submitted"}'
```

```json title="201 Created (fields)"
{
  "id": "<hook id>",
  "target_url": "https://hooks.zapier.com/hooks/standard/123/abc/",
  "events": ["form.submitted"],
  "event": "form.submitted",
  "active": true,
  "created_at": "<ISO 8601 time>",
  "secret": "whsec_<shown only here>"
}
```

Sans Business, l'appel d'abonnement renvoie `402` :

```json title="402 Payment Required"
{"code":"PLAN_REQUIRED","message":"Webhooks and Zapier/Make hooks are part of the Business plan.","status":402}
```

Une livraison `scan.created` est un lot unique ; dans Zapier, utilisez donc les éléments de ligne `data.scans` pour traiter chaque scan. Dans n8n, le nœud QRdx Trigger des [nœuds QRdx pour n8n](/docs/developers/n8n) effectue ces appels pour vous et vérifie chaque signature ; un simple nœud Webhook fonctionne aussi, configuré comme n'importe quel autre point de terminaison. Les pages de référence sont [S'abonner aux événements](/docs/developers/api/create-hook), [Lister les hooks](/docs/developers/api/list-hooks) et [Se désabonner](/docs/developers/api/delete-hook).

## En cas de problème [#if-something-goes-wrong]

### L'URL du endpoint est refusée [#the-endpoint-url-is-refused]

Seuls les noms d'hôte publics en `https://` sont acceptés : pas de `http://`, pas d'adresses IP, pas de `localhost`, pas de noms qui se résolvent vers un réseau privé. Pendant le développement, utilisez un tunnel avec un nom d'hôte public.

### Chaque livraison affiche un statut d'échec [#every-delivery-shows-a-failed-status]

Votre serveur a répondu autre chose que `2xx` en moins de 10 secondes, a redirigé la requête ou n'a pas répondu. Ouvrez les détails de la livraison pour voir le statut HTTP ou l'erreur exacte, corrigez le problème, puis choisissez **Retry now**. Si votre gestionnaire est lent, répondez d'abord `2xx` et traitez la requête ensuite.

### Les signatures ne se vérifient pas [#signatures-dont-verify]

Assurez-vous de hacher le corps brut de la requête, et non un objet JSON resérialisé, et que votre serveur utilise le secret actuel : le renouveler invalide immédiatement l'ancien. Vérifiez aussi l'horloge de votre serveur, car la vérification de l'horodatage tolère cinq minutes d'écart.

### Les événements n'arrivent plus [#events-stopped-arriving]

L'espace de travail a quitté le plan Business (les endpoints sont conservés mais mis en pause), l'endpoint est **Disabled**, ou le Zap, le scénario ou le workflow qui a créé l'abonnement a été désactivé et désabonné. Consultez **Settings → Webhooks**.

### `403 CONFIRMATION_REQUIRED` sur `POST /v1/hooks` [#403-confirmation_required-from-post-v1hooks]

Vous vous êtes abonné avec une session de navigateur. Confirmez que c'est bien vous dans QRdx et réessayez dans les 10 minutes, ou abonnez-vous avec une clé d'API depuis votre serveur.

## Auto-hébergement [#self-hosting]

Les livraisons sont envoyées immédiatement ; les nouvelles tentatives et les lots de scans dont la minute est écoulée sont envoyés par une tâche planifiée. QRdx l'exécute toutes les 5 minutes depuis un workflow GitHub Actions, ce qui fonctionne sur le plan gratuit Hobby de Vercel, et `apps/app/vercel.json` l'exécute aussi en entier une fois par jour. GitHub peut démarrer les exécutions planifiées en retard : attendez-vous donc à des nouvelles tentatives dans un délai de quelques minutes plutôt qu'à la minute près.

Pour faire de même, copiez `.github/workflows/webhook-worker.yml`, ajoutez votre `CRON_SECRET` comme secret Actions et l'URL de votre tâche comme variable `WEBHOOK_WORKER_URL`. Vous pouvez aussi appeler la tâche depuis n'importe quel planificateur, avec le `CRON_SECRET` défini dans l'environnement :

```bash title="crontab (every 1 to 5 minutes)"
curl -H "Authorization: Bearer $CRON_SECRET" https://your-host/api/cron/webhooks
```

Avec `?source=github` ajouté à l'URL, la tâche vérifie d'abord un petit marqueur dans Upstash Redis et renvoie `{"skipped": true}` sans interroger la base de données quand rien n'est à traiter, ce qui permet à une base de données qui descend à zéro de rester en veille (sans Upstash, la tâche complète s'exécute toujours). Gardez un appel par jour sans ce paramètre : cette exécution effectue toujours la tâche complète et répare le marqueur. Les autres tâches planifiées sont listées dans [Auto-hébergement](/docs/self-hosting#scheduled-jobs).
