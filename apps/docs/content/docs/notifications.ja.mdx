通知を使えば、ダッシュボードを開かなくてもコードの状況がわかります。初回スキャン、マイルストーン、フォームの回答、チームメンバーによる変更、そして週次サマリーをお届けします。QRdx から受け取る内容は [設定 → 通知](/settings/notifications) で選べます。設定は個人ごと、ワークスペースごとです。ご自身のワークスペースも、所属する他のワークスペースも、それぞれ個別のスイッチがあります。共有ワークスペースでは、メンバーそれぞれが自分の設定を選びます。

<Callout type="info" title="メールは Pro、チャットは Business">
  メール通知と週次ダイジェストは Pro と Business に含まれます。Slack と Discord のメッセージは Business に含まれます。各ワークスペースには、オーナーと請求担当メンバーのプランが適用されます。すべての通知は、オンにするまでオフです。詳しくは [プランと制限](/docs/plans-and-limits) をご覧ください。
</Callout>

お急ぎの場合は、[ログインコードやメールが届かない](/docs/help/troubleshooting/emails) で通知が届かないときの対処法を確認できます。

## 仕組み [#how-it-works]

スキャン、フォームの回答、コードの変更はすべてイベントです。通知では、関心のあるイベントを、それぞれ1つのチャネルで受け取れるように設定します。チャネルは、アカウントのアドレスへのメール、受信 Webhook を使った Slack や Discord のチャンネル、または [Webhook](/docs/webhooks) を通じたご自身のシステムです。

| チャネル | 受け取れる内容 | プラン |
| --- | --- | --- |
| メール | 週次ダイジェスト、スキャンのマイルストーン、フォーム送信、新しいコード、コードの変更 | Pro と Business |
| Slack、Discord | スキャンのマイルストーン、フォーム送信、新しいコード、コードの変更 | Business |
| [Webhook](/docs/webhooks)、Zapier、Make | 個々のスキャンを含むすべてのイベント | Business |

## 通知の種類 [#alerts]

- **スキャンのマイルストーン:** コードの初回スキャン、その後 10、100、500、1,000、5,000、10,000、50,000、100,000、500,000、1,000,000 回のスキャン、以降は100万回ごとです。初回スキャンのメールには、日時、場所、使用デバイスが記載されます。Slack と Discord のメッセージには、都市名と国名が記載されます。
- **フォーム送信:** [ホスト型ページ](/docs/forms-and-pages#forms)のフォームに寄せられた回答の内容と、すべての回答へのリンクです。
- **新しいコード**と**コードの変更:** コードを作成した人、またはリンク先、タイトル、デザイン、ドメインを変更した人がわかります。他のメンバーと共有しているワークスペースで特に役立ちます。

アクセスの多いフォームや一括インポートで受信箱やチャンネルがあふれないように、各送信先に届く同じ種類の通知は1時間あたり最大30件です。それを超えた分はスキップされます。週次ダイジェストにはスキップされた分も集計され、Webhook にはすべてのイベントが引き続き送信されます。

## 週次ダイジェスト [#weekly-digest]

毎週月曜日の朝（UTC）に、ワークスペースの先週の数値をお届けします。内容は、前週と比較したスキャン数、ユニーク訪問者数、上位5件のコード、上位の国、新しいコード、フォームの回答です。2週間連続でスキャンがなく、フォームの回答もない場合は送信されません。

## メール [#email]

通知メールは、通知設定の **Email to** の見出しの下に表示されるアカウントのメールアドレスに届きます。各メールには **Unsubscribe** リンクがあり、サインインしなくてもその種類のメールを停止できます（ワンクリック配信停止に対応したメールアプリでも表示されます）。メールの受信は、通知設定でいつでもオンまたはオフに戻せます。チームへの招待など、アカウントに関するその他のメールは、この設定の影響を受けません。

## Slack と Discord [#slack-and-discord]

1. チャットアプリで受信 Webhook を作成します。
   - **Slack:** [Incoming WebHooks](https://slack.com/apps/A0F7XDUAZ-incoming-webhooks) アプリ、または受信 Webhook を使ったご自身の Slack アプリをチャンネルに追加し、URL（`https://hooks.slack.com/services/...`）をコピーします。
   - **Discord:** チャンネルの設定 → **連携サービス** → **ウェブフック** → **新しいウェブフック** → **ウェブフック URL をコピー**（`https://discord.com/api/webhooks/...`）の順に進みます。
2. [設定 → 通知](/settings/notifications) のワークスペースの **Slack と Discord** で、**Slack** または **Discord** をクリックし、URL を貼り付けてイベントを選びます。追加するときは、先に[本人確認](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)が求められます。
3. 送信先の横にある送信ボタンで、テストメッセージを投稿できます。

受け付けるのは Slack と Discord の Webhook URL のみです。保存後は、URL を知っていれば誰でもチャンネルに投稿できてしまうため、QRdx には URL の先頭部分だけが表示されます。フォームに訪問者が何を入力しても、メッセージで `@everyone`、`@here`、ロールにメンションされることはありません。

[Slack 用 QRdx ボット](/docs/slack-bot)は別の機能で、Slack 内で QRコードを作成するためのものです。ボットを追加しても通知はオンになりませんし、通知を追加してもボットは追加されません。

## 制限とプラン [#limits-and-plans]

ワークスペースのプランにチャネルが含まれなくなった場合、そのチャネルの通知は停止しますが、設定は保持されます。通知をオフにしたり、送信先を削除したりすることは引き続きできます。QRコードは、どのプランでも使い続けられます。

## 開発者向け [#for-developers]

個々のスキャンなど、これらの通知以上のものが必要な場合は、[Webhook](/docs/webhooks) をご利用ください。`scan.created`、`form.submitted` などのイベントについて、署名付きの `POST` リクエストをご自身のエンドポイントに送信します。再試行と配信ログにも対応しています。

## セルフホスティング [#self-hosting]

メールは [Resend](https://resend.com) 経由で送信されます。`RESEND_API_KEY` と `EMAIL_FROM`（Resend で認証済みのドメインのアドレス）を設定してください。設定しない場合、メールは送信されずにログに記録され、チーム招待はコピー可能なリンクで代替されます。

週次ダイジェストは `/api/cron/digest` から送信されます。Vercel では、`apps/app/vercel.json` が毎週月曜日に `?shard=all` を付けてこれを呼び出し、すべての購読者のダイジェストを1回の実行で送信します。購読者が多い場合は、`shard=all` を付けずに月曜日に毎時呼び出すこともできます。その場合、各実行が全体の24分の1を処理します。Vercel 以外の環境では、お使いの環境の `CRON_SECRET` を使って、ご自身のスケジューラーから呼び出してください。

```bash title="Terminal"
curl -H "Authorization: Bearer $CRON_SECRET" "https://your-host/api/cron/digest?shard=all"
```

配信停止リンクは `BETTER_AUTH_SECRET` で署名されています。この値を変更すると、すでに送信済みのメールのリンクは無効になります。詳しくは [セルフホスティング](/docs/self-hosting#scheduled-jobs) をご覧ください。
