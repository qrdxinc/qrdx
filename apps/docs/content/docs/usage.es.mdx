`QRCode` es el componente al que recurrir: admite todas las opciones de estilo y una prop `logo` sencilla, y se renderiza en el servidor. Esta página repasa las props que más vas a usar. Para ver todas las props, consulta la [referencia de la API de la biblioteca](/docs/api-reference).

## Elige un componente [#choose-a-component]

| Componente | Qué dibuja | Úsalo cuando |
| --- | --- | --- |
| `QRCode` | Un `<svg>` con todas las opciones de estilo, además de `logo`, `logoOptions`, `hideLogo` y `scale`. No admite otros atributos | Casi siempre |
| `QRCodeSVG` | El mismo `<svg>`, con el logo indicado como `imageSettings` sin procesar, en píxeles. Cualquier otra prop (`aria-label`, `className`, `role`) va en el `<svg>` | Necesitas atributos en el `<svg>`, colocas el logo tú mismo o migras código de otro renderizador |
| `QRCodeCanvas` | Un `<canvas>` con módulos cuadrados simples y colores sólidos | Necesitas un elemento canvas. Se ignoran los patrones, los colores de los ojos, los degradados y las plantillas |

`QRCode` y `QRCodeSVG` no usan hooks exclusivos del navegador, así que se renderizan en React Server Components y en HTML estático. `QRCodeCanvas` incluye `"use client"`.

```tsx title="components/menu-code.tsx"
import { QRCode } from "qrdx";

export function MenuCode() {
  return (
    <div role="img" aria-label="QR code for the menu">
      <QRCode value="https://example.com/menu" size={256} margin={4} />
    </div>
  );
}
```

`value` se codifica exactamente como lo pasas, así que un payload de Wi-Fi, una vCard, `mailto:` o texto simple funcionan. `QRCode` admite solo las props propias del código y `style`, nada más: dale un nombre accesible envolviéndolo, como arriba. `QRCodeSVG` coloca `aria-label`, `className`, `role` y cualquier otro atributo en el propio `<svg>`.

## Tamaño y zona de silencio [#size-and-quiet-zone]

- `size` es el ancho y el alto en píxeles (por defecto 128). Por debajo de unos 128 px, un código denso resulta difícil de escanear desde una pantalla.
- `margin` es la zona de silencio alrededor del código, en módulos (por defecto 0). El estándar QR pide 4. Defínelo cuando el código esté sobre una foto, un patrón o una página oscura; un código dentro de una tarjeta blanca con su propio relleno puede dejarlo en 0.
- `scale` multiplica `size` en `QRCode`.

Un marco o una plantilla cambian el tamaño de la salida. Consulta [Marco o plantilla](#frame-or-template).

## Colores [#colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1d4ed8"
      bgColor="#f8fafc"
      eyeColor="#0f172a"
      dotColor="#1d4ed8"
    />
  );
}
```

- `fgColor` colorea los módulos de datos, `bgColor` el fondo, `eyeColor` los tres ojos de las esquinas y `dotColor` el punto dentro de cada ojo. Los colores de los ojos usan `fgColor` por defecto.
- Cada uno acepta cualquier color CSS (`#1d4ed8`, `rgb(29 78 216)`, un color con nombre) o un objeto de degradado. [Define colores y degradados](/docs/features/colors-gradients) explica los degradados, los colores transparentes y los rellenos con imagen.
- Mantén los módulos más oscuros que el fondo. Los escáneres leen oscuro sobre claro; un código claro sobre fondo oscuro funciona en la mayoría de las cámaras de teléfono, pero no en algunas apps antiguas.

## Formas [#shapes]

```tsx title="components/rounded-code.tsx"
import { QRCode } from "qrdx";

export function RoundedCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      bodyPattern="rounded"
      cornerEyePattern="extra-rounded"
      cornerEyeDotPattern="rounded"
    />
  );
}
```

- `bodyPattern` da forma a los módulos de datos (por defecto `circle`). Hay {facts.bodyPatterns} para elegir.
- `cornerEyePattern` da forma a los tres ojos de las esquinas (por defecto `gear`), una de {facts.eyeShapes}.
- `cornerEyeDotPattern` da forma al punto dentro de cada ojo (por defecto `circle`), una de {facts.eyeCentres}.

[Formas, ojos y marcos](/docs/styles) dibuja cada valor en vivo. [Elige formas de módulos y ojos](/docs/features/patterns) explica la escala de los módulos, los códigos con forma y los pocos pares que se escanean mal juntos.

## Logo [#logo]

```tsx title="components/logo-code.tsx"
import { QRCode } from "qrdx";

export function LogoCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      level="H"
      logo="/logo.png"
      logoOptions={{ size: 0.2, padding: 1 }}
    />
  );
}
```

`logo` acepta una ruta de tu app, una URL o una URL de datos. Los módulos que quedan detrás se borran, así que el código depende de la corrección de errores para escanearse: usa `level="H"`. `logoOptions` define el ancho del logo como proporción del código (de 0.1 a 0.3, por defecto 0.25), su espacio libre en módulos, su posición y su recorte. El componente nunca dibuja un logo más grande de lo que el código puede reparar. [Añade un logo en código](/docs/features/logos) tiene los detalles.

## Marco o plantilla [#frame-or-template]

```tsx title="components/framed-code.tsx"
import { QRCode } from "qrdx";

export function FramedCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      frame={{ style: "banner-bottom", text: "Scan me", color: "#0f172a" }}
    />
  );
}
```

- `frame` dibuja un marco con llamada a la acción alrededor del código. El código mantiene el ancho `size` y la salida crece para ajustarse al marco. Hay {facts.frameStyles} estilos integrados, además de la biblioteca oficial de marcos y tus propias especificaciones de marco. Consulta [Marcos, puntuación de escaneo y archivos de impresión](/docs/features/frames).
- `templateId` dibuja en su lugar una plantilla como `Arrow` o `StandardBox`. Una plantilla dibuja toda su ilustración al tamaño `size`, con el código más pequeño dentro. Consulta [Usa una plantilla de marco](/docs/features/templates).

Si defines ambos, el marco se dibuja alrededor de la ilustración de la plantilla.

## Corrección de errores [#error-correction]

| `level` | Puede dañarse | Úsalo para |
| --- | --- | --- |
| `L` | alrededor del 7 % | Pantallas limpias, enlaces cortos, el código más pequeño |
| `M` | alrededor del 15 % | Payloads largos como las vCards, donde importa más un código pequeño |
| `Q` | alrededor del 25 % | El valor por defecto. Uso general |
| `H` | alrededor del 30 % | Logos, arte, impresiones que se rayan o se doblan |

Un nivel más alto añade módulos, así que el código se vuelve más denso al mismo tamaño. `autoLevel` sube el nivel a `H` por sí solo cuando un logo cubre más del 7 % del código; está desactivado por defecto para que los códigos existentes conserven su aspecto.
