ホスト型ページでは、QRdxにアップロードしたファイルを表示できます。たとえば、PDFのメニューやパンフレット、フォトギャラリー、音楽やポッドキャスト、動画などです。アップロードしたファイルはサイドバーの **ファイル** にまとまり、アップロードしたワークスペースに属します。各ファイルには固定のリンクがあり、ファイルを差し替えても使い続けられます。ファイルの置き場所が他にない場合や、ページに手を加えずに来シーズンのメニューへ差し替えたい場合にお使いください。

<Callout type="info" title="プラン">
  フリーはワークスペースあたり50 MBのストレージで、ファイルは10 MBまで。Proは5 GBで100 MBまで。Businessは50 GBで250 MBまでです。[プランと制限](/docs/plans-and-limits)をご覧ください。
</Callout>

<Callout type="warn" title="このデプロイではアップロードが設定されていません">

## 仕組み [#how-it-works]

<Diagram id="file-delivery" />

ブラウザーからストレージバケットへ、ファイルを直接アップロードします。その後QRdxがファイルを検査します(サイズと、先頭のバイト列がそのファイル形式のものかどうか)。検査済みのものをファイル専用の場所にコピーし、`https://qrdx.dev/api/files/<id>` というリンクを発行します。ページやコードはこのリンクを使うため、ファイルを差し替えても影響を受けません。

## アップロードできるファイル [#what-you-can-upload]

| 種類 | 形式 |
| --- | --- |
| PDF | PDF |
| 画像 | JPEG, PNG, WebP, GIF, AVIF |
| 音声 | MP3, M4A, AAC, Ogg, WAV |
| 動画 | MP4, WebM, MOV |

H.264動画のMP4は、すべてのブラウザーで再生できます。スマートフォンで撮影したMOVファイルも通常は再生できますが、ブラウザーで再生できない場合はMP4に変換してください。SVG、HTML、アーカイブ、オフィス文書はアップロードできません。これは、ストレージから配信されるものが訪問者のブラウザーでコードを実行しないようにするためです。

アップロードされたファイルは、使用前にすべて検査されます。サイズが申告どおりであること、先頭のバイト列がそのファイル形式のものであることが条件です(`.pdf` に名前を変えたHTMLページは拒否されます)。拒否されたアップロードはストレージから削除され、**ブロック済み** として一覧に表示されます。

## ページでファイルを使う [#use-files-on-a-page]

ファイルを表示するブロックは5種類あります。どのブロックも、アップロードしたファイルか、他の場所にあるファイルへのリンクを使えます。

- **PDF** は、アップロードした文書をタブレットやパソコンではインラインで表示し、**PDFを開く**(スマートフォンでは全画面ビューアー)と、任意のダウンロードボタンを備えます。他のサイトにあるPDFにリンクした場合は、**PDFを開く** ボタンが表示されます。
- **ギャラリー** は、写真を1〜3列のグリッドで表示します。写真をタップすると全画面で開き、スワイプまたは矢印キーで切り替えられます。
- **音声** は、カバーアートとプレイリスト付きでトラックを再生し、1曲が終わると次の曲が始まります。ダウンロードボタンは任意です。
- **動画ファイル** は、アップロードしたMP4またはWebMを再生します。GIFのように消音でループ再生することもできます。YouTube、Vimeo、Loomの場合は、代わりに **動画** ブロックを使ってください。誰かが再生をタップするまで、動画サイトからは何も読み込まれません。
- **ダウンロード** は、保存できるファイルを一覧にし、それぞれに個別のラベルを付けられます。

**新規コード** の **PDF**、**画像**、**MP3 / 音声**、**動画**、**プレイリスト** の各ページタイプでは、これらのブロックがあらかじめ配置された状態から始められます。

ブロックでは、**アップロード** でお使いのデバイスからファイルを追加するか、**自分のファイルから** で以前にアップロードしたファイルを再利用するか、リンクを貼り付けます。

## ファイルを差し替える・削除する [#replace-or-delete-a-file]

サイドバーの **ファイル** を開き、ファイルの横にあるメニューを使います。

- **リンクをコピー** は、そのファイル固有のリンク(`https://qrdx.dev/api/files/<id>`)をコピーします。このリンクは、動的QRコードの宛先としても使えます。
- **ファイルを差し替え…** は、同じリンクのまま新しい内容をアップロードします。たとえば来シーズンのメニューに差し替える場合です。ファイルを使っているページやコードには、1分以内に新しいバージョンが表示されます。差し替えられるのは同じ種類のファイルだけです(PDFはPDFで)。
- **削除** は、ファイルを完全に削除します。ページやコードがまだそのファイルを使っている場合は、先にQRdxがそれらを一覧表示します。削除後、それらのページではファイルがあった場所に「ファイルは利用できません」と表示されます。

<Shot id="files-page" />

メンバーは自分がアップロードしたファイルを差し替え、削除できます。オーナーと管理者は、ワークスペース内のすべてのファイルを管理できます。

## 報告されたファイル [#reported-files]

ホスト型ページにはすべて **不正を報告** リンクがあります。ファイルが規則に違反している場合や、著作権者から削除を求められた場合、QRdxはそのファイルをブロックできます。ブロックされたファイルは、1分以内にすべてのページとQRdxのリンクでの配信が止まり(ページには「ファイルは利用できません」と表示されます)、同一のコピー(25 MBまで)は再度アップロードできなくなります。

## 制限とプラン [#limits-and-plans]

| プラン | ワークスペースあたりのストレージ | 最大ファイルサイズ |
| --- | --- | --- |
| フリー | 50 MB | 10 MB |
| Pro | 5 GB | 100 MB |
| Business | 50 GB | 250 MB |

ワークスペースには、オーナーと請求担当メンバーのうち最も上位のプランが適用されます。制限が止めるのは新規のアップロードだけです。ダウングレード後やワークスペースがストレージの上限を超えている場合でも、すでにアップロードしたファイルは、それを使うすべてのページで引き続き配信されます。新しいファイルをアップロードするには、不要なファイルを削除するか、アップグレードしてください。完了しなかったアップロードは、2時間後にストレージの使用量に含まれなくなります。

## 開発者向け [#for-developers]

ファイルのアップロードと管理はダッシュボードで行います。API側では、コードのデザインで、アップロード済みのロゴをファイルIDで指定して使えます。[コードのスタイルのロゴ](/docs/developers/rest-api#code-logos)をご覧ください。

## ストレージの設定(セルフホスト) [#set-up-storage-self-hosting]

ファイルのアップロードには[Cloudflare R2](https://developers.cloudflare.com/r2/)を使います。R2がない場合、ファイルページにはアップロードを利用できない旨が表示され、アップロードAPIは `503` と「Storage not configured on this server.」を返し、アップロード系の5つのページタイプはピッカーに表示されなくなります。ブロックでは、他の場所にあるファイルへのリンクは引き続き使えます。

1. Cloudflareのダッシュボードで **R2** を開き、バケットを作成します(例: `qrdx-files`)。
2. **R2** → **APIトークンを管理** で、そのバケットに対する **Object Read & Write** 権限のトークンを作成します。
3. 次の環境変数を設定して、再起動します。

   ```bash title="apps/app/.env.local"
   R2_ACCOUNT_ID=your-cloudflare-account-id
   R2_ACCESS_KEY_ID=token-access-key-id
   R2_SECRET_ACCESS_KEY=token-secret-access-key
   R2_BUCKET=qrdx-files
   # Optional: serve files from a public bucket URL or custom domain
   R2_PUBLIC_BASE_URL=https://files.example.com
   ```

4. バケットにCORSポリシーを追加します(**設定** → **CORSポリシー**)。ブラウザーはR2へ直接アップロードするため、バケットは、アプリのオリジンからの `Content-Type` ヘッダー付きの `PUT` リクエストを受け付ける必要があります。

   ```json title="R2 bucket CORS policy"
   [
     {
       "AllowedOrigins": ["https://qrdx.example.com", "http://localhost:3000"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["Content-Type"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

   `https://qrdx.example.com` は、ダッシュボードを開くときに使うオリジン(スキームとホスト。末尾のスラッシュは付けません)に置き換えてください。`http://localhost:3000` は、ローカルの開発サーバーからアップロードする場合にのみ残してください。

### 公開ファイルか署名付きリンクか [#public-files-or-presigned-links]

訪問者は常に `/api/files/<id>` を通してファイルを開きます。このURLは、保存されているオブジェクトへリダイレクトします。

- `R2_PUBLIC_BASE_URL` を設定した場合(バケットに接続したカスタムドメイン、またはその `r2.dev` URL。後者はCloudflareがレート制限をかけており、テスト用途のみが推奨されています)、公開URLへリダイレクトします。オブジェクトキーにはランダムなIDが含まれるため、ファイルの一覧表示や推測はできません。
- 設定しない場合、バケットは非公開のままで、リダイレクトはすべて1時間で期限切れになる署名付きリンクになります。

どちらの場合も、差し替え、削除、ブロックされたファイルは、1分以内にQRdxのリンクでの配信が止まります。ブロックされたファイルは、公開URLからも即座に外れます。オブジェクトはランダムな部分を含む `quarantine/` キーに移動され(管理者が復元できるよう保持されます)、QRdxのリンクは `410 Gone` を返します。

ブラウザーは `staging/` キーにアップロードします。アップロードの検査が済むと、QRdxは検査したバージョンそのものをファイル専用のキーにコピーします。そのため、まだ有効なアップロードリンクがあっても、検査済みのファイルを書き換えることはできません。

<Callout type="info" title="放棄されたアップロードの整理">
  完了しなかったアップロードは、2時間後にストレージの使用量に含まれなくなり、次にそのワークスペースへ誰かがアップロードしたときに整理されます。バケットに、プレフィックス `staging/` のオブジェクトを1日後に削除するオブジェクトライフサイクルルール(**設定** → **オブジェクトライフサイクルルール**)を追加しておくと、放棄されたアップロードの残りも削除されます。
</Callout>
