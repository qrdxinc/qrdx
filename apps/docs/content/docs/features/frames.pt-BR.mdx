A prop `frame` desenha uma moldura "Scan me" em volta do código, `getScanScore` diz se um design vai ser lido, e as funções de impressão geram arquivos vetoriais em tamanho físico, com sangria e marcas de corte. Esta página cobre os três, nessa ordem.

Está criando no Playground ou no painel? Veja [Adicionar uma moldura e uma chamada para ação](/docs/help/designing/frames), [Verificar um design com a pontuação de leitura](/docs/help/designing/scan-score) e [Baixar e imprimir um QR code](/docs/help/getting-started/download-and-print) na Ajuda.

## Molduras de call to action [#call-to-action-frames]

Toda moldura que o QRdx desenha é uma especificação de moldura: uma pequena descrição em JSON de formas, rótulos e cores. Um único motor desenha todas as especificações, então a moldura fica igual em SVG, PNG, PDF e EPS. Há {facts.frames} molduras: {facts.frameStyles} molduras nativas e {facts.officialFrames} [molduras oficiais](#official-frames). Você também pode escrever a sua ou escolher uma da [comunidade](/community/frames).

`frame` funciona em `QRCode`, `QRCodeSVG`, `QRCodeCanvas`, `getQRAsSVG`, `getQRData` e em todos os helpers de download.

```tsx title="components/menu-frame-code.tsx"
import { QRCode } from "qrdx";

export function MenuFrameCode() {
  return (
    <QRCode
      value="https://example.com/menu"
      size={256}
      frame={{
        style: "banner-bottom",
        text: "Scan for the menu",
        color: "#1e3a8a",
      }}
    />
  );
}
```

A moldura é adicionada em volta do código: a saída fica maior, e os módulos e a zona de silêncio nunca são cobertos, então a legibilidade não muda. Um espaço claro na cor de fundo do código separa o código da moldura.

### Molduras nativas [#built-in-frames]

Uma moldura nativa é identificada pelo seu `style`. As opções preenchem os rótulos e as cores da especificação dela:

| Opção | Padrão | Observações |
| --- | --- | --- |
| `style` | nenhum | Um dos {facts.frameStyles} estilos nativos abaixo, `none`, ou `custom` com um `spec` |
| `text` | `"Scan me"` | Até 24 caracteres. Passe `""` para ocultar o rótulo |
| `color` | a cor própria da especificação: preto em todas as molduras nativas, exceto `gradient-border`, que começa em violeta | Cor da moldura |
| `textColor` | branco na moldura, `color` nas áreas claras | Cor do rótulo |
| `secondaryText` | nenhum | Segundo rótulo, até 24 caracteres: a faixa inferior de `banner-top-bottom`, o arco inferior de `circle`, o rodapé de `menu-card` |
| `secondaryColor` | o destaque da especificação, rosa | Cor final de `gradient-border` |
| `fontScale` | `1` | Tamanho do rótulo, de 0,5 a 1,5; os rótulos ainda diminuem para caber |

As molduras nativas, por `style`:

- Faixas e bordas: `banner-bottom`, `banner-top`, `banner-top-bottom`, `border`, `rounded-border`, `gradient-border`, `focus` (colchetes nos cantos)
- Balões: `speech-bubble`, `speech-bubble-top`, `chat-bubble`
- Selos: `circle` (texto em volta de um anel), `badge` (fita), `sticker` (adesivo recortado com sombra)
- Objetos: `polaroid`, `phone`, `ticket`, `tag` (etiqueta de pendurar com furo), `envelope`, `menu-card`

Cada um desses nomes representa uma especificação no motor, e os nomes continuam válidos para sempre. Designs salvos, links da Image API, flags da CLI e códigos que os usam continuam desenhando a mesma moldura. As molduras que eliminam a linha do rótulo quando não há rótulo, como as bordas, continuam fazendo isso. Veja todas, decodificadas no seu navegador, em [Formas, olhos e molduras](/docs/styles#frames).

`BUILT_IN_FRAMES` lista as molduras com seus nomes e especificações (`BUILT_IN_FRAME_SPECS` traz as especificações por estilo). `frameSpecOf` retorna a especificação que qualquer moldura desenha, e `getFrameColors` retorna as cores com que ela pinta:

```ts title="lib/frames.ts"
import { BUILT_IN_FRAMES, frameSpecOf, getFrameColors, getFrameDimensions } from "qrdx";

BUILT_IN_FRAMES.map((frame) => frame.name); // ["Banner", "Top banner", "Two banners", …]

// A built-in style's spec, or a custom frame's own
const ticket = frameSpecOf({ style: "ticket" });

// The frame's options, else its spec's defaults
getFrameColors({ style: "border", color: "#1e3a8a" });
// { frame: "#1e3a8a", text: "#1e3a8a", accent: "#1e3a8a" }

// The output size: a 400 px code in a bottom banner
getFrameDimensions(400, { style: "banner-bottom" }); // { width: 496, height: 568 }
```

Para mudar mais do que os rótulos e as cores, comece uma moldura personalizada a partir de uma especificação nativa: `{ style: "custom", spec: frameSpecOf({ style: "ticket" }) }` desenha o mesmo ticket, e você pode editar as formas dele.

Toda moldura é feita de formas simples e texto com cores opacas, então as exportações em SVG, PNG, PDF e EPS ficam iguais. A borda em degradê é desenhada em finos passos de cor sólida, e as letras curvas da moldura circular são texto rotacionado em todos os formatos. O rótulo usa a pilha de fontes do sistema, então nada é baixado.

`FRAME_STYLES`, `frameSchema` (zod) e os tipos `QRFrame` e `FrameStyle` também são exportados de `qrdx/types` para validação no servidor. A CLI desenha as mesmas molduras com `--frame`, `--frame-text`, `--frame-color` e `--frame-text-color`; veja [CLI](/docs/developers/cli).

### Especificações de moldura [#frame-specs]

Uma especificação de moldura é um JSON com `kind: "qrdx.frame"`, `version: 1`, um tamanho de `artboard`, uma caixa `qr` onde o código fica, `colors` padrão, as `shapes` pintadas atrás do código e os `labels`. As formas são retângulos (com um furo opcional), círculos e anéis, elipses, polígonos, caminhos, linhas e ícones nativos. Elas são preenchidas com um token de tema (`frame`, `text`, `accent`, `background`), uma cor hexadecimal, uma mistura de duas ou um degradê. Uma especificação não contém marcação, links nem imagens. Verifique uma que você não escreveu com `frameSpecSchema` ou `getFrameSpecIssues` de `qrdx/types` antes de armazená-la. O motor a verifica de novo antes de desenhar.

```tsx title="components/custom-frame-code.tsx"
import { QRCode } from "qrdx";
import spec from "./my-frame.json";

export function CustomFrameCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      frame={{ style: "custom", spec, text: "Scan me", color: "#1e3a8a" }}
    />
  );
}
```

Campos opcionais que as molduras nativas e os templates usam (especificações sem eles são desenhadas como antes):

| Campo | O que faz |
| --- | --- |
| `labels[].collapse` | `{ y, height }`. Quando o rótulo não mostra texto, a faixa de `y` até `y + height` é recortada: as linhas abaixo dela sobem e a arte fica mais curta. Formas inteiramente dentro da faixa são omitidas, e formas que a cruzam ficam mais curtas. Uma faixa não pode cruzar o código, o preenchimento dele nem outra faixa |
| `qr.plate` | `"opaque"` (o padrão), `"background"` ou `"none"`. O motor pinta uma placa na cor de fundo do código sob o código. Quando esse fundo é transparente, `"opaque"` pinta a placa e `background` preenche de branco, para que a arte nunca apareça pela zona de silêncio. `"background"` os mantém transparentes e omite a placa; só é permitido quando sob a placa há apenas preenchimentos `background`, ou um anel cujo furo contém a placa. `"none"` não pinta placa nenhuma, então o fundo e a margem do próprio código são o único espaço claro, e `qr.padding` pode ficar abaixo de 4%. Os templates usam essa opção |
| `stroke` | `{ color, width }` em um retângulo, círculo, elipse, polígono ou caminho: um contorno centrado na borda da forma, desenhado depois do preenchimento, com no máximo 10% do lado menor do artboard |
| `colors.text` | Uma cor hexadecimal, ou uma mistura de `frame`, `accent`, `background` e cores hexadecimais, como `{ "mix": ["frame", "accent"], "amount": 0.5 }` para o rótulo da borda em degradê. É o padrão; `textColor` ainda prevalece |

A linha de um rótulo de texto também pode avançar sobre o preenchimento da placa, desde que fique fora do código e que suas maiúsculas fiquem fora do preenchimento no maior tamanho de texto (`fontScale` 1.5). As molduras de borda posicionam o rótulo logo abaixo do código dessa forma.

## Molduras oficiais [#official-frames]

Além das molduras nativas, o QRdx tem {facts.officialFrames} molduras oficiais: designs prontos para calls to action, restaurantes e cafés, lojas e embalagens, beleza e bem-estar, eventos e casamentos, hotéis e viagens, imóveis, carros e estacionamento, saúde e educação, esportes e fitness, negócios e redes sociais, e organizações sem fins lucrativos e grupos comunitários. {facts.seasonalFrames} delas são para feriados e estações, do Ano Novo Lunar, Holi, Eid e Diwali a Hanukkah, Páscoa, Ação de Graças e Natal. Cada uma é uma especificação de moldura com rótulos e cores que você pode mudar, publicada sob CC0, e cada uma é testada para ser lida em distâncias de uso do celular. Na [comunidade](/community/frames), elas são publicadas por @qrdx.

```tsx title="components/official-frame-code.tsx"
import { getOfficialFrame, QRCode } from "qrdx";

const diwali = getOfficialFrame("diwali-diya"); // undefined for an unknown id

export function OfficialFrameCode() {
  return diwali ? (
    <QRCode
      value="https://example.com/offers"
      size={256}
      frame={{ style: "custom", spec: diwali.spec, text: "Scan for offers" }}
    />
  ) : null;
}
```

`OFFICIAL_FRAMES` é a biblioteca inteira, e `OFFICIAL_FRAME_INDEX` lista todas as molduras sem a especificação, para que um seletor possa mostrar a biblioteca e carregar as especificações só quando forem necessárias. A biblioteca é gerada como um módulo à parte, então um app que nunca a importa não a inclui no pacote. Na [Image API](/docs/developers/image-api#community-items) e no [servidor MCP](/docs/developers/mcp), use uma moldura oficial como item da comunidade, como `item=frame:diwali-diya`.

## Vai ler? [#will-it-scan]

`getScanScore` estima com que confiabilidade um design é lido. Ele roda no navegador e carrega o jsQR sob demanda.

```ts title="lib/scan-score.ts"
import { getScanScore } from "qrdx";

const { score, grade, checks } = await getScanScore({
  value: "https://example.com",
  bodyPattern: "circle",
  cornerEyePattern: "gear",
});
// score: 0 to 100, grade: "great" | "ok" | "risky" | "fails"
// checks: [{ id, passed, message, fix? }]
```

O que ele verifica:

- **Decodificação em 96, 160 e 320 px.** O design é renderizado em cada largura, recebe desfoque e perda de contraste parecidos com os de uma câmera e é decodificado algumas vezes em escalas ligeiramente diferentes.
- **Contraste** entre cada cor do código (incluindo pontos de gradiente, cores dos olhos e dos pontos) e o fundo, e se o código é escuro sobre fundo claro.
- **Cobertura do logo** em comparação com o que o nível de correção de erros consegue recuperar.
- **Zona de silêncio**: a margem, mais o espaço que uma moldura adiciona.
- **Risco do formato dos olhos**: olhos `circle` podem não ser reconhecidos por alguns apps leitores, e os olhos `curly`, já descontinuados, falham em decodificadores rigorosos.
- **Pares de estilo** (`style-pair`): formas que falham juntas nos testes de decodificação do pacote, como módulos `small-square` ao lado de olhos quadrados (veja `getStylePairRisk`).

`getImageScanScore(fileOrImage)` faz o mesmo para uma imagem existente: retorna o conteúdo decodificado, além de verificações de decodificação, contraste, polaridade, zona de silêncio e resolução, medidas a partir dos pixels. O [verificador de leitura](/tools/scan-checker) é construído sobre ele. No Node, `scanQRPixels(pixels, expected)` verifica se pixels RGBA brutos são decodificados para um valor, como estão e também pelo modelo de câmera.

<Callout type="info">
  A pontuação é uma heurística baseada em um único decodificador de código aberto. Os apps de câmera dos celulares costumam ser mais tolerantes, então use a pontuação como guia e teste a leitura de impressões importantes.
</Callout>

## Exportação pronta para impressão [#print-ready-export]

`downloadPrintPDF` gera um PDF vetorial em um tamanho físico exato. Módulos, olhos e molduras são caminhos vetoriais; um logo continua sendo uma imagem raster.

```ts title="lib/print.ts"
import { downloadPrintPDF, downloadPrintSVG, getPrintLayout } from "qrdx";

const props = { value: "https://example.com", frame: { style: "banner-bottom" } } as const;

await downloadPrintPDF(props, {
  size: 40, // width of the code itself
  unit: "mm", // or "in"
  bleed: 3, // millimeters on every side
  cropMarks: true,
  colorMode: "cmyk",
});

await downloadPrintSVG(props, { size: 1.5, unit: "in" }); // width="…in" height="…in"

const layout = getPrintLayout(props, { size: 40 });
layout.trimWidth; // finished width in mm, frame included
layout.maxScanDistance; // 400 (mm)
```

- `size` é a largura do código, de 5 mm a 2 m; uma moldura aumenta o tamanho final.
- Com `bleed` (até 20 mm), o fundo ou a cor de uma moldura quadrada se estende além da borda de corte, para que o corte não deixe uma faixa branca. As marcas de corte ficam fora da sangria.
- `colorMode: "cmyk"` usa uma conversão simples (`rgbToCmyk`: K é 1 menos o maior valor entre R, G e B, sem perfil ICC; o preto puro é impresso apenas com K). Peça à gráfica uma conversão com gerenciamento de cor quando as cores exatas da marca forem importantes.
- Gradientes lineares e radiais são impressos como degradês suaves no PDF, em CMYK quando o PDF é CMYK; o SVG de impressão os mantém, mas continua em RGB.
- O texto da moldura no PDF usa Helvetica Bold, então caracteres fora do Latin-1 podem não ser renderizados. Use o SVG para outros alfabetos.
- `getQRAsPrintPDF` e `getQRAsPrintPDFBuffer` retornam o arquivo em vez de baixá-lo, e também funcionam no Node. `getQRAsEPS` gera o mesmo código em EPS; veja [EPS](/docs/features/downloads#eps).

Qual tamanho imprimir: um código é lido a uma distância de cerca de dez vezes a sua largura, então a largura é aproximadamente a distância de leitura dividida por 10 (2 cm de largura para 20 cm). Códigos mais densos precisam de mais; a [calculadora de tamanho de impressão](/tools/print-size) leva isso em conta.
