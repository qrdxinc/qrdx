Cuatro props colorean un código: `fgColor` para los módulos de datos, `bgColor` para el fondo, `eyeColor` para los tres ojos de las esquinas y `dotColor` para el punto dentro de cada ojo. Cada una acepta un color sólido o un objeto de degradado, y los colores de los ojos usan por defecto `fgColor`. Esta página cubre cada tipo de relleno y cómo mantener el código legible.

¿Prefieres diseñar en el Playground o en el panel? Consulta [Elige colores que se escaneen](/docs/help/designing/colors-and-contrast) en la Ayuda.

## Colores sólidos [#solid-colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1a56db"
      bgColor="#f9fafb"
      eyeColor="#0d47a1"
      dotColor="#3b82f6"
    />
  );
}
```

Un color sólido es cualquier color CSS que el motor sepa interpretar: hexadecimal de 3, 4, 6 u 8 dígitos, `rgb()` y `rgba()`, un color con nombre o `transparent`. Otras sintaxis CSS, como `hsl()`, se muestran en el SVG, pero la comprobación de contraste, el PDF y el EPS no pueden leerlas, así que usa las formas anteriores. `{ type: "solid", color: "#1a56db" }` equivale a la cadena de texto.

`eyeColors` define cada ojo por separado (`topLeft`, `topRight`, `bottomLeft`, cada uno con un color o degradado `outer` e `inner`); consulta [Colores por ojo](/docs/features/patterns#per-eye-colors).

### Fondo transparente [#transparent-background]

`bgColor="transparent"` no pinta fondo, así que las descargas en PNG y SVG son transparentes y los archivos PDF y EPS no tienen relleno de fondo. Coloca el código sobre una superficie clara y lisa: los decodificadores necesitan los espacios claros entre módulos.

## Degradados lineales [#linear-gradients]

```tsx title="components/gradient-code.tsx"
import { QRCode } from "qrdx";

export function GradientCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "linear",
        angle: 45,
        stops: [
          { color: "#4f46e5", offset: 0 },
          { color: "#db2777", offset: 100 },
        ],
      }}
    />
  );
}
```

- `angle` está en grados: 0 va de izquierda a derecha, 90 de arriba abajo y 45 desde la esquina superior izquierda hasta la inferior derecha.
- `stops` necesita al menos dos entradas. `offset` es un porcentaje de 0 a 100, y el color de una parada puede incluir alfa.
- Cualquier prop de color acepta un degradado, incluidos `bgColor` y los ojos. `QRCodeCanvas` no puede dibujar degradados y usa la primera parada; usa `QRCode` o `QRCodeSVG`.

Los degradados se incluyen en las descargas SVG, PNG, JPG, WebP y PDF. El PDF de impresión y el EPS los dibujan como sombreados suaves.

## Degradados radiales [#radial-gradients]

```tsx title="components/radial-code.tsx"
import { QRCode } from "qrdx";

export function RadialCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "radial",
        stops: [
          { color: "#0f766e", offset: 0 },
          { color: "#0c4a6e", offset: 100 },
        ],
      }}
    />
  );
}
```

Un degradado radial va desde el centro del código hacia afuera. Su centro y su radio siguen el tamaño del código, así que solo acepta `stops`.

## Degradados angulares [#angular-gradients]

Un degradado angular barre en sentido horario alrededor del centro de lo que rellena, como `conic-gradient` de CSS. `angle` es el punto donde empieza el barrido, en grados en sentido horario desde la parte superior. Los desplazamientos van de 0 a 100 a lo largo de la vuelta.

```tsx title="components/angular-code.tsx"
import { QRCode } from "qrdx";

export function AngularCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "angular",
        angle: 30,
        stops: [
          { color: "#1d4ed8", offset: 0 },
          { color: "#7c3aed", offset: 50 },
          { color: "#1d4ed8", offset: 100 },
        ],
      }}
    />
  );
}
```

SVG no tiene degradado cónico, así que el código dibuja un abanico de cuñas finas, separadas por unos dos niveles de color. PDF y EPS dibujan las mismas cuñas.

## Colores transparentes [#see-through-colors]

Los colores y las paradas de degradado pueden incluir alfa, como `#1d4ed8cc` o `rgba(29, 78, 216, 0.8)`. SVG lo escribe como `fill-opacity` y `stop-opacity`, y PDF lo conserva. EPS no admite transparencia, así que un color transparente se mezcla con el fondo. La comprobación de escaneo evalúa un color transparente tal como se ve sobre el fondo.

## Rellenos de imagen [#image-fills]

Un relleno de imagen pinta una imagen a través del fondo, los módulos o los ojos. La imagen se extiende sobre todo el código, así que los módulos y ojos que comparten una muestran una sola imagen.

```tsx title="components/photo-code.tsx"
import { QRCode } from "qrdx";

export function PhotoCode({ photo }: { photo: string }) {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "image",
        src: photo, // a data:image/jpeg;base64,… URL
        fit: "cover", // or "contain", "tile"
        position: "center",
        scale: 1,
        opacity: 0.45,
        underlay: "#000000",
      }}
    />
  );
}
```

- `src` es la propia imagen, como en un logo. QRdx guarda un relleno de imagen (en códigos, temas y la REST API) solo como una URL `data:image` en base64 (PNG, JPEG, WebP o GIF) de 1,5 MB como máximo; se rechaza una imagen procedente de un enlace. PNG y JPEG se incrustan en todas las exportaciones, y los servidores nunca descargan un enlace.
- `underlay` es un color sólido bajo la imagen. `opacity` lo deja pasar: sobre negro oscurece una foto para los módulos, y sobre blanco aclara una para el fondo.
- El detalle de una imagen se lee como ruido para una cámara, así que la comprobación de escaneo exige más contraste: 7:1 en los módulos o los ojos y 12:1 detrás de ellos (`SCAN_IMAGE_CONTRAST_MIN`). Mide una imagen por su décima parte más clara y más oscura (`getImageTones`). En el editor, **Make it scannable** encuentra la opacidad sobre el color de base que lo cumple.
- SVG, PNG y PDF admiten rellenos de imagen. EPS no; consulta [EPS](/docs/features/downloads#eps).

Los rellenos de imagen se comportan como los logos. Permanecen con el diseño en el editor, en los códigos guardados y en los temas guardados. No pasan a los enlaces `?style=`, a los estilos de la comunidad publicados, a los fragmentos de Get code ni al contexto del chat: allí cada relleno de imagen se sustituye por su color de base. La Image API (`GET /v1/qr`) y el servidor MCP no los aceptan. `POST /v1/codes` y `PATCH /v1/codes/{id}` aceptan uno solo como URL `data:image`, y responden 400 ante cualquier otra cosa.

## Comprueba el contraste [#check-the-contrast]

Los escáneres necesitan módulos oscuros sobre un fondo claro. La puntuación de escaneo comprueba cada color, incluida cada parada de degradado, frente al fondo; se exportan los mismos helpers:

```ts title="lib/check-contrast.ts"
import { getContrastLevel, getContrastRatio } from "qrdx";

const ratio = getContrastRatio("#1a56db", "#f9fafb");
// 5.9

getContrastLevel(ratio);
// { level: "AA", warning: false, message: "Good contrast" }
```

La puntuación de escaneo aprueba una relación de 4,5 o más (`SCAN_CONTRAST_MIN`), resta puntos por debajo de ese valor y suspende el diseño por debajo de 1,5. `getContrastLevel` devuelve `AAA` desde 7, `AA` desde 4,5, `AA Large` desde 3 con una advertencia, y `Fail` por debajo. Un código claro sobre fondo oscuro pasa la relación, pero pierde puntos en la comprobación de polaridad: la mayoría de las cámaras de teléfono lo leen, algunas apps de escáner no.
