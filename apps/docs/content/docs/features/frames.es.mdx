La prop `frame` dibuja un marco "Scan me" alrededor de un código, `getScanScore` te dice si un diseño se podrá escanear, y las funciones de impresión escriben archivos vectoriales en un tamaño físico con sangrado y marcas de corte. Esta página trata los tres temas, en ese orden.

¿Prefieres diseñar en el Playground o en el panel? Consulta [Añadir un marco y una llamada a la acción](/docs/help/designing/frames), [Comprobar un diseño con la puntuación de escaneo](/docs/help/designing/scan-score) y [Descargar e imprimir un código QR](/docs/help/getting-started/download-and-print) en la Ayuda.

## Marcos con llamada a la acción [#call-to-action-frames]

Cada marco que dibuja QRdx es una especificación de marco: una pequeña descripción JSON de formas, etiquetas y colores. Un solo motor dibuja todas las especificaciones, así que un marco se ve igual en SVG, PNG, PDF y EPS. Hay {facts.frames} marcos: {facts.frameStyles} marcos integrados y {facts.officialFrames} [marcos oficiales](#official-frames). También puedes escribir el tuyo o elegir uno de la [comunidad](/community/frames).

`frame` funciona en `QRCode`, `QRCodeSVG`, `QRCodeCanvas`, `getQRAsSVG`, `getQRData` y en todos los asistentes de descarga.

```tsx title="components/menu-frame-code.tsx"
import { QRCode } from "qrdx";

export function MenuFrameCode() {
  return (
    <QRCode
      value="https://example.com/menu"
      size={256}
      frame={{
        style: "banner-bottom",
        text: "Scan for the menu",
        color: "#1e3a8a",
      }}
    />
  );
}
```

El marco se añade alrededor del código: la salida es más grande, y los módulos y la zona de silencio nunca se tapan, por lo que la legibilidad no cambia. Un espacio claro del color de fondo del código separa el código del marco.

### Marcos integrados [#built-in-frames]

Un marco integrado se identifica por su `style`. Las opciones rellenan las etiquetas y los colores de su especificación:

| Opción | Valor por defecto | Notas |
| --- | --- | --- |
| `style` | ninguno | Uno de los {facts.frameStyles} estilos integrados que aparecen abajo, `none`, o `custom` con un `spec` |
| `text` | `"Scan me"` | Hasta 24 caracteres. Pasa `""` para ocultar la etiqueta |
| `color` | el color propio de la especificación: negro en todos los marcos integrados salvo `gradient-border`, que empieza en violeta | Color del marco |
| `textColor` | blanco sobre el marco, `color` sobre zonas claras | Color de la etiqueta |
| `secondaryText` | ninguno | Segunda etiqueta, hasta 24 caracteres: la banda inferior de `banner-top-bottom`, el arco inferior de `circle`, el pie de `menu-card` |
| `secondaryColor` | el acento de la especificación, rosa | Color final de `gradient-border` |
| `fontScale` | `1` | Tamaño de la etiqueta de 0,5 a 1,5; las etiquetas aún se reducen para encajar |

Los marcos integrados, por `style`:

- Banners y bordes: `banner-bottom`, `banner-top`, `banner-top-bottom`, `border`, `rounded-border`, `gradient-border`, `focus` (esquinas en corchete)
- Bocadillos: `speech-bubble`, `speech-bubble-top`, `chat-bubble`
- Insignias: `circle` (texto dispuesto en un anillo), `badge` (cinta), `sticker` (troquelado con sombra)
- Objetos: `polaroid`, `phone`, `ticket`, `tag` (etiqueta colgante con un agujero), `envelope`, `menu-card`

Cada uno de estos nombres representa una especificación del motor, y los nombres seguirán siendo válidos para siempre. Los diseños guardados, los enlaces de la Image API, las opciones de la CLI y el código que los usen seguirán dibujando el mismo marco. Los marcos que eliminan la fila de su etiqueta cuando no hay etiqueta, como los bordes, siguen haciéndolo. Míralos todos, decodificados en tu navegador, en [Formas, ojos y marcos](/docs/styles#frames).

`BUILT_IN_FRAMES` los lista con sus nombres y especificaciones (`BUILT_IN_FRAME_SPECS` tiene las especificaciones por estilo). `frameSpecOf` devuelve la especificación que dibuja cualquier marco, y `getFrameColors` los colores con los que pinta:

```ts title="lib/frames.ts"
import { BUILT_IN_FRAMES, frameSpecOf, getFrameColors, getFrameDimensions } from "qrdx";

BUILT_IN_FRAMES.map((frame) => frame.name); // ["Banner", "Top banner", "Two banners", …]

// A built-in style's spec, or a custom frame's own
const ticket = frameSpecOf({ style: "ticket" });

// The frame's options, else its spec's defaults
getFrameColors({ style: "border", color: "#1e3a8a" });
// { frame: "#1e3a8a", text: "#1e3a8a", accent: "#1e3a8a" }

// The output size: a 400 px code in a bottom banner
getFrameDimensions(400, { style: "banner-bottom" }); // { width: 496, height: 568 }
```

Para cambiar algo más que las etiquetas y los colores, parte de una especificación integrada para crear un marco personalizado: `{ style: "custom", spec: frameSpecOf({ style: "ticket" }) }` dibuja el mismo ticket, y puedes editar sus formas.

Todo marco son formas y texto simples con colores opacos, así que las exportaciones SVG, PNG, PDF y EPS coinciden. El borde degradado se dibuja con finos pasos de color sólido, y las letras curvas del marco circular son texto rotado en todos los formatos. La etiqueta usa la pila de fuentes del sistema, así que no se descarga nada.

`FRAME_STYLES`, `frameSchema` (zod) y los tipos `QRFrame` y `FrameStyle` también se exportan desde `qrdx/types` para validar en el servidor. La CLI dibuja los mismos marcos con `--frame`, `--frame-text`, `--frame-color` y `--frame-text-color`; consulta [CLI](/docs/developers/cli).

### Especificaciones de marco [#frame-specs]

Una especificación de marco es JSON con `kind: "qrdx.frame"`, `version: 1`, un tamaño de `artboard`, un cuadro `qr` donde va el código, `colors` por defecto, las `shapes` pintadas detrás del código y las `labels`. Las formas son rectángulos (con un hueco opcional), círculos y anillos, elipses, polígonos, trazados, líneas e iconos integrados. Se rellenan con un token de tema (`frame`, `text`, `accent`, `background`), un color hexadecimal, una mezcla de dos, o un degradado. Una especificación no contiene marcado, enlaces ni imágenes. Comprueba con `frameSpecSchema` o `getFrameSpecIssues` de `qrdx/types` cualquiera que no hayas escrito tú antes de guardarla. El motor la vuelve a comprobar antes de dibujar.

```tsx title="components/custom-frame-code.tsx"
import { QRCode } from "qrdx";
import spec from "./my-frame.json";

export function CustomFrameCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      frame={{ style: "custom", spec, text: "Scan me", color: "#1e3a8a" }}
    />
  );
}
```

Campos opcionales que usan los marcos integrados y las plantillas (las especificaciones sin ellos se dibujan como antes):

| Campo | Qué hace |
| --- | --- |
| `labels[].collapse` | `{ y, height }`. Cuando la etiqueta no muestra texto, se recorta la banda que va de `y` a `y + height`: las filas inferiores suben y la ilustración se acorta. Las formas que quedan por completo dentro de la banda se omiten, y las que la cruzan se acortan. Una banda no puede cruzar el código, su relleno ni otra banda |
| `qr.plate` | `"opaque"` (el valor por defecto), `"background"` o `"none"`. El motor pinta una placa del color de fondo del código bajo el código. Cuando ese fondo es transparente, `"opaque"` pinta la placa y los rellenos `background` en blanco, de modo que la ilustración nunca se vea a través de la zona de silencio. `"background"` los mantiene transparentes y omite la placa; solo se permite cuando bajo la placa no hay nada más que rellenos `background`, o un anillo cuyo hueco contiene la placa. `"none"` no pinta ninguna placa, así que el fondo y el margen del propio código son su único espacio claro, y `qr.padding` puede ser inferior al 4 %. Las plantillas lo usan |
| `stroke` | `{ color, width }` en un rectángulo, círculo, elipse, polígono o trazado: un contorno centrado en el borde de la forma, dibujado después de su relleno, de como máximo el 10 % del lado más corto del lienzo |
| `colors.text` | Un color hexadecimal, o una mezcla de `frame`, `accent`, `background` y colores hexadecimales, como `{ "mix": ["frame", "accent"], "amount": 0.5 }` para la etiqueta del borde degradado. Es el valor por defecto; `textColor` sigue teniendo prioridad |

La fila de una etiqueta de texto también puede entrar en el relleno de la placa, siempre que no toque el código y que sus mayúsculas queden fuera del relleno con el tamaño de texto más grande (`fontScale` 1.5). Los marcos de borde colocan así su etiqueta justo debajo del código.

## Marcos oficiales [#official-frames]

Además de los marcos integrados, QRdx tiene {facts.officialFrames} marcos oficiales: diseños listos para usar para llamadas a la acción, restaurantes y cafeterías, tiendas y embalajes, belleza y bienestar, eventos y bodas, hoteles y viajes, inmobiliarias, coches y aparcamientos, salud y educación, deporte y fitness, negocios y redes sociales, y organizaciones sin ánimo de lucro y grupos comunitarios. {facts.seasonalFrames} de ellos son para festividades y estaciones, desde el Año Nuevo Lunar, Holi, Eid y Diwali hasta Hanukkah, Pascua, Acción de Gracias y Navidad. Cada uno es una especificación de marco con etiquetas y colores que puedes cambiar, publicada bajo CC0, y cada uno se ha probado para que se escanee a las distancias habituales de un teléfono. En la [comunidad](/community/frames) los publica @qrdx.

```tsx title="components/official-frame-code.tsx"
import { getOfficialFrame, QRCode } from "qrdx";

const diwali = getOfficialFrame("diwali-diya"); // undefined for an unknown id

export function OfficialFrameCode() {
  return diwali ? (
    <QRCode
      value="https://example.com/offers"
      size={256}
      frame={{ style: "custom", spec: diwali.spec, text: "Scan for offers" }}
    />
  ) : null;
}
```

`OFFICIAL_FRAMES` es la biblioteca completa, y `OFFICIAL_FRAME_INDEX` lista cada marco sin su especificación, de modo que un selector pueda mostrar la biblioteca y cargar las especificaciones solo cuando se necesiten. La biblioteca se compila como un módulo aparte, así que una aplicación que nunca la importa no la incluye. En la [Image API](/docs/developers/image-api#community-items) y en el [servidor MCP](/docs/developers/mcp), usa un marco oficial como elemento de la comunidad, por ejemplo `item=frame:diwali-diya`.

## ¿Se escaneará? [#will-it-scan]

`getScanScore` estima con qué fiabilidad se escanea un diseño. Se ejecuta en el navegador y carga jsQR bajo demanda.

```ts title="lib/scan-score.ts"
import { getScanScore } from "qrdx";

const { score, grade, checks } = await getScanScore({
  value: "https://example.com",
  bodyPattern: "circle",
  cornerEyePattern: "gear",
});
// score: 0 to 100, grade: "great" | "ok" | "risky" | "fails"
// checks: [{ id, passed, message, fix? }]
```

Qué comprueba:

- **Decodificación a 96, 160 y 320 px.** El diseño se renderiza con cada ancho, se le aplica desenfoque y pérdida de contraste similares a los de una cámara, y se decodifica varias veces con escalas ligeramente distintas.
- **Contraste** entre cada color del código (incluidos los puntos de parada del degradado y los colores de los ojos y de los puntos) y el fondo, y si el código es oscuro sobre fondo claro.
- **Cobertura del logo** en comparación con lo que el nivel de corrección de errores puede recuperar.
- **Zona de silencio**: el margen, más el espacio que añade un marco.
- **Riesgo de la forma de los ojos**: algunas aplicaciones de escaneo pueden no detectar los ojos `circle`, y los ojos `curly`, ya retirados, fallan con decodificadores estrictos.
- **Combinaciones de estilos** (`style-pair`): formas que fallan juntas en las pruebas de decodificación del paquete, como módulos `small-square` junto a ojos cuadrados (consulta `getStylePairRisk`).

`getImageScanScore(fileOrImage)` hace lo mismo con una imagen existente: devuelve el contenido decodificado junto con comprobaciones de decodificación, contraste, polaridad, zona de silencio y resolución medidas a partir de los píxeles. El [verificador de escaneo](/tools/scan-checker) está basado en ella. En Node, `scanQRPixels(pixels, expected)` comprueba que los píxeles RGBA en bruto se decodifiquen a un valor, tal cual y a través del modelo de cámara.

<Callout type="info">
  La puntuación es una heurística basada en un único decodificador de código abierto. Las aplicaciones de cámara de los teléfonos suelen ser más tolerantes, así que úsala como guía y prueba el escaneo de las impresiones importantes.
</Callout>

## Exportación lista para imprimir [#print-ready-export]

`downloadPrintPDF` genera un PDF vectorial con un tamaño físico exacto. Los módulos, los ojos y los marcos son trazados vectoriales; un logo sigue siendo una imagen ráster.

```ts title="lib/print.ts"
import { downloadPrintPDF, downloadPrintSVG, getPrintLayout } from "qrdx";

const props = { value: "https://example.com", frame: { style: "banner-bottom" } } as const;

await downloadPrintPDF(props, {
  size: 40, // width of the code itself
  unit: "mm", // or "in"
  bleed: 3, // millimeters on every side
  cropMarks: true,
  colorMode: "cmyk",
});

await downloadPrintSVG(props, { size: 1.5, unit: "in" }); // width="…in" height="…in"

const layout = getPrintLayout(props, { size: 40 });
layout.trimWidth; // finished width in mm, frame included
layout.maxScanDistance; // 400 (mm)
```

- `size` es el ancho del código, de 5 mm a 2 m; un marco se suma al tamaño final.
- Con `bleed` (hasta 20 mm), el fondo o el color de un marco cuadrado se extiende más allá del borde de corte para que al recortar no quede ninguna franja blanca. Las marcas de corte quedan fuera del sangrado.
- `colorMode: "cmyk"` usa una conversión sencilla (`rgbToCmyk`: K es 1 menos el mayor valor de R, G y B, sin perfil ICC; el negro puro se imprime solo con K). Pide a tu imprenta una conversión con gestión de color cuando los colores exactos de tu marca sean importantes.
- Los degradados lineales y radiales se imprimen como sombreados suaves en el PDF, en CMYK cuando el PDF es CMYK; el SVG de impresión los conserva, pero se mantiene en RGB.
- El texto del marco en el PDF usa Helvetica Bold, por lo que los caracteres fuera de Latin-1 pueden no mostrarse. Usa el SVG para otros alfabetos.
- `getQRAsPrintPDF` y `getQRAsPrintPDFBuffer` devuelven el archivo en lugar de descargarlo, y también funcionan en Node. `getQRAsEPS` genera el mismo código como EPS; consulta [EPS](/docs/features/downloads#eps).

Qué tamaño imprimir: un código se escanea desde una distancia de unas diez veces su ancho, así que el ancho es aproximadamente la distancia de escaneo dividida entre 10 (2 cm de ancho para 20 cm). Los códigos más densos necesitan más; la [calculadora de tamaño de impresión](/tools/print-size) lo tiene en cuenta.
