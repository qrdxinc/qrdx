Quattro prop colorano un codice: `fgColor` per i moduli dei dati, `bgColor` per lo sfondo, `eyeColor` per i tre occhi agli angoli e `dotColor` per il punto all'interno di ogni occhio. Ognuna accetta un colore a tinta unita o un oggetto sfumatura, e i colori degli occhi usano `fgColor` come valore predefinito. Questa pagina copre ogni tipo di riempimento e come mantenere il codice leggibile.

Stai progettando nel Playground o nella dashboard? Vedi [Scegli colori che si scansionano bene](/docs/help/designing/colors-and-contrast) nella Guida.

## Colori a tinta unita [#solid-colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1a56db"
      bgColor="#f9fafb"
      eyeColor="#0d47a1"
      dotColor="#3b82f6"
    />
  );
}
```

Un colore a tinta unita è qualsiasi colore CSS che il motore sa interpretare: esadecimale con 3, 4, 6 o 8 cifre, `rgb()` e `rgba()`, un colore con nome oppure `transparent`. Altre sintassi CSS come `hsl()` vengono rese nell'SVG, ma il controllo del contrasto, il PDF e l'EPS non riescono a leggerle, quindi attieniti alle forme indicate sopra. `{ type: "solid", color: "#1a56db" }` equivale alla stringa.

`eyeColors` imposta ogni occhio separatamente (`topLeft`, `topRight`, `bottomLeft`, ciascuno con un colore o una sfumatura per `outer` e `inner`); vedi [Colori per singolo occhio](/docs/features/patterns#per-eye-colors).

### Sfondo trasparente [#transparent-background]

`bgColor="transparent"` non disegna alcuno sfondo, quindi i download PNG e SVG sono trasparenti e i file PDF ed EPS non hanno riempimento di sfondo. Posiziona il codice su una superficie chiara e uniforme: i decodificatori hanno bisogno degli spazi chiari tra i moduli.

## Sfumature lineari [#linear-gradients]

```tsx title="components/gradient-code.tsx"
import { QRCode } from "qrdx";

export function GradientCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "linear",
        angle: 45,
        stops: [
          { color: "#4f46e5", offset: 0 },
          { color: "#db2777", offset: 100 },
        ],
      }}
    />
  );
}
```

- `angle` è in gradi: 0 va da sinistra a destra, 90 dall'alto in basso, 45 dall'angolo in alto a sinistra fino all'angolo in basso a destra.
- `stops` richiede almeno due voci. `offset` è una percentuale da 0 a 100 e il colore di un punto può includere l'alpha.
- Qualsiasi prop di colore accetta una sfumatura, inclusi `bgColor` e gli occhi. `QRCodeCanvas` non può disegnare sfumature e usa il primo punto; usa `QRCode` o `QRCodeSVG`.

Le sfumature vengono mantenute nei download SVG, PNG, JPG, WebP e PDF. Il PDF di stampa e l'EPS le disegnano come sfumature continue.

## Sfumature radiali [#radial-gradients]

```tsx title="components/radial-code.tsx"
import { QRCode } from "qrdx";

export function RadialCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "radial",
        stops: [
          { color: "#0f766e", offset: 0 },
          { color: "#0c4a6e", offset: 100 },
        ],
      }}
    />
  );
}
```

Una sfumatura radiale va dal centro del codice verso l'esterno. Il suo centro e il suo raggio seguono le dimensioni del codice, quindi accetta solo `stops`.

## Sfumature angolari [#angular-gradients]

Una sfumatura angolare ruota in senso orario attorno al centro dell'area che riempie, come `conic-gradient` in CSS. `angle` è il punto da cui parte la rotazione, in gradi in senso orario a partire dall'alto. Gli offset vanno da 0 a 100 lungo il giro.

```tsx title="components/angular-code.tsx"
import { QRCode } from "qrdx";

export function AngularCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "angular",
        angle: 30,
        stops: [
          { color: "#1d4ed8", offset: 0 },
          { color: "#7c3aed", offset: 50 },
          { color: "#1d4ed8", offset: 100 },
        ],
      }}
    />
  );
}
```

SVG non ha una sfumatura conica, quindi il codice disegna un ventaglio di sottili spicchi, distanti circa due livelli di colore l'uno dall'altro. PDF ed EPS disegnano gli stessi spicchi.

## Colori trasparenti [#see-through-colors]

Colori e punti della sfumatura possono includere l'alpha, ad esempio `#1d4ed8cc` o `rgba(29, 78, 216, 0.8)`. SVG lo scrive come `fill-opacity` e `stop-opacity`, e il PDF lo mantiene. L'EPS non supporta la trasparenza, quindi un colore trasparente viene mescolato con lo sfondo. Il controllo della scansione valuta un colore trasparente per come appare sullo sfondo.

## Riempimenti con immagine [#image-fills]

Un riempimento con immagine dipinge una figura attraverso lo sfondo, i moduli o gli occhi. L'immagine viene stesa su tutto il codice, quindi moduli e occhi che ne condividono una mostrano un'unica immagine.

```tsx title="components/photo-code.tsx"
import { QRCode } from "qrdx";

export function PhotoCode({ photo }: { photo: string }) {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "image",
        src: photo, // a data:image/jpeg;base64,… URL
        fit: "cover", // or "contain", "tile"
        position: "center",
        scale: 1,
        opacity: 0.45,
        underlay: "#000000",
      }}
    />
  );
}
```

- `src` è l'immagine stessa, come per un logo. QRdx salva un riempimento con immagine (nei codici, nei temi e nella REST API) solo come URL `data:image` in base64 (PNG, JPEG, WebP o GIF) di al massimo 1,5 MB; un'immagine da un link viene rifiutata. PNG e JPEG vengono incorporati in ogni esportazione e i server non scaricano mai un link.
- `underlay` è un colore a tinta unita sotto l'immagine. `opacity` lo lascia trasparire: sul nero scurisce una foto per i moduli, sul bianco ne schiarisce una per lo sfondo.
- I dettagli di un'immagine sono rumore per una fotocamera, quindi il controllo della scansione richiede più contrasto: 7:1 nei moduli o negli occhi, 12:1 dietro di essi (`SCAN_IMAGE_CONTRAST_MIN`). Misura un'immagine in base al suo decimo più chiaro e al suo decimo più scuro (`getImageTones`). Nell'editor, **Make it scannable** trova l'opacità sopra l'underlay che supera il controllo.
- SVG, PNG e PDF supportano i riempimenti con immagine. L'EPS no; vedi [EPS](/docs/features/downloads#eps).

I riempimenti con immagine si comportano come i loghi. Restano con il design nell'editor, nei codici salvati e nei temi salvati. Non vengono inclusi nei link `?style=`, negli stili della community pubblicati, negli snippet di Get code né nel contesto della chat: lì ogni riempimento con immagine cede il posto al suo colore underlay. L'Image API (`GET /v1/qr`) e il server MCP non li accettano. `POST /v1/codes` e `PATCH /v1/codes/{id}` ne accettano uno solo come URL `data:image` e rispondono con 400 per qualsiasi altra cosa.

## Verifica il contrasto [#check-the-contrast]

Gli scanner richiedono moduli scuri su sfondo chiaro. Il punteggio di scansione controlla ogni colore, incluso ogni punto della sfumatura, rispetto allo sfondo; gli stessi helper sono esportati:

```ts title="lib/check-contrast.ts"
import { getContrastLevel, getContrastRatio } from "qrdx";

const ratio = getContrastRatio("#1a56db", "#f9fafb");
// 5.9

getContrastLevel(ratio);
// { level: "AA", warning: false, message: "Good contrast" }
```

Il punteggio di scansione approva un rapporto di 4.5 o superiore (`SCAN_CONTRAST_MIN`), toglie punti sotto tale soglia e boccia il design sotto 1.5. `getContrastLevel` restituisce `AAA` da 7, `AA` da 4.5, `AA Large` da 3 con un avviso e `Fail` sotto. Un codice chiaro su sfondo scuro supera il rapporto ma perde punti nel controllo della polarità: la maggior parte delle fotocamere dei telefoni lo legge, alcune app di scansione no.
