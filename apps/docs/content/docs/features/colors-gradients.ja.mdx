4つのpropでコードに色を付けます。データモジュールには `fgColor`、背景には `bgColor`、3つの角のアイには `eyeColor`、各アイの内側のドットには `dotColor` を使います。どれも単色またはグラデーションオブジェクトを受け取り、アイの色は既定で `fgColor` になります。このページでは、すべての塗りの種類と、コードを読み取れる状態に保つ方法を説明します。

Playgroundやダッシュボードでデザインする場合は、ヘルプの[スキャンできる色の選び方](/docs/help/designing/colors-and-contrast)をご覧ください。

## 単色 [#solid-colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1a56db"
      bgColor="#f9fafb"
      eyeColor="#0d47a1"
      dotColor="#3b82f6"
    />
  );
}
```

単色には、エンジンが解析できるCSSの色を指定できます。3桁、4桁、6桁、8桁の16進数、`rgb()` と `rgba()`、色名、`transparent` が使えます。`hsl()` などそれ以外のCSS構文はSVGでは描画されますが、コントラストチェック、PDF、EPSでは読み取れないため、上記の形式を使ってください。`{ type: "solid", color: "#1a56db" }` は文字列で指定した場合と同じです。

`eyeColors` では各アイを個別に設定できます（`topLeft`、`topRight`、`bottomLeft` それぞれに、`outer` と `inner` の色またはグラデーションを指定します）。詳しくは[アイごとの色](/docs/features/patterns#per-eye-colors)をご覧ください。

### 透過背景 [#transparent-background]

`bgColor="transparent"` を指定すると背景は描画されません。そのため、PNGとSVGのダウンロードは透過になり、PDFとEPSのファイルには背景の塗りがなくなります。コードは明るい無地の面に置いてください。デコーダーにはモジュール間の明るい隙間が必要です。

## 線形グラデーション [#linear-gradients]

```tsx title="components/gradient-code.tsx"
import { QRCode } from "qrdx";

export function GradientCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "linear",
        angle: 45,
        stops: [
          { color: "#4f46e5", offset: 0 },
          { color: "#db2777", offset: 100 },
        ],
      }}
    />
  );
}
```

- `angle` は度数で指定します。0は左から右、90は上から下、45は左上から右下に向かいます。
- `stops` には2つ以上の要素が必要です。`offset` は0から100までのパーセンテージで、ストップの色にはアルファを含められます。
- グラデーションは `bgColor` やアイを含め、どの色propでも使えます。`QRCodeCanvas` はグラデーションを描画できず、最初のストップを使います。`QRCode` または `QRCodeSVG` を使ってください。

グラデーションは、SVG、PNG、JPG、WebP、PDFのダウンロードに反映されます。印刷用PDFとEPSでは、なめらかなシェーディングとして描画されます。

## 放射グラデーション [#radial-gradients]

```tsx title="components/radial-code.tsx"
import { QRCode } from "qrdx";

export function RadialCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "radial",
        stops: [
          { color: "#0f766e", offset: 0 },
          { color: "#0c4a6e", offset: 100 },
        ],
      }}
    />
  );
}
```

放射グラデーションは、コードの中心から外側に向かって広がります。中心と半径はコードのサイズに合わせて決まるため、指定するのは `stops` だけです。

## 角度グラデーション [#angular-gradients]

角度グラデーションは、CSSの `conic-gradient` と同様に、塗りつぶす領域の中心を軸に時計回りに広がります。`angle` は広がりの開始位置で、真上から時計回りの度数で指定します。オフセットは、一周を0から100として指定します。

```tsx title="components/angular-code.tsx"
import { QRCode } from "qrdx";

export function AngularCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "angular",
        angle: 30,
        stops: [
          { color: "#1d4ed8", offset: 0 },
          { color: "#7c3aed", offset: 50 },
          { color: "#1d4ed8", offset: 100 },
        ],
      }}
    />
  );
}
```

SVGには円錐グラデーションがないため、コードは色の段階がおよそ2つ違いの細いくさび形を扇状に並べて描画します。PDFとEPSでも同じくさび形を描画します。

## 透過色 [#see-through-colors]

色やグラデーションのストップには、`#1d4ed8cc` や `rgba(29, 78, 216, 0.8)` のようにアルファを含められます。SVGでは `fill-opacity` と `stop-opacity` として書き出され、PDFでも保持されます。EPSには透明度がないため、透過色は背景と混ぜ合わされます。スキャンチェックは、透過色を背景の上での見た目で判定します。

## 画像塗りつぶし [#image-fills]

画像塗りつぶしは、背景、モジュール、アイに画像を敷きます。画像はコード全体に重ねて配置されるため、同じ画像を共有するモジュールとアイには、1枚の画像として表示されます。

```tsx title="components/photo-code.tsx"
import { QRCode } from "qrdx";

export function PhotoCode({ photo }: { photo: string }) {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "image",
        src: photo, // a data:image/jpeg;base64,… URL
        fit: "cover", // or "contain", "tile"
        position: "center",
        scale: 1,
        opacity: 0.45,
        underlay: "#000000",
      }}
    />
  );
}
```

- `src` はロゴと同様、画像そのものです。QRdxは、画像塗りつぶし（コード、テーマ、REST APIのいずれでも）を、1.5 MB以下のbase64の `data:image` URL（PNG、JPEG、WebP、GIF）としてのみ保存します。リンク先の画像は受け付けられません。PNGとJPEGはすべてのエクスポートに埋め込まれ、サーバーがリンクを取得することはありません。
- `underlay` は画像の下に敷く単色です。`opacity` を下げると下の色が透けて見えます。黒の上ではモジュール用に写真が暗くなり、白の上では背景用に写真が明るくなります。
- 画像の細部はカメラにはノイズとして読み取られるため、スキャンチェックはより高いコントラストを求めます。モジュールまたはアイでは7:1、その背後では12:1です（`SCAN_IMAGE_CONTRAST_MIN`）。画像は、最も明るい10分の1と最も暗い10分の1で測定されます（`getImageTones`）。エディターでは、**Make it scannable** が、underlayの上でチェックに通る不透明度を見つけます。
- 画像塗りつぶしに対応しているのは、SVG、PNG、PDFです。EPSは非対応です。[EPS](/docs/features/downloads#eps)をご覧ください。

画像塗りつぶしはロゴと同じように扱われます。エディター内、保存したコード、保存したテーマではデザインとともに保持されます。一方、`?style=` リンク、公開されたコミュニティスタイル、Get codeスニペット、チャットのコンテキストには含まれず、そこでは各画像塗りつぶしがunderlayの色に置き換わります。Image API（`GET /v1/qr`）とMCPサーバーでは使えません。`POST /v1/codes` と `PATCH /v1/codes/{id}` は `data:image` URLの場合のみ受け付け、それ以外には400を返します。

## コントラストを確認する [#check-the-contrast]

スキャナーが読み取るには、明るい背景に暗いモジュールが必要です。スキャンスコアは、各グラデーションのストップを含むすべての色を背景と照らして確認します。同じヘルパーもエクスポートされています。

```ts title="lib/check-contrast.ts"
import { getContrastLevel, getContrastRatio } from "qrdx";

const ratio = getContrastRatio("#1a56db", "#f9fafb");
// 5.9

getContrastLevel(ratio);
// { level: "AA", warning: false, message: "Good contrast" }
```

スキャンスコアは、比率が4.5以上（`SCAN_CONTRAST_MIN`）であれば合格とし、それを下回ると減点し、1.5未満ではデザインを不合格とします。`getContrastLevel` は、7以上で `AAA`、4.5以上で `AA`、3以上で警告付きの `AA Large`、それ未満で `Fail` を返します。暗い背景に明るいコードを置いた場合、比率は合格しますが、極性チェックで減点されます。ほとんどのスマートフォンのカメラは読み取れますが、読み取れないスキャナーアプリもあります。
