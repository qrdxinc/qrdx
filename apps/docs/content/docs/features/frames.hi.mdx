`frame` prop कोड के चारों ओर "Scan me" फ्रेम बनाता है, `getScanScore` बताता है कि कोई डिज़ाइन स्कैन होगा या नहीं, और print फ़ंक्शन bleed और crop marks के साथ भौतिक साइज़ में वेक्टर फ़ाइलें लिखते हैं। इस पेज में इन तीनों की जानकारी इसी क्रम में है।

अगर आप playground या डैशबोर्ड में डिज़ाइन कर रहे हैं, तो Help में [फ्रेम और call to action जोड़ें](/docs/help/designing/frames), [स्कैन स्कोर से डिज़ाइन जांचें](/docs/help/designing/scan-score) और [QR कोड डाउनलोड और प्रिंट करें](/docs/help/getting-started/download-and-print) देखें।

## Call-to-action फ्रेम [#call-to-action-frames]

QRdx जो भी फ्रेम बनाता है, वह एक फ्रेम स्पेक होता है: शेप, लेबल और रंगों का छोटा JSON विवरण। हर स्पेक को एक ही इंजन बनाता है, इसलिए फ्रेम SVG, PNG, PDF और EPS में एक जैसा दिखता है। कुल {facts.frames} फ्रेम हैं: {facts.frameStyles} बिल्ट-इन फ्रेम और {facts.officialFrames} [आधिकारिक फ्रेम](#official-frames)। आप अपना फ्रेम भी लिख सकते हैं या [कम्युनिटी](/community/frames) से चुन सकते हैं।

`frame` इन सब पर काम करता है: `QRCode`, `QRCodeSVG`, `QRCodeCanvas`, `getQRAsSVG`, `getQRData` और हर download helper।

```tsx title="components/menu-frame-code.tsx"
import { QRCode } from "qrdx";

export function MenuFrameCode() {
  return (
    <QRCode
      value="https://example.com/menu"
      size={256}
      frame={{
        style: "banner-bottom",
        text: "Scan for the menu",
        color: "#1e3a8a",
      }}
    />
  );
}
```

फ्रेम कोड के चारों ओर जोड़ा जाता है: आउटपुट बड़ा हो जाता है, और modules व quiet zone कभी नहीं ढकते, इसलिए स्कैन करने की क्षमता नहीं बदलती। कोड के बैकग्राउंड रंग की एक हल्की खाली जगह कोड को फ्रेम से अलग रखती है।

### बिल्ट-इन फ्रेम [#built-in-frames]

बिल्ट-इन फ्रेम का नाम उसकी `style` से तय होता है। विकल्प उसके स्पेक के लेबल और रंग भरते हैं:

| विकल्प | डिफ़ॉल्ट | नोट्स |
| --- | --- | --- |
| `style` | none | नीचे दी गई {facts.frameStyles} बिल्ट-इन स्टाइल में से एक, `none`, या `spec` के साथ `custom` |
| `text` | `"Scan me"` | अधिकतम 24 अक्षर। लेबल छिपाने के लिए `""` दें |
| `color` | स्पेक का अपना रंग: `gradient-border` को छोड़कर हर बिल्ट-इन फ्रेम के लिए काला, जबकि `gradient-border` बैंगनी से शुरू होता है | फ्रेम का रंग |
| `textColor` | फ्रेम पर सफ़ेद, हल्के हिस्सों पर `color` | लेबल का रंग |
| `secondaryText` | none | दूसरा लेबल, अधिकतम 24 अक्षर: `banner-top-bottom` का निचला बैंड, `circle` का निचला आर्क, `menu-card` का फ़ुटर |
| `secondaryColor` | स्पेक का accent, गुलाबी | `gradient-border` का अंतिम रंग |
| `fontScale` | `1` | 0.5 से 1.5 तक लेबल का साइज़; लेबल फिर भी फिट होने के लिए छोटे हो जाते हैं |

`style` के अनुसार बिल्ट-इन फ्रेम:

- बैनर और बॉर्डर: `banner-bottom`, `banner-top`, `banner-top-bottom`, `border`, `rounded-border`, `gradient-border`, `focus` (कोनों के ब्रैकेट)
- बबल: `speech-bubble`, `speech-bubble-top`, `chat-bubble`
- बैज: `circle` (रिंग के चारों ओर टेक्स्ट), `badge` (रिबन), `sticker` (शैडो के साथ डाई-कट)
- ऑब्जेक्ट: `polaroid`, `phone`, `ticket`, `tag` (छेद वाला हैंग टैग), `envelope`, `menu-card`

इनमें से हर नाम इंजन में एक स्पेक के लिए है, और ये नाम हमेशा के लिए मान्य रहते हैं। इन्हें इस्तेमाल करने वाले सेव किए गए डिज़ाइन, image API लिंक, CLI फ़्लैग और कोड वही फ्रेम बनाते रहेंगे। जो फ्रेम लेबल न होने पर उसकी पंक्ति हटा देते हैं, जैसे बॉर्डर, वे अब भी ऐसा ही करते हैं। इन सभी को आपके ब्राउज़र में डिकोड होते हुए [शेप, आइज़ और फ्रेम](/docs/styles#frames) में देखें।

`BUILT_IN_FRAMES` इन्हें नाम और स्पेक के साथ सूचीबद्ध करता है (`BUILT_IN_FRAME_SPECS` में स्टाइल के अनुसार स्पेक हैं)। `frameSpecOf` वह स्पेक लौटाता है जिसे कोई भी फ्रेम बनाता है, और `getFrameColors` वे रंग लौटाता है जिनसे वह पेंट होता है:

```ts title="lib/frames.ts"
import { BUILT_IN_FRAMES, frameSpecOf, getFrameColors, getFrameDimensions } from "qrdx";

BUILT_IN_FRAMES.map((frame) => frame.name); // ["Banner", "Top banner", "Two banners", …]

// A built-in style's spec, or a custom frame's own
const ticket = frameSpecOf({ style: "ticket" });

// The frame's options, else its spec's defaults
getFrameColors({ style: "border", color: "#1e3a8a" });
// { frame: "#1e3a8a", text: "#1e3a8a", accent: "#1e3a8a" }

// The output size: a 400 px code in a bottom banner
getFrameDimensions(400, { style: "banner-bottom" }); // { width: 496, height: 568 }
```

लेबल और रंगों से ज़्यादा कुछ बदलना हो, तो बिल्ट-इन स्पेक से कस्टम फ्रेम शुरू करें: `{ style: "custom", spec: frameSpecOf({ style: "ticket" }) }` वही ticket बनाता है, और आप उसकी शेप एडिट कर सकते हैं।

हर फ्रेम सादी शेप और टेक्स्ट से बना है, जिनमें अपारदर्शी रंग हैं, इसलिए SVG, PNG, PDF और EPS एक्सपोर्ट एक जैसे रहते हैं। gradient border बारीक ठोस रंग के चरणों से बनता है, और circle फ्रेम के घुमावदार अक्षर हर फ़ॉर्मैट में घुमाया हुआ टेक्स्ट होते हैं। लेबल सिस्टम फ़ॉन्ट स्टैक इस्तेमाल करता है, इसलिए कुछ भी डाउनलोड नहीं होता।

`FRAME_STYLES`, `frameSchema` (zod) और `QRFrame` व `FrameStyle` टाइप सर्वर-साइड वैलिडेशन के लिए `qrdx/types` से भी एक्सपोर्ट होते हैं। CLI `--frame`, `--frame-text`, `--frame-color` और `--frame-text-color` से वही फ्रेम बनाता है; देखें [CLI](/docs/developers/cli)।

### फ्रेम स्पेक [#frame-specs]

फ्रेम स्पेक एक JSON है जिसमें `kind: "qrdx.frame"`, `version: 1`, `artboard` साइज़, कोड रखने की `qr` बॉक्स, डिफ़ॉल्ट `colors`, कोड के पीछे पेंट होने वाली `shapes` और `labels` होते हैं। शेप में rect (वैकल्पिक छेद के साथ), circle और ring, ellipse, polygon, path, line और बिल्ट-इन आइकन शामिल हैं। इन्हें थीम टोकन (`frame`, `text`, `accent`, `background`), hex रंग, दो रंगों के मिश्रण या gradient से भरा जाता है। स्पेक में कोई markup, लिंक या इमेज नहीं होती। जो स्पेक आपने नहीं लिखा, उसे स्टोर करने से पहले `qrdx/types` के `frameSpecSchema` या `getFrameSpecIssues` से जांचें। इंजन भी बनाने से पहले उसे दोबारा जांचता है।

```tsx title="components/custom-frame-code.tsx"
import { QRCode } from "qrdx";
import spec from "./my-frame.json";

export function CustomFrameCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      frame={{ style: "custom", spec, text: "Scan me", color: "#1e3a8a" }}
    />
  );
}
```

वैकल्पिक फ़ील्ड जिन्हें बिल्ट-इन फ्रेम और templates इस्तेमाल करते हैं (इनके बिना वाले स्पेक पहले की तरह ही बनते हैं):

| फ़ील्ड | क्या करता है |
| --- | --- |
| `labels[].collapse` | `{ y, height }`। जब लेबल में टेक्स्ट नहीं दिखता, तो `y` से `y + height` तक का बैंड काट दिया जाता है: उसके नीचे की पंक्तियां ऊपर खिसक जाती हैं और आर्टवर्क छोटा हो जाता है। जो शेप पूरी तरह बैंड के अंदर हों वे छोड़ दी जाती हैं, और जो उसे पार करती हैं वे छोटी हो जाती हैं। बैंड कोड, उसकी padding या किसी दूसरे बैंड को पार नहीं कर सकता |
| `qr.plate` | `"opaque"` (डिफ़ॉल्ट), `"background"` या `"none"`। इंजन कोड के नीचे कोड के बैकग्राउंड रंग की एक plate पेंट करता है। जब वह बैकग्राउंड पारदर्शी हो, तो `"opaque"` plate पेंट करता है और `background` fill सफ़ेद हो जाता है, ताकि आर्टवर्क quiet zone से कभी न दिखे। `"background"` उन्हें पारदर्शी रखता है और plate नहीं बनाता; यह तभी मान्य है जब plate के नीचे केवल `background` fill हों, या ऐसी ring हो जिसके छेद में plate आती है। `"none"` कोई plate नहीं बनाता, इसलिए कोड का अपना बैकग्राउंड और margin ही उसकी हल्की जगह हैं, और `qr.padding` 4% से कम हो सकती है। templates इसे इस्तेमाल करते हैं |
| `stroke` | rect, circle, ellipse, polygon या path पर `{ color, width }`: शेप के किनारे पर केंद्रित आउटलाइन, जो उसके fill के बाद बनती है, और आर्टबोर्ड की छोटी भुजा के अधिकतम 10% तक होती है |
| `colors.text` | एक hex रंग, या `frame`, `accent`, `background` और hex रंगों का मिश्रण, जैसे gradient border के लेबल के लिए `{ "mix": ["frame", "accent"], "amount": 0.5 }`। यह डिफ़ॉल्ट है; `textColor` फिर भी प्राथमिकता पाता है |

टेक्स्ट लेबल की पंक्ति plate की padding तक भी जा सकती है, बशर्ते वह कोड से दूर रहे और सबसे बड़े टेक्स्ट साइज़ (`fontScale` 1.5) पर उसके capital अक्षर padding से बाहर रहें। बॉर्डर फ्रेम इसी तरह अपना लेबल कोड के ठीक नीचे रखते हैं।

## आधिकारिक फ्रेम [#official-frames]

बिल्ट-इन फ्रेम के अलावा, QRdx में {facts.officialFrames} आधिकारिक फ्रेम हैं: calls to action, रेस्तरां और कैफ़े, दुकानों और पैकेजिंग, ब्यूटी और वेलनेस, इवेंट और शादियों, होटल और यात्रा, रियल एस्टेट, कार और पार्किंग, स्वास्थ्य और शिक्षा, खेल और फ़िटनेस, बिज़नेस और सोशल, और गैर-लाभकारी संस्थाओं व सामुदायिक समूहों के लिए तैयार डिज़ाइन। इनमें से {facts.seasonalFrames} त्योहारों और मौसमों के लिए हैं, Lunar New Year, Holi, Eid और Diwali से लेकर Hanukkah, Easter, Thanksgiving और Christmas तक। हर फ्रेम एक फ्रेम स्पेक है जिसके लेबल और रंग आप बदल सकते हैं, यह CC0 के तहत जारी है, और हर एक को फ़ोन की दूरी पर स्कैन होने के लिए टेस्ट किया गया है। [कम्युनिटी](/community/frames) में इन्हें @qrdx प्रकाशित करता है।

```tsx title="components/official-frame-code.tsx"
import { getOfficialFrame, QRCode } from "qrdx";

const diwali = getOfficialFrame("diwali-diya"); // undefined for an unknown id

export function OfficialFrameCode() {
  return diwali ? (
    <QRCode
      value="https://example.com/offers"
      size={256}
      frame={{ style: "custom", spec: diwali.spec, text: "Scan for offers" }}
    />
  ) : null;
}
```

`OFFICIAL_FRAMES` पूरी लाइब्रेरी है, और `OFFICIAL_FRAME_INDEX` हर फ्रेम को उसके स्पेक के बिना सूचीबद्ध करता है, ताकि picker लाइब्रेरी दिखा सके और स्पेक सिर्फ़ ज़रूरत पड़ने पर लोड करे। लाइब्रेरी अपने अलग मॉड्यूल के रूप में बनी है, इसलिए जो app इसे कभी import नहीं करता, उसमें यह शामिल नहीं होती। [image API](/docs/developers/image-api#community-items) और [MCP server](/docs/developers/mcp) में आधिकारिक फ्रेम को community item की तरह इस्तेमाल करें, जैसे `item=frame:diwali-diya`।

## क्या यह स्कैन होगा? [#will-it-scan]

`getScanScore` अनुमान लगाता है कि कोई डिज़ाइन कितनी भरोसेमंद तरह से स्कैन होता है। यह browser में चलता है और ज़रूरत पड़ने पर jsQR लोड करता है।

```ts title="lib/scan-score.ts"
import { getScanScore } from "qrdx";

const { score, grade, checks } = await getScanScore({
  value: "https://example.com",
  bodyPattern: "circle",
  cornerEyePattern: "gear",
});
// score: 0 to 100, grade: "great" | "ok" | "risky" | "fails"
// checks: [{ id, passed, message, fix? }]
```

यह क्या जाँचता है:

- **96, 160 और 320 px पर डिकोडिंग।** डिज़ाइन को हर चौड़ाई पर रेंडर किया जाता है, उसमें कैमरे जैसा blur और contrast की कमी जोड़ी जाती है, और थोड़े अलग स्केल पर उसे कई बार डिकोड किया जाता है।
- **Contrast**: कोड के हर रंग (gradient stops, आँखों और dots के रंग सहित) और बैकग्राउंड के बीच, और क्या कोड हल्के बैकग्राउंड पर गहरा है।
- **Logo coverage**: इसकी तुलना इससे की जाती है कि error-correction level कितना हिस्सा recover कर सकता है।
- **Quiet zone**: margin, और frame से जुड़ने वाली खाली जगह।
- **आँखों के आकार का जोखिम**: `circle` आँखें कुछ स्कैनर ऐप्स में छूट सकती हैं, और बंद की जा चुकी `curly` आँखें सख़्त डिकोडर्स में फ़ेल हो जाती हैं।
- **Style pairs** (`style-pair`): ऐसे आकार जो पैकेज के डिकोड टेस्ट में साथ में फ़ेल होते हैं, जैसे square आँखों के बगल में `small-square` modules (देखें `getStylePairRisk`)।

`getImageScanScore(fileOrImage)` किसी मौजूदा इमेज के लिए यही काम करता है: यह डिकोड किया गया कंटेंट लौटाता है, साथ में पिक्सल से मापी गई decode, contrast, polarity, quiet-zone और resolution की जाँचें भी देता है। [स्कैन चेकर](/tools/scan-checker) इसी पर बना है। Node में `scanQRPixels(pixels, expected)` जाँचता है कि raw RGBA पिक्सल जैसे हैं वैसे, और कैमरा मॉडल से गुज़रकर भी, किसी वैल्यू में डिकोड होते हैं।

  यह स्कोर एक ओपन-सोर्स डिकोडर पर बना अनुमान (heuristic) है। फ़ोन के कैमरा ऐप अक्सर ज़्यादा लचीले होते हैं, इसलिए इसे सिर्फ़ मार्गदर्शन मानें और ज़रूरी प्रिंट का टेस्ट स्कैन करें।
</Callout>

## प्रिंट के लिए तैयार एक्सपोर्ट [#print-ready-export]

`downloadPrintPDF` एक सटीक भौतिक साइज़ में vector PDF बनाता है। Modules, आँखें और frames vector paths होते हैं; logo raster इमेज ही रहता है।

```ts title="lib/print.ts"
import { downloadPrintPDF, downloadPrintSVG, getPrintLayout } from "qrdx";

const props = { value: "https://example.com", frame: { style: "banner-bottom" } } as const;

await downloadPrintPDF(props, {
  size: 40, // width of the code itself
  unit: "mm", // or "in"
  bleed: 3, // millimeters on every side
  cropMarks: true,
  colorMode: "cmyk",
});

await downloadPrintSVG(props, { size: 1.5, unit: "in" }); // width="…in" height="…in"

const layout = getPrintLayout(props, { size: 40 });
layout.trimWidth; // finished width in mm, frame included
layout.maxScanDistance; // 400 (mm)
```

- `size` कोड की चौड़ाई है, 5 mm से 2 m तक; frame तैयार साइज़ में जुड़ जाता है।
- `bleed` (20 mm तक) के साथ, बैकग्राउंड या square frame का रंग trim किनारे से बाहर तक फैलता है, ताकि कटाई के बाद सफ़ेद पट्टी न दिखे। Crop marks bleed के बाहर रहते हैं।
- `colorMode: "cmyk"` एक सरल कन्वर्शन इस्तेमाल करता है (`rgbToCmyk`: K, R, G और B में सबसे बड़े मान को 1 से घटाने पर मिलता है, कोई ICC profile नहीं; शुद्ध काला सिर्फ़ K से प्रिंट होता है)। जब सटीक ब्रांड रंग मायने रखते हों, तो अपने प्रिंटर से color-managed कन्वर्शन माँगें।
- Linear और radial gradients PDF में smooth shadings के रूप में प्रिंट होते हैं, और PDF CMYK हो तो CMYK में; print SVG उन्हें रखता है लेकिन RGB ही रहता है।
- PDF में frame टेक्स्ट Helvetica Bold इस्तेमाल करता है, इसलिए Latin-1 से बाहर के अक्षर शायद रेंडर न हों। दूसरी लिपियों के लिए SVG इस्तेमाल करें।
- `getQRAsPrintPDF` और `getQRAsPrintPDFBuffer` फ़ाइल को डाउनलोड करने के बजाय लौटाते हैं, और Node में भी काम करते हैं। `getQRAsEPS` उसी कोड को EPS के रूप में लिखता है; देखें [EPS](/docs/features/downloads#eps)।

कितना बड़ा प्रिंट करें: कोड अपनी चौड़ाई के लगभग दस गुना दूरी से स्कैन हो जाता है, इसलिए चौड़ाई लगभग स्कैन की दूरी को 10 से भाग देने पर मिलती है (20 cm दूरी के लिए 2 cm चौड़ा)। ज़्यादा घने कोड को ज़्यादा बड़ा चाहिए; [प्रिंट साइज़ कैलकुलेटर](/tools/print-size) इसका ध्यान रखता है।
