네 가지 prop으로 코드에 색을 입힙니다. `fgColor`는 데이터 모듈, `bgColor`는 배경, `eyeColor`는 모서리의 눈 세 개, `dotColor`는 각 눈 안쪽의 점에 적용합니다. 각 prop에는 단색이나 그라디언트 객체를 지정할 수 있으며, 눈 색상의 기본값은 `fgColor`입니다. 이 페이지에서는 모든 채우기 종류와 코드를 읽을 수 있게 유지하는 방법을 설명합니다.

Playground나 대시보드에서 디자인하시나요? 도움말의 [스캔되는 색상 고르기](/docs/help/designing/colors-and-contrast)를 참고하세요.

## 단색 [#solid-colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1a56db"
      bgColor="#f9fafb"
      eyeColor="#0d47a1"
      dotColor="#3b82f6"
    />
  );
}
```

단색은 엔진이 해석할 수 있는 모든 CSS 색상입니다. 3, 4, 6, 8자리 16진수, `rgb()`와 `rgba()`, 이름이 있는 색상, `transparent`를 사용할 수 있습니다. `hsl()` 같은 다른 CSS 문법은 SVG에서는 렌더링되지만 대비 검사, PDF, EPS에서는 읽을 수 없으므로 위의 형식을 사용하세요. `{ type: "solid", color: "#1a56db" }`는 문자열과 같은 뜻입니다.

`eyeColors`로 각 눈을 따로 지정할 수 있습니다(`topLeft`, `topRight`, `bottomLeft`, 각각 `outer`와 `inner` 색상 또는 그라디언트). [눈별 색상](/docs/features/patterns#per-eye-colors)을 참고하세요.

### 투명 배경 [#transparent-background]

`bgColor="transparent"`는 배경을 칠하지 않으므로 PNG와 SVG 다운로드는 투명해지고 PDF와 EPS 파일에는 배경 채우기가 없습니다. 코드는 밝고 단순한 바탕 위에 놓으세요. 디코더는 모듈 사이의 밝은 틈이 필요합니다.

## 선형 그라디언트 [#linear-gradients]

```tsx title="components/gradient-code.tsx"
import { QRCode } from "qrdx";

export function GradientCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "linear",
        angle: 45,
        stops: [
          { color: "#4f46e5", offset: 0 },
          { color: "#db2777", offset: 100 },
        ],
      }}
    />
  );
}
```

- `angle`은 도 단위입니다. 0은 왼쪽에서 오른쪽, 90은 위에서 아래, 45는 왼쪽 위 모서리에서 오른쪽 아래로 향합니다.
- `stops`에는 항목이 최소 두 개 필요합니다. `offset`은 0에서 100 사이의 백분율이며, 정지점의 색상에는 알파를 지정할 수 있습니다.
- `bgColor`와 눈을 포함해 모든 색상 prop에 그라디언트를 쓸 수 있습니다. `QRCodeCanvas`는 그라디언트를 그릴 수 없어 첫 번째 정지점을 사용하므로 `QRCode` 또는 `QRCodeSVG`를 사용하세요.

그라디언트는 SVG, PNG, JPG, WebP, PDF 다운로드에 반영됩니다. 인쇄용 PDF와 EPS는 이를 부드러운 셰이딩으로 그립니다.

## 방사형 그라디언트 [#radial-gradients]

```tsx title="components/radial-code.tsx"
import { QRCode } from "qrdx";

export function RadialCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "radial",
        stops: [
          { color: "#0f766e", offset: 0 },
          { color: "#0c4a6e", offset: 100 },
        ],
      }}
    />
  );
}
```

방사형 그라디언트는 코드의 중심에서 바깥쪽으로 퍼집니다. 중심과 반지름은 코드 크기에 맞춰지므로 `stops`만 지정하면 됩니다.

## 각도형 그라디언트 [#angular-gradients]

각도형 그라디언트는 CSS `conic-gradient`처럼 채우는 영역의 중심을 기준으로 시계 방향으로 회전하며 색이 바뀝니다. `angle`은 시작 지점으로, 위쪽에서 시계 방향으로 잰 각도(도)입니다. 오프셋은 한 바퀴를 0에서 100으로 나타냅니다.

```tsx title="components/angular-code.tsx"
import { QRCode } from "qrdx";

export function AngularCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "angular",
        angle: 30,
        stops: [
          { color: "#1d4ed8", offset: 0 },
          { color: "#7c3aed", offset: 50 },
          { color: "#1d4ed8", offset: 100 },
        ],
      }}
    />
  );
}
```

SVG에는 원뿔형 그라디언트가 없으므로, 코드는 색상 단계가 약 두 단계씩 차이 나는 얇은 쐐기 모양을 부채꼴로 그립니다. PDF와 EPS에서도 같은 쐐기를 그립니다.

## 투명 색상 [#see-through-colors]

색상과 그라디언트 정지점에는 `#1d4ed8cc`나 `rgba(29, 78, 216, 0.8)`처럼 알파를 지정할 수 있습니다. SVG에서는 `fill-opacity`와 `stop-opacity`로 기록되고 PDF에서도 유지됩니다. EPS는 투명도를 지원하지 않으므로 투명 색상은 배경과 섞입니다. 스캔 검사는 투명 색상을 배경 위에서 보이는 모습 기준으로 판단합니다.

## 이미지 채우기 [#image-fills]

이미지 채우기는 배경, 모듈, 눈에 그림을 입힙니다. 그림은 코드 전체에 걸쳐 놓이므로, 같은 그림을 공유하는 모듈과 눈에는 하나의 그림이 이어서 보입니다.

```tsx title="components/photo-code.tsx"
import { QRCode } from "qrdx";

export function PhotoCode({ photo }: { photo: string }) {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "image",
        src: photo, // a data:image/jpeg;base64,… URL
        fit: "cover", // or "contain", "tile"
        position: "center",
        scale: 1,
        opacity: 0.45,
        underlay: "#000000",
      }}
    />
  );
}
```

- `src`는 로고와 마찬가지로 그림 자체입니다. QRdx는 이미지 채우기(코드, 테마, REST API 모두)를 최대 1.5 MB의 base64 `data:image` URL(PNG, JPEG, WebP, GIF)로만 저장하며, 링크로 지정한 그림은 거부됩니다. PNG와 JPEG는 모든 내보내기에 포함되고, 서버는 링크를 가져오지 않습니다.
- `underlay`는 그림 아래에 깔리는 단색입니다. `opacity`를 통해 그림 아래 색이 비쳐 보입니다. 검은색 위에서는 모듈용 사진이 어두워지고, 흰색 위에서는 배경용 사진이 밝아집니다.
- 그림의 세부 묘사는 카메라에 노이즈로 읽히므로 스캔 검사는 더 높은 대비를 요구합니다. 모듈이나 눈은 7:1, 그 뒤의 배경은 12:1입니다(`SCAN_IMAGE_CONTRAST_MIN`). 그림은 가장 밝은 10분위와 가장 어두운 10분위로 측정합니다(`getImageTones`). 편집기에서는 **스캔되게 만들기**가 underlay 위에서 검사를 통과하는 불투명도를 찾아 줍니다.
- SVG, PNG, PDF는 이미지 채우기를 지원합니다. EPS는 지원하지 않습니다. [EPS](/docs/features/downloads#eps)를 참고하세요.

이미지 채우기는 로고와 같은 방식으로 이동합니다. 편집기의 디자인, 저장된 코드, 저장된 테마에는 함께 유지됩니다. 하지만 `?style=` 링크, 게시된 커뮤니티 스타일, 코드 가져오기 스니펫, 채팅 컨텍스트에는 들어가지 않으며, 이런 곳에서는 각 이미지 채우기가 underlay 색상으로 대체됩니다. Image API(`GET /v1/qr`)와 MCP 서버는 이미지 채우기를 받지 않습니다. `POST /v1/codes`와 `PATCH /v1/codes/{id}`는 `data:image` URL로만 받으며, 그 외에는 400으로 응답합니다.

## 대비 확인 [#check-the-contrast]

스캐너는 밝은 배경 위의 어두운 모듈을 필요로 합니다. 스캔 점수는 각 그라디언트 정지점을 포함한 모든 색상을 배경과 비교해 검사하며, 같은 헬퍼가 내보내집니다.

```ts title="lib/check-contrast.ts"
import { getContrastLevel, getContrastRatio } from "qrdx";

const ratio = getContrastRatio("#1a56db", "#f9fafb");
// 5.9

getContrastLevel(ratio);
// { level: "AA", warning: false, message: "Good contrast" }
```

스캔 점수는 대비율 4.5 이상(`SCAN_CONTRAST_MIN`)이면 통과시키고, 그보다 낮으면 감점하며, 1.5 미만이면 디자인을 실패 처리합니다. `getContrastLevel`은 7 이상이면 `AAA`, 4.5 이상이면 `AA`, 3 이상이면 경고와 함께 `AA Large`, 그 미만이면 `Fail`을 반환합니다. 어두운 배경 위의 밝은 코드는 대비율은 통과하지만 극성 검사에서 점수를 잃습니다. 대부분의 휴대폰 카메라는 읽을 수 있지만 일부 스캐너 앱은 읽지 못합니다.
