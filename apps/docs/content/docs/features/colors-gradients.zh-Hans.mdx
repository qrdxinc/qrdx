四个属性为二维码着色：`fgColor` 用于数据模块，`bgColor` 用于背景，`eyeColor` 用于三个角上的定位点，`dotColor` 用于每个定位点内部的圆点。每个属性都可以是纯色或渐变对象，定位点颜色默认与 `fgColor` 相同。本页介绍所有填充类型，以及如何保证二维码仍可识读。

想在 Playground 或控制台中设计？请参阅帮助中的[选择可扫描的颜色](/docs/help/designing/colors-and-contrast)。

## 纯色 [#solid-colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1a56db"
      bgColor="#f9fafb"
      eyeColor="#0d47a1"
      dotColor="#3b82f6"
    />
  );
}
```

纯色可以是引擎能解析的任何 CSS 颜色：3 位、4 位、6 位或 8 位的十六进制颜色、`rgb()` 和 `rgba()`、颜色名称，或 `transparent`。其他 CSS 语法（如 `hsl()`）可以在 SVG 中渲染，但对比度检查、PDF 和 EPS 无法读取，因此请使用上述形式。`{ type: "solid", color: "#1a56db" }` 与直接写字符串等效。

`eyeColors` 可以单独设置每个定位点（`topLeft`、`topRight`、`bottomLeft`，每个都有 `outer` 和 `inner` 颜色或渐变）；请参阅[各定位点单独着色](/docs/features/patterns#per-eye-colors)。

### 透明背景 [#transparent-background]

`bgColor="transparent"` 不绘制背景，因此下载的 PNG 和 SVG 是透明的，PDF 和 EPS 文件没有背景填充。请把二维码放在浅色、单一的底面上：解码器需要模块之间的浅色间隙。

## 线性渐变 [#linear-gradients]

```tsx title="components/gradient-code.tsx"
import { QRCode } from "qrdx";

export function GradientCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "linear",
        angle: 45,
        stops: [
          { color: "#4f46e5", offset: 0 },
          { color: "#db2777", offset: 100 },
        ],
      }}
    />
  );
}
```

- `angle` 以度为单位：0 表示从左到右，90 表示从上到下，45 表示从左上角到右下角。
- `stops` 至少需要两项。`offset` 是 0 到 100 的百分比，色标的颜色可以带 alpha。
- 任何颜色属性都可以使用渐变，包括 `bgColor` 和定位点。`QRCodeCanvas` 无法绘制渐变，只会使用第一个色标；请使用 `QRCode` 或 `QRCodeSVG`。

渐变会保留在下载的 SVG、PNG、JPG、WebP 和 PDF 中。打印用 PDF 和 EPS 会将其绘制为平滑的渐变着色。

## 径向渐变 [#radial-gradients]

```tsx title="components/radial-code.tsx"
import { QRCode } from "qrdx";

export function RadialCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "radial",
        stops: [
          { color: "#0f766e", offset: 0 },
          { color: "#0c4a6e", offset: 100 },
        ],
      }}
    />
  );
}
```

径向渐变从二维码中心向外扩展。它的圆心和半径随二维码大小而定，因此只需要 `stops`。

## 角度渐变 [#angular-gradients]

角度渐变围绕所填充区域的中心顺时针扫过，类似 CSS 的 `conic-gradient`。`angle` 是起始位置，以从顶部起顺时针的度数表示。偏移量在一整圈内从 0 到 100。

```tsx title="components/angular-code.tsx"
import { QRCode } from "qrdx";

export function AngularCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "angular",
        angle: 30,
        stops: [
          { color: "#1d4ed8", offset: 0 },
          { color: "#7c3aed", offset: 50 },
          { color: "#1d4ed8", offset: 100 },
        ],
      }}
    />
  );
}
```

SVG 没有圆锥渐变，因此代码会绘制一圈细小的扇形，相邻扇形大约相差两个颜色级别。PDF 和 EPS 绘制相同的扇形。

## 半透明颜色 [#see-through-colors]

颜色和渐变色标都可以带 alpha，例如 `#1d4ed8cc` 或 `rgba(29, 78, 216, 0.8)`。SVG 将其写为 `fill-opacity` 和 `stop-opacity`，PDF 会保留它。EPS 不支持透明度，因此半透明颜色会与背景混合。扫描检查会按半透明颜色在背景上的实际观感来判断。

## 图片填充 [#image-fills]

图片填充会把一张图片铺在背景、模块或定位点上。图片覆盖整个二维码，因此共用同一张图片的模块和定位点会呈现同一幅画面。

```tsx title="components/photo-code.tsx"
import { QRCode } from "qrdx";

export function PhotoCode({ photo }: { photo: string }) {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "image",
        src: photo, // a data:image/jpeg;base64,… URL
        fit: "cover", // or "contain", "tile"
        position: "center",
        scale: 1,
        opacity: 0.45,
        underlay: "#000000",
      }}
    />
  );
}
```

- `src` 就是图片本身，与徽标相同。QRdx 只会保存以 base64 `data:image` URL（PNG、JPEG、WebP 或 GIF）形式提供、大小不超过 1.5 MB 的图片填充（包括二维码、主题和 REST API 中的）；来自链接的图片会被拒绝。PNG 和 JPEG 会嵌入所有导出格式，服务器从不获取链接。
- `underlay` 是图片下方的纯色。`opacity` 让它透出来：在黑色之上，它会把用于模块的照片压暗；在白色之上，它会把用于背景的照片提亮。
- 图片的细节在相机看来就是噪点，因此扫描检查要求更高的对比度：模块或定位点为 7:1，其后的背景为 12:1（`SCAN_IMAGE_CONTRAST_MIN`）。它按图片最亮和最暗的十分之一来衡量图片（`getImageTones`）。在编辑器中，**Make it scannable** 会找出在 underlay 之上能通过检查的透明度。
- SVG、PNG 和 PDF 支持图片填充，EPS 不支持；请参阅 [EPS](/docs/features/downloads#eps)。

图片填充的流转方式与徽标相同。它们会随设计保留在编辑器、已保存的二维码和已保存的主题中。它们不会进入 `?style=` 链接、已发布的社区样式、Get code 代码片段或聊天上下文：在这些地方，每个图片填充都会退回为其 underlay 颜色。Image API（`GET /v1/qr`）和 MCP 服务器不接受图片填充。`POST /v1/codes` 和 `PATCH /v1/codes/{id}` 只接受 `data:image` URL 形式的图片填充，其他形式一律返回 400。

## 检查对比度 [#check-the-contrast]

扫描器需要深色模块搭配浅色背景。扫描评分会将每种颜色（包括每个渐变色标）与背景进行比对；相同的辅助函数也已导出：

```ts title="lib/check-contrast.ts"
import { getContrastLevel, getContrastRatio } from "qrdx";

const ratio = getContrastRatio("#1a56db", "#f9fafb");
// 5.9

getContrastLevel(ratio);
// { level: "AA", warning: false, message: "Good contrast" }
```

扫描评分在比值达到 4.5 或更高时通过（`SCAN_CONTRAST_MIN`），低于该值会扣分，低于 1.5 则判定设计不合格。`getContrastLevel` 在 7 及以上返回 `AAA`，4.5 及以上返回 `AA`，3 及以上返回 `AA Large` 并附带警告，低于 3 返回 `Fail`。深色背景上的浅色二维码能通过对比度检查，但会在极性检查中失分：大多数手机相机可以读取，部分扫描应用则不能。
