Quatro props colorem um código: `fgColor` para os módulos de dados, `bgColor` para o fundo, `eyeColor` para os três olhos dos cantos e `dotColor` para o ponto dentro de cada olho. Cada uma aceita uma cor sólida ou um objeto de gradiente, e as cores dos olhos usam `fgColor` por padrão. Esta página cobre todos os tipos de preenchimento e como manter o código legível.

Prefere desenhar no Playground ou no painel? Veja [Escolha cores que funcionam na leitura](/docs/help/designing/colors-and-contrast) na Ajuda.

## Cores sólidas [#solid-colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1a56db"
      bgColor="#f9fafb"
      eyeColor="#0d47a1"
      dotColor="#3b82f6"
    />
  );
}
```

Uma cor sólida é qualquer cor CSS que o motor consegue interpretar: hex com 3, 4, 6 ou 8 dígitos, `rgb()` e `rgba()`, uma cor nomeada ou `transparent`. Outras sintaxes CSS, como `hsl()`, aparecem no SVG, mas a verificação de contraste, o PDF e o EPS não conseguem lê-las, então use as formas acima. `{ type: "solid", color: "#1a56db" }` equivale à string.

`eyeColors` define cada olho separadamente (`topLeft`, `topRight`, `bottomLeft`, cada um com uma cor ou gradiente `outer` e `inner`); veja [Cores por olho](/docs/features/patterns#per-eye-colors).

### Fundo transparente [#transparent-background]

`bgColor="transparent"` não pinta fundo nenhum, então os downloads em PNG e SVG ficam transparentes e os arquivos PDF e EPS não têm preenchimento de fundo. Coloque o código sobre uma superfície clara e lisa: os decodificadores precisam dos espaços claros entre os módulos.

## Gradientes lineares [#linear-gradients]

```tsx title="components/gradient-code.tsx"
import { QRCode } from "qrdx";

export function GradientCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "linear",
        angle: 45,
        stops: [
          { color: "#4f46e5", offset: 0 },
          { color: "#db2777", offset: 100 },
        ],
      }}
    />
  );
}
```

- `angle` é em graus: 0 vai da esquerda para a direita, 90 de cima para baixo, 45 do canto superior esquerdo até o canto inferior direito.
- `stops` precisa de pelo menos duas entradas. `offset` é uma porcentagem de 0 a 100, e a cor de um stop pode ter alfa.
- Qualquer prop de cor aceita um gradiente, inclusive `bgColor` e os olhos. `QRCodeCanvas` não consegue desenhar gradientes e usa o primeiro stop; use `QRCode` ou `QRCodeSVG`.

Os gradientes são mantidos nos downloads em SVG, PNG, JPG, WebP e PDF. O PDF de impressão e o EPS os desenham como degradês suaves.

## Gradientes radiais [#radial-gradients]

```tsx title="components/radial-code.tsx"
import { QRCode } from "qrdx";

export function RadialCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "radial",
        stops: [
          { color: "#0f766e", offset: 0 },
          { color: "#0c4a6e", offset: 100 },
        ],
      }}
    />
  );
}
```

Um gradiente radial vai do centro do código para fora. O centro e o raio acompanham o tamanho do código, então ele aceita apenas `stops`.

## Gradientes angulares [#angular-gradients]

Um gradiente angular gira no sentido horário em torno do centro da área que preenche, como o `conic-gradient` do CSS. `angle` é onde a rotação começa, em graus no sentido horário a partir do topo. Os offsets vão de 0 a 100 ao longo da volta.

```tsx title="components/angular-code.tsx"
import { QRCode } from "qrdx";

export function AngularCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "angular",
        angle: 30,
        stops: [
          { color: "#1d4ed8", offset: 0 },
          { color: "#7c3aed", offset: 50 },
          { color: "#1d4ed8", offset: 100 },
        ],
      }}
    />
  );
}
```

O SVG não tem gradiente cônico, então o código desenha um leque de fatias finas, com cerca de dois níveis de cor de diferença entre elas. PDF e EPS desenham as mesmas fatias.

## Cores translúcidas [#see-through-colors]

Cores e stops de gradiente podem ter alfa, como `#1d4ed8cc` ou `rgba(29, 78, 216, 0.8)`. O SVG grava isso como `fill-opacity` e `stop-opacity`, e o PDF mantém. O EPS não tem transparência, então uma cor translúcida é misturada com o fundo. A verificação de leitura avalia uma cor translúcida pela aparência dela sobre o fundo.

## Preenchimentos com imagem [#image-fills]

Um preenchimento com imagem pinta uma figura no fundo, nos módulos ou nos olhos. A figura é estendida sobre o código inteiro, então módulos e olhos que compartilham uma imagem mostram uma única figura.

```tsx title="components/photo-code.tsx"
import { QRCode } from "qrdx";

export function PhotoCode({ photo }: { photo: string }) {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "image",
        src: photo, // a data:image/jpeg;base64,… URL
        fit: "cover", // or "contain", "tile"
        position: "center",
        scale: 1,
        opacity: 0.45,
        underlay: "#000000",
      }}
    />
  );
}
```

- `src` é a própria imagem, como em um logo. O QRdx salva um preenchimento com imagem (em códigos, temas e na REST API) apenas como uma URL `data:image` em base64 (PNG, JPEG, WebP ou GIF) de no máximo 1,5 MB; uma imagem vinda de um link é recusada. PNG e JPEG são incorporados em todas as exportações, e os servidores nunca buscam um link.
- `underlay` é uma cor sólida sob a imagem. `opacity` deixa essa cor aparecer: sobre preto, escurece uma foto nos módulos, e sobre branco, clareia uma foto no fundo.
- Os detalhes de uma imagem parecem ruído para a câmera, então a verificação de leitura exige mais contraste: 7:1 nos módulos ou nos olhos, 12:1 atrás deles (`SCAN_IMAGE_CONTRAST_MIN`). Ela mede uma imagem pelos décimos mais claro e mais escuro (`getImageTones`). No editor, **Make it scannable** encontra a opacidade sobre o underlay que passa na verificação.
- SVG, PNG e PDF mantêm os preenchimentos com imagem. O EPS não; veja [EPS](/docs/features/downloads#eps).

Preenchimentos com imagem viajam como os logos. Ficam com o design no editor, nos códigos salvos e nos temas salvos. Não entram em links `?style=`, em estilos da comunidade publicados, em snippets de Get code nem no contexto do chat: lá, cada preenchimento com imagem cede lugar à cor do seu underlay. A Image API (`GET /v1/qr`) e o servidor MCP não os aceitam. `POST /v1/codes` e `PATCH /v1/codes/{id}` aceitam um apenas como URL `data:image` e respondem 400 para qualquer outra coisa.

## Verifique o contraste [#check-the-contrast]

Os leitores precisam de módulos escuros sobre um fundo claro. A pontuação de leitura confere cada cor, inclusive cada stop de gradiente, contra o fundo; os mesmos helpers são exportados:

```ts title="lib/check-contrast.ts"
import { getContrastLevel, getContrastRatio } from "qrdx";

const ratio = getContrastRatio("#1a56db", "#f9fafb");
// 5.9

getContrastLevel(ratio);
// { level: "AA", warning: false, message: "Good contrast" }
```

A pontuação de leitura aprova uma razão de 4,5 ou mais (`SCAN_CONTRAST_MIN`), tira pontos abaixo disso e reprova o design abaixo de 1,5. `getContrastLevel` retorna `AAA` a partir de 7, `AA` a partir de 4,5, `AA Large` a partir de 3 com um aviso e `Fail` abaixo disso. Um código claro sobre fundo escuro passa na razão, mas perde pontos na verificação de polaridade: a maioria das câmeras de celular lê, alguns apps leitores não.
