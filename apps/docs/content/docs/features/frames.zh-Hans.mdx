`frame` 属性会在二维码周围绘制“Scan me”边框,`getScanScore` 会告诉你某个设计能否被扫描,印刷函数则按物理尺寸写出带出血和裁切标记的矢量文件。本页按这个顺序依次介绍这三部分。

如果你是在 Playground 或控制台中设计?请参阅帮助中的[添加边框和行动号召](/docs/help/designing/frames)、[用扫描评分检查设计](/docs/help/designing/scan-score)和[下载并打印二维码](/docs/help/getting-started/download-and-print)。

## 行动号召边框 [#call-to-action-frames]

QRdx 绘制的每个边框都是一份边框规范:一段描述形状、标签和颜色的简短 JSON。同一个引擎绘制所有规范,因此边框在 SVG、PNG、PDF 和 EPS 中看起来完全一致。共有 {facts.frames} 种边框:{facts.frameStyles} 种内置边框和 {facts.officialFrames} 种[官方边框](#official-frames)。你也可以自己编写,或从[社区](/community/frames)中选用。

`frame` 适用于 `QRCode`、`QRCodeSVG`、`QRCodeCanvas`、`getQRAsSVG`、`getQRData` 以及所有下载辅助函数。

```tsx title="components/menu-frame-code.tsx"
import { QRCode } from "qrdx";

export function MenuFrameCode() {
  return (
    <QRCode
      value="https://example.com/menu"
      size={256}
      frame={{
        style: "banner-bottom",
        text: "Scan for the menu",
        color: "#1e3a8a",
      }}
    />
  );
}
```

边框添加在二维码外围:输出尺寸会变大,模块和静区永远不会被遮挡,因此可扫描性不受影响。二维码与边框之间有一道与二维码背景色相同的浅色间隙。

### 内置边框 [#built-in-frames]

内置边框由其 `style` 命名。各选项用于填充其规范中的标签和颜色:

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `style` | 无 | 下列 {facts.frameStyles} 种内置样式之一,或 `none`,或配合 `spec` 使用的 `custom` |
| `text` | `"Scan me"` | 最多 24 个字符。传入 `""` 可隐藏标签 |
| `color` | 规范自带的颜色:除 `gradient-border`(起始色为紫罗兰色)外,所有内置边框均为黑色 | 边框颜色 |
| `textColor` | 边框上为白色,浅色区域上为 `color` | 标签颜色 |
| `secondaryText` | 无 | 第二个标签,最多 24 个字符:`banner-top-bottom` 的底部横条、`circle` 的下弧、`menu-card` 的页脚 |
| `secondaryColor` | 规范的强调色,粉色 | `gradient-border` 的结束颜色 |
| `fontScale` | `1` | 标签大小,范围 0.5 到 1.5;标签仍会自动缩小以适应空间 |

按 `style` 划分的内置边框:

- 横幅与边框:`banner-bottom`、`banner-top`、`banner-top-bottom`、`border`、`rounded-border`、`gradient-border`、`focus`(角括号)
- 气泡:`speech-bubble`、`speech-bubble-top`、`chat-bubble`
- 徽章:`circle`(文字沿圆环排列)、`badge`(丝带)、`sticker`(带阴影的模切贴纸)
- 物件:`polaroid`、`phone`、`ticket`、`tag`(带孔的吊牌)、`envelope`、`menu-card`

这些名称各自对应引擎中的一份规范,并且会长期有效。使用它们的已保存设计、Image API 链接、CLI 标志和代码都会继续绘制相同的边框。没有标签时会去掉标签所在行的边框(例如各种边框线样式),现在仍然如此。你可以在[形状、码眼与边框](/docs/styles#frames)中查看全部边框,它们在浏览器中解码渲染。

`BUILT_IN_FRAMES` 列出它们的名称和规范(`BUILT_IN_FRAME_SPECS` 按样式给出规范)。`frameSpecOf` 返回任一边框所绘制的规范,`getFrameColors` 返回它所用的颜色:

```ts title="lib/frames.ts"
import { BUILT_IN_FRAMES, frameSpecOf, getFrameColors, getFrameDimensions } from "qrdx";

BUILT_IN_FRAMES.map((frame) => frame.name); // ["Banner", "Top banner", "Two banners", …]

// A built-in style's spec, or a custom frame's own
const ticket = frameSpecOf({ style: "ticket" });

// The frame's options, else its spec's defaults
getFrameColors({ style: "border", color: "#1e3a8a" });
// { frame: "#1e3a8a", text: "#1e3a8a", accent: "#1e3a8a" }

// The output size: a 400 px code in a bottom banner
getFrameDimensions(400, { style: "banner-bottom" }); // { width: 496, height: 568 }
```

如果想修改的不只是标签和颜色,可以从内置规范出发创建自定义边框:`{ style: "custom", spec: frameSpecOf({ style: "ticket" }) }` 会绘制同样的票券,并且你可以编辑它的形状。

每个边框都只由普通形状和文字组成,颜色均不透明,因此 SVG、PNG、PDF 和 EPS 的导出结果一致。渐变边框由细密的纯色色阶绘制,圆形边框的弧形文字在所有格式中都是旋转的文本。标签使用系统字体栈,因此不会下载任何字体。

`FRAME_STYLES`、`frameSchema`(zod)以及 `QRFrame` 和 `FrameStyle` 类型也从 `qrdx/types` 导出,可用于服务端校验。CLI 通过 `--frame`、`--frame-text`、`--frame-color` 和 `--frame-text-color` 绘制同样的边框;请参阅 [CLI](/docs/developers/cli)。

### 边框规范 [#frame-specs]

边框规范是 JSON,包含 `kind: "qrdx.frame"`、`version: 1`、`artboard` 尺寸、放置二维码的 `qr` 区域、默认 `colors`、绘制在二维码后方的 `shapes`,以及 `labels`。形状包括矩形(可带孔)、圆和圆环、椭圆、多边形、路径、线条和内置图标。它们可以用主题标记(`frame`、`text`、`accent`、`background`)、十六进制颜色、两者的混合色或渐变来填充。规范不包含标记、链接或图片。对于不是你自己编写的规范,请在存储前用 `qrdx/types` 中的 `frameSpecSchema` 或 `getFrameSpecIssues` 检查。引擎在绘制前还会再检查一次。

```tsx title="components/custom-frame-code.tsx"
import { QRCode } from "qrdx";
import spec from "./my-frame.json";

export function CustomFrameCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      frame={{ style: "custom", spec, text: "Scan me", color: "#1e3a8a" }}
    />
  );
}
```

内置边框和模板使用的可选字段(不含这些字段的规范绘制结果与以前相同):

| 字段 | 作用 |
| --- | --- |
| `labels[].collapse` | `{ y, height }`。当标签没有文本时,从 `y` 到 `y + height` 的区带会被裁掉:其下方的各行上移,图形变短。完全位于区带内的形状会被省略,跨越区带的形状会变短。区带不能跨越二维码、其内边距或另一个区带 |
| `qr.plate` | `"opaque"`(默认)、`"background"` 或 `"none"`。引擎会在二维码下方用二维码的背景色绘制一块底板。当该背景为透明时,`"opaque"` 会绘制底板,`background` 填充为白色,这样图形就不会从静区透出。`"background"` 保持它们透明并省略底板;仅当底板下方只有 `background` 填充,或只有孔中容纳底板的圆环时才允许使用。`"none"` 完全不绘制底板,此时二维码自身的背景和边距就是它唯一的浅色空间,`qr.padding` 可以小于 4%。模板使用此值 |
| `stroke` | 用于矩形、圆、椭圆、多边形或路径的 `{ color, width }`:以形状边缘为中心的轮廓线,在填充之后绘制,宽度最大为画板较短边的 10% |
| `colors.text` | 十六进制颜色,或 `frame`、`accent`、`background` 与十六进制颜色的混合,例如用于渐变边框标签的 `{ "mix": ["frame", "accent"], "amount": 0.5 }`。它是默认值;`textColor` 仍然优先 |

文本标签所在的行也可以延伸到底板的内边距中,前提是它不碰到二维码,并且在最大文字尺寸(`fontScale` 1.5)下其大写字母仍不进入内边距。边框线类边框就是这样把标签直接放在二维码下方的。

## 官方边框 [#official-frames]

除内置边框外,QRdx 还有 {facts.officialFrames} 种官方边框:现成的设计,适用于行动号召、餐厅和咖啡馆、商店和包装、美容与健康、活动和婚礼、酒店与旅行、房地产、汽车与停车、医疗与教育、运动与健身、商务与社交,以及公益和社区团体。其中 {facts.seasonalFrames} 种用于节日和季节,从农历新年、Holi、开斋节和排灯节,到光明节、复活节、感恩节和圣诞节。每一种都是带有可修改标签和颜色的边框规范,以 CC0 发布,并且都经过测试,能在手机扫描距离下被扫描。在[社区](/community/frames)中,它们由 @qrdx 发布。

```tsx title="components/official-frame-code.tsx"
import { getOfficialFrame, QRCode } from "qrdx";

const diwali = getOfficialFrame("diwali-diya"); // undefined for an unknown id

export function OfficialFrameCode() {
  return diwali ? (
    <QRCode
      value="https://example.com/offers"
      size={256}
      frame={{ style: "custom", spec: diwali.spec, text: "Scan for offers" }}
    />
  ) : null;
}
```

`OFFICIAL_FRAMES` 是完整的边框库,`OFFICIAL_FRAME_INDEX` 列出每个边框但不含其规范,因此选择器可以展示整个库,并只在需要时加载规范。该库作为独立模块构建,所以从不导入它的应用不会包含它。在 [Image API](/docs/developers/image-api#community-items) 和 [MCP 服务器](/docs/developers/mcp)中,可以把官方边框作为社区项使用,例如 `item=frame:diwali-diya`。

## 能否扫描？ [#will-it-scan]

`getScanScore` 用于估算设计的扫描可靠性。它在浏览器中运行，并按需加载 jsQR。

```ts title="lib/scan-score.ts"
import { getScanScore } from "qrdx";

const { score, grade, checks } = await getScanScore({
  value: "https://example.com",
  bodyPattern: "circle",
  cornerEyePattern: "gear",
});
// score: 0 to 100, grade: "great" | "ok" | "risky" | "fails"
// checks: [{ id, passed, message, fix? }]
```

检查内容：

- **在 96、160 和 320 px 下解码。** 设计会按每种宽度渲染，加入类似摄像头的模糊和对比度损失，并以略有差异的缩放比例解码数次。
- **对比度**：每种二维码颜色（包括渐变色标、定位点颜色和圆点颜色）与背景之间的对比度，以及二维码是否为浅底深色。
- **徽标覆盖率**：与当前纠错级别所能恢复的范围相比较。
- **静区**：边距，加上边框带来的间隙。
- **定位点形状风险**：部分扫描应用可能无法识别 `circle` 定位点，已弃用的 `curly` 定位点则无法通过严格的解码器。
- **样式组合**（`style-pair`）：在该包的解码测试中会同时失败的形状组合，例如 `small-square` 模块搭配方形定位点（参见 `getStylePairRisk`）。

`getImageScanScore(fileOrImage)` 对现有图片执行同样的检查：它会返回解码出的内容，以及根据像素测得的解码、对比度、极性、静区和分辨率检查结果。[扫描检测工具](/tools/scan-checker)就是基于它构建的。在 Node 中，`scanQRPixels(pixels, expected)` 用于检查原始 RGBA 像素能否解码为指定的值，既按原样检查，也通过摄像头模型检查。

<Callout type="info">
  该评分是基于一个开源解码器得出的启发式结果。手机相机应用通常更宽容，因此请把它当作参考，并对重要的印刷品进行实际扫描测试。
</Callout>

## 可直接印刷的导出 [#print-ready-export]

`downloadPrintPDF` 会按精确的物理尺寸输出矢量 PDF。模块、定位点和边框都是矢量路径；徽标仍是位图。

```ts title="lib/print.ts"
import { downloadPrintPDF, downloadPrintSVG, getPrintLayout } from "qrdx";

const props = { value: "https://example.com", frame: { style: "banner-bottom" } } as const;

await downloadPrintPDF(props, {
  size: 40, // width of the code itself
  unit: "mm", // or "in"
  bleed: 3, // millimeters on every side
  cropMarks: true,
  colorMode: "cmyk",
});

await downloadPrintSVG(props, { size: 1.5, unit: "in" }); // width="…in" height="…in"

const layout = getPrintLayout(props, { size: 40 });
layout.trimWidth; // finished width in mm, frame included
layout.maxScanDistance; // 400 (mm)
```

- `size` 是二维码的宽度，范围从 5 mm 到 2 m；边框会增加成品的尺寸。
- 设置 `bleed`（最大 20 mm）后，背景或方形边框的颜色会延伸到裁切线之外，这样裁切后不会留下白边。裁切标记位于出血区之外。
- `colorMode: "cmyk"` 使用简单转换（`rgbToCmyk`：K 等于 1 减去 R、G、B 中的最大值，不使用 ICC 配置文件；纯黑只用 K 通道印刷）。如果需要精确还原品牌色，请向印刷商索取经过色彩管理的转换。
- 线性和径向渐变在 PDF 中以平滑渐变底纹印刷，PDF 为 CMYK 时渐变也是 CMYK；印刷用 SVG 会保留渐变，但仍为 RGB。
- PDF 中的边框文字使用 Helvetica Bold，因此 Latin-1 之外的字符可能无法显示。其他文字请使用 SVG。
- `getQRAsPrintPDF` 和 `getQRAsPrintPDFBuffer` 返回文件而不是下载，在 Node 中也可使用。`getQRAsEPS` 会把同一个二维码输出为 EPS；参见 [EPS](/docs/features/downloads#eps)。

印多大：二维码大约可在其宽度十倍的距离处扫描，因此宽度约为扫描距离除以 10（20 cm 的距离对应 2 cm 宽）。密度更高的二维码需要更大的尺寸；[印刷尺寸计算器](/tools/print-size)已考虑这一点。
