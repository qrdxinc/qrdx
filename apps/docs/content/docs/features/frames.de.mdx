Die Prop `frame` zeichnet einen „Scan me“-Rahmen um einen Code, `getScanScore` sagt dir, ob sich ein Design scannen lässt, und die Druckfunktionen schreiben Vektordateien in physischer Größe mit Beschnitt und Schnittmarken. Diese Seite behandelt die drei Themen in dieser Reihenfolge.

Du gestaltest lieber im Playground oder im Dashboard? Dann lies in der Hilfe [Rahmen und Call-to-Action hinzufügen](/docs/help/designing/frames), [Ein Design mit dem Scan-Score prüfen](/docs/help/designing/scan-score) und [Einen QR-Code herunterladen und drucken](/docs/help/getting-started/download-and-print).

## Call-to-Action-Rahmen [#call-to-action-frames]

Jeder Rahmen, den QRdx zeichnet, ist eine Frame-Spezifikation: eine kleine JSON-Beschreibung aus Formen, Beschriftungen und Farben. Eine Engine zeichnet jede Spezifikation, deshalb sieht ein Rahmen in SVG, PNG, PDF und EPS gleich aus. Es gibt {facts.frames} Rahmen: {facts.frameStyles} integrierte Rahmen und {facts.officialFrames} [offizielle Rahmen](#official-frames). Du kannst auch einen eigenen schreiben oder einen aus der [Community](/community/frames) wählen.

`frame` funktioniert mit `QRCode`, `QRCodeSVG`, `QRCodeCanvas`, `getQRAsSVG`, `getQRData` und allen Download-Helfern.

```tsx title="components/menu-frame-code.tsx"
import { QRCode } from "qrdx";

export function MenuFrameCode() {
  return (
    <QRCode
      value="https://example.com/menu"
      size={256}
      frame={{
        style: "banner-bottom",
        text: "Scan for the menu",
        color: "#1e3a8a",
      }}
    />
  );
}
```

Der Rahmen wird um den Code herum hinzugefügt: Die Ausgabe wird größer, und die Module und die Ruhezone werden nie verdeckt, daher bleibt die Scanbarkeit unverändert. Eine helle Lücke in der Hintergrundfarbe des Codes trennt den Code vom Rahmen.

### Integrierte Rahmen [#built-in-frames]

Ein integrierter Rahmen wird über seinen `style` benannt. Die Optionen füllen die Beschriftungen und Farben seiner Spezifikation:

| Option | Standard | Hinweise |
| --- | --- | --- |
| `style` | keiner | Einer der {facts.frameStyles} integrierten Stile unten, `none` oder `custom` mit einer `spec` |
| `text` | `"Scan me"` | Bis zu 24 Zeichen. Mit `""` blendest du die Beschriftung aus |
| `color` | die eigene Farbe der Spezifikation: Schwarz bei jedem integrierten Rahmen außer `gradient-border`, der mit Violett beginnt | Rahmenfarbe |
| `textColor` | Weiß auf dem Rahmen, `color` auf hellen Flächen | Beschriftungsfarbe |
| `secondaryText` | keiner | Zweite Beschriftung, bis zu 24 Zeichen: das untere Band von `banner-top-bottom`, der untere Bogen von `circle`, die Fußzeile von `menu-card` |
| `secondaryColor` | der Akzent der Spezifikation, Pink | Endfarbe von `gradient-border` |
| `fontScale` | `1` | Beschriftungsgröße von 0.5 bis 1.5; Beschriftungen schrumpfen weiterhin, damit sie passen |

Die integrierten Rahmen nach `style`:

- Banner und Ränder: `banner-bottom`, `banner-top`, `banner-top-bottom`, `border`, `rounded-border`, `gradient-border`, `focus` (Eckklammern)
- Sprechblasen: `speech-bubble`, `speech-bubble-top`, `chat-bubble`
- Abzeichen: `circle` (Text rund um einen Ring), `badge` (Band), `sticker` (Die-Cut mit Schatten)
- Objekte: `polaroid`, `phone`, `ticket`, `tag` (Anhänger mit Loch), `envelope`, `menu-card`

Jeder dieser Namen steht für eine Spezifikation in der Engine, und die Namen bleiben dauerhaft gültig. Gespeicherte Designs, Image-API-Links, CLI-Flags und Code, die sie verwenden, zeichnen weiterhin denselben Rahmen. Rahmen, die die Zeile ihrer Beschriftung weglassen, wenn es keine Beschriftung gibt, etwa die Ränder, tun das weiterhin. Alle siehst du, direkt in deinem Browser dekodiert, unter [Formen, Augen und Rahmen](/docs/styles#frames).

`BUILT_IN_FRAMES` listet sie mit Namen und Spezifikationen auf (`BUILT_IN_FRAME_SPECS` enthält die Spezifikationen nach Stil). `frameSpecOf` gibt die Spezifikation zurück, die ein Rahmen zeichnet, und `getFrameColors` die Farben, mit denen er malt:

```ts title="lib/frames.ts"
import { BUILT_IN_FRAMES, frameSpecOf, getFrameColors, getFrameDimensions } from "qrdx";

BUILT_IN_FRAMES.map((frame) => frame.name); // ["Banner", "Top banner", "Two banners", …]

// A built-in style's spec, or a custom frame's own
const ticket = frameSpecOf({ style: "ticket" });

// The frame's options, else its spec's defaults
getFrameColors({ style: "border", color: "#1e3a8a" });
// { frame: "#1e3a8a", text: "#1e3a8a", accent: "#1e3a8a" }

// The output size: a 400 px code in a bottom banner
getFrameDimensions(400, { style: "banner-bottom" }); // { width: 496, height: 568 }
```

Wenn du mehr als die Beschriftungen und Farben ändern willst, starte einen eigenen Rahmen mit einer integrierten Spezifikation: `{ style: "custom", spec: frameSpecOf({ style: "ticket" }) }` zeichnet dasselbe Ticket, und du kannst seine Formen bearbeiten.

Jeder Rahmen besteht aus einfachen Formen und Text mit deckenden Farben, deshalb stimmen SVG-, PNG-, PDF- und EPS-Exporte überein. Der Verlaufsrand wird in feinen einfarbigen Stufen gezeichnet, und die gebogenen Buchstaben des Rahmens `circle` sind in jedem Format gedrehter Text. Die Beschriftung nutzt den System-Font-Stack, es wird also nichts heruntergeladen.

`FRAME_STYLES`, `frameSchema` (zod) und die Typen `QRFrame` und `FrameStyle` werden ebenfalls aus `qrdx/types` exportiert, für die serverseitige Validierung. Die CLI zeichnet dieselben Rahmen mit `--frame`, `--frame-text`, `--frame-color` und `--frame-text-color`; siehe [CLI](/docs/developers/cli).

### Frame-Spezifikationen [#frame-specs]

Eine Frame-Spezifikation ist JSON mit `kind: "qrdx.frame"`, `version: 1`, einer `artboard`-Größe, einer `qr`-Box, in die der Code kommt, Standard-`colors`, den `shapes`, die hinter dem Code gemalt werden, und den `labels`. Formen sind Rechtecke (optional mit Loch), Kreise und Ringe, Ellipsen, Polygone, Pfade, Linien und integrierte Icons. Sie werden mit einem Theme-Token (`frame`, `text`, `accent`, `background`), einer Hex-Farbe, einer Mischung aus zwei Farben oder einem Verlauf gefüllt. Eine Spezifikation enthält kein Markup, keine Links und keine Bilder. Prüfe eine Spezifikation, die du nicht selbst geschrieben hast, mit `frameSpecSchema` oder `getFrameSpecIssues` aus `qrdx/types`, bevor du sie speicherst. Die Engine prüft sie vor dem Zeichnen noch einmal.

```tsx title="components/custom-frame-code.tsx"
import { QRCode } from "qrdx";
import spec from "./my-frame.json";

export function CustomFrameCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      frame={{ style: "custom", spec, text: "Scan me", color: "#1e3a8a" }}
    />
  );
}
```

Optionale Felder, die die integrierten Rahmen und Vorlagen nutzen (Spezifikationen ohne sie werden wie bisher gezeichnet):

| Feld | Was es bewirkt |
| --- | --- |
| `labels[].collapse` | `{ y, height }`. Zeigt die Beschriftung keinen Text, wird das Band von `y` bis `y + height` herausgeschnitten: Zeilen darunter rücken nach oben, und das Artwork wird kürzer. Formen, die ganz im Band liegen, entfallen, und Formen, die es kreuzen, werden kürzer. Ein Band darf weder den Code noch dessen Innenabstand noch ein anderes Band kreuzen |
| `qr.plate` | `"opaque"` (Standard), `"background"` oder `"none"`. Die Engine malt unter dem Code eine Platte in der Hintergrundfarbe des Codes. Ist dieser Hintergrund durchsichtig, malt `"opaque"` die Platte und `background`-Füllungen werden weiß, sodass Artwork nie durch die Ruhezone scheint. `"background"` lässt sie durchsichtig und lässt die Platte weg; das ist nur erlaubt, wenn unter der Platte nichts als `background`-Füllungen oder ein Ring liegt, dessen Loch die Platte enthält. `"none"` malt gar keine Platte, sodass der eigene Hintergrund und Rand des Codes der einzige helle Raum sind, und `qr.padding` darf unter 4 % liegen. Die Vorlagen nutzen das |
| `stroke` | `{ color, width }` an einem Rechteck, Kreis, einer Ellipse, einem Polygon oder Pfad: eine Kontur, zentriert auf dem Rand der Form, nach der Füllung gezeichnet, höchstens 10 % der kürzeren Seite der Zeichenfläche |
| `colors.text` | Eine Hex-Farbe oder eine Mischung aus `frame`, `accent`, `background` und Hex-Farben, etwa `{ "mix": ["frame", "accent"], "amount": 0.5 }` für die Beschriftung des Verlaufsrands. Das ist der Standard; `textColor` hat weiterhin Vorrang |

Die Zeile einer Textbeschriftung darf auch in den Innenabstand der Platte hineinreichen, solange sie den Code nicht berührt und ihre Großbuchstaben bei der größten Textgröße (`fontScale` 1.5) außerhalb des Innenabstands bleiben. Die Randrahmen setzen ihre Beschriftung auf diese Weise direkt unter den Code.

## Offizielle Rahmen [#official-frames]

Zusätzlich zu den integrierten Rahmen hat QRdx {facts.officialFrames} offizielle Rahmen: fertige Designs für Call-to-Actions, Restaurants und Cafés, Geschäfte und Verpackungen, Beauty und Wellness, Events und Hochzeiten, Hotels und Reisen, Immobilien, Autos und Parken, Gesundheit und Bildung, Sport und Fitness, Business und Social sowie gemeinnützige Organisationen und Community-Gruppen. {facts.seasonalFrames} davon sind für Feiertage und Jahreszeiten, vom Mondneujahr, Holi, Eid und Diwali bis zu Chanukka, Ostern, Thanksgiving und Weihnachten. Jeder ist eine Frame-Spezifikation mit Beschriftungen und Farben, die du ändern kannst, unter CC0 veröffentlicht, und jeder wurde darauf getestet, dass er auf Handy-Entfernung scannt. In der [Community](/community/frames) werden sie von @qrdx veröffentlicht.

```tsx title="components/official-frame-code.tsx"
import { getOfficialFrame, QRCode } from "qrdx";

const diwali = getOfficialFrame("diwali-diya"); // undefined for an unknown id

export function OfficialFrameCode() {
  return diwali ? (
    <QRCode
      value="https://example.com/offers"
      size={256}
      frame={{ style: "custom", spec: diwali.spec, text: "Scan for offers" }}
    />
  ) : null;
}
```

`OFFICIAL_FRAMES` ist die gesamte Bibliothek, und `OFFICIAL_FRAME_INDEX` listet jeden Rahmen ohne seine Spezifikation auf, sodass eine Auswahl die Bibliothek anzeigen und Spezifikationen erst bei Bedarf laden kann. Die Bibliothek wird als eigenes Modul gebaut, sodass eine App, die sie nie importiert, sie auch nicht ausliefert. In der [Image API](/docs/developers/image-api#community-items) und im [MCP-Server](/docs/developers/mcp) nutzt du einen offiziellen Rahmen als Community-Element, etwa `item=frame:diwali-diya`.

## Wird er scannen? [#will-it-scan]

`getScanScore` schätzt, wie zuverlässig sich ein Design scannen lässt. Die Funktion läuft im Browser und lädt jsQR bei Bedarf nach.

```ts title="lib/scan-score.ts"
import { getScanScore } from "qrdx";

const { score, grade, checks } = await getScanScore({
  value: "https://example.com",
  bodyPattern: "circle",
  cornerEyePattern: "gear",
});
// score: 0 to 100, grade: "great" | "ok" | "risky" | "fails"
// checks: [{ id, passed, message, fix? }]
```

Das wird geprüft:

- **Dekodierung bei 96, 160 und 320 px.** Das Design wird in jeder Breite gerendert, mit kameraähnlicher Unschärfe und Kontrastverlust versehen und einige Male in leicht unterschiedlichen Maßstäben dekodiert.
- **Kontrast** zwischen jeder Farbe des Codes (einschließlich Verlaufsstopps, Augenfarben und Punktfarben) und dem Hintergrund sowie die Frage, ob der Code dunkel auf hellem Grund steht.
- **Logo-Abdeckung** im Vergleich zu dem, was die Fehlerkorrekturstufe wiederherstellen kann.
- **Ruhezone**: der Rand plus der Abstand, den ein Rahmen hinzufügt.
- **Risiko durch die Augenform**: `circle`-Augen werden von manchen Scanner-Apps möglicherweise nicht erkannt, und die eingestellten `curly`-Augen scheitern an strengen Dekodern.
- **Stilpaare** (`style-pair`): Formen, die in den Dekodiertests des Pakets gemeinsam scheitern, etwa `small-square`-Module neben quadratischen Augen (siehe `getStylePairRisk`).

`getImageScanScore(fileOrImage)` macht dasselbe für ein vorhandenes Bild: Die Funktion liefert den dekodierten Inhalt sowie Prüfungen zu Dekodierung, Kontrast, Polarität, Ruhezone und Auflösung, gemessen anhand der Pixel. Der [Scan-Checker](/tools/scan-checker) basiert darauf. In Node prüft `scanQRPixels(pixels, expected)`, ob rohe RGBA-Pixel zu einem Wert dekodiert werden, unverändert und durch das Kameramodell.

<Callout type="info">
  Der Score ist eine Heuristik, die auf einem einzigen Open-Source-Decoder beruht. Kamera-Apps auf dem Smartphone sind oft toleranter. Verstehe ihn deshalb als Orientierung und teste wichtige Drucke mit einem Probe-Scan.
</Callout>

## Druckfertiger Export [#print-ready-export]

`downloadPrintPDF` schreibt ein Vektor-PDF in einer exakten physischen Größe. Module, Augen und Rahmen sind Vektorpfade, ein Logo bleibt ein Rasterbild.

```ts title="lib/print.ts"
import { downloadPrintPDF, downloadPrintSVG, getPrintLayout } from "qrdx";

const props = { value: "https://example.com", frame: { style: "banner-bottom" } } as const;

await downloadPrintPDF(props, {
  size: 40, // width of the code itself
  unit: "mm", // or "in"
  bleed: 3, // millimeters on every side
  cropMarks: true,
  colorMode: "cmyk",
});

await downloadPrintSVG(props, { size: 1.5, unit: "in" }); // width="…in" height="…in"

const layout = getPrintLayout(props, { size: 40 });
layout.trimWidth; // finished width in mm, frame included
layout.maxScanDistance; // 400 (mm)
```

- `size` ist die Breite des Codes, von 5 mm bis 2 m. Ein Rahmen vergrößert das fertige Maß.
- Mit `bleed` (bis zu 20 mm) reicht der Hintergrund oder die Farbe eines quadratischen Rahmens über die Schnittkante hinaus, sodass beim Beschneiden kein weißer Streifen bleibt. Schnittmarken liegen außerhalb des Beschnitts.
- `colorMode: "cmyk"` nutzt eine einfache Umrechnung (`rgbToCmyk`: K ist 1 minus der größte Wert von R, G und B, ohne ICC-Profil; reines Schwarz wird nur mit K gedruckt). Bitte deine Druckerei um eine farbverwaltete Umrechnung, wenn exakte Markenfarben wichtig sind.
- Lineare und radiale Verläufe werden im PDF als weiche Schattierungen gedruckt, in CMYK, wenn das PDF CMYK ist. Das Druck-SVG behält sie, bleibt aber RGB.
- Rahmentext im PDF verwendet Helvetica Bold, daher werden Zeichen außerhalb von Latin-1 eventuell nicht dargestellt. Nutze für andere Schriften das SVG.
- `getQRAsPrintPDF` und `getQRAsPrintPDFBuffer` geben die Datei zurück, statt sie herunterzuladen, und funktionieren auch in Node. `getQRAsEPS` schreibt denselben Code als EPS, siehe [EPS](/docs/features/downloads#eps).

Wie groß du drucken solltest: Ein Code lässt sich ab etwa dem Zehnfachen seiner Breite scannen, die Breite beträgt also ungefähr die Scan-Entfernung geteilt durch 10 (2 cm breit für 20 cm). Dichtere Codes brauchen mehr. Der [Druckgrößen-Rechner](/tools/print-size) berücksichtigt das.
