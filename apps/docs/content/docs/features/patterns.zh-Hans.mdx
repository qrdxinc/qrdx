三个属性决定二维码的形状:`bodyPattern` 用于数据模块,`cornerEyePattern` 用于三个角部定位点,`cornerEyeDotPattern` 用于每个定位点内部的圆点。本页介绍这三个属性,以及模块缩放、异形二维码和逐个定位点的颜色。每个取值都可以在 [形状、定位点与边框](/docs/styles) 中实时查看。

想在 Playground 或控制台中设计?请先阅读帮助中心的 [制作你的第一个二维码](/docs/help/getting-started/first-qr-code)。

```tsx title="components/shaped-code.tsx"
import { QRCode } from "qrdx";

export function ShapedCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      bodyPattern="liquid"
      cornerEyePattern="leaf"
      cornerEyeDotPattern="leaf"
    />
  );
}
```

## 主体图案 [#body-patterns]

`bodyPattern` 决定数据模块的形状。共有 {facts.bodyPatterns} 个取值,默认值为 `circle`。

- 经典:`square`、`small-square`、`horizontal-line`、`vertical-line`、`octagon`
- 圆润:`circle`、`circle-large`、`rounded`、`liquid`、`liquid-horizontal`、`liquid-vertical`、`random-dots`
- 装饰:`classy`、`classy-rounded`、`leaf`、`diamond`、`hexagon`
- 趣味:`mosaic`、`plus`、`star`、`heart`、`pacman`、`circle-mixed`

`liquid`、`classy` 和 `classy-rounded` 会把相邻的模块连接成一条平滑的轮廓;`liquid-horizontal` 和 `liquid-vertical` 只按行或按列连接。`random-dots` 和 `mosaic` 的每个模块各不相同,但相同的取值始终会绘制出相同的二维码。无论使用哪种图案,校正图案始终绘制为实心方块,以便解码器能够识别。

### 模块缩放 [#module-scale]

`moduleScale`(0.5 到 1,默认值为 1)会让每个数据模块围绕自身中心缩小,呈现更轻盈、间距更大的效果。相连的图案则会变成更细的线条。每种图案缩小到在该软件包测试中仍可解码的最小尺寸即停止(例如 `circle` 为 0.95,`classy` 为 0.7;这些下限以 `MODULE_SCALE_FLOOR` 导出),校正图案则保持原始大小。

```tsx title="components/light-code.tsx"
import { QRCode } from "qrdx";

export function LightCode() {
  return (
    <QRCode
      value="https://example.com"
      bodyPattern="liquid"
      moduleScale={0.8}
    />
  );
}
```

## 定位点外框 [#eye-frames]

`cornerEyePattern` 决定角部定位点的形状。共有 {facts.eyeShapes} 个取值,默认值为 `gear`:`square`、`rounded`、`extra-rounded`、`squircle`、`cushion`、`bevel`、`octagon`、`leaf`、`leaf-reverse`、`drop`、`petal`、`shield`、`gear`、`circle`、`diya`、`message` 和 `pointy`。

`leaf`、`leaf-reverse`、`drop` 和 `petal` 会让三个定位点分别朝向二维码各自所在的角。`circle` 定位点可能无法被某些扫描应用识别;[扫描评分](/docs/features/frames#will-it-scan)会对此发出警告。

## 定位点中心 [#eye-centers]

`cornerEyeDotPattern` 决定每个定位点内部圆点的形状。共有 {facts.eyeCentres} 个取值,默认值为 `circle`:`square`、`rounded`、`extra-rounded`、`circle`、`squircle`、`octagon`、`hexagon`、`dots`、`leaf`、`leaf-reverse`、`drop`、`drop-reverse`、`plus`、`cross-rounded`、`flower`、`heart`、`message`、`message-reverse`、`diya`、`diya-reverse` 和 `rounded-triangle`。

## 应避免的搭配与已停用的形状 [#pairs-to-avoid-and-retired-shapes]

`diamond` 主体搭配 `square` 定位点、`pacman` 搭配 `rounded`,以及 `small-square` 搭配 `square` 或 `rounded` 定位点,近距离扫描时容易识别失败。Playground 不会组合这些搭配,它们以 `WEAK_BODY_EYES` 导出,`getStylePairRisk(props)` 会返回扫描评分所显示的警告。

在带方角的定位点(`square`、`rounded`、`extra-rounded` 及大多数其他形状)内使用 `circle` 中心,在清晰的渲染下,严格的解码器可能无法识别:包括屏幕显示、PNG 导出和大幅印刷。实心主体(`square`、`liquid`、`classy`、`classy-rounded`)通常仍可读取,`gear`、`circle` 和 `octagon` 定位点则不受影响。扫描评分会对此发出警告(`style-pair`),你仍然可以选择。这些搭配以 `WEAK_SHARP_DOT_EYES`(连同 `SHARP_DOT_EYE_SAFE_BODIES`)导出,改用 `rounded` 中心即可避免该问题。

`curly` 定位点,以及 `diamond`、`star` 和 `banner` 中心因无法可靠扫描而被停用。用它们保存的设计仍可正常渲染,但不再提供选择,也不再出现在列表中;请参阅[已停用的形状](/docs/styles#retired-shapes)。

## 圆形二维码 [#circle-codes]

`shape="circle"` 会把二维码放进一个圆盘,并用相同圆点形状的装饰模块填满圆盘的其余部分。真正的二维码四周保留一圈宽度为 `margin` 个模块(至少 3 个)的浅色边距,扫描器只读取中间的二维码。圆盘比二维码本身大,因此为了获得相同的扫描距离,印刷时要稍大一些;[打印尺寸计算器](/tools/print-size)计算的是整个圆盘。

```tsx title="components/circle-code.tsx"
import { QRCode } from "qrdx";

export function CircleCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      shape="circle"
      bodyPattern="rounded"
    />
  );
}
```

在该软件包的解码测试中,采用实心圆点形状(`square`、`rounded`、`classy`、`liquid`)的圆形二维码,读取效果与方形二维码相当。

## 心形二维码 [#heart-codes]

`shape="heart"` 的用法与圆形二维码相同,只是形状为心形。真正的二维码位于心形中央,周围同样保留至少 3 个模块的浅色边距,心形的其余部分填充装饰模块。二维码在心形中所占的比例比在圆形中小,因此为了获得相同的扫描距离,心形二维码要比方形二维码印得更大。扫描评分会把这一点计算在内:在相同尺寸下,心形二维码的得分低于圆形二维码。

```tsx title="components/heart-code.tsx"
import { QRCode } from "qrdx";

export function HeartCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      shape="heart"
      bodyPattern="rounded"
    />
  );
}
```

在 Playground 中,异形二维码会取代边框的位置:选择异形会清除边框,选择边框则会清除异形。每个边框都会在二维码下方绘制一块浅色底板,这会遮住轮廓。如果你同时传入 `shape` 和 `frame`,引擎仍然会绘制 `shape`。在该软件包的解码测试中,心形二维码搭配所有实心圆点形状,以及 `square`、`rounded` 和 `gear` 定位点,都可以读取。

## 自定义形状 [#custom-shapes]

`shape` 也接受剪影:根据你自己的图片描摹出的小型网格(每边最多 64 个单元)。二维码位于该形状中最宽敞的中间部分,形状的其余部分填充装饰模块。系统只保留网格,绝不保留图片。

```tsx title="components/silhouette-code.tsx"
import { getQRSilhouetteFit, loadQRSilhouette, QRCode } from "qrdx";

export async function silhouetteFrom(file: File) {
  const shape = await loadQRSilhouette(file); // a PNG, JPEG or SVG, in the browser
  const fit = getQRSilhouetteFit(shape);
  if (!fit.ok) throw new Error(fit.message);
  return shape;
}

export function SilhouetteCode({ shape }: { shape: Awaited<ReturnType<typeof silhouetteFrom>> }) {
  return <QRCode value="https://example.com" size={256} shape={shape} />;
}
```

`loadQRSilhouette` 会把图片绘制到画布上,并使用其透明度;若图片不透明,则使用其明暗程度,因此深色背景上的浅色形状同样可用。在服务器上,请把解码后的 RGBA 像素传给 `createQRSilhouette`。`getQRSilhouetteFit` 会拒绝过于细窄、无法容纳二维码及其静区的形状,例如细长的星形、条形或环形。被拒绝的形状会绘制为方形二维码。

在控制台中,剪影会与设计一起保存,就像上传的 Logo 一样:分享链接、社区项目、代码片段和 AI 聊天则会改用方形二维码。

## 逐个定位点的颜色 [#per-eye-colors]

`eyeColor` 和 `dotColor` 会为三个定位点统一设置颜色。`eyeColors` 可以按定位点分别覆盖(`topLeft`、`topRight`、`bottomLeft`),每个定位点都有 `outer`(外框)和 `inner`(圆点)的颜色或渐变:

```tsx title="components/eye-colors-code.tsx"
import { QRCode } from "qrdx";

export function EyeColorsCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      eyeColor="#111827"
      eyeColors={{
        topLeft: { outer: "#dc2626", inner: "#1d4ed8" },
        topRight: { outer: "#16a34a" },
      }}
    />
  );
}
```

请让每个定位点都与背景形成深色对比:解码器靠这三个定位点找到二维码。扫描评分会检查每个定位点自身颜色的对比度。
