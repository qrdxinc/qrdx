La prop `frame` dessine un cadre « Scan me » autour d'un code, `getScanScore` vous indique si un design sera scannable, et les fonctions d'impression écrivent des fichiers vectoriels à une taille physique, avec fond perdu et traits de coupe. Cette page présente ces trois sujets, dans cet ordre.

Vous concevez plutôt dans le Playground ou le tableau de bord ? Consultez [Ajouter un cadre et un appel à l'action](/docs/help/designing/frames), [Vérifier un design avec le score de scan](/docs/help/designing/scan-score) et [Télécharger et imprimer un QR code](/docs/help/getting-started/download-and-print) dans l'aide.

## Cadres d'appel à l'action [#call-to-action-frames]

Chaque cadre dessiné par QRdx est une spécification de cadre : une courte description JSON de formes, de libellés et de couleurs. Un seul moteur dessine toutes les spécifications, si bien qu'un cadre a le même aspect en SVG, PNG, PDF et EPS. Il existe {facts.frames} cadres : {facts.frameStyles} cadres intégrés et {facts.officialFrames} [cadres officiels](#official-frames). Vous pouvez aussi écrire le vôtre ou en choisir un dans la [communauté](/community/frames).

`frame` fonctionne avec `QRCode`, `QRCodeSVG`, `QRCodeCanvas`, `getQRAsSVG`, `getQRData` et tous les utilitaires de téléchargement.

```tsx title="components/menu-frame-code.tsx"
import { QRCode } from "qrdx";

export function MenuFrameCode() {
  return (
    <QRCode
      value="https://example.com/menu"
      size={256}
      frame={{
        style: "banner-bottom",
        text: "Scan for the menu",
        color: "#1e3a8a",
      }}
    />
  );
}
```

Le cadre est ajouté autour du code : la sortie est donc plus grande, et les modules et la zone de silence ne sont jamais recouverts, de sorte que la lisibilité au scan ne change pas. Un espace clair, de la couleur d'arrière-plan du code, sépare le code du cadre.

### Cadres intégrés [#built-in-frames]

Un cadre intégré est désigné par son `style`. Les options renseignent les libellés et les couleurs de sa spécification :

| Option | Valeur par défaut | Notes |
| --- | --- | --- |
| `style` | aucun | L'un des {facts.frameStyles} styles intégrés ci-dessous, `none`, ou `custom` avec une `spec` |
| `text` | `"Scan me"` | 24 caractères maximum. Passez `""` pour masquer le libellé |
| `color` | la couleur propre à la spécification : noir pour tous les cadres intégrés sauf `gradient-border`, qui commence en violet | Couleur du cadre |
| `textColor` | blanc sur le cadre, `color` sur les zones claires | Couleur du libellé |
| `secondaryText` | aucun | Second libellé, 24 caractères maximum : le bandeau du bas de `banner-top-bottom`, l'arc inférieur de `circle`, le pied de `menu-card` |
| `secondaryColor` | la couleur d'accent de la spécification, rose | Couleur de fin de `gradient-border` |
| `fontScale` | `1` | Taille du libellé de 0,5 à 1,5 ; les libellés se réduisent toujours pour tenir |

Les cadres intégrés, par `style` :

- Bannières et bordures : `banner-bottom`, `banner-top`, `banner-top-bottom`, `border`, `rounded-border`, `gradient-border`, `focus` (angles en équerre)
- Bulles : `speech-bubble`, `speech-bubble-top`, `chat-bubble`
- Badges : `circle` (texte disposé autour d'un anneau), `badge` (ruban), `sticker` (découpe à la forme avec une ombre)
- Objets : `polaroid`, `phone`, `ticket`, `tag` (étiquette à suspendre avec un trou), `envelope`, `menu-card`

Chacun de ces noms correspond à une spécification dans le moteur, et ces noms restent valides définitivement. Les designs enregistrés, les liens Image API, les options de la CLI et le code qui les utilisent continuent de dessiner le même cadre. Les cadres qui suppriment la ligne de leur libellé lorsqu'il n'y a pas de libellé, comme les bordures, continuent de le faire. Vous pouvez tous les voir, décodés dans votre navigateur, dans [Formes, yeux et cadres](/docs/styles#frames).

`BUILT_IN_FRAMES` les énumère avec leurs noms et leurs spécifications (`BUILT_IN_FRAME_SPECS` donne les spécifications par style). `frameSpecOf` renvoie la spécification dessinée par n'importe quel cadre, et `getFrameColors` les couleurs avec lesquelles il peint :

```ts title="lib/frames.ts"
import { BUILT_IN_FRAMES, frameSpecOf, getFrameColors, getFrameDimensions } from "qrdx";

BUILT_IN_FRAMES.map((frame) => frame.name); // ["Banner", "Top banner", "Two banners", …]

// A built-in style's spec, or a custom frame's own
const ticket = frameSpecOf({ style: "ticket" });

// The frame's options, else its spec's defaults
getFrameColors({ style: "border", color: "#1e3a8a" });
// { frame: "#1e3a8a", text: "#1e3a8a", accent: "#1e3a8a" }

// The output size: a 400 px code in a bottom banner
getFrameDimensions(400, { style: "banner-bottom" }); // { width: 496, height: 568 }
```

Pour modifier autre chose que les libellés et les couleurs, partez d'une spécification intégrée pour créer un cadre personnalisé : `{ style: "custom", spec: frameSpecOf({ style: "ticket" }) }` dessine le même ticket, et vous pouvez en modifier les formes.

Chaque cadre se compose uniquement de formes simples et de texte, avec des couleurs opaques, si bien que les exports SVG, PNG, PDF et EPS sont identiques. La bordure en dégradé est dessinée en fines étapes de couleurs unies, et les lettres courbes du cadre circulaire sont du texte pivoté dans tous les formats. Le libellé utilise la pile de polices du système : rien n'est donc téléchargé.

`FRAME_STYLES`, `frameSchema` (zod) et les types `QRFrame` et `FrameStyle` sont aussi exportés depuis `qrdx/types` pour la validation côté serveur. La CLI dessine les mêmes cadres avec `--frame`, `--frame-text`, `--frame-color` et `--frame-text-color` ; voir [CLI](/docs/developers/cli).

### Spécifications de cadre [#frame-specs]

Une spécification de cadre est un JSON avec `kind: "qrdx.frame"`, `version: 1`, une taille d'`artboard`, une zone `qr` où se place le code, des `colors` par défaut, les `shapes` peintes derrière le code et les `labels`. Les formes sont des rectangles (avec un trou facultatif), des cercles et des anneaux, des ellipses, des polygones, des tracés, des lignes et des icônes intégrées. Elles sont remplies avec un jeton de thème (`frame`, `text`, `accent`, `background`), une couleur hexadécimale, un mélange de deux couleurs ou un dégradé. Une spécification ne contient ni balisage, ni liens, ni images. Vérifiez toute spécification que vous n'avez pas écrite avec `frameSpecSchema` ou `getFrameSpecIssues` depuis `qrdx/types` avant de l'enregistrer. Le moteur la vérifie de nouveau avant de dessiner.

```tsx title="components/custom-frame-code.tsx"
import { QRCode } from "qrdx";
import spec from "./my-frame.json";

export function CustomFrameCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      frame={{ style: "custom", spec, text: "Scan me", color: "#1e3a8a" }}
    />
  );
}
```

Champs facultatifs utilisés par les cadres et modèles intégrés (les spécifications qui n'en ont pas se dessinent comme avant) :

| Champ | Rôle |
| --- | --- |
| `labels[].collapse` | `{ y, height }`. Lorsque le libellé n'affiche aucun texte, la bande de `y` à `y + height` est supprimée : les lignes situées en dessous remontent et l'illustration devient plus courte. Les formes entièrement comprises dans la bande sont omises, et celles qui la traversent sont raccourcies. Une bande ne peut pas croiser le code, sa marge intérieure ou une autre bande |
| `qr.plate` | `"opaque"` (valeur par défaut), `"background"` ou `"none"`. Le moteur peint une plaque de la couleur d'arrière-plan du code sous le code. Lorsque cet arrière-plan est transparent, `"opaque"` peint la plaque et `background` remplit en blanc, de sorte que l'illustration n'apparaît jamais à travers la zone de silence. `"background"` les garde transparents et omet la plaque ; il n'est autorisé que si, sous la plaque, il n'y a que des remplissages `background`, ou un anneau dont le trou contient la plaque. `"none"` ne peint aucune plaque : l'arrière-plan et la marge du code sont alors son seul espace clair, et `qr.padding` peut être inférieur à 4 %. Les modèles l'utilisent |
| `stroke` | `{ color, width }` sur un rectangle, un cercle, une ellipse, un polygone ou un tracé : un contour centré sur le bord de la forme, dessiné après son remplissage, d'au plus 10 % du petit côté de l'artboard |
| `colors.text` | Une couleur hexadécimale, ou un mélange de `frame`, `accent`, `background` et de couleurs hexadécimales, comme `{ "mix": ["frame", "accent"], "amount": 0.5 }` pour le libellé de la bordure en dégradé. C'est la valeur par défaut ; `textColor` reste prioritaire |

La ligne d'un libellé texte peut aussi empiéter sur la marge intérieure de la plaque, tant qu'elle reste à l'écart du code et que ses majuscules restent hors de la marge à la plus grande taille de texte (`fontScale` 1.5). Les cadres à bordure placent ainsi leur libellé juste sous le code.

## Cadres officiels [#official-frames]

En plus des cadres intégrés, QRdx propose {facts.officialFrames} cadres officiels : des designs prêts à l'emploi pour les appels à l'action, les restaurants et cafés, les commerces et emballages, la beauté et le bien-être, les événements et mariages, les hôtels et voyages, l'immobilier, les voitures et parkings, la santé et l'éducation, le sport et la forme, les entreprises et réseaux sociaux, ainsi que les associations et groupes communautaires. {facts.seasonalFrames} d'entre eux sont consacrés aux fêtes et aux saisons, du Nouvel An lunaire, de Holi, de l'Aïd et de Diwali à Hanoukka, Pâques, Thanksgiving et Noël. Chacun est une spécification de cadre dont vous pouvez modifier les libellés et les couleurs, publiée sous CC0, et chacun est testé pour se scanner à des distances de téléphone. Dans la [communauté](/community/frames), ils sont publiés par @qrdx.

```tsx title="components/official-frame-code.tsx"
import { getOfficialFrame, QRCode } from "qrdx";

const diwali = getOfficialFrame("diwali-diya"); // undefined for an unknown id

export function OfficialFrameCode() {
  return diwali ? (
    <QRCode
      value="https://example.com/offers"
      size={256}
      frame={{ style: "custom", spec: diwali.spec, text: "Scan for offers" }}
    />
  ) : null;
}
```

`OFFICIAL_FRAMES` est la bibliothèque complète, et `OFFICIAL_FRAME_INDEX` énumère chaque cadre sans sa spécification, afin qu'un sélecteur puisse afficher la bibliothèque et ne charger les spécifications qu'au besoin. La bibliothèque est construite comme un module à part, donc une application qui ne l'importe jamais ne l'embarque pas. Dans l'[Image API](/docs/developers/image-api#community-items) et le [serveur MCP](/docs/developers/mcp), utilisez un cadre officiel comme élément de la communauté, par exemple `item=frame:diwali-diya`.

## Sera-t-il scanné ? [#will-it-scan]

`getScanScore` estime la fiabilité de scan d'un design. Il s'exécute dans le navigateur et charge jsQR à la demande.

```ts title="lib/scan-score.ts"
import { getScanScore } from "qrdx";

const { score, grade, checks } = await getScanScore({
  value: "https://example.com",
  bodyPattern: "circle",
  cornerEyePattern: "gear",
});
// score: 0 to 100, grade: "great" | "ok" | "risky" | "fails"
// checks: [{ id, passed, message, fix? }]
```

Ce qu'il vérifie :

- **Le décodage à 96, 160 et 320 px.** Le design est rendu à chaque largeur, avec un flou et une perte de contraste semblables à ceux d'une caméra, puis décodé plusieurs fois à des échelles légèrement différentes.
- **Le contraste** entre chaque couleur du code (y compris les points de dégradé, les couleurs des yeux et des points) et l'arrière-plan, ainsi que le fait que le code soit sombre sur fond clair.
- **La couverture du logo**, comparée à ce que le niveau de correction d'erreur permet de récupérer.
- **La zone de silence** : la marge, plus l'espace qu'ajoute un cadre.
- **Le risque lié à la forme des yeux** : les yeux `circle` peuvent être manqués par certaines applications de scan, et les yeux `curly`, retirés, échouent avec les décodeurs stricts.
- **Les paires de styles** (`style-pair`) : des formes qui échouent ensemble dans les tests de décodage du package, comme des modules `small-square` à côté d'yeux carrés (voir `getStylePairRisk`).

`getImageScanScore(fileOrImage)` fait la même chose pour une image existante : il renvoie le contenu décodé, ainsi que des vérifications de décodage, de contraste, de polarité, de zone de silence et de résolution mesurées à partir des pixels. Le [vérificateur de scan](/tools/scan-checker) repose dessus. Dans Node, `scanQRPixels(pixels, expected)` vérifie que des pixels RGBA bruts se décodent en une valeur donnée, tels quels et à travers le modèle de caméra.

<Callout type="info">
  Le score est une heuristique fondée sur un seul décodeur open source. Les applications d'appareil photo des téléphones sont souvent plus tolérantes : considérez-le comme un repère et testez par un scan les impressions importantes.
</Callout>

## Export prêt à imprimer [#print-ready-export]

`downloadPrintPDF` génère un PDF vectoriel à une taille physique exacte. Les modules, les yeux et les cadres sont des tracés vectoriels ; un logo reste une image raster.

```ts title="lib/print.ts"
import { downloadPrintPDF, downloadPrintSVG, getPrintLayout } from "qrdx";

const props = { value: "https://example.com", frame: { style: "banner-bottom" } } as const;

await downloadPrintPDF(props, {
  size: 40, // width of the code itself
  unit: "mm", // or "in"
  bleed: 3, // millimeters on every side
  cropMarks: true,
  colorMode: "cmyk",
});

await downloadPrintSVG(props, { size: 1.5, unit: "in" }); // width="…in" height="…in"

const layout = getPrintLayout(props, { size: 40 });
layout.trimWidth; // finished width in mm, frame included
layout.maxScanDistance; // 400 (mm)
```

- `size` est la largeur du code, de 5 mm à 2 m ; un cadre s'ajoute à la taille finale.
- Avec `bleed` (jusqu'à 20 mm), l'arrière-plan ou la couleur d'un cadre carré dépasse du bord de coupe, pour que le rognage ne laisse aucun liseré blanc. Les traits de coupe se trouvent en dehors du fond perdu.
- `colorMode: "cmyk"` utilise une conversion simple (`rgbToCmyk` : K vaut 1 moins la plus grande des valeurs R, G et B, sans profil ICC ; le noir pur s'imprime en K seul). Demandez à votre imprimeur une conversion avec gestion des couleurs lorsque les couleurs exactes de votre marque comptent.
- Les dégradés linéaires et radiaux sont imprimés sous forme de dégradés lisses dans le PDF, en CMYK lorsque le PDF est en CMYK ; le SVG d'impression les conserve mais reste en RGB.
- Le texte du cadre dans le PDF utilise Helvetica Bold, donc les caractères hors Latin-1 peuvent ne pas s'afficher. Utilisez le SVG pour les autres écritures.
- `getQRAsPrintPDF` et `getQRAsPrintPDFBuffer` renvoient le fichier au lieu de le télécharger, et fonctionnent aussi dans Node. `getQRAsEPS` génère le même code au format EPS ; voir [EPS](/docs/features/downloads#eps).

Quelle taille imprimer : un code se scanne à une distance d'environ dix fois sa largeur, donc la largeur vaut environ la distance de scan divisée par 10 (2 cm de large pour 20 cm). Les codes plus denses demandent plus de place ; le [calculateur de taille d'impression](/tools/print-size) en tient compte.
