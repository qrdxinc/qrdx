Quatre props colorent un code : `fgColor` pour les modules de données, `bgColor` pour l'arrière-plan, `eyeColor` pour les trois yeux d'angle et `dotColor` pour le point à l'intérieur de chaque œil. Chacune accepte une couleur unie ou un objet de dégradé, et les couleurs des yeux utilisent `fgColor` par défaut. Cette page présente chaque type de remplissage et la façon de garder le code lisible.

Vous créez votre design dans le Playground ou le tableau de bord ? Consultez [Choisir des couleurs qui se scannent](/docs/help/designing/colors-and-contrast) dans l'aide.

## Couleurs unies [#solid-colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1a56db"
      bgColor="#f9fafb"
      eyeColor="#0d47a1"
      dotColor="#3b82f6"
    />
  );
}
```

Une couleur unie est n'importe quelle couleur CSS que le moteur sait interpréter : hexadécimal à 3, 4, 6 ou 8 chiffres, `rgb()` et `rgba()`, une couleur nommée ou `transparent`. Les autres syntaxes CSS, comme `hsl()`, s'affichent dans le SVG, mais la vérification du contraste, le PDF et l'EPS ne peuvent pas les lire ; tenez-vous-en donc aux formes ci-dessus. `{ type: "solid", color: "#1a56db" }` équivaut à la chaîne.

`eyeColors` définit chaque œil séparément (`topLeft`, `topRight`, `bottomLeft`, chacun avec une couleur ou un dégradé `outer` et `inner`) ; voir [Couleurs par œil](/docs/features/patterns#per-eye-colors).

### Arrière-plan transparent [#transparent-background]

`bgColor="transparent"` ne peint aucun arrière-plan : les téléchargements PNG et SVG sont donc transparents, et les fichiers PDF et EPS n'ont pas de remplissage d'arrière-plan. Placez le code sur une surface claire et unie : les décodeurs ont besoin des espaces clairs entre les modules.

## Dégradés linéaires [#linear-gradients]

```tsx title="components/gradient-code.tsx"
import { QRCode } from "qrdx";

export function GradientCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "linear",
        angle: 45,
        stops: [
          { color: "#4f46e5", offset: 0 },
          { color: "#db2777", offset: 100 },
        ],
      }}
    />
  );
}
```

- `angle` est exprimé en degrés : 0 va de gauche à droite, 90 de haut en bas, 45 du coin supérieur gauche vers le coin inférieur droit.
- `stops` nécessite au moins deux entrées. `offset` est un pourcentage de 0 à 100, et la couleur d'un point d'arrêt peut comporter de l'alpha.
- Toute prop de couleur accepte un dégradé, y compris `bgColor` et les yeux. `QRCodeCanvas` ne sait pas dessiner de dégradés et utilise le premier point d'arrêt ; utilisez `QRCode` ou `QRCodeSVG`.

Les dégradés sont conservés dans les téléchargements SVG, PNG, JPG, WebP et PDF. Le PDF d'impression et l'EPS les dessinent sous forme de dégradés lisses.

## Dégradés radiaux [#radial-gradients]

```tsx title="components/radial-code.tsx"
import { QRCode } from "qrdx";

export function RadialCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "radial",
        stops: [
          { color: "#0f766e", offset: 0 },
          { color: "#0c4a6e", offset: 100 },
        ],
      }}
    />
  );
}
```

Un dégradé radial part du centre du code vers l'extérieur. Son centre et son rayon suivent la taille du code ; il n'accepte donc que `stops`.

## Dégradés angulaires [#angular-gradients]

Un dégradé angulaire balaie le centre de la zone remplie dans le sens horaire, comme le `conic-gradient` CSS. `angle` est le point de départ du balayage, en degrés dans le sens horaire à partir du haut. Les décalages vont de 0 à 100 sur le tour complet.

```tsx title="components/angular-code.tsx"
import { QRCode } from "qrdx";

export function AngularCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "angular",
        angle: 30,
        stops: [
          { color: "#1d4ed8", offset: 0 },
          { color: "#7c3aed", offset: 50 },
          { color: "#1d4ed8", offset: 100 },
        ],
      }}
    />
  );
}
```

Le SVG n'a pas de dégradé conique : le code dessine donc un éventail de fines portions, séparées d'environ deux niveaux de couleur. Le PDF et l'EPS dessinent les mêmes portions.

## Couleurs transparentes [#see-through-colors]

Les couleurs et les points d'arrêt des dégradés peuvent comporter de l'alpha, par exemple `#1d4ed8cc` ou `rgba(29, 78, 216, 0.8)`. Le SVG l'écrit sous forme de `fill-opacity` et `stop-opacity`, et le PDF le conserve. L'EPS ne gère pas la transparence : une couleur transparente est donc mélangée à l'arrière-plan. La vérification de scan juge une couleur transparente telle qu'elle apparaît sur l'arrière-plan.

## Remplissages d'image [#image-fills]

Un remplissage d'image peint une image à travers l'arrière-plan, les modules ou les yeux. L'image est posée sur l'ensemble du code ; les modules et les yeux qui en partagent une affichent donc une seule image.

```tsx title="components/photo-code.tsx"
import { QRCode } from "qrdx";

export function PhotoCode({ photo }: { photo: string }) {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "image",
        src: photo, // a data:image/jpeg;base64,… URL
        fit: "cover", // or "contain", "tile"
        position: "center",
        scale: 1,
        opacity: 0.45,
        underlay: "#000000",
      }}
    />
  );
}
```

- `src` est l'image elle-même, comme pour un logo. QRdx n'enregistre un remplissage d'image (dans les codes, les thèmes et la REST API) que sous la forme d'une URL `data:image` en base64 (PNG, JPEG, WebP ou GIF) de 1,5 Mo maximum ; une image provenant d'un lien est refusée. Les PNG et JPEG sont intégrés dans tous les exports, et les serveurs ne récupèrent jamais un lien.
- `underlay` est une couleur unie placée sous l'image. `opacity` la laisse apparaître : sur du noir, elle assombrit une photo pour les modules, et sur du blanc, elle en éclaircit une pour l'arrière-plan.
- Le détail d'une image est perçu comme du bruit par une caméra ; la vérification de scan exige donc plus de contraste : 7:1 dans les modules ou les yeux, 12:1 derrière eux (`SCAN_IMAGE_CONTRAST_MIN`). Elle mesure une image à partir de son dixième le plus clair et de son dixième le plus sombre (`getImageTones`). Dans l'éditeur, **Rendre scannable** trouve l'opacité au-dessus de la couleur de fond qui réussit la vérification.
- Le SVG, le PNG et le PDF prennent en charge les remplissages d'image. Ce n'est pas le cas de l'EPS ; voir [EPS](/docs/features/downloads#eps).

Les remplissages d'image se comportent comme les logos. Ils restent avec le design dans l'éditeur, dans les codes enregistrés et dans les thèmes enregistrés. Ils ne sont pas inclus dans les liens `?style=`, les styles communautaires publiés, les extraits de Get code ni le contexte du chat : chaque remplissage d'image y est remplacé par sa couleur `underlay`. L'Image API (`GET /v1/qr`) et le serveur MCP ne les acceptent pas. `POST /v1/codes` et `PATCH /v1/codes/{id}` n'en acceptent un que sous forme d'URL `data:image` et répondent 400 pour tout le reste.

## Vérifier le contraste [#check-the-contrast]

Les scanners ont besoin de modules foncés sur un arrière-plan clair. Le score de scan vérifie chaque couleur, y compris chaque point d'arrêt de dégradé, par rapport à l'arrière-plan ; les mêmes utilitaires sont exportés :

```ts title="lib/check-contrast.ts"
import { getContrastLevel, getContrastRatio } from "qrdx";

const ratio = getContrastRatio("#1a56db", "#f9fafb");
// 5.9

getContrastLevel(ratio);
// { level: "AA", warning: false, message: "Good contrast" }
```

Le score de scan accepte un ratio de 4,5 ou plus (`SCAN_CONTRAST_MIN`), retire des points en dessous, et fait échouer le design sous 1,5. `getContrastLevel` renvoie `AAA` à partir de 7, `AA` à partir de 4,5, `AA Large` à partir de 3 avec un avertissement, et `Fail` en dessous. Un code clair sur un arrière-plan foncé passe le ratio mais perd des points à la vérification de polarité : la plupart des caméras de téléphone le lisent, certaines applications de scan non.
