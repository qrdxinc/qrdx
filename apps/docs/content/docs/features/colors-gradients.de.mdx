Vier Props färben einen Code: `fgColor` für die Datenmodule, `bgColor` für den Hintergrund, `eyeColor` für die drei Eyes in den Ecken und `dotColor` für den Punkt in der Mitte jedes Eyes. Jede Prop nimmt eine einfarbige Fläche oder ein Verlaufsobjekt entgegen, und die Eye-Farben übernehmen standardmäßig `fgColor`. Diese Seite behandelt alle Arten von Füllungen und zeigt, wie der Code lesbar bleibt.

Du gestaltest lieber im Playground oder im Dashboard? Dann lies in der Hilfe [Farben wählen, die sich scannen lassen](/docs/help/designing/colors-and-contrast).

## Einfarbige Flächen [#solid-colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1a56db"
      bgColor="#f9fafb"
      eyeColor="#0d47a1"
      dotColor="#3b82f6"
    />
  );
}
```

Eine einfarbige Fläche ist jede CSS-Farbe, die die Engine versteht: Hex mit 3, 4, 6 oder 8 Stellen, `rgb()` und `rgba()`, ein benannter Farbname oder `transparent`. Andere CSS-Schreibweisen wie `hsl()` werden zwar im SVG gerendert, aber die Kontrastprüfung, das PDF und das EPS können sie nicht lesen. Bleib deshalb bei den oben genannten Formen. `{ type: "solid", color: "#1a56db" }` entspricht dem String.

Mit `eyeColors` legst du jedes Eye einzeln fest (`topLeft`, `topRight`, `bottomLeft`, jeweils mit einer `outer`- und einer `inner`-Farbe oder einem Verlauf); siehe [Farben pro Eye](/docs/features/patterns#per-eye-colors).

### Transparenter Hintergrund [#transparent-background]

`bgColor="transparent"` zeichnet keinen Hintergrund. PNG- und SVG-Downloads sind dadurch durchsichtig, und PDF- und EPS-Dateien haben keine Hintergrundfüllung. Platziere den Code auf einer hellen, einfarbigen Fläche: Decoder brauchen die hellen Lücken zwischen den Modulen.

## Lineare Verläufe [#linear-gradients]

```tsx title="components/gradient-code.tsx"
import { QRCode } from "qrdx";

export function GradientCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "linear",
        angle: 45,
        stops: [
          { color: "#4f46e5", offset: 0 },
          { color: "#db2777", offset: 100 },
        ],
      }}
    />
  );
}
```

- `angle` wird in Grad angegeben: 0 verläuft von links nach rechts, 90 von oben nach unten, 45 von der linken oberen Ecke diagonal zur rechten unteren.
- `stops` braucht mindestens zwei Einträge. `offset` ist ein Prozentwert von 0 bis 100, und die Farbe eines Stopps kann einen Alphawert enthalten.
- Jede Farb-Prop nimmt einen Verlauf entgegen, auch `bgColor` und die Eyes. `QRCodeCanvas` kann keine Verläufe zeichnen und nutzt den ersten Stopp; verwende `QRCode` oder `QRCodeSVG`.

Verläufe landen in Downloads als SVG, PNG, JPG, WebP und PDF. Das Druck-PDF und das EPS zeichnen sie als weiche Farbverläufe (Shadings).

## Radiale Verläufe [#radial-gradients]

```tsx title="components/radial-code.tsx"
import { QRCode } from "qrdx";

export function RadialCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "radial",
        stops: [
          { color: "#0f766e", offset: 0 },
          { color: "#0c4a6e", offset: 100 },
        ],
      }}
    />
  );
}
```

Ein radialer Verlauf geht vom Mittelpunkt des Codes nach außen. Mittelpunkt und Radius richten sich nach der Größe des Codes, deshalb nimmt er nur `stops`.

## Winkelförmige Verläufe [#angular-gradients]

Ein winkelförmiger Verlauf läuft im Uhrzeigersinn um die Mitte der gefüllten Fläche, wie CSS `conic-gradient`. `angle` gibt an, wo der Verlauf beginnt, in Grad im Uhrzeigersinn von oben. Die Offsets laufen von 0 bis 100 einmal um den Kreis.

```tsx title="components/angular-code.tsx"
import { QRCode } from "qrdx";

export function AngularCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "angular",
        angle: 30,
        stops: [
          { color: "#1d4ed8", offset: 0 },
          { color: "#7c3aed", offset: 50 },
          { color: "#1d4ed8", offset: 100 },
        ],
      }}
    />
  );
}
```

SVG kennt keinen konischen Verlauf, deshalb zeichnet der Code einen Fächer aus dünnen Keilen, etwa zwei Farbstufen voneinander entfernt. PDF und EPS zeichnen dieselben Keile.

## Durchsichtige Farben [#see-through-colors]

Farben und Verlaufsstopps können einen Alphawert enthalten, etwa `#1d4ed8cc` oder `rgba(29, 78, 216, 0.8)`. SVG schreibt ihn als `fill-opacity` und `stop-opacity`, und PDF behält ihn bei. EPS kennt keine Transparenz, deshalb wird eine durchsichtige Farbe mit dem Hintergrund gemischt. Die Scan-Prüfung beurteilt eine durchsichtige Farbe so, wie sie auf dem Hintergrund aussieht.

## Bildfüllungen [#image-fills]

Eine Bildfüllung legt ein Bild in den Hintergrund, in die Module oder in die Eyes. Das Bild liegt über dem ganzen Code, sodass Module und Eyes, die sich eines teilen, ein einziges Bild zeigen.

```tsx title="components/photo-code.tsx"
import { QRCode } from "qrdx";

export function PhotoCode({ photo }: { photo: string }) {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor={{
        type: "image",
        src: photo, // a data:image/jpeg;base64,… URL
        fit: "cover", // or "contain", "tile"
        position: "center",
        scale: 1,
        opacity: 0.45,
        underlay: "#000000",
      }}
    />
  );
}
```

- `src` ist das Bild selbst, wie bei einem Logo. QRdx speichert eine Bildfüllung (in Codes, Themes und der REST API) nur als base64-`data:image`-URL (PNG, JPEG, WebP oder GIF) mit höchstens 1,5 MB; ein Bild von einem Link wird abgelehnt. PNG und JPEG sind in jedem Export eingebettet, und Server rufen nie einen Link ab.
- `underlay` ist eine einfarbige Fläche unter dem Bild. `opacity` lässt sie durchscheinen: Über Schwarz dunkelt sie ein Foto für die Module ab, über Weiß hellt sie eines für den Hintergrund auf.
- Die Details eines Bildes wirken auf eine Kamera wie Rauschen, deshalb verlangt die Scan-Prüfung mehr Kontrast: 7:1 in den Modulen oder Eyes, 12:1 dahinter (`SCAN_IMAGE_CONTRAST_MIN`). Ein Bild wird nach seinem hellsten und dunkelsten Zehntel bemessen (`getImageTones`). Im Editor findet **Make it scannable** die Deckkraft über dem Underlay, die besteht.
- SVG, PNG und PDF enthalten Bildfüllungen. EPS nicht; siehe [EPS](/docs/features/downloads#eps).

Bildfüllungen verhalten sich wie Logos. Sie bleiben beim Design im Editor, in gespeicherten Codes und in gespeicherten Themes. Sie landen nicht in `?style=`-Links, veröffentlichten Community-Stilen, Get-code-Snippets oder im Kontext des Chats: Dort weicht jede Bildfüllung ihrer Underlay-Farbe. Die Image API (`GET /v1/qr`) und der MCP-Server nehmen sie nicht an. `POST /v1/codes` und `PATCH /v1/codes/{id}` nehmen eine nur als `data:image`-URL an und antworten bei allem anderen mit 400.

## Kontrast prüfen [#check-the-contrast]

Scanner brauchen dunkle Module auf hellem Hintergrund. Der Scan-Score prüft jede Farbe, auch jeden Verlaufsstopp, gegen den Hintergrund; dieselben Helfer sind exportiert:

```ts title="lib/check-contrast.ts"
import { getContrastLevel, getContrastRatio } from "qrdx";

const ratio = getContrastRatio("#1a56db", "#f9fafb");
// 5.9

getContrastLevel(ratio);
// { level: "AA", warning: false, message: "Good contrast" }
```

Der Scan-Score lässt ein Verhältnis ab 4,5 durch (`SCAN_CONTRAST_MIN`), zieht darunter Punkte ab und lässt das Design unter 1,5 durchfallen. `getContrastLevel` gibt `AAA` ab 7 zurück, `AA` ab 4,5, `AA Large` ab 3 mit einer Warnung und darunter `Fail`. Ein heller Code auf dunklem Hintergrund besteht das Verhältnis, verliert aber Punkte bei der Polaritätsprüfung: Die meisten Handykameras lesen ihn, manche Scanner-Apps nicht.
