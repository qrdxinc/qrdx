すべての[動的QRコード](/docs/dynamic-qr-codes)は、Cookieを使わずにスキャンを記録します。トラッキングでは、さらに2つのことができます。コードが開くホスト型ページに自分のピクセルを読み込むことと、自社サイトでの購入などのコンバージョンを、訪問者をもたらしたスキャンに紐付けることです。QRコード経由のトラフィックをチームが普段使っているツールに表示したいとき、またどのコードが収益を生んでいるかを知りたいときに使ってください。

<Callout type="info" title="ピクセルはPro、コンバージョンはBusiness">
  トラッキングピクセルはProとBusinessに含まれ、コンバージョントラッキングはBusinessに含まれます。どちらもコードの**設定**タブで設定します。[プランと制限](/docs/plans-and-limits)をご覧ください。
</Callout>

お急ぎの場合は、[スキャンを確認する](/docs/help/dynamic-codes/scans)で、すべてのプランで使える分析機能を紹介しています。

## 仕組み [#how-it-works]

<Diagram id="tracking-paths" />

コードは、ホスト型ページを開くか、自社サイトにリダイレクトするかのどちらかで、それぞれに専用のツールがあります。ホスト型ページではQRdxがHTMLを制御するため、訪問者が同意したあとにピクセルを読み込めます。自社サイトではQRdxは何も制御できないため、署名付きのスキャンIDをURLに付けてサイトに渡し、訪問者がコンバージョンした時点でサイト側から報告してもらいます。

## すべてのコードで使える分析 [#analytics-on-every-code]

時間ごとのスキャン数、国、都市、デバイス、OS、ブラウザ、参照元に加えて、各コードの**分析**タブには次の情報が表示されます。

- **スキャンされる時間帯:** 時間帯別と曜日別のスキャン数。UTCまたはご自身のタイムゾーンで表示できます。
- **言語:** 各訪問者のブラウザの優先言語（ブラウザが送信しない場合は「不明」）。
- **A/B分割:** 各[A/B分割ルール](/docs/smart-routing#ab-tests)のバリアントごとのスキャン数。
- **ページのアクティビティ**（ホスト型ページ）: ページビュー数、ユニークビューア数、タップ数、最もタップされたリンクとボタン。
- **コンバージョン**（コードにある場合）。

<Shot id="when-people-scan" />

サイドバーの**コード** → **分析**では、ワークスペース内のすべてのコードを集計して表示します。合計、時間ごとのスキャン数、上位のコード、国、デバイス、言語、スキャン時間帯のほか、最大4つのコードを並べて比較できます。ボットやリンクプレビューはカウントされません。「ユニーク」は1日につき訪問者1人として数え、IPアドレスは保存されません。

## ホスト型ページのトラッキングピクセル [#tracking-pixels-on-hosted-pages-pro]

ホスト型ページを開くコードでは、コードの**設定**タブにある**トラッキングピクセル**パネルから、自分のタグをそのページに読み込めます。

| プロバイダー | IDの形式 |
| --- | --- |
| Google Analytics 4 | `G-` に続く4〜20文字の英数字 |
| Meta（Facebook）ピクセル | 6〜20桁の数字 |
| TikTokピクセル | 10〜30文字の英数字 |
| LinkedIn Insight Tag | パートナーID、3〜12桁の数字 |

<Shot id="pixels-panel" />

ピクセルは、設定した場合にのみ読み込まれます。ホスト型ページで読み込まれるスクリプトは、設定したピクセルを除けば、QRdx独自のページアクティビティカウンターだけです。このカウンターはビューとタップをQRdxにのみ報告し、他には送信しません。

<IfAvailable feature="customDomains">

**Google Tag Manager**（`GTM-` に続く4〜12文字の英数字）は、ページが[カスタムドメイン](/docs/custom-domains)のいずれかで開かれた場合にのみ読み込まれます。コンテナは任意のスクリプトを実行できるため、訪問者がQRdxにサインインしている可能性のあるqrdx.devでは実行されません。

</IfAvailable>

### 同意 [#consent]

ピクセルは、訪問者が同意するまで読み込まれません。

- **必要な地域（EU、EEA、英国、スイス、所在地不明）**（デフォルト）: これらの地域の訪問者と、所在地が不明な訪問者には、使用しているプロバイダー名を示す短いバナーが表示され、**同意する**か**拒否する**を選びます。選択はそのページごとに記憶され、**Cookie設定**から変更できます。それ以外の地域では、Global Privacy Controlシグナルを送信するブラウザを除き、ピクセルはすぐに読み込まれます。
- **すべての訪問者:** 全員に最初にバナーが表示されます。

プライバシーポリシーや、ピクセルが収集したデータの利用方法については、ご自身で責任を負っていただきます。自社サイトを直接開くコードは、そのままサイトに移動するため、ピクセルはサイト側に追加してください。

## コンバージョントラッキング [#conversion-tracking]

コンバージョントラッキングでは、どのスキャンが売上、登録、その他の目標につながったかを、収益とともに確認できます。自社サイトを開くコードで利用できます。

1. コードの**設定**タブで、**コンバージョントラッキング**をオンにします。以降、すべてのスキャンで、署名付きの `qrdx_sid` パラメータが付いたURL（例: `https://shop.example/?qrdx_sid=…`）が開きます。
2. 訪問者が最初に到達するページと、コンバージョンが発生するページにスニペットを追加します。

```html title="Your website (before </body>)"
<script async src="https://qrdx.dev/conversions.js"></script>
<script>
  window.qrdx = window.qrdx || function () {
    (window.qrdx.q = window.qrdx.q || []).push(arguments);
  };
  // Where the conversion happens, for example your order confirmation page:
  qrdx("conversion", { name: "purchase", value: 49.99, currency: "USD", id: "ORDER-1234" });
</script>
```

スクリプトは `qrdx_sid` をお使いのドメインのファーストパーティCookieに30日間保存し（ブラウザセッションの間だけ保持するには、scriptタグに `data-storage="session"` を追加します）、アドレスバーからは削除します。コンバージョンはスキャンから訪れた訪問者についてのみ送信されるため、それ以外の訪問者が追跡されることはありません。

| フィールド | 意味 |
| --- | --- |
| `name` | 何が起きたか。例: `purchase`、`signup`（デフォルトは `conversion`） |
| `value` | 金額。小数点以下2桁まで（任意） |
| `currency` | `USD` のようなISO 4217コード。値を指定した場合、デフォルトは `USD` |
| `id` | 注文IDまたはイベントID。同じIDを2回送信しても記録は1回だけです |
| `metadata` | 追加のキーと値のペア。最大20個（任意） |

### 制限 [#limits]

- スキャンは、発生から30日間、コンバージョンに紐付けられます。
- `qrdx_sid` は署名付きのため、推測したり、別のコードを指すように変更したりすることはできません。
- ブラウザからの報告には、そのコードでコンバージョントラッキングがオンになっている必要があり、1回のスキャンにつき1時間あたり最大10件のコンバージョンを報告できます。トークンを使ったサーバーからの報告には、どちらの制限もありません。
- ワークスペースがBusinessでなくなると、コンバージョンは記録されなくなります。既存のコンバージョンは分析に残り、トラッキングはいつでもオフにできます。

## 開発者向け [#for-developers]

バックエンドからコンバージョンを報告するほうが、ブラウザからより確実です。その場合は、`qrdx_sid` を注文と一緒に保存し、[APIキー](/docs/developers/api-keys)、または `codes:write` スコープを持つOAuthトークンを使って、[`POST /v1/conversions`](/docs/developers/api/create-conversion)を呼び出します。

```bash title="Terminal"
curl -X POST https://api.qrdx.dev/v1/conversions \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sid": "<qrdx_sid>", "name": "purchase", "value": 49.99, "currency": "USD", "id": "ORDER-1234"}'
```

APIは、新しいコンバージョンには `201` を返し、`id` がすでに記録されている場合は `"duplicate": true` とともに `200` を返します。トークンを使う場合、スキャンが不明なときは、`sid` の代わりに `"code": "<code id>"` を送信することもできます。
