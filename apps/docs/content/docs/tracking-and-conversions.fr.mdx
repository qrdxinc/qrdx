Chaque [QR code dynamique](/docs/dynamic-qr-codes) enregistre les scans sans cookies. Le suivi va plus loin sur deux points : charger vos propres pixels sur les pages hébergées qu'ouvrent vos codes, et attribuer des conversions, comme des achats sur votre site web, au scan qui a amené le visiteur. Utilisez-le lorsque le trafic des QR codes doit apparaître dans les outils que votre équipe utilise déjà, ou lorsque vous devez savoir quels codes rapportent de l'argent.

<Callout type="info" title="Pixels avec Pro, conversions avec Business">
  Les pixels de suivi font partie de Pro et de Business ; le suivi des conversions fait partie de Business. Les deux se configurent dans l'onglet **Paramètres** du code. Voir [Offres et limites](/docs/plans-and-limits).
</Callout>

Pressé ? [Consulter vos scans](/docs/help/dynamic-codes/scans) présente les statistiques disponibles avec toutes les offres.

## Fonctionnement [#how-it-works]

<Diagram id="tracking-paths" />

Un code ouvre soit une page hébergée, soit redirige vers votre site web, et chaque cas a son propre outil. Sur une page hébergée, QRdx contrôle le HTML et peut donc charger vos pixels une fois que le visiteur a donné son accord. Sur votre site web, QRdx ne contrôle rien : il transmet donc à votre site un identifiant de scan signé dans l'URL, et votre site fait remonter la conversion lorsque le visiteur convertit.

## Statistiques sur chaque code [#analytics-on-every-code]

Outre les scans dans le temps, les pays, les villes, les appareils, les systèmes d'exploitation, les navigateurs et les référents, l'onglet **Statistiques** de chaque code affiche :

- **Quand les gens scannent :** les scans par heure de la journée et par jour de la semaine, en UTC ou dans votre propre fuseau horaire.
- **Langues :** la langue préférée du navigateur de chaque visiteur (« Inconnu » lorsque le navigateur n'en envoie pas).
- **Répartition A/B :** les scans par variante pour chaque [règle de répartition A/B](/docs/smart-routing#ab-tests).
- **Activité de la page** (pages hébergées) : pages vues, visiteurs uniques, taps, ainsi que les liens et boutons les plus touchés.
- **Conversions**, si le code en a.

<Shot id="when-people-scan" />

**Codes** → **Statistiques** dans la barre latérale additionne tous les codes de l'espace de travail : totaux, scans dans le temps, meilleurs codes, pays, appareils, langues, heures de scan, et une comparaison côte à côte de jusqu'à 4 codes. Les robots et les aperçus de liens ne sont pas comptés, un visiteur compte une fois par jour pour les « uniques », et les adresses IP ne sont jamais stockées.

## Pixels de suivi sur les pages hébergées [#tracking-pixels-on-hosted-pages-pro]

Pour les codes qui ouvrent une page hébergée, le panneau **Pixels de suivi** de l'onglet **Paramètres** du code charge vos propres balises sur cette page :

| Fournisseur | Format de l'identifiant |
| --- | --- |
| Google Analytics 4 | `G-` suivi de 4 à 20 lettres et chiffres |
| Pixel Meta (Facebook) | 6 à 20 chiffres |
| Pixel TikTok | 10 à 30 lettres et chiffres |
| LinkedIn Insight Tag | Identifiant partenaire, 3 à 12 chiffres |

<Shot id="pixels-panel" />

Les pixels ne se chargent que si vous les configurez. Outre vos pixels, le seul script d'une page hébergée est le compteur d'activité de page de QRdx, qui signale les vues et les taps à QRdx et à personne d'autre.

<IfAvailable feature="customDomains">

**Google Tag Manager** (`GTM-` suivi de 4 à 12 lettres et chiffres) ne se charge que lorsque la page s'ouvre sur l'un de vos [domaines personnalisés](/docs/custom-domains). Un conteneur peut exécuter n'importe quel script : il ne s'exécute donc jamais sur qrdx.dev, où les visiteurs peuvent être connectés à QRdx.

</IfAvailable>

### Consentement [#consent]

Les pixels ne se chargent jamais avant l'accord du visiteur :

- **Là où c'est requis (UE, EEE, Royaume-Uni, Suisse, lieu inconnu)**, option par défaut : les visiteurs de ces zones, et ceux dont le lieu est inconnu, voient un court bandeau citant vos fournisseurs et choisissent **Accepter** ou **Refuser**. Le choix est mémorisé pour cette page, et **Paramètres des cookies** permet de le modifier. Ailleurs, les pixels se chargent immédiatement, sauf pour les navigateurs qui envoient le signal Global Privacy Control.
- **Pour tous les visiteurs :** tout le monde voit d'abord le bandeau.

Vous restez responsable de votre propre politique de confidentialité et de l'usage que vous faites des données collectées par vos pixels. Les codes qui ouvrent directement votre site web y redirigent immédiatement : ajoutez donc vos pixels à votre site.

## Suivi des conversions [#conversion-tracking]

Le suivi des conversions vous indique quels scans ont mené à une vente, une inscription ou tout autre objectif, avec le chiffre d'affaires. Il fonctionne pour les codes qui ouvrent votre site web.

1. Dans l'onglet **Paramètres** du code, activez **Suivi des conversions**. Chaque scan ouvre alors votre URL avec un paramètre `qrdx_sid` signé ajouté, par exemple `https://shop.example/?qrdx_sid=…`.
2. Ajoutez l'extrait de code aux pages d'arrivée des visiteurs et à la page où ils convertissent :

```html title="Your website (before </body>)"
<script async src="https://qrdx.dev/conversions.js"></script>
<script>
  window.qrdx = window.qrdx || function () {
    (window.qrdx.q = window.qrdx.q || []).push(arguments);
  };
  // Where the conversion happens, for example your order confirmation page:
  qrdx("conversion", { name: "purchase", value: 49.99, currency: "USD", id: "ORDER-1234" });
</script>
```

Le script mémorise `qrdx_sid` dans un cookie first-party sur votre domaine pendant 30 jours (ajoutez `data-storage="session"` à la balise script pour ne le conserver que pour la session du navigateur) et le retire de la barre d'adresse. Les conversions ne sont envoyées que pour les visiteurs venus d'un scan : les autres visiteurs ne sont donc jamais suivis.

| Champ | Signification |
| --- | --- |
| `name` | Ce qui s'est produit, par exemple `purchase` ou `signup` (par défaut `conversion`) |
| `value` | Montant, avec jusqu'à 2 décimales (facultatif) |
| `currency` | Code ISO 4217 comme `USD` ; `USD` par défaut lorsqu'une valeur est fournie |
| `id` | Votre identifiant de commande ou d'événement : envoyer deux fois le même identifiant ne l'enregistre qu'une fois |
| `metadata` | Jusqu'à 20 paires clé/valeur supplémentaires (facultatif) |

### Limites [#limits]

- Un scan peut être attribué pendant 30 jours après qu'il a eu lieu.
- `qrdx_sid` est signé : il ne peut donc pas être deviné ni modifié pour pointer vers un autre code.
- Les rapports envoyés depuis le navigateur exigent que le suivi des conversions soit activé pour le code, et chaque scan peut signaler jusqu'à 10 conversions par heure. Les rapports envoyés depuis votre serveur avec un jeton n'ont aucune de ces deux limites.
- Les conversions cessent d'être enregistrées si l'espace de travail quitte Business ; celles qui existent restent dans vos statistiques, et il est toujours possible de désactiver le suivi.

## Limites et offres [#limits-and-plans]

| | Gratuit | Pro | Business |
| --- | --- | --- | --- |
| Statistiques de scan, heures de scan, langues, activité de la page | Oui | Oui | Oui |
| Pixels de suivi sur les pages hébergées | Non | Oui | Oui |
| Suivi des conversions | Non | Non | Oui |

## Pour les développeurs [#for-developers]

Pour signaler les conversions depuis votre backend, ce qui est plus fiable que depuis le navigateur, conservez `qrdx_sid` avec la commande et appelez [`POST /v1/conversions`](/docs/developers/api/create-conversion) avec une [clé API](/docs/developers/api-keys) ou un jeton OAuth disposant de la portée `codes:write` :

```bash title="Terminal"
curl -X POST https://api.qrdx.dev/v1/conversions \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sid": "<qrdx_sid>", "name": "purchase", "value": 49.99, "currency": "USD", "id": "ORDER-1234"}'
```

L'API répond `201` pour une nouvelle conversion et `200` avec `"duplicate": true` lorsque l'`id` a déjà été enregistré. Avec un jeton, vous pouvez aussi envoyer `"code": "<code id>"` à la place de `sid` lorsque le scan n'est pas connu.
