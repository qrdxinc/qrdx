Ao final desta página, uma URL sob seu controle recebe um `POST` assinado poucos minutos depois de cada evento escolhido, seu servidor verifica que cada requisição veio do QRdx e você sabe como funcionam as novas tentativas, as duplicatas e o registro de entregas.

Os webhooks enviam eventos de um workspace para o seu servidor assim que acontecem: atualizar um CRM quando alguém preenche um formulário, avisar uma ferramenta interna quando um código passa de 1.000 leituras ou manter sua própria cópia dos dados de leitura.

<Callout type="info" title="Plano Business">
Webhooks, hooks do Zapier e do Make e alertas no Slack e no Discord fazem parte do plano **Business**. Alertas por e-mail e o resumo semanal fazem parte do Pro; veja [Notificações](/docs/notifications). Compare os planos em [Planos e limites](/docs/plans-and-limits).
</Callout>

## Antes de começar [#before-you-start]

- Uma URL pública `https://` que responda a requisições `POST`. Endereços IP, `localhost` e nomes de host que resolvem para redes privadas são recusados, e redirecionamentos não são seguidos. Para desenvolvimento local, use um túnel que forneça um nome de host público.
- Função de proprietário ou administrador no workspace. Membros podem ver os endpoints e seus registros de entrega, mas não adicionar nem alterar.

## 1. Adicione um endpoint [#1-add-an-endpoint]

1. Abra [Configurações → Webhooks](/dashboard?to=settings/webhooks) no workspace cujos eventos você quer. O link abre o último workspace que você usou; escolha outro no seletor de workspace e você continua na mesma página.
2. Escolha **Adicionar endpoint**, informe a **URL do endpoint** e marque os **Eventos** desejados, depois escolha **Adicionar endpoint** na caixa de diálogo. Antes disso, o QRdx pede que você [confirme que é você](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), e pede de novo sempre que você muda a URL de um endpoint; mudar os eventos ou desativá-lo não pede.
3. Copie o **Segredo de assinatura** exibido depois de salvar. Proprietários e administradores podem exibi-lo de novo, ou rotacioná-lo, na página **Entregas** do endpoint.
4. Escolha **Enviar teste**. O QRdx envia um evento `ping` assinado e mostra o status da resposta no registro de entregas.

## 2. Escolha os eventos [#2-pick-the-events]

| Evento | Quando | Observações |
| --- | --- | --- |
| `scan.created` | Um código dinâmico é lido | Em lote: no máximo uma requisição por minuto por endpoint, com até 100 leituras e o `count` exato |
| `scan.milestone` | A 1ª leitura de um código, depois 10, 100, 500, 1.000, 5.000, 10.000, 50.000, 100.000, 500.000 e 1.000.000 de leituras, e então a cada milhão | Dispara uma vez por marco |
| `code.created` | Um código dinâmico é criado, no painel ou pela API | Um evento por código, também na criação em massa |
| `code.updated` | O destino, o título, o design ou o domínio do link curto de um código muda | `changes` lista os campos |
| `form.submitted` | Alguém envia um formulário em uma página hospedada | Inclui as respostas |
| `ping` | Você escolhe **Enviar teste** | |

Leituras feitas por bots, pré-visualizações de links e prefetchers, e repetições rápidas de um mesmo visitante, não são contadas e não disparam eventos, exatamente como nas [análises de leitura](/docs/dynamic-qr-codes#scan-analytics).

## 3. Leia o payload [#payloads]

Toda requisição é um `POST` com corpo JSON e estes cabeçalhos:

| Cabeçalho | Valor |
| --- | --- |
| `Content-Type` | `application/json` |
| `User-Agent` | `QRdx-Webhooks/1.0 (+https://qrdx.dev/docs/webhooks)` |
| `X-QRdx-Event` | O tipo do evento, como `code.created` |
| `X-QRdx-Delivery` | ID da entrega: o mesmo em cada nova tentativa, para você ignorar duplicatas |
| `X-QRdx-Timestamp` | Segundos Unix em que esta tentativa foi assinada |
| `X-QRdx-Signature` | `t=<timestamp>,v1=<hex HMAC-SHA256>` |

O corpo é sempre um envelope com `id`, `type`, `created_at` e `data`:

```json title="code.created"
{
  "id": "evt_cm3x8c1a20001",
  "type": "code.created",
  "created_at": "2026-10-31T09:30:00.000Z",
  "data": {
    "code": {
      "id": "cm3x7q2l40000",
      "slug": "aB3dE5f",
      "title": "Spring menu",
      "short_link": "https://qrdx.dev/q/aB3dE5f",
      "destination_url": "https://example.com/menu",
      "status": "active",
      "scan_count": 0,
      "created_at": "2026-10-31T09:30:00.000Z",
      "updated_at": "2026-10-31T09:30:00.000Z"
    },
    "actor_id": "user_123"
  }
}
```

Um lote `scan.created`:

```json title="scan.created"
{
  "id": "evt_cm3x9d0b10002",
  "type": "scan.created",
  "created_at": "2026-10-31T09:31:00.000Z",
  "data": {
    "window_started_at": "2026-10-31T09:31:00.000Z",
    "window_seconds": 60,
    "count": 2,
    "scans": [
      {
        "scan_id": "cm3x9d0b00001",
        "code": { "id": "cm3x7q2l40000", "slug": "aB3dE5f", "title": "Spring menu" },
        "scanned_at": "2026-10-31T09:31:00.000Z",
        "country": "DE",
        "region": "BE",
        "city": "Berlin",
        "device_type": "mobile",
        "os": "iOS",
        "browser": "Safari",
        "referer": null,
        "source": "qr"
      }
    ]
  }
}
```

Quando chegam mais de 100 leituras em um minuto, `scans` traz as primeiras 100 e `count` o total exato. `source` é `nfc` para um toque em uma [tag NFC](/docs/nfc) e `qr` para uma leitura de QR code. Os payloads de leitura nunca incluem endereços IP nem hashes de visitantes.

Os outros eventos trazem:

- `scan.milestone`: `milestone`, `code` (`id`, `slug`, `title`, `scan_count`) e o `scan` que atingiu o marco.
- `code.updated`: como `code.created`, mais `changes`, como `["destination_url"]`.
- `form.submitted`: `response_id`, `page` (`id`, `title`), `code` (`id`, `slug`, ou `null`), `fields` (`name`, `label`, `value` como texto) e `submitted_at`.

Para ver um payload de cada evento montado com seus próprios dados antes de o primeiro real chegar, chame [Get sample events](/docs/developers/api/get-hook-samples):

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/hooks/sample?event=scan.created" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

## 4. Verifique as assinaturas [#verify-signatures]

Calcule um HMAC-SHA256 de `<timestamp>.<raw body>` com seu segredo de assinatura e compare com o `v1` de `X-QRdx-Signature`. Use o corpo bruto da requisição, antes de qualquer parsing de JSON, e rejeite timestamps com mais de cinco minutos.

```ts title="lib/qrdx-webhook.ts"
import { createHmac, timingSafeEqual } from "node:crypto";

export function isFromQRdx(rawBody: string, header: string, secret: string) {
  const parts = Object.fromEntries(
    header.split(",").map((part) => part.trim().split("=", 2)),
  );
  const timestamp = Number(parts.t);
  if (!timestamp || Math.abs(Date.now() / 1000 - timestamp) > 300) return false;

  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const received = Buffer.from(parts.v1 ?? "");
  return (
    received.length === expected.length &&
    timingSafeEqual(received, Buffer.from(expected))
  );
}
```

```python title="qrdx_webhook.py"
import hmac
import hashlib
import time


def is_from_qrdx(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(part.strip().split("=", 1) for part in header.split(","))
    timestamp = int(parts.get("t", "0"))
    if not timestamp or abs(time.time() - timestamp) > 300:
        return False
    expected = hmac.new(
        secret.encode(), f"{timestamp}.".encode() + raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(parts.get("v1", ""), expected)
```

A rotação do segredo tem efeito imediato: o segredo antigo deixa de ser verificado, então atualize seu servidor logo depois de rotacionar.

## 5. Responda e trate as novas tentativas [#5-respond-and-handle-retries]

Responda com qualquer status `2xx` em até 10 segundos. Qualquer outra coisa (um status de erro, um redirecionamento, um timeout, um host inacessível) conta como falha, e o QRdx tenta de novo com esperas crescentes de cerca de 1 minuto, 4 minutos, 16 minutos, 1 hora, 4 horas, 17 horas e 24 horas. Cada nova tentativa sai poucos minutos depois do fim da espera. São 8 tentativas ao longo de cerca de dois dias, e depois disso a entrega é marcada como falha.

As entregas podem chegar mais de uma vez (uma nova tentativa após uma resposta lenta, uma nova tentativa manual) e fora de ordem. Use `X-QRdx-Delivery` ou o `id` do envelope para ignorar duplicatas e faça o seu trabalho depois de responder `2xx` se ele levar mais do que alguns segundos.

## Altere depois [#change-it-later]

A página **Entregas** de cada endpoint lista as últimas 50 entregas com evento, status, tentativas e payload. **Tentar agora** reenvia de imediato uma entrega que falhou ou está pendente; **Enviar de novo** reenvia uma já entregue. As entregas são mantidas por 30 dias.

<Shot id="webhook-deliveries" />

No menu de um endpoint você pode **Editar** a URL e os eventos, **Desativar endpoint** (as novas entregas param; **Ativar endpoint** as retoma), exibir ou **Rotacionar** o **Segredo de assinatura** e **Excluir** o endpoint, o que também apaga o registro dele. Se o plano de um workspace deixar de incluir webhooks, os endpoints são mantidos, mas nada é enviado até que ele volte ao Business. Seus QR codes continuam funcionando de qualquer forma.

## Zapier, Make e n8n (REST Hooks) [#zapier-make-and-n8n-rest-hooks]

Ferramentas de automação podem assinar e cancelar a assinatura por conta própria pela API de REST Hooks. Autentique com uma [chave de API](/docs/developers/api-keys) ou um token de acesso OAuth: `codes:write` para assinar ou cancelar, `codes:read` para listar. As URLs de hook costumam ser secretas, então apenas com `codes:read` o `target_url` mostra só o host (`https://hooks.zapier.com`). Requisições com token agem no seu próprio workspace; uma chave age no workspace em que foi criada. Assinar com a sessão do seu navegador pede antes que você [confirme que é você](/docs/help/privacy-and-security/two-step-verification#confirm-its-you) e responde `403 CONFIRMATION_REQUIRED` até que você tenha confirmado nos últimos 10 minutos. As assinaturas são endpoints comuns: aparecem em **Configurações → Webhooks**, onde você também pode removê-las.

| Método | Caminho | Descrição |
| --- | --- | --- |
| `POST` | `/v1/hooks` | Assina. Corpo: `target_url` (ou `hookUrl` do Zapier) e `event` (ou um array `events`). Retorna `201` com o `id` da assinatura e seu `secret` |
| `DELETE` | `/v1/hooks/{id}` | Cancela a assinatura (`204`) |
| `GET` | `/v1/hooks` | Lista assinaturas e endpoints |
| `GET` | `/v1/hooks/{id}` | Uma assinatura |
| `GET` | `/v1/hooks/sample?event=<event>` | Exemplos recentes de payload para `event`, como um array ("perform list" do Zapier) |

```bash title="Terminal"
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://hooks.zapier.com/hooks/standard/123/abc/", "event": "form.submitted"}'
```

```json title="201 Created (fields)"
{
  "id": "<hook id>",
  "target_url": "https://hooks.zapier.com/hooks/standard/123/abc/",
  "events": ["form.submitted"],
  "event": "form.submitted",
  "active": true,
  "created_at": "<ISO 8601 time>",
  "secret": "whsec_<shown only here>"
}
```

Sem o Business, a chamada de assinatura retorna `402`:

```json title="402 Payment Required"
{"code":"PLAN_REQUIRED","message":"Webhooks and Zapier/Make hooks are part of the Business plan.","status":402}
```

Uma entrega `scan.created` é um lote, então no Zapier use os itens de linha `data.scans` para agir em cada leitura. No n8n, o nó QRdx Trigger dos [nós QRdx para n8n](/docs/developers/n8n) faz essas chamadas por você e confere cada assinatura; um nó Webhook simples também funciona, configurado como qualquer outro endpoint. As páginas de referência são [Subscribe to events](/docs/developers/api/create-hook), [List hooks](/docs/developers/api/list-hooks) e [Unsubscribe](/docs/developers/api/delete-hook).

## Se algo der errado [#if-something-goes-wrong]

### A URL do endpoint é recusada [#the-endpoint-url-is-refused]

Só são aceitos nomes de host públicos com `https://`: nada de `http://`, endereços IP, `localhost` ou nomes que resolvam para uma rede privada. Durante o desenvolvimento, use um túnel com um nome de host público.

### Toda entrega aparece com status de falha [#every-delivery-shows-a-failed-status]

Seu servidor respondeu algo diferente de `2xx` em até 10 segundos, redirecionou ou não respondeu. Abra os detalhes da entrega para ver o status HTTP ou o erro exato, corrija o problema e escolha **Retry now**. Se o seu handler for lento, responda `2xx` primeiro e processe depois.

### As assinaturas não são verificadas [#signatures-dont-verify]

Confira se você está calculando o hash do corpo bruto da requisição, e não de um objeto JSON serializado de novo, e se o seu servidor usa o segredo atual: ao rotacionar o segredo, o antigo deixa de valer na hora. Verifique também o relógio do servidor, já que a verificação do timestamp permite cinco minutos de diferença.

### Os eventos pararam de chegar [#events-stopped-arriving]

O workspace saiu do plano Business (os endpoints são mantidos, mas ficam pausados), o endpoint está **Disabled**, ou o Zap, o cenário ou o workflow que criou a assinatura foi desativado e cancelou a assinatura. Confira em **Settings → Webhooks**.

### `403 CONFIRMATION_REQUIRED` em `POST /v1/hooks` [#403-confirmation_required-from-post-v1hooks]

Você fez a assinatura com uma sessão do navegador. Confirme que é você no QRdx e tente de novo em até 10 minutos, ou faça a assinatura com uma chave de API a partir do seu servidor.

## Hospedagem própria [#self-hosting]

As entregas são enviadas na hora; as novas tentativas e os lotes de leituras cujo minuto já terminou são enviados por um job agendado. O QRdx executa esse job a cada 5 minutos a partir de um workflow do GitHub Actions, que funciona no plano Hobby grátis da Vercel, e o `apps/app/vercel.json` também o executa por completo uma vez por dia. O GitHub pode iniciar execuções agendadas com atraso, então espere as novas tentativas em alguns minutos, e não no minuto exato.

Para fazer o mesmo, copie `.github/workflows/webhook-worker.yml`, adicione seu `CRON_SECRET` como secret do Actions e a URL do seu job como a variável `WEBHOOK_WORKER_URL`. Ou chame o job a partir de qualquer agendador com o `CRON_SECRET` que você definiu no ambiente:

```bash title="crontab (every 1 to 5 minutes)"
curl -H "Authorization: Bearer $CRON_SECRET" https://your-host/api/cron/webhooks
```

Com `?source=github` adicionado à URL, o job primeiro consulta um pequeno marcador no Upstash Redis e retorna `{"skipped": true}` sem consultar o banco de dados quando não há nada pendente, para que um banco que escala até zero possa continuar dormindo (sem o Upstash, ele sempre executa o job completo). Mantenha uma chamada por dia sem esse parâmetro: essa execução sempre faz o job completo e repara o marcador. Os outros jobs agendados estão listados em [Hospedagem própria](/docs/self-hosting#scheduled-jobs).
