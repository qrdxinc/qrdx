每个[动态二维码](/docs/dynamic-qr-codes)都会根据网络信息记录每次扫描的国家、地区和城市。精确位置则更进一步：二维码会请扫描者分享自己的位置，允许的用户会在分析中显示为四舍五入到约 100 m 的点，[智能路由](/docs/smart-routing)也可以根据他们所在的位置把他们送到不同的地方。它适用于场地、门店或步道等现场使用的二维码，这类场景只知道“哪个城市”是不够的。

<Callout type="info" title="Pro 和 Business">
  请求精确位置属于 Pro 和 Business 的功能。所有二维码默认关闭，需要你手动开启，而且每位扫描者都在自己的浏览器中自行决定是否分享。请参阅[套餐与限制](/docs/plans-and-limits)。
</Callout>

赶时间？[查看你的扫描数据](/docs/help/dynamic-codes/scans)介绍了分析功能，[将扫描发送到不同链接](/docs/help/dynamic-codes/routing)介绍了规则。

## 工作原理 [#how-it-works]

<Diagram id="precise-location-flow" />

开启该设置后，有人扫描二维码时，浏览器会询问是否分享位置。如果用户允许，浏览器会在发送前把位置四舍五入到小数点后 3 位（约 100 m），QRdx 会再次取整，然后这个点会连同浏览器报告的精度一起与该次扫描存储。精确的位置信息永远不会到达 QRdx。如果用户跳过或拒绝，这次扫描仍会照常计数，并记录来自网络的国家、地区和城市。

## 开启方式 [#turn-it-on]

从[二维码](/dashboard?to=codes)中打开该二维码，进入它的**设置**标签页，在**精确位置**面板中打开**请扫描者提供精确位置**。它适用于打开网站链接的二维码，也适用于打开托管页面的二维码。

## 扫描者看到的内容 [#what-scanners-see]

**打开网站链接的二维码**会在链接打开前显示一个简短的“分享你的位置？”步骤，提供**允许**和**跳过**两个选项。点击允许会弹出浏览器自带的位置请求。这一步绝不会阻止任何人访问你的链接：

- 点击跳过会立即打开链接。
- 如果扫描者在浏览器中拒绝，或者浏览器无法获取位置，链接会打开。
- 如果在点击允许 8 秒后仍没有位置信息，链接也会打开。
- 如果浏览器已对该网站选择过拒绝，会自动跳过这一步；如果已选择过允许，则无需再点一次就会直接分享。
- 没有 JavaScript 时，链接会立即打开。

这一步会注明扫描者将要访问的网站，并附有隐私政策的链接。

**打开托管页面的二维码**会像往常一样立即打开页面。页面加载完成后，浏览器会在页面上请求位置；页面不会等待回应。它只会在扫描之后立即请求，当有人直接输入页面地址打开时不会请求。

关闭该设置后，一切照旧：扫描会直接跳转到目标，不会有额外步骤。

## 在分析中查看 [#in-analytics]

二维码的**分析**标签页中有一张**精确位置**卡片，与基于 IP 的国家和城市分开显示。它会显示被询问的扫描者人数、分享了位置的人数及其占比，然后列出每个已分享的点，包括其扫描次数、平均精度和最近一次扫描。你可以按其中任意一项对表格排序，并在 OpenStreetMap 中打开某个点，查看它的位置。

CSV 导出包含 `latitude`、`longitude`、`location_accuracy_m` 和 `location_source` 列。`location_source` 的值为：扫描者分享了位置时是 `gps`；二维码请求了位置但扫描者没有分享时是 `ip`；二维码没有请求位置时为空。

共享的分析链接（二维码菜单中的**分享分析...**）从不显示精确位置，只显示到国家级别。精确位置的保留时间与该二维码其余扫描数据相同，你能回溯查看多久则取决于你的套餐。请参阅[有人扫描时 QRdx 会记录什么](/docs/help/privacy-and-security/scan-data)。

## 按区域路由扫描 [#route-scans-by-area]

在二维码的**智能路由**面板中，添加一条带有**区域**条件的规则：设置一个中心点和一个 100 m 到 500 km 之间的半径。要获得中心点，可以在地图应用中右键点击某个地点并复制其坐标（例如 `40.7580, -73.9855`），或者身处现场时点击**使用我的位置**。**在地图上查看**会在 OpenStreetMap 中打开该点。

QRdx 会使用它为该次扫描掌握的最佳位置来判断区域：

1. 扫描者在该步骤中分享的位置，前提是精确位置已开启且对方允许。
2. 否则，使用其 IP 地址的大致位置。在 qrdx.dev 上，这来自 Vercel 的 IP 地理定位，通常是扫描者所在城市或区域的中心，因此适合几公里的半径。它只用于路由该次扫描，不会被存储。

当两者都不可用时，区域条件不匹配，而“不在”区域的条件会匹配。**测试你的规则**中有一个**位置（用于区域）**字段，因此你可以检查从任意一点发起的扫描会跳转到哪里。

### 仅限区域内 [#only-inside-an-area]

若要只向身处某地的人展示内容，例如场地或门店：

1. 添加一条规则，在该地点周围设置区域条件，并将其 URL 设为面向现场人员的内容。
2. 将二维码的主目标设为面向其他所有人的页面，例如一个说明优惠仅限现场享受的页面。

同时开启精确位置，这样扫描者分享的位置就会起决定作用，精确到约 100 m。不开启的话，则由 IP 位置决定，只能精确到城市级别。

浏览器允许用户伪造位置，因此区域规则并不是访问控制。对于必须保密的内容，请使用[密码](/docs/code-controls#password)。

## 须知 [#good-to-know]

- 机器人、链接预览和 HEAD 请求永远不会看到这一步，它们会得到常规的重定向。
- 对设置了密码的二维码，显示密码表单的那次扫描会跳过这一步。浏览器解锁后，它之后的扫描会和其他扫描一样被询问。
- 如果你的工作区降级为免费版，QRdx 将停止请求精确位置。已保存的区域规则会继续使用 IP 位置生效，而关闭该设置从不需要特定套餐。

## 面向开发者 [#for-developers]

发送带有 `{"preciseLocation": true}` 的 `PATCH /v1/codes/{id}` 即可开启该步骤；每个二维码都会在其 `preciseLocation` 字段中返回该设置（[更新二维码](/docs/developers/api/update-code)）。[`GET /v1/codes/{id}/scans`](/docs/developers/api/get-code-scans) 会在列出的每次扫描中返回 `latitude`、`longitude`、`locationAccuracyM` 和 `locationSource`，并附带一个 `preciseLocations` 汇总。

## 自托管 [#self-hosting]

未在 Vercel 上运行的自托管副本没有 IP 坐标，因此那里的区域规则只会匹配带有已分享位置的扫描。请参阅[自托管](/docs/self-hosting#what-is-different-from-qrdxdev)。
