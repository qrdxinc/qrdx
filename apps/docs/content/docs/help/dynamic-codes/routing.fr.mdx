title: "Rediriger les scans vers différents liens"
description: "Redirigez chaque scan selon l'appareil, le pays, la zone, la langue ou l'heure, et lancez des tests A/B grâce au routage intelligent."
---

Le routage intelligent envoie chaque scan d'un QR code dynamique vers un lien différent, selon les règles que vous définissez : les iPhone vers l'App Store, les visiteurs en France vers la page en français, les scans après l'heure de fermeture vers un formulaire de commande. Cette page vous mène jusqu'à une règle fonctionnelle ; le [guide du routage intelligent](/docs/smart-routing) détaille chaque condition.

<Callout type="info">
  Le routage intelligent fait partie de Pro et Business, et fonctionne avec les codes qui ouvrent un lien de site web. Consultez [Les offres et ce qu'elles incluent](/docs/help/account-and-billing/plans).
</Callout>

## Ajouter une règle [#add-a-rule]

### 1. Ouvrir le routage intelligent [#1-open-smart-routing]

Ouvrez le code depuis **Codes**, allez dans son onglet **Paramètres**, puis ouvrez **Routage intelligent**.

### 2. Commencer une règle [#2-start-a-rule]

Cliquez sur **Ajouter une règle**. Sous **Partir de**, choisissez un modèle ou **Règle vide**.

### 3. Définir les conditions et le lien [#3-set-the-conditions-and-the-link]

Choisissez les conditions qu'un scan doit remplir, ainsi que le lien qu'ouvrent les scans correspondants.

### 4. Enregistrer [#4-save]

Cliquez sur **Enregistrer les règles**. Les scans qui ne correspondent à aucune règle ouvrent la destination habituelle du code.

## Conditions disponibles [#conditions-you-can-use]

**Appareil**, **Système d'exploitation**, **Pays**, **Région**, **Zone**, **Langue**, **Heure de la journée**, **Période** et **Nombre de scans**. Cochez **n'est pas** pour inverser une condition.

Une **Zone** est un point associé à un rayon. Elle utilise la position partagée par la personne qui scanne lorsque la [localisation précise](/docs/precise-location) est activée, et sinon la position approximative de son réseau.

Une règle peut comporter jusqu'à 8 conditions. Un code peut avoir jusqu'à 20 règles.

## Modèles [#templates]

- **Lien d'application intelligent (App Store / Google Play)** : les iPhone vers l'App Store, les téléphones Android vers Google Play.
- **Pays** et **Langue du visiteur**.
- **Heures d'ouverture**.
- **Période (campagne)**.
- **Premiers scans** : un lien différent pour les premiers scans.
- **Dans une zone (geofence)** : un lien différent pour les scans près d'un lieu.
- **Répartition A/B** : répartit les scans entre 2 à 5 versions.

## La première règle correspondante l'emporte [#the-first-matching-rule-wins]

Les règles sont vérifiées de haut en bas. Placez les règles les plus spécifiques en premier.

Ouvrez **Tester vos règles (utilise les modifications non enregistrées)** et cliquez sur **Lancer le test** pour voir où irait un scan avant d'enregistrer.

## Tests A/B [#ab-tests]

Une répartition A/B envoie chaque visiteur vers une version. Chaque visiteur conserve sa version pendant la journée. L'onglet **Analytique** du code montre comment les scans se répartissent entre les versions.

## Après un passage à une offre inférieure [#after-a-downgrade]

Les règles enregistrées continuent de fonctionner. Pour les modifier à nouveau, il faut Pro ou Business.

## En cas de problème [#if-something-goes-wrong]

### Le routage intelligent n'apparaît pas dans les paramètres [#smart-routing-isnt-in-settings]

Le code ouvre une page hébergée. Le routage est réservé aux codes qui ouvrent un lien de site web ; changez d'abord le type. Consultez [Modifier ce qu'ouvre un code imprimé](/docs/help/dynamic-codes/change-the-type).

### Un scan a été redirigé vers le mauvais lien [#a-scan-went-to-the-wrong-link]

Une règle située plus haut a correspondu en premier. Réorganisez les règles, puis vérifiez avec **Lancer le test**. Consultez [Un code ouvre la mauvaise page](/docs/help/troubleshooting/wrong-destination).

### Une règle de zone ignore des personnes qui s'y trouvent [#an-area-rule-misses-people-who-are-there]

Sans localisation précise, QRdx ne connaît que la position approximative du réseau de la personne, qui peut se situer à une ville de distance. Activez **Demander la localisation précise aux personnes qui scannent** pour le code, ou élargissez le rayon.
