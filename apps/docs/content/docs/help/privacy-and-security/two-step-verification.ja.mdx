2段階認証（2FAとも呼ばれます）は、サインインに2つ目のステップを追加する機能です。メールコード、Google、GitHub<IfAvailable feature="sso">（またはワークスペースのシングルサインオン）</IfAvailable>でサインインしたあと、QRdx は<IfAvailable feature="passkeys">パスキーまたは</IfAvailable>認証アプリの6桁のコードを求めます。メールや Google アカウントに不正にアクセスされても、これがなければ QRdx にはサインインできません。

<IfAvailable feature="passkeys">

[パスキー](/docs/help/privacy-and-security/passkeys)は、指紋、顔、画面ロック、セキュリティキーのいずれかで本人確認を行います。QRdx 自身のサイトでしか動作しないため、偽サイトに情報を盗まれることはありません。

</IfAvailable>

認証アプリも使えます。30秒ごとに変わる6桁のコードを表示するアプリであればどれでも使え、多くのパスワードマネージャーのワンタイムコード機能も含まれます。QRdx は、2段階目のコードをメールやテキストメッセージでは送信しません。

両方を設定しておき、サインインのときに手元にある方を使うこともできます。

## オンにする [#turn-it-on]

1. **設定** → **プロフィールとセキュリティ**に移動します。
2. **2段階認証**で**オンにする**をクリックし、[本人確認](#confirm-its-you)を行います。
3. 以下の手順で、2段階目を設定します<IfAvailable feature="passkeys">。**パスキー**または**認証アプリ**を選びます</IfAvailable>。
4. 10個のバックアップコードを保存します。コピーするかテキストファイルとしてダウンロードし、パスワードマネージャーなど安全な場所に保管してください。QRdx が表示するのは一度だけです。**バックアップコードを保存しました**にチェックを入れ、**完了**をクリックします。

<Shot id="two-step-card" />

<IfAvailable feature="passkeys">

パスキーの場合は、提案された名前（「Chrome on macOS」のようなブラウザーとシステムの名前）をそのまま使うか、任意の名前を入力して**続ける**をクリックし、ブラウザーにパスキーを保存させます。

</IfAvailable>

認証アプリの場合は、アプリで QR コードをスキャンするか、その下に表示されるキーを入力します。アプリに表示された6桁のコードを入力し、**確認**をクリックします。

これで2段階認証がオンになり、アカウントにサインインしている他のすべてのブラウザーとデバイスはサインアウトされます。それぞれ、2段階目を使って再度サインインする必要があります。オンにしたブラウザーはサインインしたままです。<IfAvailable feature="passkeys"> もう一方の方法を後から追加するには、同じセクションを使います。すでにあるバックアップコードはそのまま使え、サインアウトされる人もいません。</IfAvailable>

<IfAvailable feature="passkeys">

2段階認証がパスキーに対応する前にパスキーを追加していた場合、設定に**パスキーを2段階目として使用できます**と表示されます。**オンにする**をクリックして本人確認を行い、そのパスキーで本人であることを確認して、バックアップコードを保存します。この操作でも、他のデバイスはサインアウトされます。

</IfAvailable>

2段階認証をオンまたはオフにしたとき、方法を追加または削除したとき、新しいバックアップコードを作成したとき、バックアップコードを使用したときは、アカウントのアドレスにメールでお知らせします。サポートに2段階認証をオフにするよう依頼した場合も、メールでお知らせします。

## 2段階認証でサインインする [#sign-in-with-it]

いつもどおりにサインインします。そのあと QRdx が2段階目を求めます。

<IfAvailable feature="passkeys">

パスキーがある場合は、ブラウザーのパスキー画面が自動的に開きます。ブラウザーによっては、クリックしないと開かないことがあります。その場合は**パスキーで続ける**をクリックしてください。画面を閉じた場合やタイムアウトした場合は、もう一度試すか、別の方法を選びます。

</IfAvailable>

ステップの下にある**認証コードを使用**と**バックアップコードを使用**で、利用できる他の方法に切り替えられます。QRdx はこのブラウザーで最後に使った方法を記憶し、次回はそれから始めます。

認証コードは30秒ごとに変わります。拒否された場合は、次のコードを待ってください。

各サインインのステップで間違えられるコードは5回までです<IfAvailable feature="passkeys">。パスキーの検証に失敗した場合も1回と数えます</IfAvailable>。超えた場合は、サインインを最初からやり直してください。連続して10回間違えると、QRdx は15分間、そのアカウントへのコードを受け付けなくなります。

このステップは10分で期限切れになります。期限が切れた場合は、もう一度サインインしてください。

## バックアップコード [#backup-codes]

バックアップコードは、スマートフォン<IfAvailable feature="passkeys">やパスキー</IfAvailable>が手元にないときに、2段階目の代わりに使えます。2段階目の画面で**バックアップコードを使用**をクリックし、コードを1つ入力します。コードは `ABCDE-FGH23` のような形式で、英大文字と2から9の数字で構成されます。紛らわしい 0、O、1、I は含まれません。小文字で入力しても、ダッシュの有無にかかわらず使えます。各コードは1回だけ使えます。

サインインや本人確認でバックアップコードを使うたびに、残りのコード数をアカウントのアドレスにメールでお知らせします。心当たりがない場合は、他の誰かがバックアップコードを持っています。すぐにサポートへご連絡ください。

設定には残りのコード数が表示されます。2個以下になったら、**新しいコード**をクリックし、本人確認を行って新しいコードを作成してください。古いコードは使えなくなります。

## 信頼済みデバイス [#trusted-devices]

2段階目の画面で**このデバイスでは30日間再度確認しない**にチェックを入れると、そのブラウザーでは30日間、2段階目が省略されます。自分のデバイスでのみ使用してください。2段階認証をオフにすると、すべての信頼済みデバイスが解除されます。

## 2段階目を求められるサインイン [#which-sign-ins-ask-for-it]

すべてのサインインで求められます。メールコード、Google、GitHub<IfAvailable feature="sso">、ワークスペースのシングルサインオン</IfAvailable>が対象です。すでにサインインしているブラウザーで再度サインインする場合も含まれます。

<IfAvailable feature="passkeys">

**パスキーで続ける**でのサインインは例外です。パスキーでのサインインは、デバイスと指紋・顔・画面ロックという2つの要素をすでに使っているため、QRdx は2段階目を求めません。QRdx は、そのように本人確認を行うパスキーだけを受け付けます。

</IfAvailable>

## 方法を変更する [#change-your-methods]

**設定** → **プロフィールとセキュリティ**の**2段階認証**で、認証アプリの設定と削除<IfAvailable feature="passkeys">、パスキーの追加、名前の変更、削除</IfAvailable>ができます。変更するたびに本人確認が必要です。

最後の方法を削除すると、2段階認証はオフになり、バックアップコードも使えなくなります。確認の前に、QRdx がその旨をお知らせします。

## 本人確認 [#confirm-its-you]

アカウントのセキュリティに関わる変更の前には、サインイン中であっても、QRdx が本人確認を求めます。対象は次のとおりです。

- メールアドレスの変更
- アカウントの削除
- 2段階認証のオン・オフ、新しいバックアップコードの作成
- 認証アプリの追加・削除<IfAvailable feature="passkeys">、パスキーの追加・名前の変更・削除</IfAvailable>
- Google または GitHub アカウントの連携・連携解除
- API キーの作成、OAuth アプリの作成、OAuth アプリの新しいクライアントシークレットの作成
- **Authorize** 画面での、QRdx アカウントの利用を求めるアプリの承認
- Webhook エンドポイントの追加、エンドポイントの URL の変更、署名シークレットの表示・ローテーション
- Slack または Discord の通知 Webhook の追加、スキャン数やフォームの回答を別のツールに送信する連携の接続
- ワークスペースでの、削除、メンバーのロールの変更、メンバーの削除、メールまたは参加リンクによる管理者の招待、[2段階認証の必須化](/docs/help/teams/require-two-step-verification)とその解除

<IfAvailable feature="sso">

ワークスペースのシングルサインオン接続の作成、編集、検証、削除や、シングルサインオンの必須化も同様です。

</IfAvailable>

本人確認の方法は、2段階認証がオンかどうかによって異なります。

| 2段階認証 | 本人確認の方法 |
| --- | --- |
| **オン** | <IfAvailable feature="passkeys">パスキー、</IfAvailable>認証アプリのコード、またはバックアップコード（使用すると無効になります）。ここではメールで送るコードは使えないため、メールにアクセスできるだけではセキュリティ設定を変更できません。 |
| **オフ** | QRdx がメールで送る6桁のコード、または連携済みの Google もしくは GitHub アカウントでの再サインイン<IfAvailable feature="sso">、またはワークスペースのシングルサインオン（OIDC を使用している場合）</IfAvailable>。<IfAvailable feature="passkeys"> パスキーがある場合は、それも使えます。</IfAvailable> |

再サインインを選ぶとそのサインインに移動し、アカウントの選択またはサインインを求められたあと、元のページに戻ります。離れている間は変更が保存されないため、戻ったらもう一度変更してください。連携したアカウントを使ってください。QRdx が別のアカウントに切り替えたり、新しく作成したりすることはありません。

そのため、メールにアクセスできなくても、別の方法で本人確認ができます。どの方法も使えない場合は、[メールにアクセスできなくなった場合](/docs/help/account-and-billing/sign-in#lost-access-to-your-email)をご覧ください。

本人確認は、そのブラウザーで10分間有効です。続けて複数の変更をする場合、確認は1回だけです。

サインインも、そのブラウザーで10分間は本人確認として扱われます。2段階認証がオンの場合、対象になるのは、2段階目に答えたサインイン<IfAvailable feature="passkeys">または**パスキーで続ける**を使ったサインイン</IfAvailable>だけです。信頼済みデバイスで2段階目が省略されたサインインは対象外です。<IfAvailable feature="sso"> ID プロバイダーのアプリダッシュボードから QRdx を開いた場合も、2段階目に答えていなければ対象外です。</IfAvailable>

他のデバイスをサインアウトする操作では本人確認を求められません。他の誰かがアカウントにアクセスした場合は、すぐにサインアウトさせることができます。

## オフにする [#turn-it-off]

**設定** → **プロフィールとセキュリティ** に移動し、**2段階認証** の下にある **オフにする** をクリックして、本人確認を行います。バックアップコードと、認証アプリを設定している場合はその設定が削除されます。

参加しているワークスペースが[2段階認証を必須にしている](/docs/help/teams/require-two-step-verification)場合、再びオンにするまでそのワークスペースを開けません。

## スマートフォンとバックアップコードを紛失した場合 [#lost-your-phone-and-your-backup-codes]

<IfAvailable feature="passkeys">パスキー、</IfAvailable>認証アプリ、またはバックアップコードがまだ手元にある場合は、それらでサインインし、設定で認証方法を変更してください。

2段階目の認証方法をすべて失った場合は、アカウントのメールアドレスから support@qrdx.dev 宛に、状況を書いてメールをお送りください。[support@qrdx.dev](mailto:support@qrdx.dev)

ご連絡をくださった方が本人とは限らないため、そのメールアドレスからのリクエストであることを確認したあと、サポートによるオフの処理は7日間待機します。

1. **当日中に、そのメールアドレスへメールを送信します。** それまでは何も変わらず、現在サインインしている場所ではサインインしたままです。
2. **心当たりがない場合は、止めてください。** 認証アプリまたはバックアップコードでサインインすると、取り消されます。<IfAvailable feature="passkeys"> パスキーでのサインインでは取り消されません。このリセットは端末を紛失した場合のためのもので、パスキーがその端末に保存されている可能性があるためです。</IfAvailable> **設定** → **プロフィールとセキュリティ** の **2段階認証** の下にある **キャンセル** をクリックして[本人確認](#confirm-its-you)を行うか、メールに返信することでも取り消せます。取り消されると、メールでお知らせします。
3. **7日後に、2段階認証がオフになります。** 認証アプリの設定、バックアップコード、信頼済みデバイスが削除され、<IfAvailable feature="passkeys">パスキーは残り、</IfAvailable>すべてのデバイスでアカウントがサインアウトされます。その旨をメールでお知らせします。その後は通常どおりサインインし、あらためてオンにしてください。
