QRdxのアカウントにはパスワードがありません。そのため、アカウントを守るとは、サインインの手段を守り、不審な動きがあったときにQRdxが何をするのかを知ることです。このページでは、2段階認証、パスキー、重要な変更の前に行う確認、届くメール、他のデバイスをサインアウトする方法まで、すべてを説明します。

## 漏れるパスワードがない [#no-password-to-leak]

QRdxにはパスワードがありません。サインインには、Google、GitHub、メールに送られるワンタイムコード<IfAvailable feature="passkeys">、またはパスキー</IfAvailable>を使います。<IfAvailable feature="sso"> ワークスペースがBusinessプランの場合は、会社の[シングルサインオン](/docs/help/teams/single-sign-on)でのサインインを許可することも、必須にすることもできます。</IfAvailable>

つまり、メールアカウントやGoogle、GitHubのアカウントがQRdxへの鍵になります。これらにも2段階認証を設定してください。

<IfAvailable feature="sso" id="if-your-company-requires-single-sign-on" title="会社がシングルサインオンを必須にしている場合">

Businessのワークスペースは、会社のメールドメインに対して[シングルサインオンを必須](/docs/help/teams/single-sign-on#require-single-sign-on)にできます。あなたのアドレスがそのドメインのものである場合は、次のとおりです。

- サインインにはシングルサインオンだけを使います。メールコード、Google、GitHub<IfAvailable feature="passkeys">、**パスキーで続行**</IfAvailable>ではサインインできません。
- 会社のサインインページの後にも2段階認証が適用されます<IfAvailable feature="passkeys">。パスキーも2段階目として引き続き使えます</IfAvailable>。
- 各サインインの有効期間は最長24時間です。その後は、もう一度シングルサインオンでサインインします。
- QRdxのメールアドレスを、ドメイン外のアドレスに変更することはできません。

ワークスペースでこの設定を有効にすると、シングルサインオンで開始していないセッションはサインアウトされます。ワークスペースのオーナーは他のサインイン方法も使えるため、会社のサインインページに問題が起きても、全員がロックアウトされることはありません。

</IfAvailable>

## 2段階認証を有効にする [#turn-on-two-step-verification]

[2段階認証](/docs/help/privacy-and-security/two-step-verification)を有効にすると、どの方法でサインインしても、サインイン後にQRdxが2段階目の確認を求めます。確認には<IfAvailable feature="passkeys">パスキーまたは</IfAvailable>認証アプリのコードを使います。メールやGoogleアカウントに侵入されても、2段階目がなければQRdxには入れません。2段階目を実行できないときのために、10個のバックアップコードが発行されます。有効にすると、アカウントにサインインしている他のブラウザやデバイスはすべてサインアウトされるため、それぞれ2段階目を使ってサインインし直す必要があります。

<IfAvailable feature="passkeys" id="add-a-passkey" title="パスキーを追加する">

[パスキー](/docs/help/privacy-and-security/passkeys)は、指紋、顔、または画面ロックで本人確認を行います。QRdx自身のサイトでしか動作しないため、偽サイトに盗まれることはありません。**パスキーで続行**でそれだけでサインインすることも、2段階目として使うこともできます。2段階認証がオフの状態でパスキーを追加すると、2段階認証がオンになり、他のデバイスがサインアウトされます。

</IfAvailable>

## 変更時は本人確認を求められます [#changes-ask-you-to-confirm-its-you]

アカウントのセキュリティに関わる変更の前には、サインイン中であっても、QRdxが[本人確認](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)を求めます。対象は次のとおりです。

- アカウント：メールアドレスの変更、アカウントの削除、2段階認証のオン/オフ、新しいバックアップコードの発行、2段階目の方法の変更、GoogleまたはGitHubの連携と連携解除。
- 開発者ツール：APIキーやOAuthアプリのクライアントシークレットの作成、アカウントの使用を求めるアプリの承認、Webhookの追加やURLの変更、Webhookの署名シークレットの表示やローテーション。
- 連携：SlackやDiscordの通知Webhookの追加、スキャンやフォームの回答を他のツールに送る連携の接続。
- ワークスペース：削除、メンバーのロールの変更、メンバーの削除、管理者の招待。<IfAvailable feature="sso"> ワークスペースのシングルサインオン接続の変更や、シングルサインオンの必須化も対象です。</IfAvailable>

2段階認証がオンの場合は、<IfAvailable feature="passkeys">パスキー、</IfAvailable>認証アプリのコード、またはバックアップコードで確認します。メールで届くコードは使えません。オフの場合は、QRdxからメールで届く6桁のコード<IfAvailable feature="passkeys">、パスキー（お持ちの場合）</IfAvailable>、または連携済みのGoogleやGitHubアカウントでの再サインインが使えます<IfAvailable feature="sso">（ワークスペースのシングルサインオンがOIDCを使っている場合は、それも使えます）</IfAvailable>。確認の有効期間は、そのブラウザで10分間です。

メールアドレスを変更するには、新しいアドレスに送られるコードも必要です。変更後は他のすべての場所からサインアウトされ、古いアドレスには変更されたことを知らせるメールが届きます。メールにアクセスできなくなった場合は、[対処方法](/docs/help/account-and-billing/sign-in#lost-access-to-your-email)をご覧ください。

## 新しい場所で使われたサインイン [#a-sign-in-used-somewhere-new]

サインインすると、QRdxはサインインした国とブラウザ（「macOS上のChrome」など）を記録します。そのサインインが後で別の国かつ別のブラウザから使われた場合、アカウントで他の操作をする前に[本人確認](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)が求められます。確認するまで、そのブラウザはQRdx上の他のすべての場所ではサインアウトした状態として扱われます。そのため、あなたのブラウザからサインイン情報をコピーした人が、本人確認までできなければ、遠く離れた場所からそれを使うことはできません。

確認を求められるのは、国とブラウザの両方が変わった場合だけです。同じブラウザで旅行した場合や、ブラウザやシステムを更新した場合は対象になりません。確認すると、QRdxはそのサインインの新しい国とブラウザを記録します。確認する代わりに、サインアウトしてからサインインし直すこともできます。

これは追加の確認であり、完全な保証ではありません。コピーされたサインインが同じ国や同じ種類のブラウザから使われた場合は、確認を求められません。QRdxが国を判別できるのは、ホスティングプロバイダーが国の情報を提供している場合のみで、提供されていない環境ではこの確認は行われません。見覚えのないサインインを終了するには、[他のデバイスをサインアウト](#sign-out-other-devices)してください。

## アカウントのセキュリティに関するメール [#emails-about-your-accounts-security]

次の場合に、アカウントのアドレスへメールを送信します。

- ブラウザやデバイスが初めてアカウントにサインインしたとき。
- 2段階認証がオンまたはオフになったとき、認証アプリ<IfAvailable feature="passkeys">やパスキー</IfAvailable>が追加または削除されたとき、または新しいバックアップコードが作成されたとき。
- サインインや本人確認のためにバックアップコードが使われたとき（残りのコード数もお知らせします）。
- サポートに2段階認証の解除が依頼されたとき（実行される日と、止める方法をお知らせします）、およびその依頼が取り消されたとき。
- メールアドレスが変更されたとき（古いアドレス宛て）。

どのメールにも、何が起きたか、どのデバイスとブラウザ（「macOS上のChrome」など）か、おおよその場所、IPアドレス、日時が記載されています。**セキュリティを確認**を押すと、セキュリティ設定が開きます。心当たりがない場合は、メールの手順に従ってサポートにご連絡ください。

サインインコードや本人確認のコードなど、コードを含むメールには、コードが要求されたおおよその場所が記載されます。QRdxが電話、チャット、メールでコードを尋ねることはありません。コードは誰にも教えないでください。

### 新しいサインイン [#new-sign-ins]

QRdxは、サインインの完了時に設定するCookieでブラウザを識別します。そのCookieを持たないブラウザやデバイスがアカウントにサインインすると、メールが届きます。2段階認証がオンの場合は、2段階目が完了してから送信されます。

QRdxがすでに識別しているブラウザで再度サインインしても、メールは送信されません。アカウントを作成したときも同様です。Cookieを削除した場合やプライベートウィンドウを使った場合は、次のサインインが新しいものとして扱われます。

新しいブラウザごとにメールが1通届きます。上限は1日10通で、サインインが集中しても受信トレイがあふれないようになっています。すべてのサインインは、これまでどおり**セッション**に表示されます。QRdxは、最近使用した50件のブラウザを記憶し、400日間サインインのないブラウザは忘れます。

<IfAvailable feature="sso">

例外が1つあります。ワークスペースのSAML IDプロバイダー経由でサインインし、2段階認証がオフの場合、QRdxは戻ってきたときにブラウザを識別できないため、このメールは送信されません。

</IfAvailable>

## サインインしたままでいられる期間 [#how-long-you-stay-signed-in]

サインインの有効期間は最長30日です。その後は、どれだけ頻繁に使っていても、そのブラウザでもう一度サインインするよう求められます。ブラウザでQRdxを約1週間使わなかった場合は、それより早くサインアウトされます。

## 他のデバイスをサインアウトする [#sign-out-other-devices]

**設定** → **プロフィールとセキュリティ**を開きます。**セッション**で、1台のデバイスだけをサインアウトするか、**他のすべての場所でサインアウト**をクリックします。この操作では本人確認を求められないため、すぐに実行できます。

<Shot id="sessions-card" />

2段階認証を有効にすると、他のすべてのデバイスもサインアウトされます。サポートがあなたの2段階認証をオフにした場合（[7日間の待機](/docs/help/privacy-and-security/two-step-verification#lost-your-phone-and-your-backup-codes)があります）、その日に、使用中のデバイスを含むすべてのデバイスがサインアウトされます。<IfAvailable feature="sso"> 会社がシングルサインオンを必須にした場合は、シングルサインオンで開始していないセッションがサインアウトされ、シングルサインオンのセッションの有効期間は最長24時間になります。</IfAvailable>

## 連携したアプリを削除する [#remove-apps-you-connected]

別のアプリに QRdx アカウントの利用を許可している場合、そのアプリは **設定** → **承認済みアプリ** に表示されます。使っていないアプリは削除してください。アプリはサインアウトした後も動作し続けるため、アプリを承認する際は本人確認が求められます。

## セキュリティ上の問題を報告する [#report-a-security-problem]

件名を `[security]` で始めて、[support@qrdx.dev](mailto:support@qrdx.dev) にメールを送ってください。公開の GitHub の issue には投稿しないでください。[セキュリティポリシー](/legal/security)をご覧ください。

有害なQRコードはセキュリティ上のバグではありません。代わりに[報告](/docs/help/privacy-and-security/report-abuse)してください。
