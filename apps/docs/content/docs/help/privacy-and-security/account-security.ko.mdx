QRdx 계정에는 비밀번호가 없어요. 그래서 계정을 지킨다는 것은 로그인 방법을 보호하고, 수상한 일이 생겼을 때 QRdx가 어떻게 동작하는지 아는 것을 뜻합니다. 이 페이지에서는 2단계 인증, 패스키, 민감한 변경 전의 확인, 받게 되는 이메일, 다른 기기를 로그아웃하는 방법까지 모두 다룹니다.

## 유출될 비밀번호가 없어요 [#no-password-to-leak]

QRdx에는 비밀번호가 없습니다. Google, GitHub 또는 이메일로 받은 일회용 코드로 로그인해요<IfAvailable feature="passkeys">. 패스키로도 로그인할 수 있어요</IfAvailable>.<IfAvailable feature="sso"> 워크스페이스가 Business 요금제라면 회사의 [싱글 사인온](/docs/help/teams/single-sign-on)으로 로그인하게 하거나 이를 필수로 지정할 수도 있습니다.</IfAvailable>

따라서 이메일 계정과 Google 또는 GitHub 계정이 QRdx의 열쇠가 됩니다. 이 계정들에도 2단계 인증을 켜 두세요.

<IfAvailable feature="sso" id="if-your-company-requires-single-sign-on" title="회사에서 싱글 사인온을 필수로 지정한 경우">

Business 워크스페이스는 회사 이메일 도메인에 [싱글 사인온을 필수로 지정](/docs/help/teams/single-sign-on#require-single-sign-on)할 수 있습니다. 내 주소가 해당 도메인이라면 다음과 같아요.

- 싱글 사인온으로만 로그인합니다. 이메일 코드, Google, GitHub<IfAvailable feature="passkeys">, **Continue with passkey**</IfAvailable>로는 로그인되지 않아요.
- 회사 로그인 페이지를 거친 뒤에도 2단계 인증은 그대로 적용되며<IfAvailable feature="passkeys">, 패스키도 두 번째 단계로 계속 사용할 수 있어요</IfAvailable>.
- 로그인은 최대 24시간 유지되며, 이후에는 싱글 사인온으로 다시 로그인해야 해요.
- QRdx 이메일을 도메인 밖의 주소로 바꿀 수 없어요.

워크스페이스에서 이 설정을 켜면 싱글 사인온으로 시작하지 않은 세션은 로그아웃됩니다. 워크스페이스 소유자는 다른 로그인 방법을 그대로 유지하므로, 회사 로그인 페이지에 문제가 생겨도 모두가 접속하지 못하는 일은 없어요.

</IfAvailable>

## 2단계 인증 켜기 [#turn-on-two-step-verification]

[2단계 인증](/docs/help/privacy-and-security/two-step-verification)을 켜면 어떤 방법으로 로그인하든 로그인 후에 QRdx가 두 번째 단계를 요구해요. <IfAvailable feature="passkeys">패스키 또는 </IfAvailable>인증 앱의 코드를 사용합니다. 이메일이나 Google 계정에 누군가 접근하더라도 이 단계 없이는 QRdx에 들어갈 수 없어요. 두 번째 단계를 진행할 수 없을 때 쓸 수 있는 백업 코드 10개가 제공됩니다. 2단계 인증을 켜면 계정에 로그인된 다른 모든 브라우저와 기기가 로그아웃되므로, 각각 두 번째 단계를 거쳐 다시 로그인해야 해요.

<IfAvailable feature="passkeys" id="add-a-passkey" title="패스키 추가하기">

[패스키](/docs/help/privacy-and-security/passkeys)는 지문, 얼굴 또는 화면 잠금으로 본인임을 확인해요. QRdx 공식 사이트에서만 작동하므로 비슷하게 만든 가짜 사이트에서는 수집할 수 없습니다. **Continue with passkey**로 단독 로그인에 쓰거나 두 번째 단계로 쓸 수 있어요. 2단계 인증이 꺼져 있을 때 패스키를 추가하면 2단계 인증이 켜지고, 그에 따라 다른 기기는 로그아웃돼요.

</IfAvailable>

## 변경 전에 본인 확인을 요청해요 [#changes-ask-you-to-confirm-its-you]

계정의 보안과 관련된 변경을 하기 전에는, 이미 로그인한 상태여도 QRdx가 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요청해요. 대상은 다음과 같습니다.

- 계정: 이메일 주소 변경, 계정 삭제, 2단계 인증 켜기/끄기, 새 백업 코드 발급, 두 번째 단계 방법 변경, Google 또는 GitHub 연결/해제
- 개발자 도구: API 키 또는 OAuth 앱의 클라이언트 시크릿 생성, 내 계정을 사용하려는 앱 승인, 웹훅 추가 또는 URL 변경, 웹훅 서명 시크릿 표시 또는 교체
- 연결: Slack 또는 Discord 알림 웹훅 추가, 스캔이나 폼 답변을 다른 도구로 보내는 연동 연결
- 워크스페이스: 삭제, 멤버 역할 변경, 멤버 제거, 관리자 초대.<IfAvailable feature="sso"> 워크스페이스의 싱글 사인온 연결 변경과 싱글 사인온 필수 지정도 해당돼요.</IfAvailable>

2단계 인증을 켜 두었다면 <IfAvailable feature="passkeys">패스키, </IfAvailable>인증 앱 코드 또는 백업 코드로 확인하며, 이메일로 받은 코드는 쓸 수 없어요. 꺼 두었다면 QRdx가 이메일로 보내는 6자리 코드<IfAvailable feature="passkeys">, 패스키가 있다면 패스키</IfAvailable>를 쓰거나, 연결해 둔 Google 또는 GitHub 계정으로 다시 로그인하면 됩니다<IfAvailable feature="sso"> (워크스페이스의 싱글 사인온이 OIDC를 사용한다면 그것으로도 가능해요)</IfAvailable>. 확인은 해당 브라우저에서 10분 동안 유지돼요.

이메일 주소를 바꿀 때는 새 주소로 보낸 코드도 필요해요. 변경이 끝나면 다른 모든 곳에서 로그아웃되고, 이전 주소로 변경 사실을 알리는 이메일이 발송됩니다. 이메일에 접근할 수 없나요? [해결 방법](/docs/help/account-and-billing/sign-in#lost-access-to-your-email)을 확인하세요.

## 새로운 곳에서 사용된 로그인 [#a-sign-in-used-somewhere-new]

로그인하면 QRdx는 로그인한 국가와 "macOS의 Chrome" 같은 브라우저 정보를 기록해요. 이후 그 로그인이 다른 국가의 다른 브라우저에서 사용되면, 계정에서 다른 작업을 하기 전에 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요청해요. 확인할 때까지 해당 브라우저는 QRdx의 다른 모든 곳에서 로그아웃된 것으로 처리됩니다. 따라서 누군가 내 브라우저에서 로그인 정보를 복사하더라도, 본인 확인까지 통과하지 못하면 먼 곳에서 사용할 수 없어요.

국가와 브라우저가 모두 바뀐 경우에만 확인을 요청해요. 같은 브라우저로 여행하거나 브라우저 또는 시스템을 업데이트하는 것은 해당하지 않습니다. 확인하고 나면 QRdx는 그 로그인에 대해 새 국가와 브라우저를 기록해요. 확인 대신 로그아웃했다가 다시 로그인해도 됩니다.

이 확인은 추가 보호 장치일 뿐 보장은 아니에요. 복사된 로그인이 같은 국가나 같은 종류의 브라우저에서 사용되면 확인을 요청하지 않아요. QRdx는 호스팅 환경에서 국가 정보를 제공하는 경우에만 국가를 알 수 있으며, 제공하지 않는 곳에서는 이 확인이 실행되지 않습니다. 알아볼 수 없는 로그인을 종료하려면 [다른 기기 로그아웃](#sign-out-other-devices)을 이용하세요.

## 계정 보안 관련 이메일 [#emails-about-your-accounts-security]

다음과 같은 경우 계정의 이메일 주소로 메일을 보내요.

- 브라우저나 기기가 처음으로 내 계정에 로그인할 때
- 2단계 인증을 켜거나 끌 때, 인증 앱<IfAvailable feature="passkeys"> 또는 패스키</IfAvailable>를 추가하거나 제거할 때, 새 백업 코드를 만들 때
- 로그인이나 본인 확인에 백업 코드를 사용했을 때. 남은 코드 수도 함께 알려 드려요.
- 지원팀에 2단계 인증 해제를 요청했을 때. 해제되는 날짜와 막는 방법이 담기며, 요청이 취소되었을 때도 메일을 보내요.
- 이메일 주소가 변경되었을 때 (이전 주소로 발송)

각 메일에는 무슨 일이 있었는지, 어떤 기기와 브라우저("macOS의 Chrome" 등)인지, 대략적인 위치, IP 주소, 시각이 담겨 있어요. **Review security**를 누르면 보안 설정이 열립니다. 본인이 한 일이 아니라면 메일의 안내에 따라 조치하고 지원팀에 문의하세요.

로그인 코드나 본인 확인 코드처럼 코드가 담긴 이메일에는 코드가 요청된 대략적인 위치가 표시돼요. QRdx는 전화, 채팅, 이메일로 코드를 요구하지 않습니다. 코드를 누구에게도 알려 주지 마세요.

### 새 로그인 [#new-sign-ins]

QRdx는 로그인을 마칠 때 설정하는 쿠키로 브라우저를 인식해요. 이 쿠키가 없는 브라우저나 기기가 내 계정에 로그인하면 이메일을 받게 됩니다. 2단계 인증을 켠 경우에는 두 번째 단계를 마친 뒤에 발송돼요.

QRdx가 이미 인식하는 브라우저에서 다시 로그인할 때는 메일을 보내지 않으며, 계정을 만들 때도 보내지 않아요. 쿠키를 삭제하거나 시크릿 창을 사용하면 그곳에서의 다음 로그인은 새 로그인으로 간주됩니다.

새 브라우저마다 각각 이메일을 보내며, 하루 최대 10통까지입니다. 로그인이 몰려도 받은편지함이 넘치지 않도록 한 거예요. 모든 로그인은 여전히 **Sessions**에 표시돼요. QRdx는 가장 최근에 사용한 브라우저 50개를 기억하고, 400일 동안 로그인하지 않은 브라우저는 잊어요.

<IfAvailable feature="sso">

예외가 하나 있어요. 워크스페이스의 SAML 아이덴티티 제공자로 로그인하고 2단계 인증이 꺼져 있으면, QRdx가 돌아올 때 브라우저를 인식할 수 없어서 이 이메일을 보내지 않습니다.

</IfAvailable>

## 로그인이 유지되는 기간 [#how-long-you-stay-signed-in]

로그인은 최대 30일 동안 유지돼요. 그 후에는 얼마나 자주 사용했는지와 관계없이 해당 브라우저에서 다시 로그인하라는 안내가 표시됩니다. 브라우저에서 약 일주일 동안 QRdx를 사용하지 않으면 그보다 일찍 로그아웃돼요.

## 다른 기기 로그아웃 [#sign-out-other-devices]

**Settings** → **Profile & security**로 이동하세요. **Sessions**에서 기기 하나를 로그아웃하거나 **Sign out everywhere else**를 클릭하면 됩니다. 이 작업은 본인 확인을 요구하지 않으므로 바로 할 수 있어요.

<Shot id="sessions-card" />

2단계 인증을 켜면 다른 모든 기기도 로그아웃돼요. 지원팀이 2단계 인증을 대신 꺼 주는 경우에는 [7일을 기다려야](/docs/help/privacy-and-security/two-step-verification#lost-your-phone-and-your-backup-codes) 하며, 해제되는 날 지금 사용 중인 기기를 포함한 모든 기기가 로그아웃됩니다.<IfAvailable feature="sso"> 회사에서 싱글 사인온을 필수로 지정하면 싱글 사인온으로 시작하지 않은 세션은 로그아웃되고, 싱글 사인온 세션은 최대 24시간 유지돼요.</IfAvailable>

## 연결한 앱 제거하기 [#remove-apps-you-connected]

다른 앱이 QRdx 계정을 사용하도록 허용했다면 **설정** → **승인된 앱**에 목록으로 표시됩니다. 사용하지 않는 앱은 모두 제거하세요. 앱은 로그아웃한 뒤에도 계속 작동하므로, 앱을 승인할 때는 본인이 맞는지 확인하는 절차가 필요합니다.

## 보안 문제 신고하기 [#report-a-security-problem]

제목을 `[security]`로 시작해서 [support@qrdx.dev](mailto:support@qrdx.dev)로 이메일을 보내 주세요. 공개 GitHub 이슈에는 올리지 마세요. [보안 정책](/legal/security)을 참고하세요.

유해한 QR 코드는 보안 버그가 아닙니다. 이 경우에는 [신고](/docs/help/privacy-and-security/report-abuse)해 주세요.
