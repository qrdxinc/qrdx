監査ログには、ワークスペースでユーザーが行った変更が、誰が行ったか、何を変更したか、いつ変更したかとともに一覧表示されます。QRdxの商用ライセンスに基づくBusiness向けの機能です。セルフホストのQRdxサーバーで有効にするには、ライセンスキー(`QRDX_EE_LICENSE`)が必要です。[セルフホスティング](/docs/self-hosting#optional-services)をご覧ください。

<IfAvailable feature="auditLog">

<Callout type="info">
  監査ログは**Business**プランに含まれます。ワークスペースのオーナーまたは請求担当メンバーのいずれかがBusinessプランを利用していると、そのワークスペースで使えます。開いてエクスポートできるのは**オーナー**と**管理者**だけです。[シートとワークスペースの上限](/docs/help/teams/seats)と[チームのロール](/docs/help/teams/roles)をご覧ください。
</Callout>

## 監査ログを開く [#open-the-audit-log]

ワークスペースで**設定** → **監査ログ**に移動します。新しい変更から順に50件ずつ表示されます。古い変更を見るには、下部の**さらに読み込む**をクリックします。エントリーの矢印をクリックすると、QRコードの変更前と変更後のリンク先など、古い値と新しい値を確認できます。

<Shot id="audit-log" />

履歴の記録は、ワークスペースがBusinessプランになった時点から始まります。それより前や、別のプランだった間の変更は記録されません。ワークスペースがBusinessプランでなくなると記録は止まりますが、すでに保存されたエントリーは{facts.auditLogRetentionDays}日が経過するまで残り、ワークスペースがBusinessプランに戻れば再び表示できます。

## 記録される内容 [#whats-recorded]

各エントリーには、時刻、変更を行った人、変更の内容、対象(QRコード、ページ、ユーザー、ドメイン)が含まれます。変更を行った人とは、ユーザー本人、またはユーザーに代わって動作するAPIキーやアプリです。APIキーを使った[REST API](/docs/developers/rest-api)での変更にはキーの名前が、承認したアプリを通じた変更にはアプリの名前が表示されます。<IfAvailable feature="slackBot"> Slackで`/qr track`により作成されたQRコードでは、連携しているユーザーが「via Slack」と表示され、SlackのユーザーIDとワークスペースIDも記録されます。オーナーまたは管理者が**設定** → **APIキーとアプリ**でSlackアカウントの連携を取り消すと、その操作は開発者のカテゴリーに記録されます。</IfAvailable>

各エントリーには、リクエストのIPアドレスとデバイス(「Chrome on macOS」のようなブラウザーとOS)も保存されます。請求によるプラン変更など、システムが行う変更にはどちらもありません。

| カテゴリー | 記録される内容 |
| --- | --- |
| **QRコード** | 作成(インポートとコピーを含む)、リンク先の変更、名前の変更、デザインの変更、短縮リンクの変更、リンク制御の変更(パスワードのオンとオフ、開始日と終了日、スキャン上限、フォールバックURL)、ルーティングルールの変更、一時停止と再開、アーカイブとアーカイブ解除、ゴミ箱への移動、復元、完全削除、以前のバージョンの復元、別のフォルダーへの移動、別のワークスペースへの移動とそこからの移動。フォルダーとタグの作成、名前の変更、削除。 |
| **ページ** | 作成、公開、削除。 |
| **チーム** | 招待の送信と取り消し、招待、参加リンク、シングルサインオンによる参加、ロールの変更、ユーザーの削除、ユーザーの退出、参加リンクのオン、変更、オフ。QRdxで行ったか、そのAPIで行ったかにかかわらず記録されます。 |
| **セキュリティ** | 「2段階認証を必須にする」と「シングルサインオンを必須にする」のオンとオフ(シングルサインオンをオンにした場合は、サインアウトされたセッション数も記録されます)、シングルサインオンの設定、変更、検証、削除、新しいユーザーが初めてシングルサインオンでサインインしたときに割り当てられるロール、監査ログのエクスポート。 |
| **開発者** | APIキーの作成と取り消し(名前とスコープ)、アプリの承認と取り消し、Webhookエンドポイントの追加、変更、削除、Webhookの署名シークレットの再発行。エンドポイントについては、WebhookのURLの残りの部分が機密であることが多いため、`https://hooks.zapier.com/…`のようにサーバー部分だけが保存されます。 |
| **ドメイン** | カスタムドメインの追加、検証、削除。 |
| **ワークスペース** | 名前またはURLの変更、ワークスペースのBusinessへの移行(「請求」として記録)。 |

監査ログには、APIキー、OAuthトークン、パスワード、WebhookのURLのパスやクエリ、Webhookの署名シークレット、シングルサインオンのクライアントシークレットや証明書は一切保存されません。作成、再発行、削除されたことだけが記録され、値は記録されません。

承認したアプリはご自身のワークスペースに対して動作するため、アプリの承認と取り消しはそのワークスペースに記録されます。

次の内容は監査ログに含まれません。

- スキャン、フォームの回答、アナリティクス。ワークスペースへの変更ではないためです(アナリティクスと回答で確認できます)。
- 名前、メールアドレス、2段階認証など、ご自身のアカウントへの変更。

## ログを絞り込む [#filter-the-log]

- **ユーザー**: 特定の1人。その人に代わって動作するAPIキーとアプリも含まれます。
- **カテゴリー**: QRコード(フォルダーとタグを含む)、ページ、チーム、セキュリティ、開発者、ドメイン、ワークスペース。
- **開始日**と**終了日**: 表示する最初の日と最後の日です。日付はUTC基準で、各エントリーの時刻はお使いのタイムゾーンで表示されます。

## CSVとしてエクスポートする [#export-as-csv]

**CSVをエクスポート**をクリックすると、現在のフィルターで表示されている内容が新しい順にダウンロードされます。1回のエクスポートに含められるのは最大{facts.auditLogExportRows}件です。それを超える場合は、日付の範囲を短くして分けてエクスポートしてください。

ファイルには、変更ごとに1行が出力されます。内容は、UTCの時刻、カテゴリー、アクション、変更を説明する文、変更を行った人(APIキーやアプリがある場合はそれも)、対象、IPアドレス、デバイス、そして変更前と変更後の値(JSON形式)です。

エクスポートも、使用したフィルターとともに記録されます。

## エントリーの保存期間 [#how-long-entries-are-kept]

エントリーは{facts.auditLogRetentionDays}日間保存され、その後削除されます。ワークスペースを削除すると、その監査ログも一緒に削除されます。

監査ログに含まれるIPアドレスとデバイスは、ワークスペースで作業するユーザーの個人データです。QRdxによる取り扱いについては、[プライバシーポリシー](/legal/privacy-policy)をご覧ください。

## うまくいかない場合 [#if-something-goes-wrong]

### 設定に監査ログが表示されない [#audit-log-isnt-in-settings]

メンバー、閲覧者、または請求担当メンバーである場合や、ワークスペースがBusinessプランでない場合です。オーナーまたは管理者に問い合わせるか、[プランと含まれる機能](/docs/help/account-and-billing/plans)をご覧ください。

### 想定している変更が表示されない [#a-change-you-expect-isnt-listed]

その変更がワークスペースのBusinessプラン開始前に行われた、{facts.auditLogRetentionDays}日より前のものである、またはスキャン、回答、ご自身のアカウントへの変更のいずれかである可能性があります。これらは記録されません。
