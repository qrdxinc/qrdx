---

Jedes Mitglied eines Workspace hat genau eine Rolle: **Owner**, **Admin**, **Mitglied**, **Abrechnung** oder **Betrachter**. In deinem eigenen Workspace bist du der Owner. Die Rolle bestimmt, was jemand ändern darf; alle können die Codes, Seiten und Analysen des Workspace sehen.

## Was jede Rolle tun kann [#what-each-role-can-do]

| | Owner | Admin | Mitglied | Abrechnung | Betrachter |
| --- | --- | --- | --- | --- | --- |
| Codes, Seiten, Dateien und Analysen ansehen | Ja | Ja | Ja | Ja | Ja |
| Codes, Seiten, Dateien, Ordner, Tags und Designs erstellen; die Codes des Workspace bearbeiten; eigene löschen | Ja | Ja | Ja | | |
| API-Schlüssel erstellen | Ja | Ja | Ja | | |
| Löschen oder ändern, was andere Mitglieder erstellt haben | Ja | Ja | | | |
| Personen einladen und entfernen sowie Rollen ändern | Ja | Ja | | | |
| Den Workspace umbenennen, seine URL und sein Logo ändern und den Beitrittslink verwalten | Ja | Ja | | | |
| Eigene Domains hinzufügen, verifizieren und entfernen | Ja | Ja | | | |
| Webhooks, geteilte Designs und das Standarddesign verwalten | Ja | Ja | | | |
| Die API-Schlüssel aller sehen und widerrufen | Ja | Ja | | | |
| [Bestätigung in zwei Schritten verlangen](/docs/help/teams/require-two-step-verification) und Single Sign-on einrichten (Business) | Ja | Ja | | | |
| Das Audit-Protokoll lesen (Business) | Ja | Ja | | | |
| Den Tarif, auf dem der Workspace läuft, upgraden, ändern oder kündigen | Ja | | | Ja | |
| Andere Mitglieder zu Owners oder Abrechnungsmitgliedern machen | Ja | | | | |
| OAuth-Apps erstellen und ändern | Ja | | | | |
| Den Workspace löschen | Ja | | | | |

Ein Mitglied mit der Rolle **Abrechnung** verwaltet den Tarif und hat sonst nur Leserechte. Ein **Betrachter** sieht alles und ändert nichts.

## Wer für den Workspace bezahlt [#who-pays-for-the-workspace]

Ein Workspace läuft auf dem besten Tarif unter seinen Owners und Abrechnungsmitgliedern. Wenn du jemandem die Rolle „Abrechnung“ gibst, kann diese Person den Workspace bezahlen, ohne seine Codes ändern zu können.

## Die Rolle einer Person ändern [#change-someones-role]

Ändere auf der Seite **Einstellungen** → **Team** die **Rolle** neben dem Namen der Person. Admins können Admin, Mitglied und Betrachter vergeben; nur Owners können die Rollen Owner und Abrechnung vergeben oder entziehen.

Wenn du eine Rolle änderst, jemanden entfernst, einen Admin einlädst oder den Workspace löschst, musst du zuerst [bestätigen, dass du es bist](/docs/help/privacy-and-security/two-step-verification#confirm-its-you). Das gilt nicht, wenn du das in diesem Browser in den letzten 10 Minuten schon getan hast.

## Einen Workspace übergeben [#hand-over-a-workspace]

Es gibt keine eigene Schaltfläche zum Übertragen. Mach die neue Person zum **Owner**. Sobald es einen weiteren Owner gibt, kannst du den Workspace verlassen. Dein eigener Workspace lässt sich auf diese Weise nicht übergeben: Du kannst ihn nicht verlassen.

## Wenn etwas nicht klappt [#if-something-goes-wrong]

### Du kannst für jemanden nicht Owner oder Abrechnung auswählen [#you-cant-pick-owner-or-billing-for-someone]

Nur ein Owner kann diese Rollen vergeben. Frag einen der Owners des Workspace.

### Ein Mitglied kann einen Code nicht löschen [#a-member-cant-delete-a-code]

Mitglieder löschen nur, was sie selbst erstellt haben. Für einen Code, den jemand anderes erstellt hat, braucht es einen Admin oder Owner.
