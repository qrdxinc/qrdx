감사 로그에는 워크스페이스에서 사람들이 한 변경 내용이 누가, 무엇을, 언제 바꿨는지 순서로 기록됩니다. QRdx 상용 라이선스에 포함된 Business 기능입니다. 자체 호스팅 QRdx 서버에서 켜려면 라이선스 키(`QRDX_EE_LICENSE`)가 필요합니다. [자체 호스팅](/docs/self-hosting#optional-services)을 참고하세요.

<IfAvailable feature="auditLog">

<Callout type="info">
  감사 로그는 **Business** 플랜에 포함된 기능입니다. 워크스페이스의 소유자나 결제 멤버 중 한 명이 Business를 사용 중이면 워크스페이스에서 쓸 수 있습니다. **소유자**와 **관리자**만 열고 내보낼 수 있습니다. [좌석과 워크스페이스 한도](/docs/help/teams/seats), [팀 역할](/docs/help/teams/roles)을 참고하세요.
</Callout>

## 감사 로그 열기 [#open-the-audit-log]

워크스페이스에서 **설정** → **감사 로그**로 이동하세요. 최신 변경이 먼저 표시되며 한 번에 50개씩 보입니다. 이전 기록은 맨 아래의 **더 보기**를 클릭하세요. 항목의 화살표를 클릭하면 QR 코드의 이전 대상과 새 대상처럼 이전 값과 새 값을 볼 수 있습니다.

<Shot id="audit-log" />

기록은 워크스페이스가 Business가 된 시점부터 시작됩니다. 그 전이나 다른 플랜을 사용하던 동안의 변경은 기록되지 않습니다. 워크스페이스가 Business에서 벗어나면 기록이 중단됩니다. 이미 저장된 항목은 {facts.auditLogRetentionDays}일이 될 때까지 남아 있으며, 워크스페이스가 다시 Business가 되면 다시 볼 수 있습니다.

## 기록되는 내용 [#whats-recorded]

각 항목에는 시간, 변경한 사람, 변경 내용, 대상(QR 코드, 페이지, 사람, 도메인)이 담깁니다. 변경한 주체는 사람이거나, 사람을 대신해 동작하는 API 키 또는 앱입니다. API 키로 [REST API](/docs/developers/rest-api)를 통해 한 변경에는 키 이름이, 사용자가 승인한 앱을 통해 한 변경에는 앱 이름이 표시됩니다.<IfAvailable feature="slackBot"> Slack에서 `/qr track`으로 만든 QR 코드는 연결된 사람이 Slack 사용자 및 워크스페이스 ID와 함께 "via Slack"으로 표시됩니다. 소유자나 관리자가 **설정** → **API 키 및 앱**에서 Slack 계정 연결을 해제하면 개발자 항목에 기록됩니다.</IfAvailable>

각 항목에는 요청의 IP 주소와 기기(예: "Chrome on macOS" 같은 브라우저와 시스템)도 함께 저장됩니다. 결제에 따른 플랜 변경처럼 시스템이 하는 변경에는 둘 다 없습니다.

| 분류 | 기록되는 내용 |
| --- | --- |
| **QR 코드** | 생성(가져오기와 복사 포함), 대상 변경, 이름 변경, 디자인 변경, 단축 링크 변경, 링크 제어 변경(비밀번호 설정 또는 해제, 시작일과 종료일, 스캔 한도, 대체 URL), 라우팅 규칙 변경, 일시중지 또는 재개, 보관 또는 보관 해제, 휴지통으로 이동, 복원, 영구 삭제, 이전 버전 복원, 다른 폴더로 이동, 다른 워크스페이스로 이동하거나 다른 워크스페이스에서 이동. 폴더와 태그의 생성, 이름 변경, 삭제. |
| **페이지** | 생성, 게시, 삭제. |
| **팀** | 초대 발송과 취소, 초대나 참여 링크 또는 싱글 사인온으로 참여한 사람, 역할 변경, 제거된 사람, 탈퇴한 사람, 참여 링크의 켜기, 변경, 끄기. QRdx에서 했든 API로 했든 변경 방식에 관계없이 기록됩니다. |
| **보안** | "2단계 인증 필수"와 "싱글 사인온 필수"의 켜기 또는 끄기(싱글 사인온을 켜면 로그아웃된 세션 수도 함께 기록), 싱글 사인온 설정, 변경, 확인, 삭제, 새 사용자가 싱글 사인온으로 처음 로그인할 때 받는 역할, 감사 로그 내보내기. |
| **개발자** | API 키의 생성과 폐기(이름과 범위), 앱 승인 또는 해제, 웹훅 엔드포인트의 추가, 변경, 삭제, 웹훅 서명 시크릿 교체. 웹훅 URL의 나머지 부분은 비밀인 경우가 많으므로, 엔드포인트는 `https://hooks.zapier.com/…`처럼 서버만 기록됩니다. |
| **도메인** | 사용자 지정 도메인의 추가, 확인, 제거. |
| **워크스페이스** | 이름이나 URL 변경, 워크스페이스의 Business 전환("결제"로 기록). |

감사 로그에는 API 키, OAuth 토큰, 비밀번호, 웹훅 URL의 경로나 쿼리, 웹훅 서명 시크릿, 싱글 사인온 클라이언트 시크릿이나 인증서가 저장되지 않습니다. 생성, 교체, 제거되었다는 사실만 기록하고 값은 기록하지 않습니다.

사용자가 승인한 앱은 사용자 본인의 워크스페이스에서 동작하므로, 앱 승인과 해제는 해당 워크스페이스에 기록됩니다.

다음은 감사 로그에 없습니다.

- 스캔, 양식 응답, 분석 데이터: 워크스페이스에 대한 변경이 아닙니다(분석과 응답에서 확인하세요).
- 이름, 이메일, 2단계 인증처럼 본인 계정에 대한 변경.

## 로그 필터링 [#filter-the-log]

- **작업자**: 한 사람과 그 사람을 대신해 동작하는 API 키 및 앱.
- **분류**: QR 코드(폴더와 태그 포함), 페이지, 팀, 보안, 개발자, 도메인, 워크스페이스.
- **시작일**과 **종료일**: 표시할 첫날과 마지막 날입니다. 날짜는 UTC 기준이며, 각 항목의 시간은 사용자의 시간대로 표시됩니다.

## CSV로 내보내기 [#export-as-csv]

**CSV 내보내기**를 클릭하면 필터에 표시된 내용이 최신순으로 다운로드됩니다. 한 번에 최대 {facts.auditLogExportRows}개 항목을 내보낼 수 있습니다. 더 많이 내보내려면 날짜 범위를 줄여 나눠서 내보내세요.

파일에는 변경마다 한 행이 있고, UTC 기준 시간, 분류, 작업, 변경을 설명하는 문장, 변경한 사람(API 키나 앱이 있으면 함께), 대상, IP 주소, 기기, 이전 값과 새 값(JSON)이 담깁니다.

내보내기도 사용한 필터와 함께 기록됩니다.

## 항목 보관 기간 [#how-long-entries-are-kept]

항목은 {facts.auditLogRetentionDays}일 동안 보관된 뒤 삭제됩니다. 워크스페이스를 삭제하면 감사 로그도 함께 삭제됩니다.

감사 로그의 IP 주소와 기기 정보는 워크스페이스에서 일하는 사람들의 개인 정보입니다. QRdx가 이 정보를 처리하는 방식은 [개인정보 처리방침](/legal/privacy-policy)에서 확인하세요.

## 문제가 생겼나요? [#if-something-goes-wrong]

### 설정에 감사 로그가 없어요 [#audit-log-isnt-in-settings]

멤버, 뷰어, 결제 멤버이거나 워크스페이스가 Business가 아닌 경우입니다. 소유자나 관리자에게 문의하거나 [플랜과 포함 기능](/docs/help/account-and-billing/plans)을 참고하세요.

### 있어야 할 변경이 목록에 없어요 [#a-change-you-expect-isnt-listed]

워크스페이스가 Business가 되기 전에 일어난 변경이거나, {facts.auditLogRetentionDays}일이 지났거나, 스캔, 응답, 개인 계정 변경처럼 기록되지 않는 항목일 수 있습니다.
