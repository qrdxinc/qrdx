审计日志会列出成员在工作区中所做的更改：谁做的、改了什么、什么时候改的。这是 QRdx 商业许可下的 Business 功能。自托管的 QRdx 服务器需要许可证密钥（`QRDX_EE_LICENSE`）才能启用；参见[自托管](/docs/self-hosting#optional-services)。

<IfAvailable feature="auditLog">

<Callout type="info">
  审计日志属于 **Business** 套餐。只要工作区的某位所有者或账单成员订阅了 Business，该工作区就拥有此功能。只有**所有者**和**管理员**可以打开和导出审计日志。参见[席位与工作区限制](/docs/help/teams/seats)和[团队角色](/docs/help/teams/roles)。
</Callout>

## 打开审计日志 [#open-the-audit-log]

在工作区中进入 **Settings** → **Audit log**。最新的更改排在最前，每次显示 50 条；点击底部的 **Load more** 可查看更早的记录。点击某条记录上的箭头，可以查看旧值和新值，例如二维码原来的目标地址和新的目标地址。

<Shot id="audit-log" />

历史记录从工作区开通 Business 时开始。在此之前，或工作区使用其他套餐期间所做的更改不会被记录。如果工作区不再使用 Business，记录会停止；已保存的记录会保留，直到满 {facts.auditLogRetentionDays} 天，工作区重新使用 Business 后可以再次查看。

## 记录的内容 [#whats-recorded]

每条记录包含时间、更改者、更改的内容以及对象（二维码、页面、人员或域名）。更改者可以是某个人，也可以是代表某个人操作的 API 密钥或应用：通过 [REST API](/docs/developers/rest-api) 使用 API 密钥所做的更改会显示该密钥的名称，通过你授权的应用所做的更改会显示该应用的名称。<IfAvailable feature="slackBot"> 在 Slack 中用 `/qr track` 创建的二维码，会显示关联的人员并标注“via Slack”，同时附上 Slack 用户和工作区的 id。当所有者或管理员在 **Settings** → **API keys & apps** 中撤销某个 Slack 账号的关联时，该操作会记录在 Developers 类别下。</IfAvailable>

每条记录还会保存请求的 IP 地址和设备，即浏览器和系统，例如“Chrome on macOS”。由系统执行的更改（例如来自账单的套餐变更）则没有这两项。

| 类别 | 记录的内容 |
| --- | --- |
| **Codes** | 创建（包括导入和复制）、目标地址更改、重命名、设计更改、短链接更改、链接控制更改（密码开启或关闭、开始和结束日期、扫描次数上限、备用 URL）、路由规则更改、暂停或恢复、归档或取消归档、移入回收站、还原、永久删除、恢复到早期版本、移到其他文件夹、移入或移出其他工作区。文件夹和标签的创建、重命名或删除。 |
| **Pages** | 创建、发布、删除。 |
| **Team** | 发送和撤销邀请，通过邀请、加入链接或单点登录加入的成员，角色变更，移除成员，成员退出，以及加入链接的开启、更改或关闭。无论更改是在 QRdx 中还是通过其 API 完成，都会记录。 |
| **Security** | “Require two-step verification”和“Require single sign-on”的开启或关闭（开启单点登录时还会记录退出了多少个会话），单点登录的设置、更改、验证或移除，新成员首次通过单点登录登录时获得的角色，以及审计日志的导出。 |
| **Developers** | API 密钥的创建和撤销（包括其名称和权限范围），应用的授权或撤销，webhook 端点的添加、更改或删除，以及 webhook 签名密钥的更换。对于端点，日志只保留其服务器，例如 `https://hooks.zapier.com/…`，因为 webhook URL 的其余部分通常是保密的。 |
| **Domains** | 自定义域名的添加、验证或移除。 |
| **Workspace** | 名称或 URL 的更改，以及工作区升级到 Business（记录为“Billing”）。 |

审计日志绝不会保存 API 密钥、OAuth 令牌、密码、webhook URL 的路径或查询参数、webhook 签名密钥，也不会保存单点登录的客户端密钥或证书。它只记录这些内容被创建、更换或移除，而不记录其值。

你授权的应用是在你自己的工作区中操作的，因此授权或撤销应用会记录在该工作区中。

以下内容不在审计日志中：

- 扫描、表单回复和分析数据，它们不属于对工作区的更改（可在 Analytics 和 Responses 中查看）；
- 对你自己账号的更改，例如姓名、电子邮件或两步验证。

## 筛选日志 [#filter-the-log]

- **Who**：某一位成员，包括代表该成员操作的 API 密钥和应用。
- **Category**：Codes（包含文件夹和标签）、Pages、Team、Security、Developers、Domains 或 Workspace。
- **From** 和 **To**：要显示的第一天和最后一天。日期按 UTC 计算；每条记录上的时间按你所在的时区显示。

## 导出为 CSV [#export-as-csv]

点击 **Export CSV**，下载当前筛选条件下显示的内容，最新的在前。一次导出最多包含 {facts.auditLogExportRows} 条记录。如需导出更多，请每次导出较短的日期范围。

文件中每次更改占一行，包含：UTC 时间、类别、操作、一句话描述、更改者（如有 API 密钥或应用也会列出）、对象、IP 地址、设备，以及以 JSON 表示的旧值和新值。

导出操作本身也会被记录，并附带所用的筛选条件。

## 记录保留多久 [#how-long-entries-are-kept]

记录会保留 {facts.auditLogRetentionDays} 天，之后删除。删除工作区时，其审计日志也会一并删除。

审计日志中的 IP 地址和设备属于在工作区中工作的成员的个人数据。[隐私政策](/legal/privacy-policy)说明了 QRdx 如何处理这些数据。

## 出现问题时 [#if-something-goes-wrong]

### Settings 中没有 Audit log [#audit-log-isnt-in-settings]

你可能是成员、查看者或账单成员，或者工作区没有使用 Business。请联系所有者或管理员，或参见[套餐及其包含的功能](/docs/help/account-and-billing/plans)。

### 预期的更改没有列出 [#a-change-you-expect-isnt-listed]

这项更改可能发生在工作区开通 Business 之前，或已超过 {facts.auditLogRetentionDays} 天，又或者它属于扫描、回复或对个人账号的更改，这些都不会被记录。
