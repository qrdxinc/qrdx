Jeder [dynamische QR-Code](/docs/dynamic-qr-codes) erfasst Scans ohne Cookies. Das Tracking geht zwei Schritte weiter: Du lädst eigene Pixel auf den gehosteten Seiten, die deine Codes öffnen, und ordnest Conversions wie Käufe auf deiner Website dem Scan zu, der die Besucherin oder den Besucher gebracht hat. Nutze es, wenn QR-Traffic in den Tools auftauchen soll, die dein Team bereits verwendet, oder wenn du wissen willst, welche Codes Umsatz bringen.

<Callout type="info" title="Pixel in Pro, Conversions in Business">
  Tracking-Pixel sind Teil von Pro und Business; Conversion-Tracking ist Teil von Business. Beides richtest du im Tab **Einstellungen** des Codes ein. Siehe [Tarife und Limits](/docs/plans-and-limits).
</Callout>

Du hast es eilig? [Scans ansehen](/docs/help/dynamic-codes/scans) behandelt die Analytics, die jeder Tarif bietet.

## So funktioniert es [#how-it-works]

<Diagram id="tracking-paths" />

Ein Code öffnet entweder eine gehostete Seite oder leitet auf deine Website weiter, und jeder Weg hat sein eigenes Werkzeug. Auf einer gehosteten Seite steuert QRdx das HTML und kann deine Pixel laden, nachdem die Besucherin oder der Besucher zugestimmt hat. Auf deiner Website steuert QRdx nichts, daher übergibt es deiner Seite eine signierte Scan-ID in der URL, und deine Seite meldet zurück, wenn der Besucher konvertiert.

## Analytics für jeden Code [#analytics-on-every-code]

Neben Scans im Zeitverlauf, Ländern, Städten, Geräten, Betriebssystemen, Browsern und Referrern zeigt der Tab **Analytics** jedes Codes:

- **Wann Menschen scannen:** Scans nach Tageszeit und Wochentag, in UTC oder in deiner eigenen Zeitzone.
- **Sprachen:** die bevorzugte Browsersprache jedes Besuchers („Unbekannt“, wenn der Browser keine sendet).
- **A/B-Split:** Scans pro Variante für jede [A/B-Split-Regel](/docs/smart-routing#ab-tests).
- **Seitenaktivität** (gehostete Seiten): Seitenaufrufe, eindeutige Besucher, Taps sowie die am häufigsten angetippten Links und Buttons.
- **Conversions**, sofern der Code welche hat.

<Shot id="when-people-scan" />

**Codes** → **Analytics** in der Seitenleiste fasst alle Codes im Workspace zusammen: Summen, Scans im Zeitverlauf, Top-Codes, Länder, Geräte, Sprachen, Scan-Zeiten und einen Vergleich von bis zu 4 Codes nebeneinander. Bots und Link-Vorschauen werden nicht gezählt, ein Besucher zählt bei „eindeutig“ einmal pro Tag, und IP-Adressen werden nie gespeichert.

## Tracking-Pixel auf gehosteten Seiten [#tracking-pixels-on-hosted-pages-pro]

Für Codes, die eine gehostete Seite öffnen, lädt das Panel **Tracking-Pixel** im Tab **Einstellungen** des Codes deine eigenen Tags auf dieser Seite:

| Anbieter | ID-Format |
| --- | --- |
| Google Analytics 4 | `G-` gefolgt von 4 bis 20 Buchstaben und Ziffern |
| Meta-(Facebook-)Pixel | 6 bis 20 Ziffern |
| TikTok-Pixel | 10 bis 30 Buchstaben und Ziffern |
| LinkedIn Insight Tag | Partner-ID, 3 bis 12 Ziffern |

<Shot id="pixels-panel" />

Pixel werden nur geladen, wenn du sie einrichtest. Neben deinen Pixeln ist das einzige Skript auf einer gehosteten Seite der eigene Seitenaktivitäts-Zähler von QRdx, der Aufrufe und Taps an QRdx und sonst niemanden meldet.

<IfAvailable feature="customDomains">

**Google Tag Manager** (`GTM-` gefolgt von 4 bis 12 Buchstaben und Ziffern) wird nur geladen, wenn die Seite auf einer deiner [eigenen Domains](/docs/custom-domains) geöffnet wird. Ein Container kann beliebige Skripte ausführen, deshalb läuft er nie auf qrdx.dev, wo Besucher bei QRdx angemeldet sein können.

</IfAvailable>

### Einwilligung [#consent]

Pixel werden nie geladen, bevor die Besucherin oder der Besucher zustimmt:

- **Wo erforderlich (EU, EWR, UK, Schweiz, unbekannter Standort)**, die Standardeinstellung: Besucher dort sowie Besucher mit unbekanntem Standort sehen ein kurzes Banner mit deinen Anbietern und wählen **Akzeptieren** oder **Ablehnen**. Die Wahl wird für diese Seite gespeichert, und über **Cookie-Einstellungen** kann sie geändert werden. Anderswo werden Pixel sofort geladen, außer bei Browsern, die das Signal Global Privacy Control senden.
- **Für alle Besucher:** Alle sehen zuerst das Banner.

Du bleibst für deine eigene Datenschutzerklärung und für die Nutzung der Daten verantwortlich, die deine Pixel erfassen. Codes, die deine eigene Website öffnen, leiten direkt dorthin weiter, also füge deine Pixel stattdessen deiner Website hinzu.

## Conversion-Tracking [#conversion-tracking]

Conversion-Tracking zeigt dir, welche Scans zu einem Verkauf, einer Anmeldung oder einem anderen Ziel geführt haben, samt Umsatz. Es funktioniert für Codes, die deine Website öffnen.

1. Aktiviere im Tab **Einstellungen** des Codes **Conversion-Tracking**. Jeder Scan öffnet dann deine URL mit einem angehängten, signierten Parameter `qrdx_sid`, zum Beispiel `https://shop.example/?qrdx_sid=…`.
2. Füge das Snippet auf den Seiten ein, auf denen Besucher landen, und auf der Seite, auf der sie konvertieren:

```html title="Your website (before </body>)"
<script async src="https://qrdx.dev/conversions.js"></script>
<script>
  window.qrdx = window.qrdx || function () {
    (window.qrdx.q = window.qrdx.q || []).push(arguments);
  };
  // Where the conversion happens, for example your order confirmation page:
  qrdx("conversion", { name: "purchase", value: 49.99, currency: "USD", id: "ORDER-1234" });
</script>
```

Das Skript speichert `qrdx_sid` 30 Tage lang in einem First-Party-Cookie auf deiner Domain (füge dem Script-Tag `data-storage="session"` hinzu, um es nur für die Browsersitzung zu speichern) und entfernt es aus der Adressleiste. Conversions werden nur für Besucher gesendet, die über einen Scan gekommen sind, andere Besucher werden also nie getrackt.

| Feld | Bedeutung |
| --- | --- |
| `name` | Was passiert ist, zum Beispiel `purchase` oder `signup` (Standard `conversion`) |
| `value` | Betrag, bis zu 2 Dezimalstellen (optional) |
| `currency` | ISO-4217-Code wie `USD`; Standard ist `USD`, wenn ein Wert angegeben wird |
| `id` | Deine Bestell- oder Ereignis-ID: Wird dieselbe ID zweimal gesendet, wird sie nur einmal erfasst |
| `metadata` | Bis zu 20 zusätzliche Schlüssel-Wert-Paare (optional) |

### Limits [#limits]

- Ein Scan kann bis zu 30 Tage nach seinem Auftreten zugeordnet werden.
- `qrdx_sid` ist signiert, daher kann es weder erraten noch so geändert werden, dass es auf einen anderen Code zeigt.
- Meldungen aus dem Browser setzen voraus, dass Conversion-Tracking für den Code aktiviert ist, und jeder Scan kann bis zu 10 Conversions pro Stunde melden. Meldungen von deinem Server mit einem Token unterliegen keinem dieser Limits.
- Conversions werden nicht mehr erfasst, wenn der Workspace Business verlässt; bestehende bleiben in deinen Analytics, und das Tracking lässt sich jederzeit ausschalten.

| | Kostenlos | Pro | Business |

| Scan-Analytics, Scan-Zeiten, Sprachen, Seitenaktivität | Ja | Ja | Ja |

## Für Entwickler [#for-developers]

Um Conversions aus deinem Backend zu melden, was zuverlässiger ist als der Browser, speichere `qrdx_sid` zusammen mit der Bestellung und rufe [`POST /v1/conversions`](/docs/developers/api/create-conversion) mit einem [API-Schlüssel](/docs/developers/api-keys) oder einem OAuth-Token mit dem Scope `codes:write` auf:

```bash title="Terminal"
curl -X POST https://api.qrdx.dev/v1/conversions \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sid": "<qrdx_sid>", "name": "purchase", "value": 49.99, "currency": "USD", "id": "ORDER-1234"}'
```

Die API antwortet mit `201` für eine neue Conversion und mit `200` samt `"duplicate": true`, wenn die `id` bereits erfasst wurde. Mit einem Token kannst du außerdem `"code": "<code id>"` statt `sid` senden, wenn der Scan nicht bekannt ist.
