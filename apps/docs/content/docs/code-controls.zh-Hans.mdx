二维码控制决定一次对[动态二维码](/docs/dynamic-qr-codes)的扫描能否通过。如果二维码只应在一段时间内有效（如活动、促销），只对部分人开放（需要密码），或只能使用固定次数，又或者你想在不重新印刷的情况下关闭已印出的二维码，就可以使用这些控制。

<Callout type="info" title="暂停免费，其余为 Pro 功能">
  所有套餐都可以使用暂停功能。密码、开始和结束日期、扫描次数限制以及备用 URL 属于 Pro 和 Business。参见[套餐与限制](/docs/plans-and-limits)。
</Callout>

时间紧？请看简短的任务页面：[暂停、定时或限制二维码](/docs/help/dynamic-codes/pause-schedule-limit)和[用密码保护二维码](/docs/help/dynamic-codes/password)。

## 工作原理 [#how-it-works]

所有控制项都位于二维码**设置**标签页的**访问与计划**面板中（从[二维码](/dashboard?to=codes)打开该二维码）。每次扫描时，QRdx 会在跳转前按顺序检查各项控制：二维码是否已暂停、是否已开始、是否已结束、是否超过扫描次数限制、是否需要密码。第一个未通过的检查决定扫描者看到的内容。更改会在下一次扫描时生效，无需重新印刷二维码。

<Shot id="code-settings" />

| 控制项 | 扫描者看到的内容 | 套餐 |
| --- | --- | --- |
| 暂停 | 你的备用 URL，或中性的“此活动已暂停”页面 | 所有套餐 |
| 密码 | 密码页面；输入正确密码即可打开二维码 | Pro 和 Business |
| 开始时间 | 开始前：“此活动尚未开始” | Pro 和 Business |
| 结束时间 | 结束后：你的备用 URL，或“此活动已结束” | Pro 和 Business |
| 扫描次数限制 | 达到限制后：你的备用 URL，或“已结束”页面 | Pro 和 Business |
| 备用 URL | 已暂停、已结束和超出次数限制的二维码将用户带到的地址 | Pro 和 Business |

## 暂停 [#pause]

打开**暂停二维码**可让二维码暂时停用，例如在两场活动之间；关闭即可恢复。二维码的 **⋯** 菜单中也有**暂停**和**恢复**，二维码列表上的批量操作可一次暂停多个二维码。二维码暂停期间，如果你设置了备用 URL，扫描会跳转到该地址，否则会显示一个说明活动已暂停的简单页面。

## 密码 [#password]

设置 4 到 64 个字符的密码后，任何扫描该二维码的人都会先看到密码页面。输入正确密码后，该浏览器会保持解锁 6 小时，对短链接及其打开的托管页面都有效。更改密码会使所有用旧密码解锁的浏览器重新锁定；删除密码则会让所有人再次可以直接打开二维码。

<Shot id="scan-password" />

密码以 bcrypt 哈希形式存储，因此 QRdx 之后无法向你显示密码，只能替换。同一访问者反复输错密码会被限速。请把密码与二维码分开分享：同时拥有两者的人就能进入。

## 开始和结束日期 [#start-and-end-dates]

- **开始时间：**在此之前，扫描会显示“此活动尚未开始，请稍后再扫描此二维码。”开始前不会使用备用 URL。
- **结束时间：**从该时间起，扫描会跳转到你的备用 URL，或显示“此活动已结束”。

日期按你自己的时区输入，并以精确时刻存储，因此二维码在各地同一时刻结束。结束时间必须晚于开始时间。

## 扫描次数限制 [#scan-limit]

限制的计数方式与你的分析数据相同：不计入机器人和链接预览，同一地址在一分钟内的重复扫描只算一次。二维码达到限制后，之后的扫描会跳转到你的备用 URL 或“已结束”页面。提高或清除限制即可重新开放二维码。

## 备用 URL [#fallback-url]

已暂停、已结束和超出次数限制的二维码将用户带到的地址，例如你的首页或下一个活动。如果没有设置，扫描者会看到一个简单的中性页面。该页面从不显示广告、QRdx 推广或注册提示，只显示活动状态和一个**举报滥用**链接。备用 URL 会经过与目标地址相同的安全检查。

## 限制与套餐 [#limits-and-plans]

- 所有套餐都可以使用暂停。
- 设置或更改密码、日期、扫描次数限制或备用 URL 需要 Pro 或 Business。
- 降级不会使任何二维码结束或锁定。你在 Pro 期间设置的控制会继续按原配置生效，并且在任何套餐上你都可以删除其中任何一项。

## 链接安全检查 [#safety-checks-on-links]

保存时，QRdx 会检查每个目标地址和备用 URL：

- 被 [Google Web Risk](https://cloud.google.com/web-risk) 列为恶意软件、网络钓鱼或不受欢迎软件的链接会被拒绝（前提是服务器配置了 Web Risk 密钥）。如果 Web Risk 未能及时响应（大批量操作时可能出现），二维码会先创建，稍后再次查询其链接；如果此时 Web Risk 将其列入名单，该二维码会被关闭，并交由审核人员查看。
- `javascript:`、`data:` 及其他非网页链接会被拒绝。
- 账户创建后的前 7 天内，指向短网址服务、纯 IP 地址或相似字符（同形字）域名的二维码会以关闭状态保存，并**等待审核**。面板会显示相关提示；你无需做其他操作，审核通过后会由审核人员开启该二维码。
- 新账户每小时最多可创建 30 个动态二维码，付费套餐工作区则为每小时 {facts.newPaidAccountHourlyCodes} 个。超出后，错误信息会告知需要等待多少分钟，控制台导入会暂停到那时。

任何人都可以在 [qrdx.dev/report-abuse](/report-abuse) 举报二维码。经审核后被关闭的二维码对所有人都会失效，其所有者无法重新开启。参见[举报有害二维码](/docs/help/privacy-and-security/report-abuse)。

## 面向开发者 [#for-developers]

REST API 可以创建、更新和删除二维码，但不能设置控制项；这些设置只能在控制台中进行。API 响应中二维码的 `status` 会告诉你它是活动还是已归档。被控制项拦截的扫描不会作为 `scan.created` [webhook](/docs/webhooks) 事件发送，因为它们不会被记录为扫描。

## 自托管 [#self-hosting]

- `WEB_RISK_API_KEY`：已启用 Web Risk API 的 Google Cloud API 密钥。没有它，链接只会按上述离线规则检查。
- `SAFETY_YOUNG_ACCOUNT_DAYS`、`SAFETY_YOUNG_ACCOUNT_DYNAMIC_PER_HOUR` 和 `SAFETY_RECHECK_BATCH` 可更改 7 天、每小时 30 个二维码以及 Web Risk 重新检查的批量大小。
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` 和 `TURNSTILE_SECRET_KEY`：用于公开举报表单的 Cloudflare Turnstile（可选）。
- 解锁 Cookie 使用 `BETTER_AUTH_SECRET` 签名。

参见[自托管](/docs/self-hosting#optional-services)。
