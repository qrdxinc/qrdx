你在 QRdx 中创建的一切都属于某个工作区:动态二维码和[托管页面](/docs/landing-pages)、[文件](/docs/files)、[自定义域名](/docs/custom-domains)、文件夹和标签、表单回复、[webhook](/docs/webhooks)以及 API 密钥。工作区是团队、客户或项目存放二维码的地方,也决定了谁可以操作这些二维码。如果不同的人应该看到不同的二维码,可以使用多个工作区。

<Callout type="info" title="套餐与席位">
  每个套餐下,每个人都有自己的工作区。创建更多工作区和邀请成员需要 Pro(最多 3 名成员)或 Business(不限人数)。任何人都可以加入受邀的工作区,包括免费版用户。参见[套餐与限制](/docs/plans-and-limits)。
</Callout>

赶时间?可以看这几个简短的任务页面:[创建工作区并邀请成员](/docs/help/teams/create-and-invite)、[团队角色](/docs/help/teams/roles)和[席位与工作区限制](/docs/help/teams/seats)。

## 工作原理 [#how-it-works]

控制台的每个页面,其 URL 中都包含工作区(`/dashboard/<workspace>/…`)。使用侧边栏底部的工作区切换器来切换工作区(在手机上,则在菜单中);切换后你仍停留在同一个板块,例如所选工作区的二维码或 设置 → 域名。已保存的主题归你个人所有,所有者和管理员可以与工作区共享副本,让每位成员使用相同的配色进行设计。

## 你自己的工作区 [#your-own-workspace]

每个账号都有一个自动创建的专属工作区,你是它的所有者。它使用你的套餐。你可以重命名它并更改其 URL,但不能退出或删除它:只有在你[删除账号](/docs/help/account-and-billing/delete-your-account)时它才会一并消失。在 Pro 或 Business 上,你可以邀请他人加入其中,也可以只自己使用,并为每个团队或客户单独创建工作区。

## 创建另一个工作区 [#create-another-workspace]

1. 打开工作区切换器,点击 **创建工作区**。
2. 输入 **工作区名称** 和 **工作区 URL**(3 到 48 个小写字母、数字和连字符)。输入时 QRdx 会检查该 URL 是否可用;`codes` 和 `settings` 等少数词语为保留词。
3. 点击 **创建工作区**。工作区会打开,你是它的所有者。

## 邀请成员 [#invite-people]

所有者和管理员可以在工作区的 **设置** → **团队** 中邀请成员:

1. 输入对方的电子邮件地址并选择角色:**管理员**、**成员** 或 **查看者**。所有者还可以将对方邀请为 **账单**。
2. QRdx 会通过电子邮件向对方发送邀请。每个邀请也都有一个链接,你可以复制后自行发送。
3. 对方打开链接,使用受邀的电子邮件地址登录,然后点击 **接受邀请**。随后工作区会为其打开。

<Shot id="team-members" />

邀请他人为管理员时,会先要求你[确认是本人操作](/docs/help/privacy-and-security/two-step-verification#confirm-its-you),除非你在该浏览器中 10 分钟内已经确认过。

邀请在 48 小时后过期,并且只对收到邀请的电子邮件地址有效,因此转发的链接不能被其他人使用。待处理的邀请在被接受之前会占用一个席位,所以请撤销不再需要的邀请。

## 加入链接 [#join-link]

加入链接是面向整个团队的一个链接:只要还有空闲席位,任何已登录的人打开它就会加入工作区。所有者和管理员可在 Pro 和 Business 上于 **设置** → **团队** 中管理它:

1. 选择人们加入时获得的角色(默认为 **成员**;不能是所有者,只有所有者才能创建 **账单** 链接),然后点击 **创建加入链接**。以管理员身份添加成员的链接,会先要求你[确认是本人操作](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)。
2. 复制链接并分享。出于安全考虑,它只显示一次;QRdx 保存的是它的指纹,而不是链接本身。
3. 链接丢了,或者发到了不该去的地方?点击 **重置链接**:旧链接会失效,并生成一个新链接。**关闭** 则会永久停用它。

未登录的人需要先登录,再回到该链接。已经是成员的人会收到相应提示。席位用完后,将无法再加入,直到有席位空出。

## 角色 [#roles]

| | 查看者 | 账单 | 成员 | 管理员 | 所有者 |
| --- | --- | --- | --- | --- | --- |
| 查看二维码、页面和分析数据 | 是 | 是 | 是 | 是 | 是 |
| 创建和编辑二维码与页面、上传文件 | 否 | 否 | 是 | 是 | 是 |
| 删除二维码、文件和表单回复 | 否 | 否 | 仅限自己的 | 任意 | 任意 |
| 创建 API 密钥 | 否 | 否 | 是 | 是 | 是 |
| 查看并撤销所有人的 API 密钥 | 否 | 否 | 否 | 是 | 是 |
| 与工作区共享已保存的主题 | 否 | 否 | 否 | 是 | 是 |
| 邀请和移除成员、更改角色 | 否 | 否 | 否 | 是 | 是 |
| 重命名工作区、更改其 URL 和徽标 | 否 | 否 | 否 | 是 | 是 |
| 添加、验证和移除自定义域名 | 否 | 否 | 否 | 是 | 是 |
| 管理 webhook 端点并查看签名密钥 | 否 | 否 | 否 | 是 | 是 |
| 设置单点登录并查看审计日志(Business) | 否 | 否 | 否 | 是 | 是 |
| 升级工作区的套餐 | 否 | 是 | 否 | 否 | 是 |
| 创建和更改 OAuth 应用 | 否 | 否 | 否 | 否 | 是 |
| 将他人设为所有者或账单成员 | 否 | 否 | 否 | 否 | 是 |
| 删除工作区 | 否 | 否 | 否 | 否 | 是 |

查看者和账单成员只能读取:他们不能在工作区中创建、编辑或删除任何内容,而且 API 密钥的权限不会超过其创建者的角色。成员可以查看 webhook 端点及其投递日志,并可将工作区已验证的域名用于自己的二维码。[通知设置](/docs/notifications)是个人性质的:每位成员为每个工作区各自选择自己的提醒。

## 限制与套餐 [#limits-and-plans]

工作区使用其所有者和账单成员中最高的套餐,因此只要其中一人使用 Business,整个工作区就享有 Business 的限制,成员无需各自订阅。这正是 **账单** 角色的用途:为工作区付费但不参与管理的人。动态二维码、页面、存储空间和表单回复等限制按工作区计算。

| | 免费版 | Pro | Business |
| --- | --- | --- | --- |
| 更多工作区 | 否 | 是 | 是 |
| 席位(成员,含所有者,加上待处理的邀请) | 1 | 3 | 不限 |
| 加入链接 | 否 | 是 | 是 |
| 要求每位成员启用两步验证 | 否 | 否 | 是 |

如果所有者的套餐发生变化,现有成员会保留,所有二维码也会继续正常工作;只有新的邀请和超出限制的新内容会被阻止。参见[席位与工作区限制](/docs/help/teams/seats)和[要求两步验证](/docs/help/teams/require-two-step-verification)。

## 重命名、退出或删除工作区 [#rename-leave-or-delete-a-workspace]

这些操作位于工作区的 **设置** → **常规**。

- **重命名:** 所有者和管理员可以更改名称和 URL。指向旧 URL 的链接将失效;已印刷的二维码不受影响。
- **徽标:** 所有者和管理员可以上传徽标(需服务器已设置文件存储),或使用 https 图片 URL。徽标会显示在工作区切换器中;没有徽标时,切换器显示名称的首字母。
- **退出:** 在危险区域点击 **退出工作区**。最后一位所有者不能退出:请先将另一位成员设为所有者,或删除工作区。任何人都不能退出自己的工作区。
- **移除成员:** 在 **设置** → **团队** 中操作。他们创建的二维码和页面会保留在工作区中。任何人都不能从自己的工作区中被移除。移除成员与更改角色一样,会先要求你[确认是本人操作](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)。
- **删除工作区:** 仅限所有者,且不能删除任何人自己的工作区。你需要输入工作区 URL 来确认,QRdx 还会要求你确认是本人操作。不会有任何内容停止工作:二维码、页面、文件、域名和其他项目会转移到各自创建者自己的工作区。工作区的 API 密钥会随之删除。

## 将二维码移动到其他工作区 [#move-a-code-to-another-workspace]

在“二维码”页面中，打开该二维码的 **⋯** 菜单，选择 **移动到工作区...**，然后选取一个你有权创建二维码的工作区。短链接保持不变，因此已印刷的二维码仍可继续使用，其扫描数据和版本历史也会随之移动。它所在的文件夹和标签不会跟随移动，因为它们属于原工作区。

- 成员可以移动自己创建的二维码；所有者和管理员可以移动任何二维码。
- 目标工作区的套餐必须还有空间容纳一个新的活跃二维码。已归档的二维码不计入。
- 链接使用自定义域名的二维码无法移动，因为该域名属于原工作区，移动后其已印刷的链接将失效。打开托管页面的二维码会与其页面一同保留在原处。
- 如果某个工作区要求两步验证，在你开启两步验证之前，它不会出现在可选列表中。

## 面向开发者 [#for-developers]

使用 OAuth 访问令牌发出的 [REST API](/docs/developers/rest-api) 请求，作用于令牌所有者自己的工作区。[API 密钥](/docs/developers/api-keys)作用于创建它的工作区，并沿用其创建者在该工作区中的角色。来自已登录浏览器会话的请求，作用于请求中指定的工作区；如果未指定，则作用于该会话最后打开的工作区。
