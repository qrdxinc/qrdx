클라이언트 포털은 클라이언트를 대신해 QR 코드를 운영하는 에이전시를 위한 기능입니다. 이메일로 클라이언트를 초대하고 볼 수 있는 폴더를 선택합니다. 클라이언트는 워크스페이스의 포털에 로그인해 해당 폴더 안의 코드를 확인할 수 있으며, 각 코드의 스캔 분석과 호스팅 페이지가 있는 경우 해당 페이지로 가는 링크도 볼 수 있습니다. 포털의 모든 내용은 읽기 전용입니다. 클라이언트가 하나의 공유 리포트가 아니라 여러 코드를 시간에 따라 살펴보고 싶어 할 때 사용하세요.

<Callout type="info" title="Business">
  포털은 Business에 포함된 기능입니다. 클라이언트는 워크스페이스 멤버가 아니며 좌석을 차지하지 않습니다. [요금제와 한도](/docs/plans-and-limits)를 참고하세요.
</Callout>

## 작동 방식 [#how-it-works]

<Diagram id="client-portal-access" />

포털 주소는 `https://qrdx.dev/portal/<your workspace's URL name>`입니다. 클라이언트는 초대받은 이메일 주소로 전송된 일회용 코드로 들어갑니다. 처음 로그인하면 클라이언트 본인의 무료 QRdx 계정도 함께 만들어지지만, 이 계정을 사용할 필요는 없습니다. 포털에는 선택한 폴더만 에이전시의 이름, 로고, 색상과 함께 표시되며, 워크스페이스의 나머지 내용은 보이지 않습니다.

## 설정하기 [#set-it-up]

워크스페이스에서 **Settings** → **Client portal**을 엽니다. 소유자와 관리자가 관리할 수 있어요.

1. **Branding**에서 클라이언트에게 보일 이름을 입력하고, 로고를 추가하고, 강조 색상을 선택합니다. 비워 두면 워크스페이스 자체의 이름과 로고가 사용됩니다.
2. [Codes](/dashboard?to=codes)에서 클라이언트별로 코드를 각각의 폴더에 넣습니다.
3. **Clients**에서 클라이언트의 이메일 주소를 입력하고 폴더를 선택한 다음 **Invite client**를 클릭합니다.

<Shot id="client-portal" />

QRdx는 포털 이름으로 클라이언트에게 포털 링크를 이메일로 보냅니다. 사용 중인 서버에 이메일이 설정되어 있지 않다면 **Portal address**에서 주소를 복사해 직접 전달하세요.

선택한 폴더만 공유됩니다. 하위 폴더는 따로 선택하지 않으면 공유되지 않습니다.

## 클라이언트에게 보이는 내용 [#what-clients-see]

로그인하면 클라이언트는 다음을 볼 수 있습니다.

- 공유된 각 폴더와 그 안의 코드, 총 스캔 수, 마지막 스캔
- 각 코드의 시간별 스캔, 고유 방문자, QR 스캔과 NFC 탭, 상위 국가, 기기, 유입 사이트(최근 7일, 30일, 90일 또는 전체 기간)
- 호스팅 페이지를 여는 코드의 경우, 페이지를 여는 버튼(포털에서 페이지를 열어도 스캔으로 집계되지 않습니다)

다른 폴더, 휴지통에 있는 코드, 목적지의 전체 주소, 도시, 정확한 위치, 멤버, 설정, 결제 정보는 볼 수 없습니다. 포털에는 에이전시의 이름, 로고, 색상만 표시되며 QRdx 표시는 나타나지 않습니다.

초대하지 않은 주소로 로그인한 사람에게는 접근 권한이 없다는 안내가 표시됩니다. 초대는 처음 그 초대로 로그인한 계정에 귀속되므로, 클라이언트가 나중에 이메일을 바꿔도 계속 사용할 수 있습니다.

## 접근 권한 변경 또는 삭제 [#change-or-remove-access]

**Clients**에서 **Folders**는 클라이언트가 볼 수 있는 항목을 바꾸고, **Remove**는 접근 권한을 없앱니다. 둘 다 클라이언트가 다음에 페이지를 불러올 때 적용됩니다. 같은 주소를 다시 초대하면 폴더가 업데이트되고 링크가 다시 전송됩니다.

## 한도와 요금제 [#limits-and-plans]

워크스페이스가 Business에서 벗어나면 다시 Business가 될 때까지 포털이 열리지 않습니다. 그동안에도 클라이언트를 삭제할 수는 있습니다. 클라이언트는 멤버로 집계되지 않으므로 워크스페이스의 좌석을 사용하지 않습니다.

## 포털이 QRdx 주소에 있는 이유 [#why-the-portal-stays-on-qrdxs-address]

클라이언트는 QRdx 자체 사이트의 쿠키로 로그인 상태를 유지합니다. 로그인이 필요한 페이지를 에이전시의 도메인에서 제공하면, QRdx 외부에서 DNS를 관리하는 도메인에 로그인 쿠키가 놓이게 됩니다. 그래서 포털은 QRdx 주소에 있고 그곳에 에이전시의 브랜딩이 표시됩니다. 공유된 [클라이언트 리포트](/docs/client-reports)는 로그인이 필요 없으므로, Business에서는 에이전시의 도메인으로 제공할 수 있습니다.
