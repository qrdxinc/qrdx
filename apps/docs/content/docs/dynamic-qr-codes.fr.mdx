title: "QR codes dynamiques"
description: "Imprimez un QR code une seule fois, modifiez plus tard la destination vers laquelle il pointe, et suivez le nombre et le lieu des scans."
---

Un QR code dynamique encode un lien court tel que `https://qrdx.dev/q/aB3dE5f` plutôt que votre URL finale. Le scanner ouvre le lien court, qui redirige vers la destination que vous avez définie. Vous pouvez modifier la destination à tout moment : les codes imprimés ne deviennent jamais obsolètes, et chaque scan est comptabilisé. Utilisez-en un dès qu'un code figure sur un support que vous ne pouvez pas réimprimer à moindre coût : menus, emballages, affiches, cartes de visite.

<Callout type="info" title="Nécessite un compte QRdx">
  Les QR codes statiques du Playground et de la bibliothèque `qrdx` restent gratuits et illimités. Les codes dynamiques nécessitent un compte : Gratuit inclut 10 QR codes dynamiques actifs, Pro et Business n'ont aucune limite. Voir [Offres et limites](/docs/plans-and-limits).
</Callout>

Voici les pages de tâches courtes : [Créer un QR code dynamique](/docs/help/dynamic-codes/create), [Modifier la destination d'un code](/docs/help/dynamic-codes/change-the-link), [Consulter vos scans](/docs/help/dynamic-codes/scans) et [Archiver, supprimer et restaurer des codes](/docs/help/dynamic-codes/archive-and-delete).

## Fonctionnement [#how-it-works]

<Diagram id="dynamic-redirect" />

Le code imprimé ne change jamais : il contient le lien court. Quand quelqu'un le scanne, QRdx vérifie les paramètres du code (est-il en pause, planifié, protégé par mot de passe, routé selon l'appareil ou la localisation), enregistre le scan sans cookies, puis redirige vers la destination. Une modification de la destination, du design ou des paramètres prend effet au scan suivant.

## Créer un code [#create-a-code]

**Tableau de bord :** ouvrez [Codes](/dashboard?to=codes) et cliquez sur **New code**. La boîte de dialogue **New dynamic QR code** demande ce que le code ouvre : **Website link**, ou l'un des modèles de [page hébergée](/docs/landing-pages). Pour un lien, saisissez la **Destination URL** et un **Title** facultatif, puis créez le code. Téléchargez-le en PNG, WebP ou SVG depuis l'onglet **Overview** du code.

<Shot id="new-code-dialog" />

**Playground :** choisissez le type de contenu **URL**, saisissez votre lien et faites passer le lien de **Static** à **Dynamic**. Le QR code contient alors un lien court et conserve votre design. Si vous modifiez ensuite l'URL, cliquez sur **Point it to the new address** pour mettre à jour la destination. **Save design to code** enregistre le design actuel avec le code. Le menu **⋯** de la barre d'actions propose **Make it dynamic…** pour un code que vous avez conçu comme statique.

<Shot id="playground-content" />

Les destinations doivent être des liens `http://` ou `https://`. Les liens contenant un nom d'utilisateur ou un mot de passe, ainsi que les liens vers d'autres liens courts QRdx, sont rejetés. Chaque destination passe aussi par des [vérifications de sécurité](/docs/code-controls#safety-checks-on-links).

## Suffixes personnalisés [#custom-back-halves]

Chaque code reçoit un suffixe aléatoire de 7 caractères, la partie située après `/q/`. Avec Pro et Business, vous pouvez choisir le vôtre, par exemple `https://qrdx.dev/q/spring-menu` : renseignez **Custom back-half** lors de la création ou de la modification d'un code ; la boîte de dialogue vous indique en temps réel s'il est disponible.

- De 3 à 64 caractères : lettres, chiffres, `-` et `_`, sans commencer ni finir par `-`.
- Les suffixes respectent la casse, comme ceux générés : `Spring-Menu` et `spring-menu` sont deux liens différents.
- Sur `qrdx.dev`, un suffixe est unique dans tout QRdx, et les mots qui ressemblent à des pages de QRdx (`admin`, `api`, `docs`, `login`, `pricing`, `settings` et d'autres) sont réservés.
- Sur votre propre [domaine personnalisé](/docs/custom-domains), il doit seulement être unique sur ce domaine, et seuls quelques mots techniques (`api`, `_next`, `null`, `undefined`) sont réservés, donc `go.yourbrand.com/pricing` fonctionne. Un tel suffixe appartient au domaine : il n'a pas de lien `qrdx.dev/q/`.

Modifier le suffixe d'un code modifie son lien : les QR codes imprimés avec l'ancien cessent de fonctionner, téléchargez donc à nouveau le code.

## Gérer un code [#manage-a-code]

Ouvrez un code depuis [Codes](/dashboard?to=codes). Sa page comporte trois onglets : **Overview** (le lien court, le QR code et ses téléchargements, les totaux de scans, **Use with NFC** et des raccourcis vers ses options), **Analytics** et **Settings**. Au-dessus des onglets :

- **Edit link** modifie la destination ou le titre. Le code imprimé continue de fonctionner et ouvre la nouvelle destination au scan suivant.
- **Change type** transforme un lien de site web en [page hébergée](/docs/landing-pages), une page en lien, ou une page en un autre type de page. Le lien court et les scans sont conservés. Voir [Changer ce qu'ouvre un code imprimé](/docs/help/dynamic-codes/change-the-type).
- Le menu **⋯** contient **Edit design in playground** (l'éditeur s'ouvre avec le code toujours lié à son lien court), **Duplicate**, **Share analytics...**, **Move to folder...**, **Move to workspace...**, **Pause** ou **Resume**, **Archive** et **Move to trash**.

<Shot id="code-overview" />

**Duplicate** crée un nouveau code avec un nouveau lien court et sans scans. Il copie la destination, le design, le dossier, les tags, les notes et le type, ainsi que, si votre offre les inclut, les contrôles, le routage, les paramètres UTM et les pixels du code.

**Archive** conserve le code mais le désactive : le lien court affiche une page « This QR code is no longer active » jusqu'à sa restauration, et les codes archivés ne comptent pas dans la limite de votre offre. **Move to trash** fait de même et vous permet de supprimer définitivement le code depuis **Trash**, ce qui supprime aussi son historique de scans ; le lien court affiche alors une page « QR code not found ».

**Version history**, en bas de l'onglet **Settings**, enregistre chaque modification du code (jusqu'à 100 versions). Restaurer une version enregistre d'abord les paramètres actuels : une restauration peut donc être annulée.

## Organiser les codes [#organize-codes]

- **Folders** : les dossiers peuvent être imbriqués sur 5 niveaux. Faites glisser des codes sur un dossier ou utilisez **Move to folder...**. Supprimer un dossier remonte d'un niveau ses codes et ses sous-dossiers.
- **Tags** : ils filtrent la liste ; sélectionnez-en plusieurs pour voir les codes qui les ont tous.
- **Favoris et notes :** mettez des codes en favoris et gardez des notes privées ; les notes sont consultables par la recherche.
- **Search** couvre les titres, destinations, notes, tags et suffixes : coller un lien court permet donc de retrouver son code.
- **Actions groupées :** sélectionnez des codes pour les déplacer, les taguer, les mettre en pause, les archiver, les mettre en favoris, les mettre à la corbeille ou les télécharger sous forme de ZIP de fichiers PNG, WebP ou SVG.
- **Import CSV :** **Codes** → **Import** dans la barre latérale (ou **New code** → **Import codes** → **From a CSV file**) crée jusqu'à {facts.importRows} QR codes dynamiques à partir d'un seul fichier : destination, titre, dossier, tags et suffixe personnalisé facultatif dans une colonne `slug`. Vous pouvez classer tous les codes dans un même dossier et les taguer tous. Un long import peut être mis en pause, et il reprend après un rechargement ou une coupure de connexion sans créer aucun code en double. Il se termine par un CSV de résultats (le lien court de chaque ligne) et un ZIP des codes en PNG ou SVG. L'import de plus d'une ligne et les suffixes personnalisés nécessitent Pro.

## Qui peut faire quoi [#who-can-do-what]

Les codes appartiennent à l'espace de travail dans lequel ils sont créés. Les propriétaires, les administrateurs et les membres créent et modifient des codes ; les membres suppriment leurs propres codes, les propriétaires et administrateurs n'importe quel code ; les lecteurs et les membres de facturation peuvent seulement consulter. Les codes d'un espace de travail utilisent la meilleure offre parmi celles de ses propriétaires et de ses membres de facturation. Voir [Espaces de travail et équipes](/docs/teams).

## Analyses des scans [#scan-analytics]

L'onglet **Analytics** d'un code affiche les scans dans le temps, les visiteurs uniques, les scans de QR code et les touches NFC, les principaux pays et villes, les appareils, les systèmes d'exploitation, les navigateurs et les sources de provenance sur les 7, 30 ou 90 derniers jours, 1 an ou 3 ans, ou sur toute la période depuis le premier scan. Gratuit affiche {facts.freeScanHistoryYears} an ; Pro et Business affichent tout. **Export CSV** télécharge les scans de la période sélectionnée.

<Shot id="code-analytics" />

Chaque scan enregistre l'heure (UTC), le pays, la région et la ville issus du réseau, le type d'appareil, le système d'exploitation et le navigateur issus du user agent, ainsi que le nom d'hôte de la source de provenance. Au lieu d'une adresse IP, QRdx stocke un hash salé de l'adresse, du user agent et du jour, qui permet de compter les visiteurs uniques par jour et ne peut pas être reconverti en adresse. Les bots connus, les aperçus de liens et les préchargements du navigateur ne sont pas comptés. Avec Pro et Business, un code peut aussi [demander aux personnes qui le scannent leur position précise](/docs/precise-location). Liste complète : [Ce que QRdx enregistre lors d'un scan](/docs/help/privacy-and-security/scan-data).

  Passer à une offre inférieure ne désactive jamais les codes existants. ## Pour les développeurs [#rest-api]

Tout ce qui précède est disponible via la REST API sous `https://api.qrdx.dev/v1/codes`, avec une [clé d'API](/docs/developers/api-keys) ou un jeton OAuth disposant du scope `codes:read` ou `codes:write`.

- [Lister les codes](/docs/developers/api/list-codes), [créer des codes](/docs/developers/api/create-codes), [récupérer](/docs/developers/api/get-code), [mettre à jour](/docs/developers/api/update-code) et [supprimer](/docs/developers/api/delete-code) un code, et [consulter ses scans](/docs/developers/api/get-code-scans).
- Avec Pro et Business, `POST /v1/codes` accepte un tableau de {facts.apiBatchCodes} codes maximum dans une seule requête « tout ou rien », avec un en-tête `Idempotency-Key` pour qu'une nouvelle tentative ne crée jamais de doublons et `Prefer: return=minimal` pour omettre le design de chaque code. Les détails se trouvent sur [Créer des codes](/docs/developers/api/create-codes).
- `slug` choisit la fin du lien court, `domainId` un domaine personnalisé, `kind` bascule entre une redirection et une page, et `preciseLocation` active l'étape de localisation. Chaque code est renvoyé avec `shortLink`, `defaultShortLink` et `nfcLink`.
- Toutes les erreurs ont la même forme : consultez [Erreurs](/docs/developers/errors).

La page [REST API](/docs/developers/rest-api) explique l'authentification et les limites de débit ; le [démarrage rapide](/docs/developers/quickstart) crée votre premier code depuis le terminal.

## Auto-hébergement [#self-hosting]

Les codes dynamiques fonctionnent sur une instance auto-hébergée avec deux variables facultatives : `NEXT_PUBLIC_SHORT_LINK_BASE_URL` définit l'origine des liens courts (par défaut, l'URL de votre application) et `SCAN_HASH_SALT` définit le sel utilisé pour les hachages de visiteurs (sans elle, un sel est dérivé de `BETTER_AUTH_SECRET`). Le pays, la région et la ville proviennent des en-têtes de géolocalisation de Vercel ; derrière Cloudflare, seul le pays est lu, et ailleurs les localisations s'affichent comme inconnues. Les [règles par zone](/docs/precise-location#route-scans-by-area) utilisent les coordonnées IP de Vercel lorsqu'une personne qui scanne n'a pas partagé sa position ; hors Vercel, elles ne correspondent donc qu'aux positions partagées. Les limites de débit s'appliquent lorsque Upstash Redis est configuré. Consultez [Auto-hébergement](/docs/self-hosting#optional-services).
