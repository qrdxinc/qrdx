Mit verbundenen Konten kann der QR-Editor Links verwenden, die in deinen anderen Tools liegen: ein Kurzlink, den du in Bitly, Rebrandly oder Short.io verwaltest, oder ein Freigabelink zu einer Datei in Dropbox oder einem anderen Cloud-Speicher. Der QR-Code kodiert diesen Link, du behältst also das Tool, das du ohnehin nutzt. Nutze das, wenn deine Links in der Analytics dieses Tools bleiben müssen oder wenn der Code eine Datei öffnen soll, die du in einem Cloud-Speicher ablegst.

<Callout type="info" title="Jeder Plan">
  Verbundene Konten gehören zu deinem Benutzerkonto und funktionieren in jedem Plan. Wenn du das Ziel lieber direkt in QRdx bearbeiten möchtest, mit Scan-Analytics, nutze stattdessen einen [dynamischen QR-Code](/docs/dynamic-qr-codes).
</Callout>

## So funktioniert es [#how-it-works]

Verbinde ein Konto unter [Einstellungen → Integrationen](/settings/integrations). Es erscheint dann im QR-Editor beim Typ **URL**, im Menü **Link verwenden aus…** neben dem Feld **Website-Adresse**. Unter **Deine Konten** steht bei jedem Dienst, was er kann:

- **Kürzen**: Bitly, Rebrandly oder Short.io. Erstelle einen Link unter **Neu erstellen** oder wähle unter **Vorhandenen verwenden** einen, den du schon hast. Der QR-Code kodiert diesen Kurzlink. So kannst du später in diesem Dienst ändern, wohin er zeigt, und der Dienst zählt die Klicks.
- **Datei**: Dropbox<IfAvailable integration="onedrive">, OneDrive</IfAvailable><IfAvailable integration="box">, Box</IfAvailable><IfAvailable integration="notion">, Notion</IfAvailable>. Durchsuche oder suche, dann wähle eine Datei oder einen Ordner. QRdx erstellt den Freigabelink des Elements und der QR-Code kodiert ihn.

Dasselbe Menü listet deine anderen verbundenen Inhaltsquellen auf, etwa Zahlungs- und Buchungslinks. Dienste, die du noch nicht verbunden hast, findest du unten im Menü unter **Konto verbinden**.

<Shot id="use-a-link-from" />

Tokens und API-Schlüssel werden verschlüsselt gespeichert, und du kannst die Verbindung jederzeit trennen.

## Kurzlinks [#short-links]

| Dienst | So verbindest du | Domains | Back-Half |
| --- | --- | --- | --- |
| Bitly | Mit Bitly anmelden oder ein generisches Zugriffstoken einfügen (Settings → Developer settings → API) | bit.ly und deine Branded Domains | Von Bitly gewählt |
| Rebrandly | API-Schlüssel einfügen (Account → API keys) | rebrand.ly und deine Branded Domains | Dein eigener Slashtag oder zufällig |
| Short.io | Geheimen API-Schlüssel einfügen (Integrations & API → API) | Deine Short.io-Domains | Dein eigener Pfad oder zufällig |

Die Einstellungsseite jeder Integration zeigt deine Domains und lässt dich die Standarddomain für neue Links wählen. Du kannst pro Link trotzdem eine andere Domain wählen.

<Callout type="info" title="Ziel später ändern">
  QRdx erstellt den Link; das Ziel bearbeitest du in Bitly, Rebrandly oder Short.io. Bitly erlaubt das Ändern des Ziels eines Links nur in kostenpflichtigen Plänen.
</Callout>

## Dateiauswahl [#file-pickers]

**Dropbox** kodiert einen freigegebenen Link (neu erstellt oder der vorhandene wiederverwendet). Jeder mit dem Link kann ihn öffnen, außer dein Team erlaubt nur Team-Links.

<IfAvailable integration="onedrive">

**OneDrive** kodiert einen Freigabelink mit reinem Leserecht. Jeder mit dem Link kann ihn öffnen; nur deine Organisation kann das, wenn dein Admin „Jeder"-Links deaktiviert hat.

</IfAvailable>

<IfAvailable integration="box">

**Box** kodiert den freigegebenen Link des Elements, eingestellt auf „Personen mit dem Link". Jeder mit dem Link kann ihn öffnen; nur dein Unternehmen kann das, wenn dein Admin es verlangt.

</IfAvailable>

<IfAvailable integration="notion">

**Notion** kodiert den Link „Im Web veröffentlichen" der Seite. Jeder kann sie öffnen, sobald die Seite veröffentlicht ist.

</IfAvailable>

Wenn der Link nicht von allen geöffnet werden kann, sagt dir QRdx das direkt nach der Auswahl, damit ein gedruckter Code niemanden auf eine Anmeldeseite schickt.

<IfAvailable integration="notion">

**Notion-Seiten.** QRdx sieht nur die Seiten, die du mit ihm teilst: Notion fragt beim Verbinden, welche. Um später weitere hinzuzufügen, öffne die Seite in Notion, klicke auf **•••** → **Verbindungen** und füge QRdx hinzu (oder verbinde neu und wähle sie aus). Die API von Notion kann keine Seite veröffentlichen. Veröffentliche sie selbst (**Teilen** → **Veröffentlichen** → **Im Web veröffentlichen**) und wähle sie dann erneut aus, damit QRdx den öffentlichen Link verwendet.

</IfAvailable>

### Dateien auf gehosteten Seiten [#files-on-hosted-pages]

Gehostete Seiten können auch Cloud-Dateien nutzen: Die Blöcke für PDF, Audio, Video und Download bekommen neben der Upload-Schaltfläche eine Schaltfläche **Aus Dropbox**, wenn Dropbox dein einziger verbundener Speicher ist, oder **Aus Cloud-Speicher**, wenn du mehr als einen verbunden hast<IfAvailable integration="onedrive">, einschließlich OneDrive</IfAvailable><IfAvailable integration="box">, einschließlich Box</IfAvailable>. Bei Dropbox<IfAvailable integration="box"> und Box</IfAvailable> erhalten Seitenblöcke einen direkten Link zur Datei, damit Audio- und Videoplayer und der PDF-Viewer sie laden können.<IfAvailable integration="onedrive"> OneDrive-Freigabelinks öffnen den Viewer von OneDrive, deshalb zeigt ein Block sie als Link an.</IfAvailable>

## Verbindung trennen [#disconnecting]

Beim Trennen wird das gespeicherte Token gelöscht. Bei Dropbox<IfAvailable integration="box">, Box</IfAvailable><IfAvailable integration="notion">, Notion</IfAvailable> widerruft QRdx es zusätzlich beim Dienst. Bei Bitly, Rebrandly und Short.io löschst du den Schlüssel auch im jeweiligen Dienst, wenn du ihn nicht mehr nutzt<IfAvailable integration="onedrive">; bei OneDrive entfernst du QRdx aus den App-Berechtigungen deines Microsoft-Kontos</IfAvailable>.

Bereits erstellte QR-Codes funktionieren weiter: Sie enthalten den Kurzlink oder Freigabelink, nicht dein Token.

## Limits und Pläne [#limits-and-plans]

Verbundene Konten haben kein eigenes Plan-Limit. Die Links, die sie erstellen, sind aus Sicht von QRdx statisch: QRdx zählt ihre Scans nicht und kann auch nicht ändern, wohin sie zeigen. Der jeweilige Plan des Dienstes bestimmt, was du dort mit dem Link tun kannst.

## Self-Hosting [#self-hosting]

Rebrandly und Short.io brauchen nichts auf dem Server. Die anderen brauchen eine App im jeweiligen Dienst, deren Client-ID und Secret in der Umgebung gesetzt sind; ohne sie ist die Integration in der Produktion ausgeblendet (in der lokalen Entwicklung erscheint ein Badge **Einrichtung nötig**). Bitly funktioniert auch ohne sie, über eingefügte Zugriffstokens.

| Integration | Variablen | Redirect-URI |
| --- | --- | --- |
| Bitly (Anmeldung) | `BITLY_CLIENT_ID`, `BITLY_CLIENT_SECRET` | `<app url>/api/integrations/bitly/callback` |
| Dropbox | `DROPBOX_CLIENT_ID`, `DROPBOX_CLIENT_SECRET` | `<app url>/api/integrations/dropbox/callback` |
| OneDrive | `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET` | `<app url>/api/integrations/onedrive/callback` |
| Box | `BOX_CLIENT_ID`, `BOX_CLIENT_SECRET` | `<app url>/api/integrations/box/callback` |
| Notion | `NOTION_CLIENT_ID`, `NOTION_CLIENT_SECRET` | `<app url>/api/integrations/notion/callback` |

`<app url>` ist in der Entwicklung `http://localhost:3000`, sonst deine Produktions-URL. Jede Integration braucht in der Produktion außerdem `INTEGRATION_ENCRYPTION_KEY`, der gespeicherte Tokens und Schlüssel verschlüsselt.

Anzufragende Scopes:

- **Dropbox:** `account_info.read`, `files.metadata.read`, `sharing.read`, `sharing.write`
- **OneDrive:** `offline_access`, `Files.ReadWrite` (Microsoft Graph braucht Schreibzugriff, um Freigabelinks zu erstellen)
- **Box:** Alle Dateien und Ordner lesen und schreiben (`root_readwrite`)
- **Bitly, Notion:** keine Scopes; Notion fragt den Benutzer, welche Seiten geteilt werden sollen

Siehe [Self-Hosting](/docs/self-hosting#optional-services).
