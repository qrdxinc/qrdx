O QRdx importa links e códigos dinâmicos de outros provedores de uma só vez, para você migrar sem reimprimir o que já está em circulação. Toda importação segue os mesmos três passos: escolher o que trazer, ver a prévia e importar. Use este guia quando você tem códigos em outro serviço e quer poder editá-los e acompanhá-los no QRdx.

<Callout type="info" title="Planos">
  A importação funciona em todos os planos, dentro do limite de códigos ativos do seu plano. Manter os back-halves originais exige Pro ou Business. Veja [Planos e limites](/docs/plans-and-limits).
</Callout>

Com pressa? Veja a página curta com a tarefa: [Traga códigos de outro serviço](/docs/help/dynamic-codes/import).

## Como funciona [#how-it-works]

<Diagram id="import-flow" />

Abra [Códigos](/dashboard?to=codes), depois o menu **⋯** → **Importar códigos** → **Do Bitly e de outros apps**. Há dois tipos de origem:

- **Contas conectadas:** Bitly, Rebrandly e Short.io. O QRdx lista seus links pela API do provedor.
- **Arquivos de exportação:** QR Code Generator PRO, Uniqode (Beaconstac), Flowcode, QR TIGER, ME-QR, TinyURL, Hovercode, Scanova ou qualquer CSV com URLs de destino.

Nada muda na sua conta antiga durante a importação em si.

### O que uma importação cria [#what-an-import-creates]

Cada link ou código vira um [QR code dinâmico](/docs/dynamic-qr-codes) com:

- o destino e o título;
- as tags (opcional) e uma pasta como "Imported from Bitly" (você pode renomeá-la ou desativá-la);
- notas como `Imported from Bitly bit.ly/3AbCdEf on 2026-11-01.` mais a data de criação original do link. O QRdx define a própria data de criação para o novo código.

A prévia mostra quantos códigos serão criados, quais tags são novas e o que será ignorado:

- **Já importado:** links importados antes (em qualquer execução anterior) são sempre ignorados, então rodar a importação duas vezes nunca cria duplicatas.
- **Já existe o mesmo destino:** links cujo destino já tem um código no QRdx são ignorados por padrão. Marque a opção para importá-los mesmo assim.
- **Acima do limite do plano:** links que não cabem nos códigos ativos do seu plano. A prévia oferece importar os primeiros que couberem ou fazer upgrade.
- **Não pode importar:** destinos ausentes ou inválidos e links que já apontam para um link curto do QRdx.

As importações rodam em lotes de 50, com barra de progresso. Fechar a janela é seguro: abra o importador de novo e a importação continua em **Importações recentes**. O resumo lista os códigos criados, ignorados e com falha, com os motivos.

## De uma conta conectada [#from-a-connected-account]

1. Escolha o provedor. Se ele ainda não estiver conectado, conecte ali mesmo (faça login ou cole uma chave de API ou token). Os tokens são armazenados criptografados, e você pode desconectar em [Configurações → Integrações](/settings/integrations).
2. Pesquise, filtre por domínio ou tag e selecione os links. **Selecionar todos os links correspondentes** pega até 1.000 links por importação; rode de novo para o restante.
3. Confira a prévia e clique em **Importar**.

| Provedor | Conectar com | Listar links | Manter códigos impressos funcionando |
| --- | --- | --- | --- |
| Bitly | Login ou um token de acesso genérico | Sim | Somente planos pagos do Bitly: 5 redirecionamentos de link por mês no Core, 20 no Growth, 110 no Premium |
| Rebrandly | Chave de API | Sim | Dentro das edições mensais de destino do Rebrandly: 10 no Essentials, 50 no Professional, 150 no Growth (nenhuma no Grátis) |
| Short.io | Chave de API | Sim, um domínio por vez | Sim, em todos os planos |

Os limites dos planos são dos próprios provedores e mudam com o tempo. Confira as páginas de preços deles.

## Mantenha os códigos impressos funcionando [#keep-printed-codes-working]

Os QR codes que você imprimiu com outro provedor codificam o link curto desse provedor. Depois de uma importação por conta conectada, o resumo oferece **Manter meus códigos impressos funcionando**:

1. Um **teste** lista cada link antigo e o link do QRdx para o qual ele apontaria. Nada muda ainda.
2. Confirme, e o QRdx muda o destino de cada link antigo para o novo código do QRdx. Os visitantes continuam chegando na mesma página, e cada leitura passa a aparecer nas análises do QRdx. O provedor antigo ainda registra um clique primeiro.
3. **Desfazer** restaura os destinos originais, que o QRdx salvou junto com a importação.

Se o provedor recusar (por exemplo, um plano do Bitly sem redirecionamentos de link restantes), o QRdx para, explica o motivo e deixa os links restantes sem alteração. Os links ignorados porque o destino já tinha um código no QRdx apontam para esse código existente.<IfAvailable feature="customDomains"> Os links cujo back-half acompanha seu próprio domínio (abaixo) não são alterados: depois da troca de DNS, eles passam a ser o link do QRdx.</IfAvailable>

<Callout type="warn" title="Por enquanto, mantenha a conta antiga">
  Mantenha o provedor conectado até ter certeza: desfazer depende da conexão. A conta antiga também precisa continuar ativa para que os links dela continuem redirecionando.
</Callout>

## Mantenha os back-halves originais [#keep-the-original-back-halves]

No Pro e no Business, marque **Manter os back-halves originais** na prévia da importação. Assim, cada código recebe o back-half antigo em vez de um aleatório sempre que o QRdx puder mantê-lo, e `bit.ly/spring-menu` vira `qrdx.dev/q/spring-menu`:

- Um back-half é mantido quando tem de 3 a 64 letras, dígitos, `-` ou `_`, não começa nem termina com `-` (veja [back-halves personalizados](/docs/dynamic-qr-codes#custom-back-halves)), não é reservado e ainda não é usado em `qrdx.dev` por nenhum código do QRdx<IfAvailable feature="customDomains"> (no seu próprio domínio, apenas pelos seus códigos nele)</IfAvailable>.
- Caso contrário, o código recebe um back-half gerado, e a prévia mostra a mudança com o motivo, por exemplo `spring-menu → Ab3xK9q · Another QRdx code already uses this back-half on qrdx.dev`. A importação usa exatamente o back-half que a prévia mostra.
- Os back-halves diferenciam maiúsculas de minúsculas, como no Bitly e no Short.io.

Os back-halves que não podem ser mantidos recebem um gerado; esses links precisam ser reimpressos ou ter um redirecionamento no provedor antigo.

<IfAvailable feature="customDomains" id="your-own-domain-go-yourbrand-com" title="Seu próprio domínio (go.yourbrand.com)">

Se seus links usam seu próprio domínio, você pode mover esse domínio para o QRdx e manter os back-halves, de modo que `go.yourbrand.com/spring-menu` continue funcionando depois da troca de DNS.

1. Primeiro, adicione o domínio em **Configurações** → **Domínios**. Ele pode ficar sem verificação por enquanto: os back-halves são mantidos no próprio domínio, onde só precisam ser únicos entre os seus códigos, e apenas algumas palavras técnicas são reservadas.
2. Na prévia da importação, marque **Manter os back-halves originais** e escolha o domínio em **Links em**. A prévia mostra quais back-halves serão mantidos.
3. Importe. Os códigos vão para o domínio e reservam seus back-halves imediatamente.
4. Aponte o DNS do domínio para o QRdx e verifique-o (veja [Domínios personalizados](/docs/custom-domains)). Faça isso em um horário tranquilo: os links do domínio deixam de funcionar no provedor antigo assim que o DNS muda e passam a funcionar no QRdx quando ele é verificado.

Se o domínio ainda não estiver no QRdx quando você importar, os back-halves dele são mantidos em `qrdx.dev` (onde precisam estar livres em todo o QRdx). Depois de adicionar e verificar o domínio, clique em **Anexar códigos** no resumo da importação para mover esses códigos para ele.

</IfAvailable>

## A partir de um arquivo de exportação [#from-an-export-file]

1. Obtenha o arquivo (passos abaixo). O QRdx lê CSV de até 2 MB e 1.000 linhas por execução; se for um arquivo do Excel, salve ou baixe como CSV antes.
2. No importador, escolha o provedor e envie o arquivo. O QRdx reconhece as colunas do provedor sempre que possível, e você pode alterar o mapeamento. Só o destino é obrigatório; o link curto antigo (ou o ID do código) permite que um novo envio ignore os códigos já importados.
3. Visualize e importe; depois use **Copiar todos os novos links** ou **Baixar CSV de mapeamento** (link antigo → novo link do QRdx).

O QRdx não consegue alterar códigos que ficam no domínio do próprio provedor. Para manter os códigos impressos funcionando, abra cada QR code dinâmico antigo no provedor antigo e defina o destino como o novo link do QRdx que está no mapeamento. A conta antiga precisa continuar ativa para que esses códigos redirecionem; reimprima com os códigos do QRdx antes de cancelar.<IfAvailable feature="customDomains"> Códigos em um domínio que você possui podem ir junto com o domínio, sem reimpressão: veja [Seu próprio domínio](#your-own-domain-go-yourbrand-com) acima.</IfAvailable>

### QR Code Generator PRO [#qr-code-generator-pro]

Não há exportação documentada da lista de códigos. Monte uma planilha com **Nome**, **URL curta** e **URL de destino** para cada código. Para redirecionar os códigos: abra o código → **Detalhes** → **Editar**, troque a URL e salve. Para muitos códigos, a atualização em massa do provedor aceita um CSV com novas URLs para até 500 códigos.

### Uniqode (Beaconstac) [#uniqode-beaconstac]

**QR Codes → Dynamic**, selecione tudo, **⋯ → Export**, por organização ou pasta. As colunas da exportação (QR Code Name, QR Code URL, Destination URL, Labels e outras) são reconhecidas. Para redirecionar: abra o código → **Edit** → nova URL → **Next** → **Save**.

### Flowcode [#flowcode]

O Flowcode exporta apenas códigos que estão em uma pasta, então mova seus códigos para pastas primeiro. Depois abra a seção **Folder**, marque as pastas e clique em **Download URLs**. As colunas do CSV (Flowcode Name, Short Links, Scan Destination) são reconhecidas, assim como as de uma planilha de criação em massa (Flowcode Name, Flowcode Scan URL). Para redirecionar: **Assets** → o código → **Overview** → **Destination** → **Save**.

### QR TIGER [#qr-tiger]

**My Account** → escolha uma categoria (por exemplo, URL) → **Download QR List**, uma vez por categoria. Para redirecionar: **My Account → Dashboard → URL** → a campanha → **Edit** → **Save**.

### ME-QR [#me-qr]

Não há exportação. Liste o nome, o link do QR e a URL de destino de cada código. Para redirecionar: edite o código na lista de códigos do ME-QR.

### TinyURL [#tinyurl]

O TinyURL oferece exportação em CSV nos planos pagos. Exporte seus links em CSV ou liste o alias e a URL longa. Editar o destino de um link do TinyURL exige um plano pago do TinyURL.

### Hovercode, Scanova e outros [#hovercode-scanova-and-others]

Exporte seus códigos em CSV pelo provedor (o Hovercode oferece exportação em CSV nos planos Business; o Scanova envia um link de download por e-mail) e depois confira o mapeamento das colunas. Qualquer CSV com uma coluna de destino funciona com **Outro provedor (CSV)**.

QR codes estáticos (do goQR.me, QR Code Monkey, Adobe Express e ferramentas parecidas) codificam o próprio destino, então continuam funcionando sem a ferramenta. Importe os destinos deles de um CSV só se quiser códigos editáveis e com acompanhamento para novas impressões.

## A partir de uma biblioteca de QR code [#from-a-qr-code-library]

As bibliotecas geram QR codes estáticos, então não há nada para migrar: os códigos já impressos continuam funcionando. Para trocar a renderização no seu app, instale `qrdx` e substitua o componente.

### De qrcode.react [#from-qrcode-react]

```tsx title="Before and after"
// Before
import { QRCodeSVG } from "qrcode.react";

<QRCodeSVG value="https://example.com" size={256} fgColor="#111827" />;

// After
import { QRCodeSVG } from "qrdx";

<QRCodeSVG
  value="https://example.com"
  size={256}
  fgColor="#111827"
  bodyPattern="rounded"
/>;
```

`value`, `size`, `level`, `fgColor`, `bgColor`, `marginSize` (como `margin`) e `imageSettings` continuam valendo; o qrdx acrescenta padrões, gradientes e modelos. Veja a [referência da API](/docs/api-reference).

### De qr-code-styling [#from-qr-code-styling]

```tsx title="Before and after"
// Before
import QRCodeStyling from "qr-code-styling";

const qr = new QRCodeStyling({
  data: "https://example.com",
  width: 256,
  dotsOptions: { type: "rounded", color: "#111827" },
  image: "/logo.png",
});
qr.append(ref.current);

// After
import { QRCodeSVG } from "qrdx";

<QRCodeSVG
  value="https://example.com"
  size={256}
  bodyPattern="rounded"
  fgColor="#111827"
  imageSettings={{ src: "/logo.png", width: 64, height: 64, excavate: true }}
/>;
```

O qrdx é um componente React, então não há instância para anexar: renderize-o como qualquer elemento. Os downloads usam os helpers da [referência da API](/docs/api-reference).

## Para desenvolvedores [#for-developers]

Para migrar os códigos com um script, crie-os pela [API de códigos](/docs/developers/api/create-codes): até {facts.apiBatchCodes} por requisição no Pro e no Business, com `slug` para o final do link que você quer manter e um `Idempotency-Key` para que uma nova tentativa nunca duplique um lote.
