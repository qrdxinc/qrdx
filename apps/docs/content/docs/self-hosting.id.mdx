Di akhir panduan ini, QRdx akan berjalan di URL Anda sendiri: editor QR, akun, kode QR dinamis dengan analitik pemindaian, halaman yang di-hosting, workspace, dan tema tersimpan, dengan database Postgres yang Anda kendalikan. Jalur Docker Compose memakan waktu sekitar setengah jam, sebagian besar untuk build image pertama.

Aplikasi web ini bersifat open source di bawah lisensi AGPL-3.0. Dua bagian tidak termasuk: single sign-on workspace dan log audit berada di folder `ee/` di bawah lisensi komersial QRdx, dan tetap nonaktif kecuali Anda mengatur kunci lisensi (`QRDX_EE_LICENSE`). Penggunaannya di produksi memerlukan perjanjian tertulis dengan QRdx; lihat [LICENSING.md](https://github.com/qrdxinc/qrdx/blob/main/LICENSING.md). Anda tidak memerlukan semua ini untuk memakai [pustaka React `qrdx`](/docs/getting-started) atau [CLI](/docs/developers/cli): keduanya berjalan di mana saja tanpa backend, di bawah lisensi MIT. [Open source di QRdx](/open-source-qr-code-generator) mencantumkan setiap bagian repositori beserta lisensinya.

<Callout type="warn" title="Pengaturan Docker masih baru">
  Jika suatu langkah tidak berfungsi seperti yang tertulis, [buat issue](https://github.com/qrdxinc/qrdx/issues) beserta perintah yang Anda jalankan dan outputnya.
</Callout>

## Sebelum memulai [#before-you-start]

- Docker dengan Compose v2 dan BuildKit (Docker Desktop dan Docker Engine terbaru sudah menyertakan keduanya), atau Node.js 22 (22.22.3 atau lebih baru) dan [Bun](https://bun.com/docs/installation) 1.4 untuk pengaturan manual.
- Memori minimal 8 GB untuk Docker selama image di-build.
- Cara untuk masuk, agar akun dapat dibuat: aplikasi OAuth GitHub atau Google, atau [Resend](https://resend.com) untuk kode masuk lewat email. Kode masuk hanya dikirim lewat email jika `NEXT_PUBLIC_APP_URL` bukan `localhost`. `bun run dev` menampilkannya di terminal, tetapi image Docker tidak, jadi uji coba Docker lokal memerlukan masuk lewat GitHub atau Google.
- Postgres: container yang disertakan di `docker-compose.yml`, atau database [Neon](https://neon.tech).
- Untuk penggunaan selain uji coba lokal, diperlukan domain dan reverse proxy yang mengakhiri HTTPS.

Dokumentasi bukan bagian dari instance self-hosted. Instance Anda mengarahkan setiap tautan dokumentasi (`/docs` dan halaman di bawahnya, salinan Markdown-nya, dan `/llms-full.txt`) ke halaman yang sama di qrdx.dev.

### Cara kerja koneksi database [#how-the-database-connection-works]

Aplikasi berkomunikasi dengan Postgres melalui driver HTTP serverless milik Neon.

- **Neon:** langsung berfungsi. Atur `DATABASE_URL` ke connection string Neon Anda.
- **Postgres biasa:** memerlukan proxy HTTP yang kompatibel dengan Neon di depannya. `docker-compose.yml` menjalankan satu ([local-neon-http-proxy](https://github.com/TimoWilhelm/local-neon-http-proxy)) dan mengatur `DATABASE_HTTP_ENDPOINT` agar aplikasi mengirim kuerinya ke sana.

Skema berasal dari `packages/database/schema.ts` dan diterapkan dengan `drizzle-kit push`. Tidak ada file migrasi yang perlu dijalankan secara manual.

## Mulai cepat dengan Docker Compose [#quick-start-with-docker-compose]

### 1. Clone repositori [#1-clone-the-repository]

```bash title="Terminal"
git clone https://github.com/qrdxinc/qrdx.git
cd qrdx
```

### 2. Konfigurasikan environment [#2-configure-the-environment]

Salin file contoh ke root repositori, tempat Compose membacanya, lalu buat session secret:

```bash title="Terminal"
cp apps/app/.env.example .env
openssl rand -base64 32
# prints a 44-character string: paste it as BETTER_AUTH_SECRET below
```

Buka `.env` dan atur nilai-nilai berikut. Baris lainnya boleh tetap dijadikan komentar.

```bash title=".env"
NEXT_PUBLIC_APP_URL=https://qr.example.com
BETTER_AUTH_URL=https://qr.example.com
BETTER_AUTH_SECRET=<the string openssl printed>

# One sign-in provider. The callback URL for GitHub is
# <NEXT_PUBLIC_APP_URL>/api/auth/callback/github
GITHUB_CLIENT_ID=<client ID of your GitHub OAuth app>
GITHUB_CLIENT_SECRET=<its client secret>
```

Asal setiap nilai:

| Variabel | Dari mana mendapatkannya |
| --- | --- |
| `NEXT_PUBLIC_APP_URL` | URL publik instance Anda, tanpa garis miring di akhir. Gunakan `http://localhost:3000` untuk uji coba lokal. |
| `BETTER_AUTH_URL` | Nilai yang sama. Hapus tanda komentar pada baris ini. |
| `BETTER_AUTH_SECRET` | Output dari `openssl rand -base64 32`. |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | [Aplikasi OAuth GitHub](https://github.com/settings/developers) dengan callback URL `<your url>/api/auth/callback/github`. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Sebagai pengganti GitHub: [klien OAuth Google](https://console.cloud.google.com/apis/credentials) dengan redirect URI `<your url>/api/auth/callback/google`. |

Biarkan `DATABASE_URL` apa adanya: Compose mengarahkan aplikasi ke container Postgres miliknya sendiri dan mengabaikan nilai di `.env`. Untuk mengubah kata sandi database, atur `POSTGRES_PASSWORD` sebelum start pertama.

### 3. Jalankan stack [#3-start-the-stack]

```bash title="Terminal"
docker compose up -d --build
```

Perintah ini membangun image, menjalankan Postgres dan proxy, menjalankan layanan sekali jalan `migrate` (`drizzle-kit push`), lalu menjalankan aplikasi di port 3000. Build pertama memakan waktu beberapa menit. Setelah selesai, keempat layanan terlihat seperti ini:

```text title="docker compose ps (columns trimmed)"
NAME              SERVICE    STATUS
qrdx-db-1         db         running (healthy)
qrdx-db-proxy-1   db-proxy   running
qrdx-migrate-1    migrate    exited (0)
qrdx-app-1        app        running
```

`migrate` memang dirancang untuk berhenti: ia menyinkronkan skema lalu berhenti. Untuk melihat sinkronisasi skema dan proses start aplikasi:

```bash title="Terminal"
docker compose logs -f migrate app
```

### 4. Masuk [#4-sign-in]

Buka `NEXT_PUBLIC_APP_URL` di browser dan masuk dengan GitHub, Google, atau kode email. Akun Anda dibuat saat pertama kali masuk.

### 5. Jadikan diri Anda admin [#5-make-yourself-an-admin]

Tambahkan alamat email akun yang Anda buat di langkah 4 ke `.env`:

```bash title=".env"
ADMIN_EMAILS=you@example.com
```

Buat ulang container aplikasi agar membaca perubahan tersebut, lalu masuk dan buka `/admin`:

```bash title="Terminal"
docker compose up -d app
```

Alamat tersebut menjadi admin saat pertama kali membuka `/admin`. `ADMIN_USER_IDS` bekerja dengan cara yang sama menggunakan ID pengguna.

## Gunakan Neon atau Postgres terkelola lainnya [#use-neon-or-another-managed-postgres]

Anda dapat melewati Postgres bawaan dan hanya menjalankan image aplikasi. Atur `DATABASE_URL` di `.env` ke connection string Neon Anda dan biarkan `DATABASE_HTTP_ENDPOINT` tidak diatur.

```bash title="Terminal"
docker build -t qrdx --build-arg NEXT_PUBLIC_APP_URL=https://qr.example.com .
docker run -d --env-file .env -p 3000:3000 qrdx
```

Terapkan skema sekali, dan lagi setelah setiap pembaruan, dengan image migrator:

```bash title="Terminal"
docker build --target migrator -t qrdx-migrate .
docker run --rm -e DATABASE_URL="<your connection string>" qrdx-migrate
```

## Pengaturan manual dengan Node.js [#manual-setup-with-nodejs]

```bash title="Terminal"
git clone https://github.com/qrdxinc/qrdx.git
cd qrdx
bun install

cp apps/app/.env.example apps/app/.env.local   # then edit it as in step 2

bun run db:push                                # apply the schema
bun run --filter app dev                       # http://localhost:3000
```

Untuk produksi, build dan jalankan aplikasi:

```bash title="Terminal"
bun x turbo build --filter=app
bun run --filter app start
```

`bun run db:push` terhubung dengan driver Neon, jadi memerlukan database Neon. Untuk memakai Postgres Docker bagi pengembangan lokal, jalankan dengan `docker compose up -d db db-proxy`, terapkan skema dengan `docker compose run --rm migrate`, lalu atur nilai berikut di `apps/app/.env.local`:

```bash title="apps/app/.env.local"
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/qrdx
DATABASE_HTTP_ENDPOINT=http://localhost:4444/sql
```

Aplikasi memeriksa setiap nilai saat dimulai, dan menolak untuk berjalan jika ada nilai wajib yang hilang atau nilai yang tidak valid, dengan menyebutkan nama variabelnya.

| Variabel | Fungsi |

<Callout type="info" title="Nilai NEXT_PUBLIC_* ditetapkan saat build">
  Nilai `NEXT_PUBLIC_*` disisipkan ke dalam bundel browser saat aplikasi di-build, sehingga mengubahnya berarti harus build ulang. Build Docker hanya membaca `.env` untuk enam di antaranya, yang diteruskan sebagai build argument di `docker-compose.yml`: `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`, `NEXT_PUBLIC_FEATUREBASE_APP_ID`, dan dua ID produk Pro. Untuk mengatur yang lain di image Docker (ID produk Business, `NEXT_PUBLIC_QRDX_EUR_PRICES`, `NEXT_PUBLIC_SHORT_LINK_BASE_URL`, site key Turnstile, atau ID Umami), tambahkan ke `build.args` layanan `app` di `docker-compose.yml` dan sebagai `ARG` di tahap build pada Dockerfile, lalu jalankan `docker compose up -d --build`. Penyiapan manual membaca semuanya dari `apps/app/.env.local`.
</Callout>

### Job terjadwal [#scheduled-jobs]

Dua rute menjalankan pekerjaan berkala: `/api/cron/webhooks` mencoba ulang pengiriman webhook yang gagal dan menghapus baris log audit lama, dan `/api/cron/digest` mengirim ringkasan mingguan. Di Vercel, `apps/app/vercel.json` menjadwalkannya. Di tempat lain, tidak ada yang memanggilnya sampai Anda melakukannya. Atur `CRON_SECRET` dan panggil keduanya dari penjadwal Anda dengan nilai tersebut:

```text title="crontab (times in UTC)"
0 4 * * *  curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://qr.example.com/api/cron/webhooks
0 9 * * 1  curl -fsS -H "Authorization: Bearer $CRON_SECRET" "https://qr.example.com/api/cron/digest?shard=all"
```

Tanpa header tersebut, rute menjawab `401` di produksi. [Notifikasi](/docs/notifications#self-hosting) menjelaskan parameter `shard` pada ringkasan.

## Reverse proxy dan HTTPS [#reverse-proxy-and-https]

Tempatkan aplikasi di belakang reverse proxy seperti Caddy, nginx, atau Traefik yang menangani terminasi TLS, dan jangan membuka port 3000 langsung ke internet. Pembatasan laju, email keamanan, dan [log audit](/docs/help/teams/audit-log) membaca IP klien dari `X-Real-IP` terlebih dahulu, lalu dari alamat pertama di `X-Forwarded-For` (di Vercel, `X-Vercel-Forwarded-For` berada di antara keduanya), sehingga proxy harus mengatur header ini dan aplikasi hanya boleh dapat dijangkau melalui proxy tersebut. Atur proxy agar mengisi `X-Real-IP` dengan alamat asal koneksi yang diterimanya. Proxy yang hanya menambahkan ke `X-Forwarded-For` memungkinkan klien menaruh alamat apa pun di urutan pertama.

```nginx title="nginx server block (the relevant lines)"
location / {
  proxy_pass http://127.0.0.1:3000;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

Caddy mengatur header ini secara default. Setelah HTTPS berfungsi, ubah `NEXT_PUBLIC_APP_URL` dan `BETTER_AUTH_URL` ke URL `https://`, perbarui URL callback OAuth, lalu build ulang.

### Content-Security-Policy [#content-security-policy]

Build produksi mengirim Content-Security-Policy pada halaman QRdx sendiri: halaman untuk pengguna yang sudah masuk mendapat nonce skrip baru pada setiap permintaan, sedangkan halaman yang di-prerender mendapat daftar host skrip yang diizinkan. Halaman yang di-hosting (`/p`) mendapat kebijakan yang longgar, karena halaman tersebut menjalankan piksel milik pemiliknya dan menyematkan media dari mana saja. Jika reverse proxy Anda juga mengatur `Content-Security-Policy`, browser akan menerapkan keduanya, jadi jangan atur di sana. Setel `CSP_REPORT_ONLY=1` untuk mengirim kebijakan sebagai report-only saat Anda memeriksa pengaturan baru; pelanggaran dicatat oleh `/api/csp-report`. Tambahkan `CSP_HTTPS=1` saat Anda melayani lewat HTTPS di luar Vercel, agar browser meningkatkan setiap resource `http://`. Keduanya dibaca di tempat aplikasi berjalan dan, untuk header halaman yang di-prerender, di tempat aplikasi di-build; Dockerfile tidak meneruskannya ke build, jadi tambahkan juga sebagai build argument jika halaman yang di-prerender membutuhkannya.

## Memperbarui QRdx [#update-qrdx]

Cadangkan database terlebih dahulu (lihat di bawah). Lalu tarik kode dan build ulang. Layanan `migrate` menyinkronkan skema lagi sebelum aplikasi dimulai.

```bash title="Terminal"
git pull
docker compose up -d --build
```

Untuk pengaturan manual, jalankan `git pull`, `bun install`, dan `bun run db:push`, lalu build ulang dan mulai ulang.

Jika perubahan skema akan menghapus data, `drizzle-kit push` meminta konfirmasi dan layanan `migrate` menunggu jawaban yang tidak bisa diberikan. Dalam kasus itu, jalankan di terminal untuk meninjau dan mengonfirmasi perubahan:

```bash title="Terminal"
docker compose run --rm migrate
```

## Pencadangan dan pemulihan [#back-up-and-restore]

Semua yang disimpan QRdx ada di Postgres, kecuali file yang diunggah, yang ada di bucket R2 Anda. Buat dump database sebelum setiap pembaruan dan secara terjadwal:

```bash title="Terminal"
docker compose exec db pg_dump -U postgres qrdx > qrdx-backup.sql
```

Untuk memulihkan ke database kosong:

```bash title="Terminal"
docker compose exec -T db psql -U postgres qrdx < qrdx-backup.sql
```

Dengan Neon, gunakan backup dan branching bawaannya.

## Perbedaan dengan qrdx.dev [#what-is-different-from-qrdxdev]

- **Dokumentasi** dibuka di qrdx.dev. Instans Anda mengalihkan setiap URL dokumentasi ke sana.
- **Pembayaran dan paket** memerlukan Polar. Tanpa Polar, setiap akun memiliki batas paket Gratis, dan tidak ada yang bisa melakukan upgrade. Batas itu sendiri ada di `apps/app/lib/plans.ts`, yang dapat Anda ubah untuk instans Anda.
- **Program afiliasi, permintaan pembayaran dengan faktur, diskon nirlaba, dan formulir kontak enterprise** adalah penjualan milik QRdx sendiri dan hanya berjalan di tempat QRdx sendiri berjalan. Salinan self-hosted tidak memilikinya.
- **Lokasi pemindaian:** negara, wilayah, dan kota berasal dari header geo Vercel. Di belakang Cloudflare hanya negara yang dibaca (`CF-IPCountry`); di tempat lain lokasi tampil sebagai tidak diketahui, dan [aturan area](/docs/precise-location#route-scans-by-area) hanya cocok dengan pemindaian yang membagikan lokasi.
- **Domain kustom** diverifikasi dengan record DNS `TXT` dan dirutekan oleh reverse proxy Anda, kecuali Anda berjalan di Vercel dengan variabel Domains API yang sudah diatur. Tombol **Set up with …** memerlukan template Domain Connect milik Anda sendiri: template QRdx hanya berfungsi untuk qrdx.dev.
- **Bot obrolan dan integrasi** masing-masing memerlukan aplikasi yang Anda daftarkan di layanan tersebut (lihat tabel di atas).
- **Halaman admin** dilayani oleh aplikasi itu sendiri; qrdx.dev memproksikan sebagian di antaranya ke konsol terpisah.

## Pemecahan masalah [#troubleshooting]

### "Invalid environment variables" saat startup [#invalid-environment-variables-on-startup]

Log menyebutkan setiap variabel yang hilang atau tidak valid, lalu menjelaskan tempat mengaturnya. Ada nilai wajib yang hilang, atau nilai opsional diatur ke sesuatu yang tidak valid: URL yang bukan alamat lengkap `http://` atau `https://`, atau secret yang terlalu pendek. Nilai kosong dianggap tidak diatur dan tidak masalah. Perbaiki variabel yang disebutkan di `.env` dan buat ulang container dengan `docker compose up -d app`.

### `redirect_uri` OAuth tidak cocok [#oauth-redirect_uri-mismatch]

URL callback di aplikasi OAuth Anda harus persis `<NEXT_PUBLIC_APP_URL>/api/auth/callback/github` atau `/api/auth/callback/google`. Atur `BETTER_AUTH_URL` ke base URL yang sama dengan `NEXT_PUBLIC_APP_URL`.

### Aplikasi tidak dapat menjangkau database (`fetch failed`) [#the-app-cant-reach-the-database-fetch-failed]

Dengan Postgres biasa, `DATABASE_HTTP_ENDPOINT` harus mengarah ke proxy yang sedang berjalan. Periksa bahwa `docker compose ps db-proxy` menunjukkan proxy berjalan.

### `migrate` tidak pernah selesai [#migrate-never-finishes]

`drizzle-kit push` sedang menunggu konfirmasi. Jalankan `docker compose run --rm migrate` di terminal dan jawab konfirmasinya; lihat [Memperbarui QRdx](#update-qrdx).

### Perubahan nilai `NEXT_PUBLIC_*` tidak berpengaruh [#a-changed-next_public_-value-has-no-effect]

Build ulang image: `docker compose up -d --build`.

### Port 4444 sudah digunakan [#port-4444-is-already-in-use]

Ubah pemetaan port `db-proxy` di `docker-compose.yml`. Hanya pengembangan lokal di host yang menggunakannya.

### "the --mount option requires BuildKit" [#the---mount-option-requires-buildkit]

Docker Anda tidak memiliki BuildKit. Instal plugin `buildx`, atau perbarui Docker.

### Build berhenti dengan `Killed` atau kode keluar 137 [#the-build-stops-with-killed-or-exit-code-137]

Docker kehabisan memori. Berikan setidaknya 8 GB (Docker Desktop: **Settings** → **Resources**) dan jalankan `docker compose up -d --build` lagi.

### "sign-in code email is off for this deployment" [#sign-in-code-email-is-off-for-this-deployment]

Email kode tidak dikirim selama `NEXT_PUBLIC_APP_URL` adalah `localhost`. Gunakan masuk dengan GitHub atau Google untuk uji coba lokal.

Masih buntu? [Buka issue](https://github.com/qrdxinc/qrdx/issues) beserta output `docker compose logs app`, dengan secret yang sudah dihapus.
