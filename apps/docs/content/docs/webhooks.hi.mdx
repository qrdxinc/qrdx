इस पेज के अंत तक, आपके चुने हर event के कुछ मिनट के भीतर आपके नियंत्रण वाले URL पर एक साइन किया हुआ `POST` पहुँचेगा, आपका सर्वर वेरिफ़ाई करेगा कि हर रिक्वेस्ट QRdx से आया है, और आप जान जाएँगे कि retries, डुप्लिकेट और डिलीवरी लॉग कैसे काम करते हैं।

Webhooks किसी वर्कस्पेस के events को होते ही आपके सर्वर पर भेजते हैं: जैसे कोई फ़ॉर्म भरे तो CRM अपडेट करना, कोई कोड 1,000 स्कैन पार करे तो इंटरनल टूल में पोस्ट करना, या स्कैन डेटा की अपनी कॉपी रखना।

<Callout type="info" title="Business प्लान">
Webhooks, Zapier और Make hooks, और Slack और Discord अलर्ट **Business** प्लान का हिस्सा हैं। ईमेल अलर्ट और साप्ताहिक डाइजेस्ट Pro में शामिल हैं; देखें [नोटिफ़िकेशन](/docs/notifications)। प्लान की तुलना [प्लान और सीमाएँ](/docs/plans-and-limits) पर देखें।
</Callout>

## शुरू करने से पहले [#before-you-start]

- एक सार्वजनिक `https://` URL जो `POST` रिक्वेस्ट का जवाब दे। IP पते, `localhost` और ऐसे होस्ट नाम जो प्राइवेट नेटवर्क पर resolve होते हैं, अस्वीकार किए जाते हैं, और रीडायरेक्ट फ़ॉलो नहीं किए जाते। लोकल डेवलपमेंट के लिए ऐसा tunnel इस्तेमाल करें जो सार्वजनिक होस्ट नाम दे।
- वर्कस्पेस में Owner या admin भूमिका। Members endpoints और उनके डिलीवरी लॉग देख सकते हैं, पर जोड़ या बदल नहीं सकते।

## 1. endpoint जोड़ें [#1-add-an-endpoint]

1. जिस वर्कस्पेस के events चाहिए, उसमें [Settings → Webhooks](/dashboard?to=settings/webhooks) खोलें। यह लिंक आपके आख़िरी इस्तेमाल किए वर्कस्पेस को खोलता है; वर्कस्पेस स्विचर में दूसरा चुनें, आप उसी पेज पर रहेंगे।
2. **Add endpoint** चुनें, **Endpoint URL** डालें और जो **Events** चाहिए उन पर टिक करें, फिर डायलॉग में **Add endpoint** चुनें। QRdx पहले आपसे [पुष्टि करने को कहता है कि यह आप ही हैं](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), और endpoint का URL बदलने पर हर बार दोबारा कहता है; events बदलने या endpoint बंद करने पर नहीं पूछता।
3. सेव करने के बाद दिखने वाला **Signing secret** कॉपी करें। Owners और admins इसे endpoint के **Deliveries** पेज से दोबारा दिखा सकते हैं, या rotate कर सकते हैं।
4. **Send test** चुनें। QRdx एक साइन किया हुआ `ping` event भेजता है और डिलीवरी लॉग में रिस्पॉन्स स्टेटस दिखाता है।

## 2. events चुनें [#2-pick-the-events]

| Event | कब | नोट्स |
| --- | --- | --- |
| `scan.created` | कोई डायनेमिक कोड स्कैन होता है | बैच में: हर endpoint पर एक मिनट में अधिकतम एक रिक्वेस्ट, जिसमें 100 तक स्कैन और सटीक `count` होता है |
| `scan.milestone` | किसी कोड का पहला स्कैन, फिर 10, 100, 500, 1,000, 5,000, 10,000, 50,000, 100,000, 500,000 और 1,000,000 स्कैन, फिर हर दस लाख पर | हर milestone पर एक बार चलता है |
| `code.created` | डैशबोर्ड या API से कोई डायनेमिक कोड बनाया जाता है | हर कोड पर एक event, बल्क क्रिएशन में भी |
| `code.updated` | किसी कोड का डेस्टिनेशन, टाइटल, डिज़ाइन या शॉर्ट-लिंक डोमेन बदलता है | `changes` में फ़ील्ड की सूची होती है |
| `form.submitted` | कोई होस्टेड पेज पर फ़ॉर्म सबमिट करता है | जवाब शामिल होते हैं |
| `ping` | आप **Send test** चुनते हैं | |

बॉट, लिंक प्रीव्यू और प्रीफ़ेचर के स्कैन, और एक ही विज़िटर के तेज़ दोहराव गिने नहीं जाते और events ट्रिगर नहीं करते, ठीक वैसे ही जैसे [स्कैन एनालिटिक्स](/docs/dynamic-qr-codes#scan-analytics) में।

## 3. payload पढ़ें [#payloads]

हर रिक्वेस्ट JSON बॉडी और इन हेडर्स के साथ एक `POST` होता है:

| Header | मान |
| --- | --- |
| `Content-Type` | `application/json` |
| `User-Agent` | `QRdx-Webhooks/1.0 (+https://qrdx.dev/docs/webhooks)` |
| `X-QRdx-Event` | event का प्रकार, जैसे `code.created` |
| `X-QRdx-Delivery` | डिलीवरी id: हर retry पर वही रहता है, ताकि आप डुप्लिकेट अनदेखा कर सकें |
| `X-QRdx-Timestamp` | Unix सेकंड में वह समय जब यह प्रयास साइन किया गया |
| `X-QRdx-Signature` | `t=<timestamp>,v1=<hex HMAC-SHA256>` |

बॉडी हमेशा एक envelope होती है जिसमें `id`, `type`, `created_at` और `data` होते हैं:

```json title="code.created"
{
  "id": "evt_cm3x8c1a20001",
  "type": "code.created",
  "created_at": "2026-10-31T09:30:00.000Z",
  "data": {
    "code": {
      "id": "cm3x7q2l40000",
      "slug": "aB3dE5f",
      "title": "Spring menu",
      "short_link": "https://qrdx.dev/q/aB3dE5f",
      "destination_url": "https://example.com/menu",
      "status": "active",
      "scan_count": 0,
      "created_at": "2026-10-31T09:30:00.000Z",
      "updated_at": "2026-10-31T09:30:00.000Z"
    },
    "actor_id": "user_123"
  }
}
```

एक `scan.created` बैच:

```json title="scan.created"
{
  "id": "evt_cm3x9d0b10002",
  "type": "scan.created",
  "created_at": "2026-10-31T09:31:00.000Z",
  "data": {
    "window_started_at": "2026-10-31T09:31:00.000Z",
    "window_seconds": 60,
    "count": 2,
    "scans": [
      {
        "scan_id": "cm3x9d0b00001",
        "code": { "id": "cm3x7q2l40000", "slug": "aB3dE5f", "title": "Spring menu" },
        "scanned_at": "2026-10-31T09:31:00.000Z",
        "country": "DE",
        "region": "BE",
        "city": "Berlin",
        "device_type": "mobile",
        "os": "iOS",
        "browser": "Safari",
        "referer": null,
        "source": "qr"
      }
    ]
  }

```

जब एक मिनट में 100 से ज़्यादा स्कैन आते हैं, तो `scans` में पहले 100 होते हैं और `count` में सटीक कुल संख्या। [NFC टैग](/docs/nfc) पर टैप के लिए `source` `nfc` होता है और QR स्कैन के लिए `qr`। स्कैन payload में IP पते या विज़िटर hash कभी शामिल नहीं होते।

बाकी events में ये होते हैं:

- `scan.milestone`: `milestone`, `code` (`id`, `slug`, `title`, `scan_count`) और वह `scan` जिसने इसे पूरा किया।
- `code.updated`: `code.created` जैसा, साथ में `changes`, जैसे `["destination_url"]`।
- `form.submitted`: `response_id`, `page` (`id`, `title`), `code` (`id`, `slug`, या `null`), `fields` (`name`, `label`, `value` टेक्स्ट के रूप में) और `submitted_at`।

पहला असली event आने से पहले अपने डेटा से बना हर event का payload देखने के लिए [Get sample events](/docs/developers/api/get-hook-samples) कॉल करें:

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/hooks/sample?event=scan.created" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

## 4. signatures वेरिफ़ाई करें [#verify-signatures]

अपने signing secret से `<timestamp>.<raw body>` का HMAC-SHA256 निकालें और उसे `X-QRdx-Signature` के `v1` से मिलाएँ। रॉ रिक्वेस्ट बॉडी इस्तेमाल करें, JSON पार्स करने से पहले की, और पाँच मिनट से पुराने timestamps अस्वीकार करें।

```ts title="lib/qrdx-webhook.ts"
import { createHmac, timingSafeEqual } from "node:crypto";

export function isFromQRdx(rawBody: string, header: string, secret: string) {
  const parts = Object.fromEntries(
    header.split(",").map((part) => part.trim().split("=", 2)),
  );
  const timestamp = Number(parts.t);
  if (!timestamp || Math.abs(Date.now() / 1000 - timestamp) > 300) return false;

  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const received = Buffer.from(parts.v1 ?? "");
  return (
    received.length === expected.length &&
    timingSafeEqual(received, Buffer.from(expected))
  );
}
```

```python title="qrdx_webhook.py"
import hmac
import hashlib
import time


def is_from_qrdx(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(part.strip().split("=", 1) for part in header.split(","))
    timestamp = int(parts.get("t", "0"))
    if not timestamp or abs(time.time() - timestamp) > 300:
        return False
    expected = hmac.new(
        secret.encode(), f"{timestamp}.".encode() + raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(parts.get("v1", ""), expected)
```

secret rotate करना तुरंत लागू होता है: पुराना secret वेरिफ़ाई करना बंद कर देता है, इसलिए rotate करने के तुरंत बाद अपना सर्वर अपडेट करें।

## 5. जवाब दें, और retries संभालें [#5-respond-and-handle-retries]

10 सेकंड के भीतर किसी भी `2xx` स्टेटस से जवाब दें। इसके अलावा कुछ भी (एरर स्टेटस, रीडायरेक्ट, टाइमआउट, पहुँच से बाहर होस्ट) विफलता माना जाता है, और QRdx बढ़ते इंतज़ार के साथ retry करता है: लगभग 1 मिनट, 4 मिनट, 16 मिनट, 1 घंटा, 4 घंटे, 17 घंटे और 24 घंटे। हर retry अपना इंतज़ार ख़त्म होने के कुछ मिनट के भीतर भेजा जाता है। यानी लगभग दो दिनों में 8 प्रयास, जिसके बाद डिलीवरी को failed मार्क कर दिया जाता है।

डिलीवरी एक से ज़्यादा बार (धीमे रिस्पॉन्स के बाद retry, मैन्युअल retry) और क्रम से बाहर भी आ सकती हैं। डुप्लिकेट अनदेखा करने के लिए `X-QRdx-Delivery` या envelope `id` इस्तेमाल करें, और अगर आपके काम में कुछ सेकंड से ज़्यादा लगता है तो `2xx` जवाब देने के बाद काम करें।

## बाद में बदलें [#change-it-later]

हर endpoint का **Deliveries** पेज पिछली 50 डिलीवरी उनके event, स्टेटस, प्रयासों और payload के साथ दिखाता है। **Retry now** किसी failed या pending डिलीवरी को तुरंत दोबारा भेजता है; **Send again** किसी delivered डिलीवरी को दोबारा भेजता है। डिलीवरी 30 दिन तक रखी जाती हैं।

endpoint के मेन्यू से आप उसका URL और events **Edit** कर सकते हैं, **Disable endpoint** कर सकते हैं (नई डिलीवरी रुक जाती हैं; **Enable endpoint** उन्हें फिर शुरू करता है), उसका **Signing secret** दिखा या **Rotate** कर सकते हैं, और उसे **Delete** कर सकते हैं, जिससे उसका लॉग भी डिलीट हो जाता है। अगर किसी वर्कस्पेस के प्लान में webhooks शामिल नहीं रहते, तो endpoints रखे जाते हैं पर जब तक वह फिर से Business पर न हो कुछ नहीं भेजा जाता। आपके QR कोड दोनों स्थितियों में काम करते रहते हैं।

## Zapier, Make और n8n (REST Hooks) [#zapier-make-and-n8n-rest-hooks]

ऑटोमेशन टूल REST Hooks API के ज़रिए खुद सब्सक्राइब और अनसब्सक्राइब कर सकते हैं। [API key](/docs/developers/api-keys) या OAuth access token से ऑथेंटिकेट करें: सब्सक्राइब या अनसब्सक्राइब करने के लिए `codes:write`, सूची देखने के लिए `codes:read`। Hook URL अक्सर गोपनीय होते हैं, इसलिए सिर्फ़ `codes:read` होने पर `target_url` केवल होस्ट दिखाता है (`https://hooks.zapier.com`)। Token वाले रिक्वेस्ट आपके अपने वर्कस्पेस पर काम करते हैं; key उसी वर्कस्पेस पर काम करती है जिसमें वह बनाई गई थी। इसके बजाय साइन-इन ब्राउज़र सेशन से सब्सक्राइब करने पर पहले आपसे [पुष्टि करने को कहा जाता है कि यह आप ही हैं](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), और जब तक आपने पिछले 10 मिनट में पुष्टि न की हो, `403 CONFIRMATION_REQUIRED` मिलता है। सब्सक्रिप्शन सामान्य endpoints ही हैं: वे **Settings → Webhooks** में दिखते हैं, जहाँ से आप उन्हें हटा भी सकते हैं।

| मेथड | पाथ | विवरण |
| --- | --- | --- |
| `POST` | `/v1/hooks` | सब्सक्राइब करें। बॉडी: `target_url` (या Zapier का `hookUrl`) और `event` (या `events` ऐरे)। सब्सक्रिप्शन `id` और उसके `secret` के साथ `201` लौटाता है |
| `DELETE` | `/v1/hooks/{id}` | अनसब्सक्राइब करें (`204`) |
| `GET` | `/v1/hooks` | सब्सक्रिप्शन और endpoints की सूची |
| `GET` | `/v1/hooks/{id}` | एक सब्सक्रिप्शन |
| `GET` | `/v1/hooks/sample?event=<event>` | `event` के हाल के उदाहरण payload, ऐरे के रूप में (Zapier की "perform list") |

```bash title="Terminal"
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://hooks.zapier.com/hooks/standard/123/abc/", "event": "form.submitted"}'
```

```json title="201 Created (fields)"
{
  "id": "<hook id>",
  "target_url": "https://hooks.zapier.com/hooks/standard/123/abc/",
  "events": ["form.submitted"],
  "event": "form.submitted",
  "active": true,
  "created_at": "<ISO 8601 time>",
  "secret": "whsec_<shown only here>"
}
```

Business के बिना सब्सक्राइब कॉल `402` लौटाती है:

```json title="402 Payment Required"
{"code":"PLAN_REQUIRED","message":"Webhooks and Zapier/Make hooks are part of the Business plan.","status":402}
```

`scan.created` डिलीवरी एक बैच होती है, इसलिए Zapier में हर स्कैन पर कार्रवाई करने के लिए `data.scans` line items इस्तेमाल करें। n8n में, [n8n के लिए QRdx nodes](/docs/developers/n8n) का QRdx Trigger node ये कॉल आपके लिए करता है और हर signature जाँचता है; सामान्य Webhook node भी चलता है, जिसे किसी भी दूसरे endpoint की तरह सेट करें। रेफ़रेंस पेज हैं [Subscribe to events](/docs/developers/api/create-hook), [List hooks](/docs/developers/api/list-hooks) और [Unsubscribe](/docs/developers/api/delete-hook)।

## अगर कुछ गड़बड़ हो जाए [#if-something-goes-wrong]

### एंडपॉइंट URL अस्वीकार हो जाता है [#the-endpoint-url-is-refused]

सिर्फ़ पब्लिक `https://` होस्ट नेम स्वीकार किए जाते हैं: `http://` नहीं, IP address नहीं, `localhost` नहीं, और ऐसे नाम नहीं जो किसी प्राइवेट नेटवर्क पर resolve होते हों। डेवलपमेंट के दौरान पब्लिक होस्ट नेम वाली टनल इस्तेमाल करें।

### हर डिलीवरी में फ़ेल्ड स्टेटस दिखता है [#every-delivery-shows-a-failed-status]

आपके सर्वर ने 10 सेकंड के अंदर `2xx` के अलावा कुछ और जवाब दिया, रीडायरेक्ट किया, या कोई जवाब नहीं दिया। सटीक HTTP स्टेटस या एरर देखने के लिए डिलीवरी की डिटेल खोलें, उसे ठीक करें, फिर **Retry now** चुनें। अगर आपका हैंडलर धीमा है, तो पहले `2xx` से जवाब दें और प्रोसेसिंग बाद में करें।

### सिग्नेचर वेरिफ़ाई नहीं होते [#signatures-dont-verify]

ध्यान रखें कि आप रॉ रिक्वेस्ट बॉडी का हैश बना रहे हैं, दोबारा सीरियलाइज़ किए गए JSON ऑब्जेक्ट का नहीं, और आपका सर्वर मौजूदा सीक्रेट इस्तेमाल कर रहा है: सीक्रेट रोटेट करने पर पुराना सीक्रेट तुरंत अमान्य हो जाता है। अपने सर्वर की घड़ी भी जाँचें, क्योंकि टाइमस्टैम्प चेक में पाँच मिनट की छूट है।

### इवेंट आना बंद हो गए [#events-stopped-arriving]

वर्कस्पेस Business प्लान से बाहर हो गया (एंडपॉइंट रखे जाते हैं, लेकिन रोक दिए जाते हैं), एंडपॉइंट **Disabled** है, या जिस Zap, सिनेरियो या वर्कफ़्लो ने सब्सक्रिप्शन बनाया था उसे बंद कर दिया गया और वह अनसब्सक्राइब हो गया। **Settings → Webhooks** देखें।

### `POST /v1/hooks` से `403 CONFIRMATION_REQUIRED` [#403-confirmation_required-from-post-v1hooks]

आपने ब्राउज़र सेशन से सब्सक्राइब किया था। QRdx में पुष्टि करें कि यह आप ही हैं और 10 मिनट के अंदर दोबारा कोशिश करें, या अपने सर्वर से API key के साथ सब्सक्राइब करें।

## सेल्फ़-होस्टिंग [#self-hosting]

डिलीवरी तुरंत भेजी जाती हैं; रीट्राई और वे स्कैन बैच जिनका मिनट पूरा हो चुका है, एक शेड्यूल्ड जॉब भेजता है। QRdx इसे GitHub Actions वर्कफ़्लो से हर 5 मिनट में चलाता है, जो Vercel के फ़्री Hobby प्लान पर काम करता है, और `apps/app/vercel.json` इसे दिन में एक बार पूरा भी चलाता है। GitHub शेड्यूल्ड रन देर से शुरू कर सकता है, इसलिए रीट्राई मिनट के हिसाब से नहीं, बल्कि कुछ मिनट के अंदर होने की उम्मीद रखें।

ऐसा ही करने के लिए `.github/workflows/webhook-worker.yml` कॉपी करें, अपना `CRON_SECRET` Actions secret के रूप में जोड़ें और अपना जॉब URL `WEBHOOK_WORKER_URL` वेरिएबल के रूप में जोड़ें। या किसी भी शेड्यूलर से जॉब को कॉल करें, उस `CRON_SECRET` के साथ जो आपने एनवायरनमेंट में सेट किया है:

```bash title="crontab (every 1 to 5 minutes)"
curl -H "Authorization: Bearer $CRON_SECRET" https://your-host/api/cron/webhooks
```

URL में `?source=github` जोड़ने पर, जॉब पहले Upstash Redis में एक छोटा मार्कर देखता है और अगर कुछ भी बाकी नहीं है तो डेटाबेस को क्वेरी किए बिना `{"skipped": true}` लौटा देता है, ताकि जीरो तक स्केल होने वाला डेटाबेस सोता रह सके (Upstash के बिना यह हमेशा पूरा जॉब चलाता है)। बिना इसके दिन में एक कॉल रखें: वह रन हमेशा पूरा जॉब करता है और मार्कर को ठीक कर देता है। बाकी शेड्यूल्ड जॉब [सेल्फ़-होस्टिंग](/docs/self-hosting#scheduled-jobs) में सूचीबद्ध हैं।
