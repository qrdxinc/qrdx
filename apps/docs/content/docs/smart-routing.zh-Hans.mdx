[动态二维码](/docs/dynamic-qr-codes)通常会把每次扫描都发送到同一个目标。启用智能路由后，同一个印刷出来的二维码可以在 iPhone 上打开 App Store，在 Android 上打开 Google Play，向说西班牙语的访客显示西班牙语页面，或在营业时间之外显示另一个优惠。当合适的页面取决于谁在扫描、在哪里扫描或何时扫描时，就可以使用它。

<Callout type="info" title="Pro 和 Business">
  智能路由和 UTM 参数包含在 Pro 和 Business 中。它们适用于打开网站链接的二维码；[托管页面](/docs/landing-pages)不会重定向，因此没有路由功能。请参阅[套餐与限制](/docs/plans-and-limits)。
</Callout>

时间紧？请看简短的任务页面：[将扫描发送到不同链接](/docs/help/dynamic-codes/routing)。

## 工作原理 [#how-it-works]

<Diagram id="smart-routing" />

你可以在二维码的**设置**标签页中的**智能路由**面板里配置路由（从[二维码](/dashboard?to=codes)中打开该二维码）。

- 每个二维码最多可以有 20 条**规则**。每条规则包含条件（“当”）和动作（“则”：一个 URL，或一个 A/B 分流）。
- 每次扫描都会从上到下依次检查规则。第一条所有条件都匹配的规则决定这次扫描的去向。可以用箭头调整规则顺序。
- 没有任何规则匹配时，扫描会进入二维码的主目标。
- 没有条件的规则会匹配每一次扫描，因此它下面的规则永远不会运行。
- 关闭规则可以保留它但不使用它。
- 更改会应用于下一次扫描，你无需重新印刷二维码。

如果某条规则因故无法判定，扫描仍会进入主目标：路由不会让二维码失效。

## 条件 [#conditions]

每个条件都可以用**不是**来反选（例如“国家不是 US”）。

| 条件 | 匹配时机 | 说明 |
| --- | --- | --- |
| 设备 | 扫描者使用手机、平板、桌面设备或其他设备 | 来自浏览器的 user agent |
| 操作系统 | iOS、Android、Windows、macOS、Linux、ChromeOS、HarmonyOS 等 | iPhone 和 iPad 都算作 iOS |
| 国家 | 扫描来自所列国家之一 | 2 位字母代码，如 `US, CA, GB` |
| 地区 | 扫描来自所列地区之一 | 代码如 `US-CA, US-NY`（国家加行政区划） |
| 语言 | 访客浏览器的首选语言是所列语言之一 | `es` 匹配所有西班牙语变体（`es-MX`、`es-ES`）；`pt-BR` 仅匹配巴西葡萄牙语 |
| 时段 | 扫描发生在所选的星期几，且在你选定时区的两个时间之间 | 像 22:00 到 02:00 这样的时间段会跨过午夜，并归属于它开始的那一天 |
| 日期范围 | 扫描发生在两个日期之间 | 一端留空表示“截止到”或“从……起”；日期使用你浏览器的时区 |
| 扫描次数 | 属于前 N 次扫描，或第 N 次之后的任意扫描 | 统计已记录的扫描（不含机器人），因此在大量用户同时扫描时只是近似值 |
| 区域 | 扫描者位于某个点的指定半径（100 m 到 500 km）之内 | 开启[精确位置](/docs/precise-location)时使用扫描者共享的位置，否则使用其 IP 地址的大致位置 |

国家、地区以及区域条件中基于 IP 的位置都来自扫描者的 IP 地址，QRdx 不会存储该地址。位置未知时，位置条件不会匹配（“不是”条件则会匹配）。[精确位置与地理围栏](/docs/precise-location)介绍了区域，包括如何让二维码只在某个区域内生效。

## 智能应用链接 [#smart-app-links]

选择**添加规则** → **智能应用链接（App Store / Google Play）**，即可一次创建两条规则：iOS 进入你的 App Store 链接，Android 进入你的 Google Play 链接。其他所有人（桌面设备、其他手机）进入主目标，例如你的网站。

## A/B 测试 [#ab-tests]

把规则的动作设为**在多个 URL 之间分流（A/B）**，并添加 2 到 5 个变体，每个变体包含一个 URL 和一个权重。权重为 70 和 30 的分流会把大约 70% 的访客发送到第一个 URL。

- 分配是固定的：同一天再次扫描的访客会得到相同的变体。它基于匿名的每日访客哈希，绝不使用 cookie。
- 二维码的**分析**标签页会显示一张 **A/B 分流**卡片，统计自分流的变体或权重上次更改以来每个变体的扫描次数。每次扫描都会存储它所分配到的变体。QRdx 开始存储变体之前的扫描会按你当前的规则重新推算，此时卡片会标注为估算值。
- 分流也可以带条件，例如只针对德国访客的 A/B 测试。

## 测试你的规则 [#test-your-rules]

二维码至少有一条规则后，面板底部的**测试你的规则（使用未保存的更改）**会显示：针对任意设备、操作系统、国家、地区、语言、日期和时间、扫描序号、访客和位置，一次扫描会去往哪里。它按你在面板中当前的规则运行（无论是否已保存），并使用二维码已保存的主目标和 UTM 设置。它会列出匹配的规则以及其他规则未匹配的原因，并显示包含 UTM 参数的最终 URL。

## UTM 参数 [#utm-parameters]

路由面板下方的 **UTM 参数**面板会把 `utm_source`、`utm_medium`、`utm_campaign`、`utm_term`、`utm_content` 以及最多 10 个自定义参数添加到每次扫描打开的 URL 上，以便分析工具区分来自二维码的流量。

- 参数在路由之后添加，附加到扫描最终进入的那个 URL 上。
- URL 中已有的参数绝不会被替换，URL 的其余部分会与你输入的完全一致。
- 以 `qrdx_` 开头的名称保留给[转化追踪](/docs/tracking-and-conversions)使用。

## 限制与套餐 [#limits-and-plans]

| | 免费版 | Pro | Business |
| --- | --- | --- | --- |
| 每个二维码的规则数 | 无 | 20 | 20 |
| 每个 A/B 分流的变体数 | 无 | 2 到 5 | 2 到 5 |
| 自定义 UTM 参数 | 无 | 10 | 10 |

在 Pro 上保存的规则和 UTM 参数在你降级后仍会继续生效：限制只会阻止创建新的内容。没有 Pro 时，你仍可以关闭规则、删除规则和移除 UTM 参数；若要修改则需要再次使用 Pro。

## 面向开发者 [#for-developers]

规则、分流和 UTM 参数都在控制台中设置。[二维码 API](/docs/developers/api/update-code)可以创建和更新二维码及其目标，但不能管理路由规则。[`GET /v1/codes/{id}/scans`](/docs/developers/api/get-code-scans) 中每条已记录的扫描都带有规则所看到的设备类型、操作系统、国家、地区和城市。
