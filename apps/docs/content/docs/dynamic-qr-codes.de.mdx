title: "Dynamische QR-Codes"
description: "Drucke einen QR-Code einmal, ändere später, wohin er zeigt, und sieh, wie oft und wo er gescannt wird."
---

Ein dynamischer QR-Code enthält statt deiner finalen URL einen Kurzlink wie `https://qrdx.dev/q/aB3dE5f`. Beim Scannen wird der Kurzlink geöffnet und leitet zu dem Ziel weiter, das du festgelegt hast. Du kannst das Ziel jederzeit ändern, sodass gedruckte Codes nie veralten, und jeder Scan wird gezählt. Nutze ihn immer dann, wenn ein Code auf etwas kommt, das du nicht günstig neu drucken kannst: Speisekarten, Verpackungen, Poster, Visitenkarten.

<Callout type="info" title="Erfordert ein QRdx-Konto">
  Statische QR-Codes aus dem Playground und der `qrdx`-Bibliothek bleiben kostenlos und unbegrenzt. Dynamische Codes brauchen ein Konto: Kostenlos enthält 10 aktive dynamische Codes, Pro und Business haben kein Limit. Siehe [Tarife und Limits](/docs/plans-and-limits).
</Callout>

Du hast es eilig? Hier die kurzen Aufgabenseiten: [Dynamischen QR-Code erstellen](/docs/help/dynamic-codes/create), [Ändern, wohin ein Code zeigt](/docs/help/dynamic-codes/change-the-link), [Deine Scans ansehen](/docs/help/dynamic-codes/scans) und [Codes archivieren, löschen und wiederherstellen](/docs/help/dynamic-codes/archive-and-delete).

## So funktioniert es [#how-it-works]

<Diagram id="dynamic-redirect" />

Der gedruckte Code ändert sich nie: Er enthält den Kurzlink. Wenn jemand ihn scannt, prüft QRdx die Einstellungen des Codes (ist er pausiert, zeitgesteuert, passwortgeschützt, nach Gerät oder Standort geroutet), erfasst den Scan ohne Cookies und leitet zum Ziel weiter. Änderungen an Ziel, Design oder Einstellungen gelten ab dem nächsten Scan.

## Code erstellen [#create-a-code]

**Dashboard:** Öffne [Codes](/dashboard?to=codes) und klicke auf **New code**. Der Dialog **New dynamic QR code** fragt, was der Code öffnet: **Website link** oder eine der Vorlagen für [gehostete Seiten](/docs/landing-pages). Gib bei einem Link die **Destination URL** und optional einen **Title** ein und erstelle dann den Code. Lade ihn auf dem Tab **Overview** des Codes als PNG, WebP oder SVG herunter.

<Shot id="new-code-dialog" />

**Playground:** Wähle den Inhaltstyp **URL**, gib deinen Link ein und stelle den Link von **Static** auf **Dynamic** um. Der QR-Code enthält nun einen Kurzlink und behält dein Design. Wenn du die URL danach bearbeitest, klicke auf **Point it to the new address**, um das Ziel zu aktualisieren. **Save design to code** speichert das aktuelle Design beim Code. Das Menü **⋯** der Aktionsleiste enthält **Make it dynamic…** für einen Code, den du als statisch gestaltet hast.

<Shot id="playground-content" />

Ziele müssen Links mit `http://` oder `https://` sein. Links mit Benutzername oder Passwort und Links zu anderen QRdx-Kurzlinks werden abgelehnt. Jedes Ziel durchläuft außerdem [Sicherheitsprüfungen](/docs/code-controls#safety-checks-on-links).

## Eigene Back-Halves [#custom-back-halves]

Jeder Code erhält einen zufälligen Back-Half mit 7 Zeichen, den Teil nach `/q/`. Mit Pro und Business kannst du einen eigenen wählen, zum Beispiel `https://qrdx.dev/q/spring-menu`: Fülle **Custom back-half** aus, wenn du einen Code erstellst oder bearbeitest. Der Dialog zeigt dir schon beim Tippen, ob er frei ist.

- 3 bis 64 Zeichen: Buchstaben, Ziffern, `-` und `_`, kein `-` am Anfang oder Ende.
- Back-Halves unterscheiden wie generierte zwischen Groß- und Kleinschreibung: `Spring-Menu` und `spring-menu` sind zwei verschiedene Links.
- Auf `qrdx.dev` ist ein Back-Half in ganz QRdx einmalig, und Wörter, die wie QRdx-Seiten wirken (`admin`, `api`, `docs`, `login`, `pricing`, `settings` und weitere), sind reserviert.
- Auf deiner eigenen [eigenen Domain](/docs/custom-domains) muss er nur auf dieser Domain einmalig sein, und nur wenige technische Wörter (`api`, `_next`, `null`, `undefined`) sind reserviert, sodass `go.yourbrand.com/pricing` funktioniert. Ein solcher Back-Half gehört zur Domain: Er hat keinen `qrdx.dev/q/`-Link.

Wenn du den Back-Half eines Codes änderst, ändert sich sein Link: Mit dem alten Back-Half gedruckte QR-Codes funktionieren nicht mehr, lade den Code also erneut herunter.

## Code verwalten [#manage-a-code]

Öffne einen Code über [Codes](/dashboard?to=codes). Seine Seite hat drei Tabs: **Overview** (der Kurzlink, der QR-Code und seine Downloads, Scan-Summen, **Use with NFC** und Shortcuts zu seinen Optionen), **Analytics** und **Settings**. Über den Tabs:

- **Edit link** ändert das Ziel oder den Titel. Der gedruckte Code funktioniert weiter und öffnet beim nächsten Scan das neue Ziel.
- **Change type** macht aus einem Website-Link eine [gehostete Seite](/docs/landing-pages), aus einer Seite wieder einen Link oder aus einer Seite einen anderen Seitentyp. Kurzlink und Scans bleiben erhalten. Siehe [Ändern, was ein gedruckter Code öffnet](/docs/help/dynamic-codes/change-the-type).
- Das Menü **⋯** enthält **Edit design in playground** (der Editor öffnet sich, wobei der Code weiterhin an seinen Kurzlink gebunden ist), **Duplicate**, **Share analytics...**, **Move to folder...**, **Move to workspace...**, **Pause** oder **Resume**, **Archive** und **Move to trash**.

<Shot id="code-overview" />

**Duplicate** erstellt einen neuen Code mit neuem Kurzlink und ohne Scans. Er kopiert Ziel, Design, Ordner, Tags, Notizen und Typ sowie, wenn dein Tarif sie enthält, die Steuerungen, das Routing sowie die UTM- und Pixel-Einstellungen des Codes.

**Archive** behält den Code, schaltet ihn aber ab: Der Kurzlink zeigt eine Seite „This QR code is no longer active“, bis du ihn wiederherstellst, und archivierte Codes zählen nicht zum Limit deines Tarifs. **Move to trash** macht dasselbe und lässt dich den Code im **Trash** endgültig löschen, wodurch auch sein Scan-Verlauf entfernt wird; der Kurzlink zeigt dann eine Seite „QR code not found“.

Der **Version history** am Ende des Tabs **Settings** zeichnet jede Änderung am Code auf (bis zu 100 Versionen). Beim Wiederherstellen einer Version werden zuerst die aktuellen Einstellungen gespeichert, sodass sich eine Wiederherstellung rückgängig machen lässt.

## Codes organisieren [#organize-codes]

- **Ordner** lassen sich bis zu 5 Ebenen tief verschachteln. Ziehe Codes auf einen Ordner oder nutze **Move to folder...**. Wenn du einen Ordner löschst, rücken seine Codes und Unterordner eine Ebene nach oben.
- **Tags** filtern die Liste: Wähle mehrere aus, um Codes zu sehen, die alle davon haben.
- **Favoriten und Notizen:** Markiere Codes mit einem Stern und führe private Notizen; Notizen sind durchsuchbar.
- **Die Suche** umfasst Titel, Ziele, Notizen, Tags und Back-Halves, sodass du durch Einfügen eines Kurzlinks den zugehörigen Code findest.
- **Sammelaktionen:** Wähle Codes aus, um sie zu verschieben, zu taggen, zu pausieren, zu archivieren, als Favorit zu markieren, in den Papierkorb zu legen oder als ZIP aus PNG-, WebP- oder SVG-Dateien herunterzuladen.
- **CSV-Import:** **Codes** → **Import** in der Seitenleiste (oder **New code** → **Import codes** → **From a CSV file**) erstellt aus einer Datei bis zu {facts.importRows} dynamische Codes: Ziel, Titel, Ordner, Tags und ein optionaler eigener Back-Half in einer Spalte `slug`. Du kannst jeden Code in einen Ordner legen und alle taggen. Ein langer Import lässt sich pausieren und setzt nach einem Neuladen oder einer unterbrochenen Verbindung fort, ohne einen Code doppelt zu erstellen. Am Ende steht eine Ergebnis-CSV (mit dem Kurzlink jeder Zeile) und ein ZIP der Codes als PNG oder SVG. Der Import von mehr als einer Zeile und eigene Back-Halves erfordern Pro.

## Wer was darf [#who-can-do-what]

Codes gehören zu dem Workspace, in dem sie erstellt werden. Inhaber, Admins und Mitglieder erstellen und bearbeiten Codes; Mitglieder löschen ihre eigenen Codes, Inhaber und Admins jeden Code; Betrachter und Abrechnungsmitglieder können nur ansehen. Die Codes eines Workspace nutzen den besten Tarif unter seinen Inhabern und Abrechnungsmitgliedern. Siehe [Workspaces und Teams](/docs/teams).

## Scan-Analytics [#scan-analytics]

Der Tab **Analytics** eines Codes zeigt Scans im Zeitverlauf, eindeutige Besucher, QR-Scans und NFC-Taps, Top-Länder und -Städte, Geräte, Betriebssysteme, Browser und Referrer für die letzten 7, 30 oder 90 Tage, 1 Jahr oder 3 Jahre oder für die gesamte Zeit seit dem ersten Scan. Kostenlos zeigt das letzte {facts.freeScanHistoryYears} Jahr; Pro und Business zeigen alles. **Export CSV** lädt die Scans im gewählten Zeitraum herunter.

<Shot id="code-analytics" />

Jeder Scan erfasst die Uhrzeit (UTC), Land, Region und Stadt aus dem Netzwerk, Gerätetyp, Betriebssystem und Browser aus dem User-Agent sowie den Hostnamen des Referrers. Statt einer IP-Adresse speichert er einen gesalzenen Hash aus Adresse, User-Agent und Tag, der eindeutige Besucher pro Tag zählt und sich nicht in die Adresse zurückrechnen lässt. Bekannte Bots, Link-Vorschauen und Browser-Prefetches werden nicht gezählt. Mit Pro und Business kann ein Code Scannende auch [nach ihrem genauen Standort fragen](/docs/precise-location). Vollständige Liste: [Was QRdx erfasst, wenn jemand scannt](/docs/help/privacy-and-security/scan-data).

## Limits und Tarife [#limits-and-plans]

| | Kostenlos | Pro | Business |
| --- | --- | --- | --- |
| Aktive dynamische Codes | 10 | Unbegrenzt | Unbegrenzt |
| Scans | Unbegrenzt | Unbegrenzt | Unbegrenzt |
| Scan-Verlauf | {facts.freeScanHistoryYears} Jahr | Alles | Alles |
| Eigene Back-Halves | Nein | Ja | Ja |
| CSV-Import | 1 Zeile | Bis zu {facts.importRows} Zeilen | Bis zu {facts.importRows} Zeilen |
| Massenerstellung über die API | Nein | Bis zu {facts.apiBatchCodes} pro Anfrage | Bis zu {facts.apiBatchCodes} pro Anfrage |

<Callout type="info" title="Codes sterben nie">
  Ein Downgrade schaltet bestehende Codes nie ab. Über dem Limit kannst du Codes weiterhin bearbeiten und archivieren; neue erstellen oder wiederherstellen kannst du erst wieder, wenn du unter dem Limit bist. Siehe [Was mit deinen Codes passiert, wenn du nicht mehr zahlst](/docs/help/account-and-billing/never-hostage).
</Callout>

## Für Entwickler [#rest-api]

Alles oben Beschriebene ist über die REST API unter `https://api.qrdx.dev/v1/codes` verfügbar, entweder mit einem [API-Schlüssel](/docs/developers/api-keys) oder mit einem OAuth-Token, das den Scope `codes:read` oder `codes:write` hat.

- Du kannst Codes [auflisten](/docs/developers/api/list-codes), [erstellen](/docs/developers/api/create-codes), [abrufen](/docs/developers/api/get-code), [aktualisieren](/docs/developers/api/update-code) und [löschen](/docs/developers/api/delete-code) sowie [ihre Scans auslesen](/docs/developers/api/get-code-scans).
- Mit Pro und Business nimmt `POST /v1/codes` ein Array mit bis zu {facts.apiBatchCodes} Codes in einer einzigen Alles-oder-nichts-Anfrage entgegen. Mit einem `Idempotency-Key`-Header erzeugt ein erneuter Versuch nie Duplikate, und `Prefer: return=minimal` lässt das Design jedes Codes weg. Die Details findest du unter [Codes erstellen](/docs/developers/api/create-codes).
- `slug` legt den hinteren Teil des Links fest, `domainId` eine eigene Domain, `kind` schaltet zwischen Weiterleitung und Seite um, und `preciseLocation` aktiviert den Schritt zur Standortabfrage. Jeder Code wird mit `shortLink`, `defaultShortLink` und `nfcLink` zurückgegeben.
- Jeder Fehler hat dieselbe Struktur: siehe [Fehler](/docs/developers/errors).

Die Seite [REST API](/docs/developers/rest-api) erklärt Authentifizierung und Rate Limits; die [Schnellstartanleitung](/docs/developers/quickstart) erstellt deinen ersten Code über das Terminal.

## Self-Hosting [#self-hosting]

Dynamische Codes funktionieren auf einer selbst gehosteten Instanz mit zwei optionalen Variablen: `NEXT_PUBLIC_SHORT_LINK_BASE_URL` legt den Origin der Kurzlinks fest (Standard ist die URL deiner App) und `SCAN_HASH_SALT` legt den Salt für die Besucher-Hashes fest (ohne ihn wird einer aus `BETTER_AUTH_SECRET` abgeleitet). Land, Region und Stadt stammen aus den Geo-Headern von Vercel; hinter Cloudflare wird nur das Land gelesen, und anderswo werden Standorte als unbekannt angezeigt. [Gebietsregeln](/docs/precise-location#route-scans-by-area) verwenden die IP-Koordinaten von Vercel, wenn eine scannende Person keinen Standort geteilt hat; außerhalb von Vercel greifen sie daher nur bei geteilten Standorten. Rate Limits gelten, sobald Upstash Redis konfiguriert ist. Siehe [Self-Hosting](/docs/self-hosting#optional-services).
