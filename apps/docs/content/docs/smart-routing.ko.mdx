[동적 QR 코드](/docs/dynamic-qr-codes)는 보통 모든 스캔을 하나의 목적지로 보냅니다. 스마트 라우팅을 사용하면 인쇄된 코드 하나로 iPhone에서는 App Store를, Android에서는 Google Play를 열 수 있고, 스페인어 사용자에게는 스페인어 페이지를, 영업시간 외에는 다른 혜택 페이지를 보여줄 수도 있습니다. 누가, 어디서, 언제 스캔하느냐에 따라 알맞은 페이지가 달라질 때 사용하세요.

<Callout type="info" title="Pro와 Business">
  스마트 라우팅과 UTM 매개변수는 Pro와 Business에서 사용할 수 있습니다. 웹사이트 링크를 여는 코드에 적용되며, [호스팅 페이지](/docs/landing-pages)는 리디렉션하지 않으므로 라우팅이 없습니다. [요금제 및 한도](/docs/plans-and-limits)를 참고하세요.
</Callout>

서두르시나요? 간단한 작업 안내 페이지가 있습니다: [스캔을 다른 링크로 보내기](/docs/help/dynamic-codes/routing).

## 작동 방식 [#how-it-works]

<Diagram id="smart-routing" />

라우팅은 코드의 **설정** 탭에 있는 **스마트 라우팅** 패널에서 설정합니다([코드](/dashboard?to=codes)에서 코드를 여세요).

- 코드 하나에는 최대 20개의 **규칙**을 만들 수 있습니다. 각 규칙은 조건("언제")과 동작("그러면": URL 또는 A/B 분할)으로 구성됩니다.
- 규칙은 스캔할 때마다 위에서 아래로 확인합니다. 조건이 모두 일치하는 첫 번째 규칙이 스캔의 이동 위치를 결정합니다. 화살표로 규칙 순서를 바꿀 수 있습니다.
- 일치하는 규칙이 없으면 스캔은 코드의 기본 목적지로 이동합니다.
- 조건이 없는 규칙은 모든 스캔과 일치하므로, 그 아래에 있는 규칙은 실행되지 않습니다.
- 규칙을 끄면 삭제하지 않고 사용하지 않는 상태로 보관할 수 있습니다.
- 변경 사항은 다음 스캔부터 적용되며, 코드를 다시 인쇄할 필요가 없습니다.

어떤 이유로 규칙을 평가할 수 없더라도 스캔은 기본 목적지로 이동합니다. 라우팅 때문에 코드가 작동을 멈추는 일은 없습니다.

## 조건 [#conditions]

각 조건은 **이(가) 아님**으로 반전할 수 있습니다(예: "국가가 US가 아님").

| 조건 | 일치하는 경우 | 참고 |
| --- | --- | --- |
| 기기 | 스캔한 기기가 휴대폰, 태블릿, 데스크톱 또는 기타 기기인 경우 | 브라우저의 user agent 기준 |
| 운영체제 | iOS, Android, Windows, macOS, Linux, ChromeOS, HarmonyOS 등 | iPhone과 iPad는 모두 iOS로 취급 |
| 국가 | 목록에 있는 국가에서 스캔한 경우 | `US, CA, GB` 같은 2자리 코드 |
| 지역 | 목록에 있는 지역에서 스캔한 경우 | `US-CA, US-NY` 같은 코드(국가와 하위 행정구역) |
| 언어 | 방문자가 선호하는 브라우저 언어가 목록에 있는 언어 중 하나인 경우 | `es`는 모든 스페인어 변형(`es-MX`, `es-ES`)과 일치하고, `pt-BR`은 브라질 포르투갈어만 일치 |
| 시간대 | 선택한 요일에, 직접 고른 시간대(time zone)의 두 시각 사이에 스캔한 경우 | 22:00부터 02:00 같은 구간은 자정을 넘기며 시작하는 날에 속함 |
| 날짜 범위 | 두 날짜 사이에 스캔한 경우 | 한쪽을 비워 두면 "까지" 또는 "부터"가 됨, 날짜는 브라우저의 시간대 기준 |
| 스캔 횟수 | 처음 N번의 스캔 중 하나이거나 N번 이후의 스캔인 경우 | 기록된 스캔만 집계하며(봇은 제외) 많은 사람이 동시에 스캔하면 대략적인 값 |
| 영역 | 스캔한 사람이 한 지점에서 반경(100 m~500 km) 안에 있는 경우 | [정밀 위치](/docs/precise-location)가 켜져 있으면 스캔한 사람이 공유한 위치를, 아니면 IP 주소의 대략적인 위치를 사용 |

국가, 지역, 영역의 IP 기반 위치는 스캔한 사람의 IP 주소에서 가져오며, QRdx는 IP 주소를 저장하지 않습니다. 위치를 알 수 없으면 위치 조건은 일치하지 않습니다("이(가) 아님" 조건은 일치합니다). [정밀 위치와 지오펜싱](/docs/precise-location)에서 영역 설정과, 코드가 특정 영역 안에서만 작동하게 만드는 방법을 설명합니다.

## 스마트 앱 링크 [#smart-app-links]

**규칙 추가** → **스마트 앱 링크(App Store / Google Play)**를 선택하면 규칙 두 개가 한 번에 만들어집니다. iOS는 App Store 링크로, Android는 Google Play 링크로 이동합니다. 그 외(데스크톱, 다른 휴대폰)는 예를 들어 웹사이트 같은 기본 목적지로 이동합니다.

## A/B 테스트 [#ab-tests]

규칙의 동작을 **URL 간 분할(A/B)**로 설정하고 URL과 가중치를 가진 변형을 2~5개 추가하세요. 70과 30으로 분할하면 방문자의 약 70%가 첫 번째 URL로 이동합니다.

- 할당은 고정됩니다. 같은 날 다시 스캔한 방문자는 같은 변형을 받습니다. 쿠키가 아니라 익명의 일별 방문자 해시를 기반으로 합니다.
- 코드의 **분석** 탭에는 분할의 변형이나 가중치가 마지막으로 바뀐 이후 변형별 스캔 수를 보여주는 **A/B 분할** 카드가 표시됩니다. 각 스캔은 제공된 변형을 함께 저장합니다. QRdx가 변형을 저장하기 전의 스캔은 현재 규칙으로 다시 계산하며, 이 경우 카드에 추정치라고 표시됩니다.
- 분할에도 조건을 걸 수 있습니다. 예를 들어 독일 방문자에게만 A/B 테스트를 할 수 있습니다.

## 규칙 테스트 [#test-your-rules]

코드에 규칙이 하나 이상 있으면 패널 하단의 **규칙 테스트(저장하지 않은 변경 사항 사용)**에서 기기, 운영체제, 국가, 지역, 언어, 날짜와 시간, 스캔 번호, 방문자, 위치별로 스캔이 어디로 이동할지 확인할 수 있습니다. 저장 여부와 관계없이 패널에 있는 그대로의 규칙을, 저장된 코드의 기본 목적지와 UTM 설정에 적용해 실행합니다. 어떤 규칙이 일치했고 다른 규칙은 왜 일치하지 않았는지 보여주며, UTM 매개변수를 포함한 최종 URL도 표시합니다.

## UTM 매개변수 [#utm-parameters]

라우팅 패널 아래의 **UTM 매개변수** 패널에서는 `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`와 직접 만든 매개변수를 최대 10개까지 각 스캔이 여는 URL에 추가할 수 있어, 분석 도구가 QR 트래픽을 구분할 수 있습니다.

- 매개변수는 라우팅 후에, 스캔이 이동하는 URL에 추가됩니다.
- URL에 이미 있는 매개변수는 바꾸지 않으며, URL의 나머지 부분은 입력한 그대로 유지됩니다.
- `qrdx_`로 시작하는 이름은 [전환 추적](/docs/tracking-and-conversions)용으로 예약되어 있습니다.

## 한도와 요금제 [#limits-and-plans]

| | 무료 | Pro | Business |
| --- | --- | --- | --- |
| 코드당 규칙 수 | 없음 | 20 | 20 |
| A/B 분할당 변형 수 | 없음 | 2~5 | 2~5 |
| 사용자 지정 UTM 매개변수 | 없음 | 10 | 10 |

Pro에서 저장한 규칙과 UTM 매개변수는 요금제를 다운그레이드해도 계속 작동합니다. 한도는 새로 만드는 것만 막습니다. Pro가 없어도 규칙을 끄거나 삭제하고 UTM 매개변수를 제거할 수 있지만, 수정하려면 다시 Pro가 필요합니다.

## 개발자용 [#for-developers]

규칙, 분할, UTM 매개변수는 대시보드에서 설정합니다. [코드 API](/docs/developers/api/update-code)는 코드와 목적지를 만들고 업데이트하지만 라우팅 규칙은 관리하지 않습니다. [`GET /v1/codes/{id}/scans`](/docs/developers/api/get-code-scans)에 기록된 각 스캔에는 규칙이 확인한 기기 유형, 운영체제, 국가, 지역, 도시가 포함됩니다.
