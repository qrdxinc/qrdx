REST APIのエラーは、どのエンドポイントから返される場合でも、すべて同じ形式のJSONです。`code` は変わることがないため、処理の分岐には `code` を使用してください。`message` は人が読むための文章であり、表現が変更されることがあります。

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## エラーコード [#error-codes]

ステータス順に並べています。同じコードが2回出てくる場合は、ステータスごとに意味が異なります。

| ステータス | コード | 発生する状況 | 対処方法 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | ボディ、クエリ、パスのいずれかが検証に失敗しました。`data.details` に各問題が `{ path, message }` の形式で一覧されます（Image API では `{ param, message }`）。ボディがコードの配列の場合は、その行の `index` も含まれます。 | `data.details` に示されたフィールドを修正して、リクエストを再送してください。 |
| 400 | `INVALID_SLUG` | カスタムバックハーフ（`slug`）がルールに違反しています。予約語である場合や、同じバックハーフが1回のリクエスト内に2回含まれている場合です。配列の場合、`data.details` に各行が `index` 付きで一覧されます。 | 別のバックハーフを選んでください。メッセージに違反したルールが示されます。 |
| 400 | `TOO_MANY_CODES` | 1回のリクエストに1,000件を超えるコードが含まれています。通常は、ボディのスキーマが先に `VALIDATION_ERROR` として拒否します。 | 1回のリクエストで送るコードは最大1,000件にしてください。 |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` が、まだ検証されていないカスタムドメインを指しています。 | ドメインページでドメインの検証を完了するか、`domainId` を指定しないでください。 |
| 400 | `SID_REQUIRED` | コンバージョンの送信時に、スキャンの `qrdx_sid`（ブラウザから送る場合）、または `sid` か `code`（サーバーから送る場合）がありません。 | ショートリンクがページURLに付与した `qrdx_sid` を送信してください。APIキーまたはトークンを使う場合は、コードIDを `code` として送信してください。 |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` がAIアート用としては長すぎます（300文字を超えています）。 | 代わりに動的コードのIDを `code` として送信してください。アートにはそのショートリンクがエンコードされるため、短く、編集可能なままです。 |
| 401 | `UNAUTHORIZED` | 認証情報がありません。リクエストに `Authorization: Bearer` ヘッダーがなく、QRdxのブラウザセッションもありません。 | APIキーを `Authorization: Bearer <key>` として送信してください。キーは「設定 → APIキーとアプリ」で作成できます。OAuthアクセストークンも同じヘッダーで送信します。 |
| 401 | `INVALID_TOKEN` | APIキーまたはアクセストークンが不明、失効済み、または期限切れです（アクセストークンの有効期間は1時間です）。または、キーの作成者がBANされたか、キーのワークスペースを離れました。 | キー全体を送信しているか確認するか、新しいキーを作成してください。アクセストークンの場合は、リフレッシュトークンで新しいトークンを取得するか、ユーザーにもう一度認可してもらってください。 |
| 402 | `PLAN_REQUIRED` | この機能はワークスペースのプランに含まれていません。一括作成、カスタムバックハーフ、カスタムドメインには Pro が、コンバージョンとフックには Business が必要です。 | ワークスペースをアップグレードするか、リクエストからその機能を外してください。 |
| 402 | `LIMIT_REACHED` | ワークスペースのアクティブな動的コードが、プランに含まれる数に達しています（フリーでは10個）。 | コードをアーカイブするか（アーカイブ済みのコードは数に含まれません）、Pro にアップグレードしてコードを無制限にしてください。 |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | ワークスペースが今月分のAIアート画像をすべて使用しました（フリーと Pro）。このリクエストでは課金されていません。 | 毎月1日（UTC）に利用枠がリセットされるまでお待ちください。または、アップグレードして画像数を増やしてください。 |
| 403 | `INSUFFICIENT_SCOPE` | APIキーまたはトークンは有効ですが、このエンドポイントに必要なスコープがありません。 | メッセージに示されたスコープを持つキーを作成してください（キーのスコープは変更できません）。OAuthアプリの場合は、スコープを追加し、ユーザーの認可時にそのスコープを要求してください。 |
| 403 | `FORBIDDEN` | 呼び出し元にはこの操作を行う権限がありません。たとえば、ワークスペースのメンバーが他のユーザーの作成したコードを削除する場合、メンバーがフックを管理する場合、または別のサイトからブラウザセッションで書き込みを行う場合です。APIキーでできるのは、そのワークスペースにおけるキー作成者のロールで許可されている操作のみです。 | ワークスペースのオーナーまたは管理者に依頼するか、サーバーからAPIキーを使ってAPIを呼び出してください。 |
| 403 | `CONFIRMATION_REQUIRED` | サインイン済みのブラウザセッションでフックを作成するには、直近の「本人確認」が必要です。APIキーとOAuthトークンでは求められません。 | QRdxで本人確認を行い、10分以内にもう一度お試しください。または、サーバーからAPIキーを使ってフックを作成してください。 |
| 403 | `CONVERSIONS_OFF` | コンバージョントラッキングがオンになっていないコードに対して、ブラウザからコンバージョンが送信されました。 | そのコードのコンバージョントラッキングをオンにするか、サーバーからAPIキーを使ってコンバージョンを報告してください。 |
| 403 | `LIMIT_REACHED` | ワークスペースにはすでに20件のWebhookエンドポイントとフックがあります。 | 使っていないエンドポイントまたはフックを削除してください。 |
| 404 | `NOT_FOUND` | そのエンドポイントが存在しないか、キーまたはトークンが操作対象とするワークスペースに、コード、フック、テーマ、カスタムドメインが存在しません。 | パスとIDを確認してください。APIキーは作成されたワークスペースで動作し、OAuthトークンはそのユーザー自身のワークスペースで動作します。 |
| 404 | `INVALID_SID` | `qrdx_sid` が不明か、帰属期間である30日より古くなっています。 | 最近のスキャンの `qrdx_sid` を送信するか、サーバーからコードIDを指定してコンバージョンを報告してください。 |
| 409 | `SLUG_TAKEN` | そのドメインでは、別のコードがすでにそのバックハーフを使用しています。配列の場合、`data.details` に使用済みの各行が `index` 付きで一覧され、何も作成されません。 | 別のバックハーフを選んでください。 |
| 413 | `PAYLOAD_TOO_LARGE` | ボディがエンドポイントの上限を超えています。コードは4 MB、フックは16 KB、コンバージョンは8 KBです。また、レスポンス（各コードとそのデザイン）が4 MBを超えるコードのバッチも該当します。この場合、何も作成されません。 | ボディを小さくして送信してください。コードの場合は、インラインの大きなロゴが原因であることが多いです。バッチの場合は、`Prefer: return=minimal` を送信するか、コードの数を減らしてください。 |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | `photo` または `reference` の画像がAIアートのサイズ上限を超えています（どちらかはメッセージに示されます）。 | 画像を縮小し（`reference` は長辺を約512 px、`photo` は約1024 px四方）、PNGまたはJPEGのデータURLとして再送してください。 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | `Content-Type: application/json` なしで書き込みが行われました。 | `Content-Type: application/json` を付けて、JSONボディを送信してください。 |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk が宛先URLにフラグを立てました（マルウェア、フィッシング、または不要なソフトウェア）。配列の場合、`data.details` にフラグが立った各行が `index` 付きで一覧され、何も作成されません。 | 別の宛先を使用してください。フラグが誤りの場合は、Googleにサイトの再審査を依頼してください。 |
| 429 | `RATE_LIMITED` | リクエストが多すぎます。分単位の制限（設定されるのは `Retry-After` のみ）、またはワークスペースの1日あたりのクォータ（`Retry-After` と `X-RateLimit-*`）に達しました。 | `Retry-After` の秒数だけお待ちください。1日あたりのクォータの場合は、00:00 UTCまで待つか、プランをアップグレードしてください。 |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Business のワークスペースが今月分のAIアート画像をすべて使用しました。この枠はチーム全体で共有されます。 | 毎月1日（UTC）に利用枠がリセットされるまでお待ちください。 |
| 429 | `AI_ART_DAILY_LIMIT` | キーの作成者が今日（UTC）すでに25枚のAIアート画像を作成しました。これは月間の利用枠とは別の、安全のための上限です。 | 明日（UTC）にもう一度お試しください。 |
| 500 | `INTERNAL_ERROR` | QRdx側で何らかの障害が発生しました。内容はログに記録されています。 | しばらくしてからもう一度お試しください。繰り返し発生する場合は、リクエストの時刻を添えてご報告ください。 |
| 502 | `AI_ART_FAILED` | 画像モデルが失敗したか、プロンプトを拒否したか、QRdxが読み取れない画像を返しました。AIアートのクレジットは消費されていません。 | もう一度お試しいただくか、プロンプトを言い換えてください。メッセージに状況が示されます。 |
| 502 | `AI_ART_UNSCANNABLE` | モデルの画像を、選択したQRの可視度の範囲内でスキャンできるようにできませんでした。AIアートのクレジットは消費されていません。 | `visibility` を上げるか、別のシードでもう一度お試しください。 |
| 502 | `AI_ART_DESCRIBE_FAILED` | `prompt` を指定しなかったため、代わりにプロンプトを作成するテキストモデルが動作しましたが、失敗しました。AIアートのクレジットは消費されていません。 | もう一度お試しいただくか、独自の `prompt` を送信してください。 |
| 503 | `SLUG_UNAVAILABLE` | 空いているショートリンクのスラッグを、時間内に確保できませんでした。 | 同じリクエストをもう一度送信してください。 |
| 503 | `AI_ART_BUSY` | 画像モデルが現在、処理能力の上限を超えています。AIアートのクレジットは消費されていません。 | 1分ほど待ってから、もう一度お試しください。 |
| 503 | `AI_NOT_CONFIGURED` | このデプロイ環境ではAIアートが設定されていません（`AI_GATEWAY_API_KEY` のないセルフホストのインスタンスです）。 | ホスト版のQRdx APIを使用するか、お使いのインスタンスにVercel AI Gatewayを設定してください。 |
| 503 | `UNAVAILABLE` | このデプロイ環境ではカスタムドメインが設定されていません（カスタムドメインのないセルフホストのインスタンスです）。 | `domainId` を指定しないか、お使いのインスタンスでカスタムドメインを設定してください。 |
| 504 | `AI_ART_TIMEOUT` | 画像モデルの処理に時間がかかりすぎたため、リクエストの1分の制限に達する前にQRdxが待機を打ち切りました。AIアートのクレジットは消費されていません。 | もう一度お試しください。通常、呼び出しには15〜45秒かかります。 |

## エラーの本文 [#the-error-body]

| フィールド | 内容 |
| --- | --- |
| `code` | 上の表にある、機械で読み取れる固定のコード |
| `message` | 何が問題で、どう直せばよいかを人向けに説明した文。文言は変更されることがあります |
| `status` | HTTPステータス（重複して返されます） |
| `docs` | 修正方法を説明するページ（ある場合） |
| `data` | 一部のエラーに付く追加の詳細。`VALIDATION_ERROR` では、各問題が `data.details` に一覧で入ります |

バリデーションエラーでは、失敗したすべてのフィールドが示されます。コードを一括で処理した場合は、各問題に、0から数えた行の `index` も含まれます。

```json title="400 Bad Request"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

画像エンドポイント（`GET /v1/qr`、`GET /v1/barcode`）では、クエリパラメータは `{ "path", "message" }` ではなく `{ "param", "message" }` の形式で報告されます。

## リトライ [#retrying]

- **`429`:** `Retry-After` に示された秒数だけ待ってから、同じリクエストを送信してください。1日のクォータを使い切った場合は、`X-RateLimit-*` ヘッダーに、プランで許可されているリクエスト数とカウントがリセットされる時刻（00:00 UTC）が示されます。1分あたりの制限では `Retry-After` のみが返されます。[レート制限](/docs/developers/rest-api#rate-limits)を参照してください。
- **`500`、`502`、`503`、`504`:** 約1秒から始めて、指数バックオフでリトライしてください。AIアートの `5xx` エラーでは画像が使われないため、リトライしても消費はありません。
- **その他の `4xx`:** 同じリクエストは同じように失敗します。まずリクエストを修正してください。

`POST /v1/codes` は、リクエストに `Idempotency-Key` ヘッダーを付けていれば安全にリトライできます。同じキーを送ると、コードが二重に作成されることはなく、最初の試行で作成されたコードが `Idempotent-Replayed: true` とともに返されます（[コードを作成](/docs/developers/api/create-codes)）。ヘッダーがない場合は、リクエストを再送する前にコードの一覧を確認してください。`POST /v1/conversions` は、独自の `id` を送っていれば安全に繰り返せます。再送すると、`duplicate: true` とともに `200` が返されます。

## `/v1/me` と `/v1/themes` [#v1me-and-v1themes]

この2つのエンドポイントは、同じ本文に加えて、従来から返しているOAuthのフィールド `error` と `error_description`（`message` と同じ文）も返します。これにより、古いクライアントも引き続き動作します。

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED または INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED（1日のクォータ） |
| `not_found` | NOT_FOUND（テーマ） |

## OAuthエンドポイント [#oauth-endpoints]

`https://qrdx.dev/api/oauth` 配下のOAuthエンドポイント（authorize、token、revoke、userinfo）は、代わりにOAuth 2.0の標準に従い、`{ "error", "error_description" }` を返します。`error` は `invalid_request`、`invalid_client`、`invalid_grant`、`unsupported_grant_type`、`invalid_token`、`access_denied` のいずれかです。更新時に `invalid_grant` が返された場合は、リフレッシュトークンがすでに使用済み（更新のたびに新しいトークンが返されます）、30日で期限切れ、またはユーザーがアプリを取り消したことを意味します。ユーザーにもう一度認可の手順を行ってもらってください。[REST APIとOAuth](/docs/developers/rest-api#get-an-access-token)を参照してください。

## 存在しないエンドポイント [#unknown-endpoints]

`/v1` 配下に存在しないパスへアクセスすると、HTMLページではなく、JSONで `404 NOT_FOUND` が返されます。エンドポイント一覧への `docs` リンクも含まれます。[APIリファレンス](/docs/developers/api)には、すべてのエンドポイントが載っています。
