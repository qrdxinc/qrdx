Chaque erreur de la REST API est renvoyée en JSON, avec la même structure, quel que soit le point de terminaison concerné. Appuyez-vous sur `code`, qui ne change jamais, pour votre logique de traitement ; `message` s'adresse aux humains et sa formulation peut évoluer.

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## Codes d'erreur [#error-codes]

Classés par statut. Un code qui apparaît deux fois a une signification différente selon le statut.

| Statut | Code | Quand cela se produit | Que faire |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Le corps, la requête (query) ou le chemin (path) a échoué à la validation. `data.details` liste chaque problème sous la forme `{ path, message }` (`{ param, message }` sur l'image API), avec l'`index` de la ligne lorsque le corps est un tableau de codes. | Corrigez les champs listés dans `data.details`, puis renvoyez la requête. |
| 400 | `INVALID_SLUG` | La fin d'URL personnalisée (`slug`) enfreint une règle : un mot réservé, ou la même fin d'URL deux fois dans une même requête. Pour un tableau, `data.details` liste chaque ligne par `index`. | Choisissez une autre fin d'URL. Le message indique la règle concernée. |
| 400 | `TOO_MANY_CODES` | Plus de 1 000 codes dans une même requête. Le schéma du corps la rejette normalement d'abord, avec `VALIDATION_ERROR`. | Envoyez au maximum 1 000 codes par requête. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` pointe vers un domaine personnalisé qui n'est pas encore vérifié. | Terminez la vérification du domaine sur la page Domaines, ou omettez `domainId`. |
| 400 | `SID_REQUIRED` | Une conversion sans le `qrdx_sid` du scan (depuis le navigateur), ou sans `sid` ni `code` (depuis un serveur). | Envoyez le `qrdx_sid` que le lien court a ajouté à l'URL de votre page ou, avec une clé API ou un jeton, l'identifiant du code dans `code`. |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` est trop long pour l'art IA (plus de 300 caractères). | Envoyez plutôt l'identifiant d'un QR code dynamique dans `code` : l'art encode son lien court, qui est court et reste modifiable. |
| 401 | `UNAUTHORIZED` | Aucun identifiant : la requête n'a pas d'en-tête `Authorization: Bearer` (ni de session de navigateur QRdx). | Envoyez une clé API sous la forme `Authorization: Bearer <key>` ; créez-en une dans Paramètres → Clés API et applications. Les jetons d'accès OAuth se placent dans le même en-tête. |
| 401 | `INVALID_TOKEN` | La clé API ou le jeton d'accès est inconnu, révoqué ou expiré (les jetons d'accès durent une heure), ou le créateur de la clé a été banni ou a quitté l'espace de travail de la clé. | Vérifiez que vous avez envoyé la clé en entier, ou créez-en une nouvelle. Pour un jeton d'accès, obtenez-en un nouveau avec votre jeton d'actualisation, ou renvoyez l'utilisateur vers l'autorisation. |
| 402 | `PLAN_REQUIRED` | La fonctionnalité n'est pas incluse dans le forfait de l'espace de travail : la création en masse, les fins d'URL personnalisées et les domaines personnalisés nécessitent Pro ; les conversions et les hooks nécessitent Business. | Passez l'espace de travail à un forfait supérieur, ou retirez la fonctionnalité de la requête. |
| 402 | `LIMIT_REACHED` | L'espace de travail a atteint le nombre de QR codes dynamiques actifs inclus dans son forfait (10 avec Gratuit). | Archivez un code (les codes archivés ne comptent pas) ou passez à Pro pour avoir des codes illimités. |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | L'espace de travail a utilisé les images d'art IA de ce mois (Gratuit et Pro). Rien n'a été facturé pour la requête. | Attendez la réinitialisation du quota le 1er du mois (UTC), ou passez à un forfait supérieur pour obtenir plus d'images. |
| 403 | `INSUFFICIENT_SCOPE` | La clé API ou le jeton est valide, mais n'a pas la portée (scope) requise par ce point de terminaison. | Créez une clé avec la portée indiquée dans le message (les portées d'une clé ne peuvent pas être modifiées). Pour une application OAuth, ajoutez la portée et demandez-la lors de l'autorisation par l'utilisateur. |
| 403 | `FORBIDDEN` | L'appelant n'est pas autorisé à effectuer cette action : un membre de l'espace de travail qui supprime un code créé par quelqu'un d'autre, un membre qui gère des hooks, ou une écriture depuis une session de navigateur provenant d'un autre site. Une clé API ne peut faire que ce que permet le rôle de son créateur dans son espace de travail. | Demandez à un propriétaire ou à un administrateur de l'espace de travail, ou appelez l'API avec une clé API depuis votre serveur. |
| 403 | `CONFIRMATION_REQUIRED` | La création d'un hook avec une session de navigateur connectée nécessite une confirmation « C'est bien vous » récente. Les clés API et les jetons OAuth n'ont pas à la fournir. | Confirmez votre identité dans QRdx, puis réessayez dans les 10 minutes, ou créez le hook avec une clé API depuis votre serveur. |
| 403 | `CONVERSIONS_OFF` | Une conversion depuis le navigateur pour un code dont le suivi des conversions n'est pas activé. | Activez le suivi des conversions pour le code, ou signalez la conversion depuis votre serveur avec une clé API. |
| 403 | `LIMIT_REACHED` | L'espace de travail compte déjà 20 points de terminaison webhook et hooks. | Supprimez un point de terminaison ou un hook que vous n'utilisez plus. |
| 404 | `NOT_FOUND` | Ce point de terminaison n'existe pas, ou le code, le hook, le thème ou le domaine personnalisé n'existe pas dans l'espace de travail sur lequel agit la clé ou le jeton. | Vérifiez le chemin et l'identifiant. Une clé API agit sur l'espace de travail où elle a été créée ; un jeton OAuth agit sur l'espace de travail personnel de son utilisateur. |
| 404 | `INVALID_SID` | Le `qrdx_sid` est inconnu ou date de plus de 30 jours, la fenêtre d'attribution. | Envoyez le `qrdx_sid` d'un scan récent, ou signalez la conversion par identifiant de code depuis votre serveur. |
| 409 | `SLUG_TAKEN` | Un autre code utilise déjà cette fin d'URL sur ce domaine. Pour un tableau, `data.details` liste chaque fin d'URL prise par `index`, et rien n'est créé. | Choisissez une autre fin d'URL. |
| 413 | `PAYLOAD_TOO_LARGE` | Le corps dépasse la limite du point de terminaison : 4 Mo pour les codes, 16 Ko pour les hooks, 8 Ko pour les conversions. Également un lot de codes dont la réponse (chaque code avec son design) dépasserait 4 Mo ; rien n'est créé. | Envoyez un corps plus petit. Pour les codes, la cause habituelle est un logo volumineux intégré ; pour un lot, envoyez `Prefer: return=minimal` ou moins de codes. |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | L'image `photo` ou `reference` dépasse la taille maximale pour l'art IA (le message indique laquelle). | Réduisez la taille de l'image (une `reference` à environ 512 px sur son plus grand côté, une `photo` à environ 1024 px de côté) et renvoyez-la sous forme d'URL de données PNG ou JPEG. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Une écriture sans `Content-Type: application/json`. | Envoyez un corps JSON avec `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk signale l'URL de destination (logiciel malveillant, hameçonnage ou logiciel indésirable). Pour un tableau, `data.details` liste chaque ligne signalée par `index`, et rien n'est créé. | Utilisez une autre destination. Si le signalement est erroné, demandez à Google de réexaminer le site. |
| 429 | `RATE_LIMITED` | Trop de requêtes : une limite par minute (seul `Retry-After` est défini) ou le quota quotidien de l'espace de travail (`Retry-After` plus `X-RateLimit-*`). | Attendez `Retry-After` secondes. Pour le quota quotidien, attendez 00:00 UTC ou passez à un forfait supérieur. |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Un espace de travail Business a utilisé les images d'art IA de ce mois, partagées par toute l'équipe. | Attendez la réinitialisation du quota le 1er du mois (UTC). |
| 429 | `AI_ART_DAILY_LIMIT` | Le créateur de la clé a généré 25 images d'art IA aujourd'hui (UTC), un plafond de sécurité en plus du quota mensuel. | Réessayez demain (UTC). |
| 500 | `INTERNAL_ERROR` | Une défaillance est survenue côté QRdx. Elle a été consignée. | Réessayez dans un instant. Si le problème persiste, signalez-le en indiquant l'heure de la requête. |
| 502 | `AI_ART_FAILED` | Le modèle d'image a échoué, a refusé le prompt ou a renvoyé une image que QRdx n'a pas pu lire. Aucun crédit d'art IA n'a été utilisé. | Réessayez, ou reformulez le prompt. Le message indique ce qui s'est passé. |
| 502 | `AI_ART_UNSCANNABLE` | Il a été impossible de rendre l'image du modèle scannable avec la visibilité du QR que vous avez choisie. Aucun crédit d'art IA n'a été utilisé. | Réessayez avec une `visibility` plus élevée, ou une autre graine (seed). |
| 502 | `AI_ART_DESCRIBE_FAILED` | Vous avez omis `prompt`, et le modèle de texte qui en rédige un pour vous a échoué. Aucun crédit d'art IA n'a été utilisé. | Réessayez, ou envoyez votre propre `prompt`. |
| 503 | `SLUG_UNAVAILABLE` | Aucun slug de lien court libre n'a pu être réservé à temps. | Renvoyez la même requête. |
| 503 | `AI_ART_BUSY` | Le modèle d'image est actuellement saturé. Aucun crédit d'art IA n'a été utilisé. | Attendez une minute et réessayez. |
| 503 | `AI_NOT_CONFIGURED` | L'art IA n'est pas configuré sur ce déploiement (une instance auto-hébergée sans `AI_GATEWAY_API_KEY`). | Utilisez l'API QRdx hébergée, ou configurez Vercel AI Gateway sur votre instance. |
| 503 | `UNAVAILABLE` | Les domaines personnalisés ne sont pas configurés sur ce déploiement (une instance auto-hébergée sans domaines personnalisés). | Omettez `domainId`, ou configurez les domaines personnalisés sur votre instance. |
| 504 | `AI_ART_TIMEOUT` | Le modèle d'image a mis trop de temps, et QRdx a cessé d'attendre avant la limite d'une minute de la requête. Aucun crédit d'art IA n'a été utilisé. | Réessayez. Les appels durent généralement de 15 à 45 secondes. |

## Le corps de l'erreur [#the-error-body]

| Champ | Description |
| --- | --- |
| `code` | Un code stable, lisible par une machine, issu du tableau ci-dessus |
| `message` | Ce qui s'est mal passé et comment le corriger, à l'attention des utilisateurs. La formulation peut changer |
| `status` | Le statut HTTP, répété |
| `docs` | Une page qui explique la correction, lorsqu'il y en a une |
| `data` | Détails supplémentaires pour certaines erreurs. `VALIDATION_ERROR` liste chaque problème dans `data.details` |

Une erreur de validation nomme chaque champ en échec. Dans un lot de codes, chaque problème indique aussi l'`index` de la ligne, compté à partir de 0 :

```json title="400 Bad Request"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Les endpoints d'image (`GET /v1/qr`, `GET /v1/barcode`) signalent les paramètres de requête sous la forme `{ "param", "message" }` au lieu de `{ "path", "message" }`.

## Nouvelles tentatives [#retrying]

- **`429` :** attendez le nombre de secondes indiqué dans `Retry-After`, puis renvoyez la même requête. Lorsque le quota quotidien est épuisé, les en-têtes `X-RateLimit-*` indiquent combien de requêtes le plan autorise et quand le compteur est réinitialisé (00:00 UTC). Une limite par minute envoie uniquement `Retry-After`. Voir [limites de débit](/docs/developers/rest-api#rate-limits).
- **`500`, `502`, `503` et `504` :** réessayez avec un backoff exponentiel, en commençant à environ une seconde. Les erreurs `5xx` de l'art IA n'utilisent jamais d'image, donc une nouvelle tentative ne coûte rien.
- **Autres `4xx` :** la même requête échoue de la même manière. Corrigez-la d'abord.

Réessayer `POST /v1/codes` est sans risque lorsque la requête contient un en-tête `Idempotency-Key` : la même clé renvoie les codes créés par la première tentative, avec `Idempotent-Replayed: true`, au lieu de les créer deux fois ([Créer des codes](/docs/developers/api/create-codes)). Sans cet en-tête, listez vos codes avant de renvoyer la requête. `POST /v1/conversions` peut être répété sans risque si vous envoyez votre propre `id` : une répétition renvoie `200` avec `duplicate: true`.

## `/v1/me` et `/v1/themes` [#v1me-and-v1themes]

Ces deux endpoints envoient le même corps, plus les champs OAuth qu'ils ont toujours envoyés, `error` et `error_description` (le même texte que `message`), afin que les anciens clients continuent de fonctionner :

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED ou INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (quota quotidien) |
| `not_found` | NOT_FOUND (thèmes) |

## Endpoints OAuth [#oauth-endpoints]

Les endpoints OAuth sous `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) suivent à la place la norme OAuth 2.0 : `{ "error", "error_description" }`, avec `error` valant `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` ou `access_denied`. Obtenir `invalid_grant` lors d'un renouvellement signifie que le refresh token a déjà été utilisé (chaque renouvellement en renvoie un nouveau), qu'il a expiré après 30 jours, ou que l'utilisateur a révoqué votre application : faites repasser l'utilisateur par l'autorisation. Voir [REST API et OAuth](/docs/developers/rest-api#get-an-access-token).

## Endpoints inconnus [#unknown-endpoints]

Un chemin sous `/v1` qui n'existe pas renvoie `404 NOT_FOUND` en JSON, jamais une page HTML, avec un lien `docs` vers la liste des endpoints. La [référence de l'API](/docs/developers/api) liste tous les endpoints.
