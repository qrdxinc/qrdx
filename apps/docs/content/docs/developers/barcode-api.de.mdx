Am Ende dieser Seite hast du eine Barcode-Bild-URL für ein `<img>`-Tag, einen Produkt-Feed oder eine Etikettenvorlage, weißt, wie Prüfziffern und Formate validiert werden, und weißt, wie du Barcodes in einem Workspace speicherst, um sie später zu bearbeiten.

`GET https://api.qrdx.dev/v1/barcode` liefert ein Barcode-Bild. Alles steht im Query-String, die URL ist also das Bild. Die API zeichnet dieselben {facts.barcodeFormats} Formate wie der [Barcode-Generator](/barcode-generator), mit denselben Regeln, und liefert dieselbe SVG. Du brauchst weder ein Konto noch einen API-Schlüssel.

```html title="index.html"
<img
  src="https://api.qrdx.dev/v1/barcode?format=ean13&data=590123412345"
  alt="EAN-13 barcode 5901234123457"
/>
```

Dieser Wert ist eine Ziffer zu kurz, daher wird die Prüfziffer (7) ergänzt. Sendest du alle 13 Ziffern, wird stattdessen die Prüfziffer geprüft: Eine falsche liefert `400` mit dem Hinweis, wie sie lauten müsste.

## 1. Bild anfordern [#1-request-an-image]

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -o box.png "https://api.qrdx.dev/v1/barcode?format=ean13&data=5901234123457&type=png&scale=3"
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="barcode.mjs"
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/barcode");
    url.search = new URLSearchParams({
      format: "ean13",
      data: "5901234123457",
      type: "png",
      scale: "3",
    }).toString();

    const response = await fetch(url);
    await writeFile("box.png", Buffer.from(await response.arrayBuffer()));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="barcode.py"
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/barcode",
        params={"format": "ean13", "data": "5901234123457", "type": "png", "scale": 3},
    )
    response.raise_for_status()
    open("box.png", "wb").write(response.content)
    ```
  </Tab>
</Tabs>

```txt title="Output"
200 image/png
box.png: PNG image data, 385 x 237, 8-bit/color RGBA, non-interlaced
```

Setze die URL in der Shell in Anführungszeichen, damit das `&` erhalten bleibt, und kodiere Werte mit `&`, `#`, `+` oder Leerzeichen, zum Beispiel mit `encodeURIComponent` in JavaScript.

## 2. Weitere Beispiele [#2-more-examples]

Ein Vektor-PDF eines GS1-128-Logistiketiketts, mit Klammern um jeden Application Identifier:

```bash title="Terminal"
curl -o pallet.pdf "https://api.qrdx.dev/v1/barcode?format=gs1-128&type=pdf&data=(01)09501101530003(17)261231(10)AB-123"
# 200 application/pdf, 1 page
```

Ein Code-128-Regaletikett in Dunkelblau, ohne den Text unter den Balken, um 90° gedreht:

```txt
https://api.qrdx.dev/v1/barcode?format=code128&data=SHELF-A12&fg=1e3a8a&text=false&rotate=90
```

Ein Data Matrix mit breiterem Rand:

```txt
https://api.qrdx.dev/v1/barcode?format=datamatrix&data=SN-0042-7781&quietZone=4
```

## 3. Den Wert aus der URL heraushalten [#3-keep-the-value-out-of-the-url]

`POST https://api.qrdx.dev/v1/barcode` nimmt dieselben Felder als JSON entgegen und liefert dieselbe Datei, ungecacht. Nutze es, wenn der Wert nicht wie bei einer URL in Logs, im Verlauf oder in Caches landen soll:

```bash title="Terminal"
curl -o label.png https://api.qrdx.dev/v1/barcode \
  -H "Content-Type: application/json" \
  -d '{"format":"datamatrix","data":"Internal note 42","type":"png"}'
# 200 image/png, Cache-Control: no-store
```

In JSON ist `text` ein Boolean, und `scale`, `height`, `quietZone` und `rotate` sind Zahlen. Ein Body ohne `Content-Type: application/json` führt zu `415`:

```json title="415 Unsupported Media Type"
{"code":"UNSUPPORTED_MEDIA_TYPE","message":"Send a JSON body with Content-Type: application/json.","status":415}
```

## Parameter [#parameters]

| Parameter | Standard | Beschreibung |
| --- | --- | --- |
| `format` | erforderlich | Der Barcode-Typ; siehe [Formate](#formats). Groß- und Kleinschreibung sowie Bindestriche spielen keine Rolle: `EAN-13` funktioniert auch |
| `data` | erforderlich | Die zu kodierende Zahl oder der Text, bis zu 1.000 Zeichen (bei den meisten linearen Formaten weniger) |
| `type` | `svg` | `svg`, `png`, `jpg`, `webp`, `avif`, `pdf` oder `eps` |
| `scale` | `4` | Pixel pro Modul bei PNG, JPG, WebP und AVIF, `1` bis `10` |
| `height` | abhängig vom Format | Balkenhöhe linearer Barcodes in Millimetern bei Vektorgröße, `5` bis `60` (23 für EAN-13) |
| `quietZone` | das Minimum des Formats | Leerer Rand in Modulen: je Seite bei linearen Barcodes (`0` bis `20`), rundherum bei 2D-Codes (`0` bis `10`) |
| `text` | `true` | Die Ziffern oder den Text unter linearen Barcodes ausgeben |
| `fg` | `000000` | Balken und Text, als Hex |
| `bg` | `ffffff` | Hintergrund, als Hex |
| `rotate` | `0` | Drehung im Uhrzeigersinn: `0`, `90`, `180` oder `270` |

Schreibe Farben ohne das `#` oder kodiere es als `%23`.

## Formate [#formats]

| `format` | Barcode | Akzeptiert |
| --- | --- | --- |
| `ean13` | EAN-13 | 12 Ziffern (Prüfziffer wird ergänzt) oder 13 (wird geprüft) |
| `ean8` | EAN-8 | 7 Ziffern oder 8 |
| `upca` | UPC-A | 11 Ziffern oder 12 |
| `upce` | UPC-E | 6 bis 8 Ziffern oder ein 12-stelliger UPC-A, der verkürzt werden kann |
| `itf14` | ITF-14 | 13 Ziffern oder 14 |
| `gs1-128` | GS1-128 | Application Identifier in Klammern mit ihren Werten; GTIN- und SSCC-Prüfziffern werden ergänzt oder geprüft; bis zu 48 Zeichen Daten |
| `code128` | Code 128 | Bis zu 80 druckbare ASCII-Zeichen |
| `code39` | Code 39 | Bis zu 40 Großbuchstaben, Ziffern, Leerzeichen und `- . $ / + %` |
| `datamatrix` | Data Matrix | Beliebiger Text bis zu 1.000 Zeichen |
| `pdf417` | PDF417 | Beliebiger Text bis zu 1.000 Zeichen |
| `aztec` | Aztec | Beliebiger Text bis zu 1.000 Zeichen |

Handelsnummern (EAN, UPC, ITF-14, die GTIN von GS1-128) werden von GS1 an Unternehmen lizenziert. Die API zeichnet jede gültige Nummer; sie vergibt oder registriert keine.

## Größen [#sizes]

PNG, JPG, WebP und AVIF haben `scale` Pixel pro Modul, also die Breite des schmalsten Balkens. Eine 2D-Zelle ist zwei Module breit.

SVG, PDF und EPS sind Vektoren mit einem Punkt pro Modul (0,353 mm). Ein EAN-13 mit den Standardwerten kommt daher auf etwa 45 × 28 mm, rund 107 % der Nenngröße. Skaliere Vektordateien in deinem Layout; bei Handelsbarcodes bleib zwischen 80 % und 200 % und kürze die Balkenhöhe nicht.

## Antworten [#responses]

Eine erfolgreiche Anfrage liefert die Datei mit:

- `Content-Type` des Dateityps. EPS kommt als Download (`Content-Disposition: attachment`); die anderen werden inline mit einem Dateinamen wie `ean13-5901234123457.png` geöffnet
- `Cache-Control: public, max-age=31536000, immutable` bei `GET`: Dieselbe Query liefert immer dieselben Bytes. `POST`-Antworten sind `no-store`
- `Access-Control-Allow-Origin: *`, sodass du sie von jeder Website per `fetch` laden kannst

## Gespeicherte Barcodes [#saved-barcodes]

Mit einem [API-Schlüssel](/docs/developers/api-keys) speichert die REST API Barcodes im Workspace des Schlüssels, wo sie im Dashboard unter **Barcodes** erscheinen. Es gelten dieselben Scopes wie bei Codes: `codes:read` zum Auflisten und Herunterladen, `codes:write` zum Ändern.

```bash title="Terminal"
curl https://api.qrdx.dev/v1/barcodes \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"format":"ean13","value":"590123412345","title":"Spring box"}'
```

```json title="201 Created"
{
  "data": {
    "id": "cmwgwqcxo0003iscgecog7m1b",
    "title": "Spring box",
    "format": "ean13",
    "formatLabel": "EAN-13",
    "value": "5901234123457",
    "options": {
      "foreground": "#000000",
      "background": "#ffffff",
      "showText": true,
      "barHeightMm": 23,
      "quietZone": 11,
      "scale": 4,
      "rotation": 0
    },
    "folderId": null,
    "imageUrl": "https://qrdx.dev/api/v1/barcode?format=ean13&data=5901234123457",
    "createdAt": "2026-11-14T21:18:01.212Z",
    "updatedAt": "2026-11-14T21:18:01.212Z",
    "deletedAt": null,
    "organizationId": "ws_ad2c5e1cce31ccf31535e78f08ab5b78"
  }
}
```

Der 12-stellige Wert kam mit Prüfziffer zurück, und `options` enthält die Standardwerte des Formats. Jeder gespeicherte Barcode hat eine `imageUrl`: dasselbe Bild wie bei `GET /v1/barcode`, das jeder mit dem Link laden kann. Der Endpunkt `/image` unten ist privat und braucht den Schlüssel.

| Endpunkt | Funktion |
| --- | --- |
| [`GET /v1/barcodes`](/docs/developers/api/list-barcodes) | Listet sie auf, zuletzt geänderte zuerst; Filter mit `q`, `format`, `folderId`, `status=trash` |
| [`POST /v1/barcodes`](/docs/developers/api/create-barcode) | Speichert einen. `options` akzeptiert `foreground`, `background`, `showText`, `barHeightMm`, `quietZone`, `scale` und `rotation` |
| [`GET /v1/barcodes/{id}`](/docs/developers/api/get-barcode) | Ein Barcode |
| [`PATCH /v1/barcodes/{id}`](/docs/developers/api/update-barcode) | Ändert Titel, Format, Wert, Optionen oder Ordner |
| [`DELETE /v1/barcodes/{id}`](/docs/developers/api/delete-barcode) | Verschiebt ihn in den Papierkorb (`{ "deleted": false, "trashed": true }`); `?permanent=true` löscht ihn endgültig |
| [`GET /v1/barcodes/{id}/image`](/docs/developers/api/get-saved-barcode-image) | Die Datei, gezeichnet wie gespeichert: `type` und `scale` wie oben. `Cache-Control: private, no-store` |

Jeder Plan speichert Barcodes: bis zu 1.000 bei Kostenlos, 10.000 bei Pro und 100.000 bei Business, ohne den Papierkorb. Diese Anfragen zählen auf das tägliche API-Kontingent des Workspace und senden die `X-RateLimit-*`-Header, wie der Rest der [REST API](/docs/developers/rest-api#rate-limits).

## Wenn etwas schiefgeht [#if-something-goes-wrong]

### `400` mit `"param": "data"` [#400-with-param-data]

Der Wert verstößt gegen die Regeln des Formats. Die Meldung sagt genau, was nicht stimmt: Prüfziffer, Länge oder Zeichensatz:

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"EAN-13: The check digit should be 7, not 8. Check the number, or leave the last digit off and it's worked out for you."}]},"status":400}
```

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"Code 39: Code 39 has no lowercase letters. Use capitals, or Code 128 for mixed case."}]},"status":400}
```

### `400` mit `"param": "format"` [#400-with-param-format]

`format` fehlt oder ist keine der elf IDs unter [Formate](#formats). Die Meldung listet sie auf.

### Das Rasterbild wird abgelehnt oder abgeschnitten [#the-raster-image-is-refused-or-cut]

Rasterbilder sind höchstens 6.000 Pixel pro Seite groß. Verringere `scale` bei langen Werten oder nutze SVG oder PDF.

### `429 RATE_LIMITED` [#429-rate_limited]

Mehr als {facts.imageApiPerMinute} Anfragen pro Minute von einer IP-Adresse, für `GET` und `POST /v1/barcode` zusammen. Warte die Sekunden aus `Retry-After` ab; `GET`-Antworten können ein Jahr lang gecacht werden, lade also jedes Bild nur einmal.

## Limits [#limits]

- **Rate Limit:** {facts.imageApiPerMinute} Anfragen pro Minute und IP-Adresse für `GET` und `POST /v1/barcode`, wie bei der [QR-Image-API](/docs/developers/image-api). Gespeicherte Barcodes folgen den Limits pro Minute und dem Tageskontingent der REST API.
- **Bildgröße:** Rasterbilder sind höchstens 6.000 Pixel pro Seite groß.
- **Hier gibt es keine Scan-Prüfung.** Der [Barcode-Generator](/barcode-generator) dekodiert, was er zeichnet, bevor du herunterlädst; die API zeichnet, was du anforderst. Drucke einen Test und scanne ihn mit den Scannern, die ihn später lesen sollen.

## MCP [#mcp]

Der [MCP-Server](/docs/developers/mcp) bietet `generate_barcode`, das den Wert prüft und ein PNG mit Bild-URLs liefert, und `save_barcode`, das im Workspace des API-Schlüssels der Verbindung speichert.

## Self-Hosting [#self-hosting]

Die Endpunkte sind Teil der QRdx-Web-App, daher stellt eine [selbst gehostete](/docs/self-hosting) Instanz sie unter `/api/v1/barcode` und `/api/v1/barcodes` auf deiner eigenen Domain bereit.
