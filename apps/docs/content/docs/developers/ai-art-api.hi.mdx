इस पेज के अंत तक आपके पास 1024 px की एक PNG होगी, जिसमें QR code एक पेंट की गई तस्वीर के अंदर बैठा है और आपके पास पहुँचने से पहले QRdx उसे डिकोड कर चुका है। आप यह भी जान जाएँगे कि फ़िक्स्ड टेक्स्ट की जगह डायनेमिक कोड कैसे एन्कोड करें, कौन-सा मोड चुनें और हर error का क्या मतलब है।

`POST https://api.qrdx.dev/v1/art` विवरण से QR code को AI आर्टवर्क में पेंट करता है और इमेज लौटाता है। यह वही [AI QR art](/ai/art) है जो Playground के Art टैब और स्टूडियो में है: {facts.artModel} तस्वीर पेंट करता है, फिर आपको देने से पहले QRdx जाँचता है कि वह आपके कंटेंट पर स्कैन होती है। जहाँ मॉडल की इमेज जैसी बनी है वैसी स्कैन नहीं होती, वहाँ QRdx मॉडल के अपने पिक्सल पर कोड को उतना ही मज़बूत करता है जितना ज़रूरी हो।

<Callout type="info" title="API key और मासिक इमेज">
इस endpoint के लिए `codes:write` स्कोप वाली [API key](/docs/developers/api-keys) चाहिए (**Full access** keys में यह होता है)। हर इमेज key के वर्कस्पेस की मासिक AI art इमेज में से एक इस्तेमाल करती है, यानी वही कोटा जो app इस्तेमाल करता है; हर प्लान के आँकड़े [प्लान और सीमाएँ](/docs/plans-and-limits) में हैं। जो call fail हो जाए, या जिसकी इमेज को स्कैन होने लायक न बनाया जा सके, वह कोई इमेज इस्तेमाल नहीं करती।
</Callout>

## शुरू करने से पहले [#before-you-start]

- `codes:write` वाली एक API key, जो `QRDX_API_KEY` के रूप में export की गई हो।
- कम से कम 60 सेकंड के timeout वाला HTTP client। एक call code मोड में लगभग 15 से 45 सेकंड, photo मोड में 25 से 45 और scene मोड में 40 से 55 सेकंड लेती है, क्योंकि scene मोड पहले अपनी तस्वीर पेंट करता है।
- डायनेमिक कोड के लिए उसका `id`, जो [`GET /v1/codes`](/docs/developers/api/list-codes) से या उस response से मिलता है जिसने उसे [बनाया था](/docs/developers/api/create-codes)।

## 1. किसी लिंक के लिए कोड पेंट करें [#1-paint-a-code-for-a-link]

    ```bash title="Terminal"
      -H "Authorization: Bearer $QRDX_API_KEY" \
    ```

  <Tab value="JavaScript">

    ```js title="art.mjs"
    const response = await fetch("https://api.qrdx.dev/v1/art", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.QRDX_API_KEY}`,

      },
      body: JSON.stringify({

      }),
      signal: AbortSignal.timeout(90_000),
    });
    const { data, credits } = await response.json();
    // data.imageUrl is a data: URL; save the PNG bytes
    const base64 = data.imageUrl.split(",")[1];

    console.log(data.text, data.blend, credits.remaining);
    ```
  </Tab>
  <Tab value="Python">
    ```python title="art.py"
    import base64
    import os
    import requests

    response = requests.post(
        "https://api.qrdx.dev/v1/art",
        headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},

        timeout=90,
    )
    response.raise_for_status()
    body = response.json()
    png = base64.b64decode(body["data"]["imageUrl"].split(",", 1)[1])

    ```

Response JSON होता है, जिसमें इमेज `data:` URL के रूप में होती है:

```json title="200 OK (fields)"
{
  "data": {
    "imageUrl": "data:image/png;base64,iVBORw0KGgo…",
    "width": 1024,
    "height": 1024,
    "seed": 2841337190,
    "mode": "code",
    "blend": "least",
    "blendStrength": 0.35,
    "text": "https://qrdx.dev",
    "visibility": 50,
    "creativity": 45
  },
  "credits": { "plan": "pro", "limit": 30, "used": 7, "remaining": 23, "pooled": false, "resetsAt": "2026-12-01T00:00:00.000Z" }
}
```

- `imageUrl` 1024 px की चौकोर PNG है, `data:` URL के रूप में। QRdx इसकी कॉपी नहीं रखता, इसलिए इसे सेव कर लें।
- `text` ठीक वही है जिस पर इमेज स्कैन होती है। QRdx ने जवाब देने से पहले इसे डिकोड किया था।
- `blend` बताता है कि इमेज को स्कैन होने लायक कैसे बनाया गया: `none` (मॉडल की इमेज जैसी बनी थी), `least` (फ़ाइंडर स्क्वेयर, क्वाइट ज़ोन और मॉड्यूल उतने ही मज़बूत किए गए जितना ज़रूरी था, मॉडल की इमेज पर) या `image-qr` (Image QR कोड के रूप में दोबारा बनाई गई, आख़िरी उपाय)। `blendStrength` `0` (जैसी बनी थी) से `1` (Image QR) तक जाता है।
- `credits` इस इमेज के बाद वर्कस्पेस का बचा हुआ कोटा है।

JSON की जगह सीधे PNG पाने के लिए `?format=png` जोड़ें या `Accept: image/png` भेजें। तब seed, मोड, blend और बची हुई इमेज `X-QRdx-Seed`, `X-QRdx-Mode`, `X-QRdx-Blend`, `X-QRdx-Blend-Strength` और `X-QRdx-Credits-Remaining` headers में आती हैं:

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/art?format=png" \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text": "https://qrdx.dev", "prompt": "a lighthouse on a cliff, woodcut print"}' \
  --max-time 90 -o art.png
```

## 2. इसकी जगह डायनेमिक कोड एन्कोड करें [#encode]

`text` और `code` में से ठीक एक भेजें:

- `text`: वह लिंक या टेक्स्ट जो कोड में रहता है, अधिकतम 300 अक्षर। आर्ट एक तस्वीर है, इसलिए प्रिंट करने के बाद इसका कंटेंट बदला नहीं जा सकता।
- `code`: वर्कस्पेस के किसी [डायनेमिक कोड](/docs/dynamic-qr-codes) का `id`। आर्ट कोड के शॉर्ट लिंक को एन्कोड करता है, इसलिए प्रिंट के बाद भी आप बदल सकते हैं कि वह कहाँ जाए, और उसके स्कैन analytics में दिखते हैं। किसी दूसरे वर्कस्पेस का कोड, या ट्रैश में पड़ा कोड, `404` देता है।

```bash title="Terminal"
curl https://api.qrdx.dev/v1/art \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"code": "cm5code0spring0menu00001", "prompt": "a bistro chalkboard menu on a brick wall", "mode": "scene"}' \
  --max-time 90 -o art.json
```

तब response में `"code": { "id", "shortLink" }` भी होता है, और `text` शॉर्ट लिंक होता है।

## 3. मोड और लुक चुनें [#modes]

| `mode` | आपको क्या मिलता है |
| --- | --- |
| `code` (डिफ़ॉल्ट) | कोड ही पूरी तस्वीर है: आपका आर्टवर्क उसके मॉड्यूल में पेंट होता है, साथ में सादे फ़ाइंडर स्क्वेयर और चारों ओर हल्का क्वाइट ज़ोन। सबसे भरोसेमंद ढंग से स्कैन होता है |
| `scene` | पहले विवरण से एक तस्वीर पेंट होती है, फिर कोड उसके बीच में पेंट किया जाता है, इसलिए तस्वीर कोड तक और उसके आर-पार जाती है, और मॉड्यूल उसके रंगों और रोशनी से बनते हैं |
| `photo` | वही, पर तस्वीर के रूप में आपकी अपनी `photo` के साथ: कोड के आसपास और आर-पार उसका विषय, रंग और रोशनी बने रहते हैं। फ़ोटो सिर्फ़ इसी मोड के साथ भेजें |

### क्विक लुक [#quick-looks]

क्विक लुक एक तैयार स्टाइल है, जैसे कोई माध्यम या मूड, जिसे QRdx आपके अपने `prompt` में जोड़ देता है: `"style": "watercolor"` के साथ `"a koi pond in the rain"` कोई पोखर को वॉटरकलर में पेंट करता है। इसकी id `style` के रूप में भेजें; कोई और मान `400 VALIDATION_ERROR` देता है। ये लुक वही हैं जो [AI art स्टूडियो](/ai/art) और Playground के Art टैब में चिप्स के रूप में दिखते हैं, और ये हर मोड में काम करते हैं।

| `style` | लुक |
| --- | --- |
| `watercolor` | वॉटरकलर |
| `oil-painting` | ऑयल पेंटिंग |
| `anime` | एनिमे |
| `cartoon` | कार्टून |
| `pixel-art` | पिक्सल आर्ट |
| `pop-art` | पॉप आर्ट |
| `charcoal` | चारकोल |
| `ink` | इंक |
| `cyberpunk` | साइबरपंक |
| `fantasy` | फ़ैंटेसी |
| `photographic` | फ़ोटोग्राफ़िक |
| `low-poly` | लो पॉली |
| `papercut` | पेपरकट |

`prompt` वैकल्पिक है। इसे छोड़ दें तो QRdx आपके भेजे `mode`, `style` और `photo` के लिए पहले खुद एक लिख देता है: विषय, जगह और रोशनी वाला एक ठोस दृश्य, या photo मोड में आपकी फ़ोटो में जो है उसका विवरण ताकि आर्ट उसे बनाए रखे। इसे लिखने में कोई अतिरिक्त AI art इमेज इस्तेमाल नहीं होती। तब response में जो लिखा गया वह `writtenPrompt` के रूप में आता है, ताकि आप अगली बार उसे बदलकर दोबारा भेज सकें। अगर लिखना fail हो जाए, तो आपको `502 AI_ART_DESCRIBE_FAILED` मिलता है और कोई इमेज इस्तेमाल नहीं होती।

## Request फ़ील्ड [#request-fields]

| फ़ील्ड | डिफ़ॉल्ट | विवरण |
| --- | --- | --- |
| `text` | | कोड क्या एन्कोड करता है, अधिकतम 300 अक्षर। यह या `code` भेजें |
| `code` | | डायनेमिक कोड का `id`, `text` की जगह |
| `prompt` | आपके लिए लिखा जाता है | पेंट किया जाने वाला आर्टवर्क, सादे शब्दों में, भेजने पर कम से कम 3 अक्षर |
| `mode` | `code` | `code`, `scene` या `photo`; ऊपर देखें |
| `style` | | क्विक लुक की id, जो आपके prompt के साथ जुड़ती है |
| `negativePrompt` | | तस्वीर से क्या बाहर रखना है |
| `visibility` | `50` | QR की दृश्यता, `0` से `100`: ज़्यादा होने पर कोड ज़्यादा साफ़ दिखता है, कम होने पर तस्वीर को तरजीह मिलती है |
| `creativity` | `45` | `0` prompt का अक्षरशः पालन करता है, `100` उसे खुलकर समझता है |
| `seed` | रैंडम | मिलती-जुलती इमेज के लिए पिछले response का seed भेजें |
| `reference` | | रंगों और आकृतियों के लिए रेफ़रेंस इमेज, जैसे लोगो या पैलेट |
| `photo` | | सिर्फ़ photo मोड: वह तस्वीर जिसमें कोड पेंट करना है |

`reference` और `photo` PNG या JPEG `data:` URL होते हैं (`data:image/jpeg;base64,…`)। `reference` को उसकी सबसे लंबी तरफ़ लगभग 512 px तक छोटा करें (अधिकतम 600 KB), और `photo` को लगभग 1024 px पर चौकोर क्रॉप करें (अधिकतम 1 MB), यही वह साइज़ है जिस पर आर्ट बनता है। ये मॉडल को जाते हैं और फिर हटा दिए जाते हैं: QRdx इन्हें कभी स्टोर या लॉग नहीं करता। बड़ी इमेज `413 AI_ART_IMAGE_TOO_LARGE` के साथ ठुकरा दी जाती हैं। [रेफ़रेंस पेज](/docs/developers/api/create-art) में पूरा schema और Try it पैनल है।

## क्रेडिट और सीमाएँ [#credits-and-limits]

API उसी मासिक AI art इमेज कोटे से चलता है जिससे app, और यह उस वर्कस्पेस के लिए गिना जाता है जिसकी key है। फ़्री, Pro और Business हर एक में महीने की कुछ इमेज शामिल हैं, और Business इन्हें पूरी टीम में साझा करता है; आँकड़े [प्लान और सीमाएँ](/docs/plans-and-limits) में हैं। ये हर महीने की 1 तारीख़ (UTC) को रीसेट होती हैं।

- जब महीने की इमेज खत्म हो जाती हैं, तो API `AI_ART_CREDITS_EXHAUSTED` लौटाता है: फ़्री और Pro पर `402`, जहाँ अपग्रेड करने से और मिलती हैं, और Business पर `429`।
- मासिक कोटे के अलावा हर व्यक्ति दिन में अधिकतम 25 इमेज बना सकता है (`429 AI_ART_DAILY_LIMIT`), और एक मिनट में अधिकतम 12 इमेज शुरू कर सकता है।
- हर call वर्कस्पेस के रोज़ाना API कोटे और writes की प्रति-मिनट सीमा ([Rate limits](/docs/developers/rest-api#rate-limits)) में भी गिनी जाती है।

## अगर कुछ गलत हो जाए [#if-something-goes-wrong]

Errors का स्वरूप API के सामान्य स्वरूप जैसा ही है (`code`, `message`, `status`); सभी errors की सूची [Errors](/docs/developers/errors) में है। किसी भी `5xx` error में इमेज नहीं आती।

| Status | `code` | क्या करें |
| --- | --- | --- |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` छोटा करें, या डायनेमिक कोड का `code` भेजें |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | महीने की 1 तारीख का इंतज़ार करें, या अपग्रेड करें |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | `photo` या `reference` का साइज़ घटाएँ |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Business: महीने की 1 तारीख का इंतज़ार करें |
| 429 | `AI_ART_DAILY_LIMIT` | कल दोबारा कोशिश करें (UTC) |
| 502 | `AI_ART_FAILED` | मॉडल फ़ेल हो गया या उसने प्रॉम्प्ट को अस्वीकार कर दिया। दोबारा कोशिश करें या प्रॉम्प्ट बदलकर लिखें |
| 502 | `AI_ART_UNSCANNABLE` | ज़्यादा `visibility` के साथ या दूसरे seed के साथ दोबारा कोशिश करें |
| 502 | `AI_ART_DESCRIBE_FAILED` | कोई `prompt` नहीं भेजा गया था और प्रॉम्प्ट लिखने की कोशिश फ़ेल हो गई। दोबारा कोशिश करें या अपना प्रॉम्प्ट भेजें |
| 503 | `AI_ART_BUSY` | मॉडल व्यस्त है। एक मिनट रुककर दोबारा कोशिश करें |
| 503 | `AI_NOT_CONFIGURED` | इस सर्वर पर AI art सेट अप नहीं है (सेल्फ़-होस्टेड) |
| 504 | `AI_ART_TIMEOUT` | मॉडल ने बहुत ज़्यादा समय लिया (scene मोड में, तस्वीर बनाने के बाद कोड पेंट करने के लिए बहुत कम समय बचा)। दोबारा कोशिश करें, या code मोड इस्तेमाल करें |

Vercel AI Gateway के बिना चल रहा सेल्फ़-होस्टेड इंस्टेंस हर कॉल का जवाब इस तरह देता है:

```json title="503 Service Unavailable"
{"code":"AI_NOT_CONFIGURED","message":"AI QR art is not configured on this server","status":503}
```

## MCP [#mcp]

कनेक्शन पर QRdx API key होने पर, [MCP सर्वर](/docs/developers/mcp) में `generate_ai_art` टूल मिलता है। यह request body वाले ही फ़ील्ड लेता है और PNG लौटाता है, साथ ही यह भी बताता है कि वह किस पर स्कैन होता है और इस महीने कितनी इमेज बची हैं। अपने असिस्टेंट से सीधी भाषा में कहें:

```txt title="Prompt"
Make AI QR art for my code cm5code0spring0menu00001: a bistro chalkboard menu on a brick wall, as a scene.
```

key न होने पर, टूल बताता है कि उसे कैसे जोड़ें। REST API की तरह इस कॉल में भी एक मिनट तक लग सकता है।

## सेल्फ़-होस्टिंग [#self-hosting]

AI art Vercel AI Gateway के ज़रिए चलता है। अपने इंस्टेंस पर `AI_GATEWAY_API_KEY` सेट करें; इसके बिना `POST /v1/art` और `generate_ai_art` का जवाब `503 AI_NOT_CONFIGURED` आता है।
