API 키를 사용하면 OAuth 흐름 없이 직접 운영하는 서버, 스크립트, CI 작업에서 [REST API](/docs/developers/rest-api)를 호출할 수 있습니다. 이 페이지를 끝까지 읽으면 워크스페이스 하나에 대한 키를 갖게 되고, 그 키로 무엇을 할 수 있는지 정확히 알게 되며, 키를 교체하는 방법도 알게 됩니다.

```bash title="Terminal"
curl https://api.qrdx.dev/v1/codes -H "Authorization: Bearer $QRDX_API_KEY"
```

OAuth 액세스 토큰을 받는 모든 엔드포인트는 같은 헤더로 키도 받습니다. [Image API](/docs/developers/image-api)와 [바코드 API](/docs/developers/barcode-api)는 둘 다 필요하지 않습니다. 제품이 다른 QRdx 사용자를 대신해 동작한다면 [OAuth 앱](/docs/developers/build-an-integration)을 대신 사용하세요. 그러면 각 사용자가 직접 승인합니다.

## 시작하기 전에 [#before-you-start]

- 로그인한 QRdx 계정. 모든 플랜에서 API 키를 쓸 수 있습니다.
- 키를 사용할 워크스페이스. 키는 워크스페이스 하나에 속하며, 그 워크스페이스에서 사용자 본인으로 동작합니다.

## 1. 키 만들기 [#create-a-key]

1. 키를 사용할 워크스페이스에서 [설정 → API 키 및 앱](/dashboard?to=settings/developers&new=1)을 엽니다. 이 링크는 마지막으로 사용한 워크스페이스를 엽니다. 다른 워크스페이스를 쓰려면 워크스페이스 전환기에서 선택하세요. **API 키 만들기** 양식이 열립니다.
2. **이름**을 입력합니다. 키를 사용하는 위치를 적어 두면 나중에 어떤 키를 폐기해야 할지 알 수 있습니다. **액세스**를 선택하고, **만료**에서 키의 유효 기간을 선택합니다. 그다음 **키 만들기**를 선택합니다. 키는 사용자가 없어도 동작하므로, 해당 브라우저에서 최근 10분 안에 확인하지 않았다면 QRdx가 먼저 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요청합니다.
3. **API 키 복사** 대화상자에서 키를 복사합니다. 키는 이번 한 번만 표시됩니다. QRdx는 키의 해시만 저장합니다. 같은 대화상자에는 키와 이 사이트의 API 주소가 채워진 curl 요청이 있어 바로 붙여 넣을 수 있습니다.

키는 `qrdx_` 뒤에 영문자와 숫자 40자가 이어지는 형태입니다. 목록에는 `qrdx_7KpQ2m…`처럼 앞부분만 표시되므로 키를 구분할 수 있습니다.

## 2. 액세스 선택하기 [#access]

키는 OAuth 앱과 같은 스코프를 사용합니다. 키를 만들 때 세 가지 옵션 중 하나를 선택하세요.

| 액세스 | 스코프 | 허용 범위 |
| --- | --- | --- |
| 전체 액세스 | `profile:read`, `themes:read`, `codes:read`, `codes:write` | API가 하는 모든 작업 |
| 읽기 전용 | `profile:read`, `themes:read`, `codes:read` | 코드, 스캔 분석, 저장된 바코드, 테마, 프로필 읽기 |
| 사용자 지정 | 직접 선택한 스코프 | 해당 스코프가 허용하는 작업([스코프 목록](/docs/developers/rest-api#scopes)) |

`codes:write`는 `codes:read`가 허용하는 모든 작업도 허용합니다. 키의 스코프는 나중에 변경할 수 없으므로 새 키를 만드세요. 키의 스코프를 벗어난 요청은 `403 INSUFFICIENT_SCOPE`를 받으며, 메시지에 필요했던 스코프의 이름이 표시됩니다.

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## 3. 키 사용하기 [#3-use-it]

키를 Bearer 토큰으로 보냅니다. 처음 호출해 볼 만한 요청은 `GET /v1/me`입니다. 키를 만든 사용자의 프로필을 반환하며 키가 동작하는지 확인해 줍니다.

```bash title="Terminal"
curl https://api.qrdx.dev/v1/me -H "Authorization: Bearer $QRDX_API_KEY"
```

```json title="200 OK"
{"data":{"id":"usr_docsdev0000000000000001","name":"Ada Lovelace","email":"ada@example.com","image":null}}
```

키는 서버의 환경 변수나 비밀 관리자에 보관하고, 코드에서는 거기서 읽어 오세요.

```js title="qrdx.mjs"
const response = await fetch("https://api.qrdx.dev/v1/codes", {
  headers: { Authorization: `Bearer ${process.env.QRDX_API_KEY}` },
});
```

```python title="qrdx.py"
import os
import requests

response = requests.get(
    "https://api.qrdx.dev/v1/codes",
    headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},
)
```

## 워크스페이스와 역할 [#workspaces-and-roles]

키는 만들 때 열려 있던 워크스페이스에 속하며, 그 워크스페이스에서 사용자 본인으로 동작합니다.

- 키는 해당 워크스페이스의 코드, 스캔, 바코드, 훅, 테마를 다루며, 워크스페이스의 플랜과 [일일 할당량](/docs/developers/rest-api#rate-limits)을 따릅니다.
- 키는 워크스페이스에서 사용자가 할 수 있는 작업을 할 수 있으며, 요청할 때마다 그 시점의 [역할](/docs/teams)을 기준으로 판단합니다. 본인의 워크스페이스에서는 소유자입니다. 역할이 바뀌면 키의 권한도 함께 바뀝니다. 워크스페이스를 떠나면 키는 동작하지 않고, 워크스페이스를 삭제하면 그 키도 삭제됩니다.

워크스페이스의 모든 멤버가 키를 만들 수 있습니다. 소유자와 관리자는 워크스페이스의 모든 키를 보고 폐기할 수 있으며, 멤버는 본인의 키만 보고 폐기할 수 있습니다. 각 사용자는 워크스페이스마다 활성 키를 최대 25개까지 가질 수 있으며, 폐기되었거나 만료된 키는 포함되지 않습니다.

## 만료, 마지막 사용, 폐기 [#revoke]

- **만료.** **만료**에서 키를 영구적으로(**없음**) 또는 30일, 90일, 1년 동안 유효하게 설정할 수 있습니다. 만료된 키는 `401 INVALID_TOKEN`을 받으며, 폐기할 때까지 **만료됨**으로 표시된 채 목록에 남습니다.
- **마지막 사용.** 목록에는 각 키가 마지막으로 요청을 인증한 날짜가 표시됩니다.
- **폐기.** 키 옆의 **폐기**를 선택하고 **키 폐기**로 확인합니다. 이후 해당 키를 쓰는 요청은 `401 INVALID_TOKEN`을 받습니다. 폐기는 되돌릴 수 없습니다.

```json title="401 Unauthorized"
{
  "code": "INVALID_TOKEN",
  "message": "Invalid API key: it doesn't exist, was revoked or has expired, or its creator left the workspace. Check that you copied the whole key, or create a new one at https://qrdx.dev/dashboard?to=settings/developers.",
  "status": 401,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## 키를 안전하게 관리하기 [#keep-keys-safe]

- 키를 웹 페이지, 모바일 앱, 프롬프트, 저장소에 넣지 마세요. QR 이미지가 필요한 브라우저 코드는 키가 필요 없는 [Image API](/docs/developers/image-api)를 사용하세요.
- 키가 실행되는 곳마다 키를 하나씩 사용하세요. 그러면 다른 키에 영향을 주지 않고 하나만 폐기할 수 있습니다.
- 보고만 하는 스크립트에는 **읽기 전용** 키를 주고, 단기 작업에는 만료되는 키를 주세요.
- 키가 유출되면 폐기하고 새 키를 만드세요. `qrdx_` 접두사 덕분에 코드와 로그에서 키를 찾기 쉬우며, 비밀 정보 스캐너는 `qrdx_[0-9A-Za-z]{40}`으로 일치 여부를 확인할 수 있습니다.

## 문제가 생겼을 때 [#if-something-goes-wrong]

### `401 UNAUTHORIZED` [#401-unauthorized]

요청에 `Authorization` 헤더가 없었습니다. 헤더 이름과 HTTP 클라이언트가 헤더를 보내는지 확인하세요. 값은 `Bearer ` 뒤에 키 전체를 붙인 것입니다.

### `401 INVALID_TOKEN` [#401-invalid_token]

키를 일부만 복사했거나, 폐기되었거나, 만료되었거나, 키를 만든 사용자가 워크스페이스를 떠났습니다. 새 키를 만드세요. OAuth 토큰이라면 토큰을 갱신하거나 사용자에게 인증을 다시 진행하게 하세요.

### `403 INSUFFICIENT_SCOPE` [#403-insufficient_scope]

키가 **읽기 전용**이거나, 메시지에 표시된 스코프가 없는 **사용자 지정** 키입니다. 해당 스코프가 있는 키를 만드세요. 기존 키에는 스코프를 추가할 수 없습니다.

### 이 배포에서는 아직 API 키를 사용할 수 없어요 [#api-keys-arent-available-on-this-deployment-yet]

[셀프 호스팅](/docs/self-hosting) 인스턴스는 데이터베이스에 `api_key` 테이블이 생기기 전까지 이 메시지를 표시합니다. 이 테이블은 업데이트 후 스키마 동기화에서 만들어집니다(Docker에서는 `migrate` 서비스, 그 외에는 `bun run db:push`). 그때까지 API는 키를 `401`로 거부합니다. 해당 인스턴스의 API는 자체 도메인의 `/api/v1`에 있으며, 새 키 대화상자에 채워지는 주소가 바로 이것입니다.
