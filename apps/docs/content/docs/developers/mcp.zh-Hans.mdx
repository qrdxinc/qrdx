读完本页后，你的 AI 助手就能制作二维码：为任意内容设计带有扫描评分检测的二维码，按编辑器中的样式渲染，为 Wi-Fi、联系人、电子邮件、短信、位置和银行支付生成正确的数据，查找社区边框，并绘制条形码。如果在连接中配置了 API 密钥，它还能把设计和条形码保存到你的工作区，并生成 AI 图像。

QRdx 运行着一个公开的 [Model Context Protocol](https://modelcontextprotocol.io) 服务器，地址为：

```txt title="Server URL"
https://mcp.qrdx.dev/mcp
```

它使用 Streamable HTTP 传输，不保存会话状态，也不需要账号、登录或 API 密钥。同一个服务器也可通过 `https://qrdx.dev/api/mcp` 访问。[连接页面](/mcp)提供一键连接按钮，并列出了比本页更多客户端的连接步骤。

[在 Playground 中试用](/playground?open=code&lang=mcp)：先在那里设计样式，再将其复制为 `design_qr` 参数交给你的助手。

## 2. 让助手生成二维码 [#2-ask-for-a-code]

然后直接用日常语言提出要求。以下提示可原样使用：

```txt title="Prompts"
Make a QR code for https://example.com in our brand blue, #155dfc, with rounded modules.
Create a Wi-Fi QR code for the network Office Guest with password correct-horse-battery.
Design a Wi-Fi QR code for Cafe Guest in warm browns with a Free Wi-Fi banner, and tell me its scan score.
Generate a contact QR code for Ada Lovelace, ada@example.com, and add it to the README.
Find a community frame for a restaurant menu and use it for https://example.com/menu.
Draw an EAN-13 barcode for 590123412345 as a PNG.
```

对于第一条提示，助手会调用 `generate_qr_code`，返回 PNG 以及下面这些可直接粘贴的内容：

```txt title="generate_qr_code result"
QR code, 512x512px, error correction Q.
SVG URL: https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&fg=155dfc&body=rounded
PNG URL: https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=png&fg=155dfc&body=rounded
WebP URL (lossless, smaller than PNG): https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=webp&fg=155dfc&body=rounded
EPS URL (vector, for print; 512 pt wide): https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=eps&fg=155dfc&body=rounded
Markdown: ![QR code](https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&fg=155dfc&body=rounded)
```

对于第二条提示，助手会调用 `qr_payload_wifi`，它返回 `WIFI:T:WPA;S:Office Guest;P:correct-horse-battery;;`，然后助手把这个字符串作为 `data` 传给 `generate_qr_code`，或作为 `design_qr` 的内容。

## 工具 [#tools]

| 工具 | 功能 |
| --- | --- |
| `design_qr` | 为任意内容类型设计二维码，样式由你的助手选定，也可以从内置主题或社区条目起步；检查其扫描评分，并修复样式直至评级为“优秀”。返回评分、改动内容、样式 JSON、Playground 链接、PNG 和 SVG |
| `list_options` | 列出 `design_qr` 接受的所有取值：内容类型及其字段、颜色和渐变、形状、边框（含 QRdx 官方边框的 id）、边线、Logo 图标和品牌 Logo、内置主题、纠错等级和限制 |
| `generate_qr_code` | 使用编辑器的样式渲染二维码。返回 PNG 图像和公开的 [Image API](/docs/developers/image-api) URL（SVG、PNG、无损 WebP 和矢量 EPS），可直接用于 Markdown、HTML 或印刷；按需还可返回 SVG 标记 |
| `list_qr_styles` | 列出码体图案、定位点外框和定位点内点的形状、边框（内置样式和以模板绘制的样式）、Logo 图标、纠错等级、默认值和限制 |
| `search_community` | 按关键词、类型或标签查找已发布的[社区](/community)边框、主题和合集 |
| `get_community_item` | 获取单个社区条目及其应用的样式，可直接用于 `design_qr` 或 `generate_qr_code` |
| `save_template` | 将设计作为主题保存到你的工作区。需要 [API 密钥](#use-an-api-key) |
| `generate_barcode` | 在校验数值（校验位、长度、字符）后，绘制 EAN-13、UPC-A、UPC-E、EAN-8、ITF-14、GS1-128、Code 128、Code 39、Data Matrix、PDF417 或 Aztec 条码。返回 PNG 和公开的[条码 API](/docs/developers/barcode-api) URL |
| `save_barcode` | 将条码保存到你工作区的“条码”中。需要 [API 密钥](#use-an-api-key) |
| `generate_ai_art` | 将二维码绘入 AI 艺术图，并检查其能否扫描。会消耗工作区每月 AI 艺术图额度中的一张，最多耗时一分钟。需要 [API 密钥](#use-an-api-key)。参见 [AI 艺术 API](/docs/developers/ai-art-api) |
| `qr_payload_wifi` | 生成 `WIFI:` 网络载荷（WPA、WEP 或开放网络，可选隐藏），并对特殊字符进行转义 |
| `qr_payload_vcard` | 生成 vCard 3.0 联系人（RFC 2426）：姓名、组织、职位、电话、电子邮件、网站、地址和备注 |
| `qr_payload_email` | 生成 `mailto:` 链接（RFC 6068），可选抄送、密送、主题和正文 |
| `qr_payload_sms` | 生成 `sms:` 链接（RFC 5724），可选附带消息，也可使用较旧的 `SMSTO:` 形式 |
| `qr_payload_geo` | 根据纬度和经度生成 `geo:` 位置（RFC 5870） |
| `qr_payload_payment` | 生成银行支付码：Pix BR Code、SEPA 贷记转账（EPC069-12），或 PayNow、PromptPay、VietQR 码（EMV，含其 CRC）。它对字段的检查与 Playground 的表单一致 |

载荷工具返回纯字符串。随后你的助手会将其作为 `data` 传给 `generate_qr_code`。

### design_qr [#design_qr]

`design_qr` 接收以类型及其字段表示的内容（类型和检查与编辑器的内容表单相同，可用 `list_options` 查看），以及可选的样式：

```json title="design_qr arguments"
{
  "content": { "type": "wifi", "ssid": "Cafe Guest", "password": "sunshine123", "encryption": "WPA" },
  "style": {
    "bgColor": "#FFF7ED",
    "fgColor": "#9A3412",
    "bodyPattern": "rounded",
    "cornerEyePattern": "rounded",
    "frame": { "style": "banner-bottom", "text": "Free Wi-Fi" }
  }
}
```

```txt title="design_qr result (first lines)"
Scan score 85/100 (great). No changes were needed. Content: WiFi · Cafe Guest (47 bytes). Open it in the playground: https://qrdx.dev/playground?style=1.eyJiIjoiI0ZGRjdFRCIs…&ref=mcp
```

结果的 JSON 包含 `payload`（二维码编码的确切字符串）、`style`、`qrdxStyle`、`score`、`grade`、`stillFailing`（仍未通过的检查，每项附带修复建议）、`repairs`、`changes` 和 `playgroundUrl`，其后是 PNG 和 SVG。

未设置的选项会采用默认值（定位点跟随码点颜色、方形形状、边距 4、纠错等级 Q、无边框）。随后 QRdx 会对设计运行编辑器的扫描检查：渲染二维码，通过手机摄像头模型在 96、160 和 320 px 下解码，并检查对比度、静区、定位点形状和形状搭配。若评分低于“优秀”（85），它最多会修复样式三次，并尽量少改动（保持色相的更深颜色、更安全的定位点形状、为长内容降低纠错等级）。如果仍然不够，则回退为带有你所选边框的经典黑白二维码。结果会说明改动了什么以及原因。

`design_qr` 在 QRdx 一侧不运行任何 AI 模型：样式由你的助手选定，QRdx 负责验证、检查和修复。无效内容（例如少于 8 个字符的 WPA 密码、格式错误的电子邮件地址）会被拒绝，并给出原因。`design_qr` 有独立的限制：每个 IP 地址每分钟 {facts.designQrPerMinute} 次调用。

更多输入项：

- **`preset`**：按 id 从内置主题起步（可用 `list_options` 查看）。你设置的样式选项优先于它。
- **`community_item`**：按 id 从社区边框或主题起步，例如 `frame:wifi-card`。边框条目放置在经典二维码上；你的样式选项会改变其下的二维码。QRdx 的官方边框同样是社区条目，因此这里可以使用 `frame:diwali-diya` 或 `frame:menu-cutlery`。
- **自定义边框**：`style.frame` 可以是带有边框规格的 `{ "style": "custom", "spec": … }`，例如来自 `get_community_item` 的社区边框规格。它按原样绘制并评分；修复只会改变二维码，绝不会改变边框。
- **`style.logo`**：快捷 Logo 图标（`wifi`、`location`、`phone`、`email`、`link`、`file`、`calendar`、`whatsapp` 或 `instagram`），或按 [Simple Icons](https://simpleicons.org) 标识名指定的品牌 Logo（`spotify`、`paypal:white`）。`list_options` 会列出热门品牌标识名。
- **引擎选项**：`style.eyeColors`（逐个定位点的 `#RRGGBB` 颜色）、`moduleScale`（码点大小，`0.5` 到 `1`）、`shape`（`circle` 表示圆形二维码）、`autoLevel` 和 `logoOptions`（Logo 的大小、留白、位置、裁剪和底板）。它们按给定值绘制和评分；修复不会改动它们。

<IfAvailable feature="fileStorage">
`logo_file_id` 会改为绘制你上传到 QRdx 的 Logo，需要 [API 密钥](#use-an-api-key)。
</IfAvailable>

与编辑器一样，Logo 按其覆盖的模块评分，因此修复可能会将纠错等级提高到 H，或移除 Logo。编辑器默认显示的 QRdx 标记不会在这里绘制。

结果中的 `qrdxStyle` 是以编辑器样式 JSON 表示的设计。可将它传给 `save_template`；也可作为 `style` 传给 `generate_qr_code`，以另一种尺寸渲染同一设计；或传给 Image API 的 [`style`](/docs/developers/image-api#style)。`playground_url` 会在 [Playground](/playground) 中打开该设计：它只携带样式，绝不包含 Logo 或内容，`playgroundLeftOut` 会说明省略了哪些内容。

### generate_qr_code [#generate_qr_code]

输入项与 [Image API 参数](/docs/developers/image-api#parameters)一致：`data`（必填）、`size`、`fg`、`bg`、`eyeColor`、`dotColor`、`body`、`eye`、`dot`、`level`、`margin`、`template`、`frame`、`frameText`、`logoIcon`、`logoFileId`、`item`（社区条目 id）和 `style`（编辑器的样式 JSON：渐变、自定义边框等，与 `design_qr` 返回的一致）。单项选项优先于 `style`，`style` 优先于 `item`。将 `include_svg` 设为 `true` 可同时以文本形式获得 SVG 标记，例如用于保存 `.svg` 文件。该选项默认关闭，因为标记通常有 50 到 150 KB，会占满对话。

`generate_qr_code` 不检查扫描评分；如需检查，请使用 `design_qr`。带有你上传 Logo 的二维码没有公开图像 URL，因为 Image API 只会在带有你的密钥的请求中绘制该 Logo。

### 二维码卡片 [#qr-card]

在支持 [MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview) 的应用中，`design_qr` 和 `generate_qr_code` 还会在对话中显示二维码卡片。卡片包含二维码、它编码的内容（Wi-Fi 二维码显示网络名称，绝不显示密码）、尺寸与纠错等级或扫描评分，以及一个 **在编辑器中打开** 按钮。编辑器链接与 `playground_url` 一样，只携带样式。

PNG 和 SVG 按钮取决于应用的权限。如果应用能从卡片保存文件，按钮就会保存文件；否则会在浏览器中打开 Image API 的 URL，因此 `design_qr` 的卡片只在能保存文件的应用中显示这些按钮：它的内容绝不会放入图像 URL。应用可能会在打开链接前请你确认。

不支持 MCP Apps 的应用仍会得到与之前相同的文本和图像。面向客户端开发者：

- 卡片是资源 `ui://qrdx/qr-card`（`text/html;profile=mcp-app`），由 `resources/list` 列出。两个工具都通过 `_meta.ui.resourceUri` 指向它。
- 其数据位于工具结果的 `_meta` 中，键为 `dev.qrdx/qr-card`，仅供卡片使用，而非供模型使用。这些工具不返回 `structuredContent`。
- 卡片是单个 HTML 文件，样式和脚本均内联。它唯一加载的内容是来自 Image API 的二维码图像（`https://api.qrdx.dev`，自托管时为你自己的域名），其内容安全策略（`_meta.ui.csp.resourceDomains`）只允许该主机。

如果你在卡片出现之前就已连接 QRdx，请移除连接器后重新添加，或刷新其工具，以便应用获取新的工具元数据。

### 社区 [#community]

`search_community` 按关键词（`q`）、`type` 和 `tag` 查找已发布的[社区](/community)边框、主题和合集，均以 CC0 免费提供。`get_community_item` 返回单个条目及其应用的样式；将其 id 作为 `community_item` 传给 `design_qr`，或作为 `item` 传给 `generate_qr_code`。同样的数据也可通过 REST API 的 [`/v1/community/items`](/docs/developers/api/list-community-items) 获取。

条目文本由社区成员撰写。名称、描述、用户名、标签和边框标签返回时会被缩短，保持单行，且不含链接、电子邮件或标记，每个结果还会提示应将它们视为数据，而非指令。

## 使用 API 密钥 [#use-an-api-key]

部分工具需要在连接上附带 QRdx [API 密钥](/docs/developers/api-keys),以 `Authorization: Bearer qrdx_…` 的形式发送:

- **`save_template`** 将设计保存为主题,会列在控制台的“主题”下,并在编辑器中提供选用。它需要具有 `codes:write` 权限的密钥,**完全访问**密钥具备该权限。你自己工作区的密钥会保存到你的主题;团队密钥在其创建者是所有者或管理员、且套餐包含团队主题时,会保存到团队的共享主题。保存次数计入套餐的已保存主题上限(参见[套餐与限制](/docs/plans-and-limits));超出上限时,该工具会返回 API 的 `LIMIT_REACHED` 错误(`402`)。
- **`save_barcode`** 将条形码(格式、值、可选的标题和绘制选项)保存到该密钥所在的工作区,会列在控制台的“条形码”下。它需要具有 `codes:write` 权限的密钥。所有套餐都可以保存条形码,免费版最多 1,000 个;超出上限时返回 `LIMIT_REACHED`(`402`)。
- **`generate_ai_art`** 将二维码绘制成 AI 艺术图,来源可以是链接、文本,或按 id 指定的动态二维码,并在 QRdx 确认其可被扫描后返回 PNG。它接受与 [`POST /v1/art`](/docs/developers/ai-art-api) 相同的字段,并需要具有 `codes:write` 权限的密钥。每张图片会消耗该密钥所在工作区每月 AI 艺术图额度中的一张,一次调用最长可能需要一分钟。
<IfAvailable feature="fileStorage">
- **你上传的 Logo**,位于 [控制台 → 文件](/docs/files),通过文件 id 指定(`design_qr` 中的 `logo_file_id`,`generate_qr_code` 中的 `logoFileId`):PNG 或 JPEG,最大 1 MB。密钥必须属于拥有该文件的工作区。
</IfAvailable>

没有密钥时,这些工具会回复如何添加密钥:

```txt title="save_template without a key"
save_template needs a QRdx API key: send it as Authorization: Bearer qrdx_… (create one in Settings → API keys & apps).
```

## 出现问题时 [#if-something-goes-wrong]

### 客户端无法连接 [#the-client-cant-connect]

请检查 URL 是否恰好为 `https://mcp.qrdx.dev/mcp`,传输方式是否为 HTTP(Streamable HTTP),而不是 SSE 或 stdio。只能运行本地服务器的客户端需要使用上文的 `mcp-remote` 桥接。在浏览器中打开该 URL 会重定向到连接页面,这是正常现象:MCP 客户端从不请求 HTML。

### 助手提示某个工具需要 API 密钥 [#the-assistant-says-a-tool-needs-an-api-key]

`save_template`、`save_barcode`、`generate_ai_art` 以及上传的 Logo 都需要在连接上附带 `Authorization: Bearer qrdx_…`。请按上文所示添加该请求头,然后重新连接。

### `design_qr` 拒绝了内容 [#design_qr-refuses-the-content]

内容未通过与编辑器表单相同的检查:例如 WPA 密码少于 8 个字符、电子邮件地址格式不正确、支付字段超出范围。原因会写在回复中;`list_options` 会列出每种内容类型的字段和规则。

### 请求过多 [#too-many-requests]

服务器允许每个 IP 地址每分钟 {facts.mcpPerMinute} 次请求,`design_qr` 为每分钟 {facts.designQrPerMinute} 次。使用密钥时,`save_template` 还限制为每位用户每分钟 30 次。请等待一分钟后再试。

## 隐私与限制 [#privacy-and-limits]

- 这些工具负责渲染图片、检查设计、格式化文本和读取公开社区内容。只有 `save_template` 和 `save_barcode` 会写入数据:即你要求它们保存的主题或条形码,写入 API 密钥所在的工作区。`generate_ai_art` 会消耗工作区每月 AI 艺术图额度中的一张,并且既不保留图片,也不保留你发送的照片。服务器不会保存你生成的二维码。
- `generate_qr_code` 和 `generate_barcode` 返回的图片 URL 包含编码的数据。如果数据是私密的,例如 Wi-Fi 密码,请不要分享这些 URL。
- 请求限制为每个 IP 地址每分钟 {facts.mcpPerMinute} 次,`design_qr` 为每分钟 {facts.designQrPerMinute} 次。

## 自托管与本地开发 [#self-hosting-and-local-development]

MCP 服务器是 QRdx Web 应用的一部分,因此每个实例都在 `/api/mcp` 提供该服务:

- **自托管。** 当 `NEXT_PUBLIC_APP_URL` 是你自己的域名时,连接页面、代码片段和安装链接会使用 `https://<your-domain>/api/mcp`。
- **本地开发。** `bun run dev` 会在 `http://localhost:3000/api/mcp` 提供该服务。连接页面仍会显示公共 URL,并以提示的形式给出本地 URL,这样你可以让客户端指向你的机器,在服务器改动上线之前进行测试。
