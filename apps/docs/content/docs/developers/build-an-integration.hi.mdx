इस पेज के अंत तक, लोग आपके प्रोडक्ट में **Connect QRdx** पर क्लिक कर सकेंगे, QRdx की consent स्क्रीन पर आपके ऐप को अनुमति दे सकेंगे, और आपके सर्वर के पास एक access token होगा जो उनकी ओर से `https://api.qrdx.dev/v1` को कॉल करता है, और केवल उन्हीं scopes तक सीमित रहता है जिन्हें उन्होंने मंज़ूर किया है।

इंटीग्रेशन एक OAuth ऐप होता है। [API key](/docs/developers/api-keys) एक वर्कस्पेस में आपके रूप में काम करती है, जबकि token उस व्यक्ति के रूप में काम करता है जिसने आपके ऐप को मंज़ूरी दी है, उसके अपने वर्कस्पेस पर, और वह व्यक्ति यह एक्सेस कभी भी वापस ले सकता है।

## शुरू करने से पहले [#before-you-start]

- एक QRdx अकाउंट। फ़्री वर्कस्पेस में 1 OAuth ऐप हो सकता है, Pro में 5 और Business में 25; वर्कस्पेस अपने owners में से सबसे अच्छा प्लान इस्तेमाल करता है।
- एक सर्वर जो secret सुरक्षित रख सके और redirect प्राप्त कर सके। कोड सैंपल Fetch API के साथ Node.js में हैं; HTTPS और SHA-256 वाली कोई भी भाषा चलेगी।
- दो `https://` redirect URI जिन्हें आप इस्तेमाल करेंगे: एक प्रोडक्शन के लिए, एक डेवलपमेंट के लिए (उसके लिए `http://localhost` की अनुमति है)।

## 1. OAuth ऐप बनाएँ [#1-create-an-oauth-app]

[Settings → API keys & apps](/dashboard?to=settings/developers) खोलें और **New app** चुनें। ऐप उसी वर्कस्पेस का होता है जो खुला है। केवल वर्कस्पेस के owners ऐप बना और बदल सकते हैं; admins और members उन्हें देख सकते हैं।

<Shot id="oauth-new-app-form" />

| फ़ील्ड | यह किसलिए है |
| --- | --- |
| **Name**, **Description**, **Logo**, **Website** | consent स्क्रीन पर दिखाए जाते हैं। कम से कम 128 × 128 px का चौकोर लोगो अपलोड करें, या उसका `https://` लिंक पेस्ट करें |
| **Redirect URIs** | QRdx लोगों को यहाँ वापस भेजता है, हर लाइन में एक, अधिकतम 10। केवल `https://`, और डेवलपमेंट के लिए `http://localhost`। कोई wildcard या `#fragments` नहीं: हर रिक्वेस्ट को इनमें से एक हूबहू भेजना होगा |
| **Scopes** | आपका ऐप अधिकतम जितना माँग सकता है। हर authorization इनमें से कुछ या सभी माँगता है |
| **Require PKCE** | हर authorization को `S256` code challenge भेजना होगा। सुझाया गया है, और डिफ़ॉल्ट रूप से चालू है |

सेव करने के बाद, QRdx **Client ID** और **Client secret** दिखाता है। secret को तभी कॉपी कर लें: QRdx उसका केवल hash रखता है और उसे दोबारा नहीं दिखा सकता। अगर वह खो जाए या लीक हो जाए, तो ऐप के पेज पर **Regenerate secret** चुनें। पुराना secret तुरंत काम करना बंद कर देता है; जो लोग पहले से कनेक्ट हैं वे कनेक्टेड रहते हैं। ऐप बनाने और उसका secret दोबारा बनाने से पहले आपको [पुष्टि करनी होगी कि यह आप ही हैं](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), जब तक कि आपने उसी ब्राउज़र में पिछले 10 मिनट में ऐसा न किया हो।

<Shot id="oauth-app-credentials" />

दोनों वैल्यू अपने सर्वर पर रखें:

```bash title=".env"
QRDX_CLIENT_ID=qrdx_app_...
QRDX_CLIENT_SECRET=qrdx_secret_...
```

## 2. लोगों को QRdx पर भेजें [#2-send-people-to-qrdx]

एक रैंडम `state` और एक PKCE `code_verifier` बनाएँ, दोनों को व्यक्ति के सेशन में रखें, और authorize URL पर redirect करें:

```txt title="Authorize URL"
https://qrdx.dev/api/oauth/authorize
  ?response_type=code
  &client_id=<client id>
  &redirect_uri=https://acme.example/oauth/qrdx/callback
  &scope=profile:read codes:read codes:write
  &state=<random value>
  &code_challenge=<BASE64URL(SHA256(code_verifier))>
  &code_challenge_method=S256
```

| पैरामीटर | ज़रूरी | वैल्यू |
| --- | --- | --- |
| `response_type` | हाँ | `code` |
| `client_id` | हाँ | आपके ऐप की client ID |
| `redirect_uri` | हाँ | ऐप के redirect URI में से एक, अक्षरशः |
| `scope` | हाँ | स्पेस या कॉमा से अलग किए हुए; केवल वही scopes जो ऐप के पास हैं |
| `state` | सुझाया गया | कोई भी वैल्यू; QRdx उसे बिना बदले वापस भेजता है। cross-site request forgery रोकने के लिए लौटने पर उसे जाँचें |
| `code_challenge` | अगर ऐप को PKCE चाहिए | 43 से 128 अक्षर: आपके `code_verifier` का base64url SHA-256 |
| `code_challenge_method` | नहीं | `S256`, डिफ़ॉल्ट और एकमात्र स्वीकार किया जाने वाला तरीका। `plain` को `invalid_request` के साथ अस्वीकार किया जाता है |
| `prompt` | नहीं | `consent` consent स्क्रीन तब भी दिखाता है जब व्यक्ति पहले इन scopes को मंज़ूर कर चुका हो |

```ts title="lib/qrdx-oauth.ts"
import { createHash, randomBytes } from "node:crypto";

export const QRDX_AUTHORIZE_URL = "https://qrdx.dev/api/oauth/authorize";

export function createPkce() {
  const verifier = randomBytes(32).toString("base64url"); // 43 characters
  const challenge = createHash("sha256").update(verifier).digest("base64url");
  return { verifier, challenge };
}

export function authorizeUrl({ state, challenge }: { state: string; challenge: string }) {
  const url = new URL(QRDX_AUTHORIZE_URL);
  url.search = new URLSearchParams({
    response_type: "code",
    client_id: process.env.QRDX_CLIENT_ID!,
    redirect_uri: "https://acme.example/oauth/qrdx/callback",
    scope: "profile:read codes:read codes:write",
    state,
    code_challenge: challenge,
    code_challenge_method: "S256",
  }).toString();
  return url.toString();
}
```

जो लोग QRdx में साइन इन नहीं हैं, वे पहले साइन इन करते हैं। फिर उन्हें consent स्क्रीन दिखती है: आपके ऐप का लोगो, नाम, वेबसाइट और उसे किसने बनाया, आपके माँगे गए permissions, और वह अकाउंट जिससे वे साइन इन हैं। जिन ऐप्स को QRdx ने रिव्यू नहीं किया है उन पर **Unverified app.** नोट लगा होता है। **Authorize** उनसे [पुष्टि करवाता है कि यह वही हैं](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), जब तक कि उन्होंने पिछले 10 मिनट में ऐसा न किया हो (कुछ क्षण पहले का साइन-इन भी गिना जाता है)। जिसने आपके ऐप के लिए यही scopes पहले मंज़ूर किए हैं, वह सीधे आपके पास लौट जाता है।

<Shot id="oauth-consent-screen" />

इसके बाद QRdx आपके `redirect_uri` पर redirect करता है:

- मंज़ूर होने पर: `?code=<authorization code>&state=<your state>`। कोड एक बार ही काम करता है, 10 मिनट के भीतर।
- रद्द होने पर: `?error=access_denied&error_description=...&state=<your state>`।

अमान्य रिक्वेस्ट कभी redirect नहीं होतीं; वे OAuth 2.0 के रूप में JSON लौटाती हैं। अज्ञात `client_id` पर `invalid_client`, अपंजीकृत `redirect_uri` या `plain` challenge पर `invalid_request`, और ऐसे scope पर जो ऐप के पास नहीं है `invalid_scope` आता है:

```json title="400 Bad Request"
{"error":"invalid_scope","error_description":"Invalid or unsupported scope"}
```

## 3. कोड को tokens से बदलें [#3-exchange-the-code-for-tokens]

अपने सर्वर से, कोड को token endpoint पर पोस्ट करें। बॉडी form-encoded होती है, और `redirect_uri` वही होना चाहिए जो आपने स्टेप 2 में इस्तेमाल किया था।

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=authorization_code \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d code=$CODE \
  -d redirect_uri=https://acme.example/oauth/qrdx/callback \
  -d code_verifier=$CODE_VERIFIER
```

```ts title="app/oauth/qrdx/callback/route.ts"
export async function GET(req: Request) {
  const params = new URL(req.url).searchParams;
  const session = await getSession(req); // your own session store
  if (params.get("state") !== session.qrdxState) {
    return new Response("Invalid state", { status: 400 });
  }
  if (params.get("error")) {
    return Response.redirect("https://acme.example/settings?qrdx=canceled");
  }

  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "authorization_code",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      code: params.get("code") ?? "",
      redirect_uri: "https://acme.example/oauth/qrdx/callback",
      code_verifier: session.qrdxVerifier,
    }),
  });
  if (!response.ok) {
    const { error, error_description } = await response.json();
    throw new Error(`QRdx token exchange failed: ${error} ${error_description}`);
  }

  const tokens: {
    access_token: string;
    token_type: "Bearer";
    expires_in: number;
    refresh_token: string;
    scope: string;
  } = await response.json();
  await saveQrdxTokens(session.userId, tokens); // encrypt at rest
  return Response.redirect("https://acme.example/settings?qrdx=connected");
}
```

```json title="Response fields"
{
  "access_token": "<send as Authorization: Bearer>",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "<store encrypted; it rotates on each refresh>",
  "scope": "profile:read codes:read codes:write"
}
```

`scope` में वह सब है जो दिया गया, स्पेस से अलग किया हुआ। Access tokens 1 घंटे चलते हैं और refresh tokens 30 दिन। `code_verifier` ठीक तभी भेजें जब authorization में `code_challenge` था; बिना challenge के जारी हुए कोड के लिए verifier अस्वीकार किया जाता है। गलत secret या पहले से इस्तेमाल हो चुके कोड पर `invalid_client` या `invalid_grant` आता है, और समर्थित दोनों के अलावा किसी अन्य grant type पर:

```json title="400 Bad Request"
{"error":"unsupported_grant_type","error_description":"Supported: authorization_code, refresh_token"}
```

## 4. Tokens रिफ़्रेश करें [#4-refresh-tokens]

Access token की मियाद खत्म होने से पहले, refresh token देकर नया जोड़ा लें। Refresh tokens रोटेट होते हैं: हर एक सिर्फ़ एक बार काम करता है, इसलिए हर बार नया वाला सेव करें।

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=refresh_token \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d refresh_token=$REFRESH_TOKEN
```

```ts title="lib/qrdx-oauth.ts"
export async function refreshQrdxTokens(refreshToken: string) {
  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "refresh_token",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      refresh_token: refreshToken,
    }),
  });
  // invalid_grant: revoked, expired or already used. Ask the person to reconnect.
  if (!response.ok) throw new Error((await response.json()).error);
  return response.json();
}
```

token endpoint प्रति IP address प्रति मिनट 30 रिक्वेस्ट की अनुमति देता है।

## 5. API कॉल करें [#5-call-the-api]

Access token को Bearer token के रूप में `https://api.qrdx.dev/v1` पर भेजें। Token रिक्वेस्ट उस व्यक्ति के अपने वर्कस्पेस पर काम करती हैं जिसने आपके ऐप को authorize किया (हर अकाउंट का एक होता है), उस वर्कस्पेस के प्लान और [दैनिक कोटा](/docs/developers/rest-api#rate-limits) के तहत। केवल उतना ही माँगें जितना आपके इंटीग्रेशन को चाहिए; लोग consent स्क्रीन पर हर scope देखते हैं।

| Scope | क्या अनुमति देता है |
| --- | --- |
| `profile:read` | यूज़र की id, नाम, ईमेल और avatar: `GET /v1/me` और `GET /api/oauth/userinfo` |
| `themes:read` | उनकी सेव की हुई QR थीम: `GET /v1/themes`, `GET /v1/themes/{id}` |
| `codes:read` | उनके डायनेमिक कोड, स्कैन analytics और सेव किए हुए बारकोड; hooks की सूची |
| `codes:write` | वह सब जो `codes:read` देता है, साथ ही कोड और बारकोड बनाना, बदलना और हटाना, conversions रिपोर्ट करना और इवेंट की सदस्यता लेना |

```ts title="lib/qrdx.ts"
const response = await fetch("https://api.qrdx.dev/v1/codes", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${accessToken}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    destinationUrl: "https://acme.example/menu",
    title: "Spring menu",
  }),
});
const { data: code } = await response.json(); // code.shortLink is what the QR encodes
```

`401 INVALID_TOKEN` का मतलब है कि token की मियाद खत्म हो गई या उसे रद्द कर दिया गया: उसे रिफ़्रेश करें, या व्यक्ति से दोबारा कनेक्ट करने को कहें। `403 INSUFFICIENT_SCOPE` का मतलब है कि token के पास वह scope नहीं है। [API रेफ़रेंस](/docs/developers/api) में हर endpoint उसके scope और errors के साथ दी गई है।

## 6. webhooks से इवेंट प्राप्त करें [#6-receive-events-with-webhooks]

लोगों से URL पेस्ट करवाने के बजाय REST Hooks API से उनकी ओर से सब्सक्राइब करें। इसके लिए `codes:write` चाहिए, और व्यक्ति के प्लान में [webhooks](/docs/webhooks) (Business) शामिल होने चाहिए; नहीं तो यह `402 PLAN_REQUIRED` लौटाता है।

```bash title="Terminal"
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://acme.example/webhooks/qrdx", "events": ["scan.created", "form.submitted"]}'
```

`201` रिस्पॉन्स में सब्सक्रिप्शन की `id` और एक signing `secret` होता है, जो सिर्फ़ एक बार दिखता है। हर डिलीवरी इसी से `X-QRdx-Signature` में साइन की जाती है; [सिग्नेचर सत्यापित करें](/docs/webhooks#verify-signatures) देखें। जब व्यक्ति डिस्कनेक्ट करे तो `DELETE /v1/hooks/{id}` से सब्सक्रिप्शन हटाएँ। सब्सक्रिप्शन उनके अपने वर्कस्पेस की **Settings → Webhooks** में भी दिखते हैं, जहाँ वे उन्हें हटा सकते हैं।

## 7. डिस्कनेक्ट करें और लोगों की पहचान करें [#7-disconnect-and-identify-people]

जब कोई आपके प्रोडक्ट में QRdx को डिस्कनेक्ट करे, तो उसके tokens रद्द करें। जोड़े के किसी भी एक token को रद्द करने से पूरा जोड़ा रद्द हो जाता है; endpoint अज्ञात tokens के लिए भी `200` लौटाता है।

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/revoke -d token=$REFRESH_TOKEN
```

लोग QRdx में **Settings → Authorized apps** में जाकर **Revoke access** से कभी भी खुद एक्सेस वापस ले सकते हैं। आपके ऐप के पास उनके अकाउंट के जितने भी tokens हैं, सब तुरंत काम करना बंद कर देते हैं: API कॉल `invalid_token` के साथ `401` लौटाती हैं और रिफ़्रेश करने पर `invalid_grant` आता है। दोनों को "डिस्कनेक्टेड" मानें और उनसे दोबारा कनेक्ट करने को कहें; उन्हें फिर से consent स्क्रीन दिखेगी।

कनेक्ट करने वाले की पहचान के लिए, `profile:read` token के साथ `GET /api/oauth/userinfo` कॉल करें। यह OpenID-style claims लौटाता है: `sub`, `name`, `email` और `picture`; स्थायी अकाउंट id के रूप में `sub` इस्तेमाल करें, क्योंकि ईमेल बदल सकते हैं।

```bash title="Terminal"
curl https://qrdx.dev/api/oauth/userinfo -H "Authorization: Bearer $ACCESS_TOKEN"
```

```json title="401 Unauthorized: an expired or revoked token"
{"error":"invalid_token","error_description":"Invalid or expired token"}
```

## 8. लिस्ट हों [#8-get-listed]

जब आपका इंटीग्रेशन शुरू से अंत तक काम करे, तो उसे [इंटीग्रेशन डायरेक्टरी](/integrations) में जोड़ने का अनुरोध करें, जहाँ वह आपके बनाए कम्युनिटी इंटीग्रेशन के रूप में दिखता है। आपके ऐप के पेज पर, **Get listed** [support@qrdx.dev](mailto:support@qrdx.dev?subject=List%20my%20integration) को एक ईमेल खोलता है जिसमें विवरण पहले से भरे होते हैं:

- आपके ऐप का नाम और client ID;
- एक लाइन में कि वह क्या करता है, और किसके लिए है;
- सेटअप के स्टेप, या उनका लिंक;
- सपोर्ट के लिए संपर्क।

QRdx टीम लिस्ट किए गए ऐप्स को रिव्यू करती है और उन्हें **Verified** मार्क करती है, जिससे consent स्क्रीन से **Unverified app.** नोट हट जाता है। किसी verified ऐप का नाम, लोगो या वेबसाइट बदलने पर दोबारा रिव्यू होने तक बैज हट जाता है।

## अगर कुछ गड़बड़ हो जाए [#if-something-goes-wrong]

### `invalid_request: redirect_uri not registered` [#invalid_request-redirect_uri-not-registered]

authorize URL में दिया गया `redirect_uri` ऐप के किसी भी redirect URI से अक्षरशः मेल नहीं खाता, स्कीम और अंत के स्लैश समेत। इसे ऐप में जोड़ें, या URL ठीक करें।

### `invalid_scope` [#invalid_scope]

authorize URL ऐसा स्कोप माँग रहा है जो ऐप के पास नहीं है। **Settings → API keys & apps** में ऐप में वह स्कोप जोड़ें, फिर दोबारा माँगें।

### रिफ़्रेश पर `invalid_grant` [#invalid_grant-on-refresh]

रिफ़्रेश टोकन पहले ही इस्तेमाल हो चुका है (हर रिफ़्रेश एक नया टोकन देता है), 30 दिन बाद एक्सपायर हो गया है, या यूज़र ने आपके ऐप का एक्सेस रद्द कर दिया है। उन्हें फिर से ऑथराइज़ेशन के लिए भेजें।

### सीक्रेट दोबारा जनरेट करने के बाद टोकन काम करना बंद कर दें [#tokens-stop-working-after-you-regenerated-the-secret]

सिर्फ़ नए टोकन अनुरोध नया सीक्रेट इस्तेमाल करते हैं; मौजूदा एक्सेस और रिफ़्रेश टोकन वैध रहते हैं। जाँच लें कि हर सर्वर इंस्टेंस नया `QRDX_CLIENT_SECRET` पढ़ रहा है।

## सिक्योरिटी चेकलिस्ट [#security-checklist]

- क्लाइंट सीक्रेट अपने सर्वर पर रखें। ब्राउज़र और मोबाइल कोड को यह कभी नहीं दिखना चाहिए।
- हर ऑथराइज़ेशन के लिए PKCE (`S256`) और नया `state` इस्तेमाल करें, और वापसी पर `state` जाँचें।
- सटीक redirect URI रजिस्टर करें; QRdx उन्हें अक्षरशः मिलाता है।
- एक्सेस और रिफ़्रेश टोकन एन्क्रिप्ट करके स्टोर करें, और हर रिफ़्रेश के बाद नया रिफ़्रेश टोकन सेव करें।
- जब लोग डिस्कनेक्ट करें तो टोकन रद्द करें। **Settings → API keys & apps** में अपना ऐप डिलीट करने पर उसके जारी किए सभी टोकन रद्द हो जाते हैं; उसे पॉज़ करने पर वे तब तक अस्वीकार रहते हैं जब तक आप उसे फिर से चालू नहीं करते।
