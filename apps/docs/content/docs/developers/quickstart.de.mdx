Am Ende dieser Seite hast du ein QR-Code-Bild, das aus einer einzigen Anfrage gespeichert wurde, einen API-Key für deinen Workspace, einen dynamischen QR-Code, dessen gedruckter QR weiter funktioniert, nachdem du das Ziel geändert hast, und einen ersten Blick auf seine Scan-Analysen.

Die API besteht aus zwei Hälften. Bilder brauchen nichts: kein Konto, keinen Key. Dynamische Codes, Scans und Webhooks gehören zu einem Workspace und brauchen deshalb einen API-Key.

## Bevor du loslegst [#before-you-start]

- curl, Node.js 18 oder neuer oder Python 3 mit dem Paket `requests`. Wähle den Tab für das, was du nutzt; die Auswahl bleibt auf allen Seiten erhalten.
- Ein QRdx-Konto für die Schritte 2 bis 4. Ein kostenloses reicht: Kostenlos-Workspaces haben 10 aktive dynamische Codes und 1.000 API-Anfragen pro Tag.

## 1. Ein QR-Code-Bild erstellen (ohne Key) [#1-make-a-qr-code-image-no-key]

Führe das aus. Es speichert ein PNG eines QR-Codes, der qrdx.dev öffnet.

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png" -o qr.png
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="qr.mjs"
    // Node 18 or later
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/qr");
    url.searchParams.set("data", "https://qrdx.dev");
    url.searchParams.set("format", "png");

    const response = await fetch(url);
    await writeFile("qr.png", Buffer.from(await response.arrayBuffer()));
    console.log(response.status, response.headers.get("content-type"));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="qr.py"
    # pip install requests
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/qr",
        params={"data": "https://qrdx.dev", "format": "png"},
    )
    response.raise_for_status()
    open("qr.png", "wb").write(response.content)
    print(response.status_code, response.headers["content-type"])
    ```
  </Tab>
</Tabs>

```txt title="Output"
200 image/png
qr.png: PNG image data, 512 x 512, 8-bit/color RGBA, non-interlaced
```

Das ist ein funktionierender API-Aufruf. Die URL selbst ist das Bild, deshalb funktioniert sie auch direkt in einem `<img>`-Tag:

```html title="index.html"
<img src="https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&fg=111111&body=circle" alt="QR code for qrdx.dev" />
```

Ändere Farben, Formen, Größe und Format über Query-Parameter oder probiere sie im Browser auf der Seite [QR-Code-Bild rendern](/docs/developers/api/get-qr-image) aus: Das Panel **Try it** sendet die Anfrage und zeigt das Bild. Bilder zählen nicht auf ein Kontingent an; das Limit liegt bei {facts.imageApiPerMinute} Anfragen pro Minute und IP-Adresse.

## 2. Einen API-Key erstellen [#create-an-api-key]

Alles andere in der API wirkt auf einen Workspace: dynamische Codes erstellen, ihr Ziel ändern, ihre Scans lesen. Diese Anfragen tragen einen API-Key im `Authorization`-Header.

1. Öffne [Einstellungen → API-Keys & Apps](/dashboard?to=settings/developers&new=1) und melde dich bei Bedarf zuerst an. Das Formular **API-Key erstellen** öffnet sich.
2. Gib dem Key einen Namen, zum Beispiel den des Servers, auf dem er laufen wird, lass **Vollzugriff** ausgewählt und wähle **Key erstellen**. QRdx fragt eventuell zuerst, ob du es wirklich bist.
3. Kopiere den Key aus dem Dialog **API-Key kopieren**. Er wird nur dieses eine Mal angezeigt: QRdx speichert nur einen Hash davon und kann ihn nicht erneut anzeigen. Der Dialog zeigt außerdem eine curl-Anfrage, die einen dynamischen QR-Code erstellt, mit eingetragenem Key, falls du lieber diese einfügst.

<Shot id="create-key-dialog" />

<Shot id="api-key-copy-dialog" />

Exportiere den Key für die nächsten Schritte:

```bash title="Terminal"
export QRDX_API_KEY=qrdx_...
```

Der Key handelt als du in dem Workspace, der beim Erstellen geöffnet war, und Anfragen damit zählen auf das Tageskontingent dieses Workspace. [API-Keys](/docs/developers/api-keys) behandelt Scopes, Teams, Ablauf und Widerrufen.

## 3. Einen dynamischen QR-Code erstellen [#3-create-a-dynamic-code]

Ein dynamischer QR-Code ist ein Kurzlink, den du nach dem Druck auf ein anderes Ziel zeigen lassen kannst:

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -X POST https://api.qrdx.dev/v1/codes \
      -H "Authorization: Bearer $QRDX_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"destinationUrl": "https://example.com", "title": "My first code"}'
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="create.mjs"
    const response = await fetch("https://api.qrdx.dev/v1/codes", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.QRDX_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        destinationUrl: "https://example.com",
        title: "My first code",
      }),
    });
    const { data: code } = await response.json();
    console.log(response.status, code.id, code.shortLink);
    ```
  </Tab>
  <Tab value="Python">
    ```python title="create.py"
    import os
    import requests

    response = requests.post(
        "https://api.qrdx.dev/v1/codes",
        headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},
        json={"destinationUrl": "https://example.com", "title": "My first code"},
    )
    response.raise_for_status()
    code = response.json()["data"]
    print(response.status_code, code["id"], code["shortLink"])
    ```
  </Tab>
</Tabs>

Die Antwort ist `201 Created` mit dem neuen Code:

```json title="201 Created"
{
  "data": {
    "id": "cmwgwq0t80000iscg4ybn05kh",
    "slug": "l0q9fZn",
    "shortLink": "https://qrdx.dev/q/l0q9fZn",
    "defaultShortLink": "https://qrdx.dev/q/l0q9fZn",
    "nfcLink": "https://qrdx.dev/q/l0q9fZn?nfc",
    "domain": null,
    "destinationUrl": "https://example.com/",
    "title": "My first code",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-11-14T21:17:45.512Z",
    "updatedAt": "2026-11-14T21:17:45.512Z",
    "organizationId": "ws_ad2c5e1cce31ccf31535e78f08ab5b78",
    "preciseLocation": false
  }
}
```

Zwei Felder sind jetzt wichtig. `shortLink` ist das, was der QR-Code kodiert: Rendere ihn mit der Image API aus Schritt 1, `https://api.qrdx.dev/v1/qr?data=https://qrdx.dev/q/l0q9fZn&format=png`, und drucke das. `id` ist ab jetzt dein Bezug auf den Code, also bewahre ihn auf:

```bash title="Terminal"
export CODE_ID=cmwgwq0t80000iscg4ybn05kh
```

[Codes erstellen](/docs/developers/api/create-codes) listet alle Felder auf, die du senden kannst, darunter einen eigenen Back-Half und ein Design.

## 4. Auf ein anderes Ziel zeigen lassen [#4-point-it-somewhere-else]

Ändere das Ziel jederzeit; der gedruckte Code funktioniert weiter:

```bash title="Terminal"
curl -X PATCH https://api.qrdx.dev/v1/codes/$CODE_ID \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/new-page"}'
```

Die Antwort `200 OK` ist derselbe Code mit `"destinationUrl": "https://example.com/new-page"` und einem neuen `updatedAt`. Scanne den Code mit deinem Handy und lies dann seine Analysen:

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/codes/$CODE_ID/scans?range=7d" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

```json title="200 OK (before the first scan, trimmed)"
{
  "data": {
    "codeId": "cmwgwq0t80000iscg4ybn05kh",
    "range": "7d",
    "retentionDays": 365,
    "days": 7,
    "total": 0,
    "unique": 0,
    "interval": "day",
    "series": [{ "date": "2026-11-08", "count": 0 }, { "date": "2026-11-09", "count": 0 }],
    "countries": [],
    "devices": [],
    "sources": { "qr": 0, "nfc": 0 }
  }
}
```

Nach einem Scan steigt `total`, und `countries`, `cities`, `devices`, `os` und `browsers` füllen sich. [Scan-Analysen abrufen](/docs/developers/api/get-code-scans) erklärt die Zeiträume und wie du einzelne Scans seitenweise durchgehst.

## Wenn etwas schiefgeht [#if-something-goes-wrong]

Jeder Fehler ist JSON mit einem stabilen `code` und einer Meldung, die sagt, was zu tun ist. Die beiden, die dir auf dieser Seite am ehesten begegnen:

```json title="401 Unauthorized: the header is missing"
{
  "code": "UNAUTHORIZED",
  "message": "Missing API key. Send an API key as \"Authorization: Bearer <key>\"; create one at https://qrdx.dev/dashboard?to=settings/developers. OAuth access tokens go in the same header.",
  "status": 401,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

```json title="400 Bad Request: the destination isn't a full URL"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "data": { "details": [{ "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }] },
  "status": 400
}
```

Ein `401 INVALID_TOKEN` bedeutet, dass der Key zu kurz kopiert wurde, widerrufen wurde oder abgelaufen ist: Erstelle einen neuen. Ein `403 INSUFFICIENT_SCOPE` bedeutet, dass du einen **Nur Lesen**-Key erstellt hast; Schritt 3 braucht `codes:write`. Die [Fehlerseite](/docs/developers/errors) listet jeden Code mit seiner Lösung auf.

## Im Namen anderer Personen handeln [#get-an-access-token]

Ein API-Key handelt als du. Wenn dein Produkt QRdx für andere Personen aufruft, registriere stattdessen eine OAuth-App: Jede Person genehmigt sie einmal, und dein Server erhält ein Access-Token für ihr Konto, das im selben `Authorization: Bearer`-Header gesendet wird. Jede Anfrage oben funktioniert unverändert mit einem Token anstelle des Keys. Siehe [REST API und OAuth](/docs/developers/rest-api#get-an-access-token) und [Eine Integration bauen](/docs/developers/build-an-integration).
