모든 REST API 오류는 어떤 엔드포인트에서 반환되든 같은 형태의 JSON입니다. `code`는 절대 바뀌지 않으므로 `code`를 기준으로 분기하세요. `message`는 사람이 읽도록 작성된 문구라서 표현이 바뀔 수 있습니다.

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## 오류 코드 [#error-codes]

상태 코드 순서로 정렬했습니다. 두 번 나오는 코드는 상태 코드마다 의미가 다릅니다.

| 상태 | 코드 | 발생 시점 | 해결 방법 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 본문, 쿼리 또는 경로가 유효성 검사를 통과하지 못했습니다. `data.details`에 각 문제가 `{ path, message }` 형태로 나열됩니다(이미지 API에서는 `{ param, message }`). 본문이 코드 배열이면 해당 행의 `index`도 함께 표시됩니다. | `data.details`에 나열된 필드를 수정한 다음 요청을 다시 보내세요. |
| 400 | `INVALID_SLUG` | 사용자 지정 back-half(`slug`)가 규칙을 어겼습니다. 예약어이거나, 한 요청에 같은 back-half가 두 번 들어간 경우입니다. 배열이면 `data.details`에 각 행이 `index`별로 나열됩니다. | 다른 back-half를 선택하세요. 메시지에 어떤 규칙인지 나와 있습니다. |

| 400 | `DOMAIN_NOT_VERIFIED` | `domainId`가 아직 인증되지 않은 사용자 지정 도메인을 가리킵니다. | 도메인 페이지에서 도메인 인증을 완료하거나, `domainId`를 빼세요. |

| 401 | `UNAUTHORIZED` | 자격 증명이 없습니다. 요청에 `Authorization: Bearer` 헤더가 없고 QRdx 브라우저 세션도 없습니다. | API 키를 `Authorization: Bearer <key>`로 보내세요. 키는 설정 → API 키 및 앱에서 만들 수 있습니다. OAuth 액세스 토큰도 같은 헤더에 넣습니다. |

| 402 | `AI_ART_CREDITS_EXHAUSTED` | 워크스페이스가 이번 달 AI 아트 이미지를 모두 사용했습니다(무료와 Pro). 이 요청에는 비용이 청구되지 않았습니다. | 매월 1일(UTC)에 사용량이 초기화될 때까지 기다리거나, 더 많은 이미지를 쓰려면 업그레이드하세요. |

## 오류 본문 [#the-error-body]

| 필드 | 설명 |
| --- | --- |
| `code` | 위 표에 있는, 변하지 않는 기계 판독용 코드 |
| `message` | 무엇이 잘못되었고 어떻게 고치는지 사람이 읽도록 설명한 문장입니다. 문구는 바뀔 수 있어요 |
| `status` | HTTP 상태 코드를 그대로 다시 보여 줍니다 |
| `docs` | 해결 방법을 설명하는 페이지입니다. 해당 페이지가 있을 때만 포함돼요 |
| `data` | 일부 오류에 포함되는 추가 정보입니다. `VALIDATION_ERROR`는 각 문제를 `data.details`에 나열해요 |

검증 오류는 실패한 모든 필드를 알려 줍니다. 코드를 일괄 생성하는 요청에서는 각 문제에 0부터 센 행의 `index`도 함께 들어갑니다.

```json title="400 Bad Request"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

이미지 엔드포인트(`GET /v1/qr`, `GET /v1/barcode`)는 쿼리 파라미터를 `{ "path", "message" }` 대신 `{ "param", "message" }` 형태로 알려 줍니다.

## 재시도 [#retrying]

- **`429`:** `Retry-After`에 적힌 초만큼 기다린 뒤 같은 요청을 다시 보내세요. 일일 할당량이 소진되면 `X-RateLimit-*` 헤더에서 플랜이 허용하는 요청 수와 카운트가 초기화되는 시각(00:00 UTC)을 확인할 수 있습니다. 분당 제한에서는 `Retry-After`만 전송됩니다. [요청 제한](/docs/developers/rest-api#rate-limits)을 참고하세요.
- **`500`, `502`, `503`, `504`:** 약 1초부터 시작하는 지수 백오프로 재시도하세요. AI 아트의 `5xx` 오류는 이미지를 사용하지 않으므로 재시도해도 비용이 들지 않습니다.
- **그 밖의 `4xx`:** 같은 요청은 같은 방식으로 실패합니다. 먼저 요청을 고치세요.

`POST /v1/codes` 요청에 `Idempotency-Key` 헤더가 있으면 안전하게 재시도할 수 있습니다. 같은 키로 다시 보내면 코드를 두 번 만들지 않고, 첫 번째 시도에서 만든 코드를 `Idempotent-Replayed: true`와 함께 반환합니다([코드 만들기](/docs/developers/api/create-codes)). 헤더가 없다면 요청을 다시 보내기 전에 코드 목록을 먼저 조회하세요. `POST /v1/conversions`는 직접 지정한 `id`를 함께 보내면 안전하게 반복할 수 있으며, 반복 요청에는 `duplicate: true`와 함께 `200`이 반환됩니다.

## `/v1/me`와 `/v1/themes` [#v1me-and-v1themes]

이 두 엔드포인트는 같은 본문에 더해, 예전부터 보내던 OAuth 필드인 `error`와 `error_description`(`message`와 같은 텍스트)도 보냅니다. 그래서 이전 클라이언트도 계속 동작해요.

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED 또는 INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (일일 할당량) |
| `not_found` | NOT_FOUND (themes) |

## OAuth 엔드포인트 [#oauth-endpoints]

`https://qrdx.dev/api/oauth` 아래의 OAuth 엔드포인트(authorize, token, revoke, userinfo)는 대신 OAuth 2.0 표준을 따릅니다. 형식은 `{ "error", "error_description" }`이고, `error`는 `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token`, `access_denied` 중 하나입니다. 토큰 갱신 시 `invalid_grant`가 반환되면 리프레시 토큰이 이미 사용되었거나(갱신할 때마다 새 토큰이 발급됩니다), 30일이 지나 만료되었거나, 사용자가 앱 권한을 취소했다는 뜻입니다. 사용자가 인증 과정을 처음부터 다시 거치게 하세요. [REST API와 OAuth](/docs/developers/rest-api#get-an-access-token)를 참고하세요.

## 알 수 없는 엔드포인트 [#unknown-endpoints]

`/v1` 아래에 없는 경로는 HTML 페이지가 아니라 JSON 형식의 `404 NOT_FOUND`를 반환하며, 엔드포인트 목록으로 연결되는 `docs` 링크가 포함됩니다. [API 레퍼런스](/docs/developers/api)에서 모든 엔드포인트를 확인할 수 있어요.
