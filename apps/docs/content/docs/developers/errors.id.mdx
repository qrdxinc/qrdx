Setiap error REST API berupa JSON dengan struktur yang sama, apa pun endpoint yang mengembalikannya. Gunakan `code` sebagai dasar percabangan logika karena nilainya tidak pernah berubah; `message` ditulis untuk manusia dan redaksinya dapat berubah.

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## Kode error [#error-codes]

Diurutkan berdasarkan status. Kode yang muncul dua kali memiliki arti yang berbeda pada setiap status.

| Status | Kode | Kapan terjadi | Yang perlu dilakukan |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Isi permintaan (body), query, atau path gagal validasi. `data.details` mencantumkan setiap masalah sebagai `{ path, message }` (`{ param, message }` pada API gambar), beserta `index` baris tersebut jika body berupa array kode. | Perbaiki kolom yang tercantum di `data.details`, lalu kirim ulang permintaan. |
| 400 | `INVALID_SLUG` | Back-half kustom (`slug`) melanggar aturan: kata yang dicadangkan, atau back-half yang sama dua kali dalam satu permintaan. Untuk array, `data.details` mencantumkan setiap baris berdasarkan `index`. | Pilih back-half lain. Pesan error menyebutkan aturannya. |
| 400 | `TOO_MANY_CODES` | Lebih dari 1.000 kode dalam satu permintaan. Skema body biasanya menolaknya lebih dulu sebagai `VALIDATION_ERROR`. | Kirim paling banyak 1.000 kode per permintaan. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` merujuk ke domain kustom yang belum diverifikasi. | Selesaikan verifikasi domain di halaman Domain, atau hapus `domainId` dari permintaan. |
| 400 | `SID_REQUIRED` | Konversi tanpa `qrdx_sid` dari pemindaian (dari browser), atau tanpa `sid` atau `code` (dari server). | Kirim `qrdx_sid` yang ditambahkan tautan pendek ke URL halaman Anda, atau, dengan kunci API atau token, kirim id kode sebagai `code`. |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` terlalu panjang untuk seni AI (lebih dari 300 karakter). | Kirim id kode dinamis sebagai `code`: seni tersebut mengodekan tautan pendeknya, yang singkat dan tetap bisa diedit. |
| 401 | `UNAUTHORIZED` | Tidak ada kredensial: permintaan tidak memiliki header `Authorization: Bearer` (dan tidak ada sesi browser QRdx). | Kirim kunci API sebagai `Authorization: Bearer <key>`; buat di Pengaturan → Kunci API & aplikasi. Token akses OAuth dikirim di header yang sama. |
| 401 | `INVALID_TOKEN` | Kunci API atau token akses tidak dikenal, dicabut, atau kedaluwarsa (token akses berlaku satu jam), atau pembuat kunci diblokir atau keluar dari workspace kunci tersebut. | Pastikan Anda mengirim kunci secara utuh, atau buat yang baru. Untuk token akses, dapatkan yang baru dengan refresh token Anda, atau arahkan pengguna melalui otorisasi lagi. |
| 402 | `PLAN_REQUIRED` | Fitur tidak tersedia di paket workspace: pembuatan massal, back-half kustom, dan domain kustom memerlukan Pro; konversi dan hook memerlukan Business. | Upgrade workspace, atau hapus fitur tersebut dari permintaan. |
| 402 | `LIMIT_REACHED` | Workspace sudah memiliki kode dinamis aktif sebanyak yang disertakan paketnya (10 di Gratis). | Arsipkan sebuah kode (kode yang diarsipkan tidak dihitung) atau upgrade ke Pro untuk kode tanpa batas. |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | Workspace telah menggunakan jatah gambar seni AI bulan ini (Gratis dan Pro). Permintaan ini tidak dikenai biaya. | Tunggu jatah direset pada tanggal 1 setiap bulan (UTC), atau upgrade untuk mendapatkan lebih banyak gambar. |
| 403 | `INSUFFICIENT_SCOPE` | Kunci API atau token valid, tetapi tidak memiliki scope yang dibutuhkan endpoint ini. | Buat kunci dengan scope yang disebutkan di pesan (scope kunci tidak dapat diubah). Untuk aplikasi OAuth, tambahkan scope tersebut dan minta saat pengguna memberi otorisasi. |
| 403 | `FORBIDDEN` | Pemanggil tidak diizinkan melakukan ini: anggota workspace menghapus kode yang dibuat orang lain, anggota mengelola hook, atau penulisan dari sesi browser di situs lain. Kunci API hanya dapat melakukan apa yang diizinkan oleh peran pembuatnya di workspace tersebut. | Minta pemilik atau admin workspace, atau panggil API dengan kunci API dari server Anda. |
| 403 | `CONFIRMATION_REQUIRED` | Membuat hook dengan sesi browser yang sedang masuk memerlukan "Konfirmasi bahwa ini Anda" yang baru. Kunci API dan token OAuth tidak dimintai konfirmasi. | Konfirmasi bahwa ini Anda di QRdx, lalu coba lagi dalam 10 menit, atau buat hook dengan kunci API dari server Anda. |
| 403 | `CONVERSIONS_OFF` | Konversi dari browser untuk kode yang pelacakan konversinya tidak diaktifkan. | Aktifkan pelacakan konversi untuk kode tersebut, atau laporkan konversi dari server Anda dengan kunci API. |
| 403 | `LIMIT_REACHED` | Workspace sudah memiliki 20 endpoint webhook dan hook. | Hapus endpoint atau hook yang tidak lagi Anda gunakan. |
| 404 | `NOT_FOUND` | Endpoint tidak ada, atau kode, hook, tema, atau domain kustom tidak ada di workspace tempat kunci atau token bekerja. | Periksa path dan id. Kunci API bekerja di workspace tempat kunci itu dibuat; token OAuth bekerja di workspace milik penggunanya sendiri. |
| 404 | `INVALID_SID` | `qrdx_sid` tidak dikenal atau lebih lama dari 30 hari, yaitu jendela atribusi. | Kirim `qrdx_sid` dari pemindaian terbaru, atau laporkan konversi berdasarkan id kode dari server Anda. |
| 409 | `SLUG_TAKEN` | Kode lain sudah menggunakan back-half tersebut di domain itu. Untuk array, `data.details` mencantumkan setiap yang sudah dipakai berdasarkan `index`, dan tidak ada yang dibuat. | Pilih back-half lain. |
| 413 | `PAYLOAD_TOO_LARGE` | Body melebihi batas endpoint: 4 MB untuk kode, 16 KB untuk hook, 8 KB untuk konversi. | 415 | `UNSUPPORTED_MEDIA_TYPE` | Penulisan tanpa `Content-Type: application/json`. | Kirim body JSON dengan `Content-Type: application/json`. |

## Isi respons error [#the-error-body]

| Field | Keterangan |
| --- | --- |
| `code` | Kode yang stabil dan dapat dibaca mesin dari tabel di atas |
| `message` | Penjelasan untuk manusia tentang apa yang salah dan cara memperbaikinya. Redaksinya dapat berubah |
| `status` | Status HTTP, diulang di sini |
| `docs` | Halaman yang menjelaskan cara memperbaikinya, jika ada |
| `data` | Detail tambahan pada beberapa error. `VALIDATION_ERROR` mencantumkan setiap masalah di `data.details` |

Error validasi menyebutkan setiap field yang gagal. Pada batch kode, setiap masalah juga membawa `index` baris, dihitung mulai dari 0:

```json title="400 Bad Request"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Endpoint gambar (`GET /v1/qr`, `GET /v1/barcode`) melaporkan parameter query sebagai `{ "param", "message" }`, bukan `{ "path", "message" }`.

## Mencoba ulang [#retrying]

- **`429`:** tunggu sejumlah detik yang tertera di `Retry-After`, lalu kirim permintaan yang sama. Saat kuota harian habis, header `X-RateLimit-*` menunjukkan jumlah permintaan yang diizinkan paket Anda dan kapan hitungan direset (00:00 UTC). Batas per menit hanya mengirim `Retry-After`. Lihat [batas laju](/docs/developers/rest-api#rate-limits).
- **`500`, `502`, `503`, dan `504`:** coba ulang dengan exponential backoff, mulai dari sekitar satu detik. Error `5xx` pada seni AI tidak pernah memakai gambar, sehingga percobaan ulang tidak dikenai biaya.
- **`4xx` lainnya:** permintaan yang sama akan gagal dengan cara yang sama. Perbaiki dulu.

Mencoba ulang `POST /v1/codes` aman jika permintaan membawa header `Idempotency-Key`: kunci yang sama mengembalikan kode yang dibuat pada percobaan pertama, dengan `Idempotent-Replayed: true`, alih-alih membuatnya dua kali ([Buat kode](/docs/developers/api/create-codes)). Tanpa header tersebut, daftar kode Anda terlebih dahulu sebelum mengirim permintaan lagi. `POST /v1/conversions` aman diulang jika Anda mengirim `id` sendiri: pengulangan mengembalikan `200` dengan `duplicate: true`.

## `/v1/me` dan `/v1/themes` [#v1me-and-v1themes]

Kedua endpoint ini mengirim body yang sama ditambah field OAuth yang selama ini mereka kirim, yaitu `error` dan `error_description` (teksnya sama dengan `message`), sehingga klien lama tetap berfungsi:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED atau INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (kuota harian) |
| `not_found` | NOT_FOUND (themes) |

## Endpoint OAuth [#oauth-endpoints]

Endpoint OAuth di bawah `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) mengikuti standar OAuth 2.0: `{ "error", "error_description" }`, dengan `error` berupa salah satu dari `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token`, atau `access_denied`. Jika Anda menerima `invalid_grant` saat refresh, artinya refresh token sudah dipakai (setiap refresh mengembalikan token baru), kedaluwarsa setelah 30 hari, atau pengguna telah mencabut akses aplikasi Anda: arahkan pengguna melalui otorisasi lagi. Lihat [REST API dan OAuth](/docs/developers/rest-api#get-an-access-token).

## Endpoint yang tidak dikenal [#unknown-endpoints]

Path di bawah `/v1` yang tidak ada mengembalikan `404 NOT_FOUND` sebagai JSON, bukan halaman HTML, dengan tautan `docs` ke daftar endpoint. [Referensi API](/docs/developers/api) mencantumkan semua endpoint.
