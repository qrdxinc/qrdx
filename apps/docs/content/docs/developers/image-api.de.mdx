Am Ende dieser Seite hast du eine URL für ein QR-Code-Bild, die du in eine README, ein `<img>`-Tag oder eine E-Mail-Vorlage einfügen kannst, im gewünschten Stil. Außerdem weißt du, was die API ablehnt und warum.

`GET https://api.qrdx.dev/v1/qr` liefert einen QR-Code als SVG-, PNG- oder WebP-Bild oder als Vektor-EPS-Datei für Druck- und Designtools. Alles steht im Query-String, die URL ist also selbst das Bild. Auch die Stile des Editors werden unterstützt: Verläufe, Rahmen (auch eigene Rahmen), Ränder, Farben für Augen und Punkte sowie Logo-Icons. Du brauchst weder ein Konto noch einen API-Schlüssel, außer für ein Logo, das du zu QRdx hochgeladen hast (siehe [Logos](#logos)).

```md title="README.md"
![QR code](https://api.qrdx.dev/v1/qr?data=https://github.com/you/repo)
```

[Im Playground ausprobieren](/playground?open=code&lang=image): Gestalte dort einen Code und kopiere dann seine Bild-URL. Oder sende Anfragen von der Referenzseite [QR-Code-Bild rendern](/docs/developers/api/get-qr-image).

## 1. Ein Bild anfordern [#1-request-an-image]

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -o qr.png "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png&size=1024"
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="qr.mjs"
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/qr");
    url.searchParams.set("data", "https://qrdx.dev");
    url.searchParams.set("format", "png");
    url.searchParams.set("size", "1024");

    const response = await fetch(url);
    await writeFile("qr.png", Buffer.from(await response.arrayBuffer()));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="qr.py"
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/qr",
        params={"data": "https://qrdx.dev", "format": "png", "size": 1024},
    )
    response.raise_for_status()
    open("qr.png", "wb").write(response.content)
    ```
  </Tab>
</Tabs>

```txt title="Output"
qr.png: PNG image data, 1024 x 1024, 8-bit/color RGBA, non-interlaced
```

Setze die URL in der Shell in Anführungszeichen, damit das `&` erhalten bleibt. In einer HTML-Seite kommt die URL direkt in `src`:

```html title="index.html"
<img
  src="https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&size=256&fg=155dfc"
  width="256"
  height="256"
  alt="QR code for qrdx.dev"
/>
```

## 2. Ein Format wählen [#2-pick-a-format]

| `format` | Liefert | Wann |
| --- | --- | --- |
| `svg` (Standard) | `image/svg+xml` | Webseiten und alles, was skaliert |
| `png` | `image/png` | E-Mail, Chat-Apps, Dokumente |
| `webp` | `image/webp`, verlustfrei, Transparenz bleibt erhalten | Websites: die Pixel des PNG in einer kleineren Datei |
| `eps` | `application/postscript`, gesendet als Download `qr-code.eps` | Illustrator, InDesign, Druckereien. `size` ist dann die Breite in Punkt, 72 pro Zoll, also sind `144` 2 Zoll |

```bash title="Terminal"
curl -o qr.webp "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=webp&size=1024"
curl -o qr.eps "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=eps&size=144"
head -2 qr.eps
# %!PS-Adobe-3.0 EPSF-3.0
# %%BoundingBox: 0 0 144 144
```

## 3. Gestalten [#3-style-it]

Flache Parameter decken Farben, Formen, einen Rahmen und ein Logo ab:

```txt title="Rounded modules with a frame drawn as a template"
https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&body=rounded&eye=rounded&dot=rounded&template=Arrow
```

```txt title="A built-in frame with its label, and a community frame by id"
https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&frame=banner-bottom&frameText=Scan%20the%20menu
https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&item=frame:wifi-card
```

Für Verläufe, eigene Rahmen und Farben pro Auge sendest du das ganze Design als JSON in `style`:

```js title="styled.mjs"
const style = {
  fgColor: {
    type: "linear",
    angle: 45,
    stops: [
      { color: "#1d4ed8", offset: 0 },
      { color: "#7c3aed", offset: 100 },
    ],
  },
  eyeColor: "#b91c1c",
  frame: { style: "banner-bottom", text: "Scan the menu" },
};
const src = `https://api.qrdx.dev/v1/qr?data=${encodeURIComponent(link)}&style=${encodeURIComponent(JSON.stringify(style))}`;
// 200 image/svg+xml, 634.88 × 727.04: the frame adds to the 512 px code
```

<Callout type="info">
Kodiere den Wert von `data`, wenn er `&`, `#`, `+` oder Leerzeichen enthält, zum Beispiel mit `encodeURIComponent` in JavaScript. Sonst wird die URL an diesen Zeichen aufgetrennt. Kodiere `style` genauso und schreibe Farben ohne `#` (oder als `%23`): Ein einzelnes `#` beginnt das URL-Fragment und wird nie gesendet.
</Callout>

## Parameter [#parameters]

| Parameter | Standard | Beschreibung |
| --- | --- | --- |
| `data` | erforderlich | Text oder URL zum Kodieren, bis zu 2048 Zeichen |
| `format` | `svg` | `svg`, `png`, `webp` oder `eps` |
| `size` | `512` | Breite und Höhe in Pixeln, `64` bis `2048` (Punkt bei EPS) |
| `fg` | `000000` | Modulfarbe als Hex-Wert (`155dfc`, `fff` oder 8 Ziffern mit Alpha) |
| `bg` | `ffffff` | Hintergrundfarbe als Hex-Wert. `00000000` ergibt einen transparenten Hintergrund |
| `eyeColor` | `fg` | Farbe der drei Eckaugen |
| `dotColor` | `fg` | Farbe des Punkts in jedem Eckauge |
| `body` | `square` | Form der Datenmodule; siehe [Muster-Werte](#pattern-values) |
| `eye` | `square` | Form der Rahmen der Eckaugen |
| `dot` | `square` | Form des Punkts in jedem Eckauge |
| `level` | `Q` | Fehlerkorrektur: `L` (etwa 7 %), `M` (15 %), `Q` (25 %) oder `H` (30 %) |
| `margin` | `4` | Ruhezone um den Code in Modulen, `0` bis `16` |
| `template` | keine | Ein [als Vorlage gezeichneter Rahmen](/docs/features/templates): Das ganze Bild ist `size` breit, der Code sitzt kleiner darin |
| `frame` | keine | Ein integrierter [Rahmen](/docs/features/frames) mit Handlungsaufforderung, etwa `banner-bottom`, `speech-bubble` oder `circle`: jeder der {facts.frameStyles} integrierten Rahmen |
| `frameText` | `Scan me` | Die Beschriftung des Rahmens, bis zu 24 Zeichen. Beschriftet auch den Rahmen von `style` oder `item` um |
| `style` | keine | Das gesamte Design des Editors als JSON; siehe [Stile](#style) |
| `item` | keine | Ein Community-Rahmen oder -Theme per ID, etwa `frame:wifi-card`; siehe [Community-Elemente](#community-items) |
| `logoIcon` | keine | Ein Schnell-Icon oder ein Markenlogo in der Mitte; siehe [Logos](#logos) |
| `logoFileId` | keine | Ein von dir hochgeladenes Logo per Datei-ID; erfordert einen API-Schlüssel; siehe [Logos](#logos) |

Enum-Werte (`level`, `format`, `template`, `frame`) unterscheiden nicht zwischen Groß- und Kleinschreibung. Bei einem Rahmen ist `size` die Breite des Codes selbst, und der Rahmen kommt in jedem Format zum Bild hinzu. Flache Parameter haben Vorrang vor `style`, und `style` hat Vorrang vor `item`.

## Stile [#style]

`style` nimmt das Design als JSON mit denselben Feldern wie ein gespeichertes Theme. Ein Theme aus [`GET /v1/themes`](/docs/developers/api/list-themes) oder das `qrdxStyle`, das `design_qr` des [MCP-Servers](/docs/developers/mcp) zurückgibt, kann also unverändert übergeben werden (ohne ein hochgeladenes Logo, siehe unten):

| Feld | Akzeptiert |
| --- | --- |
| `bgColor`, `fgColor`, `eyeColor`, `dotColor` | Eine Farbe (Hex wie `#155dfc`, `rgb()`, `hsl()` oder ein Farbname) oder einen Verlauf: `{ "type": "linear", "angle": 45, "stops": [...] }` oder `{ "type": "radial", "stops": [...] }`, mit 2 bis 8 Stopps aus `{ "color", "offset" }` (Offset 0 bis 100) |
| `bodyPattern`, `cornerEyePattern`, `cornerEyeDotPattern` | Die [Muster-Werte](#pattern-values) |
| `level`, `margin` | Wie die Parameter oben (`margin` 0 bis 16) |
| `templateId` | Ein als Vorlage gezeichneter Rahmen, `default` für keinen |
| `frame` | Ein integrierter Rahmen, `{ "style": "banner-bottom", "text": "Scan me", "color": "#155dfc", "textColor": "#ffffff" }`, oder ein eigener, `{ "style": "custom", "spec": { … } }`, mit einer Rahmen-Spezifikation aus der [Community](#community-items) oder einem eigenen Rahmen aus dem Bereich „Rahmen“ im Playground. Spezifikationen werden gegen die Regeln der Engine für Rahmen-Spezifikationen geprüft (kein Markup, keine Links oder Bilder; höchstens 32 KB) |
| `eyeColors` | Farben pro Auge, über `eyeColor` und `dotColor`: `{ "topLeft": { "outer": "#b91c1c", "inner": "#1d4ed8" }, "topRight": …, "bottomLeft": … }`, jeweils eine Farbe oder ein Verlauf |
| `moduleScale` | Größe jedes Punkts, `0.5` bis `1` (Standard `1`) |
| `shape` | `square` (Standard) oder `circle`: der Code in einer Scheibe aus dekorativen Punkten |
| `autoLevel` | Hebt die Fehlerkorrektur auf `H`, wenn das Logo mehr als 7 % des Codes bedeckt (hier immer aktiv, wenn es ein Logo gibt) |
| `logoOptions` | Das Layout des Logos: `size` (`0.1` bis `0.3` der Breite des Codes; QRdx verkleinert es, wenn der Code die Module nicht entbehren kann), `padding` (`0` bis `2` Module), `x` und `y` (`0` bis `1`), `shape` (Zuschnitt `square`, `rounded` oder `circle`) und `plate` (eine Farbe dahinter) |
| `showLogo`, `logoIcon`, `logoFileId` | Siehe [Logos](#logos) |

`style` akzeptiert auch den `style`-Wert eines Playground-Links (er beginnt mit `1.`), sodass ein im [Playground](/playground) geteiltes Design so gerendert wird, wie es dort aussieht, ohne sein Logo. Unbekannte Felder, Logo-Adressen (`customLogo`) und Logo-QR- oder Image-QR-Grafiken (`art`) werden mit einem `400` abgelehnt, der den Grund nennt:

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"style.customLogo","message":"Logo images by address aren't accepted: upload the image to QRdx and pass its file id as logoFileId, or pick a logoIcon."}]},"status":400}
```

## Community-Elemente [#community-items]

`item` rendert einen veröffentlichten [Community](/community)-Rahmen oder ein Theme, kostenlos unter CC0. IDs findest du mit [`GET /v1/community/items`](/docs/developers/api/list-community-items), oder öffne eine Element-Seite und nutze Typ und Slug: `/community/frames/wifi-card` ist `frame:wifi-card`. Ein Rahmen-Element sitzt auf einem schlichten schwarz-auf-weißen Code; füge `style` oder flache Parameter hinzu, um den Code darunter zu ändern. Renderings mit `item` werden 5 Minuten zwischengespeichert (10 am CDN), da ein Element eine neue Version bekommen oder entfernt werden kann.

## Logos [#logos]

- **Schnelle Icons.** `logoIcon` setzt eines der Icons aus dem Editor auf eine weiße Kachel in der Mitte: `wifi`, `location`, `phone`, `email`, `link`, `file`, `calendar`, `whatsapp` oder `instagram`. QRdx zeichnet sie selbst, und du brauchst dafür keinen Schlüssel.
- **Markenlogos.** `logoIcon` akzeptiert auch jede der {facts.brandLogos} Marken von [Simple Icons](https://simpleicons.org) über ihren Slug: `spotify`, `paypal`, `googlemaps`, `appstore`. Das Zeichen wird ohne Hintergrund in seiner Markenfarbe gezeichnet. Mit `:black` oder `:white` bekommst du diese Farben (`whatsapp:white`), und mit `logoOptions.plate` in `style` legst du eine Platte dahinter. [`GET /api/brand-logos`](https://qrdx.dev/api/brand-logos) listet alle Slugs auf. Bei einem Slug, den QRdx nicht kennt, bekommst du ein `400`, das die richtige Schreibweise vorschlägt.
- **Das QRdx-Zeichen**, das der Editor standardmäßig zeigt, wird hier nicht gezeichnet: `showLogo: true` allein fügt kein Logo hinzu.
- **Die Fehlerkorrektur steigt bei einem Logo.** Wenn ein Logo mehr als 7 % des Codes bedeckt, wird der Code auf Stufe `H` gezeichnet, egal was `level` angibt, damit er weiterhin scannt.

```bash title="Terminal"
curl -o spotify.png "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png&logoIcon=spotify"
```

<IfAvailable feature="fileStorage">

**Dein eigenes Logo.** `logoFileId` zeichnet ein PNG oder JPEG mit bis zu 1 MB, das du unter [Dashboard → Dateien](/docs/files) hochgeladen hast. Die ID ist der letzte Teil des Links der Datei, `https://qrdx.dev/api/files/<id>`. Sende einen [API-Schlüssel](/docs/developers/api-keys) des Workspaces, dem die Datei gehört:

```bash title="Terminal"
curl -o qr.png -H "Authorization: Bearer $QRDX_API_KEY" \
  "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png&logoFileId=<id>"
```

Die Antwort ist privat (`Cache-Control: private, no-store`) und zählt auf das tägliche API-Kontingent des Workspaces. Eine Datei aus einem anderen Workspace ergibt `404`, eine Anfrage ohne Schlüssel `401`. QRdx liest das Bild aus dem eigenen Speicher und prüft, dass es wirklich ein PNG oder JPEG ist. Ein Logo von einer Webadresse, die du sendest, ruft es nie ab.

</IfAvailable>

`logoOptions` legt Größe, Position, Zuschnitt und Hintergrund für jedes dieser Logos fest. Den eigenen Hintergrund eines hochgeladenen Logos entfernst du im Playground; die Image API zeichnet die hochgeladene Datei so, wie sie ist. Logo QR und Image QR sind hier nicht verfügbar: Der Playground erstellt sie im Browser aus deinem Bild. Gestalte Art-Codes im [Playground](/playground?tab=art), oder male einen Code mit der [AI-Art-API](/docs/developers/ai-art-api) in ein KI-Kunstwerk.

### Musterwerte [#pattern-values]

- `body`: `circle`, `circle-large`, `square`, `diamond`, `circle-mixed`, `pacman`, `rounded`, `small-square`, `vertical-line`, `horizontal-line`, `liquid`, `liquid-horizontal`, `liquid-vertical`, `classy`, `classy-rounded`, `leaf`, `plus`, `hexagon`, `star`, `heart`, `random-dots`, `mosaic`, `octagon`
- `eye`: `square`, `rounded`, `gear`, `circle`, `diya`, `extra-rounded`, `message`, `pointy`, `leaf`, `drop`, `octagon`, `bevel`, `squircle`, `cushion`, `shield`, `petal`, `leaf-reverse`
- `dot`: `square`, `rounded`, `circle`, `message`, `message-reverse`, `diya`, `diya-reverse`, `rounded-triangle`, `leaf`, `drop`, `plus`, `cross-rounded`, `hexagon`, `octagon`, `flower`, `heart`, `squircle`, `dots`, `extra-rounded`, `leaf-reverse`, `drop-reverse`
- `template`: `default`, `Arrow`, `StandardBox`, `SquareBorder`, `StrikedBox`, `Halloween`, `DotRing`

Das sind dieselben Stile wie in der [`qrdx`-React-Bibliothek](/docs/features/patterns). Der [MCP-Server](/docs/developers/mcp) kann sie auch mit Kurzbeschreibungen auflisten.

## Antworten [#responses]

Eine erfolgreiche Anfrage liefert das Bild mit:

- `Content-Type: image/svg+xml`, `image/png`, `image/webp` oder `application/postscript` (EPS wird als Download `qr-code.eps` gesendet)
- `Cache-Control: public, max-age=31536000, immutable`, außer bei Renderings mit `item` (5 Minuten, 10 am CDN) und mit `logoFileId` (`private, no-store`)
- `Access-Control-Allow-Origin: *`, damit du es von jeder Website aus per `fetch` abrufen kannst

Das Rendering ist deterministisch: Derselbe Query-String liefert immer dieselben Bytes, weshalb Antworten ein Jahr lang gecacht werden können. URLs, die nur die ursprünglichen Parameter verwenden, werden genau so gerendert wie immer.

## Wenn etwas schiefgeht [#if-something-goes-wrong]

### `400` mit `"param": "size"` [#400-with-param-size]

`size` liegt unter 64 oder über 2048. Der Body nennt das Limit:

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"size","message":"Too small: expected number to be >=64"}]},"status":400}
```

### `400` mit `"param": "data"` [#400-with-param-data]

Die Daten passen bei der gewählten Fehlerkorrekturstufe nicht in einen QR-Code. Nutze ein niedrigeres `level` (`L` fasst am meisten) oder kürzere Daten; bei langen URLs hilft meist der Kurzlink eines dynamischen QR-Codes.

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"Data is too long for a QR code at error correction level H. Shorten it or use a lower level (L holds the most)."}]},"status":400}
```

### `400` mit `"param": "logoIcon"` [#400-with-param-logoicon]

Der Slug ist weder eine Marke, die QRdx kennt, noch ein schnelles Icon. Die Meldung schlägt Schreibweisen vor, die funktionieren (`spotify`, `paypal`, `googlemaps` oder `wifi`, `phone`, `email`).

### Das Bild sieht falsch aus oder ist geteilt [#the-image-looks-wrong-or-is-split]

Ein `&`, `#` oder `+` in `data` oder `style` wurde nicht kodiert, sodass die URL an diesem Zeichen abgeschnitten wurde. Kodiere beide Werte und schreibe Farben ohne das `#`.

### `429 RATE_LIMITED` [#429-rate_limited]

Mehr als {facts.imageApiPerMinute} Anfragen pro Minute von einer IP-Adresse. Warte die Sekunden aus `Retry-After` ab. Dieselbe URL liefert immer dasselbe Bild, also cache es oder speichere die Datei, statt es live zu laden.

## Limits [#limits]

- **Ratenlimit:** {facts.imageApiPerMinute} Anfragen pro Minute und IP-Adresse. Bilder zählen nicht auf das tägliche Kontingent der REST API.
- **Keine Scan-Prüfung.** Die Image API zeichnet, was du anforderst. Um den Scan-Wert eines Designs vorab zu prüfen und zu reparieren, nutze `design_qr` auf dem [MCP-Server](/docs/developers/mcp) oder den Scan-Wert im [Playground](/playground?tab=design).
- **`style` umfasst bis zu 8.192 Zeichen** in der URL, sein JSON bis zu 40 KB.
- **Die Daten sind Teil der URL.** Wie jede URL kann sie in Server-Logs, im Browserverlauf und in Caches landen. Gib keine Passwörter oder andere Geheimnisse darin an.

## Tipps zum Scannen [#scanning-tips]

- Lass `margin` bei `2` oder mehr, wenn das Bild auf einem dunklen oder unruhigen Hintergrund liegt, etwa in einer README im Dark Mode von GitHub.
- Achte auf guten Kontrast zwischen `fg` und `bg`. Dunkle Module auf hellem Hintergrund scannen am zuverlässigsten.
- Die Standardwerte (quadratische Module, 4 Module Rand) scannen mit jedem Lesegerät. Stilisierte Formen wie `circle`-Punkte wirken weicher, und manche ältere Scanner lesen sie weniger zuverlässig: Prüfe das mit dem [Scan-Checker](/tools/scan-checker).
- Teste den Code vor dem Drucken mit ein paar Smartphones.

## Self-Hosting [#self-hosting]

Der Endpunkt gehört zur QRdx-Web-App, daher stellt ihn eine [selbst gehostete](/docs/self-hosting) Instanz unter `/api/v1/qr` auf deiner eigenen Domain bereit (zum Beispiel `https://qr.example.com/api/v1/qr?data=…`). Der kurze Pfad `/v1/qr` funktioniert nur auf `api.qrdx.dev`. Das Ratenlimit nutzt Upstash Redis, wenn es konfiguriert ist, und ist sonst aus.
