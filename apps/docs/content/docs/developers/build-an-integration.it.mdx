Alla fine di questa pagina, le persone potranno fare clic su **Connect QRdx** nel tuo prodotto, approvare la tua app nella schermata di consenso di QRdx, e il tuo server avrà un token di accesso che chiama `https://api.qrdx.dev/v1` per loro conto, limitato agli scope che hanno approvato.

Un'integrazione è un'app OAuth. A differenza di una [chiave API](/docs/developers/api-keys), che agisce come te in un singolo workspace, un token agisce come la persona che ha approvato la tua app, sul suo workspace, e può revocare quell'accesso in qualsiasi momento.

## Prima di iniziare [#before-you-start]

- Un account QRdx. I workspace Gratuito possono avere 1 app OAuth, Pro 5 e Business 25; un workspace usa il piano migliore tra i suoi proprietari.
- Un server in grado di custodire un segreto e ricevere un redirect. Gli esempi di codice sono in Node.js con la Fetch API; va bene qualsiasi linguaggio con HTTPS e SHA-256.
- I due redirect URI `https://` che userai: uno per la produzione, uno per lo sviluppo (per quest'ultimo è consentito `http://localhost`).

## 1. Crea un'app OAuth [#1-create-an-oauth-app]

Apri [Impostazioni → Chiavi API e app](/dashboard?to=settings/developers) e scegli **New app**. L'app appartiene al workspace aperto. Solo i proprietari del workspace possono creare e modificare le app; amministratori e membri possono vederle.

<Shot id="oauth-new-app-form" />

| Campo | A cosa serve |
| --- | --- |
| **Name**, **Description**, **Logo**, **Website** | Mostrati nella schermata di consenso. Carica un logo quadrato di almeno 128 × 128 px, oppure incolla un link `https://` a un logo |
| **Redirect URIs** | Dove QRdx rimanda le persone, uno per riga, fino a 10. Solo `https://`, più `http://localhost` per lo sviluppo. Niente caratteri jolly né `#fragments`: ogni richiesta deve inviarne uno esattamente uguale |
| **Scopes** | Il massimo che la tua app può richiedere. Ogni autorizzazione ne richiede alcuni o tutti |
| **Require PKCE** | Ogni autorizzazione deve inviare un code challenge `S256`. Consigliato e attivo per impostazione predefinita |

Dopo il salvataggio, QRdx mostra il **Client ID** e il **Client secret**. Copia subito il secret: QRdx ne conserva solo un hash e non può mostrartelo di nuovo. Se lo perdi o viene esposto, scegli **Regenerate secret** nella pagina dell'app. Il vecchio secret smette di funzionare subito; le persone già connesse restano connesse. Creare un'app e rigenerarne il secret richiede prima di [confermare la tua identità](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), a meno che tu non l'abbia già fatto in quel browser negli ultimi 10 minuti.

<Shot id="oauth-app-credentials" />

Tieni entrambi i valori sul tuo server:

```bash title=".env"
QRDX_CLIENT_ID=qrdx_app_...
QRDX_CLIENT_SECRET=qrdx_secret_...
```

## 2. Porta le persone su QRdx [#2-send-people-to-qrdx]

Genera uno `state` casuale e un `code_verifier` PKCE, conservali entrambi nella sessione della persona e reindirizza all'URL di autorizzazione:

```txt title="Authorize URL"
https://qrdx.dev/api/oauth/authorize
  ?response_type=code
  &client_id=<client id>
  &redirect_uri=https://acme.example/oauth/qrdx/callback
  &scope=profile:read codes:read codes:write
  &state=<random value>
  &code_challenge=<BASE64URL(SHA256(code_verifier))>
  &code_challenge_method=S256
```

| Parametro | Obbligatorio | Valore |
| --- | --- | --- |
| `response_type` | Sì | `code` |
| `client_id` | Sì | Il client ID della tua app |
| `redirect_uri` | Sì | Uno dei redirect URI dell'app, carattere per carattere |
| `scope` | Sì | Separati da spazi o virgole; solo scope che l'app possiede |
| `state` | Consigliato | Un valore qualsiasi; QRdx lo restituisce invariato. Controllalo al ritorno per prevenire il cross-site request forgery |
| `code_challenge` | Se l'app richiede PKCE | Da 43 a 128 caratteri: lo SHA-256 in base64url del tuo `code_verifier` |
| `code_challenge_method` | No | `S256`, il valore predefinito e l'unico metodo accettato. `plain` viene rifiutato con `invalid_request` |
| `prompt` | No | `consent` mostra la schermata di consenso anche se la persona ha già approvato questi scope |

```ts title="lib/qrdx-oauth.ts"
import { createHash, randomBytes } from "node:crypto";

export const QRDX_AUTHORIZE_URL = "https://qrdx.dev/api/oauth/authorize";

export function createPkce() {
  const verifier = randomBytes(32).toString("base64url"); // 43 characters
  const challenge = createHash("sha256").update(verifier).digest("base64url");
  return { verifier, challenge };
}

export function authorizeUrl({ state, challenge }: { state: string; challenge: string }) {
  const url = new URL(QRDX_AUTHORIZE_URL);
  url.search = new URLSearchParams({
    response_type: "code",
    client_id: process.env.QRDX_CLIENT_ID!,
    redirect_uri: "https://acme.example/oauth/qrdx/callback",
    scope: "profile:read codes:read codes:write",
    state,
    code_challenge: challenge,
    code_challenge_method: "S256",
  }).toString();
  return url.toString();
}
```

Chi non ha effettuato l'accesso a QRdx lo fa prima. Poi vede la schermata di consenso: logo, nome e sito web della tua app, chi l'ha creata, i permessi richiesti e l'account con cui ha effettuato l'accesso. Le app che QRdx non ha verificato riportano la nota **Unverified app.** **Authorize** chiede di [confermare la propria identità](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), a meno che non l'abbia già fatto negli ultimi 10 minuti (vale anche un accesso effettuato pochi istanti prima). Chi ha già approvato gli stessi scope per la tua app torna direttamente da te.

<Shot id="oauth-consent-screen" />

QRdx poi reindirizza al tuo `redirect_uri`:

- Approvato: `?code=<authorization code>&state=<your state>`. Il codice funziona una sola volta, entro 10 minuti.
- Annullato: `?error=access_denied&error_description=...&state=<your state>`.

Le richieste non valide non reindirizzano mai; rispondono con JSON nel formato OAuth 2.0. Un `client_id` sconosciuto genera `invalid_client`, un `redirect_uri` non registrato o una challenge `plain` generano `invalid_request`, e uno scope che l'app non possiede genera `invalid_scope`:

```json title="400 Bad Request"
{"error":"invalid_scope","error_description":"Invalid or unsupported scope"}
```

## 3. Scambia il codice con i token [#3-exchange-the-code-for-tokens]

Dal tuo server, invia il codice all'endpoint dei token. Il corpo è codificato come form e `redirect_uri` deve essere lo stesso usato nel passaggio 2.

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=authorization_code \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d code=$CODE \
  -d redirect_uri=https://acme.example/oauth/qrdx/callback \
  -d code_verifier=$CODE_VERIFIER
```

```ts title="app/oauth/qrdx/callback/route.ts"
export async function GET(req: Request) {
  const params = new URL(req.url).searchParams;
  const session = await getSession(req); // your own session store
  if (params.get("state") !== session.qrdxState) {
    return new Response("Invalid state", { status: 400 });
  }
  if (params.get("error")) {
    return Response.redirect("https://acme.example/settings?qrdx=canceled");
  }

  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "authorization_code",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      code: params.get("code") ?? "",
      redirect_uri: "https://acme.example/oauth/qrdx/callback",
      code_verifier: session.qrdxVerifier,
    }),
  });
  if (!response.ok) {
    const { error, error_description } = await response.json();
    throw new Error(`QRdx token exchange failed: ${error} ${error_description}`);
  }

  const tokens: {
    access_token: string;
    token_type: "Bearer";
    expires_in: number;
    refresh_token: string;
    scope: string;
  } = await response.json();
  await saveQrdxTokens(session.userId, tokens); // encrypt at rest
  return Response.redirect("https://acme.example/settings?qrdx=connected");
}
```

```json title="Response fields"
{
  "access_token": "<send as Authorization: Bearer>",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "<store encrypted; it rotates on each refresh>",
  "scope": "profile:read codes:read codes:write"
}
```

`scope` elenca ciò che è stato concesso, separato da spazi. I token di accesso durano 1 ora e i refresh token 30 giorni. Invia `code_verifier` esattamente quando l'autorizzazione aveva un `code_challenge`; un verifier per un codice emesso senza challenge viene rifiutato. Un secret errato o un codice già usato generano `invalid_client` o `invalid_grant`, e un grant type diverso dai due supportati:

```json title="400 Bad Request"
{"error":"unsupported_grant_type","error_description":"Supported: authorization_code, refresh_token"}
```

## 4. Aggiorna i token [#4-refresh-tokens]

Prima che il token di accesso scada, scambia il refresh token con una nuova coppia. I refresh token ruotano: ciascuno funziona una sola volta, quindi salva ogni volta quello nuovo.

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=refresh_token \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d refresh_token=$REFRESH_TOKEN
```

```ts title="lib/qrdx-oauth.ts"
export async function refreshQrdxTokens(refreshToken: string) {
  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "refresh_token",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      refresh_token: refreshToken,
    }),
  });
  // invalid_grant: revoked, expired or already used. Ask the person to reconnect.
  if (!response.ok) throw new Error((await response.json()).error);
  return response.json();
}
```

L'endpoint dei token consente 30 richieste al minuto per indirizzo IP.

## 5. Chiama l'API [#5-call-the-api]

Invia il token di accesso come Bearer token a `https://api.qrdx.dev/v1`. Le richieste con token agiscono sul workspace personale della persona che ha autorizzato la tua app (ogni account ne ha uno), con il piano e la [quota giornaliera](/docs/developers/rest-api#rate-limits) di quel workspace. Richiedi il minimo indispensabile per la tua integrazione; le persone vedono ogni scope nella schermata di consenso.

| Scope | Consente |
| --- | --- |
| `profile:read` | ID, nome, email e avatar dell'utente: `GET /v1/me` e `GET /api/oauth/userinfo` |
| `themes:read` | I suoi temi QR salvati: `GET /v1/themes`, `GET /v1/themes/{id}` |
| `codes:read` | I suoi QR code dinamici, le analisi delle scansioni e i codici a barre salvati; elenco degli hook |
| `codes:write` | Tutto ciò che consente `codes:read`, più creazione, modifica ed eliminazione di codici e codici a barre, segnalazione delle conversioni e iscrizione agli eventi |

```ts title="lib/qrdx.ts"
const response = await fetch("https://api.qrdx.dev/v1/codes", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${accessToken}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    destinationUrl: "https://acme.example/menu",
    title: "Spring menu",
  }),
});
const { data: code } = await response.json(); // code.shortLink is what the QR encodes
```

Un `401 INVALID_TOKEN` significa che il token è scaduto o è stato revocato: aggiornalo, oppure chiedi alla persona di riconnettersi. Un `403 INSUFFICIENT_SCOPE` significa che al token manca lo scope. Il [riferimento API](/docs/developers/api) elenca ogni endpoint con il relativo scope e gli errori.

## 6. Ricevi eventi con i webhook [#6-receive-events-with-webhooks]

Iscriviti per conto della persona con la REST Hooks API, invece di chiederle di incollare un URL. Serve `codes:write` e il piano della persona deve includere i [webhook](/docs/webhooks) (Business); altrimenti restituisce `402 PLAN_REQUIRED`.

```bash title="Terminal"
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://acme.example/webhooks/qrdx", "events": ["scan.created", "form.submitted"]}'
```

La risposta `201` contiene l'`id` della sottoscrizione e un `secret` di firma, mostrato una sola volta. Ogni consegna è firmata con esso in `X-QRdx-Signature`; vedi [Verifica le firme](/docs/webhooks#verify-signatures). Annulla l'iscrizione con `DELETE /v1/hooks/{id}` quando la persona si disconnette. Le sottoscrizioni compaiono anche in **Settings → Webhooks** del suo workspace, dove può rimuoverle.

## 7. Disconnetti e identifica le persone [#7-disconnect-and-identify-people]

Quando qualcuno disconnette QRdx nel tuo prodotto, revoca i suoi token. Revocare uno dei due token di una coppia revoca l'intera coppia; l'endpoint risponde `200` anche per token sconosciuti.

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/revoke -d token=$REFRESH_TOKEN
```

Le persone possono revocare l'accesso da sole in qualsiasi momento, in **Settings → Authorized apps** su QRdx, con **Revoke access**. Ogni token che la tua app possiede per il loro account smette subito di funzionare: le chiamate API rispondono `401` con `invalid_token` e l'aggiornamento risponde `invalid_grant`. Considera entrambi come "disconnesso" e chiedi di collegarsi di nuovo; vedranno di nuovo la schermata di consenso.

Per identificare chi si è connesso, chiama `GET /api/oauth/userinfo` con un token `profile:read`. Restituisce claim in stile OpenID, `sub`, `name`, `email` e `picture`; usa `sub` come ID stabile dell'account, perché le email possono cambiare.

```bash title="Terminal"
curl https://qrdx.dev/api/oauth/userinfo -H "Authorization: Bearer $ACCESS_TOKEN"
```

```json title="401 Unauthorized: an expired or revoked token"
{"error":"invalid_token","error_description":"Invalid or expired token"}
```

## 8. Fatti inserire nella directory [#8-get-listed]

Quando la tua integrazione funziona da un capo all'altro, chiedi di aggiungerla alla [directory delle integrazioni](/integrations), dove compare come integrazione della community creata da te. Nella pagina della tua app, **Get listed** apre un'email a [support@qrdx.dev](mailto:support@qrdx.dev?subject=List%20my%20integration) con i dettagli già compilati:

- il nome della tua app e il client ID;
- una riga su cosa fa e a chi è rivolta;
- i passaggi di configurazione, o un link a essi;
- un contatto per l'assistenza.

Il team di QRdx esamina le app inserite e le contrassegna come **Verified**, il che rimuove la nota **Unverified app.** dalla schermata di consenso. Modificare nome, logo o sito web di un'app verificata rimuove il badge finché non viene riesaminata.

## Se qualcosa va storto [#if-something-goes-wrong]

### `invalid_request: redirect_uri not registered` [#invalid_request-redirect_uri-not-registered]

Il valore `redirect_uri` nell'URL di autorizzazione non corrisponde carattere per carattere a uno dei redirect URI dell'app, schema e slash finale compresi. Aggiungilo all'app oppure correggi l'URL.

### `invalid_scope` [#invalid_scope]

L'URL di autorizzazione richiede uno scope che l'app non ha. Aggiungi lo scope all'app in **Impostazioni → Chiavi API e app**, poi richiedilo di nuovo.

### `invalid_grant` durante il refresh [#invalid_grant-on-refresh]

Il refresh token è già stato usato (ogni refresh ne restituisce uno nuovo), è scaduto dopo 30 giorni oppure la persona ha revocato la tua app. Fai ripetere l'autorizzazione.

### I token smettono di funzionare dopo aver rigenerato il secret [#tokens-stop-working-after-you-regenerated-the-secret]

Solo le nuove richieste di token usano il nuovo secret; gli access token e i refresh token esistenti restano validi. Controlla che ogni istanza del server legga il nuovo `QRDX_CLIENT_SECRET`.

## Checklist di sicurezza [#security-checklist]

- Tieni il client secret sul tuo server. Il codice del browser e quello mobile non devono mai vederlo.
- Usa PKCE (`S256`) e un `state` nuovo per ogni autorizzazione, e controlla `state` al ritorno.
- Registra redirect URI esatti: QRdx li confronta carattere per carattere.
- Conserva gli access token e i refresh token cifrati, e salva il nuovo refresh token dopo ogni refresh.
- Revoca i token quando le persone si disconnettono. Eliminare la tua app in **Impostazioni → Chiavi API e app** revoca tutti i token che ha emesso; metterla in pausa li rifiuta finché non la riattivi.
