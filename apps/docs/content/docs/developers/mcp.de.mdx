Am Ende dieser Seite kann dein KI-Assistent QR-Codes erstellen: Er gestaltet einen Code für beliebige Inhalte mit geprüftem Scan-Score, rendert ihn in den Stilen des Editors, baut den passenden Payload für Wi-Fi, Kontakte, E-Mail, SMS, Standorte und Banküberweisungen, findet Frames aus der Community und zeichnet Barcodes. Mit einem API-Schlüssel an der Verbindung kann er außerdem Designs und Barcodes in deinem Workspace speichern und KI-Kunst malen.

QRdx betreibt einen öffentlichen [Model Context Protocol](https://modelcontextprotocol.io)-Server unter:

```txt title="Server URL"
https://mcp.qrdx.dev/mcp
```

Er nutzt den Streamable-HTTP-Transport, speichert keinen Sitzungsstatus und braucht weder Konto noch Anmeldung noch API-Schlüssel. Derselbe Server antwortet auch unter `https://qrdx.dev/api/mcp`. Auf der [Verbindungsseite](/mcp) findest du One-Click-Buttons und Anleitungen für mehr Clients, als diese Seite zeigt.

[Im Playground ausprobieren](/playground?open=code&lang=mcp): Gestalte dort einen Code und kopiere ihn dann als `design_qr`-Argumente für deinen Assistenten.

## 2. Nach einem Code fragen [#2-ask-for-a-code]

Frag dann einfach in normalen Worten. Diese Prompts funktionieren genau so:

```txt title="Prompts"
Make a QR code for https://example.com in our brand blue, #155dfc, with rounded modules.
Create a Wi-Fi QR code for the network Office Guest with password correct-horse-battery.
Design a Wi-Fi QR code for Cafe Guest in warm browns with a Free Wi-Fi banner, and tell me its scan score.
Generate a contact QR code for Ada Lovelace, ada@example.com, and add it to the README.
Find a community frame for a restaurant menu and use it for https://example.com/menu.
Draw an EAN-13 barcode for 590123412345 as a PNG.
```

Beim ersten Prompt ruft der Assistent `generate_qr_code` auf und erhält das PNG und diese Zeilen, die du direkt einfügen kannst:

```txt title="generate_qr_code result"
QR code, 512x512px, error correction Q.
SVG URL: https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&fg=155dfc&body=rounded
PNG URL: https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=png&fg=155dfc&body=rounded
WebP URL (lossless, smaller than PNG): https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=webp&fg=155dfc&body=rounded
EPS URL (vector, for print; 512 pt wide): https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=eps&fg=155dfc&body=rounded
Markdown: ![QR code](https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&fg=155dfc&body=rounded)
```

Beim zweiten ruft er `qr_payload_wifi` auf, das `WIFI:T:WPA;S:Office Guest;P:correct-horse-battery;;` zurückgibt, und übergibt diesen String als `data` an `generate_qr_code` oder als Inhalt von `design_qr`.

## Tools [#tools]

| Tool | Was es macht |
| --- | --- |
| `design_qr` | Gestaltet einen Code für jeden Inhaltstyp mit dem Stil, den dein Assistent wählt, oder ausgehend von einem integrierten Theme oder einem Community-Element, prüft den Scan-Score und repariert den Stil, bis er „Great“ erreicht. Gibt den Score, die vorgenommenen Änderungen, das Stil-JSON, einen Playground-Link, ein PNG und das SVG zurück |
| `list_options` | Listet jeden Wert auf, den `design_qr` akzeptiert: Inhaltstypen und ihre Felder, Farben und Verläufe, Formen, Rahmen (mit den IDs der offiziellen QRdx-Rahmen), Ränder, Logo-Icons und Markenlogos, integrierte Themes, Fehlerkorrekturstufen und Limits |
| `generate_qr_code` | Rendert einen QR-Code mit den Stilen des Editors. Gibt ein PNG-Bild und öffentliche [Image-API](/docs/developers/image-api)-URLs (SVG, PNG, verlustfreies WebP und Vektor-EPS) zurück, bereit für Markdown, HTML oder Druck, auf Wunsch zusätzlich das SVG-Markup |
| `list_qr_styles` | Listet Körpermuster, Formen von Eckaugen und Augenpunkten, Rahmen (die integrierten Stile und die als Vorlagen gezeichneten), Logo-Icons, Fehlerkorrekturstufen, Standardwerte und Limits auf |
| `search_community` | Findet veröffentlichte Rahmen, Themes und Sammlungen der [Community](/community) nach Wörtern, Typ oder Tag |
| `get_community_item` | Ein Community-Element mit dem Stil, den es anwendet, bereit für `design_qr` oder `generate_qr_code` |
| `save_template` | Speichert ein Design als Theme in deinem Workspace. Erfordert einen [API-Schlüssel](#use-an-api-key) |
| `generate_barcode` | Zeichnet einen EAN-13-, UPC-A-, UPC-E-, EAN-8-, ITF-14-, GS1-128-, Code-128-, Code-39-, Data-Matrix-, PDF417- oder Aztec-Barcode, nachdem der Wert geprüft wurde (Prüfziffern, Längen, Zeichen). Gibt ein PNG und öffentliche [Barcode-API](/docs/developers/barcode-api)-URLs zurück |
| `save_barcode` | Speichert einen Barcode in den Barcodes deines Workspace. Erfordert einen [API-Schlüssel](#use-an-api-key) |
| `generate_ai_art` | Malt einen QR-Code in KI-Kunst und prüft, ob er sich scannen lässt. Verbraucht eines der monatlichen KI-Kunst-Bilder des Workspace und dauert bis zu eine Minute. Erfordert einen [API-Schlüssel](#use-an-api-key). Siehe [KI-Kunst-API](/docs/developers/ai-art-api) |
| `qr_payload_wifi` | Erstellt einen `WIFI:`-Netzwerk-Payload (WPA, WEP oder offen, optional versteckt) mit maskierten Sonderzeichen |
| `qr_payload_vcard` | Erstellt einen vCard-3.0-Kontakt (RFC 2426): Name, Organisation, Titel, Telefonnummern, E-Mail, Website, Adresse und Notiz |
| `qr_payload_email` | Erstellt einen `mailto:`-Link (RFC 6068) mit optionalen Feldern für cc, bcc, Betreff und Text |
| `qr_payload_sms` | Erstellt einen `sms:`-Link (RFC 5724) mit optionaler Nachricht oder in der älteren `SMSTO:`-Form |
| `qr_payload_geo` | Erstellt einen `geo:`-Standort (RFC 5870) aus Breiten- und Längengrad |
| `qr_payload_payment` | Erstellt einen Bank-Zahlungscode: einen Pix BR Code, eine SEPA-Überweisung (EPC069-12) oder einen PayNow-, PromptPay- oder VietQR-Code (EMV, mit CRC). Die Felder werden so geprüft wie in den Formularen des Playground |

Die Payload-Tools geben einen einfachen String zurück. Dein Assistent übergibt ihn dann als `data` an `generate_qr_code`.

### design_qr [#design_qr]

`design_qr` nimmt den Inhalt als Typ mit seinen Feldern entgegen, mit denselben Typen und Prüfungen wie die Inhaltsformulare des Editors (`list_options` listet sie auf), und optional einen Stil:

```json title="design_qr arguments"
{
  "content": { "type": "wifi", "ssid": "Cafe Guest", "password": "sunshine123", "encryption": "WPA" },
  "style": {
    "bgColor": "#FFF7ED",
    "fgColor": "#9A3412",
    "bodyPattern": "rounded",
    "cornerEyePattern": "rounded",
    "frame": { "style": "banner-bottom", "text": "Free Wi-Fi" }
  }
}
```

```txt title="design_qr result (first lines)"
Scan score 85/100 (great). No changes were needed. Content: WiFi · Cafe Guest (47 bytes). Open it in the playground: https://qrdx.dev/playground?style=1.eyJiIjoiI0ZGRjdFRCIs…&ref=mcp
```

Das JSON des Ergebnisses enthält `payload` (den exakten String, den der Code kodiert), `style`, `qrdxStyle`, `score`, `grade`, `stillFailing` (Prüfungen, die weiterhin fehlschlagen, jeweils mit einer Lösung), `repairs`, `changes` und `playgroundUrl`, gefolgt vom PNG und vom SVG.

Optionen, die du weglässt, bekommen Standardwerte (Augen folgen der Punktfarbe, eckige Formen, Rand 4, Fehlerkorrektur Q, kein Rahmen). Danach führt QRdx die Scan-Prüfung des Editors für das Design aus: Es rendert den Code, dekodiert ihn bei 96, 160 und 320 px über ein Smartphone-Kameramodell und prüft Kontrast, Ruhezone, Augenformen und Formpaare. Liegt der Score unter Great (85), repariert es den Stil bis zu dreimal und ändert dabei so wenig wie möglich (dunklere Farben, die ihren Farbton behalten, eine sicherere Augenform, weniger Fehlerkorrektur bei langen Inhalten). Reicht das nicht aus, greift es auf einen klassischen schwarz-weißen Code mit deinem Rahmen zurück. Das Ergebnis nennt, was geändert wurde und warum.

Bei `design_qr` läuft auf der Seite von QRdx kein KI-Modell: Dein Assistent wählt den Stil, QRdx validiert, prüft und repariert ihn. Ungültige Inhalte (ein WPA-Passwort mit weniger als 8 Zeichen, eine fehlerhafte E-Mail-Adresse) werden mit Begründung abgelehnt. `design_qr` hat ein eigenes Limit von {facts.designQrPerMinute} Aufrufen pro Minute und IP-Adresse.

Weitere Eingaben:

- **`preset`**: Starte mit einem integrierten Theme per ID (`list_options` listet sie auf). Stiloptionen, die du setzt, haben Vorrang.
- **`community_item`**: Starte mit einem Community-Rahmen oder -Theme per ID, zum Beispiel `frame:wifi-card`. Ein Rahmen-Element sitzt auf einem klassischen Code; deine Stiloptionen verändern den Code darunter. Die offiziellen Rahmen von QRdx sind ebenfalls Community-Elemente, daher funktionieren hier auch `frame:diwali-diya` oder `frame:menu-cutlery`.
- **Ein eigener Rahmen**: `style.frame` kann `{ "style": "custom", "spec": … }` mit einer Rahmenspezifikation sein, zum Beispiel der eines Community-Rahmens aus `get_community_item`. Er wird so gezeichnet und bewertet, wie er ist; Reparaturen ändern den Code, nie den Rahmen.
- **`style.logo`**: ein schnelles Logo-Icon (`wifi`, `location`, `phone`, `email`, `link`, `file`, `calendar`, `whatsapp` oder `instagram`) oder ein Markenlogo über seinen [Simple Icons](https://simpleicons.org)-Slug (`spotify`, `paypal:white`). `list_options` listet die beliebten Marken-Slugs auf.
- **Engine-Optionen**: `style.eyeColors` (Farben pro Auge als `#RRGGBB`), `moduleScale` (Punktgröße, `0.5` bis `1`), `shape` (`circle` für einen runden Code), `autoLevel` und `logoOptions` (Größe, Freiraum, Position, Zuschnitt und Unterlage des Logos). Sie werden so gezeichnet und bewertet, wie du sie angibst; Reparaturen ändern sie nicht.

<IfAvailable feature="fileStorage">
`logo_file_id` zeichnet stattdessen ein Logo, das du zu QRdx hochgeladen hast, mit einem [API-Schlüssel](#use-an-api-key).
</IfAvailable>

Logos werden wie im Editor nach den Modulen bewertet, die sie abdecken. Deshalb kann eine Reparatur die Fehlerkorrektur auf H erhöhen oder das Logo entfernen. Die QRdx-Marke, die der Editor standardmäßig zeigt, wird hier nicht gezeichnet.

`qrdxStyle` im Ergebnis ist das Design als Stil-JSON des Editors. Übergib es an `save_template`, an `generate_qr_code` als `style`, um dasselbe Design in einer anderen Größe zu rendern, oder an den [`style`](/docs/developers/image-api#style)-Parameter der Image API. `playground_url` öffnet das Design im [Playground](/playground): Sie enthält nur den Stil, nie das Logo oder den Inhalt, und `playgroundLeftOut` nennt, was weggelassen wird.

### generate_qr_code [#generate_qr_code]

Die Eingaben entsprechen den [Parametern der Image API](/docs/developers/image-api#parameters): `data` (erforderlich), `size`, `fg`, `bg`, `eyeColor`, `dotColor`, `body`, `eye`, `dot`, `level`, `margin`, `template`, `frame`, `frameText`, `logoIcon`, `logoFileId`, `item` (eine Community-Element-ID) und `style` (das Stil-JSON des Editors: Verläufe, eigene Rahmen und der Rest, so wie `design_qr` es zurückgibt). Die einzelnen Optionen haben Vorrang vor `style`, und `style` hat Vorrang vor `item`. Setze `include_svg` auf `true`, um das SVG-Markup zusätzlich als Text zu erhalten, zum Beispiel um eine `.svg`-Datei zu speichern. Standardmäßig ist das aus, weil das Markup oft 50 bis 150 KB groß ist und die Unterhaltung füllen würde.

`generate_qr_code` prüft den Scan-Score nicht; nutze dafür `design_qr`. Ein Code mit deinem hochgeladenen Logo hat keine öffentliche Bild-URL, da die Image API dieses Logo nur für Anfragen mit deinem Schlüssel zeichnet.

### Die QR-Karte [#qr-card]

In Apps, die [MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview) unterstützen, zeigen `design_qr` und `generate_qr_code` zusätzlich eine QR-Karte im Chat. Sie enthält den Code, was er kodiert (ein Wi-Fi-Code zeigt seinen Netzwerknamen, nie das Passwort), die Größe und Fehlerkorrektur oder den Scan-Score sowie eine Schaltfläche **Im Editor öffnen**. Der Editor-Link enthält wie `playground_url` nur den Stil.

Die Schaltflächen PNG und SVG hängen davon ab, was die App erlaubt. Wo sie Dateien aus einer Karte speichern kann, speichern sie diese. Andernfalls öffnen sie die URL der Image API in deinem Browser, deshalb zeigt die Karte von `design_qr` sie nur in Apps, die Dateien speichern: Sein Inhalt landet nie in einer Bild-URL. Apps können dich um Bestätigung bitten, bevor ein Link geöffnet wird.

Apps ohne MCP Apps erhalten wie bisher denselben Text und dasselbe Bild. Für Client-Entwickler:

- Die Karte ist die Ressource `ui://qrdx/qr-card` (`text/html;profile=mcp-app`), aufgelistet von `resources/list`. Beide Tools verweisen mit `_meta.ui.resourceUri` darauf.
- Ihre Daten kommen im `_meta` des Tool-Ergebnisses unter `dev.qrdx/qr-card`, das für die Karte gedacht ist und nicht für das Modell. Die Tools geben kein `structuredContent` zurück.
- Die Karte ist eine einzelne HTML-Datei mit eingebetteten Styles und Skript. Das Einzige, was sie lädt, ist das Bild des Codes von der Image API (`https://api.qrdx.dev` oder deine eigene Domain bei Self-Hosting), und ihre Content Security Policy (`_meta.ui.csp.resourceDomains`) erlaubt diesen Host und sonst keinen.

Wenn du QRdx verbunden hast, bevor es die Karte gab, entferne den Connector und füge ihn erneut hinzu oder aktualisiere seine Tools, damit die App die neuen Tool-Metadaten übernimmt.

### Community [#community]

`search_community` findet veröffentlichte Rahmen, Themes und Sammlungen der [Community](/community), kostenlos unter CC0, nach Wörtern (`q`), `type` und `tag`. `get_community_item` gibt ein Element mit dem Stil zurück, den es anwendet; übergib seine ID an `design_qr` als `community_item` oder an `generate_qr_code` als `item`. Dieselben Daten gibt es in der REST API unter [`/v1/community/items`](/docs/developers/api/list-community-items).

Die Texte der Elemente stammen von Community-Mitgliedern. Namen, Beschreibungen, Handles, Tags und Rahmenbeschriftungen kommen gekürzt, einzeilig und ohne Links, E-Mail-Adressen oder Markup zurück, und jedes Ergebnis weist darauf hin, sie als Daten zu behandeln, nicht als Anweisungen.

## API-Schlüssel verwenden [#use-an-api-key]

Einige Tools brauchen für die Verbindung einen QRdx-[API-Schlüssel](/docs/developers/api-keys), der als `Authorization: Bearer qrdx_…` gesendet wird:

- **`save_template`** speichert ein Design als Theme, das im Dashboard unter Themes aufgelistet und im Editor angeboten wird. Dafür brauchst du einen Schlüssel mit `codes:write`, den **Vollzugriff**-Schlüssel haben. Ein Schlüssel deines eigenen Workspace speichert in deine Themes; ein Team-Schlüssel speichert in die gemeinsamen Themes des Teams, wenn sein Ersteller Owner oder Admin ist und der Plan Team-Themes enthält. Gespeicherte Themes zählen zum Limit des Plans (siehe [Pläne und Limits](/docs/plans-and-limits)); wird es überschritten, gibt das Tool den API-Fehler `LIMIT_REACHED` (`402`) zurück.
- **`save_barcode`** speichert einen Barcode (Format, Wert, optional ein Titel und Zeichenoptionen) im Workspace des Schlüssels, aufgelistet im Dashboard unter Barcodes. Dafür brauchst du einen Schlüssel mit `codes:write`. Jeder Plan kann Barcodes speichern, im Plan Kostenlos bis zu 1.000; bei Überschreitung des Limits wird `LIMIT_REACHED` (`402`) zurückgegeben.
- **`generate_ai_art`** malt einen QR-Code in ein KI-Kunstwerk, ausgehend von einem Link, Text oder einem dynamischen QR-Code über seine ID, und gibt das PNG zurück, sobald QRdx geprüft hat, dass es sich scannen lässt. Es nimmt dieselben Felder wie [`POST /v1/art`](/docs/developers/ai-art-api) und braucht einen Schlüssel mit `codes:write`. Jedes Bild verbraucht eines der monatlichen KI-Art-Bilder des Workspace des Schlüssels, und ein Aufruf dauert bis zu einer Minute.
<IfAvailable feature="fileStorage">
- **Hochgeladene Logos** unter [Dashboard → Dateien](/docs/files), über die Datei-ID (`logo_file_id` in `design_qr`, `logoFileId` in `generate_qr_code`): ein PNG oder JPEG bis 1 MB. Der Schlüssel muss zum Workspace gehören, dem die Datei gehört.
</IfAvailable>

Ohne Schlüssel antworten diese Tools mit einer Anleitung, wie du ihn hinzufügst:

```txt title="save_template without a key"

```

## Wenn etwas schiefgeht [#if-something-goes-wrong]

### Der Client kann keine Verbindung herstellen [#the-client-cant-connect]

Prüfe, ob die URL genau `https://mcp.qrdx.dev/mcp` lautet und der Transport HTTP (Streamable HTTP) ist, nicht SSE oder stdio. Clients, die nur lokale Server ausführen, brauchen die oben beschriebene `mcp-remote`-Bridge. Wenn du die URL im Browser öffnest, wirst du auf die Verbindungsseite weitergeleitet. Das ist so gewollt: MCP-Clients fragen nie nach HTML.

### Der Assistent sagt, ein Tool braucht einen API-Schlüssel [#the-assistant-says-a-tool-needs-an-api-key]

`save_template`, `save_barcode`, `generate_ai_art` und hochgeladene Logos brauchen `Authorization: Bearer qrdx_…` für die Verbindung. Füge den Header wie oben gezeigt hinzu und verbinde dich neu.

### `design_qr` lehnt den Inhalt ab [#design_qr-refuses-the-content]

Der Inhalt hat dieselben Prüfungen nicht bestanden wie die Formulare des Editors: ein WPA-Passwort mit weniger als 8 Zeichen, eine fehlerhafte E-Mail-Adresse, ein Zahlungsfeld außerhalb des Bereichs. Den Grund findest du in der Antwort; `list_options` listet die Felder und Regeln jedes Inhaltstyps auf.

### Zu viele Anfragen [#too-many-requests]

Der Server erlaubt {facts.mcpPerMinute} Anfragen pro Minute und IP-Adresse, bei `design_qr` {facts.designQrPerMinute}. Mit Schlüssel ist `save_template` zusätzlich auf 30 pro Minute und Nutzer begrenzt. Warte eine Minute und versuche es erneut.

## Datenschutz und Limits [#privacy-and-limits]

- Die Tools rendern Bilder, prüfen Designs, formatieren Text und lesen die öffentliche Community. Nur `save_template` und `save_barcode` schreiben etwas: das Theme oder den Barcode, den du speichern lässt, im Workspace des API-Schlüssels. `generate_ai_art` verbraucht eines der monatlichen KI-Art-Bilder des Workspace und speichert weder das Bild noch ein Foto, das du sendest. Der Server speichert die QR-Codes, die du generierst, nicht.
- Die Bild-URLs, die `generate_qr_code` und `generate_barcode` zurückgeben, enthalten die codierten Daten. Teile sie nicht, wenn die Daten privat sind, etwa ein Wi-Fi-Passwort.
- Anfragen sind auf {facts.mcpPerMinute} pro Minute und IP-Adresse begrenzt, `design_qr` auf {facts.designQrPerMinute}.

## Self-Hosting und lokale Entwicklung [#self-hosting-and-local-development]

Der MCP-Server ist Teil der QRdx-Web-App, daher stellt jede Instanz ihn unter `/api/mcp` bereit:

- **Self-Hosting.** Wenn `NEXT_PUBLIC_APP_URL` deine eigene Domain ist, verwenden die Verbindungsseite, die Snippets und die Installationslinks `https://<your-domain>/api/mcp`.
- **Lokale Entwicklung.** `bun run dev` stellt ihn unter `http://localhost:3000/api/mcp` bereit. Die Verbindungsseite zeigt weiterhin die öffentliche URL und bietet die lokale als Hinweis an, sodass du einen Client auf deinen Rechner richten kannst, um Änderungen am Server vor der Veröffentlichung zu testen.
