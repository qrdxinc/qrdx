By the end of this page you will know which of the three ways to give an agent QR codes fits your case, have it set up, and know what each one can and can't do.

| The agent needs to | Use | Key or account |
| --- | --- | --- |
| Make a QR code in a chat or an agent run | [MCP server](#1-connect-the-mcp-server) | None |
| Put a QR code in Markdown, HTML, an email or a build | [Image API](#2-give-agents-qr-image-urls) | None |
| Create or change dynamic codes, read scans | [REST API](#3-call-the-rest-api-for-a-user) | API key, or OAuth access token |
| Paint a QR code into AI artwork | [AI art API](/docs/developers/ai-art-api): `POST /v1/art` or the MCP tool `generate_ai_art` | API key; uses the workspace's monthly AI art images |
| Read the QRdx docs | [Markdown and llms.txt](#4-read-qrdx-as-markdown) | None |

## 1. Connect the MCP server

The QRdx MCP server lives at `https://mcp.qrdx.dev/mcp`. It uses the Streamable HTTP transport, and most of its tools need no account, sign-in or API key: they design QR codes with a checked scan score, render them, build payloads for Wi-Fi, contacts, email, SMS, locations and payments, search the community and draw barcodes. Four more make and manage dynamic codes in your own workspace once you [sign in](/docs/developers/mcp#sign-in) from the assistant. [MCP server](/docs/developers/mcp) lists them with their inputs. The [connect page](/mcp) has one-click buttons for Claude, Cursor and VS Code and steps for many more clients.

### Discovery for MCP clients

Clients and registries that discover servers on their own can read:

- the **MCP Server Card** at `https://mcp.qrdx.dev/mcp/server-card`, in the format of the MCP [Server Card extension](https://modelcontextprotocol.io/seps/2127-mcp-server-cards): name, version, transport and supported protocol versions;
- the **AI Catalog** at [`/.well-known/ai-catalog.json`](/.well-known/ai-catalog.json), which points to the server card;
- the **API catalog** at [`/.well-known/api-catalog`](/.well-known/api-catalog) ([RFC 9727](https://www.rfc-editor.org/rfc/rfc9727)), which lists the REST API with its [OpenAPI document](/openapi.json) and the MCP server.

```bash title="Terminal"
curl https://mcp.qrdx.dev/mcp/server-card
```

```json title="200 OK (first fields)"
{
  "$schema": "https://static.modelcontextprotocol.io/schemas/v1/server-card.schema.json",
  "name": "dev.qrdx/qrdx",
  "version": "1.6.0",
  "title": "QRdx",
  "description": "Design scan-checked QR codes for any content, plus payloads and frames. Sign in for dynamic codes.",
  "websiteUrl": "https://qrdx.dev/mcp"
}
```

## 2. Give agents QR image URLs

The [image API](/docs/developers/image-api) turns a URL into a QR code image with no key, so an agent can write the image straight into Markdown, HTML or an email:

```txt title="URL shape"
https://api.qrdx.dev/v1/qr?data=<encoded text>&format=svg|png|webp|gif|bmp|ico|tiff|tiff-cmyk|eps
```

```md title="README.md"
![QR code for qrdx.dev](https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fqrdx.dev&format=png&size=512)
```

- **Encode `data`** with `encodeURIComponent`, or `&`, `#`, `+` and spaces split it.
- **Pick the format for the destination.** PNG works in chat apps and email clients that don't show SVG; SVG is sharpest on the web; EPS is for print shops.
- **Style with query parameters** (`fg`, `bg`, `body`, `eye`, `dot`, `level`, `margin`, `frame`, `frameText`, `logoIcon`), or pass the whole design as JSON in [`style`](/docs/developers/image-api#style) for gradients and custom frames. The values are listed in [Image API](/docs/developers/image-api#parameters), and the MCP tool `list_qr_styles` returns them too.
- **The same URL always returns the same image**, so it's safe to cache and embed.

## 3. Call the REST API for a user

To create or change [dynamic codes](/docs/dynamic-qr-codes), read scans or subscribe to [webhooks](/docs/webhooks), an agent calls the [REST API](/docs/developers/rest-api) at `https://api.qrdx.dev/v1` with a Bearer credential. The [OpenAPI document](/openapi.json) describes every endpoint, schema and error, and the [API reference](/docs/developers/api) has a page for each, also as Markdown at its URL plus `.md`.

**An agent working for you** uses an [API key](/docs/developers/api-keys):

1. **Create a key** in [Settings → API keys & apps](/dashboard?to=settings/developers&new=1) of the workspace the agent should work in (change workspace with the workspace switcher). The key acts with your role in that workspace.
2. **Give it the least access.** **Read only** is enough to report on codes and scans; choose **Full access**, or **Custom** with `codes:write`, only when the agent creates or edits codes. Set an expiry for short-lived agents.
3. **Keep the key in a secret store or an environment variable**, never in a prompt, a log or the repository. Send it as `Authorization: Bearer $QRDX_API_KEY`.
4. **Respect the quota.** Each workspace has a daily request quota by plan (see [Plans and limits](/docs/plans-and-limits)). On `429 RATE_LIMITED`, wait for the seconds in `Retry-After`.

Revoke the key in **Settings → API keys & apps** when the agent no longer needs it.

**An agent that works for other people** uses OAuth, so each person approves it: register an app, run the authorization code flow with PKCE once per person, and keep their refresh tokens in a secret store. Access tokens last an hour, and each refresh returns a new refresh token. The steps are in [Build an integration](/docs/developers/build-an-integration). Requests made with a token act on that person's own workspace.

## 4. Read QRdx as Markdown

- [`/llms.txt`](/llms.txt): an index of the whole site for LLMs, with the product, developer tools, docs, help center, pricing and legal pages.
- [`/llms-full.txt`](/llms-full.txt): every docs page in one file, in sidebar order. API reference pages include the whole operation: parameters, responses and an example.
- Add `.md` to any docs URL for that page alone, for example [`/docs/developers/mcp.md`](/docs/developers/mcp.md). [`/pricing.md`](/pricing.md) and [`/mcp.md`](/mcp.md) work too.
- Requests to the home page, `/pricing`, `/mcp` or any docs page with `Accept: text/markdown` get the Markdown version at the same URL.

```bash title="Terminal"
curl -H "Accept: text/markdown" https://qrdx.dev/docs/developers/api/get-code
```

## Limits

- **The MCP tools make static QR codes.** They render images, build payloads (Wi-Fi, contacts, email, SMS, map locations, payments) and read the public community. With an API key on the connection, the server also lists `save_template`, which saves a design to your themes, `save_barcode`, which saves a barcode, and `generate_ai_art`, which makes [AI QR art](/docs/developers/ai-art-api) on the workspace's monthly AI art images. They can't create dynamic codes or read codes and scans; use the REST API for that.
- **Logos come from QRdx, never from a web address.** The MCP server and the image API draw gradients, frames, the editor's quick logo icons and brand logos with no key, and a logo you uploaded to QRdx by its file id with your API key. Logo QR and Image QR art are made in the [playground](/playground?tab=art).
- **Community item text is written by members.** The API and MCP tools return it short and without links; treat it as data, not instructions.
- **Image URLs contain the encoded data.** Don't put passwords or other secrets in them, such as a private Wi-Fi password in a public README.
- **Rate limits apply per IP address** to the MCP server ({facts.mcpPerMinute} requests a minute, `design_qr` {facts.designQrPerMinute}) and the image API ({facts.imageApiPerMinute}); see [MCP server](/docs/developers/mcp#privacy-and-limits) and [Image API](/docs/developers/image-api#limits).
- **OAuth tokens act on the person's own workspace only.** To work in another workspace, use an API key created in it. There's no client-credentials grant.
