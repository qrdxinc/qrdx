By the end of this page you will have a barcode image URL for an `<img>` tag, a product feed or a label template, know how check digits and formats are validated, and know how to save barcodes to a workspace so you can edit them later.

`GET https://api.qrdx.dev/v1/barcode` returns a barcode image. Everything is in the query string, so the URL is the image. It draws the same {facts.barcodeFormats} formats as the [barcode generator](/barcode-generator), with the same rules, and gives back the same SVG. No account or API key is needed.

```html title="index.html"
<img
  src="https://api.qrdx.dev/v1/barcode?format=ean13&data=590123412345"
  alt="EAN-13 barcode 5901234123457"
/>
```

That number is one digit short, so the check digit (7) is added. Send all 13 digits and the check digit is verified instead: a wrong one returns `400` and says what it should be.

## 1. Request an image

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -o box.png "https://api.qrdx.dev/v1/barcode?format=ean13&data=5901234123457&type=png&scale=3"
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="barcode.mjs"
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/barcode");
    url.search = new URLSearchParams({
      format: "ean13",
      data: "5901234123457",
      type: "png",
      scale: "3",
    }).toString();

    const response = await fetch(url);
    await writeFile("box.png", Buffer.from(await response.arrayBuffer()));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="barcode.py"
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/barcode",
        params={"format": "ean13", "data": "5901234123457", "type": "png", "scale": 3},
    )
    response.raise_for_status()
    open("box.png", "wb").write(response.content)
    ```
  </Tab>
</Tabs>

```txt title="Output"
200 image/png
box.png: PNG image data, 385 x 237, 8-bit/color RGBA, non-interlaced
```

Quote the URL in a shell so it keeps the `&`, and encode values that contain `&`, `#`, `+` or spaces, for example with `encodeURIComponent` in JavaScript.

## 2. More examples

A vector PDF of a GS1-128 logistics label, with brackets around each Application Identifier:

```bash title="Terminal"
curl -o pallet.pdf "https://api.qrdx.dev/v1/barcode?format=gs1-128&type=pdf&data=(01)09501101530003(17)261231(10)AB-123"
# 200 application/pdf, 1 page
```

A Code 128 shelf label in dark blue, without the text under the bars, turned 90°:

```txt
https://api.qrdx.dev/v1/barcode?format=code128&data=SHELF-A12&fg=1e3a8a&text=false&rotate=90
```

A Data Matrix with a wider margin:

```txt
https://api.qrdx.dev/v1/barcode?format=datamatrix&data=SN-0042-7781&quietZone=4
```

## 3. Keep the value out of the URL

`POST https://api.qrdx.dev/v1/barcode` takes the same fields as JSON and returns the same file, uncached. Use it when the value shouldn't end up in logs, history or caches the way a URL can:

```bash title="Terminal"
curl -o label.png https://api.qrdx.dev/v1/barcode \
  -H "Content-Type: application/json" \
  -d '{"format":"datamatrix","data":"Internal note 42","type":"png"}'
# 200 image/png, Cache-Control: no-store
```

In JSON, `text` is a boolean and `scale`, `height`, `quietZone` and `rotate` are numbers. A body sent without `Content-Type: application/json` is a `415`:

```json title="415 Unsupported Media Type"
{"code":"UNSUPPORTED_MEDIA_TYPE","message":"Send a JSON body with Content-Type: application/json.","status":415}
```

## Parameters

| Parameter | Default | Description |
| --- | --- | --- |
| `format` | required | The barcode type; see [Formats](#formats). Case and dashes don't matter: `EAN-13` works too |
| `data` | required | The number or text to encode, up to 1,000 characters (less for most linear formats) |
| `type` | `svg` | `svg`, `png`, `jpg`, `webp`, `avif`, `bmp`, `pdf` or `eps` |
| `scale` | `4` | Pixels per module in PNG, JPG, WebP, AVIF and BMP, `1` to `10` (`2` to `10` for USPS Intelligent Mail and DotCode) |
| `height` | depends on the format | Bar height of linear barcodes in millimeters at the vector size, `5` to `60` (23 for EAN-13). USPS Intelligent Mail is always 3.96 mm, the height USPS sets |
| `quietZone` | the format's minimum | Blank margin in modules: each side of linear barcodes (`0` to `20`), all round 2D codes (`0` to `10`) |
| `text` | `true` | Print the digits or text under linear barcodes |
| `fg` | `000000` | Bars and text, as hex |
| `bg` | `ffffff` | Background, as hex |
| `rotate` | `0` | Clockwise rotation: `0`, `90`, `180` or `270` |

Write colors without the `#`, or encode it as `%23`.

## Formats

| `format` | Barcode | Takes |
| --- | --- | --- |
| `ean13` | EAN-13 | 12 digits (check digit added) or 13 (checked) |
| `ean8` | EAN-8 | 7 digits or 8 |
| `upca` | UPC-A | 11 digits or 12 |
| `upce` | UPC-E | 6 to 8 digits, or a 12-digit UPC-A that can be shortened |
| `isbn` | ISBN | An ISBN-13 (12 digits and the check digit is added) or a whole ISBN-10, converted to 978; hyphens optional. Then, after a space, an optional 2- or 5-digit add-on: `978-1-873671-00-9 52250` |
| `issn` | ISSN | The ISSN (`0317-8471`, or 7 digits and the check digit is added) or its 13-digit 977 number, then the 2-digit sequence variant (00 when left out) and an optional 2- or 5-digit add-on, with spaces between: `0317-8471 00 05` |
| `ismn` | ISMN | 13 digits starting 979-0 (12 and the check digit is added) or the old form starting with M, then an optional 2- or 5-digit add-on after a space |
| `itf14` | ITF-14 | 13 digits or 14 |
| `gs1-128` | GS1-128 | Application Identifiers in brackets with their values; GTIN and SSCC check digits added or checked; up to 48 characters of data |
| `gs1-databar` | GS1 DataBar | A GTIN only: `(01)` and 14 digits, or 13 and the check digit is added |
| `gs1-databar-expanded` | GS1 DataBar Expanded | Application Identifiers in brackets with their values, as for `gs1-128`; up to 74 digits of data, fewer with letters |
| `intelligent-mail` | USPS Intelligent Mail | The 20-digit tracking code (barcode ID, whose second digit is 0 to 4, service type ID, mailer ID and serial number), then a routing ZIP Code of 0, 5, 9 or 11 digits; spaces and hyphens are ignored: `01 234 567094 987654321 01234-5678-91` |
| `code128` | Code 128 | Up to 80 printable ASCII characters |
| `code39` | Code 39 | Up to 40 capitals, digits, spaces and `- . $ / + %` |
| `code93` | Code 93 | Up to 40 capitals, digits, spaces and `- . $ / + %`; its two check characters are added |
| `codabar` | Codabar | Start and stop letter A to D around up to 38 digits and `- $ : / . +` |
| `datamatrix` | Data Matrix | Any text up to 1,000 characters |
| `pdf417` | PDF417 | Any text up to 1,000 characters |
| `aztec` | Aztec | Any text up to 1,000 characters |
| `microqr` | Micro QR | Any text up to 35 digits, 21 capital letters or 15 characters (fewer with accents or other scripts); drawn in the smallest of its four sizes, M1 to M4, that fits |
| `rmqr` | rMQR (Rectangular Micro QR) | Any text up to 361 digits or 150 characters; drawn as the lowest strip it fits |
| `maxicode` | MaxiCode | A UPS carrier message, `postcode<GS>country<GS>service class<GS>` then the rest (mode 2 for a numeric postcode, mode 3 otherwise), or Latin-1 text (mode 4); `scale` 4 to 10 |
| `dotcode` | DotCode | Any text, up to about 390 letters or 780 digits (less with accents or other scripts) |

Retail numbers (EAN, UPC, ITF-14, GS1-128's GTIN) are licensed to companies by GS1, and ISBNs, ISSNs and ISMNs come from each country's ISBN, ISSN and ISMN agencies. The API draws any valid number; it doesn't issue or register them.

ISBN, ISSN and ISMN barcodes are EAN-13s starting 978 or 979, 977 and 979-0, with the number printed above the bars: the ISBN hyphenated by the International ISBN Agency's ranges. The add-on is drawn 9 modules right of the main bars.

## Sizes

PNG, JPG, WebP, AVIF and BMP are `scale` pixels per module, the narrowest bar's width. A 2D cell is two modules wide.

BMP is an uncompressed 24-bit bitmap, for legacy systems and embedded tools that only take BMP. It has no alpha channel; the background is always a solid color, so it has the same pixels as the PNG.

SVG, PDF and EPS are vectors at one point per module (0.353 mm), so an EAN-13 at the defaults comes out at about 45 × 28 mm, about 107% of its nominal size. Scale vector files in your layout; for retail barcodes, keep between 80% and 200% and don't cut the bar height.

USPS Intelligent Mail is drawn at the size USPS-B-3200 sets, so print it at 100%: bars 0.02 in wide, about 22 to the inch and 3.96 mm (0.156 in) tall, with 0.042 in clear above and below (USPS asks for 0.028 in). Its `scale` is pixels per point (a bar is 1.44 points wide), and its `quietZone` counts bar widths: the default of 7 gives the 0.125 in USPS asks for at each end. The digits, when `text` is on, follow the specification's layout: fields separated by spaces, starting at the first bar. A DotCode dot is a 2D cell, two modules (0.71 mm) across.

## Responses

A successful request returns the file with:

- `Content-Type` of the file type. EPS comes as a download (`Content-Disposition: attachment`); the rest open inline with a file name such as `ean13-5901234123457.png`
- `Cache-Control: public, max-age=31536000, immutable` for `GET`: the same query always returns the same bytes. `POST` responses are `no-store`
- `Access-Control-Allow-Origin: *`, so you can `fetch` it from any website

## Saved barcodes [#saved-barcodes]

With an [API key](/docs/developers/api-keys), the REST API keeps barcodes in the key's workspace, where they show under **Barcodes** in the dashboard. Same scopes as codes: `codes:read` to list and download, `codes:write` to change.

```bash title="Terminal"
curl https://api.qrdx.dev/v1/barcodes \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"format":"ean13","value":"590123412345","title":"Spring box"}'
```

```json title="201 Created"
{
  "data": {
    "id": "cmwgwqcxo0003iscgecog7m1b",
    "title": "Spring box",
    "format": "ean13",
    "formatLabel": "EAN-13",
    "value": "5901234123457",
    "options": {
      "foreground": "#000000",
      "background": "#ffffff",
      "showText": true,
      "barHeightMm": 23,
      "quietZone": 11,
      "scale": 4,
      "rotation": 0
    },
    "folderId": null,
    "imageUrl": "https://qrdx.dev/api/v1/barcode?format=ean13&data=5901234123457",
    "createdAt": "2026-11-14T21:18:01.212Z",
    "updatedAt": "2026-11-14T21:18:01.212Z",
    "deletedAt": null,
    "organizationId": "ws_ad2c5e1cce31ccf31535e78f08ab5b78"
  }
}
```

The 12-digit value came back with its check digit, and `options` holds the format's defaults. Each saved barcode has an `imageUrl`: the same picture from `GET /v1/barcode`, which anyone with the link can load. The `/image` endpoint below is private and needs the key.

| Endpoint | Does |
| --- | --- |
| [`GET /v1/barcodes`](/docs/developers/api/list-barcodes) | Lists them, newest change first; filter with `q`, `format`, `folderId`, `status=trash` |
| [`POST /v1/barcodes`](/docs/developers/api/create-barcode) | Saves one. `options` takes `foreground`, `background`, `showText`, `barHeightMm`, `quietZone`, `scale` and `rotation` |
| [`GET /v1/barcodes/{id}`](/docs/developers/api/get-barcode) | One barcode |
| [`PATCH /v1/barcodes/{id}`](/docs/developers/api/update-barcode) | Changes its title, format, value, options or folder |
| [`DELETE /v1/barcodes/{id}`](/docs/developers/api/delete-barcode) | Moves it to the trash (`{ "deleted": false, "trashed": true }`); `?permanent=true` deletes it for good |
| [`GET /v1/barcodes/{id}/image`](/docs/developers/api/get-saved-barcode-image) | The file, drawn as saved: `type` and `scale` as above. `Cache-Control: private, no-store` |

Every plan saves barcodes: up to 1,000 on Free, 10,000 on Pro and 100,000 on Business, not counting the trash. These requests count toward the workspace's daily API quota and send the `X-RateLimit-*` headers, like the rest of the [REST API](/docs/developers/rest-api#rate-limits).

## If something goes wrong

### `400` with `"param": "data"`

The value breaks the format's rules. The message says exactly what, with a check digit, a length or a character set:

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"EAN-13: The check digit should be 7, not 8. Check the number, or leave the last digit off and it's worked out for you."}]},"status":400}
```

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"Code 39: Code 39 has no lowercase letters. Use capitals, or Code 128 for mixed case."}]},"status":400}
```

### `400` with `"param": "format"`

`format` is missing or not one of the {facts.barcodeFormats} ids in [Formats](#formats). The message lists them.

### The raster image is refused or cut

Raster images are at most 6,000 pixels on a side. Lower `scale` for long values, or use SVG or PDF.

### `429 RATE_LIMITED`

Over {facts.imageApiPerMinute} requests a minute from one IP address, for `GET` and `POST /v1/barcode` together. Wait the seconds in `Retry-After`; `GET` responses can be cached for a year, so load each image once.

## Limits

- **Rate limit:** {facts.imageApiPerMinute} requests a minute per IP address for `GET` and `POST /v1/barcode`, as for the [QR image API](/docs/developers/image-api). Saved barcodes follow the REST API's per-minute limits and daily quota.
- **Image size:** raster images are at most 6,000 pixels on a side.
- **No scan check here.** The [barcode generator](/barcode-generator) decodes what it draws before you download; the API draws what you ask for. Print a test and scan it with the scanners that will read it. The generator can't check DotCode or USPS Intelligent Mail either: its reader doesn't decode them.

## MCP

The [MCP server](/docs/developers/mcp) has `generate_barcode`, which checks the value and returns a PNG with image URLs, and `save_barcode`, which saves to the workspace of the API key on the connection and is listed only when the connection has one.

## Self-hosting

The endpoints are part of the QRdx web app, so a [self-hosted](/docs/self-hosting) instance serves them at `/api/v1/barcode` and `/api/v1/barcodes` on your own domain.
