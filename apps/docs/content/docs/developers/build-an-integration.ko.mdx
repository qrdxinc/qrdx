이 페이지를 마치면 사용자가 여러분의 제품에서 **Connect QRdx**를 클릭하고 QRdx 동의 화면에서 앱을 승인할 수 있습니다. 그러면 여러분의 서버가 액세스 토큰을 보유하게 되고, 이 토큰으로 사용자를 대신해 `https://api.qrdx.dev/v1`을 호출할 수 있습니다. 호출 범위는 사용자가 승인한 스코프로 제한됩니다.

통합은 OAuth 앱입니다. 하나의 워크스페이스에서 여러분 본인으로 동작하는 [API 키](/docs/developers/api-keys)와 달리, 토큰은 앱을 승인한 사용자로서 그 사용자의 워크스페이스에서 동작하며, 사용자는 언제든 이 접근 권한을 회수할 수 있습니다.

## 시작하기 전에 [#before-you-start]

- QRdx 계정이 필요합니다. 무료 워크스페이스는 OAuth 앱을 1개, Pro는 5개, Business는 25개까지 만들 수 있습니다. 워크스페이스에는 소유자들이 가진 플랜 중 가장 높은 플랜이 적용됩니다.
- 비밀 값을 보관하고 리디렉션을 받을 수 있는 서버가 필요합니다. 코드 샘플은 Fetch API를 사용하는 Node.js이며, HTTPS와 SHA-256을 지원하는 언어라면 어떤 언어든 사용할 수 있습니다.
- 사용할 `https://` 리디렉션 URI 두 개가 필요합니다. 하나는 프로덕션용, 다른 하나는 개발용입니다(개발용에는 `http://localhost`를 사용할 수 있습니다).

## 1. OAuth 앱 만들기 [#1-create-an-oauth-app]

[설정 → API 키 및 앱](/dashboard?to=settings/developers)을 열고 **New app**을 선택하세요. 앱은 현재 열려 있는 워크스페이스에 속합니다. 앱을 만들고 변경할 수 있는 사람은 워크스페이스 소유자뿐이며, 관리자와 멤버는 앱을 볼 수만 있습니다.

<Shot id="oauth-new-app-form" />

| 필드 | 용도 |
| --- | --- |
| **Name**, **Description**, **Logo**, **Website** | 동의 화면에 표시됩니다. 128 × 128 px 이상의 정사각형 로고를 업로드하거나 로고의 `https://` 링크를 붙여 넣으세요 |
| **Redirect URIs** | QRdx가 사용자를 다시 보낼 주소입니다. 한 줄에 하나씩 최대 10개까지 입력할 수 있습니다. `https://`만 가능하며, 개발용으로 `http://localhost`도 사용할 수 있습니다. 와일드카드와 `#fragments`는 사용할 수 없으며, 모든 요청은 이 중 하나를 정확히 그대로 보내야 합니다 |
| **Scopes** | 앱이 요청할 수 있는 최대 범위입니다. 각 인증 요청에서는 이 중 일부 또는 전부를 요청합니다 |
| **Require PKCE** | 모든 인증 요청에서 `S256` 코드 챌린지를 보내야 합니다. 권장하며 기본적으로 켜져 있습니다 |

저장하면 QRdx가 **Client ID**와 **Client secret**을 보여 줍니다. 시크릿은 이때 꼭 복사하세요. QRdx는 해시만 보관하므로 다시 보여 줄 수 없습니다. 시크릿을 잃어버렸거나 유출되었다면 앱 페이지에서 **Regenerate secret**을 선택하세요. 이전 시크릿은 즉시 사용할 수 없게 되며, 이미 연결한 사용자는 연결이 유지됩니다. 앱을 만들 때와 시크릿을 다시 생성할 때는 먼저 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 해야 합니다. 해당 브라우저에서 최근 10분 이내에 확인했다면 생략됩니다.

<Shot id="oauth-app-credentials" />

두 값은 모두 서버에만 보관하세요.

```bash title=".env"
QRDX_CLIENT_ID=qrdx_app_...
QRDX_CLIENT_SECRET=qrdx_secret_...
```

## 2. 사용자를 QRdx로 보내기 [#2-send-people-to-qrdx]

무작위 `state`와 PKCE `code_verifier`를 생성해 둘 다 사용자의 세션에 보관한 뒤, 인증 URL로 리디렉션하세요.

```txt title="Authorize URL"
https://qrdx.dev/api/oauth/authorize
  ?response_type=code
  &client_id=<client id>
  &redirect_uri=https://acme.example/oauth/qrdx/callback
  &scope=profile:read codes:read codes:write
  &state=<random value>
  &code_challenge=<BASE64URL(SHA256(code_verifier))>
  &code_challenge_method=S256
```

| 매개변수 | 필수 여부 | 값 |
| --- | --- | --- |
| `response_type` | 예 | `code` |
| `client_id` | 예 | 앱의 클라이언트 ID |
| `redirect_uri` | 예 | 앱의 리디렉션 URI 중 하나(문자 하나까지 동일해야 함) |
| `scope` | 예 | 공백 또는 쉼표로 구분하며, 앱이 가진 스코프만 가능 |
| `state` | 권장 | 임의의 값이며 QRdx가 그대로 돌려보냅니다. 돌아왔을 때 이 값을 확인해 사이트 간 요청 위조를 막으세요 |
| `code_challenge` | 앱에서 PKCE를 요구하는 경우 | 43~128자: `code_verifier`의 base64url SHA-256 값 |
| `code_challenge_method` | 아니요 | `S256`이며 기본값이자 유일하게 허용되는 방식입니다. `plain`은 `invalid_request`로 거부됩니다 |
| `prompt` | 아니요 | `consent`는 사용자가 이전에 같은 스코프를 승인했더라도 동의 화면을 표시합니다 |

```ts title="lib/qrdx-oauth.ts"
import { createHash, randomBytes } from "node:crypto";

export const QRDX_AUTHORIZE_URL = "https://qrdx.dev/api/oauth/authorize";

export function createPkce() {
  const verifier = randomBytes(32).toString("base64url"); // 43 characters
  const challenge = createHash("sha256").update(verifier).digest("base64url");
  return { verifier, challenge };
}

export function authorizeUrl({ state, challenge }: { state: string; challenge: string }) {
  const url = new URL(QRDX_AUTHORIZE_URL);
  url.search = new URLSearchParams({
    response_type: "code",
    client_id: process.env.QRDX_CLIENT_ID!,
    redirect_uri: "https://acme.example/oauth/qrdx/callback",
    scope: "profile:read codes:read codes:write",
    state,
    code_challenge: challenge,
    code_challenge_method: "S256",
  }).toString();
  return url.toString();
}
```

QRdx에 로그인하지 않은 사용자는 먼저 로그인합니다. 그다음 동의 화면이 나타나며, 여기에는 앱의 로고, 이름, 웹사이트, 만든 사람, 요청한 권한, 그리고 로그인한 계정이 표시됩니다. QRdx가 검토하지 않은 앱에는 **Unverified app.** 문구가 표시됩니다. **Authorize**를 누르면 최근 10분 이내에 확인하지 않은 경우 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요청합니다(직전에 로그인했다면 확인한 것으로 간주됩니다). 이미 같은 스코프를 앱에 승인한 사용자는 바로 여러분의 서비스로 돌아갑니다.

<Shot id="oauth-consent-screen" />

그다음 QRdx가 `redirect_uri`로 리디렉션합니다.

- 승인한 경우: `?code=<authorization code>&state=<your state>`. 코드는 한 번만 사용할 수 있으며 10분 이내에 사용해야 합니다.
- 취소한 경우: `?error=access_denied&error_description=...&state=<your state>`.

잘못된 요청은 리디렉션되지 않고 OAuth 2.0 형식의 JSON으로 응답합니다. 알 수 없는 `client_id`는 `invalid_client`, 등록되지 않은 `redirect_uri`나 `plain` 챌린지는 `invalid_request`, 앱에 없는 스코프는 `invalid_scope`입니다.

```json title="400 Bad Request"
{"error":"invalid_scope","error_description":"Invalid or unsupported scope"}
```

## 3. 코드를 토큰으로 교환하기 [#3-exchange-the-code-for-tokens]

서버에서 토큰 엔드포인트로 코드를 전송하세요. 본문은 폼 인코딩 형식이며, `redirect_uri`는 2단계에서 사용한 값과 같아야 합니다.

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=authorization_code \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d code=$CODE \
  -d redirect_uri=https://acme.example/oauth/qrdx/callback \
  -d code_verifier=$CODE_VERIFIER
```

```ts title="app/oauth/qrdx/callback/route.ts"
export async function GET(req: Request) {
  const params = new URL(req.url).searchParams;
  const session = await getSession(req); // your own session store
  if (params.get("state") !== session.qrdxState) {
    return new Response("Invalid state", { status: 400 });
  }
  if (params.get("error")) {
    return Response.redirect("https://acme.example/settings?qrdx=canceled");
  }

  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "authorization_code",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      code: params.get("code") ?? "",
      redirect_uri: "https://acme.example/oauth/qrdx/callback",
      code_verifier: session.qrdxVerifier,
    }),
  });
  if (!response.ok) {
    const { error, error_description } = await response.json();
    throw new Error(`QRdx token exchange failed: ${error} ${error_description}`);
  }

  const tokens: {
    access_token: string;
    token_type: "Bearer";
    expires_in: number;
    refresh_token: string;
    scope: string;
  } = await response.json();
  await saveQrdxTokens(session.userId, tokens); // encrypt at rest
  return Response.redirect("https://acme.example/settings?qrdx=connected");
}
```

```json title="Response fields"
{
  "access_token": "<send as Authorization: Bearer>",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "<store encrypted; it rotates on each refresh>",
  "scope": "profile:read codes:read codes:write"
}
```

`scope`에는 부여된 스코프가 공백으로 구분되어 나열됩니다. 액세스 토큰은 1시간, 리프레시 토큰은 30일 동안 유효합니다. `code_verifier`는 인증 요청에 `code_challenge`가 있었을 때만 보내세요. 챌린지 없이 발급된 코드에 verifier를 보내면 거부됩니다. 시크릿이 틀렸거나 이미 사용된 코드는 `invalid_client` 또는 `invalid_grant`로 응답하고, 지원하는 두 가지 외의 grant type은 다음과 같이 응답합니다.

```json title="400 Bad Request"
{"error":"unsupported_grant_type","error_description":"Supported: authorization_code, refresh_token"}
```

## 4. 토큰 갱신하기 [#4-refresh-tokens]

액세스 토큰이 만료되기 전에 리프레시 토큰을 새 토큰 쌍으로 교환하세요. 리프레시 토큰은 순환됩니다. 각 토큰은 한 번만 사용할 수 있으므로 매번 새 토큰을 저장하세요.

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=refresh_token \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d refresh_token=$REFRESH_TOKEN
```

```ts title="lib/qrdx-oauth.ts"
export async function refreshQrdxTokens(refreshToken: string) {
  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "refresh_token",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      refresh_token: refreshToken,
    }),
  });
  // invalid_grant: revoked, expired or already used. Ask the person to reconnect.
  if (!response.ok) throw new Error((await response.json()).error);
  return response.json();
}
```

토큰 엔드포인트는 IP 주소당 분당 30건의 요청을 허용합니다.

## 5. API 호출하기 [#5-call-the-api]

액세스 토큰을 Bearer 토큰으로 `https://api.qrdx.dev/v1`에 보내세요. 토큰 요청은 앱을 승인한 사용자 본인의 워크스페이스(모든 계정에 하나씩 있습니다)에서 해당 워크스페이스의 플랜과 [일일 할당량](/docs/developers/rest-api#rate-limits)에 따라 동작합니다. 통합에 필요한 최소한의 범위만 요청하세요. 사용자는 동의 화면에서 각 스코프를 확인합니다.

| 스코프 | 허용 범위 |
| --- | --- |
| `profile:read` | 사용자의 ID, 이름, 이메일, 아바타: `GET /v1/me`, `GET /api/oauth/userinfo` |
| `themes:read` | 저장된 QR 테마: `GET /v1/themes`, `GET /v1/themes/{id}` |
| `codes:read` | 동적 QR 코드, 스캔 분석, 저장된 바코드, 훅 목록 조회 |
| `codes:write` | `codes:read`에서 허용하는 모든 작업과 함께 코드와 바코드 생성·수정·삭제, 전환 보고, 이벤트 구독 |

```ts title="lib/qrdx.ts"
const response = await fetch("https://api.qrdx.dev/v1/codes", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${accessToken}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    destinationUrl: "https://acme.example/menu",
    title: "Spring menu",
  }),
});
const { data: code } = await response.json(); // code.shortLink is what the QR encodes
```

`401 INVALID_TOKEN`은 토큰이 만료되었거나 폐기되었다는 뜻입니다. 토큰을 갱신하거나 사용자에게 다시 연결하도록 요청하세요. `403 INSUFFICIENT_SCOPE`는 토큰에 필요한 스코프가 없다는 뜻입니다. [API 레퍼런스](/docs/developers/api)에서 모든 엔드포인트와 해당 스코프 및 오류를 확인할 수 있습니다.

## 6. 웹훅으로 이벤트 받기 [#6-receive-events-with-webhooks]

사용자에게 URL을 붙여 넣으라고 요청하는 대신, REST Hooks API로 사용자를 대신해 구독하세요. `codes:write`가 필요하며, 사용자의 플랜에 [웹훅](/docs/webhooks)(Business)이 포함되어 있어야 합니다. 그렇지 않으면 `402 PLAN_REQUIRED`가 반환됩니다.

```bash title="Terminal"
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://acme.example/webhooks/qrdx", "events": ["scan.created", "form.submitted"]}'
```

`201` 응답에는 구독 `id`와 서명용 `secret`이 포함되며, `secret`은 한 번만 표시됩니다. 모든 전송은 이 값으로 서명되어 `X-QRdx-Signature`에 담깁니다. 자세한 내용은 [서명 확인](/docs/webhooks#verify-signatures)을 참고하세요. 사용자가 연결을 해제하면 `DELETE /v1/hooks/{id}`로 구독을 취소하세요. 구독은 사용자 본인 워크스페이스의 **Settings → Webhooks**에도 표시되며, 거기서 직접 삭제할 수 있습니다.

## 7. 연결 해제와 사용자 식별 [#7-disconnect-and-identify-people]

사용자가 여러분의 제품에서 QRdx 연결을 해제하면 해당 토큰을 폐기하세요. 한 쌍의 토큰 중 하나를 폐기하면 쌍 전체가 폐기되며, 이 엔드포인트는 알 수 없는 토큰이라도 `200`으로 응답합니다.

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/revoke -d token=$REFRESH_TOKEN
```

사용자는 QRdx의 **Settings → Authorized apps**에서 **Revoke access**로 언제든 직접 접근 권한을 회수할 수 있습니다. 앱이 해당 계정에 대해 보유한 모든 토큰은 즉시 작동하지 않게 됩니다. API 호출은 `invalid_token`과 함께 `401`로 응답하고, 갱신은 `invalid_grant`로 응답합니다. 두 경우 모두 "연결 해제됨"으로 처리하고 다시 연결하도록 안내하세요. 사용자에게는 동의 화면이 다시 표시됩니다.

연결한 사용자를 식별하려면 `profile:read` 토큰으로 `GET /api/oauth/userinfo`를 호출하세요. OpenID 방식의 클레임인 `sub`, `name`, `email`, `picture`가 반환됩니다. 이메일은 바뀔 수 있으므로 `sub`를 변하지 않는 계정 ID로 사용하세요.

```bash title="Terminal"
curl https://qrdx.dev/api/oauth/userinfo -H "Authorization: Bearer $ACCESS_TOKEN"
```

```json title="401 Unauthorized: an expired or revoked token"
{"error":"invalid_token","error_description":"Invalid or expired token"}
```

## 8. 디렉터리에 등록하기 [#8-get-listed]

통합이 처음부터 끝까지 정상 동작하면 [통합 디렉터리](/integrations)에 추가해 달라고 요청하세요. 디렉터리에는 여러분이 만든 커뮤니티 통합으로 표시됩니다. 앱 페이지에서 **Get listed**를 누르면 세부 정보가 채워진 이메일이 [support@qrdx.dev](mailto:support@qrdx.dev?subject=List%20my%20integration)로 열립니다.

- 앱 이름과 클라이언트 ID
- 앱이 하는 일과 대상 사용자를 설명하는 한 줄
- 설정 단계 또는 설정 단계로 연결되는 링크
- 지원 연락처

QRdx 팀이 등록된 앱을 검토하고 **Verified**로 표시하며, 그러면 동의 화면에서 **Unverified app.** 문구가 사라집니다. 인증된 앱의 이름, 로고, 웹사이트를 변경하면 다시 검토를 받을 때까지 배지가 제거됩니다.

## 문제가 생겼을 때 [#if-something-goes-wrong]

### `invalid_request: redirect_uri not registered` [#invalid_request-redirect_uri-not-registered]

authorize URL의 `redirect_uri`가 앱에 등록된 리디렉션 URI 중 어느 것과도 스킴과 끝의 슬래시까지 한 글자도 다르지 않게 일치하지 않습니다. 앱에 해당 URI를 추가하거나 URL을 수정하세요.

### `invalid_scope` [#invalid_scope]

authorize URL이 앱에 없는 scope를 요청하고 있습니다. **Settings → API keys & apps**에서 앱에 해당 scope를 추가한 뒤 다시 요청하세요.

### 갱신 시 `invalid_grant` [#invalid_grant-on-refresh]

refresh token을 이미 사용했거나(갱신할 때마다 새 토큰이 반환됩니다), 30일이 지나 만료되었거나, 사용자가 앱 권한을 해제했습니다. 사용자가 인증 과정을 처음부터 다시 진행하도록 안내하세요.

### 시크릿을 다시 생성한 뒤 토큰이 동작하지 않을 때 [#tokens-stop-working-after-you-regenerated-the-secret]

새 시크릿은 새로 요청하는 토큰에만 적용되며, 기존 access token과 refresh token은 계속 유효합니다. 모든 서버 인스턴스가 새 `QRDX_CLIENT_SECRET`을 읽고 있는지 확인하세요.

## 보안 체크리스트 [#security-checklist]

- 클라이언트 시크릿은 서버에만 보관하세요. 브라우저와 모바일 코드에는 절대 노출되면 안 됩니다.
- 인증할 때마다 PKCE(`S256`)와 새로운 `state`를 사용하고, 돌아올 때 `state`를 확인하세요.
- 리디렉션 URI는 정확하게 등록하세요. QRdx는 한 글자씩 비교합니다.
- access token과 refresh token은 암호화해서 저장하고, 갱신할 때마다 새 refresh token을 저장하세요.
- 사용자가 연결을 해제하면 토큰을 폐기하세요. **Settings → API keys & apps**에서 앱을 삭제하면 앱이 발급한 모든 토큰이 폐기되고, 앱을 일시 중지하면 다시 시작할 때까지 토큰이 거부됩니다.
