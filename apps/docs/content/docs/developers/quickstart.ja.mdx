このページを終えると、1回のリクエストで保存したQRコード画像、ワークスペース用のAPIキー、リンク先を変更しても印刷済みのQRが使い続けられる動的QRコード、そしてそのスキャン分析の最初の確認が手に入ります。

APIは2つの部分に分かれています。画像の生成には何も必要ありません。アカウントもキーも不要です。動的QRコード、スキャン、Webhookはワークスペースに属するため、APIキーが必要です。

## はじめる前に [#before-you-start]

- curl、Node.js 18以降、または`requests`パッケージを入れたPython 3。お使いのものに合わせてタブを選んでください。選択は他のページでも保持されます。
- ステップ2〜4にはQRdxアカウントが必要です。フリープランで十分です。フリーのワークスペースでは、有効な動的QRコードを10個まで、APIリクエストを1日1,000回まで利用できます。

## 1. QRコード画像を作成する（キー不要） [#1-make-a-qr-code-image-no-key]

次のコードを実行します。qrdx.devを開くQRコードのPNGが保存されます。

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png" -o qr.png
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="qr.mjs"
    // Node 18 or later
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/qr");
    url.searchParams.set("data", "https://qrdx.dev");
    url.searchParams.set("format", "png");

    const response = await fetch(url);
    await writeFile("qr.png", Buffer.from(await response.arrayBuffer()));
    console.log(response.status, response.headers.get("content-type"));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="qr.py"
    # pip install requests
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/qr",
        params={"data": "https://qrdx.dev", "format": "png"},
    )
    response.raise_for_status()
    open("qr.png", "wb").write(response.content)
    print(response.status_code, response.headers["content-type"])
    ```
  </Tab>
</Tabs>

```txt title="Output"
200 image/png
qr.png: PNG image data, 512 x 512, 8-bit/color RGBA, non-interlaced
```

これで動作するAPI呼び出しが完成です。URL自体が画像になっているため、`<img>`タグにそのまま指定しても使えます。

```html title="index.html"
<img src="https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&fg=111111&body=circle" alt="QR code for qrdx.dev" />
```

色、形、サイズ、形式はクエリパラメータで変更できます。ブラウザで試すこともでき、[QRコード画像を生成する](/docs/developers/api/get-qr-image)ページの**Try it**パネルからリクエストを送信して画像を確認できます。画像の生成はどのクォータにも含まれません。上限はIPアドレスごとに1分あたり{facts.imageApiPerMinute}リクエストです。

## 2. APIキーを作成する [#create-an-api-key]

これ以外のAPIはすべてワークスペースに対して動作します。動的QRコードの作成、リンク先の変更、スキャンの取得などです。これらのリクエストでは、`Authorization`ヘッダーにAPIキーを含めます。

1. [設定 → APIキーとアプリ](/dashboard?to=settings/developers&new=1)を開きます。必要に応じて先にサインインしてください。**Create API key**フォームが開きます。
2. キーに名前を付けます（実行するサーバー名など）。**Full access**のまま**Create key**を選びます。先に本人確認を求められる場合があります。
3. **Copy your API key**ダイアログからキーをコピーします。キーが表示されるのはこの1回だけです。QRdxはキーのハッシュを保存しており、再表示はできません。ダイアログには、キーが入力済みの、動的QRコードを作成するcurlリクエストも表示されます。こちらを貼り付けて使うこともできます。

<Shot id="create-key-dialog" />

<Shot id="api-key-copy-dialog" />

以降のステップのために、キーをエクスポートします。

```bash title="Terminal"
export QRDX_API_KEY=qrdx_...
```

このキーは、作成時に開いていたワークスペースであなたとして動作し、そのキーでのリクエストはそのワークスペースの1日のクォータに計上されます。スコープ、チーム、有効期限、無効化については[APIキー](/docs/developers/api-keys)をご覧ください。

## 3. 動的QRコードを作成する [#3-create-a-dynamic-code]

動的QRコードは、印刷後でもリンク先を変更できる短縮リンクです。

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -X POST https://api.qrdx.dev/v1/codes \
      -H "Authorization: Bearer $QRDX_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"destinationUrl": "https://example.com", "title": "My first code"}'
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="create.mjs"
    const response = await fetch("https://api.qrdx.dev/v1/codes", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.QRDX_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        destinationUrl: "https://example.com",
        title: "My first code",
      }),
    });
    const { data: code } = await response.json();
    console.log(response.status, code.id, code.shortLink);
    ```
  </Tab>
  <Tab value="Python">
    ```python title="create.py"
    import os
    import requests

    response = requests.post(
        "https://api.qrdx.dev/v1/codes",
        headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},
        json={"destinationUrl": "https://example.com", "title": "My first code"},
    )
    response.raise_for_status()
    code = response.json()["data"]
    print(response.status_code, code["id"], code["shortLink"])
    ```
  </Tab>
</Tabs>

レスポンスは、新しいコードを含む`201 Created`です。

```json title="201 Created"
{
  "data": {
    "id": "cmwgwq0t80000iscg4ybn05kh",
    "slug": "l0q9fZn",
    "shortLink": "https://qrdx.dev/q/l0q9fZn",
    "defaultShortLink": "https://qrdx.dev/q/l0q9fZn",
    "nfcLink": "https://qrdx.dev/q/l0q9fZn?nfc",
    "domain": null,
    "destinationUrl": "https://example.com/",
    "title": "My first code",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-11-14T21:17:45.512Z",
    "updatedAt": "2026-11-14T21:17:45.512Z",
    "organizationId": "ws_ad2c5e1cce31ccf31535e78f08ab5b78",
    "preciseLocation": false
  }
}
```

ここで重要なフィールドは2つです。`shortLink`はQRコードにエンコードされる値です。ステップ1の画像APIで`https://api.qrdx.dev/v1/qr?data=https://qrdx.dev/q/l0q9fZn&format=png`のように生成し、それを印刷します。`id`は今後このコードを指定するときに使うので、控えておいてください。

```bash title="Terminal"
export CODE_ID=cmwgwq0t80000iscg4ybn05kh
```

送信できるすべてのフィールド（カスタムのバックハーフやデザインを含む）は、[コードを作成する](/docs/developers/api/create-codes)に一覧があります。

## 4. リンク先を別の場所に変更する [#4-point-it-somewhere-else]

リンク先はいつでも変更できます。印刷済みのコードはそのまま使い続けられます。

```bash title="Terminal"
curl -X PATCH https://api.qrdx.dev/v1/codes/$CODE_ID \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/new-page"}'
```

`200 OK`のレスポンスは同じコードで、`"destinationUrl": "https://example.com/new-page"`と新しい`updatedAt`が含まれます。スマートフォンでコードをスキャンしてから、分析を取得します。

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/codes/$CODE_ID/scans?range=7d" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

```json title="200 OK (before the first scan, trimmed)"
{
  "data": {
    "codeId": "cmwgwq0t80000iscg4ybn05kh",
    "range": "7d",
    "retentionDays": 365,
    "days": 7,
    "total": 0,
    "unique": 0,
    "interval": "day",
    "series": [{ "date": "2026-11-08", "count": 0 }, { "date": "2026-11-09", "count": 0 }],
    "countries": [],
    "devices": [],
    "sources": { "qr": 0, "nfc": 0 }
  }
}
```

スキャン後は`total`が増え、`countries`、`cities`、`devices`、`os`、`browsers`に値が入ります。範囲の指定方法や個別のスキャンをページ送りで取得する方法は、[スキャン分析を取得する](/docs/developers/api/get-code-scans)で説明しています。

## うまくいかない場合 [#if-something-goes-wrong]

すべてのエラーは、固定の`code`と、対処法を示すメッセージを含むJSONで返されます。このページで遭遇しやすいのは次の2つです。

```json title="401 Unauthorized: the header is missing"
{
  "code": "UNAUTHORIZED",
  "message": "Missing API key. Send an API key as \"Authorization: Bearer <key>\"; create one at https://qrdx.dev/dashboard?to=settings/developers. OAuth access tokens go in the same header.",
  "status": 401,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

```json title="400 Bad Request: the destination isn't a full URL"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "data": { "details": [{ "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }] },
  "status": 400
}
```

`401 INVALID_TOKEN`は、キーのコピーが途中で切れている、無効化された、または期限切れであることを意味します。新しいキーを作成してください。`403 INSUFFICIENT_SCOPE`は、**Read only**のキーを作成したことを意味します。ステップ3には`codes:write`が必要です。すべてのコードと対処法は[エラーのページ](/docs/developers/errors)に一覧があります。

## 他のユーザーのために操作する [#get-an-access-token]

APIキーはあなた自身として動作します。お使いのプロダクトが他のユーザーのためにQRdxを呼び出す場合は、代わりにOAuthアプリを登録してください。各ユーザーが1回承認すると、サーバーはそのユーザーのアカウント用のアクセストークンを取得し、同じ`Authorization: Bearer`ヘッダーで送信します。ここまでのリクエストはすべて、キーの代わりにトークンを使ってもそのまま動作します。[REST APIとOAuth](/docs/developers/rest-api#get-an-access-token)と[連携を構築する](/docs/developers/build-an-integration)をご覧ください。
