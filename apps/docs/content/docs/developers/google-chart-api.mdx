By the end of this page, every QR code your pages, emails or spreadsheets loaded from `chart.googleapis.com` loads from the QRdx [image API](/docs/developers/image-api) instead, at the same size and error correction level, with no account or key.

Google deprecated its Image Charts in April 2012, QR codes at `chart.googleapis.com/chart?cht=qr` included. The endpoint answers `404` today (checked on November 15, 2026), so every old `<img>` tag shows a broken image. The QRdx image API works the same way, a `GET` URL that returns the image, so the change is a new host and three renamed parameters.

## Before you start

- Find the files that still use the old API. The command below lists them, including the older `chart.apis.google.com` host:

```bash title="Terminal"
grep -rlE "chart\.(googleapis|apis\.google)\.com/chart" .
```

- Work in a git checkout or another place where you can review the change before it goes live.

## 1. Compare one URL

The two URLs below draw the same thing: a 300 × 300 PNG of `https://example.com` at error correction `M` with a 2-module margin.

```txt title="Before and after"
https://chart.googleapis.com/chart?cht=qr&chs=300x300&chl=https%3A%2F%2Fexample.com&chld=M|2
https://api.qrdx.dev/v1/qr?format=png&size=300&data=https%3A%2F%2Fexample.com&level=M&margin=2
```

```bash title="Terminal"
curl -o after.png "https://api.qrdx.dev/v1/qr?format=png&size=300&data=https%3A%2F%2Fexample.com&level=M&margin=2"
file after.png
# after.png: PNG image data, 300 x 300, 8-bit/color RGBA, non-interlaced
```

## 2. Map the parameters

| Google Chart | QRdx | Notes |
| --- | --- | --- |
| `cht=qr` | not needed | The endpoint only draws QR codes. Left in, it's ignored |
| `chl=<data>` | `data=<data>` | URL-encoded the same way, up to 2,048 characters |
| `chs=<width>x<height>` | `size=<width>` | One number, because QR codes are square: `64` to `2048` pixels |
| `chld=<level>\|<margin>` | `level=<level>&margin=<margin>` | The same letters, `L`, `M`, `Q` and `H`. The margin is in modules, `0` to `16` |
| `choe=UTF-8` | not needed | QRdx always encodes text as UTF-8, which was Google's default. There's no Shift_JIS or ISO-8859-1 option. Left in, it's ignored |
| always PNG | `format=png` | QRdx returns SVG unless you ask for `png`, `webp`, `bmp` or `eps`. Keep PNG for email, since many email clients don't show SVG |

Two defaults differ. Without `chld`, Google used error correction `L`; QRdx uses `Q`, which survives more damage but makes a denser code. Add `level=L` if you need the old look. Both default to a 4-module margin.

## 3. Rewrite the URLs in your files

This rewrites every Google Chart QR URL in the files you name, both hosts included: it changes the host and path, renames `chl`, `chs` and `chld`, and adds `format=png` so the images stay PNG. Perl comes with macOS and most Linux distributions.

```bash title="Terminal"
perl -pi -e 's{https?://chart\.(?:googleapis|apis\.google)\.com/chart\?([^\s"\x27<>)]*)}{my $q = $1; $q =~ s/(^|[&;])chl=/${1}data=/; $q =~ s/(^|[&;])chs=(\d+)x\d+/${1}size=$2/; $q =~ s/(^|[&;])chld=([LMQH])(?:\||%7C)(\d+)/${1}level=$2&margin=$3/i; $q =~ s/(^|[&;])chld=([LMQH])/${1}level=$2/i; "https://api.qrdx.dev/v1/qr?format=png&$q"}ge' index.html
```

Run on a file with three old tags, it produces:

```html title="index.html (after)"
<img src="https://api.qrdx.dev/v1/qr?format=png&cht=qr&size=300&data=https%3A%2F%2Fexample.com&level=M&margin=2" alt="QR">
<img src="https://api.qrdx.dev/v1/qr?format=png&cht=qr&size=150&data=https%3A%2F%2Fexample.com%2Fmenu" alt="QR 2">
<img src="https://api.qrdx.dev/v1/qr?format=png&size=200&cht=qr&data=hello&level=H&choe=UTF-8" alt="QR 3">
```

The leftover `cht=qr` and `choe=UTF-8` are ignored by QRdx; remove them by hand if you want tidy URLs. Check the diff, then run the `grep` from the start again: it should list nothing.

## 4. Change the code that builds URLs

```js title="qr.js"
// Before
const src = `https://chart.googleapis.com/chart?cht=qr&chs=200x200&chl=${encodeURIComponent(link)}`;

// After
const src = `https://api.qrdx.dev/v1/qr?format=png&size=200&data=${encodeURIComponent(link)}`;
```

In Google Sheets:

```txt title="Sheets formula"
=IMAGE("https://api.qrdx.dev/v1/qr?format=png&size=150&data="&ENCODEURL(A2))
```

Sheets loads images through Google's own servers, so a sheet with hundreds of codes can run into the per-IP limit below. For a long list, make the files once with the [bulk generator](/tools/bulk) or the [CLI](/docs/developers/cli)'s `qrdx batch`.

## If something goes wrong

### `400` with `"param": "size"`

A `chs` under 64 pixels (such as `50x50`) or over 2048 is refused. Change those sizes by hand; `64` is the smallest the image API draws.

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"size","message":"Too small: expected number to be >=64"}]},"status":400}
```

### The image is denser than before

Google's default error correction was `L`; QRdx's is `Q`. Add `level=L` to match the old look.

### `429` after a bulk reload

The image API allows {facts.imageApiPerMinute} requests a minute per IP address. Wait the seconds in the `Retry-After` header, or generate the files once instead of loading them live.

## What else to know

- **Caching:** the same URL always returns the same bytes, so responses are cached for a year (`Cache-Control: public, max-age=31536000, immutable`).
- **More options:** colors (`fg`, `bg`), module and eye shapes, a logo icon (`logoIcon`) and frames. Try them in the [URL builder](/qr-code-api), or read the [parameters](/docs/developers/image-api#parameters).
- **Self-hosting:** a [self-hosted](/docs/self-hosting) QRdx serves the same API at `/api/v1/qr` on your own domain.
