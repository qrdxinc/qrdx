By the end of this page you will have a QR code image saved from one request, an API key for your workspace, a dynamic code whose printed QR keeps working after you change where it sends people, and a first look at its scan analytics.

The API has two halves. Images need nothing: no account, no key. Dynamic codes, scans and webhooks belong to a workspace, so they need an API key.

## Before you start

- curl, Node.js 18 or later, or Python 3 with the `requests` package. Pick the tab for the one you use; the choice sticks across pages.
- A QRdx account for steps 2 to 4. A free one is enough: Free workspaces have 10 active dynamic codes and 1,000 API requests a day.

## 1. Make a QR code image (no key)

Run this. It saves a PNG of a QR code that opens qrdx.dev.

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png" -o qr.png
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="qr.mjs"
    // Node 18 or later
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/qr");
    url.searchParams.set("data", "https://qrdx.dev");
    url.searchParams.set("format", "png");

    const response = await fetch(url);
    await writeFile("qr.png", Buffer.from(await response.arrayBuffer()));
    console.log(response.status, response.headers.get("content-type"));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="qr.py"
    # pip install requests
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/qr",
        params={"data": "https://qrdx.dev", "format": "png"},
    )
    response.raise_for_status()
    open("qr.png", "wb").write(response.content)
    print(response.status_code, response.headers["content-type"])
    ```
  </Tab>
</Tabs>

```txt title="Output"
200 image/png
qr.png: PNG image data, 512 x 512, 8-bit/color RGBA, non-interlaced
```

That's a working API call. The URL itself is the image, so it also works straight in an `<img>` tag:

```html title="index.html"
<img src="https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&fg=111111&body=circle" alt="QR code for qrdx.dev" />
```

Change the colors, shapes, size and format with query parameters, or try them in the browser on the [Render a QR code image](/docs/developers/api/get-qr-image) page: its **Try it** panel sends the request and shows the image. Images don't count against any quota; the limit is {facts.imageApiPerMinute} requests a minute per IP address.

## 2. Create an API key [#create-an-api-key]

Everything else in the API acts on a workspace: create dynamic codes, change where they point, read their scans. Those requests carry an API key in the `Authorization` header.

1. Open [Settings → API keys & apps](/dashboard?to=settings/developers&new=1), signing in first if you need to. The **Create API key** form opens.
2. Give the key a name, such as the server it will run on, keep **Full access** and choose **Create key**. QRdx may ask you to confirm it's you first.
3. Copy the key from the **Copy your API key** dialog. It's shown only this once: QRdx stores a hash of it and can't show it again. The dialog also shows a curl request that creates a dynamic code, with your key filled in, if you'd rather paste that.

<Shot id="create-key-dialog" />

<Shot id="api-key-copy-dialog" />

Export the key for the next steps:

```bash title="Terminal"
export QRDX_API_KEY=qrdx_...
```

The key acts as you in the workspace that was open when you made it, and requests with it count against that workspace's daily quota. [API keys](/docs/developers/api-keys) covers scopes, teams, expiry and revoking.

## 3. Create a dynamic code

A dynamic code is a short link you can point somewhere else after it's printed:

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -X POST https://api.qrdx.dev/v1/codes \
      -H "Authorization: Bearer $QRDX_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"destinationUrl": "https://example.com", "title": "My first code"}'
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="create.mjs"
    const response = await fetch("https://api.qrdx.dev/v1/codes", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.QRDX_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        destinationUrl: "https://example.com",
        title: "My first code",
      }),
    });
    const { data: code } = await response.json();
    console.log(response.status, code.id, code.shortLink);
    ```
  </Tab>
  <Tab value="Python">
    ```python title="create.py"
    import os
    import requests

    response = requests.post(
        "https://api.qrdx.dev/v1/codes",
        headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},
        json={"destinationUrl": "https://example.com", "title": "My first code"},
    )
    response.raise_for_status()
    code = response.json()["data"]
    print(response.status_code, code["id"], code["shortLink"])
    ```
  </Tab>
</Tabs>

The response is `201 Created` with the new code:

```json title="201 Created"
{
  "data": {
    "id": "cmwgwq0t80000iscg4ybn05kh",
    "slug": "l0q9fZn",
    "shortLink": "https://qrdx.dev/q/l0q9fZn",
    "defaultShortLink": "https://qrdx.dev/q/l0q9fZn",
    "nfcLink": "https://qrdx.dev/q/l0q9fZn?nfc",
    "domain": null,
    "destinationUrl": "https://example.com/",
    "title": "My first code",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-11-14T21:17:45.512Z",
    "updatedAt": "2026-11-14T21:17:45.512Z",
    "organizationId": "ws_ad2c5e1cce31ccf31535e78f08ab5b78",
    "preciseLocation": false
  }
}
```

Two fields matter now. `shortLink` is what the QR code encodes: render it with the image API from step 1, `https://api.qrdx.dev/v1/qr?data=https://qrdx.dev/q/l0q9fZn&format=png`, and print that. `id` is how you refer to the code from now on, so keep it:

```bash title="Terminal"
export CODE_ID=cmwgwq0t80000iscg4ybn05kh
```

[Create codes](/docs/developers/api/create-codes) lists every field you can send, including a custom back-half and a design.

## 4. Point it somewhere else

Change the destination at any time; the printed code keeps working:

```bash title="Terminal"
curl -X PATCH https://api.qrdx.dev/v1/codes/$CODE_ID \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/new-page"}'
```

The `200 OK` response is the same code with `"destinationUrl": "https://example.com/new-page"` and a new `updatedAt`. Scan the code with your phone, then read its analytics:

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/codes/$CODE_ID/scans?range=7d" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

```json title="200 OK (before the first scan, trimmed)"
{
  "data": {
    "codeId": "cmwgwq0t80000iscg4ybn05kh",
    "range": "7d",
    "retentionDays": 365,
    "days": 7,
    "total": 0,
    "unique": 0,
    "interval": "day",
    "series": [{ "date": "2026-11-08", "count": 0 }, { "date": "2026-11-09", "count": 0 }],
    "countries": [],
    "devices": [],
    "sources": { "qr": 0, "nfc": 0 }
  }
}
```

After a scan, `total` goes up and `countries`, `cities`, `devices`, `os` and `browsers` fill in. [Get scan analytics](/docs/developers/api/get-code-scans) explains the ranges and how to page through individual scans.

## If something goes wrong

Every error is JSON with a stable `code` and a message that says what to do. The two you are most likely to meet on this page:

```json title="401 Unauthorized: the header is missing"
{
  "code": "UNAUTHORIZED",
  "message": "Missing API key. Send an API key as \"Authorization: Bearer <key>\"; create one at https://qrdx.dev/dashboard?to=settings/developers. OAuth access tokens go in the same header.",
  "status": 401,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

```json title="400 Bad Request: the destination isn't a full URL"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "data": { "details": [{ "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }] },
  "status": 400
}
```

A `401 INVALID_TOKEN` means the key was copied short, revoked or expired: create a new one. A `403 INSUFFICIENT_SCOPE` means you created a **Read only** key; step 3 needs `codes:write`. The [errors page](/docs/developers/errors) lists every code with its fix.

## Acting for other people [#get-an-access-token]

An API key acts as you. If your product calls QRdx for other people, register an OAuth app instead: each person approves it once, and your server gets an access token for their account, sent in the same `Authorization: Bearer` header. Every request above works unchanged with a token in place of the key. See [REST API and OAuth](/docs/developers/rest-api#get-an-access-token) and [Build an integration](/docs/developers/build-an-integration).
