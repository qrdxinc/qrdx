QRdx 的所有功能都可以通过代码调用。从你想构建的内容出发：每一行都列出了工具、使用它所需的条件，以及对应的页面。

| 你想要 | 使用 | 需要 |
| --- | --- | --- |
| 在网页、邮件或 README 中放入二维码 | [二维码图片 API](/docs/developers/image-api)：一个 `GET` URL 本身就是图片 | 无 |
| 为标签或商品数据源绘制条形码 | [条形码 API](/docs/developers/barcode-api)：用法相同，支持 EAN、UPC、Code 128 等 | 无 |
| 创建印刷后仍可改指向其他地址的二维码，并读取它们的扫描数据 | [REST API](/docs/developers/quickstart)：`POST /v1/codes`、`PATCH`、`GET …/scans` | 一个 [API 密钥](/docs/developers/api-keys) |
| 在你自己的系统中响应扫描、新建二维码或表单回答 | [Webhook](/docs/webhooks)：向你的 URL 发送带签名的 `POST` 请求 | API 密钥或控制台，Business 套餐 |
| 让 AI 助手在聊天中生成二维码 | [MCP 服务器](/docs/developers/mcp)：`https://mcp.qrdx.dev/mcp` | 无 |
| 通过脚本、构建流程或 CSV 生成二维码 | [CLI](/docs/developers/cli)：`npx @qrdx/cli` | Node.js 22 |
| 将二维码绘入 AI 艺术图 | [AI 艺术 API](/docs/developers/ai-art-api)：`POST /v1/art` | 一个 API 密钥，以及每月的 AI 艺术图额度 |
| 让其他人把他们的 QRdx 账户连接到你的产品 | [构建集成](/docs/developers/build-an-integration)：带 PKCE 的 OAuth 2.0 | 一个 OAuth 应用 |
| 在 n8n 中自动化 QRdx | [n8n 节点](/docs/developers/n8n)：`@qrdx/n8n-nodes-qrdx` | 自托管的 n8n |
| 在 React 应用中渲染带样式的二维码 | [React 库](/docs/getting-started)：`qrdx` 包 | npm |

## 两分钟发出第一个请求 [#first-request-in-two-minutes]

[快速开始](/docs/developers/quickstart)会用一个无需密钥的请求生成二维码图片，创建 API 密钥，创建动态二维码，并将它改指向其他地址。本页的其余内容都建立在这四个步骤之上。

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png" -o qr.png
```

## 基础 URL 与身份验证 [#base-url-and-authentication]

REST API 位于 `https://api.qrdx.dev/v1`。同样的路由也可通过 `https://qrdx.dev/api/v1` 访问，[自托管](/docs/self-hosting)实例则在其自己域名的 `/api/v1` 下提供这些路由。

请求通过 `Authorization: Bearer qrdx_…` 携带 [API 密钥](/docs/developers/api-keys)。密钥作用于创建它的工作区，并沿用你在该工作区中的角色。代表其他 QRdx 用户操作的应用，则在同一个请求头中改用 [OAuth 2.0 访问令牌](/docs/developers/rest-api#get-an-access-token)。图片、条形码和社区端点都不需要密钥或令牌。
