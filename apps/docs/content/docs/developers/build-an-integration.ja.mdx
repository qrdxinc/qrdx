このページを終えると、ユーザーはあなたのプロダクトで **Connect QRdx** をクリックし、QRdxの同意画面でアプリを承認できるようになります。あなたのサーバーは、ユーザーが承認したスコープの範囲内で、ユーザーに代わって `https://api.qrdx.dev/v1` を呼び出せるアクセストークンを保持します。

連携とはOAuthアプリのことです。1つのワークスペースであなた自身として動作する [APIキー](/docs/developers/api-keys) とは異なり、トークンはアプリを承認した本人として、その人自身のワークスペースに対して動作します。ユーザーはいつでもそのアクセスを取り消せます。

## 始める前に [#before-you-start]

- QRdxアカウント。フリーのワークスペースではOAuthアプリを1つ、Proでは5つ、Businessでは25個まで作成できます。ワークスペースには、オーナーが持つプランのうち最も上位のものが適用されます。
- シークレットを保管でき、リダイレクトを受け取れるサーバー。コードサンプルはFetch APIを使ったNode.jsですが、HTTPSとSHA-256が使える言語であれば何でも利用できます。
- 使用する2つの `https://` リダイレクトURI。本番用と開発用です（開発用には `http://localhost` も使えます）。

## 1. OAuthアプリを作成する [#1-create-an-oauth-app]

[設定 → APIキーとアプリ](/dashboard?to=settings/developers) を開き、**New app** を選びます。アプリは、現在開いているワークスペースに属します。アプリを作成・変更できるのはワークスペースのオーナーだけです。管理者とメンバーは閲覧のみ可能です。

<Shot id="oauth-new-app-form" />

| 項目 | 用途 |
| --- | --- |
| **Name**、**Description**、**Logo**、**Website** | 同意画面に表示されます。128 × 128 px以上の正方形のロゴをアップロードするか、ロゴへの `https://` リンクを貼り付けます |
| **Redirect URIs** | QRdxがユーザーを戻す先です。1行に1つ、最大10個まで登録できます。使えるのは `https://` のみで、開発用に `http://localhost` も使えます。ワイルドカードや `#fragments` は使えません。すべてのリクエストで、登録したいずれかを完全に一致する形で送る必要があります |
| **Scopes** | アプリが要求できる最大の範囲です。各認可リクエストでは、そのうちの一部またはすべてを要求します |
| **Require PKCE** | すべての認可リクエストで `S256` のコードチャレンジを送る必要があります。推奨設定で、デフォルトでオンです |

保存すると、QRdxに **Client ID** と **Client secret** が表示されます。シークレットはこのときに必ずコピーしてください。QRdxはそのハッシュしか保存しておらず、再表示できません。紛失した場合や漏洩した場合は、アプリのページで **Regenerate secret** を選びます。古いシークレットはただちに使えなくなりますが、すでに接続しているユーザーの接続は維持されます。アプリの作成とシークレットの再生成では、そのブラウザーで直近10分以内に本人確認をしていない限り、先に[本人確認](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)を求められます。

<Shot id="oauth-app-credentials" />

両方の値をサーバー上で保管してください。

```bash title=".env"
QRDX_CLIENT_ID=qrdx_app_...
QRDX_CLIENT_SECRET=qrdx_secret_...
```

## 2. ユーザーをQRdxへ誘導する [#2-send-people-to-qrdx]

ランダムな `state` とPKCEの `code_verifier` を生成して、両方をユーザーのセッションに保存し、認可URLへリダイレクトします。

```txt title="Authorize URL"
https://qrdx.dev/api/oauth/authorize
  ?response_type=code
  &client_id=<client id>
  &redirect_uri=https://acme.example/oauth/qrdx/callback
  &scope=profile:read codes:read codes:write
  &state=<random value>
  &code_challenge=<BASE64URL(SHA256(code_verifier))>
  &code_challenge_method=S256
```

| パラメーター | 必須 | 値 |
| --- | --- | --- |
| `response_type` | はい | `code` |
| `client_id` | はい | アプリのクライアントID |
| `redirect_uri` | はい | アプリのリダイレクトURIのいずれか（1文字も違わず一致させる） |
| `scope` | はい | スペースまたはカンマ区切り。アプリが持つスコープのみ指定できます |
| `state` | 推奨 | 任意の値。QRdxはそのまま返します。戻ってきたときに検証して、クロスサイトリクエストフォージェリを防ぎます |
| `code_challenge` | アプリがPKCEを必須にしている場合 | 43〜128文字。`code_verifier` のSHA-256をbase64urlでエンコードした値 |
| `code_challenge_method` | いいえ | `S256`。デフォルトであり、受け付ける唯一の方式です。`plain` は `invalid_request` で拒否されます |
| `prompt` | いいえ | `consent` を指定すると、ユーザーが以前にこれらのスコープを承認していても同意画面を表示します |

```ts title="lib/qrdx-oauth.ts"
import { createHash, randomBytes } from "node:crypto";

export const QRDX_AUTHORIZE_URL = "https://qrdx.dev/api/oauth/authorize";

export function createPkce() {
  const verifier = randomBytes(32).toString("base64url"); // 43 characters
  const challenge = createHash("sha256").update(verifier).digest("base64url");
  return { verifier, challenge };
}

export function authorizeUrl({ state, challenge }: { state: string; challenge: string }) {
  const url = new URL(QRDX_AUTHORIZE_URL);
  url.search = new URLSearchParams({
    response_type: "code",
    client_id: process.env.QRDX_CLIENT_ID!,
    redirect_uri: "https://acme.example/oauth/qrdx/callback",
    scope: "profile:read codes:read codes:write",
    state,
    code_challenge: challenge,
    code_challenge_method: "S256",
  }).toString();
  return url.toString();
}
```

QRdxにサインインしていないユーザーは、先にサインインします。その後、同意画面が表示されます。同意画面には、アプリのロゴ、名前、ウェブサイト、開発者、要求した権限、サインインしているアカウントが表示されます。QRdxが審査していないアプリには **Unverified app.** の注記が付きます。**Authorize** では、直近10分以内に本人確認をしていない限り、[本人確認](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)を求められます（直前のサインインも確認済みとして扱われます）。すでにそのアプリに同じスコープを承認しているユーザーは、そのままあなたのアプリに戻ります。

<Shot id="oauth-consent-screen" />

その後、QRdxは `redirect_uri` にリダイレクトします。

- 承認された場合: `?code=<authorization code>&state=<your state>`。コードは1回のみ、10分以内に使用できます。
- キャンセルされた場合: `?error=access_denied&error_description=...&state=<your state>`。

無効なリクエストはリダイレクトされず、OAuth 2.0の形式のJSONで応答します。不明な `client_id` は `invalid_client`、未登録の `redirect_uri` や `plain` のチャレンジは `invalid_request`、アプリが持たないスコープは `invalid_scope` になります。

```json title="400 Bad Request"
{"error":"invalid_scope","error_description":"Invalid or unsupported scope"}
```

## 3. コードをトークンと交換する [#3-exchange-the-code-for-tokens]

サーバーから、トークンエンドポイントにコードをPOSTします。ボディはフォームエンコード形式で、`redirect_uri` はステップ2で使用したものと同じである必要があります。

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=authorization_code \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d code=$CODE \
  -d redirect_uri=https://acme.example/oauth/qrdx/callback \
  -d code_verifier=$CODE_VERIFIER
```

```ts title="app/oauth/qrdx/callback/route.ts"
export async function GET(req: Request) {
  const params = new URL(req.url).searchParams;
  const session = await getSession(req); // your own session store
  if (params.get("state") !== session.qrdxState) {
    return new Response("Invalid state", { status: 400 });
  }
  if (params.get("error")) {
    return Response.redirect("https://acme.example/settings?qrdx=canceled");
  }

  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "authorization_code",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      code: params.get("code") ?? "",
      redirect_uri: "https://acme.example/oauth/qrdx/callback",
      code_verifier: session.qrdxVerifier,
    }),
  });
  if (!response.ok) {
    const { error, error_description } = await response.json();
    throw new Error(`QRdx token exchange failed: ${error} ${error_description}`);
  }

  const tokens: {
    access_token: string;
    token_type: "Bearer";
    expires_in: number;
    refresh_token: string;
    scope: string;
  } = await response.json();
  await saveQrdxTokens(session.userId, tokens); // encrypt at rest
  return Response.redirect("https://acme.example/settings?qrdx=connected");
}
```

```json title="Response fields"
{
  "access_token": "<send as Authorization: Bearer>",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "<store encrypted; it rotates on each refresh>",
  "scope": "profile:read codes:read codes:write"
}
```

`scope` には、付与された内容がスペース区切りで並びます。アクセストークンの有効期間は1時間、リフレッシュトークンは30日です。`code_verifier` は、認可リクエストに `code_challenge` があった場合に限って送ってください。チャレンジなしで発行されたコードにverifierを送ると拒否されます。シークレットが誤っている場合や、すでに使用済みのコードの場合は `invalid_client` または `invalid_grant` が返り、サポートされている2つ以外のグラントタイプを指定した場合は次のように返ります。

```json title="400 Bad Request"
{"error":"unsupported_grant_type","error_description":"Supported: authorization_code, refresh_token"}
```

## 4. トークンを更新する [#4-refresh-tokens]

アクセストークンの有効期限が切れる前に、リフレッシュトークンを新しいトークンのペアと交換します。リフレッシュトークンはローテーションされます。各トークンは1回しか使えないため、毎回新しいものを保存してください。

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=refresh_token \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d refresh_token=$REFRESH_TOKEN
```

```ts title="lib/qrdx-oauth.ts"
export async function refreshQrdxTokens(refreshToken: string) {
  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "refresh_token",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      refresh_token: refreshToken,
    }),
  });
  // invalid_grant: revoked, expired or already used. Ask the person to reconnect.
  if (!response.ok) throw new Error((await response.json()).error);
  return response.json();
}
```

トークンエンドポイントは、IPアドレスごとに1分あたり30リクエストまで受け付けます。

## 5. APIを呼び出す [#5-call-the-api]

アクセストークンをBearerトークンとして `https://api.qrdx.dev/v1` に送ります。トークンを使ったリクエストは、アプリを承認したユーザー自身のワークスペース（どのアカウントにも1つあります）に対して、そのワークスペースのプランと[1日あたりのクォータ](/docs/developers/rest-api#rate-limits)の範囲内で動作します。要求するスコープは、連携に必要な最小限にしてください。ユーザーは同意画面で各スコープを確認します。

| スコープ | 許可される内容 |
| --- | --- |
| `profile:read` | ユーザーのID、名前、メールアドレス、アバター: `GET /v1/me` と `GET /api/oauth/userinfo` |
| `themes:read` | 保存済みのQRテーマ: `GET /v1/themes`、`GET /v1/themes/{id}` |
| `codes:read` | 動的QRコード、スキャン分析、保存済みのバーコード。フックの一覧取得 |
| `codes:write` | `codes:read` で許可されるすべてに加え、コードとバーコードの作成・編集・削除、コンバージョンの報告、イベントの購読 |

```ts title="lib/qrdx.ts"
const response = await fetch("https://api.qrdx.dev/v1/codes", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${accessToken}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    destinationUrl: "https://acme.example/menu",
    title: "Spring menu",
  }),
});
const { data: code } = await response.json(); // code.shortLink is what the QR encodes
```

`401 INVALID_TOKEN` は、トークンの有効期限が切れたか、取り消されたことを意味します。トークンを更新するか、ユーザーに再接続を依頼してください。`403 INSUFFICIENT_SCOPE` は、トークンに必要なスコープがないことを意味します。すべてのエンドポイントとそのスコープ、エラーは [APIリファレンス](/docs/developers/api) に記載しています。

## 6. Webhookでイベントを受信する [#6-receive-events-with-webhooks]

ユーザーにURLの貼り付けを求める代わりに、REST Hooks APIを使ってユーザーに代わって購読します。`codes:write` が必要で、ユーザーのプランに[Webhook](/docs/webhooks)（Business）が含まれている必要があります。含まれていない場合は `402 PLAN_REQUIRED` が返ります。

```bash title="Terminal"
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://acme.example/webhooks/qrdx", "events": ["scan.created", "form.submitted"]}'
```

`201` レスポンスには、購読の `id` と署名用の `secret` が含まれます。`secret` は一度しか表示されません。すべての配信は、この `secret` で署名され、`X-QRdx-Signature` に格納されます。詳しくは [署名を検証する](/docs/webhooks#verify-signatures) を参照してください。ユーザーが接続を解除したときは、`DELETE /v1/hooks/{id}` で購読を解除します。購読は、ユーザー自身のワークスペースの **設定 → Webhook** にも表示され、ユーザーはそこから削除できます。

## 7. 接続の解除とユーザーの識別 [#7-disconnect-and-identify-people]

ユーザーがあなたのプロダクトでQRdxとの接続を解除したときは、そのユーザーのトークンを取り消します。ペアのどちらか一方のトークンを取り消すと、ペア全体が取り消されます。このエンドポイントは、不明なトークンに対しても `200` を返します。

```bash title="Terminal"
curl -X POST https://qrdx.dev/api/oauth/revoke -d token=$REFRESH_TOKEN
```

ユーザーは、QRdxの **設定 → 承認済みアプリ** で **Revoke access** を選ぶことで、いつでも自分でアクセスを取り消せます。あなたのアプリがそのユーザーのアカウントに対して保持しているすべてのトークンは、ただちに使えなくなります。API呼び出しは `invalid_token` を伴う `401` を返し、トークンの更新は `invalid_grant` を返します。どちらも「接続解除」として扱い、ユーザーに再度接続を依頼してください。ユーザーには再び同意画面が表示されます。

接続したユーザーを識別するには、`profile:read` のトークンで `GET /api/oauth/userinfo` を呼び出します。OpenID形式のクレーム `sub`、`name`、`email`、`picture` が返されます。メールアドレスは変更される可能性があるため、安定したアカウントIDとして `sub` を使用してください。

```bash title="Terminal"
curl https://qrdx.dev/api/oauth/userinfo -H "Authorization: Bearer $ACCESS_TOKEN"
```

```json title="401 Unauthorized: an expired or revoked token"
{"error":"invalid_token","error_description":"Invalid or expired token"}
```

## 8. 掲載をリクエストする [#8-get-listed]

連携がエンドツーエンドで動作したら、[連携ディレクトリ](/integrations)への追加を依頼できます。あなたが開発したコミュニティ連携として掲載されます。アプリのページで **Get listed** を選ぶと、詳細が入力された状態で [support@qrdx.dev](mailto:support@qrdx.dev?subject=List%20my%20integration) 宛てのメールが開きます。

- アプリの名前とクライアントID
- 何をするものか、誰向けかを説明する1行
- セットアップ手順、またはその手順へのリンク
- サポート窓口

QRdxチームは掲載アプリを審査し、**Verified** のマークを付けます。これにより、同意画面から **Unverified app.** の注記が消えます。確認済みアプリの名前、ロゴ、ウェブサイトを変更すると、再審査が完了するまでバッジは外れます。

## 問題が発生した場合 [#if-something-goes-wrong]

### `invalid_request: redirect_uri not registered` [#invalid_request-redirect_uri-not-registered]

認可URLの `redirect_uri` が、アプリに登録されているリダイレクトURIのいずれとも一字一句一致していません。スキームや末尾のスラッシュも含めて一致する必要があります。アプリにそのURIを追加するか、URLを修正してください。

### `invalid_scope` [#invalid_scope]

認可URLで、アプリが持っていないスコープを要求しています。**設定 → APIキーとアプリ**でアプリにスコープを追加してから、もう一度要求してください。

### 更新時の `invalid_grant` [#invalid_grant-on-refresh]

リフレッシュトークンがすでに使用済み（更新のたびに新しいトークンが返されます）、30日で期限切れ、またはユーザーがアプリを取り消した可能性があります。ユーザーをもう一度認可の手順に進めてください。

### シークレットを再生成した後にトークンが使えなくなる [#tokens-stop-working-after-you-regenerated-the-secret]

新しいシークレットが使われるのは新規のトークンリクエストだけで、既存のアクセストークンとリフレッシュトークンは引き続き有効です。すべてのサーバーインスタンスが新しい `QRDX_CLIENT_SECRET` を読み込んでいるか確認してください。

## セキュリティチェックリスト [#security-checklist]

- クライアントシークレットはサーバー上で保管してください。ブラウザやモバイルのコードからは決して見えないようにします。
- 認可のたびに、PKCE（`S256`）と新しい `state` を使用し、戻ってきたときに `state` を確認してください。
- リダイレクトURIは正確に登録してください。QRdxは一字一句一致するかどうかで比較します。
- アクセストークンとリフレッシュトークンは暗号化して保存し、更新のたびに新しいリフレッシュトークンを保存してください。
- ユーザーが連携を解除したら、トークンを取り消してください。**設定 → APIキーとアプリ**でアプリを削除すると、発行したすべてのトークンが取り消されます。一時停止した場合は、再開するまでトークンが拒否されます。
