Todos los errores de la REST API son JSON con la misma estructura, sin importar qué endpoint los devuelva. Basa tu lógica en `code`, que nunca cambia; `message` está escrito para personas y puede reformularse.

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## Códigos de error [#error-codes]

Ordenados por estado. Un código que aparece dos veces tiene un significado distinto en cada estado.

| Estado | Código | Cuándo ocurre | Qué hacer |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | El cuerpo, la consulta o la ruta no superaron la validación. `data.details` enumera cada problema como `{ path, message }` (`{ param, message }` en la Image API), con el `index` de la fila cuando el cuerpo es un array de códigos. | Corrige los campos indicados en `data.details` y vuelve a enviar la solicitud. |
| 400 | `INVALID_SLUG` | El back-half personalizado (`slug`) incumple una regla: es una palabra reservada, o el mismo back-half aparece dos veces en una solicitud. En un array, `data.details` enumera cada fila por `index`. | Elige otro back-half. El mensaje indica la regla. |
| 400 | `TOO_MANY_CODES` | Hay más de 1.000 códigos en una solicitud. Normalmente el esquema del cuerpo lo rechaza antes, como `VALIDATION_ERROR`. | Envía como máximo 1.000 códigos por solicitud. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` apunta a un dominio personalizado que aún no está verificado. | Termina de verificar el dominio en la página Dominios, o no incluyas `domainId`. |
| 400 | `SID_REQUIRED` | Una conversión sin el `qrdx_sid` del escaneo (desde el navegador), o sin `sid` ni `code` (desde un servidor). | Envía el `qrdx_sid` que el enlace corto añadió a la URL de tu página o, con una clave de API o un token, el id del código como `code`. |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` es demasiado largo para el arte con IA (más de 300 caracteres). | Envía en su lugar el id de un código dinámico como `code`: el arte codifica su enlace corto, que es breve y sigue siendo editable. |
| 401 | `UNAUTHORIZED` | No hay credenciales: la solicitud no tiene el encabezado `Authorization: Bearer` (ni sesión de navegador de QRdx). | Envía una clave de API como `Authorization: Bearer <key>`; crea una en Ajustes → Claves de API y apps. Los tokens de acceso de OAuth van en el mismo encabezado. |
| 401 | `INVALID_TOKEN` | La clave de API o el token de acceso es desconocido, fue revocado o caducó (los tokens de acceso duran una hora), o el creador de la clave fue bloqueado o dejó el espacio de trabajo de la clave. | Comprueba que enviaste la clave completa, o crea una nueva. Para un token de acceso, obtén uno nuevo con tu token de actualización, o haz que el usuario vuelva a autorizar. |
| 402 | `PLAN_REQUIRED` | La función no está en el plan del espacio de trabajo: la creación masiva, los back-halves personalizados y los dominios personalizados requieren Pro; las conversiones y los hooks requieren Business. | Mejora el plan del espacio de trabajo, o quita la función de la solicitud. |
| 402 | `LIMIT_REACHED` | El espacio de trabajo tiene tantos códigos dinámicos activos como incluye su plan (10 en Gratis). | Archiva un código (los códigos archivados no cuentan) o mejora a Pro para tener códigos ilimitados. |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | El espacio de trabajo ha usado las imágenes de arte con IA de este mes (Gratis y Pro). No se cobró nada por la solicitud. | Espera a que la cuota se restablezca el día 1 del mes (UTC), o mejora el plan para tener más imágenes. |
| 403 | `INSUFFICIENT_SCOPE` | La clave de API o el token es válido, pero no tiene el alcance que necesita este endpoint. | Crea una clave con el alcance indicado en el mensaje (los alcances de una clave no se pueden cambiar). Para una app OAuth, añade el alcance y solicítalo cuando el usuario autorice. |
| 403 | `FORBIDDEN` | El solicitante no puede hacer esto: un miembro del espacio de trabajo que elimina un código creado por otra persona, un miembro que gestiona hooks, o una escritura con sesión de navegador desde otro sitio. Una clave de API solo puede hacer lo que permite el rol de su creador en su espacio de trabajo. | Pide ayuda a un propietario o administrador del espacio de trabajo, o llama a la API con una clave de API desde tu servidor. |
| 403 | `CONFIRMATION_REQUIRED` | Crear un hook con una sesión de navegador iniciada requiere una confirmación reciente de "Confirma que eres tú". A las claves de API y los tokens de OAuth no se les pide. | Confirma que eres tú en QRdx y vuelve a intentarlo en un plazo de 10 minutos, o crea el hook con una clave de API desde tu servidor. |
| 403 | `CONVERSIONS_OFF` | Una conversión desde el navegador para un código que no tiene activado el seguimiento de conversiones. | Activa el seguimiento de conversiones del código, o informa de la conversión desde tu servidor con una clave de API. |
| 403 | `LIMIT_REACHED` | El espacio de trabajo ya tiene 20 endpoints de webhook y hooks. | Elimina un endpoint o un hook que ya no uses. |
| 404 | `NOT_FOUND` | No existe ese endpoint, o el código, hook, tema o dominio personalizado no existe en el espacio de trabajo en el que actúa la clave o el token. | Revisa la ruta y el id. Una clave de API actúa en el espacio de trabajo donde se creó; un token de OAuth actúa en el espacio de trabajo propio de su usuario. |
| 404 | `INVALID_SID` | El `qrdx_sid` es desconocido o tiene más de 30 días, la ventana de atribución. | Envía el `qrdx_sid` de un escaneo reciente, o informa de la conversión por id de código desde tu servidor. |
| 409 | `SLUG_TAKEN` | Otro código ya usa ese back-half en ese dominio. En un array, `data.details` enumera cada back-half ocupado por `index`, y no se crea nada. | Elige otro back-half. |
| 413 | `PAYLOAD_TOO_LARGE` | El cuerpo supera el límite del endpoint: 4 MB para códigos, 16 KB para hooks, 8 KB para conversiones. También un lote de códigos cuya respuesta (cada código con su diseño) superaría los 4 MB; no se crea nada. | Envía un cuerpo más pequeño. En el caso de los códigos, la causa habitual es un logo en línea grande; en un lote, envía `Prefer: return=minimal` o menos códigos. |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | La imagen `photo` o `reference` supera el límite de tamaño del arte con IA (el mensaje indica cuál). | Reduce el tamaño de la imagen (una `reference` a unos 512 px en su lado más largo, una `photo` a unos 1024 px cuadrados) y envíala de nuevo como una URL de datos PNG o JPEG. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Una escritura sin `Content-Type: application/json`. | Envía un cuerpo JSON con `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk marca la URL de destino (malware, phishing o software no deseado). En un array, `data.details` enumera cada fila marcada por `index`, y no se crea nada. | Usa otro destino. Si la marca es errónea, pide a Google que revise el sitio. |
| 429 | `RATE_LIMITED` | Demasiadas solicitudes: un límite por minuto (solo se establece `Retry-After`) o la cuota diaria del espacio de trabajo (`Retry-After` más `X-RateLimit-*`). | Espera los segundos indicados en `Retry-After`. Para la cuota diaria, espera a las 00:00 UTC o mejora el plan. |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Un espacio de trabajo Business ha usado las imágenes de arte con IA de este mes, que comparte todo el equipo. | Espera a que la cuota se restablezca el día 1 del mes (UTC). |
| 429 | `AI_ART_DAILY_LIMIT` | El creador de la clave ha generado 25 imágenes de arte con IA hoy (UTC), un tope de seguridad además de la cuota mensual. | Inténtalo de nuevo mañana (UTC). |
| 500 | `INTERNAL_ERROR` | Algo falló en QRdx. Quedó registrado. | Inténtalo de nuevo en un momento. Si sigue ocurriendo, infórmalo indicando la hora de la solicitud. |
| 502 | `AI_ART_FAILED` | El modelo de imágenes falló, rechazó el prompt o devolvió una imagen que QRdx no pudo leer. No se usó ningún crédito de arte con IA. | Inténtalo de nuevo, o reformula el prompt. El mensaje indica qué pasó. |
| 502 | `AI_ART_UNSCANNABLE` | No se pudo lograr que la imagen del modelo se escaneara con la visibilidad del QR que elegiste. No se usó ningún crédito de arte con IA. | Inténtalo de nuevo con una `visibility` más alta, u otra semilla. |
| 502 | `AI_ART_DESCRIBE_FAILED` | No incluiste `prompt`, y el modelo de texto que escribe uno por ti falló. No se usó ningún crédito de arte con IA. | Inténtalo de nuevo, o envía tu propio `prompt`. |
| 503 | `SLUG_UNAVAILABLE` | No se pudo reservar a tiempo ningún slug libre de enlace corto. | Envía de nuevo la misma solicitud. |
| 503 | `AI_ART_BUSY` | El modelo de imágenes está ahora por encima de su capacidad. No se usó ningún crédito de arte con IA. | Espera un minuto e inténtalo de nuevo. |
| 503 | `AI_NOT_CONFIGURED` | El arte con IA no está configurado en este despliegue (una instancia autoalojada sin `AI_GATEWAY_API_KEY`). | Usa la API de QRdx alojada, o configura Vercel AI Gateway en tu instancia. |
| 503 | `UNAVAILABLE` | Los dominios personalizados no están configurados en este despliegue (una instancia autoalojada sin ellos). | No incluyas `domainId`, o configura los dominios personalizados en tu instancia. |
| 504 | `AI_ART_TIMEOUT` | El modelo de imágenes tardó demasiado, y QRdx dejó de esperar antes del límite de un minuto de la solicitud. No se usó ningún crédito de arte con IA. | Inténtalo de nuevo. Las llamadas suelen tardar entre 15 y 45 segundos. |

## El cuerpo del error [#the-error-body]

| Campo | Qué es |
| --- | --- |
| `code` | Un código estable y legible por máquinas, de la tabla anterior |
| `message` | Qué salió mal y cómo solucionarlo, pensado para personas. El texto puede cambiar |
| `status` | El estado HTTP, repetido |
| `docs` | Una página que explica la solución, cuando existe |
| `data` | Detalle adicional en algunos errores. `VALIDATION_ERROR` enumera cada problema en `data.details` |

Un error de validación nombra todos los campos que fallaron. En un lote de códigos, cada problema incluye además el `index` de la fila, contado desde 0:

```json title="400 Bad Request"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Los endpoints de imagen (`GET /v1/qr`, `GET /v1/barcode`) informan de los parámetros de consulta como `{ "param", "message" }` en lugar de `{ "path", "message" }`.

## Reintentos [#retrying]

- **`429`:** espera el número de segundos indicado en `Retry-After` y luego envía la misma solicitud. Cuando se agota la cuota diaria, los encabezados `X-RateLimit-*` indican cuántas solicitudes permite el plan y cuándo se reinicia el contador (00:00 UTC). Un límite por minuto envía solo `Retry-After`. Consulta los [límites de uso](/docs/developers/rest-api#rate-limits).
- **`500`, `502`, `503` y `504`:** reintenta con retroceso exponencial, empezando en aproximadamente un segundo. Los errores `5xx` del arte con IA nunca consumen una imagen, así que reintentar no cuesta nada.
- **Otros `4xx`:** la misma solicitud fallará de la misma forma. Corrígela primero.

Reintentar `POST /v1/codes` es seguro cuando la solicitud incluye un encabezado `Idempotency-Key`: la misma clave devuelve los códigos que creó el primer intento, con `Idempotent-Replayed: true`, en lugar de crearlos dos veces ([Crear códigos](/docs/developers/api/create-codes)). Sin el encabezado, lista tus códigos antes de volver a enviar la solicitud. `POST /v1/conversions` se puede repetir sin riesgo cuando envías tu propio `id`: una repetición devuelve `200` con `duplicate: true`.

## `/v1/me` y `/v1/themes` [#v1me-and-v1themes]

Estos dos endpoints envían el mismo cuerpo más los campos OAuth que siempre han enviado, `error` y `error_description` (el mismo texto que `message`), para que los clientes antiguos sigan funcionando:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED o INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (cuota diaria) |
| `not_found` | NOT_FOUND (temas) |

## Endpoints de OAuth [#oauth-endpoints]

Los endpoints de OAuth bajo `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) siguen en cambio el estándar OAuth 2.0: `{ "error", "error_description" }`, donde `error` es uno de `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` o `access_denied`. Recibir `invalid_grant` al renovar significa que el token de renovación ya se usó (cada renovación devuelve uno nuevo), caducó a los 30 días o el usuario revocó tu aplicación: vuelve a enviar al usuario por el proceso de autorización. Consulta [REST API y OAuth](/docs/developers/rest-api#get-an-access-token).

## Endpoints desconocidos [#unknown-endpoints]

Una ruta bajo `/v1` que no existe devuelve `404 NOT_FOUND` como JSON, nunca una página HTML, con un enlace `docs` a la lista de endpoints. La [referencia de la API](/docs/developers/api) enumera todos los endpoints.
