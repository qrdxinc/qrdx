Ao final desta página, um workflow do n8n gera imagens de QR code, cria e edita códigos dinâmicos no seu workspace e consulta as leituras deles, e um segundo workflow é iniciado sempre que um código é lido, criado ou alterado ou que um formulário é enviado.

O pacote `@qrdx/n8n-nodes-qrdx` adiciona dois nós ao [n8n](https://n8n.io):

- **QRdx** gera imagens de QR code, cria e edita [QR codes dinâmicos](/docs/dynamic-qr-codes) e consulta as leituras deles e os seus temas salvos. Um AI Agent do n8n pode usá-lo como ferramenta.
- **QRdx Trigger** inicia um workflow quando seus códigos são lidos, criados ou alterados, ou quando alguém envia um formulário em uma [página hospedada](/docs/forms-and-pages).

<Callout type="info" title="n8n auto-hospedado">
O pacote está no npm como [`@qrdx/n8n-nodes-qrdx`](https://www.npmjs.com/package/@qrdx/n8n-nodes-qrdx) e é instalado em um n8n auto-hospedado. O n8n Cloud só executa community nodes verificados pelo n8n, e este ainda não foi verificado. Para receber eventos no n8n Cloud, use um [nó Webhook](#without-the-package).
</Callout>

## Antes de começar [#before-you-start]

- Um n8n auto-hospedado onde você possa instalar community nodes.
- Uma [chave de API](/docs/developers/api-keys) do workspace em que os nós devem trabalhar, para as operações de códigos, leituras e temas e para o trigger. Gerar imagens de QR não exige chave.
- Para o trigger: o plano Business, já que os [webhooks](/docs/webhooks) fazem parte dele, e o n8n acessível em um endereço `https://` público.

## 1. Instale os nós [#1-install-the-nodes]

No n8n, abra **Settings → Community Nodes**, escolha **Install**, digite `@qrdx/n8n-nodes-qrdx`, aceite o aviso sobre community nodes e escolha **Install**. Depois, procure por **QRdx** no painel de nós.

Se o seu n8n esconde essa página, ou você o gerencia pela linha de comando, instale o pacote na pasta `nodes` da pasta de usuário do n8n e reinicie o n8n:

```bash title="Terminal"
mkdir -p ~/.n8n/nodes
cd ~/.n8n/nodes
npm install @qrdx/n8n-nodes-qrdx
```

Se o n8n roda no Docker, execute os mesmos comandos dentro do contêiner (`docker exec -it n8n sh`) ou configure-os na sua imagem.

## 2. Conecte seu workspace [#2-connect-your-workspace]

Crie uma [chave de API](/docs/developers/api-keys) em [Configurações → Chaves de API e apps](/dashboard?to=settings/developers) e adicione no n8n uma credencial **QRdx API** com a chave. Deixe **Base URL** como `https://api.qrdx.dev/v1`, a menos que você [hospede o QRdx por conta própria](/docs/self-hosting); nesse caso, use o seu endereço seguido de `/api/v1`.

O n8n testa a credencial lendo o seu perfil, o que exige o escopo `profile:read`, então uma chave de **Acesso total** é o mais simples. Uma chave age no workspace em que foi criada.

## 3. Use o nó QRdx [#3-use-the-qrdx-node]

| Recurso | Operações |
| --- | --- |
| **QR Image** | **Generate** gera uma imagem PNG, WebP, SVG ou EPS. Sem chave de API, sem conta |
| **Code** | **Create**, **Get**, **Get Many**, **Update** (incluindo arquivar e restaurar), **Delete** |
| **Scan** | **Get Many** (leituras individuais, das mais recentes às mais antigas), **Get Summary** (totais, contagens diárias e principais países, cidades, dispositivos, navegadores e origens) |
| **Theme** | **Get**, **Get Many** |

**Generate** coloca a imagem em um campo binário que você pode anexar a um e-mail ou enviar para qualquer lugar. Você pode definir tamanho, cores, formatos do corpo, dos olhos e dos pontos dos olhos, correção de erros, margem, uma [moldura](/docs/features/frames) com seu texto e um ícone de logo. A saída também traz `url`: um link para a mesma imagem pela [API de imagens](/docs/developers/image-api), pronto para uma tag `<img>`.

As operações de códigos e leituras chamam a [REST API](/docs/developers/rest-api) com a sua chave e contam na cota diária de API do workspace. **Get Many** percorre as páginas de resultados para você. **Create** recebe a URL de destino e, nos campos adicionais, um título, um final de link personalizado (`slug`) e um domínio personalizado; **Update** recebe os mesmos campos, além de arquivar e restaurar. Os erros mantêm a mensagem original do QRdx: um final de link personalizado exige Pro ou Business, por exemplo, e no plano Grátis o nó mostra o [erro](/docs/developers/errors) `PLAN_REQUIRED` da API.

## 4. Inicie workflows a partir de eventos [#4-start-workflows-from-events]

Adicione o nó **QRdx Trigger**, escolha os **Events** e ative o workflow. O nó se inscreve pela [API REST Hooks](/docs/webhooks#zapier-make-and-n8n-rest-hooks) e cancela a inscrição quando você desativa o workflow. A inscrição aparece em **Configurações → Webhooks** enquanto estiver ativa.

| Evento | Quando |
| --- | --- |
| **Scans** | Códigos são lidos. As entregas são agrupadas: uma por minuto, com até 100 leituras e a contagem exata |
| **Scan Milestones** | A primeira leitura de um código, depois 10, 100, 500, 1.000 leituras e além |
| **New Codes** | Um QR code dinâmico é criado |
| **Code Changes** | O destino, o título, o design ou o domínio de um código muda |
| **Form Submissions** | Alguém envia um formulário em uma página hospedada |

O nó confere o `X-QRdx-Signature` de cada entrega com o segredo de assinatura que o QRdx devolveu na inscrição e responde `401` a qualquer coisa que não corresponda. Em **Options**, ative **Output One Item per Scan** para receber um lote de Scans como itens separados e **Include Test Events** para executar o workflow quando você escolher **Enviar teste** em **Configurações → Webhooks**. Os payloads são os descritos em [Webhooks](/docs/webhooks#payloads).

O trigger exige:

- o plano Business, já que os [webhooks](/docs/webhooks) fazem parte dele;
- uma chave de API com `codes:write` (**Acesso total**);
- o n8n em um endereço `https://` público, porque o QRdx não entrega para `localhost` nem para redes privadas. Atrás de um proxy, defina o `WEBHOOK_URL` do n8n. Isso vale também para a URL de teste que o n8n usa enquanto você escolhe **Listen for test event**.

## Sem o pacote [#without-the-package]

O QRdx pode entregar eventos direto a um nó **Webhook** do n8n, no n8n Cloud ou em um n8n auto-hospedado:

1. Adicione um nó Webhook, defina o método HTTP como `POST` e copie a URL de produção.
2. Ative o workflow. A URL de produção só responde enquanto o workflow está ativo.
3. Em [Configurações → Webhooks](/dashboard?to=settings/webhooks), escolha **Adicionar endpoint**, cole a URL e selecione os eventos.

Cada evento inicia o workflow com o payload em JSON. Para conferir as assinaturas, leia `X-QRdx-Signature` em um nó Code e [verifique-a](/docs/webhooks#verify-signatures) com o segredo de assinatura do endpoint.

## Se algo der errado [#if-something-goes-wrong]

### O teste da credencial falha [#the-credential-test-fails]

A chave não tem `profile:read` (uma chave **Personalizada** sem ele), foi revogada ou expirou, ou a **Base URL** aponta para o host errado. Uma chave de **Acesso total** com `https://api.qrdx.dev/v1` funciona.

### O trigger não ativa, ou `402 PLAN_REQUIRED` [#the-trigger-wont-activate-or-402-plan_required]

Os webhooks fazem parte do plano Business. Faça upgrade do workspace, ou use um nó Webhook e os alertas por e-mail das [Notificações](/docs/notifications).

### O trigger ativa, mas nada chega [#the-trigger-activates-but-nothing-arrives]

O QRdx não consegue alcançar o n8n: ele recusa `http://`, `localhost` e endereços privados, e não segue redirecionamentos. Coloque o n8n atrás de um nome de host `https://` público e defina `WEBHOOK_URL`. Depois, confira as entregas da inscrição em **Configurações → Webhooks**.

### `PLAN_REQUIRED` em Create [#plan_required-on-create]

Um final de link personalizado ou um domínio personalizado exige Pro ou Business. Deixe esses campos vazios no plano Grátis.
