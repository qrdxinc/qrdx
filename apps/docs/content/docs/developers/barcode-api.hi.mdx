इस पेज के अंत तक आपके पास `<img>` टैग, प्रोडक्ट फ़ीड या लेबल टेम्पलेट के लिए barcode इमेज का URL होगा, आप जान जाएँगे कि check digit और फ़ॉर्मैट कैसे validate होते हैं, और यह भी कि barcode को वर्कस्पेस में कैसे सेव करें ताकि बाद में उन्हें एडिट कर सकें।

`GET https://api.qrdx.dev/v1/barcode` एक barcode इमेज लौटाता है। सब कुछ query string में होता है, इसलिए URL ही इमेज है। यह [barcode generator](/barcode-generator) जैसे ही {facts.barcodeFormats} फ़ॉर्मैट उन्हीं नियमों के साथ बनाता है और वही SVG लौटाता है। अकाउंट या API key की ज़रूरत नहीं है।

```html title="index.html"
<img
  src="https://api.qrdx.dev/v1/barcode?format=ean13&data=590123412345"
  alt="EAN-13 barcode 5901234123457"
/>
```

उस नंबर में एक अंक कम है, इसलिए check digit (7) जोड़ दिया जाता है। सभी 13 अंक भेजें तो check digit की जाँच की जाती है: ग़लत होने पर `400` लौटता है और बताता है कि सही क्या होना चाहिए।

## 1. इमेज का अनुरोध करें [#1-request-an-image]

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -o box.png "https://api.qrdx.dev/v1/barcode?format=ean13&data=5901234123457&type=png&scale=3"
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="barcode.mjs"
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/barcode");
    url.search = new URLSearchParams({
      format: "ean13",
      data: "5901234123457",
      type: "png",
      scale: "3",
    }).toString();

    const response = await fetch(url);
    await writeFile("box.png", Buffer.from(await response.arrayBuffer()));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="barcode.py"
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/barcode",
        params={"format": "ean13", "data": "5901234123457", "type": "png", "scale": 3},
    )
    response.raise_for_status()
    open("box.png", "wb").write(response.content)
    ```
  </Tab>
</Tabs>

```txt title="Output"
200 image/png
box.png: PNG image data, 385 x 237, 8-bit/color RGBA, non-interlaced
```

शेल में URL को quotes में रखें ताकि `&` बना रहे, और जिन वैल्यू में `&`, `#`, `+` या स्पेस हों उन्हें encode करें, जैसे JavaScript में `encodeURIComponent` से।

## 2. और उदाहरण [#2-more-examples]

GS1-128 लॉजिस्टिक्स लेबल का वेक्टर PDF, जिसमें हर Application Identifier ब्रैकेट में है:

```bash title="Terminal"
curl -o pallet.pdf "https://api.qrdx.dev/v1/barcode?format=gs1-128&type=pdf&data=(01)09501101530003(17)261231(10)AB-123"
# 200 application/pdf, 1 page
```

गहरे नीले रंग का Code 128 शेल्फ़ लेबल, बार के नीचे टेक्स्ट के बिना, 90° घुमाया हुआ:

```txt
https://api.qrdx.dev/v1/barcode?format=code128&data=SHELF-A12&fg=1e3a8a&text=false&rotate=90
```

चौड़े मार्जिन वाला Data Matrix:

```txt
https://api.qrdx.dev/v1/barcode?format=datamatrix&data=SN-0042-7781&quietZone=4
```

## 3. वैल्यू को URL से बाहर रखें [#3-keep-the-value-out-of-the-url]

`POST https://api.qrdx.dev/v1/barcode` वही फ़ील्ड JSON में लेता है और वही फ़ाइल लौटाता है, बिना cache के। इसका उपयोग तब करें जब वैल्यू लॉग, हिस्ट्री या cache में नहीं जानी चाहिए, जैसा URL के साथ हो सकता है:

```bash title="Terminal"
curl -o label.png https://api.qrdx.dev/v1/barcode \
  -H "Content-Type: application/json" \
  -d '{"format":"datamatrix","data":"Internal note 42","type":"png"}'
# 200 image/png, Cache-Control: no-store
```

JSON में `text` boolean है और `scale`, `height`, `quietZone` और `rotate` संख्याएँ हैं। `Content-Type: application/json` के बिना भेजा गया body `415` देता है:

```json title="415 Unsupported Media Type"
{"code":"UNSUPPORTED_MEDIA_TYPE","message":"Send a JSON body with Content-Type: application/json.","status":415}
```

## पैरामीटर [#parameters]

| पैरामीटर | डिफ़ॉल्ट | विवरण |
| --- | --- | --- |
| `format` | ज़रूरी | barcode का प्रकार; देखें [फ़ॉर्मैट](#formats)। अक्षरों का केस और डैश मायने नहीं रखते: `EAN-13` भी चलता है |
| `data` | ज़रूरी | एन्कोड करने वाला नंबर या टेक्स्ट, अधिकतम 1,000 अक्षर (ज़्यादातर linear फ़ॉर्मैट में कम) |
| `type` | `svg` | `svg`, `png`, `jpg`, `webp`, `avif`, `pdf` या `eps` |
| `scale` | `4` | PNG, JPG, WebP और AVIF में प्रति module पिक्सल, `1` से `10` |
| `height` | फ़ॉर्मैट पर निर्भर | वेक्टर साइज़ पर linear barcode की बार की ऊँचाई मिलीमीटर में, `5` से `60` (EAN-13 के लिए 23) |
| `quietZone` | फ़ॉर्मैट का न्यूनतम | modules में खाली मार्जिन: linear barcode के हर तरफ़ (`0` से `20`), 2D कोड के चारों ओर (`0` से `10`) |
| `text` | `true` | linear barcode के नीचे अंक या टेक्स्ट प्रिंट करें |
| `fg` | `000000` | बार और टेक्स्ट, hex में |
| `bg` | `ffffff` | बैकग्राउंड, hex में |
| `rotate` | `0` | घड़ी की दिशा में घुमाव: `0`, `90`, `180` या `270` |

रंग `#` के बिना लिखें, या उसे `%23` के रूप में encode करें।

## फ़ॉर्मैट [#formats]

| `format` | Barcode | क्या लेता है |
| --- | --- | --- |
| `ean13` | EAN-13 | 12 अंक (check digit जुड़ता है) या 13 (जाँचा जाता है) |
| `ean8` | EAN-8 | 7 अंक या 8 |
| `upca` | UPC-A | 11 अंक या 12 |
| `upce` | UPC-E | 6 से 8 अंक, या 12 अंकों का UPC-A जिसे छोटा किया जा सके |
| `itf14` | ITF-14 | 13 अंक या 14 |
| `gs1-128` | GS1-128 | ब्रैकेट में Application Identifier और उनकी वैल्यू; GTIN और SSCC के check digit जोड़े या जाँचे जाते हैं; अधिकतम 48 अक्षर का डेटा |
| `code128` | Code 128 | अधिकतम 80 प्रिंट होने योग्य ASCII अक्षर |
| `code39` | Code 39 | अधिकतम 40 कैपिटल अक्षर, अंक, स्पेस और `- . $ / + %` |
| `datamatrix` | Data Matrix | 1,000 अक्षर तक कोई भी टेक्स्ट |
| `pdf417` | PDF417 | 1,000 अक्षर तक कोई भी टेक्स्ट |
| `aztec` | Aztec | 1,000 अक्षर तक कोई भी टेक्स्ट |

रिटेल नंबर (EAN, UPC, ITF-14, GS1-128 का GTIN) GS1 कंपनियों को लाइसेंस करता है। API कोई भी वैध नंबर बना देता है; वह उन्हें जारी या रजिस्टर नहीं करता।

## साइज़ [#sizes]

PNG, JPG, WebP और AVIF में हर module के लिए `scale` पिक्सल होते हैं, यानी सबसे पतली बार की चौड़ाई। 2D का एक सेल दो module चौड़ा होता है।

SVG, PDF और EPS प्रति module एक पॉइंट (0.353 mm) पर वेक्टर होते हैं, इसलिए डिफ़ॉल्ट पर EAN-13 लगभग 45 × 28 mm का बनता है, जो उसके नॉमिनल साइज़ का करीब 107% है। वेक्टर फ़ाइलों को अपने लेआउट में स्केल करें; रिटेल barcode के लिए 80% से 200% के बीच रखें और बार की ऊँचाई न काटें।

## रिस्पॉन्स [#responses]

सफल अनुरोध पर फ़ाइल इन चीज़ों के साथ लौटती है:

- `Content-Type` फ़ाइल के प्रकार का। EPS डाउनलोड के रूप में आता है (`Content-Disposition: attachment`); बाकी `ean13-5901234123457.png` जैसे फ़ाइल नाम के साथ इनलाइन खुलते हैं
- `GET` के लिए `Cache-Control: public, max-age=31536000, immutable`: एक ही query हमेशा वही बाइट लौटाती है। `POST` के रिस्पॉन्स `no-store` होते हैं
- `Access-Control-Allow-Origin: *`, इसलिए आप इसे किसी भी वेबसाइट से `fetch` कर सकते हैं

## सेव किए गए barcode [#saved-barcodes]

[API key](/docs/developers/api-keys) के साथ REST API barcode को key के वर्कस्पेस में रखता है, जहाँ वे डैशबोर्ड में **Barcodes** के तहत दिखते हैं। स्कोप कोड वाले ही हैं: सूची देखने और डाउनलोड के लिए `codes:read`, बदलाव के लिए `codes:write`।

```bash title="Terminal"
curl https://api.qrdx.dev/v1/barcodes \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"format":"ean13","value":"590123412345","title":"Spring box"}'
```

```json title="201 Created"
{
  "data": {
    "id": "cmwgwqcxo0003iscgecog7m1b",
    "title": "Spring box",
    "format": "ean13",
    "formatLabel": "EAN-13",
    "value": "5901234123457",
    "options": {
      "foreground": "#000000",
      "background": "#ffffff",
      "showText": true,
      "barHeightMm": 23,
      "quietZone": 11,
      "scale": 4,
      "rotation": 0
    },
    "folderId": null,
    "imageUrl": "https://qrdx.dev/api/v1/barcode?format=ean13&data=5901234123457",
    "createdAt": "2026-11-14T21:18:01.212Z",
    "updatedAt": "2026-11-14T21:18:01.212Z",
    "deletedAt": null,
    "organizationId": "ws_ad2c5e1cce31ccf31535e78f08ab5b78"
  }
}
```

12 अंकों की वैल्यू check digit के साथ लौटी, और `options` में फ़ॉर्मैट के डिफ़ॉल्ट हैं। हर सेव किए गए barcode का एक `imageUrl` होता है: `GET /v1/barcode` वाली ही तस्वीर, जिसे लिंक रखने वाला कोई भी लोड कर सकता है। नीचे का `/image` endpoint निजी है और उसके लिए key चाहिए।

| Endpoint | क्या करता है |
| --- | --- |
| [`GET /v1/barcodes`](/docs/developers/api/list-barcodes) | उनकी सूची देता है, हाल में बदले हुए पहले; `q`, `format`, `folderId`, `status=trash` से फ़िल्टर करें |
| [`POST /v1/barcodes`](/docs/developers/api/create-barcode) | एक सेव करता है। `options` में `foreground`, `background`, `showText`, `barHeightMm`, `quietZone`, `scale` और `rotation` लिए जाते हैं |
| [`GET /v1/barcodes/{id}`](/docs/developers/api/get-barcode) | एक barcode |
| [`PATCH /v1/barcodes/{id}`](/docs/developers/api/update-barcode) | उसका शीर्षक, फ़ॉर्मैट, वैल्यू, options या फ़ोल्डर बदलता है |
| [`DELETE /v1/barcodes/{id}`](/docs/developers/api/delete-barcode) | उसे ट्रैश में भेजता है (`{ "deleted": false, "trashed": true }`); `?permanent=true` उसे हमेशा के लिए हटा देता है |
| [`GET /v1/barcodes/{id}/image`](/docs/developers/api/get-saved-barcode-image) | फ़ाइल, जैसी सेव की गई थी वैसी बनी हुई: `type` और `scale` ऊपर की तरह। `Cache-Control: private, no-store` |

हर प्लान में barcode सेव होते हैं: फ़्री में 1,000 तक, Pro में 10,000 और Business में 100,000, ट्रैश को गिने बिना। ये अनुरोध वर्कस्पेस के रोज़ाना API कोटा में गिने जाते हैं और [REST API](/docs/developers/rest-api#rate-limits) के बाकी अनुरोधों की तरह `X-RateLimit-*` हेडर भेजते हैं।

## कुछ गड़बड़ हो जाए तो [#if-something-goes-wrong]

### `"param": "data"` के साथ `400` [#400-with-param-data]

वैल्यू फ़ॉर्मैट के नियम तोड़ती है। संदेश ठीक-ठीक बताता है कि क्या, चाहे check digit हो, लंबाई हो या अक्षरों का सेट:

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"EAN-13: The check digit should be 7, not 8. Check the number, or leave the last digit off and it's worked out for you."}]},"status":400}
```

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"Code 39: Code 39 has no lowercase letters. Use capitals, or Code 128 for mixed case."}]},"status":400}
```

### `"param": "format"` के साथ `400` [#400-with-param-format]

`format` या तो नहीं दिया गया है या [फ़ॉर्मैट](#formats) में दिए ग्यारह id में से कोई नहीं है। संदेश में उनकी सूची होती है।

### raster इमेज अस्वीकार हुई या कट गई [#the-raster-image-is-refused-or-cut]

raster इमेज एक तरफ़ से अधिकतम 6,000 पिक्सल की होती हैं। लंबी वैल्यू के लिए `scale` घटाएँ, या SVG या PDF इस्तेमाल करें।

### `429 RATE_LIMITED` [#429-rate_limited]

एक IP पते से प्रति मिनट {facts.imageApiPerMinute} से ज़्यादा अनुरोध, `GET` और `POST /v1/barcode` को मिलाकर। `Retry-After` में दिए सेकंड तक रुकें; `GET` रिस्पॉन्स एक साल तक cache हो सकते हैं, इसलिए हर इमेज एक ही बार लोड करें।

## सीमाएँ [#limits]

- **रेट लिमिट:** `GET` और `POST /v1/barcode` के लिए प्रति IP पता प्रति मिनट {facts.imageApiPerMinute} अनुरोध, जैसा [QR image API](/docs/developers/image-api) में है। सेव किए गए barcode REST API की प्रति मिनट सीमाओं और रोज़ाना कोटा के हिसाब से चलते हैं।
- **इमेज साइज़:** raster इमेज एक तरफ़ से अधिकतम 6,000 पिक्सल की होती हैं।
- **यहाँ स्कैन जाँच नहीं होती।** [barcode generator](/barcode-generator) डाउनलोड से पहले जो बनाता है उसे decode करके जाँचता है; API वही बनाता है जो आप माँगते हैं। टेस्ट प्रिंट करें और उन स्कैनर से स्कैन करें जो उसे असल में पढ़ेंगे।

## MCP [#mcp]

[MCP सर्वर](/docs/developers/mcp) में `generate_barcode` है, जो वैल्यू जाँचता है और इमेज URL के साथ PNG लौटाता है, और `save_barcode` है, जो कनेक्शन की API key के वर्कस्पेस में सेव करता है।

## सेल्फ़-होस्टिंग [#self-hosting]

ये endpoint QRdx वेब ऐप का हिस्सा हैं, इसलिए [सेल्फ़-होस्टेड](/docs/self-hosting) इंस्टेंस उन्हें आपके अपने डोमेन पर `/api/v1/barcode` और `/api/v1/barcodes` पर चलाता है।
