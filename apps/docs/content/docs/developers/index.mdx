Everything QRdx does is available to code. Start from what you want to build: each row names the tool, what it needs and the page that gets you there.

| You want to | Use | Needs |
| --- | --- | --- |
| Put a QR code in a page, an email or a README | [QR code image API](/docs/developers/image-api): a `GET` URL that is the image | Nothing |
| Draw a barcode for a label or a product feed | [Barcode API](/docs/developers/barcode-api): the same, for EAN, UPC, Code 128 and more | Nothing |
| Create codes you can point somewhere else after printing, and read their scans | [REST API](/docs/developers/quickstart): `POST /v1/codes`, `PATCH`, `GET …/scans` | An [API key](/docs/developers/api-keys) |
| React to scans, new codes or form answers in your own system | [Webhooks](/docs/webhooks): signed `POST` requests to your URL | An API key or the dashboard, Business plan |
| Let an AI assistant make QR codes in a chat | [MCP server](/docs/developers/mcp): `https://mcp.qrdx.dev/mcp` | Nothing |
| Make QR codes from a script, a build or a CSV | [CLI](/docs/developers/cli): `npx @qrdx/cli` | Node.js 22 |
| Paint a QR code into AI artwork | [AI art API](/docs/developers/ai-art-api): `POST /v1/art` | An API key, monthly AI art images |
| Let other people connect their QRdx account to your product | [Build an integration](/docs/developers/build-an-integration): OAuth 2.0 with PKCE | An OAuth app |
| Automate QRdx in n8n | [n8n nodes](/docs/developers/n8n): `@qrdx/n8n-nodes-qrdx` | A self-hosted n8n |
| Render styled codes inside a React app | [React library](/docs/getting-started): the `qrdx` package | npm |

## First request in two minutes

The [quickstart](/docs/developers/quickstart) makes a QR code image with one keyless request, creates an API key, creates a dynamic code and points it somewhere else. Everything else on this page builds on those four steps.

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png" -o qr.png
```

## Base URL and authentication

The REST API lives at `https://api.qrdx.dev/v1`. The same routes answer at `https://qrdx.dev/api/v1`, and a [self-hosted](/docs/self-hosting) instance serves them at `/api/v1` on its own domain.

Requests carry an [API key](/docs/developers/api-keys) as `Authorization: Bearer qrdx_…`. A key acts on the workspace it was created in, with your role there. Apps that act for other QRdx users send an [OAuth 2.0 access token](/docs/developers/rest-api#get-an-access-token) in the same header instead. The image, barcode and community endpoints need neither.
