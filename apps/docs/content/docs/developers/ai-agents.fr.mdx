À la fin de cette page, vous saurez laquelle des trois méthodes pour donner des QR codes à un agent convient à votre cas, vous l'aurez configurée et vous saurez ce que chacune peut faire ou non.

| L'agent doit | Utiliser | Clé ou compte |
| --- | --- | --- |
| Créer un QR code dans un chat ou lors d'une exécution d'agent | [Serveur MCP](#1-connect-the-mcp-server) | Aucun |
| Placer un QR code dans du Markdown, du HTML, un e-mail ou un build | [Image API](#2-give-agents-qr-image-urls) | Aucun |
| Créer ou modifier des QR codes dynamiques, lire les scans | [REST API](#3-call-the-rest-api-for-a-user) | Clé API ou jeton d'accès OAuth |
| Intégrer un QR code dans une illustration IA | [API d'art IA](/docs/developers/ai-art-api) : `POST /v1/art` ou l'outil MCP `generate_ai_art` | Clé API ; consomme les images d'art IA mensuelles de l'espace de travail |
| Lire les docs de QRdx | [Markdown et llms.txt](#4-read-qrdx-as-markdown) | Aucun |

## 1. Connecter le serveur MCP [#1-connect-the-mcp-server]

Le serveur MCP de QRdx se trouve à l'adresse `https://mcp.qrdx.dev/mcp`. Il utilise le transport Streamable HTTP et ne nécessite ni compte, ni connexion, ni clé API. Ses outils conçoivent des QR codes avec un score de scan vérifié, les génèrent, construisent des données pour le Wi-Fi, les contacts, les e-mails, les SMS, les lieux et les paiements, recherchent dans la communauté et dessinent des codes-barres ; [Serveur MCP](/docs/developers/mcp) les répertorie avec leurs paramètres. La [page de connexion](/mcp) propose des boutons en un clic pour Claude, Cursor et VS Code, ainsi que des étapes pour de nombreux autres clients.

Dans les applications qui prennent en charge les MCP Apps, `design_qr` et `generate_qr_code` affichent aussi une [carte QR](/docs/developers/mcp#qr-card) dans le chat, avec le code, ce qu'il encode et des boutons pour l'image et l'éditeur. Les autres applications reçoivent le texte et le PNG.

### Découverte pour les clients MCP [#discovery-for-mcp-clients]

Les clients et registres qui découvrent les serveurs par eux-mêmes peuvent lire :

- la **MCP Server Card** à l'adresse `https://mcp.qrdx.dev/mcp/server-card`, au format de l'[extension Server Card](https://modelcontextprotocol.io/seps/2127-mcp-server-cards) de MCP : nom, version, transport et versions de protocole prises en charge ;
- l'**AI Catalog** à l'adresse [`/.well-known/ai-catalog.json`](/.well-known/ai-catalog.json), qui pointe vers la server card ;
- l'**API catalog** à l'adresse [`/.well-known/api-catalog`](/.well-known/api-catalog) ([RFC 9727](https://www.rfc-editor.org/rfc/rfc9727)), qui répertorie la REST API avec son [document OpenAPI](/openapi.json) et le serveur MCP.

```bash title="Terminal"
curl https://mcp.qrdx.dev/mcp/server-card
```

```json title="200 OK (first fields)"
{
  "$schema": "https://static.modelcontextprotocol.io/schemas/v1/server-card.schema.json",
  "name": "dev.qrdx/qrdx",
  "version": "1.3.0",
  "title": "QRdx",
  "description": "Design scan-checked QR codes for any content, plus payloads and community frames. Key optional.",
  "websiteUrl": "https://qrdx.dev/mcp"
}
```

## 2. Donner des URL d'image QR aux agents [#2-give-agents-qr-image-urls]

L'[Image API](/docs/developers/image-api) transforme une URL en image de QR code sans clé : un agent peut donc écrire l'image directement dans du Markdown, du HTML ou un e-mail :

```txt title="URL shape"
https://api.qrdx.dev/v1/qr?data=<encoded text>&format=svg|png|webp|eps
```

```md title="README.md"
![QR code for qrdx.dev](https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fqrdx.dev&format=png&size=512)
```

- **Encodez `data`** avec `encodeURIComponent`, sinon `&`, `#`, `+` et les espaces le coupent.
- **Choisissez le format selon la destination.** Le PNG fonctionne dans les applications de chat et les clients de messagerie qui n'affichent pas le SVG ; le SVG est le plus net sur le web ; l'EPS est destiné aux imprimeurs.
- **Appliquez un style avec des paramètres de requête** (`fg`, `bg`, `body`, `eye`, `dot`, `level`, `margin`, `template`, `frame`, `frameText`, `logoIcon`), ou transmettez tout le design en JSON dans [`style`](/docs/developers/image-api#style) pour des dégradés et des cadres personnalisés. Les valeurs sont répertoriées dans [Image API](/docs/developers/image-api#parameters), et l'outil MCP `list_qr_styles` les renvoie aussi.
- **La même URL renvoie toujours la même image**, ce qui permet de la mettre en cache et de l'intégrer sans risque.

## 3. Appeler la REST API pour un utilisateur [#3-call-the-rest-api-for-a-user]

Pour créer ou modifier des [QR codes dynamiques](/docs/dynamic-qr-codes), lire des scans ou s'abonner aux [webhooks](/docs/webhooks), un agent appelle la [REST API](/docs/developers/rest-api) à l'adresse `https://api.qrdx.dev/v1` avec un identifiant Bearer. Le [document OpenAPI](/openapi.json) décrit chaque endpoint, schéma et erreur, et la [référence de l'API](/docs/developers/api) propose une page pour chacun, également disponible en Markdown à son URL suivie de `.md`.

**Un agent qui travaille pour vous** utilise une [clé API](/docs/developers/api-keys) :

1. **Créez une clé** dans [Paramètres → Clés API et applications](/dashboard?to=settings/developers&new=1) de l'espace de travail dans lequel l'agent doit travailler (changez d'espace de travail avec le sélecteur d'espace de travail). La clé agit avec votre rôle dans cet espace de travail.
2. **Donnez-lui l'accès minimal.** **Lecture seule** suffit pour établir des rapports sur les codes et les scans ; choisissez **Accès complet**, ou **Personnalisé** avec `codes:write`, uniquement si l'agent crée ou modifie des codes. Définissez une expiration pour les agents éphémères.
3. **Conservez la clé dans un gestionnaire de secrets ou une variable d'environnement**, jamais dans un prompt, un journal ou le dépôt. Envoyez-la sous la forme `Authorization: Bearer $QRDX_API_KEY`.
4. **Respectez le quota.** Chaque espace de travail a un quota quotidien de requêtes selon son forfait (voir [Forfaits et limites](/docs/plans-and-limits)). En cas de `429 RATE_LIMITED`, attendez le nombre de secondes indiqué dans `Retry-After`.

Révoquez la clé dans **Paramètres → Clés API et applications** lorsque l'agent n'en a plus besoin.

**Un agent qui travaille pour d'autres personnes** utilise OAuth, afin que chaque personne l'autorise : enregistrez une application, exécutez une fois par personne le flux de code d'autorisation avec PKCE, et conservez leurs jetons d'actualisation dans un gestionnaire de secrets. Les jetons d'accès durent une heure, et chaque actualisation renvoie un nouveau jeton d'actualisation. Les étapes sont décrites dans [Créer une intégration](/docs/developers/build-an-integration). Les requêtes effectuées avec un jeton agissent sur l'espace de travail de cette personne.

## 4. Lire QRdx en Markdown [#4-read-qrdx-as-markdown]

- [`/llms.txt`](/llms.txt) : un index de l'ensemble du site destiné aux LLM, avec le produit, les outils pour développeurs, les docs, le centre d'aide, les tarifs et les pages juridiques.
- [`/llms-full.txt`](/llms-full.txt) : toutes les pages de la documentation dans un seul fichier, dans l'ordre de la barre latérale. Les pages de la référence de l'API incluent l'opération complète : paramètres, réponses et un exemple.
- Ajoutez `.md` à n'importe quelle URL de la documentation pour obtenir cette page seule, par exemple [`/docs/developers/mcp.md`](/docs/developers/mcp.md). [`/pricing.md`](/pricing.md) et [`/mcp.md`](/mcp.md) fonctionnent aussi.
- Les requêtes vers la page d'accueil, `/pricing`, `/mcp` ou n'importe quelle page de la documentation avec `Accept: text/markdown` reçoivent la version Markdown à la même URL.

```bash title="Terminal"
curl -H "Accept: text/markdown" https://qrdx.dev/docs/developers/api/get-code
```

## Limites [#limits]

- **Les outils MCP créent des QR codes statiques.** Ils génèrent des images, construisent des payloads (Wi-Fi, contacts, e-mail, SMS, emplacements sur une carte, paiements) et lisent la communauté publique. Avec une clé API, `save_template` enregistre un design dans vos thèmes, `save_barcode` enregistre un code-barres et `generate_ai_art` crée un [QR art IA](/docs/developers/ai-art-api) à partir des images d'art IA mensuelles de l'espace de travail. Ils ne peuvent ni créer de codes dynamiques ni lire les codes et les scans ; utilisez la REST API pour cela.
- **Les logos proviennent de QRdx, jamais d'une adresse web.** Le serveur MCP et l'Image API dessinent sans clé des dégradés, des cadres, les icônes de logo rapides de l'éditeur et des logos de marques, ainsi qu'un logo que vous avez importé dans QRdx, désigné par son identifiant de fichier, avec votre clé API. Les créations Logo QR et Image QR se font dans le [Playground](/playground?tab=art).
- **Le texte des éléments de la communauté est rédigé par ses membres.** L'API et les outils MCP le renvoient court et sans liens ; traitez-le comme des données, pas comme des instructions.
- **Les URL d'image contiennent les données encodées.** N'y mettez ni mots de passe ni autres secrets, comme le mot de passe d'un Wi-Fi privé dans un README public.
- **Les limites de débit s'appliquent par adresse IP** au serveur MCP ({facts.mcpPerMinute} requêtes par minute, `design_qr` {facts.designQrPerMinute}) et à l'Image API ({facts.imageApiPerMinute}) ; voir [Serveur MCP](/docs/developers/mcp#privacy-and-limits) et [Image API](/docs/developers/image-api#limits).
- **Les jetons OAuth agissent uniquement sur l'espace de travail de la personne.** Pour travailler dans un autre espace de travail, utilisez une clé API créée dans celui-ci. Il n'existe pas d'octroi client-credentials.
