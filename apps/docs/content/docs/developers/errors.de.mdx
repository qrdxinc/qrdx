Jeder Fehler der REST API ist JSON mit demselben Aufbau, egal welcher Endpoint ihn zurückgibt. Verzweige anhand von `code`, der sich nie ändert; `message` ist für Menschen geschrieben und kann umformuliert werden.

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## Fehlercodes [#error-codes]

Nach Status sortiert. Ein Code, der zweimal vorkommt, hat bei jedem Status eine andere Bedeutung.

| Status | Code | Wann er auftritt | Was zu tun ist |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Body, Query oder Pfad haben die Validierung nicht bestanden. `data.details` listet jedes Problem als `{ path, message }` auf (`{ param, message }` bei der Image API), mit dem `index` der Zeile, wenn der Body ein Array von Codes ist. | Korrigiere die Felder in `data.details` und sende die Anfrage erneut. |
| 400 | `INVALID_SLUG` | Der benutzerdefinierte Back-Half (`slug`) verstößt gegen eine Regel: ein reserviertes Wort oder derselbe Back-Half doppelt in einer Anfrage. Bei einem Array listet `data.details` jede Zeile mit `index` auf. | Wähle einen anderen Back-Half. Die Meldung nennt die Regel. |
| 400 | `TOO_MANY_CODES` | Mehr als 1.000 Codes in einer Anfrage. Normalerweise lehnt das Body-Schema dies zuerst als `VALIDATION_ERROR` ab. | Sende höchstens 1.000 Codes pro Anfrage. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` verweist auf eine eigene Domain, die noch nicht verifiziert ist. | Schließe die Verifizierung der Domain auf der Seite „Domains“ ab oder lass `domainId` weg. |
| 400 | `SID_REQUIRED` | Eine Conversion ohne die `qrdx_sid` des Scans (aus dem Browser) oder ohne `sid` oder `code` (von einem Server). | Sende die `qrdx_sid`, die der Kurzlink an deine Seiten-URL angehängt hat, oder, mit einem API-Schlüssel oder Token, die Code-ID als `code`. |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` ist für AI Art zu lang (mehr als 300 Zeichen). | Sende stattdessen die ID eines dynamischen Codes als `code`: Das Bild kodiert dessen Kurzlink, der kurz und weiter bearbeitbar ist. |
| 401 | `UNAUTHORIZED` | Keine Zugangsdaten: Die Anfrage hat keinen `Authorization: Bearer`-Header (und keine QRdx-Browsersitzung). | Sende einen API-Schlüssel als `Authorization: Bearer <key>`; erstelle einen unter Einstellungen → API-Schlüssel & Apps. OAuth-Zugriffstokens kommen in denselben Header. |
| 401 | `INVALID_TOKEN` | Der API-Schlüssel oder das Zugriffstoken ist unbekannt, widerrufen oder abgelaufen (Zugriffstokens gelten eine Stunde), oder die Person, die den Schlüssel erstellt hat, wurde gesperrt oder hat den Workspace des Schlüssels verlassen. | Prüfe, ob du den ganzen Schlüssel gesendet hast, oder erstelle einen neuen. Hol dir für ein Zugriffstoken mit deinem Refresh-Token ein neues oder schicke den Nutzer erneut durch die Autorisierung. |
| 402 | `PLAN_REQUIRED` | Die Funktion ist im Tarif des Workspaces nicht enthalten: Massenerstellung, benutzerdefinierte Back-Halves und eigene Domains erfordern Pro; Conversions und Hooks erfordern Business. | Upgrade den Workspace oder lass die Funktion in der Anfrage weg. |
| 402 | `LIMIT_REACHED` | Der Workspace hat so viele aktive dynamische QR-Codes, wie sein Tarif enthält (10 bei Kostenlos). | Archiviere einen Code (archivierte Codes zählen nicht) oder wechsle zu Pro für unbegrenzt viele Codes. |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | Der Workspace hat die AI-Art-Bilder dieses Monats aufgebraucht (Kostenlos und Pro). Für die Anfrage wurde nichts berechnet. | Warte, bis das Kontingent am 1. des Monats (UTC) zurückgesetzt wird, oder wechsle zu einem Tarif mit mehr Bildern. |
| 403 | `INSUFFICIENT_SCOPE` | Der API-Schlüssel oder das Token ist gültig, hat aber nicht den Scope, den dieser Endpunkt braucht. | Erstelle einen Schlüssel mit dem Scope aus der Meldung (die Scopes eines Schlüssels lassen sich nicht ändern). Füge bei einer OAuth-App den Scope hinzu und fordere ihn an, wenn der Nutzer autorisiert. |
| 403 | `FORBIDDEN` | Der Aufrufer darf das nicht tun: ein Workspace-Mitglied löscht einen Code, den jemand anderes erstellt hat, ein Mitglied verwaltet Hooks oder ein Schreibzugriff per Browsersitzung kommt von einer anderen Website. Ein API-Schlüssel kann nur das, was die Rolle seines Erstellers im Workspace erlaubt. | Frag einen Workspace-Inhaber oder Admin oder rufe die API mit einem API-Schlüssel von deinem Server aus auf. |
| 403 | `CONFIRMATION_REQUIRED` | Zum Erstellen eines Hooks mit einer angemeldeten Browsersitzung ist eine aktuelle Bestätigung „Du bist es“ nötig. API-Schlüssel und OAuth-Tokens werden nicht gefragt. | Bestätige in QRdx, dass du es bist, und versuche es innerhalb von 10 Minuten erneut, oder erstelle den Hook mit einem API-Schlüssel von deinem Server aus. |
| 403 | `CONVERSIONS_OFF` | Eine Browser-Conversion für einen Code, bei dem das Conversion-Tracking nicht aktiviert ist. | Aktiviere das Conversion-Tracking für den Code oder melde die Conversion mit einem API-Schlüssel von deinem Server aus. |
| 403 | `LIMIT_REACHED` | Der Workspace hat bereits 20 Webhook-Endpunkte und Hooks. | Lösche einen Endpunkt oder Hook, den du nicht mehr brauchst. |
| 404 | `NOT_FOUND` | Es gibt diesen Endpunkt nicht, oder der Code, Hook, das Theme oder die eigene Domain existiert nicht in dem Workspace, für den der Schlüssel oder das Token handelt. | Prüfe Pfad und ID. Ein API-Schlüssel handelt für den Workspace, in dem er erstellt wurde; ein OAuth-Token handelt für den eigenen Workspace des Nutzers. |
| 404 | `INVALID_SID` | Die `qrdx_sid` ist unbekannt oder älter als 30 Tage, das Attributionsfenster. | Sende die `qrdx_sid` eines aktuellen Scans oder melde die Conversion per Code-ID von deinem Server aus. |
| 409 | `SLUG_TAKEN` | Ein anderer Code verwendet diesen Back-Half bereits auf dieser Domain. Bei einem Array listet `data.details` jeden vergebenen mit `index` auf, und es wird nichts erstellt. | Wähle einen anderen Back-Half. |
| 413 | `PAYLOAD_TOO_LARGE` | Der Body überschreitet das Limit des Endpunkts: 4 MB für Codes, 16 KB für Hooks, 8 KB für Conversions. Auch bei einem Batch von Codes, dessen Antwort (jeder Code mit seinem Design) über 4 MB läge; es wird nichts erstellt. | Sende einen kleineren Body. Bei Codes ist meist ein großes Inline-Logo die Ursache; bei einem Batch sende `Prefer: return=minimal` oder weniger Codes. |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | Das `photo`- oder `reference`-Bild überschreitet das Größenlimit für AI Art (die Meldung nennt, welches). | Verkleinere das Bild (eine `reference` auf etwa 512 px an der längsten Seite, ein `photo` auf etwa 1024 px im Quadrat) und sende es erneut als PNG- oder JPEG-Data-URL. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Ein Schreibzugriff ohne `Content-Type: application/json`. | Sende einen JSON-Body mit `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk markiert die Ziel-URL (Malware, Phishing oder unerwünschte Software). Bei einem Array listet `data.details` jede markierte Zeile mit `index` auf, und es wird nichts erstellt. | Verwende ein anderes Ziel. Wenn die Markierung falsch ist, bitte Google, die Website zu prüfen. |
| 429 | `RATE_LIMITED` | Zu viele Anfragen: ein Limit pro Minute (nur `Retry-After` ist gesetzt) oder das Tageskontingent des Workspaces (`Retry-After` plus `X-RateLimit-*`). | Warte `Retry-After` Sekunden. Warte beim Tageskontingent bis 00:00 UTC oder wechsle den Tarif. |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Ein Business-Workspace hat die AI-Art-Bilder dieses Monats aufgebraucht, die das ganze Team gemeinsam nutzt. | Warte, bis das Kontingent am 1. des Monats (UTC) zurückgesetzt wird. |
| 429 | `AI_ART_DAILY_LIMIT` | Die Person, die den Schlüssel erstellt hat, hat heute (UTC) 25 AI-Art-Bilder erzeugt, eine Sicherheitsgrenze zusätzlich zum Monatskontingent. | Versuche es morgen (UTC) erneut. |
| 500 | `INTERNAL_ERROR` | Auf Seiten von QRdx ist etwas fehlgeschlagen. Es wurde protokolliert. | Versuche es gleich noch einmal. Tritt es weiter auf, melde es mit dem Zeitpunkt der Anfrage. |
| 502 | `AI_ART_FAILED` | Das Bildmodell ist fehlgeschlagen, hat den Prompt abgelehnt oder ein Bild geliefert, das QRdx nicht lesen konnte. Es wurde kein AI-Art-Guthaben verbraucht. | Versuche es erneut oder formuliere den Prompt um. Die Meldung sagt, was passiert ist. |
| 502 | `AI_ART_UNSCANNABLE` | Das Bild des Modells ließ sich mit der gewählten QR-Sichtbarkeit nicht scanbar machen. Es wurde kein AI-Art-Guthaben verbraucht. | Versuche es mit einer höheren `visibility` oder einem anderen Seed erneut. |
| 502 | `AI_ART_DESCRIBE_FAILED` | Du hast `prompt` weggelassen, und das Textmodell, das einen für dich schreibt, ist fehlgeschlagen. Es wurde kein AI-Art-Guthaben verbraucht. | Versuche es erneut oder sende einen eigenen `prompt`. |
| 503 | `SLUG_UNAVAILABLE` | Es konnte nicht rechtzeitig ein freier Kurzlink-Slug reserviert werden. | Sende dieselbe Anfrage erneut. |
| 503 | `AI_ART_BUSY` | Das Bildmodell ist gerade überlastet. Es wurde kein AI-Art-Guthaben verbraucht. | Warte eine Minute und versuche es erneut. |
| 503 | `AI_NOT_CONFIGURED` | AI Art ist in dieser Installation nicht eingerichtet (eine selbst gehostete Instanz ohne `AI_GATEWAY_API_KEY`). | Nutze die gehostete QRdx API oder richte Vercel AI Gateway auf deiner Instanz ein. |
| 503 | `UNAVAILABLE` | Eigene Domains sind in dieser Installation nicht eingerichtet (eine selbst gehostete Instanz ohne sie). | Lass `domainId` weg oder konfiguriere eigene Domains auf deiner Instanz. |
| 504 | `AI_ART_TIMEOUT` | Das Bildmodell hat zu lange gebraucht, und QRdx hat vor dem Ein-Minuten-Limit der Anfrage aufgehört zu warten. Es wurde kein AI-Art-Guthaben verbraucht. | Versuche es erneut. Aufrufe dauern meist 15 bis 45 Sekunden. |

## Der Fehler-Body [#the-error-body]

| Feld | Bedeutung |
| --- | --- |
| `code` | Ein stabiler, maschinenlesbarer Code aus der Tabelle oben |
| `message` | Was schiefgelaufen ist und wie du es behebst, für Menschen geschrieben. Der Wortlaut kann sich ändern |
| `status` | Der HTTP-Status, wiederholt |
| `docs` | Eine Seite, die die Lösung erklärt, falls es eine gibt |
| `data` | Zusätzliche Details bei einigen Fehlern. `VALIDATION_ERROR` listet jedes Problem in `data.details` auf |

Ein Validierungsfehler nennt jedes Feld, das fehlgeschlagen ist. Bei einem Stapel von Codes enthält jedes Problem außerdem den `index` der Zeile, gezählt ab 0:

```json title="400 Bad Request"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Die Image-Endpunkte (`GET /v1/qr`, `GET /v1/barcode`) melden Query-Parameter als `{ "param", "message" }` statt als `{ "path", "message" }`.

## Erneut versuchen [#retrying]

- **`429`:** Warte die Anzahl an Sekunden aus `Retry-After` ab und sende dann dieselbe Anfrage. Ist das Tageskontingent aufgebraucht, zeigen die `X-RateLimit-*`-Header, wie viele Anfragen der Plan erlaubt und wann der Zähler zurückgesetzt wird (00:00 UTC). Ein Limit pro Minute sendet nur `Retry-After`. Siehe [Rate Limits](/docs/developers/rest-api#rate-limits).
- **`500`, `502`, `503` und `504`:** Versuche es mit exponentiellem Backoff erneut, beginnend bei etwa einer Sekunde. Die `5xx`-Fehler der KI-Grafik verbrauchen nie ein Bild, ein erneuter Versuch kostet also nichts.
- **Andere `4xx`:** Dieselbe Anfrage schlägt auf dieselbe Weise fehl. Behebe zuerst die Ursache.

Ein erneuter Versuch von `POST /v1/codes` ist sicher, wenn die Anfrage einen `Idempotency-Key`-Header enthält: Derselbe Schlüssel liefert die Codes zurück, die der erste Versuch erstellt hat, mit `Idempotent-Replayed: true`, statt sie doppelt anzulegen ([Codes erstellen](/docs/developers/api/create-codes)). Ohne den Header listest du deine Codes auf, bevor du die Anfrage erneut sendest. `POST /v1/conversions` kannst du gefahrlos wiederholen, wenn du eine eigene `id` mitsendest: Eine Wiederholung liefert `200` mit `duplicate: true`.

## `/v1/me` und `/v1/themes` [#v1me-and-v1themes]

Diese beiden Endpunkte senden denselben Body plus die OAuth-Felder, die sie schon immer gesendet haben, `error` und `error_description` (derselbe Text wie `message`), damit ältere Clients weiter funktionieren:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED oder INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (Tageskontingent) |
| `not_found` | NOT_FOUND (Themes) |

## OAuth-Endpunkte [#oauth-endpoints]

Die OAuth-Endpunkte unter `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) folgen stattdessen dem OAuth-2.0-Standard: `{ "error", "error_description" }`, wobei `error` einer der Werte `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` oder `access_denied` ist. Wenn du bei einem Refresh `invalid_grant` erhältst, wurde das Refresh-Token bereits verwendet (jeder Refresh liefert ein neues), ist nach 30 Tagen abgelaufen oder der Nutzer hat den Zugriff deiner App widerrufen: Schicke den Nutzer erneut durch die Autorisierung. Siehe [REST API und OAuth](/docs/developers/rest-api#get-an-access-token).

## Unbekannte Endpunkte [#unknown-endpoints]

Ein Pfad unter `/v1`, der nicht existiert, gibt `404 NOT_FOUND` als JSON zurück, nie eine HTML-Seite, mit einem `docs`-Link zur Endpunktliste. Die [API-Referenz](/docs/developers/api) listet jeden Endpunkt auf.
