Alles, was QRdx kann, steht dir auch im Code zur Verfügung. Geh davon aus, was du bauen willst: Jede Zeile nennt das Tool, was es braucht und die Seite, die dich weiterbringt.

| Du willst | Nutze | Braucht |
| --- | --- | --- |
| Einen QR-Code in eine Seite, eine E-Mail oder eine README einbinden | [QR-Code Image API](/docs/developers/image-api): eine `GET`-URL, die das Bild ist | Nichts |
| Einen Barcode für ein Etikett oder einen Produkt-Feed zeichnen | [Barcode-API](/docs/developers/barcode-api): dasselbe für EAN, UPC, Code 128 und mehr | Nichts |
| Codes erstellen, die du nach dem Druck auf ein anderes Ziel umlenken kannst, und ihre Scans auslesen | [REST API](/docs/developers/quickstart): `POST /v1/codes`, `PATCH`, `GET …/scans` | Ein [API-Schlüssel](/docs/developers/api-keys) |
| In deinem eigenen System auf Scans, neue Codes oder Formularantworten reagieren | [Webhooks](/docs/webhooks): signierte `POST`-Anfragen an deine URL | Ein API-Schlüssel oder das Dashboard, Business-Tarif |
| Einen KI-Assistenten in einem Chat QR-Codes erstellen lassen | [MCP-Server](/docs/developers/mcp): `https://mcp.qrdx.dev/mcp` | Nichts |
| QR-Codes aus einem Skript, einem Build oder einer CSV erzeugen | [CLI](/docs/developers/cli): `npx @qrdx/cli` | Node.js 22 |
| Einen QR-Code in KI-Artwork einbetten | [KI-Art-API](/docs/developers/ai-art-api): `POST /v1/art` | Ein API-Schlüssel, monatliche KI-Art-Bilder |
| Anderen ermöglichen, ihr QRdx-Konto mit deinem Produkt zu verbinden | [Integration bauen](/docs/developers/build-an-integration): OAuth 2.0 mit PKCE | Eine OAuth-App |
| QRdx in n8n automatisieren | [n8n-Nodes](/docs/developers/n8n): `@qrdx/n8n-nodes-qrdx` | Ein selbst gehostetes n8n |
| Gestaltete Codes in einer React-App rendern | [React-Bibliothek](/docs/getting-started): das Paket `qrdx` | npm |

## Erste Anfrage in zwei Minuten [#first-request-in-two-minutes]

Die [Schnellstart-Anleitung](/docs/developers/quickstart) erzeugt mit einer schlüssellosen Anfrage ein QR-Code-Bild, erstellt einen API-Schlüssel, legt einen dynamischen QR-Code an und lenkt ihn auf ein anderes Ziel um. Alles Weitere auf dieser Seite baut auf diesen vier Schritten auf.

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png" -o qr.png
```

## Basis-URL und Authentifizierung [#base-url-and-authentication]

Die REST API läuft unter `https://api.qrdx.dev/v1`. Dieselben Routen antworten auch unter `https://qrdx.dev/api/v1`, und eine [selbst gehostete](/docs/self-hosting) Instanz stellt sie unter `/api/v1` auf ihrer eigenen Domain bereit.

Anfragen enthalten einen [API-Schlüssel](/docs/developers/api-keys) als `Authorization: Bearer qrdx_…`. Ein Schlüssel handelt im Workspace, in dem er erstellt wurde, mit deiner Rolle dort. Apps, die im Namen anderer QRdx-Nutzer handeln, senden stattdessen ein [OAuth-2.0-Zugriffstoken](/docs/developers/rest-api#get-an-access-token) im selben Header. Die Endpunkte für Bilder, Barcodes und die Community brauchen keines von beiden.
