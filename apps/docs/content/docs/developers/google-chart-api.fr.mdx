À la fin de cette page, tous les QR codes que vos pages, e-mails ou feuilles de calcul chargeaient depuis `chart.googleapis.com` se chargeront à la place depuis l'[Image API](/docs/developers/image-api) de QRdx, avec la même taille et le même niveau de correction d'erreur, sans compte ni clé.

Google a déprécié ses Image Charts en avril 2012, y compris les QR codes de `chart.googleapis.com/chart?cht=qr`. Le point de terminaison répond aujourd'hui `404` (vérifié le 15 novembre 2026) : chaque ancienne balise `<img>` affiche donc une image cassée. L'Image API de QRdx fonctionne de la même manière, avec une URL `GET` qui renvoie l'image. Le changement se résume donc à un nouvel hôte et trois paramètres renommés.

## Avant de commencer [#before-you-start]

- Repérez les fichiers qui utilisent encore l'ancienne API. La commande ci-dessous les liste, y compris avec l'ancien hôte `chart.apis.google.com` :

```bash title="Terminal"
grep -rlE "chart\.(googleapis|apis\.google)\.com/chart" .
```

- Travaillez dans un dépôt git ou un autre endroit où vous pouvez relire la modification avant sa mise en ligne.

## 1. Comparer une URL [#1-compare-one-url]

Les deux URL ci-dessous produisent le même rendu : un PNG de 300 × 300 de `https://example.com` avec la correction d'erreur `M` et une marge de 2 modules.

```txt title="Before and after"
https://chart.googleapis.com/chart?cht=qr&chs=300x300&chl=https%3A%2F%2Fexample.com&chld=M|2
https://api.qrdx.dev/v1/qr?format=png&size=300&data=https%3A%2F%2Fexample.com&level=M&margin=2
```

```bash title="Terminal"
curl -o after.png "https://api.qrdx.dev/v1/qr?format=png&size=300&data=https%3A%2F%2Fexample.com&level=M&margin=2"
file after.png
# after.png: PNG image data, 300 x 300, 8-bit/color RGBA, non-interlaced
```

## 2. Faire correspondre les paramètres [#2-map-the-parameters]

| Google Chart | QRdx | Remarques |
| --- | --- | --- |
| `cht=qr` | inutile | Le point de terminaison ne dessine que des QR codes. S'il est présent, il est ignoré |
| `chl=<data>` | `data=<data>` | Encodé en URL de la même façon, jusqu'à 2 048 caractères |
| `chs=<width>x<height>` | `size=<width>` | Un seul nombre, car les QR codes sont carrés : de `64` à `2048` pixels |
| `chld=<level>\|<margin>` | `level=<level>&margin=<margin>` | Les mêmes lettres, `L`, `M`, `Q` et `H`. La marge est exprimée en modules, de `0` à `16` |
| `choe=UTF-8` | inutile | QRdx encode toujours le texte en UTF-8, qui était la valeur par défaut de Google. Il n'existe pas d'option Shift_JIS ou ISO-8859-1. S'il est présent, il est ignoré |
| toujours PNG | `format=png` | QRdx renvoie du SVG, sauf si vous demandez `png`, `webp` ou `eps`. Gardez le PNG pour les e-mails, car de nombreux clients de messagerie n'affichent pas le SVG |

Deux valeurs par défaut diffèrent. Sans `chld`, Google utilisait la correction d'erreur `L` ; QRdx utilise `Q`, qui résiste à davantage de dégâts mais produit un code plus dense. Ajoutez `level=L` si vous voulez retrouver l'ancien rendu. Dans les deux cas, la marge par défaut est de 4 modules.

## 3. Réécrire les URL dans vos fichiers [#3-rewrite-the-urls-in-your-files]

Cette commande réécrit toutes les URL de QR code Google Chart dans les fichiers que vous indiquez, avec les deux hôtes : elle change l'hôte et le chemin, renomme `chl`, `chs` et `chld`, et ajoute `format=png` pour que les images restent en PNG. Perl est fourni avec macOS et la plupart des distributions Linux.

```bash title="Terminal"
perl -pi -e 's{https?://chart\.(?:googleapis|apis\.google)\.com/chart\?([^\s"\x27<>)]*)}{my $q = $1; $q =~ s/(^|[&;])chl=/${1}data=/; $q =~ s/(^|[&;])chs=(\d+)x\d+/${1}size=$2/; $q =~ s/(^|[&;])chld=([LMQH])(?:\||%7C)(\d+)/${1}level=$2&margin=$3/i; $q =~ s/(^|[&;])chld=([LMQH])/${1}level=$2/i; "https://api.qrdx.dev/v1/qr?format=png&$q"}ge' index.html
```

Exécutée sur un fichier contenant trois anciennes balises, elle produit :

```html title="index.html (after)"
<img src="https://api.qrdx.dev/v1/qr?format=png&cht=qr&size=300&data=https%3A%2F%2Fexample.com&level=M&margin=2" alt="QR">
<img src="https://api.qrdx.dev/v1/qr?format=png&cht=qr&size=150&data=https%3A%2F%2Fexample.com%2Fmenu" alt="QR 2">
<img src="https://api.qrdx.dev/v1/qr?format=png&size=200&cht=qr&data=hello&level=H&choe=UTF-8" alt="QR 3">
```

Les `cht=qr` et `choe=UTF-8` restants sont ignorés par QRdx ; supprimez-les à la main si vous voulez des URL propres. Vérifiez le diff, puis relancez le `grep` du début : il ne doit plus rien lister.

## 4. Modifier le code qui construit les URL [#4-change-the-code-that-builds-urls]

```js title="qr.js"
// Before
const src = `https://chart.googleapis.com/chart?cht=qr&chs=200x200&chl=${encodeURIComponent(link)}`;

// After
const src = `https://api.qrdx.dev/v1/qr?format=png&size=200&data=${encodeURIComponent(link)}`;
```

Dans Google Sheets :

```txt title="Sheets formula"
=IMAGE("https://api.qrdx.dev/v1/qr?format=png&size=150&data="&ENCODEURL(A2))
```

Sheets charge les images via les serveurs de Google, donc une feuille contenant des centaines de codes peut atteindre la limite par IP indiquée plus bas. Pour une longue liste, créez les fichiers une seule fois avec le [générateur en masse](/tools/bulk) ou avec `qrdx batch` de la [CLI](/docs/developers/cli).

## En cas de problème [#if-something-goes-wrong]

### `400` avec `"param": "size"` [#400-with-param-size]

Un `chs` inférieur à 64 pixels (comme `50x50`) ou supérieur à 2048 est refusé. Modifiez ces tailles à la main ; `64` est la plus petite taille que l'Image API dessine.

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"size","message":"Too small: expected number to be >=64"}]},"status":400}
```

### L'image est plus dense qu'avant [#the-image-is-denser-than-before]

La correction d'erreur par défaut de Google était `L` ; celle de QRdx est `Q`. Ajoutez `level=L` pour retrouver l'ancien rendu.

### `429` après un rechargement en masse [#429-after-a-bulk-reload]

L'Image API autorise {facts.imageApiPerMinute} requêtes par minute et par adresse IP. Attendez le nombre de secondes indiqué dans l'en-tête `Retry-After`, ou générez les fichiers une fois au lieu de les charger en direct.

## À savoir aussi [#what-else-to-know]

- **Mise en cache :** la même URL renvoie toujours les mêmes octets, les réponses sont donc mises en cache pendant un an (`Cache-Control: public, max-age=31536000, immutable`).
- **Plus d'options :** couleurs (`fg`, `bg`), formes des modules et des yeux, icône de logo (`logoIcon`) et cadres. Essayez-les dans le [générateur d'URL](/qr-code-api), ou consultez les [paramètres](/docs/developers/image-api#parameters).
- **Auto-hébergement :** une instance QRdx [auto-hébergée](/docs/self-hosting) sert la même API à l'adresse `/api/v1/qr` sur votre propre domaine.
