Una chiave API permette ai tuoi server, script e job di CI di chiamare la [REST API](/docs/developers/rest-api) senza un flusso OAuth. Alla fine di questa pagina avrai una chiave per un workspace, saprai esattamente cosa può fare e come ruotarla.

```bash title="Terminal"
curl https://api.qrdx.dev/v1/codes -H "Authorization: Bearer $QRDX_API_KEY"
```

Ogni endpoint che accetta un access token OAuth accetta una chiave nello stesso header. L'[Image API](/docs/developers/image-api) e la [API dei codici a barre](/docs/developers/barcode-api) non richiedono né l'uno né l'altra. Quando il tuo prodotto agisce per conto di altri utenti QRdx, usa invece una [app OAuth](/docs/developers/build-an-integration), così ogni persona la approva.

## Prima di iniziare [#before-you-start]

- Un account QRdx, con accesso effettuato. Tutti i piani hanno le chiavi API.
- Il workspace a cui è destinata la chiave. Una chiave appartiene a un solo workspace e lì agisce come te.

## 1. Crea una chiave [#create-a-key]

1. Apri [Impostazioni → Chiavi API e app](/dashboard?to=settings/developers&new=1) nel workspace a cui è destinata la chiave. Il link apre l'ultimo workspace che hai usato; scegline un altro nel selettore dei workspace. Si apre il modulo **Crea chiave API**.
2. Compila **Nome**: dove viene usata la chiave, così saprai quale revocare in seguito. Scegli il suo **Accesso** e, in **Scadenza**, quanto dura. Scegli **Crea chiave**. Una chiave funziona anche senza di te, quindi QRdx ti chiede prima di [confermare che sei tu](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), a meno che tu non l'abbia fatto in quel browser negli ultimi 10 minuti.
3. Copia la chiave dalla finestra **Copia la tua chiave API**. Viene mostrata solo questa volta: QRdx ne conserva soltanto un hash. La stessa finestra mostra una richiesta curl con la chiave e l'indirizzo API di questo sito già inseriti, pronta da incollare.

Una chiave è `qrdx_` seguito da 40 lettere e cifre. Gli elenchi ne mostrano solo l'inizio, ad esempio `qrdx_7KpQ2m…`, così puoi distinguere le chiavi.

## 2. Scegli l'accesso [#access]

Le chiavi usano gli stessi scope delle app OAuth. Scegli una delle tre opzioni quando crei la chiave:

| Accesso | Scope | Consente |
| --- | --- | --- |
| Accesso completo | `profile:read`, `themes:read`, `codes:read`, `codes:write` | Tutto ciò che fa l'API |
| Sola lettura | `profile:read`, `themes:read`, `codes:read` | Leggere codici, statistiche delle scansioni, codici a barre salvati, temi e il profilo |
| Personalizzato | Quelli che selezioni | Ciò che consentono quegli scope ([l'elenco degli scope](/docs/developers/rest-api#scopes)) |

`codes:write` consente anche tutto ciò che consente `codes:read`. Gli scope di una chiave non si possono modificare in seguito; crea invece una nuova chiave. Una richiesta fuori dagli scope della chiave riceve `403 INSUFFICIENT_SCOPE`, e il messaggio indica lo scope necessario:

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## 3. Usala [#3-use-it]

Invia la chiave come token Bearer. La prima chiamata da fare è `GET /v1/me`, che restituisce il profilo di chi ha creato la chiave e conferma che la chiave funziona:

```bash title="Terminal"
curl https://api.qrdx.dev/v1/me -H "Authorization: Bearer $QRDX_API_KEY"
```

```json title="200 OK"
{"data":{"id":"usr_docsdev0000000000000001","name":"Ada Lovelace","email":"ada@example.com","image":null}}
```

Tieni la chiave su un server, in una variabile d'ambiente o in un gestore di segreti, e leggila da lì nel codice:

```js title="qrdx.mjs"
const response = await fetch("https://api.qrdx.dev/v1/codes", {
  headers: { Authorization: `Bearer ${process.env.QRDX_API_KEY}` },
});
```

```python title="qrdx.py"
import os
import requests

response = requests.get(
    "https://api.qrdx.dev/v1/codes",
    headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},
)
```

## Workspace e ruoli [#workspaces-and-roles]

Una chiave appartiene al workspace che era aperto quando l'hai creata e lì agisce come te:

- La chiave lavora con i codici, le scansioni, i codici a barre, gli hook e i temi di quel workspace, secondo il piano del workspace e la sua [quota giornaliera](/docs/developers/rest-api#rate-limits).
- Può fare ciò che puoi fare tu nel workspace, in base al tuo [ruolo](/docs/teams) al momento di ogni richiesta. Nel tuo workspace sei il proprietario. Se il tuo ruolo cambia, cambiano anche i diritti della chiave; se lasci il workspace, la chiave smette di funzionare, e l'eliminazione di un workspace elimina le sue chiavi.

Ogni membro di un workspace può creare chiavi. Proprietari e amministratori vedono tutte le chiavi del workspace e possono revocarle; i membri vedono e revocano solo le proprie. Ogni persona può avere fino a 25 chiavi attive in ogni workspace; le chiavi revocate e scadute non contano.

## Scadenza, ultimo utilizzo e revoca [#revoke]

- **Scadenza.** In **Scadenza**, una chiave dura per sempre (**Mai**) oppure 30 giorni, 90 giorni o 1 anno. Una chiave scaduta riceve `401 INVALID_TOKEN` e resta nell'elenco, contrassegnata come **Scaduta**, finché non la revochi.
- **Ultimo utilizzo.** L'elenco mostra la data in cui ogni chiave ha autenticato l'ultima richiesta.
- **Revoca.** Scegli **Revoca** accanto a una chiave e conferma con **Revoca chiave**. Da quel momento, le richieste con essa ricevono `401 INVALID_TOKEN`. La revoca non può essere annullata.

```json title="401 Unauthorized"
{
  "code": "INVALID_TOKEN",
  "message": "Invalid API key: it doesn't exist, was revoked or has expired, or its creator left the workspace. Check that you copied the whole key, or create a new one at https://qrdx.dev/dashboard?to=settings/developers.",
  "status": 401,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## Proteggi le chiavi [#keep-keys-safe]

- Non inserire mai una chiave in una pagina web, in un'app mobile, in un prompt o in un repository. Il codice nel browser che ha bisogno di un'immagine QR usa l'[Image API](/docs/developers/image-api), che non richiede chiave.
- Usa una chiave per ogni luogo in cui viene eseguita, così puoi revocarne una senza rompere le altre.
- Dai agli script che si limitano a produrre report una chiave **Sola lettura**, e ai job di breve durata una chiave che scade.
- Se una chiave viene esposta, revocala e creane una nuova. Il prefisso `qrdx_` rende le chiavi facili da trovare nel codice e nei log, e gli scanner di segreti possono riconoscere `qrdx_[0-9A-Za-z]{40}`.

## Se qualcosa va storto [#if-something-goes-wrong]

### `401 UNAUTHORIZED` [#401-unauthorized]

La richiesta non aveva l'header `Authorization`. Controlla il nome dell'header e che il tuo client HTTP lo invii; il valore è `Bearer ` seguito dall'intera chiave.

### `401 INVALID_TOKEN` [#401-invalid_token]

La chiave è stata copiata incompleta, revocata, è scaduta, oppure chi l'ha creata ha lasciato il workspace. Crea una nuova chiave. Per un token OAuth, aggiornalo o fai ripetere l'autorizzazione alla persona.

### `403 INSUFFICIENT_SCOPE` [#403-insufficient_scope]

La chiave è **Sola lettura** oppure è una chiave **Personalizzato** senza lo scope indicato nel messaggio. Crea una chiave con quello scope; non si possono aggiungere scope a una chiave esistente.

### Le chiavi API non sono ancora disponibili su questa installazione [#api-keys-arent-available-on-this-deployment-yet]

Un'istanza [self-hosted](/docs/self-hosting) mostra questo messaggio finché il suo database non ha la tabella `api_key`, che viene creata dalla sincronizzazione dello schema dopo un aggiornamento (il servizio `migrate` con Docker, altrimenti `bun run db:push`). Fino ad allora l'API rifiuta le chiavi con `401`. La sua API si trova su `/api/v1` sul suo dominio, che è l'indirizzo inserito nella finestra della nuova chiave.
