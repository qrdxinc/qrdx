Todo erro da REST API é um JSON com o mesmo formato, não importa qual endpoint o retorne. Use `code` para tratar cada caso, pois ele nunca muda; `message` é escrita para pessoas e pode ser reformulada.

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## Códigos de erro [#error-codes]

Ordenados por status. Um código que aparece duas vezes tem um significado diferente em cada status.

| Status | Código | Quando acontece | O que fazer |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | O corpo, a query ou o caminho não passou na validação. `data.details` lista cada problema como `{ path, message }` (`{ param, message }` na Image API), com o `index` da linha quando o corpo é uma lista de códigos. | Corrija os campos listados em `data.details` e envie a requisição de novo. |
| 400 | `INVALID_SLUG` | O back-half personalizado (`slug`) quebra uma regra: é uma palavra reservada, ou o mesmo back-half aparece duas vezes na mesma requisição. Para uma lista, `data.details` lista cada linha por `index`. | Escolha outro back-half. A mensagem informa a regra. |
| 400 | `TOO_MANY_CODES` | Mais de 1.000 códigos em uma única requisição. Normalmente o schema do corpo rejeita isso antes, como `VALIDATION_ERROR`. | Envie no máximo 1.000 códigos por requisição. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` aponta para um domínio personalizado que ainda não foi verificado. | Conclua a verificação do domínio na página Domínios ou deixe `domainId` de fora. |
| 400 | `SID_REQUIRED` | Uma conversão sem o `qrdx_sid` da leitura (vindo do navegador), ou sem `sid` ou `code` (vindo de um servidor). | Envie o `qrdx_sid` que o link curto adicionou à URL da sua página ou, com uma chave de API ou token, o id do código como `code`. |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` é longo demais para a arte com IA (mais de 300 caracteres). | Envie o id de um código dinâmico como `code`: a arte codifica o link curto dele, que é curto e continua editável. |
| 401 | `UNAUTHORIZED` | Sem credenciais: a requisição não tem o header `Authorization: Bearer` (nem sessão do QRdx no navegador). | Envie uma chave de API como `Authorization: Bearer <key>`; crie uma em Configurações → Chaves de API e apps. Tokens de acesso OAuth vão no mesmo header. |
| 401 | `INVALID_TOKEN` | A chave de API ou o token de acesso é desconhecido, foi revogado ou expirou (tokens de acesso duram uma hora), ou quem criou a chave foi banido ou saiu do workspace da chave. | Confira se você enviou a chave inteira ou crie uma nova. Para um token de acesso, obtenha outro com o seu refresh token ou leve o usuário pela autorização novamente. |
| 402 | `PLAN_REQUIRED` | O recurso não está no plano do workspace: criação em lote, back-halves personalizados e domínios personalizados exigem Pro; conversões e hooks exigem Business. | Faça upgrade do workspace ou deixe o recurso de fora da requisição. |
| 402 | `LIMIT_REACHED` | O workspace já tem todos os QR codes dinâmicos ativos que o plano inclui (10 no Grátis). | Arquive um código (códigos arquivados não contam) ou faça upgrade para o Pro e tenha códigos ilimitados. |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | O workspace usou as imagens de arte com IA deste mês (Grátis e Pro). Nada foi cobrado por esta requisição. | Espere a franquia ser renovada no dia 1º do mês (UTC) ou faça upgrade para ter mais imagens. |
| 403 | `INSUFFICIENT_SCOPE` | A chave de API ou o token é válido, mas não tem o escopo que este endpoint exige. | Crie uma chave com o escopo citado na mensagem (os escopos de uma chave não podem ser alterados). Em um app OAuth, adicione o escopo e peça por ele quando o usuário autorizar. |
| 403 | `FORBIDDEN` | Quem fez a chamada não pode fazer isso: um membro do workspace excluindo um código criado por outra pessoa, um membro gerenciando hooks, ou uma escrita por sessão de navegador vinda de outro site. Uma chave de API só pode fazer o que o papel de quem a criou permite no workspace dela. | Peça a um proprietário ou administrador do workspace, ou chame a API com uma chave de API a partir do seu servidor. |
| 403 | `CONFIRMATION_REQUIRED` | Criar um hook com uma sessão de navegador logada exige uma confirmação recente de "Confirme que é você". Chaves de API e tokens OAuth não passam por essa pergunta. | Confirme que é você no QRdx e tente de novo em até 10 minutos, ou crie o hook com uma chave de API a partir do seu servidor. |
| 403 | `CONVERSIONS_OFF` | Uma conversão pelo navegador para um código que não tem o rastreamento de conversões ativado. | Ative o rastreamento de conversões do código ou informe a conversão a partir do seu servidor com uma chave de API. |
| 403 | `LIMIT_REACHED` | O workspace já tem 20 endpoints de webhook e hooks. | Exclua um endpoint ou hook que você não usa mais. |
| 404 | `NOT_FOUND` | O endpoint não existe, ou o código, hook, tema ou domínio personalizado não existe no workspace em que a chave ou o token atua. | Confira o caminho e o id. Uma chave de API atua no workspace em que foi criada; um token OAuth atua no workspace do próprio usuário. |
| 404 | `INVALID_SID` | O `qrdx_sid` é desconhecido ou tem mais de 30 dias, a janela de atribuição. | Envie o `qrdx_sid` de uma leitura recente ou informe a conversão pelo id do código a partir do seu servidor. |
| 409 | `SLUG_TAKEN` | Outro código já usa esse back-half nesse domínio. Para uma lista, `data.details` lista cada um já em uso por `index`, e nada é criado. | Escolha outro back-half. |
| 413 | `PAYLOAD_TOO_LARGE` | O corpo passa do limite do endpoint: 4 MB para códigos, 16 KB para hooks, 8 KB para conversões. Também vale para um lote de códigos cuja resposta (cada código com o seu design) passaria de 4 MB; nada é criado. | Envie um corpo menor. Para códigos, um logo inline grande costuma ser a causa; para um lote, envie `Prefer: return=minimal` ou menos códigos. |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | A imagem `photo` ou `reference` passa do limite de tamanho da arte com IA (a mensagem diz qual). | Reduza a imagem (uma `reference` para cerca de 512 px no lado maior, uma `photo` para cerca de 1024 px quadrados) e envie de novo como data URL em PNG ou JPEG. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Uma escrita sem `Content-Type: application/json`. | Envie um corpo JSON com `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | O Google Web Risk sinaliza a URL de destino (malware, phishing ou software indesejado). Para uma lista, `data.details` lista cada linha sinalizada por `index`, e nada é criado. | Use outro destino. Se a sinalização estiver errada, peça ao Google para revisar o site. |
| 429 | `RATE_LIMITED` | Requisições demais: um limite por minuto (só `Retry-After` é definido) ou a cota diária do workspace (`Retry-After` mais `X-RateLimit-*`). | Espere `Retry-After` segundos. Para a cota diária, espere até 00:00 UTC ou faça upgrade do plano. |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Um workspace Business usou as imagens de arte com IA deste mês, que a equipe inteira divide. | Espere a franquia ser renovada no dia 1º do mês (UTC). |
| 429 | `AI_ART_DAILY_LIMIT` | Quem criou a chave já gerou 25 imagens de arte com IA hoje (UTC), um limite de segurança além da franquia mensal. | Tente de novo amanhã (UTC). |
| 500 | `INTERNAL_ERROR` | Algo falhou do lado do QRdx. O erro foi registrado. | Tente de novo daqui a pouco. Se continuar acontecendo, avise com o horário da requisição. |
| 502 | `AI_ART_FAILED` | O modelo de imagem falhou, recusou o prompt ou devolveu uma imagem que o QRdx não conseguiu ler. Nenhum crédito de arte com IA foi usado. | Tente de novo ou reescreva o prompt. A mensagem diz o que aconteceu. |
| 502 | `AI_ART_UNSCANNABLE` | Não foi possível fazer a imagem do modelo ser lida dentro da visibilidade do QR que você escolheu. Nenhum crédito de arte com IA foi usado. | Tente de novo com uma `visibility` maior ou outra seed. |
| 502 | `AI_ART_DESCRIBE_FAILED` | Você deixou `prompt` de fora, e o modelo de texto que escreve um para você falhou. Nenhum crédito de arte com IA foi usado. | Tente de novo ou envie o seu próprio `prompt`. |
| 503 | `SLUG_UNAVAILABLE` | Não foi possível reservar a tempo um slug livre para o link curto. | Envie a mesma requisição de novo. |
| 503 | `AI_ART_BUSY` | O modelo de imagem está acima da capacidade neste momento. Nenhum crédito de arte com IA foi usado. | Espere um minuto e tente de novo. |
| 503 | `AI_NOT_CONFIGURED` | A arte com IA não está configurada neste deploy (uma instância auto-hospedada sem `AI_GATEWAY_API_KEY`). | Use a API hospedada do QRdx ou configure o Vercel AI Gateway na sua instância. |
| 503 | `UNAVAILABLE` | Domínios personalizados não estão configurados neste deploy (uma instância auto-hospedada sem eles). | Deixe `domainId` de fora ou configure domínios personalizados na sua instância. |
| 504 | `AI_ART_TIMEOUT` | O modelo de imagem demorou demais, e o QRdx parou de esperar antes do limite de um minuto da requisição. Nenhum crédito de arte com IA foi usado. | Tente de novo. As chamadas costumam levar de 15 a 45 segundos. |

## O corpo do erro [#the-error-body]

| Campo | O que é |
| --- | --- |
| `code` | Um código estável e legível por máquina, da tabela acima |
| `message` | O que deu errado e como corrigir, escrito para pessoas. O texto pode mudar |
| `status` | O status HTTP, repetido |
| `docs` | Uma página que explica a correção, quando existe |
| `data` | Detalhes extras em alguns erros. `VALIDATION_ERROR` lista cada problema em `data.details` |

Um erro de validação nomeia todos os campos que falharam. Em um lote de códigos, cada problema também traz o `index` da linha, contado a partir de 0:

```json title="400 Bad Request"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Os endpoints de imagem (`GET /v1/qr`, `GET /v1/barcode`) informam os parâmetros de consulta como `{ "param", "message" }` em vez de `{ "path", "message" }`.

## Tentando de novo [#retrying]

- **`429`:** espere o número de segundos indicado em `Retry-After` e envie a mesma requisição. Quando a cota diária acaba, os headers `X-RateLimit-*` informam quantas requisições o plano permite e quando a contagem é zerada (00:00 UTC). Um limite por minuto envia só `Retry-After`. Veja [limites de requisições](/docs/developers/rest-api#rate-limits).
- **`500`, `502`, `503` e `504`:** tente de novo com backoff exponencial, começando em cerca de um segundo. Os erros `5xx` da arte com IA nunca consomem uma imagem, então tentar de novo não custa nada.
- **Outros `4xx`:** a mesma requisição falha do mesmo jeito. Corrija antes de tentar.

Repetir um `POST /v1/codes` é seguro quando a requisição leva um header `Idempotency-Key`: a mesma chave devolve os códigos criados na primeira tentativa, com `Idempotent-Replayed: true`, em vez de criá-los duas vezes ([Criar códigos](/docs/developers/api/create-codes)). Sem o header, liste seus códigos antes de enviar a requisição de novo. Repetir `POST /v1/conversions` é seguro quando você envia seu próprio `id`: a repetição retorna `200` com `duplicate: true`.

## `/v1/me` e `/v1/themes` [#v1me-and-v1themes]

Esses dois endpoints enviam o mesmo corpo mais os campos OAuth que sempre enviaram, `error` e `error_description` (o mesmo texto de `message`), para que clientes mais antigos continuem funcionando:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED ou INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (cota diária) |
| `not_found` | NOT_FOUND (themes) |

## Endpoints OAuth [#oauth-endpoints]

Os endpoints OAuth em `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) seguem o padrão OAuth 2.0: `{ "error", "error_description" }`, com `error` sendo `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` ou `access_denied`. Receber `invalid_grant` em uma renovação significa que o refresh token já foi usado (cada renovação devolve um novo), expirou após 30 dias ou o usuário revogou seu app: leve o usuário pela autorização de novo. Veja [REST API e OAuth](/docs/developers/rest-api#get-an-access-token).

## Endpoints desconhecidos [#unknown-endpoints]

Um caminho em `/v1` que não existe retorna `404 NOT_FOUND` em JSON, nunca uma página HTML, com um link `docs` para a lista de endpoints. A [referência da API](/docs/developers/api) lista todos os endpoints.
