Una clave de API permite que tus propios servidores, scripts y tareas de CI llamen a la [REST API](/docs/developers/rest-api) sin un flujo de OAuth. Al terminar esta página tendrás una clave para un espacio de trabajo, sabrás exactamente qué puede hacer y cómo rotarla.

```bash title="Terminal"
curl https://api.qrdx.dev/v1/codes -H "Authorization: Bearer $QRDX_API_KEY"
```

Todos los endpoints que aceptan un token de acceso de OAuth aceptan una clave en el mismo encabezado. La [Image API](/docs/developers/image-api) y la [API de códigos de barras](/docs/developers/barcode-api) no necesitan ninguno de los dos. Cuando tu producto actúe en nombre de otros usuarios de QRdx, usa en su lugar una [app OAuth](/docs/developers/build-an-integration), para que cada persona la apruebe.

## Antes de empezar [#before-you-start]

- Una cuenta de QRdx con la sesión iniciada. Todos los planes incluyen claves de API.
- El espacio de trabajo para el que es la clave. Una clave pertenece a un espacio de trabajo y actúa en él como tú.

## 1. Crea una clave [#create-a-key]

1. Abre [Ajustes → Claves de API y apps](/dashboard?to=settings/developers&new=1) en el espacio de trabajo para el que es la clave. El enlace abre el último espacio de trabajo que usaste; elige otro en el selector de espacios de trabajo. Se abre el formulario **Crear clave de API**.
2. Rellena **Nombre**: dónde se usa la clave, para saber cuál revocar más adelante. Elige su **Acceso** y, en **Caduca**, cuánto tiempo vive. Elige **Crear clave**. Una clave funciona sin ti, así que QRdx te pide [confirmar que eres tú](/docs/help/privacy-and-security/two-step-verification#confirm-its-you) antes, salvo que lo hayas hecho en ese navegador en los últimos 10 minutos.
3. Copia la clave del cuadro de diálogo **Copia tu clave de API**. Solo se muestra esta vez: QRdx guarda únicamente un hash de ella. El mismo cuadro muestra una petición curl con la clave y la dirección de la API de este sitio ya rellenadas, lista para pegar.

Una clave es `qrdx_` seguido de 40 letras y dígitos. Las listas muestran solo su inicio, como `qrdx_7KpQ2m…`, para que puedas distinguir unas claves de otras.

## 2. Elige su acceso [#access]

Las claves usan los mismos scopes que las apps OAuth. Elige una de las tres opciones al crear la clave:

| Acceso | Scopes | Permite |
| --- | --- | --- |
| Acceso total | `profile:read`, `themes:read`, `codes:read`, `codes:write` | Todo lo que hace la API |
| Solo lectura | `profile:read`, `themes:read`, `codes:read` | Leer códigos, analíticas de escaneo, códigos de barras guardados, temas y el perfil |
| Personalizado | Los que marques | Lo que permitan esos scopes ([la lista de scopes](/docs/developers/rest-api#scopes)) |

`codes:write` también permite todo lo que permite `codes:read`. Los scopes de una clave no se pueden cambiar después; crea una clave nueva. Una petición fuera de los scopes de la clave recibe `403 INSUFFICIENT_SCOPE`, y el mensaje indica el scope que necesitaba:

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## 3. Úsala [#3-use-it]

Envía la clave como token Bearer. La primera llamada que conviene hacer es `GET /v1/me`, que devuelve el perfil del creador de la clave y confirma que funciona:

```bash title="Terminal"
curl https://api.qrdx.dev/v1/me -H "Authorization: Bearer $QRDX_API_KEY"
```

```json title="200 OK"
{"data":{"id":"usr_docsdev0000000000000001","name":"Ada Lovelace","email":"ada@example.com","image":null}}
```

Guarda la clave en un servidor, en una variable de entorno o en un gestor de secretos, y léela desde ahí en el código:

```js title="qrdx.mjs"
const response = await fetch("https://api.qrdx.dev/v1/codes", {
  headers: { Authorization: `Bearer ${process.env.QRDX_API_KEY}` },
});
```

```python title="qrdx.py"
import os
import requests

response = requests.get(
    "https://api.qrdx.dev/v1/codes",
    headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},
)
```

## Espacios de trabajo y roles [#workspaces-and-roles]

Una clave pertenece al espacio de trabajo que estaba abierto cuando la creaste y actúa en él como tú:

- La clave trabaja con los códigos, escaneos, códigos de barras, hooks y temas de ese espacio de trabajo, según el plan del espacio y su [cuota diaria](/docs/developers/rest-api#rate-limits).
- Puede hacer lo que tú puedes hacer en el espacio de trabajo, según tu [rol](/docs/teams) en el momento de cada petición. En tu propio espacio de trabajo eres el propietario. Si tu rol cambia, los permisos de la clave cambian con él; si sales del espacio de trabajo, la clave deja de funcionar, y al eliminar un espacio de trabajo se eliminan sus claves.

Todos los miembros de un espacio de trabajo pueden crear claves. Los propietarios y administradores ven todas las claves del espacio de trabajo y pueden revocar cualquiera; los miembros solo ven y revocan las suyas. Cada persona puede tener hasta 25 claves activas en cada espacio de trabajo; las claves revocadas y caducadas no cuentan.

## Caducidad, último uso y revocación [#revoke]

- **Caducidad.** En **Caduca**, una clave vive para siempre (**Nunca**) o durante 30 días, 90 días o 1 año. Una clave caducada recibe `401 INVALID_TOKEN` y permanece en la lista, marcada como **Caducada**, hasta que la revoques.
- **Último uso.** La lista muestra la fecha en que cada clave autenticó una petición por última vez.
- **Revocación.** Elige **Revocar** junto a una clave y confirma con **Revocar clave**. Desde ese momento, las peticiones con ella reciben `401 INVALID_TOKEN`. La revocación no se puede deshacer.

```json title="401 Unauthorized"
{
  "code": "INVALID_TOKEN",
  "message": "Invalid API key: it doesn't exist, was revoked or has expired, or its creator left the workspace. Check that you copied the whole key, or create a new one at https://qrdx.dev/dashboard?to=settings/developers.",
  "status": 401,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## Mantén las claves seguras [#keep-keys-safe]

- Nunca pongas una clave en una página web, una app móvil, un prompt o un repositorio. El código de navegador que necesite una imagen QR usa la [Image API](/docs/developers/image-api), que no requiere clave.
- Usa una clave por cada lugar donde se ejecuta, para poder revocar una sin romper las demás.
- Da una clave de **Solo lectura** a los scripts que solo generan informes, y da a las tareas de corta duración una clave que caduque.
- Si una clave se filtra, revócala y crea una nueva. El prefijo `qrdx_` facilita encontrar las claves en el código y en los registros, y los escáneres de secretos pueden detectar `qrdx_[0-9A-Za-z]{40}`.

## Si algo sale mal [#if-something-goes-wrong]

### `401 UNAUTHORIZED` [#401-unauthorized]

La petición no tenía el encabezado `Authorization`. Comprueba el nombre del encabezado y que tu cliente HTTP lo envíe; el valor es `Bearer ` seguido de la clave completa.

### `401 INVALID_TOKEN` [#401-invalid_token]

La clave se copió incompleta, fue revocada, caducó o su creador salió del espacio de trabajo. Crea una clave nueva. En el caso de un token de OAuth, actualízalo o haz que la persona vuelva a autorizar.

### `403 INSUFFICIENT_SCOPE` [#403-insufficient_scope]

La clave es de **Solo lectura** o una clave **Personalizado** sin el scope indicado en el mensaje. Crea una clave con ese scope; no se pueden añadir scopes a una clave existente.

### Las claves de API aún no están disponibles en este despliegue [#api-keys-arent-available-on-this-deployment-yet]

Una instancia [autoalojada](/docs/self-hosting) muestra este mensaje hasta que su base de datos tenga la tabla `api_key`, que crea la sincronización del esquema tras una actualización (el servicio `migrate` con Docker, `bun run db:push` en los demás casos). Hasta entonces la API rechaza las claves con `401`. Su API está en `/api/v1` en su propio dominio, que es la dirección que rellena el cuadro de diálogo de nueva clave.
