À la fin de cette page, vous aurez obtenu un PNG de 1024 px dans lequel un QR code est intégré à une image peinte, décodé par QRdx avant de vous parvenir. Vous saurez aussi comment encoder un code dynamique plutôt qu'un texte fixe, quel mode choisir et ce que signifie chaque erreur.

`POST https://api.qrdx.dev/v1/art` intègre un QR code dans une illustration IA à partir d'une description et renvoie l'image. C'est le même [art QR IA](/ai/art) que l'onglet Art du Playground et le studio : {facts.artModel} peint l'image, puis QRdx vérifie qu'elle se scanne bien vers votre contenu avant de vous la remettre. Lorsque l'image du modèle ne se scanne pas telle qu'elle a été dessinée, QRdx renforce le code juste ce qu'il faut, sur les pixels mêmes du modèle.

<Callout type="info" title="Clé API et images mensuelles">
Le point de terminaison nécessite une [clé API](/docs/developers/api-keys) avec la portée `codes:write` (les clés **Accès complet** l'ont). Chaque image consomme une des images d'art IA mensuelles de l'espace de travail de la clé, le même quota que celui utilisé par l'application ; [Offres et limites](/docs/plans-and-limits) donne les chiffres par offre. Un appel qui échoue, ou dont l'image ne peut pas être rendue scannable, ne consomme aucune image.
</Callout>

## Avant de commencer [#before-you-start]

- Une clé API avec `codes:write`, exportée sous le nom `QRDX_API_KEY`.
- Un client HTTP avec un délai d'attente d'au moins 60 secondes. Un appel prend environ 15 à 45 secondes en mode code, 25 à 45 en mode photo et 40 à 55 en mode scène, qui peint d'abord son image.
- Pour un code dynamique, son `id`, obtenu via [`GET /v1/codes`](/docs/developers/api/list-codes) ou dans la réponse qui [l'a créé](/docs/developers/api/create-codes).

## 1. Peindre un code pour un lien [#1-paint-a-code-for-a-link]

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>

    ```bash title="Terminal"
    curl https://api.qrdx.dev/v1/art \
      -H "Authorization: Bearer $QRDX_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"text": "https://qrdx.dev", "prompt": "a koi pond at dusk, ink and watercolor"}' \
      --max-time 90 -o art.json
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="art.mjs"
    import { writeFile } from "node:fs/promises";

    const response = await fetch("https://api.qrdx.dev/v1/art", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.QRDX_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({

        prompt: "a koi pond at dusk, ink and watercolor",
      }),
      signal: AbortSignal.timeout(90_000),
    });
    const { data, credits } = await response.json();
    // data.imageUrl is a data: URL; save the PNG bytes
    const base64 = data.imageUrl.split(",")[1];
    await writeFile("art.png", Buffer.from(base64, "base64"));
    console.log(data.text, data.blend, credits.remaining);
    ```
  </Tab>
  <Tab value="Python">
    ```python title="art.py"
    import base64
    import os
    import requests

    response = requests.post(
        "https://api.qrdx.dev/v1/art",
        headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},
        json={"text": "https://qrdx.dev", "prompt": "a koi pond at dusk, ink and watercolor"},
        timeout=90,
    )
    response.raise_for_status()
    body = response.json()
    png = base64.b64decode(body["data"]["imageUrl"].split(",", 1)[1])
    open("art.png", "wb").write(png)
    print(body["data"]["text"], body["data"]["blend"], body["credits"]["remaining"])
    ```

La réponse est un JSON avec l'image sous forme d'URL `data:` :

```json title="200 OK (fields)"
{
  "data": {
    "imageUrl": "data:image/png;base64,iVBORw0KGgo…",
    "width": 1024,
    "height": 1024,
    "seed": 2841337190,
    "mode": "code",
    "blend": "least",
    "blendStrength": 0.35,
    "text": "https://qrdx.dev",
    "visibility": 50,
    "creativity": 45
  },
  "credits": { "plan": "pro", "limit": 30, "used": 7, "remaining": 23, "pooled": false, "resetsAt": "2026-12-01T00:00:00.000Z" }
}
```

- `imageUrl` est un PNG carré de 1024 px sous forme d'URL `data:`. QRdx n'en conserve pas de copie, enregistrez-la donc.
- `text` correspond exactement à ce vers quoi l'image se scanne. QRdx l'a décodé avant de répondre.
- `blend` indique comment l'image a été rendue scannable : `none` (l'image du modèle telle que dessinée), `least` (les carrés de repérage, la zone de silence et les modules renforcés juste ce qu'il faut, sur l'image du modèle) ou `image-qr` (redessinée sous forme de QR code Image QR, en dernier recours). `blendStrength` va de `0` (telle que dessinée) à `1` (Image QR).
- `credits` correspond au quota restant de l'espace de travail après cette image.

Pour obtenir directement le PNG plutôt que du JSON, ajoutez `?format=png` ou envoyez `Accept: image/png`. La graine, le mode, le blend et le nombre d'images restantes arrivent alors dans les en-têtes `X-QRdx-Seed`, `X-QRdx-Mode`, `X-QRdx-Blend`, `X-QRdx-Blend-Strength` et `X-QRdx-Credits-Remaining` :

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/art?format=png" \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text": "https://qrdx.dev", "prompt": "a lighthouse on a cliff, woodcut print"}' \
  --max-time 90 -o art.png
```

## 2. Encoder un code dynamique à la place [#encode]

Envoyez exactement un des deux champs, `text` ou `code` :

- `text` : le lien ou le texte contenu dans le code, jusqu'à 300 caractères. L'art est une image : son contenu ne peut plus changer une fois imprimé.
- `code` : l'`id` d'un des [QR codes dynamiques](/docs/dynamic-qr-codes) de l'espace de travail. L'art encode le lien court du code, ce qui vous permet de modifier sa destination après l'impression, et ses scans apparaissent dans les statistiques. Un code d'un autre espace de travail, ou placé dans la corbeille, renvoie une erreur `404`.

```bash title="Terminal"
curl https://api.qrdx.dev/v1/art \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"code": "cm5code0spring0menu00001", "prompt": "a bistro chalkboard menu on a brick wall", "mode": "scene"}' \
  --max-time 90 -o art.json
```

La réponse contient alors aussi `"code": { "id", "shortLink" }`, et `text` est le lien court.

## 3. Choisir un mode et un style [#modes]

| `mode` | Ce que vous obtenez |
| --- | --- |
| `code` (par défaut) | Le code constitue toute l'image : votre illustration est peinte dans ses modules, avec des carrés de repérage unis et une zone de silence claire autour. C'est le plus fiable au scan |
| `scene` | Une image est d'abord peinte à partir de la description, puis le code est peint en son centre : l'image s'étend jusqu'au code et à travers lui, avec des modules faits de ses couleurs et de sa lumière |
| `photo` | Pareil, avec votre propre `photo` comme image : elle conserve son sujet, ses couleurs et sa lumière autour du code et à travers lui. N'envoyez la photo qu'avec ce mode |

### Styles rapides [#quick-looks]

Un style rapide est un rendu prêt à l'emploi, comme une technique ou une ambiance, que QRdx ajoute à votre propre `prompt` : `"a koi pond in the rain"` avec `"style": "watercolor"` peint le bassin de carpes koï à l'aquarelle. Envoyez son identifiant dans `style` ; toute autre valeur renvoie une erreur `400 VALIDATION_ERROR`. Les styles sont ceux proposés sous forme de puces dans le [studio d'art IA](/ai/art) et dans l'onglet Art du Playground, et ils fonctionnent dans tous les modes.

| `style` | Rendu |
| --- | --- |
| `watercolor` | Aquarelle |
| `oil-painting` | Peinture à l'huile |
| `anime` | Anime |
| `cartoon` | Dessin animé |
| `pixel-art` | Pixel art |
| `pop-art` | Pop art |
| `charcoal` | Fusain |
| `ink` | Encre |
| `cyberpunk` | Cyberpunk |
| `fantasy` | Fantasy |
| `photographic` | Photographique |
| `low-poly` | Low poly |
| `papercut` | Papier découpé |

`prompt` est facultatif. Si vous l'omettez, QRdx en rédige d'abord un à partir du `mode`, du `style` et de la `photo` envoyés : une scène concrète avec un sujet, un décor et la lumière, ou, en mode photo, une description du contenu de votre photo afin que l'art le conserve. Cette rédaction ne consomme aucune image d'art IA supplémentaire. La réponse inclut alors le texte rédigé sous `writtenPrompt`, ce qui vous permet de le renvoyer, modifié, la fois suivante. Si la rédaction échoue, vous recevez `502 AI_ART_DESCRIBE_FAILED` et aucune image n'est consommée.

## Champs de la requête [#request-fields]

| Champ | Valeur par défaut | Description |
| --- | --- | --- |
| `text` | | Ce que le code encode, jusqu'à 300 caractères. Envoyez ce champ ou `code` |
| `code` | | L'`id` d'un code dynamique, à la place de `text` |
| `prompt` | rédigé pour vous | L'illustration à peindre, en mots simples, d'au moins 3 caractères lorsqu'il est envoyé |
| `mode` | `code` | `code`, `scene` ou `photo` ; voir plus haut |
| `style` | | L'identifiant d'un style rapide, combiné à votre prompt |
| `negativePrompt` | | Ce qu'il faut exclure de l'image |
| `visibility` | `50` | Visibilité du QR, de `0` à `100` : plus la valeur est élevée, plus le code est net ; plus elle est basse, plus l'image est favorisée |
| `creativity` | `45` | `0` suit le prompt à la lettre, `100` l'interprète librement |
| `seed` | aléatoire | Envoyez la graine d'une réponse précédente pour obtenir une image similaire |
| `reference` | | Une image de référence pour les couleurs et les formes, comme un logo ou une palette |
| `photo` | | Mode photo uniquement : l'image dans laquelle peindre le code |

`reference` et `photo` sont des URL `data:` PNG ou JPEG (`data:image/jpeg;base64,…`). Réduisez une `reference` à environ 512 px sur son plus grand côté (600 Ko au maximum), et recadrez une `photo` en carré à environ 1024 px (1 Mo au maximum), la taille à laquelle l'art est généré. Elles sont transmises au modèle puis supprimées : QRdx ne les stocke ni ne les consigne jamais. Les images plus grandes sont refusées avec `413 AI_ART_IMAGE_TOO_LARGE`. La [page de référence](/docs/developers/api/create-art) donne le schéma complet et un panneau Try it.

## Crédits et limites [#credits-and-limits]

L'API puise dans les mêmes images d'art IA mensuelles que l'application, décomptées pour l'espace de travail auquel appartient la clé. Les offres Gratuit, Pro et Business incluent chacune un certain nombre d'images par mois, et Business les partage entre toute l'équipe ; [Offres et limites](/docs/plans-and-limits) donne les chiffres. Elles sont réinitialisées le 1er de chaque mois (UTC).

- Lorsque les images du mois sont épuisées, l'API répond `AI_ART_CREDITS_EXHAUSTED` : `402` avec Gratuit et Pro, où une mise à niveau en ajoute, et `429` avec Business.
- Chaque personne peut créer au plus 25 images par jour, en plus du quota mensuel (`429 AI_ART_DAILY_LIMIT`), et lancer jusqu'à 12 images par minute.
- Chaque appel compte aussi dans le quota API quotidien de l'espace de travail et dans la limite par minute sur les écritures ([Limites de débit](/docs/developers/rest-api#rate-limits)).

## En cas de problème [#if-something-goes-wrong]

Les erreurs ont la forme habituelle de l'API (`code`, `message`, `status`) ; la page [Erreurs](/docs/developers/errors) les répertorie toutes. Aucune des erreurs `5xx` ne consomme d'image.

| Statut | `code` | Que faire |
| --- | --- | --- |
| 400 | `AI_ART_TEXT_TOO_LONG` | Raccourcissez `text`, ou envoyez le `code` d'un code dynamique |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | Attendez le 1er du mois, ou passez à une offre supérieure |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | Réduisez la taille de `photo` ou de `reference` |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Business : attendez le 1er du mois |
| 429 | `AI_ART_DAILY_LIMIT` | Réessayez demain (UTC) |
| 502 | `AI_ART_FAILED` | Le modèle a échoué ou a refusé le prompt. Réessayez ou reformulez-le |
| 502 | `AI_ART_UNSCANNABLE` | Réessayez avec une `visibility` plus élevée ou une autre seed |
| 502 | `AI_ART_DESCRIBE_FAILED` | Aucun `prompt` n'a été envoyé et sa rédaction a échoué. Réessayez ou envoyez le vôtre |
| 503 | `AI_ART_BUSY` | Le modèle est occupé. Attendez une minute et réessayez |
| 503 | `AI_NOT_CONFIGURED` | L'art IA n'est pas configuré sur ce serveur (auto-hébergé) |
| 504 | `AI_ART_TIMEOUT` | Le modèle a mis trop de temps (en mode scène, l'image a laissé trop peu de temps pour peindre le code). Réessayez, ou utilisez le mode code |

Une instance auto-hébergée sans Vercel AI Gateway répond à chaque appel par :

```json title="503 Service Unavailable"
{"code":"AI_NOT_CONFIGURED","message":"AI QR art is not configured on this server","status":503}
```

## MCP [#mcp]

Avec une clé API QRdx sur la connexion, le [serveur MCP](/docs/developers/mcp) dispose d'un outil `generate_ai_art`. Il accepte les mêmes champs que le corps de la requête et renvoie le PNG, la destination du scan et le nombre d'images restantes ce mois-ci. Demandez à votre assistant en langage courant :

```txt title="Prompt"
Make AI QR art for my code cm5code0spring0menu00001: a bistro chalkboard menu on a brick wall, as a scene.
```

Sans clé, l'outil répond en indiquant comment en ajouter une. L'appel peut durer jusqu'à une minute, comme avec la REST API.

## Auto-hébergement [#self-hosting]

L'art IA passe par Vercel AI Gateway. Sur votre propre instance, définissez `AI_GATEWAY_API_KEY` ; sans cette variable, `POST /v1/art` et `generate_ai_art` répondent `503 AI_NOT_CONFIGURED`.
