Al terminar esta página, un flujo de trabajo de n8n creará imágenes de códigos QR, creará y editará códigos dinámicos en tu espacio de trabajo y leerá sus escaneos, y un segundo flujo se iniciará cada vez que se escanee, cree o modifique un código o se envíe un formulario.

El paquete `@qrdx/n8n-nodes-qrdx` añade dos nodos a [n8n](https://n8n.io):

- **QRdx** crea imágenes de códigos QR, crea y edita [códigos dinámicos](/docs/dynamic-qr-codes) y lee sus escaneos y tus temas guardados. Un agente de IA de n8n puede usarlo como herramienta.
- **QRdx Trigger** inicia un flujo de trabajo cuando se escanean, crean o modifican tus códigos, o cuando alguien envía un formulario en una [página alojada](/docs/forms-and-pages).

<Callout type="info" title="n8n autoalojado">
El paquete está en npm como [`@qrdx/n8n-nodes-qrdx`](https://www.npmjs.com/package/@qrdx/n8n-nodes-qrdx) y se instala en un n8n autoalojado. n8n Cloud solo ejecuta los nodos de la comunidad que n8n ha verificado, y este todavía no está verificado. Para recibir eventos en n8n Cloud, usa en su lugar un [nodo Webhook](#without-the-package).
</Callout>

## Antes de empezar [#before-you-start]

- Un n8n autoalojado donde puedas instalar nodos de la comunidad.
- Una [clave de API](/docs/developers/api-keys) del espacio de trabajo en el que deben funcionar los nodos, para las operaciones de códigos, escaneos y temas y para el trigger. Generar imágenes QR no requiere clave.
- Para el trigger: el plan Business, ya que los [webhooks](/docs/webhooks) forman parte de él, y n8n accesible en una dirección pública `https://`.

## 1. Instala los nodos [#1-install-the-nodes]

En n8n, abre **Settings → Community Nodes**, elige **Install**, introduce `@qrdx/n8n-nodes-qrdx`, acepta el aviso sobre nodos de la comunidad y elige **Install**. Después busca **QRdx** en el panel de nodos.

Si tu n8n oculta esa página, o lo gestionas desde la línea de comandos, instala el paquete en la carpeta `nodes` de la carpeta de usuario de n8n y reinicia n8n:

```bash title="Terminal"
mkdir -p ~/.n8n/nodes
cd ~/.n8n/nodes
npm install @qrdx/n8n-nodes-qrdx
```

Si n8n se ejecuta en Docker, ejecuta los mismos comandos dentro del contenedor (`docker exec -it n8n sh`) o configúralos en tu imagen.

## 2. Conecta tu espacio de trabajo [#2-connect-your-workspace]

Crea una [clave de API](/docs/developers/api-keys) en [Settings → API keys & apps](/dashboard?to=settings/developers) y luego añade en n8n una credencial **QRdx API** con la clave. Deja **Base URL** como `https://api.qrdx.dev/v1`, salvo que [autoalojes](/docs/self-hosting) QRdx; en ese caso usa tu dirección seguida de `/api/v1`.

n8n prueba la credencial leyendo tu perfil, lo que requiere el alcance `profile:read`, así que lo más sencillo es una clave de **Full access**. Una clave actúa sobre el espacio de trabajo en el que se creó.

## 3. Usa el nodo QRdx [#3-use-the-qrdx-node]

| Recurso | Operaciones |
| --- | --- |
| **QR Image** | **Generate** una imagen PNG, WebP, SVG o EPS. Sin clave de API ni cuenta |
| **Code** | **Create**, **Get**, **Get Many**, **Update** (incluidos archivar y restaurar), **Delete** |
| **Scan** | **Get Many** (escaneos individuales, los más recientes primero), **Get Summary** (totales, recuentos diarios y principales países, ciudades, dispositivos, navegadores y referentes) |
| **Theme** | **Get**, **Get Many** |

**Generate** coloca la imagen en un campo binario que puedes adjuntar a un correo o subir a cualquier sitio. Puedes definir su tamaño, colores, formas del cuerpo, de los ojos y de los puntos de los ojos, corrección de errores, margen, un [marco](/docs/features/frames) con su etiqueta y un icono de logo. La salida también incluye `url`: un enlace a la misma imagen desde la [API de imágenes](/docs/developers/image-api), listo para una etiqueta `<img>`.

Las operaciones de códigos y escaneos llaman a la [REST API](/docs/developers/rest-api) con tu clave y cuentan para la cuota diaria de API del espacio de trabajo. **Get Many** recorre los resultados por páginas por ti. **Create** recibe la URL de destino y, en los campos adicionales, un título, una parte final personalizada (`slug`) y un dominio personalizado; **Update** recibe los mismos campos además de archivar y restaurar. Los errores conservan el mensaje propio de QRdx: por ejemplo, una parte final personalizada requiere Pro o Business, y en Gratis el nodo muestra el [error](/docs/developers/errors) `PLAN_REQUIRED` de la API.

## 4. Inicia flujos de trabajo a partir de eventos [#4-start-workflows-from-events]

Añade el nodo **QRdx Trigger**, elige los **Events** y activa el flujo de trabajo. El nodo se suscribe mediante la [API de REST Hooks](/docs/webhooks#zapier-make-and-n8n-rest-hooks) y cancela la suscripción cuando desactivas el flujo. La suscripción aparece en **Settings → Webhooks** mientras está activa.

| Evento | Cuándo |
| --- | --- |
| **Scans** | Se escanean códigos. Las entregas se agrupan: una por minuto con hasta 100 escaneos y el recuento exacto |
| **Scan Milestones** | El primer escaneo de un código, luego 10, 100, 500, 1.000 escaneos y más |
| **New Codes** | Se crea un código dinámico |
| **Code Changes** | Cambia el destino, el título, el diseño o el dominio de un código |
| **Form Submissions** | Alguien envía un formulario en una página alojada |

El nodo comprueba el `X-QRdx-Signature` de cada entrega con el secreto de firma que QRdx devolvió al suscribirse, y responde `401` a todo lo que no coincida. En **Options**, activa **Output One Item per Scan** para obtener un lote de Scans como elementos separados, e **Include Test Events** para ejecutar el flujo cuando eliges **Send test** en **Settings → Webhooks**. Los payloads son los descritos en [Webhooks](/docs/webhooks#payloads).

El trigger necesita:

- el plan Business, ya que los [webhooks](/docs/webhooks) forman parte de él;
- una clave de API con `codes:write` (**Full access**);
- n8n en una dirección pública `https://`, porque QRdx no entrega a `localhost` ni a redes privadas. Detrás de un proxy, define `WEBHOOK_URL` de n8n. Esto también se aplica a la URL de prueba que n8n usa mientras eliges **Listen for test event**.

## Sin el paquete [#without-the-package]

QRdx puede entregar eventos directamente a un nodo **Webhook** de n8n, en n8n Cloud o en un n8n autoalojado:

1. Añade un nodo Webhook, establece su método HTTP en `POST` y copia su URL de producción.
2. Activa el flujo de trabajo. La URL de producción solo responde mientras el flujo está activo.
3. En [Settings → Webhooks](/dashboard?to=settings/webhooks), elige **Add endpoint**, pega la URL y selecciona los eventos.

Cada evento inicia el flujo con el payload JSON. Para comprobar las firmas, lee `X-QRdx-Signature` en un nodo Code y [verifícala](/docs/webhooks#verify-signatures) con el secreto de firma del endpoint.

## Si algo sale mal [#if-something-goes-wrong]

### Falla la prueba de la credencial [#the-credential-test-fails]

A la clave le falta `profile:read` (una clave **Custom** sin él), fue revocada o ha caducado, o la **Base URL** apunta al host equivocado. Una clave de **Full access** con `https://api.qrdx.dev/v1` pasa la prueba.

### El trigger no se activa, o `402 PLAN_REQUIRED` [#the-trigger-wont-activate-or-402-plan_required]

Los webhooks forman parte del plan Business. Mejora el plan del espacio de trabajo, o usa un nodo Webhook y las alertas por correo de [Notificaciones](/docs/notifications).

### El trigger se activa pero no llega nada [#the-trigger-activates-but-nothing-arrives]

QRdx no puede llegar a n8n: rechaza `http://`, `localhost` y las direcciones privadas, y no sigue redirecciones. Pon n8n detrás de un nombre de host público con `https://` y define `WEBHOOK_URL`. Después revisa las entregas de la suscripción en **Settings → Webhooks**.

### `PLAN_REQUIRED` al crear [#plan_required-on-create]

Una parte final personalizada o un dominio personalizado requiere Pro o Business. Deja esos campos vacíos en Gratis.
