QRdx veröffentlicht eine shadcn/ui-Registry mit QR-Code-Komponenten, die auf der `qrdx`-Bibliothek basieren. Die shadcn CLI kopiert den Quellcode jeder Komponente in dein Projekt, sodass der Code dir gehört und du ihn ändern kannst. Nutze die Registry, wenn du ein fertiges UI-Element brauchst, etwa mit Download-Buttons, einer Karte, einem Teilen-Dialog oder einem Scanner. Nutze das `QRCode` der Bibliothek selbst, wenn du nur den Code brauchst.

<NpmStatus package="qrdx" />

<PackageManagerTabs command="npx shadcn@latest add https://qrdx.dev/r/qr-code.json" />

Jede Komponente hat eine eigene Seite mit Live-Vorschau, Quellcode, Installationsschritten, Beispielen und einer Props-Tabelle. Hast du einen Code im [Playground](/playground?open=code&lang=shadcn) gestaltet? Kopiere ihn dort für die QR-Code-Komponente der Registry.

## Was installiert wird [#what-gets-installed]

Jede Komponente ist eine einzelne Datei in deinem `components`-Ordner. Die CLI installiert außerdem `qrdx` (plus `lucide-react` für die Icons, die die meisten Komponenten verwenden) und fügt die shadcn/ui-Komponenten hinzu, auf denen sie aufbaut, etwa `button`, `card`, `dialog`, `dropdown-menu`, `input` oder `label`. Die Seite jeder Komponente listet ihre eigenen Abhängigkeiten unter **Manual** in den Installations-Tabs auf.

Den vollständigen Index findest du unter [`https://qrdx.dev/r/registry.json`](https://qrdx.dev/r/registry.json) und jedes einzelne Element unter `https://qrdx.dev/r/<name>.json`.

## Installation über den Namen [#install-by-name]

Für die Installation mit einem Kurznamen fügst du die Registry zu deiner `components.json` hinzu:

```json title="components.json"
{
  "registries": {
    "@qrdx": "https://qrdx.dev/r/{name}.json"
  }
}
```

Füge dann eine oder mehrere Komponenten über den Namen hinzu:

<PackageManagerTabs command="npx shadcn@latest add @qrdx/qr-code @qrdx/qr-code-download @qrdx/qr-code-share-dialog" />

## Styling und Theming [#styling-and-theming]

Die Komponenten nutzen Tailwind-Klassen mit den Standard-Theme-Tokens von shadcn/ui (`bg-card`, `border`, `text-muted-foreground`, `ring-ring`) sowie deine eigenen Button-, Card-, Dialog- und Input-Komponenten. Sie folgen daher deinem Theme und dem Dark Mode. QR-Codes behalten standardmäßig einen hellen Hintergrund, weil dunkle Module auf einer hellen Fläche mit jedem Lesegerät scannen. Auf der Seite [QR Code](/docs/components/qr-code#dark-mode) siehst du, wie sie stattdessen dem Theme folgen.

Jede Komponente ist eine Client Component (ihre Datei beginnt mit `"use client"`), wegen ihrer Buttons und ihres Zustands. Der Code selbst wird trotzdem auf dem Server gerendert, sodass er im HTML der Seite steht, bevor die Buttons interaktiv werden. Eine Seite als Server Component kann jede davon importieren und Serverdaten als Props übergeben.

PDF-Downloads brauchen das optionale Paket `jspdf` (`npm install jspdf`). Alles andere funktioniert, sobald die CLI fertig ist.
