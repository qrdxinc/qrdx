이 페이지를 마치면 n8n 워크플로가 QR 코드 이미지를 만들고, 워크스페이스에서 동적 QR 코드를 만들고 수정하며, 해당 코드의 스캔 내역을 읽어 와요. 또 다른 워크플로는 코드가 스캔되거나 생성되거나 변경될 때, 또는 양식이 제출될 때마다 시작돼요.

`@qrdx/n8n-nodes-qrdx` 패키지는 [n8n](https://n8n.io)에 노드 두 개를 추가해요.

- **QRdx**는 QR 코드 이미지를 만들고, [동적 QR 코드](/docs/dynamic-qr-codes)를 만들고 수정하며, 스캔 내역과 저장된 테마를 읽어요. n8n AI Agent가 도구로 사용할 수 있어요.
- **QRdx Trigger**는 코드가 스캔되거나 생성되거나 변경될 때, 또는 누군가 [호스팅 페이지](/docs/forms-and-pages)에서 양식을 제출할 때 워크플로를 시작해요.

<Callout type="info" title="자체 호스팅 n8n">
이 패키지는 npm에 [`@qrdx/n8n-nodes-qrdx`](https://www.npmjs.com/package/@qrdx/n8n-nodes-qrdx)로 올라와 있으며 자체 호스팅 n8n에 설치해요. n8n Cloud는 n8n이 검증한 커뮤니티 노드만 실행하는데, 이 노드는 아직 검증되지 않았어요. n8n Cloud에서 이벤트를 받으려면 대신 [Webhook 노드](#without-the-package)를 사용하세요.
</Callout>

## 시작하기 전에 [#before-you-start]

- 커뮤니티 노드를 설치할 수 있는 자체 호스팅 n8n.
- 노드가 작업할 워크스페이스의 [API 키](/docs/developers/api-keys). 코드, 스캔, 테마 작업과 트리거에 필요해요. QR 이미지 생성에는 키가 필요 없어요.
- 트리거에는 Business 플랜이 필요해요. [웹훅](/docs/webhooks)이 Business 플랜에 포함되어 있기 때문이에요. 또한 n8n에 공개 `https://` 주소로 접근할 수 있어야 해요.

## 1. 노드 설치 [#1-install-the-nodes]

n8n에서 **Settings → Community Nodes**를 열고 **Install**을 선택한 다음 `@qrdx/n8n-nodes-qrdx`를 입력하세요. 커뮤니티 노드 관련 안내를 수락하고 **Install**을 선택하세요. 그런 다음 노드 패널에서 **QRdx**를 검색하세요.

n8n에서 해당 페이지가 숨겨져 있거나 명령줄로 관리한다면, n8n 사용자 폴더의 `nodes` 폴더에 패키지를 설치하고 n8n을 다시 시작하세요.

```bash title="Terminal"
mkdir -p ~/.n8n/nodes
cd ~/.n8n/nodes
npm install @qrdx/n8n-nodes-qrdx
```

n8n이 Docker에서 실행 중이라면 컨테이너 안에서 같은 명령을 실행하거나(`docker exec -it n8n sh`) 이미지에 설정해 두세요.

## 2. 워크스페이스 연결 [#2-connect-your-workspace]

[Settings → API keys & apps](/dashboard?to=settings/developers)에서 [API 키](/docs/developers/api-keys)를 만든 다음, n8n에서 해당 키로 **QRdx API** 자격 증명을 추가하세요. QRdx를 [자체 호스팅](/docs/self-hosting)하지 않는다면 **Base URL**은 `https://api.qrdx.dev/v1`로 두세요. 자체 호스팅한다면 사용하는 주소 뒤에 `/api/v1`을 붙여 입력하세요.

n8n은 프로필을 읽어 자격 증명을 테스트하는데, 이때 `profile:read` 범위가 필요해요. 그래서 **Full access** 키가 가장 간단해요. 키는 만들어진 워크스페이스에서만 작동해요.

## 3. QRdx 노드 사용 [#3-use-the-qrdx-node]

| 리소스 | 작업 |
| --- | --- |
| **QR Image** | PNG, WebP, SVG, EPS 이미지를 **Generate**해요. API 키도 계정도 필요 없어요 |
| **Code** | **Create**, **Get**, **Get Many**, **Update**(보관 및 복원 포함), **Delete** |
| **Scan** | **Get Many**(개별 스캔, 최신순), **Get Summary**(총계, 일별 횟수, 상위 국가·도시·기기·브라우저·유입 경로) |
| **Theme** | **Get**, **Get Many** |

**Generate**는 이미지를 바이너리 필드에 넣어 주므로 이메일에 첨부하거나 어디에든 업로드할 수 있어요. 크기, 색상, 본체·눈·눈 점 모양, 오류 정정, 여백, 레이블이 있는 [프레임](/docs/features/frames), 로고 아이콘을 설정할 수 있어요. 출력에는 `url`도 있어요. [이미지 API](/docs/developers/image-api)에서 같은 이미지를 가리키는 링크이며, `<img>` 태그에 바로 쓸 수 있어요.

코드와 스캔 작업은 키로 [REST API](/docs/developers/rest-api)를 호출하며 워크스페이스의 일일 API 할당량에 포함돼요. **Get Many**는 결과를 알아서 페이지별로 가져와요. **Create**는 대상 URL을 받고, 추가 필드로 제목, 사용자 지정 back-half(`slug`), 사용자 지정 도메인을 받아요. **Update**는 같은 필드에 더해 보관과 복원도 받아요. 오류에는 QRdx의 메시지가 그대로 담겨요. 예를 들어 사용자 지정 back-half는 Pro 또는 Business가 필요하고, 무료 플랜에서는 노드에 API의 `PLAN_REQUIRED` [오류](/docs/developers/errors)가 표시돼요.

## 4. 이벤트로 워크플로 시작 [#4-start-workflows-from-events]

**QRdx Trigger** 노드를 추가하고 **Events**를 고른 다음 워크플로를 활성화하세요. 노드는 [REST Hooks API](/docs/webhooks#zapier-make-and-n8n-rest-hooks)로 구독하며, 워크플로를 비활성화하면 구독을 해제해요. 구독은 활성 상태인 동안 **Settings → Webhooks**에 표시돼요.

| 이벤트 | 시점 |
| --- | --- |
| **Scans** | 코드가 스캔될 때. 전송은 일괄 처리돼요. 1분에 한 번, 최대 100건의 스캔과 정확한 횟수가 담겨요 |
| **Scan Milestones** | 코드의 첫 스캔, 그다음 10, 100, 500, 1,000회 이상 |
| **New Codes** | 동적 QR 코드가 생성될 때 |
| **Code Changes** | 코드의 대상, 제목, 디자인 또는 도메인이 변경될 때 |
| **Form Submissions** | 누군가 호스팅 페이지에서 양식을 제출할 때 |

노드는 구독할 때 QRdx가 돌려준 서명 비밀 키로 각 전송의 `X-QRdx-Signature`를 확인하고, 일치하지 않으면 `401`로 응답해요. **Options**에서 **Output One Item per Scan**을 켜면 Scans 일괄 전송이 개별 항목으로 나오고, **Include Test Events**를 켜면 **Settings → Webhooks**에서 **Send test**를 선택할 때 워크플로가 실행돼요. 페이로드는 [웹훅](/docs/webhooks#payloads)에 설명된 것과 같아요.

트리거에 필요한 조건은 다음과 같아요.

- Business 플랜. [웹훅](/docs/webhooks)이 Business 플랜에 포함되어 있어요.
- `codes:write`(**Full access**)가 있는 API 키.
- 공개 `https://` 주소의 n8n. QRdx는 `localhost`나 사설 네트워크로는 전송하지 않기 때문이에요. 프록시 뒤에 있다면 n8n의 `WEBHOOK_URL`을 설정하세요. **Listen for test event**를 선택하는 동안 n8n이 쓰는 테스트 URL에도 해당돼요.

## 패키지 없이 사용하기 [#without-the-package]

n8n Cloud든 자체 호스팅 n8n이든, QRdx는 n8n **Webhook** 노드로 이벤트를 직접 전달할 수 있어요.

1. Webhook 노드를 추가하고 HTTP 메서드를 `POST`로 설정한 다음 프로덕션 URL을 복사하세요.
2. 워크플로를 활성화하세요. 프로덕션 URL은 워크플로가 활성 상태일 때만 응답해요.
3. [Settings → Webhooks](/dashboard?to=settings/webhooks)에서 **Add endpoint**를 선택하고 URL을 붙여넣은 다음 이벤트를 고르세요.

각 이벤트는 JSON 페이로드와 함께 워크플로를 시작해요. 서명을 확인하려면 Code 노드에서 `X-QRdx-Signature`를 읽고 엔드포인트의 서명 비밀 키로 [검증](/docs/webhooks#verify-signatures)하세요.

## 문제가 생겼을 때 [#if-something-goes-wrong]

### 자격 증명 테스트가 실패해요 [#the-credential-test-fails]

키에 `profile:read`가 없거나(이 범위가 없는 **Custom** 키), 키가 폐기되었거나 만료되었거나, **Base URL**이 잘못된 호스트를 가리키는 경우예요. `https://api.qrdx.dev/v1`에 **Full access** 키를 사용하면 통과해요.

### 트리거가 활성화되지 않거나 `402 PLAN_REQUIRED`가 나와요 [#the-trigger-wont-activate-or-402-plan_required]

웹훅은 Business 플랜에 포함되어 있어요. 워크스페이스를 업그레이드하거나, 대신 Webhook 노드와 [알림](/docs/notifications)의 이메일 알림을 사용하세요.

### 트리거는 활성화되었는데 아무것도 도착하지 않아요 [#the-trigger-activates-but-nothing-arrives]

QRdx가 n8n에 접근할 수 없는 상태예요. QRdx는 `http://`, `localhost`, 사설 주소를 거부하고 리디렉션도 따라가지 않아요. n8n을 공개 `https://` 호스트 이름 뒤에 두고 `WEBHOOK_URL`을 설정하세요. 그런 다음 **Settings → Webhooks**에서 구독의 전송 내역을 확인하세요.

### Create에서 `PLAN_REQUIRED`가 나와요 [#plan_required-on-create]

사용자 지정 back-half나 사용자 지정 도메인에는 Pro 또는 Business가 필요해요. 무료 플랜에서는 해당 필드를 비워 두세요.
