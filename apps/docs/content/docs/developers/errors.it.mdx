Ogni errore della REST API è un JSON con la stessa struttura, indipendentemente dall'endpoint che lo restituisce. Gestisci i casi in base a `code`, che non cambia mai; `message` è scritto per le persone e può essere riformulato.

```json title="403 Forbidden"
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

## Codici di errore [#error-codes]

Ordinati per stato. Un codice che compare due volte ha un significato diverso in ciascuno stato.

| Stato | Codice | Quando succede | Cosa fare |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Il body, la query o il path non ha superato la validazione. `data.details` elenca ogni problema come `{ path, message }` (`{ param, message }` nell'API delle immagini), con l'`index` della riga quando il body è un array di codici. | Correggi i campi elencati in `data.details` e invia di nuovo la richiesta. |
| 400 | `INVALID_SLUG` | Il back-half personalizzato (`slug`) viola una regola: è una parola riservata oppure lo stesso back-half compare due volte nella stessa richiesta. Per un array, `data.details` elenca ogni riga per `index`. | Scegli un altro back-half. Il messaggio indica la regola. |
| 400 | `TOO_MANY_CODES` | Più di 1.000 codici in una sola richiesta. Di norma lo schema del body lo rifiuta prima, come `VALIDATION_ERROR`. | Invia al massimo 1.000 codici per richiesta. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` punta a un dominio personalizzato che non è ancora verificato. | Completa la verifica del dominio nella pagina Domini, oppure ometti `domainId`. |
| 400 | `SID_REQUIRED` | Una conversione senza il `qrdx_sid` della scansione (dal browser), oppure senza `sid` o `code` (da un server). | Invia il `qrdx_sid` che il link breve ha aggiunto all'URL della tua pagina oppure, con una chiave API o un token, l'id del codice come `code`. |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` è troppo lungo per l'AI art (più di 300 caratteri). | Invia invece come `code` l'id di un codice dinamico: l'arte codifica il suo link breve, che è corto e resta modificabile. |
| 401 | `UNAUTHORIZED` | Nessuna credenziale: la richiesta non ha l'header `Authorization: Bearer` (e nemmeno una sessione browser QRdx). | Invia una chiave API come `Authorization: Bearer <key>`; creane una in Impostazioni → Chiavi API e app. I token di accesso OAuth vanno nello stesso header. |
| 401 | `INVALID_TOKEN` | La chiave API o il token di accesso è sconosciuto, revocato o scaduto (i token di accesso durano un'ora), oppure chi ha creato la chiave è stato bannato o ha lasciato il workspace della chiave. | Verifica di aver inviato la chiave per intero, oppure creane una nuova. Per un token di accesso, ottienine uno nuovo con il refresh token oppure fai ripetere l'autorizzazione all'utente. |
| 402 | `PLAN_REQUIRED` | La funzione non è inclusa nel piano del workspace: la creazione in blocco, i back-half personalizzati e i domini personalizzati richiedono Pro; le conversioni e gli hook richiedono Business. | Passa a un piano superiore per il workspace oppure togli la funzione dalla richiesta. |
| 402 | `LIMIT_REACHED` | Il workspace ha già tutti i QR code dinamici attivi inclusi nel suo piano (10 con Gratuito). | Archivia un codice (i codici archiviati non contano) oppure passa a Pro per avere codici illimitati. |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | Il workspace ha usato le immagini AI art di questo mese (Gratuito e Pro). Per la richiesta non è stato addebitato nulla. | Aspetta che la quota si azzeri il 1° del mese (UTC) oppure passa a un piano superiore per avere più immagini. |
| 403 | `INSUFFICIENT_SCOPE` | La chiave API o il token è valido ma non ha lo scope richiesto da questo endpoint. | Crea una chiave con lo scope indicato nel messaggio (gli scope di una chiave non si possono modificare). Per un'app OAuth, aggiungi lo scope e richiedilo quando l'utente autorizza. |
| 403 | `FORBIDDEN` | Il chiamante non può eseguire questa azione: un membro del workspace che elimina un codice creato da un altro, un membro che gestisce gli hook, oppure una scrittura da sessione browser proveniente da un altro sito. Una chiave API può fare solo ciò che consente il ruolo del suo creatore nel workspace. | Rivolgiti a un proprietario o a un amministratore del workspace, oppure chiama l'API con una chiave API dal tuo server. |
| 403 | `CONFIRMATION_REQUIRED` | Creare un hook con una sessione browser autenticata richiede un "Conferma che sei tu" recente. Alle chiavi API e ai token OAuth non viene richiesto. | Conferma la tua identità in QRdx, poi riprova entro 10 minuti, oppure crea l'hook con una chiave API dal tuo server. |
| 403 | `CONVERSIONS_OFF` | Una conversione dal browser per un codice che non ha il tracciamento delle conversioni attivo. | Attiva il tracciamento delle conversioni per il codice, oppure segnala la conversione dal tuo server con una chiave API. |
| 403 | `LIMIT_REACHED` | Il workspace ha già 20 endpoint webhook e hook. | Elimina un endpoint o un hook che non usi più. |
| 404 | `NOT_FOUND` | L'endpoint non esiste, oppure il codice, l'hook, il tema o il dominio personalizzato non esiste nel workspace su cui agisce la chiave o il token. | Controlla il path e l'id. Una chiave API agisce sul workspace in cui è stata creata; un token OAuth agisce sul workspace personale del suo utente. |
| 404 | `INVALID_SID` | Il `qrdx_sid` è sconosciuto o ha più di 30 giorni, la finestra di attribuzione. | Invia il `qrdx_sid` di una scansione recente, oppure segnala la conversione tramite l'id del codice dal tuo server. |
| 409 | `SLUG_TAKEN` | Un altro codice usa già quel back-half su quel dominio. Per un array, `data.details` elenca per `index` ogni back-half già occupato e non viene creato nulla. | Scegli un altro back-half. |
| 413 | `PAYLOAD_TOO_LARGE` | Il body supera il limite dell'endpoint: 4 MB per i codici, 16 KB per gli hook, 8 KB per le conversioni. Vale anche per un batch di codici la cui risposta (ogni codice con il suo design) supererebbe 4 MB; non viene creato nulla. | Invia un body più piccolo. Per i codici, la causa usuale è un logo inline grande; per un batch, invia `Prefer: return=minimal` o meno codici. |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | L'immagine `photo` o `reference` supera il limite di dimensione dell'AI art (il messaggio indica quale). | Riduci l'immagine (una `reference` a circa 512 px sul lato più lungo, una `photo` a circa 1024 px quadrati) e inviala di nuovo come data URL PNG o JPEG. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Una scrittura senza `Content-Type: application/json`. | Invia un body JSON con `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk segnala l'URL di destinazione (malware, phishing o software indesiderato). Per un array, `data.details` elenca per `index` ogni riga segnalata e non viene creato nulla. | Usa un'altra destinazione. Se la segnalazione è errata, chiedi a Google di rivedere il sito. |
| 429 | `RATE_LIMITED` | Troppe richieste: un limite al minuto (viene impostato solo `Retry-After`) oppure la quota giornaliera del workspace (`Retry-After` più `X-RateLimit-*`). | Aspetta i secondi indicati da `Retry-After`. Per la quota giornaliera, aspetta le 00:00 UTC oppure passa a un piano superiore. |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Un workspace Business ha usato le immagini AI art di questo mese, condivise da tutto il team. | Aspetta che la quota si azzeri il 1° del mese (UTC). |
| 429 | `AI_ART_DAILY_LIMIT` | Chi ha creato la chiave ha già generato 25 immagini AI art oggi (UTC), un limite di sicurezza oltre alla quota mensile. | Riprova domani (UTC). |
| 500 | `INTERNAL_ERROR` | Qualcosa non ha funzionato lato QRdx. L'errore è stato registrato. | Riprova tra un attimo. Se continua a succedere, segnalalo indicando l'ora della richiesta. |
| 502 | `AI_ART_FAILED` | Il modello di immagini ha fallito, ha rifiutato il prompt o ha restituito un'immagine che QRdx non è riuscito a leggere. Non è stato usato alcun credito AI art. | Riprova oppure riformula il prompt. Il messaggio spiega cosa è successo. |
| 502 | `AI_ART_UNSCANNABLE` | Non è stato possibile rendere l'immagine del modello leggibile alla scansione con la visibilità del QR che hai scelto. Non è stato usato alcun credito AI art. | Riprova con un valore di `visibility` più alto, oppure con un altro seed. |
| 502 | `AI_ART_DESCRIBE_FAILED` | Hai omesso `prompt` e il modello di testo che ne scrive uno al posto tuo ha fallito. Non è stato usato alcun credito AI art. | Riprova oppure invia un tuo `prompt`. |
| 503 | `SLUG_UNAVAILABLE` | Non è stato possibile riservare in tempo uno slug libero per il link breve. | Invia di nuovo la stessa richiesta. |
| 503 | `AI_ART_BUSY` | Il modello di immagini è al momento oltre la sua capacità. Non è stato usato alcun credito AI art. | Aspetta un minuto e riprova. |
| 503 | `AI_NOT_CONFIGURED` | L'AI art non è configurata in questo deployment (un'istanza self-hosted senza `AI_GATEWAY_API_KEY`). | Usa l'API QRdx ospitata, oppure configura Vercel AI Gateway sulla tua istanza. |
| 503 | `UNAVAILABLE` | I domini personalizzati non sono configurati in questo deployment (un'istanza self-hosted che non li ha). | Ometti `domainId`, oppure configura i domini personalizzati sulla tua istanza. |
| 504 | `AI_ART_TIMEOUT` | Il modello di immagini ha impiegato troppo e QRdx ha smesso di aspettare prima del limite di un minuto della richiesta. Non è stato usato alcun credito AI art. | Riprova. Le chiamate di solito durano da 15 a 45 secondi. |

## Il corpo dell'errore [#the-error-body]

| Campo | Cos'è |
| --- | --- |
| `code` | Un codice stabile e leggibile da una macchina, preso dalla tabella qui sopra |
| `message` | Cosa è andato storto e come risolvere, scritto per le persone. La formulazione può cambiare |
| `status` | Lo stato HTTP, ripetuto |
| `docs` | Una pagina che spiega la soluzione, quando esiste |
| `data` | Dettagli aggiuntivi su alcuni errori. `VALIDATION_ERROR` elenca ogni problema in `data.details` |

Un errore di validazione indica ogni campo che non è andato a buon fine. In un batch di codici ogni problema include anche l'`index` della riga, contato a partire da 0:

```json title="400 Bad Request"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Gli endpoint immagine (`GET /v1/qr`, `GET /v1/barcode`) segnalano i parametri della query come `{ "param", "message" }` invece di `{ "path", "message" }`.

## Nuovi tentativi [#retrying]

- **`429`:** attendi il numero di secondi indicato in `Retry-After`, poi invia di nuovo la stessa richiesta. Quando la quota giornaliera si esaurisce, gli header `X-RateLimit-*` indicano quante richieste consente il piano e quando il conteggio si azzera (00:00 UTC). Un limite al minuto invia solo `Retry-After`. Vedi [limiti di frequenza](/docs/developers/rest-api#rate-limits).
- **`500`, `502`, `503` e `504`:** riprova con backoff esponenziale, partendo da circa un secondo. Gli errori `5xx` dell'arte AI non usano mai un'immagine, quindi un nuovo tentativo non costa nulla.
- **Altri `4xx`:** la stessa richiesta fallirà allo stesso modo. Correggila prima.

Ripetere `POST /v1/codes` è sicuro quando la richiesta include un header `Idempotency-Key`: la stessa chiave restituisce i codici creati dal primo tentativo, con `Idempotent-Replayed: true`, invece di crearli due volte ([Crea codici](/docs/developers/api/create-codes)). Senza l'header, elenca i tuoi codici prima di inviare di nuovo la richiesta. `POST /v1/conversions` si può ripetere in sicurezza se invii un tuo `id`: una ripetizione restituisce `200` con `duplicate: true`.

## `/v1/me` e `/v1/themes` [#v1me-and-v1themes]

Questi due endpoint inviano lo stesso corpo più i campi OAuth che hanno sempre inviato, `error` e `error_description` (lo stesso testo di `message`), così i client più vecchi continuano a funzionare:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED o INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (quota giornaliera) |
| `not_found` | NOT_FOUND (temi) |

## Endpoint OAuth [#oauth-endpoints]

Gli endpoint OAuth sotto `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) seguono invece lo standard OAuth 2.0: `{ "error", "error_description" }`, con `error` uno tra `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` o `access_denied`. Ricevere `invalid_grant` durante un refresh significa che il refresh token è già stato usato (ogni refresh ne restituisce uno nuovo), è scaduto dopo 30 giorni, oppure l'utente ha revocato la tua app: fai ripassare l'utente dall'autorizzazione. Vedi [REST API e OAuth](/docs/developers/rest-api#get-an-access-token).

## Endpoint sconosciuti [#unknown-endpoints]

Un percorso sotto `/v1` che non esiste restituisce `404 NOT_FOUND` in JSON, mai una pagina HTML, con un link `docs` all'elenco degli endpoint. Il [riferimento API](/docs/developers/api) elenca tutti gli endpoint.
