读完本页,你将得到一个二维码图片 URL,可以粘贴到 README、`<img>` 标签或邮件模板中,样式随你定制,同时你也会了解 API 会拒绝哪些请求以及原因。

`GET https://api.qrdx.dev/v1/qr` 会返回 SVG、PNG 或 WebP 格式的二维码图片,也可以返回用于印刷和设计工具的矢量 EPS 文件。所有参数都放在查询字符串中,因此 URL 本身就是图片。它同样支持编辑器中的样式:渐变、边框(包括自定义边框)、描边、定位点和圆点颜色,以及 Logo 图标。无需账号或 API 密钥,但使用上传到 QRdx 的 Logo 时除外(参见 [Logo](#logos))。

```md title="README.md"
![QR code](https://api.qrdx.dev/v1/qr?data=https://github.com/you/repo)
```

[在 Playground 中试用](/playground?open=code&lang=image):先在那里设计二维码样式,再复制它的图片 URL。你也可以在 [渲染二维码图片](/docs/developers/api/get-qr-image) 参考页面中发送请求。

## 1. 请求图片 [#1-request-an-image]

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -o qr.png "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png&size=1024"
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="qr.mjs"
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/qr");
    url.searchParams.set("data", "https://qrdx.dev");
    url.searchParams.set("format", "png");
    url.searchParams.set("size", "1024");

    const response = await fetch(url);
    await writeFile("qr.png", Buffer.from(await response.arrayBuffer()));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="qr.py"
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/qr",
        params={"data": "https://qrdx.dev", "format": "png", "size": 1024},
    )
    response.raise_for_status()
    open("qr.png", "wb").write(response.content)
    ```
  </Tab>
</Tabs>

```txt title="Output"
qr.png: PNG image data, 1024 x 1024, 8-bit/color RGBA, non-interlaced
```

在 shell 中请给 URL 加上引号,以保留其中的 `&`。在 HTML 页面中,URL 可以直接放入 `src`:

```html title="index.html"
<img
  src="https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&size=256&fg=155dfc"
  width="256"
  height="256"
  alt="QR code for qrdx.dev"
/>
```

## 2. 选择格式 [#2-pick-a-format]

| `format` | 返回 | 适用场景 |
| --- | --- | --- |
| `svg`(默认) | `image/svg+xml` | 网页以及任何需要缩放的场景 |
| `png` | `image/png` | 电子邮件、聊天应用、文档 |
| `webp` | `image/webp`,无损,保留透明度 | 网站:像素与 PNG 相同,文件更小 |
| `eps` | `application/postscript`,以 `qr-code.eps` 下载形式发送 | Illustrator、InDesign、印刷厂。此时 `size` 表示以点为单位的宽度,每英寸 72 点,因此 `144` 即 2 英寸 |

```bash title="Terminal"
curl -o qr.webp "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=webp&size=1024"
curl -o qr.eps "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=eps&size=144"
head -2 qr.eps
# %!PS-Adobe-3.0 EPSF-3.0
# %%BoundingBox: 0 0 144 144
```

## 3. 设置样式 [#3-style-it]

通过扁平参数即可设置颜色、形状、边框和 Logo:

```txt title="Rounded modules with a frame drawn as a template"
https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&body=rounded&eye=rounded&dot=rounded&template=Arrow
```

```txt title="A built-in frame with its label, and a community frame by id"
https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&frame=banner-bottom&frameText=Scan%20the%20menu
https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&item=frame:wifi-card
```

如需使用渐变、自定义边框和分别设置每个定位点的颜色,请将整个设计以 JSON 形式放在 `style` 中发送:

```js title="styled.mjs"
const style = {
  fgColor: {
    type: "linear",
    angle: 45,
    stops: [
      { color: "#1d4ed8", offset: 0 },
      { color: "#7c3aed", offset: 100 },
    ],
  },
  eyeColor: "#b91c1c",
  frame: { style: "banner-bottom", text: "Scan the menu" },
};
const src = `https://api.qrdx.dev/v1/qr?data=${encodeURIComponent(link)}&style=${encodeURIComponent(JSON.stringify(style))}`;
// 200 image/svg+xml, 634.88 × 727.04: the frame adds to the 512 px code
```

<Callout type="info">
当 `data` 的值包含 `&`、`#`、`+` 或空格时,请对其进行编码,例如在 JavaScript 中使用 `encodeURIComponent`。否则 URL 会在这些字符处被截断。`style` 也要以同样的方式编码,并且颜色要写成不带 `#` 的形式(或写成 `%23`):单独的 `#` 会开启 URL 片段,且不会被发送。
</Callout>

## 参数 [#parameters]

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `data` | 必填 | 要编码的文本或 URL,最多 2048 个字符 |
| `format` | `svg` | `svg`、`png`、`webp` 或 `eps` |
| `size` | `512` | 宽度和高度,以像素为单位,范围 `64` 到 `2048`(EPS 为点) |
| `fg` | `000000` | 模块颜色,十六进制(`155dfc`、`fff`,或带透明度的 8 位) |
| `bg` | `ffffff` | 背景颜色,十六进制。`00000000` 表示透明背景 |
| `eyeColor` | `fg` | 三个角上定位点的颜色 |
| `dotColor` | `fg` | 每个定位点内部圆点的颜色 |
| `body` | `square` | 数据模块的形状;参见 [图案取值](#pattern-values) |
| `eye` | `square` | 角上定位点外框的形状 |
| `dot` | `square` | 每个定位点内部圆点的形状 |
| `level` | `Q` | 纠错级别:`L`(约 7%)、`M`(15%)、`Q`(25%)或 `H`(30%) |
| `margin` | `4` | 二维码四周的静区,以模块为单位,范围 `0` 到 `16` |
| `template` | 无 | [以模板绘制的边框](/docs/features/templates):整张图片宽度为 `size`,二维码在其中显得更小 |
| `frame` | 无 | 内置的行动号召[边框](/docs/features/frames),例如 `banner-bottom`、`speech-bubble` 或 `circle`:{facts.frameStyles} 种内置边框中的任意一种 |
| `frameText` | `Scan me` | 边框的文字标签,最多 24 个字符。也会修改 `style` 或 `item` 中边框的标签 |
| `style` | 无 | 以 JSON 表示的编辑器完整设计;参见 [样式](#style) |
| `item` | 无 | 按 id 指定的社区边框或主题,例如 `frame:wifi-card`;参见 [社区项目](#community-items) |
| `logoIcon` | 无 | 放在中心的快捷图标或品牌 Logo;参见 [Logo](#logos) |
| `logoFileId` | 无 | 按文件 id 指定的已上传 Logo;需要 API 密钥;参见 [Logo](#logos) |

枚举值(`level`、`format`、`template`、`frame`)不区分大小写。使用边框时,`size` 是二维码本身的宽度,边框会在此基础上增加图片尺寸,所有格式均如此。扁平参数优先于 `style`,`style` 优先于 `item`。

## 样式 [#style]

`style` 以 JSON 形式接收设计,字段与已保存的主题相同,因此来自 [`GET /v1/themes`](/docs/developers/api/list-themes) 的主题,或 [MCP 服务器](/docs/developers/mcp)的 `design_qr` 返回的 `qrdxStyle`,都可以原样传入(上传的 Logo 除外,见下文):

| 字段 | 接受的值 |
| --- | --- |
| `bgColor`、`fgColor`、`eyeColor`、`dotColor` | 一种颜色(十六进制如 `#155dfc`、`rgb()`、`hsl()` 或颜色名称),或一个渐变:`{ "type": "linear", "angle": 45, "stops": [...] }` 或 `{ "type": "radial", "stops": [...] }`,包含 2 到 8 个 `{ "color", "offset" }` 形式的色标(offset 为 0 到 100) |
| `bodyPattern`、`cornerEyePattern`、`cornerEyeDotPattern` | [图案取值](#pattern-values) |
| `level`、`margin` | 同上述参数(`margin` 为 0 到 16) |
| `templateId` | 以模板绘制的边框,`default` 表示无 |
| `frame` | 内置边框:`{ "style": "banner-bottom", "text": "Scan me", "color": "#155dfc", "textColor": "#ffffff" }`,或自定义边框:`{ "style": "custom", "spec": { … } }`,其中边框规范来自[社区](#community-items),或来自在 Playground 的边框部分制作的自定义边框。规范会按引擎的边框规范规则进行检查(不允许标记、链接或图片;最大 32 KB) |
| `eyeColors` | 每个定位点的颜色,优先于 `eyeColor` 和 `dotColor`:`{ "topLeft": { "outer": "#b91c1c", "inner": "#1d4ed8" }, "topRight": …, "bottomLeft": … }`,每项可以是颜色或渐变 |
| `moduleScale` | 每个圆点的大小,`0.5` 到 `1`(默认 `1`) |
| `shape` | `square`(默认)或 `circle`:由装饰性圆点组成的圆盘形二维码 |
| `autoLevel` | 当 Logo 覆盖超过二维码 7% 的面积时,将纠错级别提高到 `H`(有 Logo 时此处始终开启) |
| `logoOptions` | Logo 的布局:`size`(占二维码宽度的 `0.1` 到 `0.3`;当二维码无法腾出足够模块时,QRdx 会将其缩小)、`padding`(`0` 到 `2` 个模块)、`x` 和 `y`(`0` 到 `1`)、`shape`(`square`、`rounded` 或 `circle` 裁剪)以及 `plate`(其后的底色) |
| `showLogo`、`logoIcon`、`logoFileId` | 参见 [Logo](#logos) |

`style` 也接受 Playground 链接中的 `style` 值(以 `1.` 开头),因此从 [Playground](/playground) 分享的设计可以渲染成与那里一致的外观,但不含其 Logo。未知字段、Logo 地址(`customLogo`)以及 Logo QR 或 Image QR 的图案(`art`)都会被拒绝,并返回说明原因的 `400`:

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"style.customLogo","message":"Logo images by address aren't accepted: upload the image to QRdx and pass its file id as logoFileId, or pick a logoIcon."}]},"status":400}
```

## 社区项目 [#community-items]

`item` 会渲染已发布的[社区](/community)边框或主题,以 CC0 免费提供。可通过 [`GET /v1/community/items`](/docs/developers/api/list-community-items) 查找 id,也可以打开某个项目页面,使用其类型和 slug:`/community/frames/wifi-card` 对应 `frame:wifi-card`。边框项目默认搭配黑底白色的普通二维码;可添加 `style` 或扁平参数来更改其下方的二维码。使用 `item` 的渲染结果会缓存 5 分钟(CDN 上为 10 分钟),因为项目可能会发布新版本或被下架。

## Logo [#logos]

- **快捷图标。** `logoIcon` 会把编辑器中的一个图标放在中央的白色底块上，可选值有：`wifi`、`location`、`phone`、`email`、`link`、`file`、`calendar`、`whatsapp` 或 `instagram`。这些图标由 QRdx 自行绘制，无需密钥。
- **品牌 Logo。** `logoIcon` 也接受 [Simple Icons](https://simpleicons.org) 中 {facts.brandLogos} 个品牌里的任意一个，用 slug 指定：`spotify`、`paypal`、`googlemaps`、`appstore`。标志会以品牌色直接绘制，不带底板；加上 `:black` 或 `:white` 可改为黑色或白色（`whatsapp:white`），在 `style` 中设置 `logoOptions.plate` 可在标志后添加底板。[`GET /api/brand-logos`](https://qrdx.dev/api/brand-logos) 会列出所有 slug。如果使用了 QRdx 没有的 slug，会返回 `400`，并提示正确的写法。
- **QRdx 标志**是编辑器默认显示的标志，这里不会绘制：单独设置 `showLogo: true` 不会添加任何 Logo。
- **使用 Logo 时纠错级别会提高。** 当 Logo 覆盖超过二维码 7% 的面积时，无论 `level` 设置为何，二维码都会按 `H` 级绘制，以确保仍可扫描。

```bash title="Terminal"
curl -o spotify.png "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png&logoIcon=spotify"
```

<IfAvailable feature="fileStorage">

**使用你自己的 Logo。** `logoFileId` 会绘制你在 [控制台 → 文件](/docs/files) 中上传的 PNG 或 JPEG 文件，大小不超过 1 MB。其 id 是文件链接的最后一部分，即 `https://qrdx.dev/api/files/<id>`。请发送拥有该文件的工作区的 [API 密钥](/docs/developers/api-keys)：

```bash title="Terminal"
curl -o qr.png -H "Authorization: Bearer $QRDX_API_KEY" \
  "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png&logoFileId=<id>"
```

响应为私有（`Cache-Control: private, no-store`），并计入工作区的每日 API 配额。来自其他工作区的文件会返回 `404`，未带密钥的请求会返回 `401`。QRdx 从自己的存储中读取图片，并检查它确实是 PNG 或 JPEG；它绝不会从你发送的网址获取 Logo。

</IfAvailable>

`logoOptions` 可以为上述任意 Logo 设置大小、位置、裁剪和底板。去除已上传 Logo 自带的背景需要在 Playground 中完成；Image API 会按原样绘制上传的文件。这里不支持 Logo QR 和 Image QR 艺术码：Playground 会在浏览器中根据你的图片生成它们。请在 [Playground](/playground?tab=art) 中设计艺术码，或者用 [AI 艺术 API](/docs/developers/ai-art-api) 把二维码绘制成 AI 艺术作品。

### 图案取值 [#pattern-values]

- `body`：`circle`、`circle-large`、`square`、`diamond`、`circle-mixed`、`pacman`、`rounded`、`small-square`、`vertical-line`、`horizontal-line`、`liquid`、`liquid-horizontal`、`liquid-vertical`、`classy`、`classy-rounded`、`leaf`、`plus`、`hexagon`、`star`、`heart`、`random-dots`、`mosaic`、`octagon`
- `eye`：`square`、`rounded`、`gear`、`circle`、`diya`、`extra-rounded`、`message`、`pointy`、`leaf`、`drop`、`octagon`、`bevel`、`squircle`、`cushion`、`shield`、`petal`、`leaf-reverse`
- `dot`：`square`、`rounded`、`circle`、`message`、`message-reverse`、`diya`、`diya-reverse`、`rounded-triangle`、`leaf`、`drop`、`plus`、`cross-rounded`、`hexagon`、`octagon`、`flower`、`heart`、`squircle`、`dots`、`extra-rounded`、`leaf-reverse`、`drop-reverse`
- `template`：`default`、`Arrow`、`StandardBox`、`SquareBorder`、`StrikedBox`、`Halloween`、`DotRing`

这些样式与 [`qrdx` React 库](/docs/features/patterns)中的相同。[MCP 服务器](/docs/developers/mcp)也可以列出它们，并附带简短说明。

## 响应 [#responses]

请求成功时会返回图片，并带有以下响应头：

- `Content-Type: image/svg+xml`、`image/png`、`image/webp` 或 `application/postscript`（EPS 会作为 `qr-code.eps` 下载发送）
- `Cache-Control: public, max-age=31536000, immutable`，但使用 `item` 的渲染（5 分钟，CDN 上为 10 分钟）和使用 `logoFileId` 的渲染（`private, no-store`）除外
- `Access-Control-Allow-Origin: *`，因此你可以在任何网站上用 `fetch` 获取它

渲染是确定性的：相同的查询字符串始终返回相同的字节，所以响应可以缓存一年。只使用原有参数的 URL 渲染结果与以往完全一致。

## 出错时 [#if-something-goes-wrong]

### 带有 `"param": "size"` 的 `400` [#400-with-param-size]

`size` 小于 64 或大于 2048。响应正文会指出限制：

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"size","message":"Too small: expected number to be >=64"}]},"status":400}
```

### 带有 `"param": "data"` 的 `400` [#400-with-param-data]

在所选的纠错级别下，数据无法放入二维码。请使用更低的 `level`（`L` 容量最大）或更短的数据；对于较长的 URL，通常的解决办法是使用动态二维码的短链接。

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"Data is too long for a QR code at error correction level H. Shorten it or use a lower level (L holds the most)."}]},"status":400}
```

### 带有 `"param": "logoIcon"` 的 `400` [#400-with-param-logoicon]

该 slug 既不是 QRdx 支持的品牌，也不是快捷图标。错误信息会给出可用的写法（`spotify`、`paypal`、`googlemaps`，或 `wifi`、`phone`、`email`）。

### 图片显示异常或被截断 [#the-image-looks-wrong-or-is-split]

`data` 或 `style` 中的 `&`、`#` 或 `+` 没有编码，导致 URL 在该字符处被截断。请对这两个值进行编码，并且颜色不要带 `#`。

### `429 RATE_LIMITED` [#429-rate_limited]

同一 IP 地址每分钟的请求超过了 {facts.imageApiPerMinute} 次。请等待 `Retry-After` 中指定的秒数。相同的 URL 始终返回相同的图片，因此请缓存它或保存文件，而不要实时加载。

## 限制 [#limits]

- **速率限制：**每个 IP 地址每分钟 {facts.imageApiPerMinute} 次请求。图片请求不占用 REST API 的每日配额。
- **不做扫描检查。** Image API 只会按你的要求绘制。若要先检查并修复设计的扫描得分，请使用 [MCP 服务器](/docs/developers/mcp)上的 `design_qr`，或 [Playground](/playground?tab=design) 中的扫描得分。
- **`style` 在 URL 中最多 8,192 个字符**，其 JSON 最大 40 KB。
- **数据是 URL 的一部分。**和任何 URL 一样，它可能出现在服务器日志、浏览器历史记录和缓存中。请不要在其中放入密码或其他机密信息。

## 扫描提示 [#scanning-tips]

- 当图片放在深色或杂乱的背景上时（例如 GitHub 深色模式下的 README），请将 `margin` 保持在 `2` 或更大。
- `fg` 与 `bg` 之间要保持良好的对比度。浅色背景上的深色模块扫描最可靠。
- 默认设置（方形模块、4 个模块宽的边距）在所有读取器上都能扫描。`circle` 圆点等风格化形状看起来更柔和，但一些较旧的扫描器读取它们时可靠性较低：请用[扫描检查器](/tools/scan-checker)检查。
- 打印前，请用几部手机测试二维码。

## 自托管 [#self-hosting]

该端点是 QRdx Web 应用的一部分，因此[自托管](/docs/self-hosting)实例会在你自己域名下的 `/api/v1/qr` 提供服务（例如 `https://qr.example.com/api/v1/qr?data=…`）。较短的 `/v1/qr` 路径只在 `api.qrdx.dev` 上有效。配置了 Upstash Redis 时，速率限制会使用它，否则不启用速率限制。
