इस पेज के अंत तक आप जान जाएँगे कि एजेंट को QR कोड देने के तीनों तरीकों में से कौन-सा आपके काम का है, उसे सेट अप कर चुके होंगे, और यह भी जान लेंगे कि हर तरीका क्या कर सकता है और क्या नहीं।

| एजेंट को चाहिए | इस्तेमाल करें | Key या अकाउंट |
| --- | --- | --- |
| चैट या एजेंट रन में QR कोड बनाना | [MCP server](#1-connect-the-mcp-server) | कोई नहीं |
| Markdown, HTML, ईमेल या बिल्ड में QR कोड डालना | [Image API](#2-give-agents-qr-image-urls) | कोई नहीं |
| डायनेमिक कोड बनाना या बदलना, स्कैन पढ़ना | [REST API](#3-call-the-rest-api-for-a-user) | API key, या OAuth access token |
| AI आर्टवर्क में QR कोड पेंट करना | [AI art API](/docs/developers/ai-art-api): `POST /v1/art` या MCP टूल `generate_ai_art` | API key; वर्कस्पेस की मासिक AI art इमेज इस्तेमाल होती हैं |
| QRdx docs पढ़ना | [Markdown और llms.txt](#4-read-qrdx-as-markdown) | कोई नहीं |

## 1. Connect the MCP server [#1-connect-the-mcp-server]

QRdx MCP server `https://mcp.qrdx.dev/mcp` पर है। यह Streamable HTTP transport इस्तेमाल करता है और इसके लिए अकाउंट, साइन-इन या API key की ज़रूरत नहीं है। इसके टूल जाँचे हुए स्कैन स्कोर के साथ QR कोड डिज़ाइन करते हैं, उन्हें रेंडर करते हैं, Wi-Fi, कॉन्टैक्ट, ईमेल, SMS, लोकेशन और पेमेंट के payload बनाते हैं, कम्युनिटी में खोजते हैं और बारकोड बनाते हैं; इनकी सूची इनपुट के साथ [MCP server](/docs/developers/mcp) में है। [connect पेज](/mcp) पर Claude, Cursor और VS Code के लिए one-click बटन हैं और कई और क्लाइंट के स्टेप भी।

### MCP क्लाइंट के लिए Discovery [#discovery-for-mcp-clients]

जो क्लाइंट और registries servers को खुद खोजते हैं, वे ये पढ़ सकते हैं:

- `https://mcp.qrdx.dev/mcp/server-card` पर **MCP Server Card**, MCP [Server Card extension](https://modelcontextprotocol.io/seps/2127-mcp-server-cards) के फ़ॉर्मैट में: नाम, वर्शन, transport और सपोर्टेड protocol वर्शन;
- [`/.well-known/ai-catalog.json`](/.well-known/ai-catalog.json) पर **AI Catalog**, जो server card की ओर इशारा करता है;
- [`/.well-known/api-catalog`](/.well-known/api-catalog) पर **API catalog** ([RFC 9727](https://www.rfc-editor.org/rfc/rfc9727)), जो REST API को उसके [OpenAPI document](/openapi.json) और MCP server के साथ सूचीबद्ध करता है।

```bash title="Terminal"
curl https://mcp.qrdx.dev/mcp/server-card
```

```json title="200 OK (first fields)"
{
  "$schema": "https://static.modelcontextprotocol.io/schemas/v1/server-card.schema.json",
  "name": "dev.qrdx/qrdx",
  "version": "1.3.0",
  "title": "QRdx",
  "description": "Design scan-checked QR codes for any content, plus payloads and community frames. Key optional.",
  "websiteUrl": "https://qrdx.dev/mcp"
}
```

## 2. Give agents QR image URLs [#2-give-agents-qr-image-urls]

[image API](/docs/developers/image-api) बिना key के किसी URL को QR कोड इमेज में बदल देती है, इसलिए एजेंट इमेज को सीधे Markdown, HTML या ईमेल में लिख सकता है:

```txt title="URL shape"
https://api.qrdx.dev/v1/qr?data=<encoded text>&format=svg|png|webp|eps
```

```md title="README.md"
![QR code for qrdx.dev](https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fqrdx.dev&format=png&size=512)
```

- **`data` को एन्कोड करें** `encodeURIComponent` से, वरना `&`, `#`, `+` और स्पेस उसे तोड़ देते हैं।
- **डेस्टिनेशन के हिसाब से फ़ॉर्मैट चुनें।** PNG उन चैट apps और ईमेल क्लाइंट में चलता है जो SVG नहीं दिखाते; SVG वेब पर सबसे साफ़ दिखता है; EPS प्रिंट शॉप के लिए है।
- **क्वेरी पैरामीटर से स्टाइल करें** (`fg`, `bg`, `body`, `eye`, `dot`, `level`, `margin`, `template`, `frame`, `frameText`, `logoIcon`), या ग्रेडिएंट और कस्टम फ़्रेम के लिए पूरा डिज़ाइन JSON के रूप में [`style`](/docs/developers/image-api#style) में दें। वैल्यू की सूची [Image API](/docs/developers/image-api#parameters) में है, और MCP टूल `list_qr_styles` भी उन्हें लौटाता है।
- **एक ही URL हमेशा वही इमेज लौटाता है**, इसलिए उसे cache करना और embed करना सुरक्षित है।

## 3. Call the REST API for a user [#3-call-the-rest-api-for-a-user]

[डायनेमिक कोड](/docs/dynamic-qr-codes) बनाने या बदलने, स्कैन पढ़ने या [webhooks](/docs/webhooks) सब्सक्राइब करने के लिए एजेंट Bearer credential के साथ `https://api.qrdx.dev/v1` पर [REST API](/docs/developers/rest-api) कॉल करता है। [OpenAPI document](/openapi.json) हर endpoint, schema और error बताता है, और [API reference](/docs/developers/api) में हर एक का अलग पेज है, जो उसके URL के आगे `.md` लगाकर Markdown में भी मिलता है।

**आपके लिए काम करने वाला एजेंट** [API key](/docs/developers/api-keys) इस्तेमाल करता है:

1. **Key बनाएँ**, उस वर्कस्पेस की [Settings → API keys & apps](/dashboard?to=settings/developers&new=1) में जिसमें एजेंट को काम करना है (वर्कस्पेस बदलने के लिए workspace switcher इस्तेमाल करें)। Key उस वर्कस्पेस में आपके रोल के साथ काम करती है।
2. **सबसे कम एक्सेस दें।** कोड और स्कैन की रिपोर्ट के लिए **Read only** काफ़ी है; **Full access** या `codes:write` वाला **Custom** तभी चुनें जब एजेंट को कोड बनाने या बदलने हों। थोड़े समय चलने वाले एजेंट्स के लिए expiry सेट करें।
3. **Key को secret store या environment variable में रखें**, कभी प्रॉम्प्ट, लॉग या रिपॉज़िटरी में नहीं। इसे `Authorization: Bearer $QRDX_API_KEY` के रूप में भेजें।
4. **कोटा का ध्यान रखें।** हर वर्कस्पेस का प्लान के हिसाब से रोज़ का रिक्वेस्ट कोटा होता है ([Plans and limits](/docs/plans-and-limits) देखें)। `429 RATE_LIMITED` आने पर `Retry-After` में दिए सेकंड तक रुकें।

जब एजेंट की ज़रूरत न रहे, तो **Settings → API keys & apps** में key रद्द (revoke) कर दें।

**दूसरे लोगों के लिए काम करने वाला एजेंट** OAuth इस्तेमाल करता है, ताकि हर व्यक्ति उसे मंज़ूरी दे: एक app रजिस्टर करें, हर व्यक्ति के लिए एक बार PKCE के साथ authorization code flow चलाएँ, और उनके refresh tokens secret store में रखें। Access token एक घंटे चलते हैं, और हर refresh एक नया refresh token लौटाता है। स्टेप [Build an integration](/docs/developers/build-an-integration) में हैं। token से किए गए रिक्वेस्ट उसी व्यक्ति के अपने वर्कस्पेस पर काम करते हैं।

## 4. Read QRdx as Markdown [#4-read-qrdx-as-markdown]

- [`/llms.txt`](/llms.txt): LLMs के लिए पूरी साइट का इंडेक्स, जिसमें प्रोडक्ट, डेवलपर टूल, docs, help center, प्राइसिंग और लीगल पेज शामिल हैं।
- [`/llms-full.txt`](/llms-full.txt): हर docs पेज एक फ़ाइल में, sidebar के क्रम में। API reference पेजों में पूरा ऑपरेशन शामिल है: पैरामीटर, responses और एक उदाहरण।
- किसी भी docs URL में `.md` जोड़ने पर सिर्फ़ वही पेज मिलता है, जैसे [`/docs/developers/mcp.md`](/docs/developers/mcp.md)। [`/pricing.md`](/pricing.md) और [`/mcp.md`](/mcp.md) भी काम करते हैं।
- होम पेज, `/pricing`, `/mcp` या किसी भी docs पेज पर `Accept: text/markdown` के साथ रिक्वेस्ट करने पर उसी URL पर Markdown वर्शन मिलता है।

```bash title="Terminal"
curl -H "Accept: text/markdown" https://qrdx.dev/docs/developers/api/get-code
```

## सीमाएँ [#limits]

- **MCP टूल स्टैटिक QR कोड बनाते हैं।** ये इमेज रेंडर करते हैं, पेलोड बनाते हैं (Wi-Fi, कॉन्टैक्ट, ईमेल, SMS, मैप लोकेशन, पेमेंट) और पब्लिक कम्युनिटी पढ़ते हैं। API key के साथ `save_template` किसी डिज़ाइन को आपकी थीम में सेव करता है, `save_barcode` बारकोड सेव करता है और `generate_ai_art` वर्कस्पेस की मासिक AI आर्ट इमेज में से [AI QR आर्ट](/docs/developers/ai-art-api) बनाता है। ये डायनेमिक QR कोड नहीं बना सकते और कोड या स्कैन नहीं पढ़ सकते; इसके लिए REST API का इस्तेमाल करें।
- **लोगो QRdx से आते हैं, कभी वेब एड्रेस से नहीं।** MCP सर्वर और Image API बिना key के ग्रेडिएंट, फ़्रेम, एडिटर के क्विक लोगो आइकन और ब्रांड लोगो बनाते हैं, और आपकी API key के साथ QRdx पर अपलोड किया गया आपका लोगो उसकी फ़ाइल id से इस्तेमाल करते हैं। Logo QR और Image QR आर्ट [Playground](/playground?tab=art) में बनते हैं।
- **कम्युनिटी आइटम का टेक्स्ट सदस्य लिखते हैं।** API और MCP टूल इसे छोटा और बिना लिंक के लौटाते हैं; इसे डेटा मानें, निर्देश नहीं।
- **इमेज URL में एन्कोड किया गया डेटा होता है।** उनमें पासवर्ड या दूसरे सीक्रेट न डालें, जैसे किसी पब्लिक README में प्राइवेट Wi-Fi पासवर्ड।
- **रेट लिमिट हर IP एड्रेस पर लागू होती है**, MCP सर्वर पर ({facts.mcpPerMinute} रिक्वेस्ट प्रति मिनट, `design_qr` पर {facts.designQrPerMinute}) और Image API पर ({facts.imageApiPerMinute}); देखें [MCP सर्वर](/docs/developers/mcp#privacy-and-limits) और [Image API](/docs/developers/image-api#limits)।
- **OAuth टोकन सिर्फ़ उस व्यक्ति के अपने वर्कस्पेस पर काम करते हैं।** किसी दूसरे वर्कस्पेस में काम करने के लिए उसी में बनाई गई API key इस्तेमाल करें। क्लाइंट-क्रेडेंशियल्स ग्रांट उपलब्ध नहीं है।
