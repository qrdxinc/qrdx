读完本页，你将得到一个可用于 `<img>` 标签、商品数据源或标签模板的条形码图片 URL，了解校验位和格式是如何验证的，并知道如何把条形码保存到工作区，以便日后编辑。

`GET https://api.qrdx.dev/v1/barcode` 会返回一张条形码图片。所有参数都在查询字符串中，因此 URL 本身就是图片。它与[条形码生成器](/barcode-generator)绘制相同的 {facts.barcodeFormats} 种格式，规则相同，返回的 SVG 也相同。无需账号或 API 密钥。

```html title="index.html"
<img
  src="https://api.qrdx.dev/v1/barcode?format=ean13&data=590123412345"
  alt="EAN-13 barcode 5901234123457"
/>
```

这个数字少了一位，所以会自动补上校验位（7）。如果发送完整的 13 位数字，则会验证校验位：校验位错误时返回 `400`，并说明正确的校验位应该是什么。

## 1. 请求图片 [#1-request-an-image]

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -o box.png "https://api.qrdx.dev/v1/barcode?format=ean13&data=5901234123457&type=png&scale=3"
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="barcode.mjs"
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/barcode");
    url.search = new URLSearchParams({
      format: "ean13",
      data: "5901234123457",
      type: "png",
      scale: "3",
    }).toString();

    const response = await fetch(url);
    await writeFile("box.png", Buffer.from(await response.arrayBuffer()));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="barcode.py"
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/barcode",
        params={"format": "ean13", "data": "5901234123457", "type": "png", "scale": 3},
    )
    response.raise_for_status()
    open("box.png", "wb").write(response.content)
    ```
  </Tab>
</Tabs>

```txt title="Output"
200 image/png
box.png: PNG image data, 385 x 237, 8-bit/color RGBA, non-interlaced
```

在 shell 中请给 URL 加上引号，以保留其中的 `&`；如果值中包含 `&`、`#`、`+` 或空格，请先进行编码，例如在 JavaScript 中使用 `encodeURIComponent`。

## 2. 更多示例 [#2-more-examples]

一张 GS1-128 物流标签的矢量 PDF，每个应用标识符（Application Identifier）都带有括号：

```bash title="Terminal"
curl -o pallet.pdf "https://api.qrdx.dev/v1/barcode?format=gs1-128&type=pdf&data=(01)09501101530003(17)261231(10)AB-123"
# 200 application/pdf, 1 page
```

一张深蓝色的 Code 128 货架标签，不显示条形下方的文字，并旋转 90°：

```txt
https://api.qrdx.dev/v1/barcode?format=code128&data=SHELF-A12&fg=1e3a8a&text=false&rotate=90
```

一个边距更宽的 Data Matrix：

```txt
https://api.qrdx.dev/v1/barcode?format=datamatrix&data=SN-0042-7781&quietZone=4
```

## 3. 不让值出现在 URL 中 [#3-keep-the-value-out-of-the-url]

`POST https://api.qrdx.dev/v1/barcode` 以 JSON 接收相同的字段，并返回相同的文件，但不做缓存。当值不应像 URL 那样留在日志、历史记录或缓存中时，请使用它：

```bash title="Terminal"
curl -o label.png https://api.qrdx.dev/v1/barcode \
  -H "Content-Type: application/json" \
  -d '{"format":"datamatrix","data":"Internal note 42","type":"png"}'
# 200 image/png, Cache-Control: no-store
```

在 JSON 中，`text` 是布尔值，`scale`、`height`、`quietZone` 和 `rotate` 是数字。如果请求体发送时没有带 `Content-Type: application/json`，会返回 `415`：

```json title="415 Unsupported Media Type"
{"code":"UNSUPPORTED_MEDIA_TYPE","message":"Send a JSON body with Content-Type: application/json.","status":415}
```

## 参数 [#parameters]

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `format` | 必填 | 条形码类型，参见[格式](#formats)。不区分大小写，也不区分连字符：`EAN-13` 同样有效 |
| `data` | 必填 | 要编码的数字或文本，最多 1,000 个字符（大多数线性格式更少） |
| `type` | `svg` | `svg`、`png`、`jpg`、`webp`、`avif`、`pdf` 或 `eps` |
| `scale` | `4` | PNG、JPG、WebP 和 AVIF 中每个模块的像素数，范围 `1` 到 `10` |
| `height` | 取决于格式 | 线性条形码在矢量尺寸下的条高，单位为毫米，范围 `5` 到 `60`（EAN-13 为 23） |
| `quietZone` | 该格式的最小值 | 以模块为单位的空白边距：线性条形码为左右两侧（`0` 到 `20`），二维码为四周（`0` 到 `10`） |
| `text` | `true` | 在线性条形码下方打印数字或文本 |
| `fg` | `000000` | 条形和文字的颜色，十六进制 |
| `bg` | `ffffff` | 背景色，十六进制 |
| `rotate` | `0` | 顺时针旋转：`0`、`90`、`180` 或 `270` |

颜色请不要带 `#`，或将其编码为 `%23`。

## 格式 [#formats]

| `format` | 条形码 | 接受的内容 |
| --- | --- | --- |
| `ean13` | EAN-13 | 12 位数字（自动补校验位）或 13 位（会校验） |
| `ean8` | EAN-8 | 7 位或 8 位数字 |
| `upca` | UPC-A | 11 位或 12 位数字 |
| `upce` | UPC-E | 6 到 8 位数字，或可缩短的 12 位 UPC-A |
| `itf14` | ITF-14 | 13 位或 14 位数字 |
| `gs1-128` | GS1-128 | 带括号的应用标识符及其值；GTIN 和 SSCC 的校验位会自动补上或校验；数据最多 48 个字符 |
| `code128` | Code 128 | 最多 80 个可打印 ASCII 字符 |
| `code39` | Code 39 | 最多 40 个大写字母、数字、空格以及 `- . $ / + %` |
| `datamatrix` | Data Matrix | 最多 1,000 个字符的任意文本 |
| `pdf417` | PDF417 | 最多 1,000 个字符的任意文本 |
| `aztec` | Aztec | 最多 1,000 个字符的任意文本 |

零售编码（EAN、UPC、ITF-14、GS1-128 的 GTIN）由 GS1 授权给企业使用。API 会绘制任何有效的编码，但不负责发放或注册。

## 尺寸 [#sizes]

PNG、JPG、WebP 和 AVIF 的大小为每个模块 `scale` 像素，即最窄条的宽度。二维码的一个单元宽两个模块。

SVG、PDF 和 EPS 是矢量格式，每个模块为一个点（0.353 毫米），因此默认设置下的 EAN-13 大约为 45 × 28 毫米，约为标称尺寸的 107%。请在你的版面中缩放矢量文件；对于零售条形码，请保持在 80% 到 200% 之间，并且不要裁切条高。

## 响应 [#responses]

请求成功时会返回文件，并带有：

- `Content-Type`，对应文件类型。EPS 以下载形式返回（`Content-Disposition: attachment`）；其余格式以内联方式打开，文件名形如 `ean13-5901234123457.png`
- `GET` 带有 `Cache-Control: public, max-age=31536000, immutable`：相同的查询始终返回相同的字节。`POST` 响应为 `no-store`
- `Access-Control-Allow-Origin: *`，因此可以在任何网站上通过 `fetch` 获取

## 已保存的条形码 [#saved-barcodes]

使用 [API 密钥](/docs/developers/api-keys)时，REST API 会把条形码保存在该密钥所属的工作区中，并显示在控制台的 **Barcodes** 下。权限范围与二维码相同：`codes:read` 用于列出和下载，`codes:write` 用于修改。

```bash title="Terminal"
curl https://api.qrdx.dev/v1/barcodes \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"format":"ean13","value":"590123412345","title":"Spring box"}'
```

```json title="201 Created"
{
  "data": {
    "id": "cmwgwqcxo0003iscgecog7m1b",
    "title": "Spring box",
    "format": "ean13",
    "formatLabel": "EAN-13",
    "value": "5901234123457",
    "options": {
      "foreground": "#000000",
      "background": "#ffffff",
      "showText": true,
      "barHeightMm": 23,
      "quietZone": 11,
      "scale": 4,
      "rotation": 0
    },
    "folderId": null,
    "imageUrl": "https://qrdx.dev/api/v1/barcode?format=ean13&data=5901234123457",
    "createdAt": "2026-11-14T21:18:01.212Z",
    "updatedAt": "2026-11-14T21:18:01.212Z",
    "deletedAt": null,
    "organizationId": "ws_ad2c5e1cce31ccf31535e78f08ab5b78"
  }
}
```

12 位的值返回时已带上校验位，`options` 中是该格式的默认值。每个已保存的条形码都有一个 `imageUrl`：它与 `GET /v1/barcode` 生成的图片相同，任何拥有该链接的人都可以加载。下面的 `/image` 端点是私有的，需要密钥。

| 端点 | 作用 |
| --- | --- |
| [`GET /v1/barcodes`](/docs/developers/api/list-barcodes) | 列出条形码，最近修改的在前；可用 `q`、`format`、`folderId`、`status=trash` 过滤 |
| [`POST /v1/barcodes`](/docs/developers/api/create-barcode) | 保存一个条形码。`options` 接受 `foreground`、`background`、`showText`、`barHeightMm`、`quietZone`、`scale` 和 `rotation` |
| [`GET /v1/barcodes/{id}`](/docs/developers/api/get-barcode) | 获取单个条形码 |
| [`PATCH /v1/barcodes/{id}`](/docs/developers/api/update-barcode) | 修改标题、格式、值、选项或文件夹 |
| [`DELETE /v1/barcodes/{id}`](/docs/developers/api/delete-barcode) | 移入回收站（`{ "deleted": false, "trashed": true }`）；加上 `?permanent=true` 则永久删除 |
| [`GET /v1/barcodes/{id}/image`](/docs/developers/api/get-saved-barcode-image) | 按保存时的样式绘制的文件：`type` 和 `scale` 同上。`Cache-Control: private, no-store` |

所有套餐都可以保存条形码：免费版最多 1,000 个，Pro 最多 10,000 个，Business 最多 100,000 个，回收站中的不计算在内。这些请求会计入工作区的每日 API 配额，并会发送 `X-RateLimit-*` 响应头，与其余 [REST API](/docs/developers/rest-api#rate-limits) 相同。

## 出现问题时 [#if-something-goes-wrong]

### 带有 `"param": "data"` 的 `400` [#400-with-param-data]

该值违反了格式的规则。错误信息会明确指出问题所在，例如校验位、长度或字符集：

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"EAN-13: The check digit should be 7, not 8. Check the number, or leave the last digit off and it's worked out for you."}]},"status":400}
```

```json title="400 Bad Request"
{"code":"VALIDATION_ERROR","message":"Invalid query parameters","data":{"details":[{"param":"data","message":"Code 39: Code 39 has no lowercase letters. Use capitals, or Code 128 for mixed case."}]},"status":400}
```

### 带有 `"param": "format"` 的 `400` [#400-with-param-format]

`format` 缺失，或不是[格式](#formats)中列出的十一个 ID 之一。错误信息会列出这些 ID。

### 位图图片被拒绝或被裁切 [#the-raster-image-is-refused-or-cut]

位图图片每边最多 6,000 像素。对于较长的值，请降低 `scale`，或改用 SVG 或 PDF。

### `429 RATE_LIMITED` [#429-rate_limited]

同一 IP 地址每分钟的请求超过了 {facts.imageApiPerMinute} 次，`GET` 和 `POST /v1/barcode` 合并计算。请等待 `Retry-After` 中给出的秒数；`GET` 响应可以缓存一年，因此每张图片只需加载一次。

## 限制 [#limits]

- **速率限制：** `GET` 和 `POST /v1/barcode` 每个 IP 地址每分钟 {facts.imageApiPerMinute} 次请求，与[二维码图片 API](/docs/developers/image-api)相同。已保存的条形码遵循 REST API 的每分钟限制和每日配额。
- **图片尺寸：** 位图图片每边最多 6,000 像素。
- **此处不做扫描检查。** [条形码生成器](/barcode-generator)会在你下载之前解码它所绘制的内容；API 只会按你的要求绘制。请打印一份测试样张，并用实际会读取它的扫描设备进行扫描。

## MCP [#mcp]

[MCP 服务器](/docs/developers/mcp)提供 `generate_barcode` 和 `save_barcode`：前者会检查值并返回一张 PNG 以及图片 URL，后者会把条形码保存到连接所用 API 密钥对应的工作区。

## 自托管 [#self-hosting]

这些端点是 QRdx Web 应用的一部分，因此[自托管](/docs/self-hosting)的实例会在你自己的域名下通过 `/api/v1/barcode` 和 `/api/v1/barcodes` 提供它们。
