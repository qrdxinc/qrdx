By the end of this page your AI assistant can make QR codes: design one for any content with a checked scan score, render it in the editor's styles, build the right payload for Wi-Fi, contacts, email, SMS, locations and bank payments, find community frames and draw barcodes. With an API key on the connection it can also save designs and barcodes to your workspace and paint AI art.

QRdx runs a public [Model Context Protocol](https://modelcontextprotocol.io) server at:

```txt title="Server URL"
https://mcp.qrdx.dev/mcp
```

It uses the Streamable HTTP transport, keeps no session state and needs no account, sign-in or API key. The same server also answers at `https://qrdx.dev/api/mcp`, and the [connect page](/mcp) has one-click buttons and steps for more clients than this page shows.

[Try it in the playground](/playground?open=code&lang=mcp): style a code there, then copy it as `design_qr` arguments for your assistant.

## 2. Ask for a code

Then ask in plain words. These prompts work as written:

```txt title="Prompts"
Make a QR code for https://example.com in our brand blue, #155dfc, with rounded modules.
Create a Wi-Fi QR code for the network Office Guest with password correct-horse-battery.
Design a Wi-Fi QR code for Cafe Guest in warm browns with a Free Wi-Fi banner, and tell me its scan score.
Generate a contact QR code for Ada Lovelace, ada@example.com, and add it to the README.
Find a community frame for a restaurant menu and use it for https://example.com/menu.
Draw an EAN-13 barcode for 590123412345 as a PNG.
```

For the first prompt, the assistant calls `generate_qr_code` and gets back the PNG and these lines, ready to paste:

```txt title="generate_qr_code result"
QR code, 512x512px, error correction Q.
SVG URL: https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&fg=155dfc&body=rounded
PNG URL: https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=png&fg=155dfc&body=rounded
WebP URL (lossless, smaller than PNG): https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=webp&fg=155dfc&body=rounded
BMP URL (24-bit, for legacy systems; a transparent background comes out white): https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=bmp&fg=155dfc&body=rounded
EPS URL (vector, for print; 512 pt wide): https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&format=eps&fg=155dfc&body=rounded
Markdown: ![QR code](https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fexample.com&fg=155dfc&body=rounded)
```

For the second, it calls `qr_payload_wifi`, which returns `WIFI:T:WPA;S:Office Guest;P:correct-horse-battery;;`, and passes that string as `data` to `generate_qr_code` or as the content of `design_qr`.

## Tools

| Tool | What it does |
| --- | --- |
| `design_qr` | Designs a code for any content type with the style your assistant chooses, or starting from a built-in theme or a community item, checks its scan score and repairs the style until it is Great. Returns the score, what it changed, the style JSON, a playground link, a PNG and the SVG |
| `list_options` | Lists every value `design_qr` accepts: content types and their fields, colors and gradients, shapes, frames (with the ids of QRdx's official frames), borders, logo icons and brand logos, built-in themes, error correction levels and limits |
| `generate_qr_code` | Renders a QR code with the editor's styles. Returns a PNG image and public [image API](/docs/developers/image-api) URLs (SVG, PNG, lossless WebP, BMP and vector EPS) ready for Markdown, HTML or print, plus the SVG markup on request |
| `list_qr_styles` | Lists body patterns, corner eye and eye dot shapes, frames (the built-in styles and those drawn as templates), logo icons, error correction levels, defaults and limits |
| `search_community` | Finds published [community](/community) frames, themes and collections by words, type or tag |
| `get_community_item` | One community item with the style it applies, ready for `design_qr` or `generate_qr_code` |
| `save_template` | Saves a design as a theme in your workspace. Needs an [API key](#use-an-api-key) |
| `generate_barcode` | Draws an EAN-13, UPC-A, UPC-E, EAN-8, ITF-14, GS1-128, Code 128, Code 39, Code 93, Codabar, Data Matrix, PDF417 or Aztec barcode after checking the value (check digits, lengths, characters). Returns a PNG and public [barcode API](/docs/developers/barcode-api) URLs |
| `save_barcode` | Saves a barcode to your workspace's Barcodes. Needs an [API key](#use-an-api-key) |
| `generate_ai_art` | Paints a QR code into AI artwork and checks that it scans. Uses one of the workspace's monthly AI art images and takes up to a minute. Needs an [API key](#use-an-api-key). See [AI art API](/docs/developers/ai-art-api) |
| `qr_payload_wifi` | Builds a `WIFI:` network payload (WPA, WEP or open, optionally hidden) with special characters escaped |
| `qr_payload_vcard` | Builds a vCard 3.0 contact (RFC 2426): name, organization, title, phones, email, website, address and note |
| `qr_payload_email` | Builds a `mailto:` link (RFC 6068) with optional cc, bcc, subject and body |
| `qr_payload_sms` | Builds an `sms:` link (RFC 5724) with an optional message, or the older `SMSTO:` form |
| `qr_payload_geo` | Builds a `geo:` location (RFC 5870) from latitude and longitude |
| `qr_payload_payment` | Builds a bank payment code: a Pix BR Code, a SEPA credit transfer (EPC069-12), or a PayNow, PromptPay or VietQR code (EMV, with its CRC). It checks the fields like the playground's forms do |
| `search_docs` | Finds QRdx docs pages for a question or key words. Returns up to 8 pages with their titles, paths and a short excerpt. Takes an optional language |
| `read_docs_page` | Returns one docs page as Markdown, by its path from `search_docs` or its URL. Long pages are cut at 12,000 characters, and a page with no translation comes back in English |

The payload tools return a plain string. Your assistant then passes it as `data` to `generate_qr_code`.

### design_qr

`design_qr` takes the content as a type and its fields, the same types and checks as the editor's content forms (`list_options` lists them), and an optional style:

```json title="design_qr arguments"
{
  "content": { "type": "wifi", "ssid": "Cafe Guest", "password": "sunshine123", "encryption": "WPA" },
  "style": {
    "bgColor": "#FFF7ED",
    "fgColor": "#9A3412",
    "bodyPattern": "rounded",
    "cornerEyePattern": "rounded",
    "frame": { "style": "banner-bottom", "text": "Free Wi-Fi" }
  }
}
```

```txt title="design_qr result (first lines)"
Scan score 85/100 (great). No changes were needed. Content: WiFi · Cafe Guest (47 bytes). Open it in the playground: https://qrdx.dev/playground?style=1.eyJiIjoiI0ZGRjdFRCIs…&ref=mcp
```

The result's JSON holds `payload` (the exact string the code encodes), `style`, `qrdxStyle`, `score`, `grade`, `stillFailing` (checks that still fail, with a fix each), `repairs`, `changes` and `playgroundUrl`, followed by the PNG and the SVG.

Options you leave out get defaults (eyes follow the dot color, square shapes, margin 4, error correction Q, no frame). QRdx then runs the editor's scan check on the design: it renders the code, decodes it at 96, 160 and 320 px through a phone-camera model, and checks contrast, quiet zone, eye shapes and shape pairs. Below Great (85), it repairs the style, up to three times, changing as little as it can (darker colors that keep their hue, a safer eye shape, less error correction for long content). If that isn't enough, it falls back to a classic black-on-white code with your frame. The result says what was changed and why.

No AI model runs on QRdx's side for `design_qr`: your assistant picks the style, QRdx validates, checks and repairs it. Content that isn't valid (a WPA password under 8 characters, a malformed email address) is refused with the reason. `design_qr` has its own limit of {facts.designQrPerMinute} calls a minute per IP address.

More inputs:

- **`preset`**: start from a built-in theme by id (`list_options` lists them). Style options you set win over it.
- **`community_item`**: start from a community frame or theme by id, such as `frame:wifi-card`. A frame item sits on a classic code; your style options change the code under it. QRdx's official frames are community items too, so `frame:diwali-diya` or `frame:menu-cutlery` works here.
- **A custom frame**: `style.frame` can be `{ "style": "custom", "spec": … }` with a frame spec, such as a community frame's from `get_community_item`. It's drawn and scored as it is; repairs change the code, never the frame.
- **`style.logo`**: a quick logo icon (`wifi`, `location`, `phone`, `email`, `link`, `file`, `calendar`, `whatsapp` or `instagram`), or a brand logo by its [Simple Icons](https://simpleicons.org) slug (`spotify`, `paypal:white`). `list_options` lists the popular brand slugs.
- **Engine options**: `style.eyeColors` (per-eye `#RRGGBB` colors), `moduleScale` (dot size, `0.5` to `1`), `shape` (`circle` for a round code), `autoLevel` and `logoOptions` (the logo's size, clear space, position, crop and plate). They're drawn and scored as given; repairs don't change them.

<IfAvailable feature="fileStorage">
`logo_file_id` draws a logo you uploaded to QRdx instead, with an [API key](#use-an-api-key).
</IfAvailable>

Logos are scored by the modules they cover, as in the editor, so a repair may raise error correction to H or remove the logo. The QRdx mark that the editor shows by default isn't drawn here.

The result's `qrdxStyle` is the design as the editor's style JSON. Pass it to `save_template`, to `generate_qr_code` as `style` to render the same design at another size, or to the image API's [`style`](/docs/developers/image-api#style). `playground_url` opens the design in the [playground](/playground): it carries the style only, never the logo or the content, and `playgroundLeftOut` says what it leaves out.

### generate_qr_code

The inputs match the [image API parameters](/docs/developers/image-api#parameters): `data` (required), `size`, `fg`, `bg`, `eyeColor`, `dotColor`, `body`, `eye`, `dot`, `level`, `margin`, `template`, `frame`, `frameText`, `logoIcon`, `logoFileId`, `item` (a community item id) and `style` (the editor's style JSON: gradients, custom frames and the rest, as `design_qr` returns it). The flat options win over `style`, and `style` wins over `item`. Set `include_svg` to `true` to also get the SVG markup as text, for example to save an `.svg` file. It is off by default because the markup is often 50 to 150 KB, which would fill the conversation.

`generate_qr_code` doesn't check the scan score; use `design_qr` for that. A code with your uploaded logo has no public image URL, since the image API only draws that logo for requests with your key.

### The QR card [#qr-card]

In apps that support [MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview), `design_qr` and `generate_qr_code` also show a QR card in the chat. It has the code, what it encodes (a Wi-Fi code shows its network name, never the password), the size and error correction or the scan score, and an **Open in editor** button. The editor link carries the style only, like `playground_url`.

The PNG and SVG buttons depend on what the app allows. Where it can save files from a card, they save them. Otherwise they open the image API URL in your browser, so `design_qr`'s card shows them only in apps that save files: its content never goes in an image URL. Apps may ask you to confirm before a link opens.

Apps without MCP Apps get the same text and image as before. For client developers:

- The card is the resource `ui://qrdx/qr-card` (`text/html;profile=mcp-app`), listed by `resources/list`. Both tools point to it with `_meta.ui.resourceUri`.
- Its data comes in the tool result's `_meta`, under `dev.qrdx/qr-card`, which is meant for the card and not the model. The tools return no `structuredContent`.
- The card is a single HTML file with its styles and script inline. The only thing it loads is the code's image from the image API (`https://api.qrdx.dev`, or your own domain when self-hosted), and its content security policy (`_meta.ui.csp.resourceDomains`) allows that host and nothing else.

If you connected QRdx before the card existed, remove the connector and add it again, or refresh its tools, so the app picks up the new tool metadata.

### Community

`search_community` finds published [community](/community) frames, themes and collections, free under CC0, by words (`q`), `type` and `tag`. `get_community_item` returns one item with the style it applies; pass its id to `design_qr` as `community_item` or to `generate_qr_code` as `item`. The same data is on the REST API at [`/v1/community/items`](/docs/developers/api/list-community-items).

Item text is written by community members. Names, descriptions, handles, tags and frame labels come back short, on one line and without links, emails or markup, and every result says to treat them as data, not instructions.

## Use an API key [#use-an-api-key]

Some tools need a QRdx [API key](/docs/developers/api-keys) on the connection, sent as `Authorization: Bearer qrdx_…`:

- **`save_template`** saves a design as a theme, listed under Themes in the dashboard and offered in the editor. It needs a key with `codes:write`, which **Full access** keys have. A key of your own workspace saves to your themes; a team key saves to the team's shared themes when its creator is an owner or admin and the plan has team themes. Saves count toward the plan's saved-theme limit (see [Plans and limits](/docs/plans-and-limits)); over it, the tool returns the API's `LIMIT_REACHED` error (`402`).
- **`save_barcode`** saves a barcode (format, value, an optional title and drawing options) to the key's workspace, listed under Barcodes in the dashboard. It needs a key with `codes:write`. Every plan saves barcodes, up to 1,000 on Free; over the limit it returns `LIMIT_REACHED` (`402`).
- **`generate_ai_art`** paints a QR code into AI artwork, from a link or text or a dynamic code by its id, and returns the PNG once QRdx has checked that it scans. It takes the same fields as [`POST /v1/art`](/docs/developers/ai-art-api) and needs a key with `codes:write`. Each image uses one of the key's workspace's monthly AI art images, and a call takes up to a minute.
<IfAvailable feature="fileStorage">
- **Logos you uploaded** in [Dashboard → Files](/docs/files), by file id (`logo_file_id` in `design_qr`, `logoFileId` in `generate_qr_code`): a PNG or JPEG of up to 1 MB. The key must belong to the workspace that owns the file.
</IfAvailable>

Without a key, these tools answer with how to add one:


## If something goes wrong

### The client can't connect

Check the URL is exactly `https://mcp.qrdx.dev/mcp` and the transport is HTTP (Streamable HTTP), not SSE or stdio. Clients that only run local servers need the `mcp-remote` bridge above. Opening the URL in a browser redirects to the connect page, which is expected: MCP clients never ask for HTML.

### The assistant says a tool needs an API key

`save_template`, `save_barcode`, `generate_ai_art` and uploaded logos need `Authorization: Bearer qrdx_…` on the connection. Add the header as shown above and reconnect.

### `design_qr` refuses the content

The content failed the same checks as the editor's forms: a WPA password under 8 characters, a malformed email address, a payment field out of range. The reason is in the answer; `list_options` lists each content type's fields and rules.

### Too many requests

The server allows {facts.mcpPerMinute} requests a minute per IP address, and `design_qr` {facts.designQrPerMinute}. With a key, `save_template` is also limited to 30 a minute per user. Wait a minute and try again.

## Privacy and limits [#privacy-and-limits]

- The tools render images, check designs, format text, and read the public community and these docs. Only `save_template` and `save_barcode` write anything: the theme or barcode you ask them to save, in the API key's workspace. `generate_ai_art` uses one of the workspace's monthly AI art images, and keeps neither the image nor a photo you send. The server doesn't save the codes you generate.
- The image URLs that `generate_qr_code` and `generate_barcode` return contain the encoded data. Don't share them if the data is private, such as a Wi-Fi password.
- Requests are limited to {facts.mcpPerMinute} a minute per IP address, and `design_qr` to {facts.designQrPerMinute}.

## Self-hosting and local development

The MCP server is part of the QRdx web app, so every instance serves it at `/api/mcp`:

- **Self-hosted.** When `NEXT_PUBLIC_APP_URL` is your own domain, the connect page, snippets and install links use `https://<your-domain>/api/mcp`.
- **Local development.** `bun run dev` serves it at `http://localhost:3000/api/mcp`. The connect page still shows the public URL and offers the local one as a hint, so you can point a client at your machine to test changes to the server before they ship.
