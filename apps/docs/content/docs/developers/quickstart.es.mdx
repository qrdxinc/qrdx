Al terminar esta página tendrás una imagen de código QR guardada a partir de una solicitud, una clave de API para tu espacio de trabajo, un código dinámico cuyo QR impreso sigue funcionando después de cambiar el destino al que envía a las personas, y un primer vistazo a sus analíticas de escaneos.

La API tiene dos mitades. Las imágenes no necesitan nada: ni cuenta ni clave. Los códigos dinámicos, los escaneos y los webhooks pertenecen a un espacio de trabajo, así que necesitan una clave de API.

## Antes de empezar [#before-you-start]

- curl, Node.js 18 o posterior, o Python 3 con el paquete `requests`. Elige la pestaña del que uses; la elección se mantiene en todas las páginas.
- Una cuenta de QRdx para los pasos 2 a 4. Con una cuenta gratis basta: los espacios de trabajo Gratis tienen 10 códigos dinámicos activos y 1.000 solicitudes de API al día.

## 1. Crea una imagen de código QR (sin clave) [#1-make-a-qr-code-image-no-key]

Ejecuta esto. Guarda un PNG de un código QR que abre qrdx.dev.

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png" -o qr.png
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="qr.mjs"
    // Node 18 or later
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/qr");
    url.searchParams.set("data", "https://qrdx.dev");
    url.searchParams.set("format", "png");

    const response = await fetch(url);
    await writeFile("qr.png", Buffer.from(await response.arrayBuffer()));
    console.log(response.status, response.headers.get("content-type"));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="qr.py"
    # pip install requests
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/qr",
        params={"data": "https://qrdx.dev", "format": "png"},
    )
    response.raise_for_status()
    open("qr.png", "wb").write(response.content)
    print(response.status_code, response.headers["content-type"])
    ```
  </Tab>
</Tabs>

```txt title="Output"
200 image/png
qr.png: PNG image data, 512 x 512, 8-bit/color RGBA, non-interlaced
```

Esa es una llamada a la API que funciona. La propia URL es la imagen, así que también sirve directamente en una etiqueta `<img>`:

```html title="index.html"
<img src="https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&fg=111111&body=circle" alt="QR code for qrdx.dev" />
```

Cambia los colores, las formas, el tamaño y el formato con parámetros de consulta, o pruébalos en el navegador en la página [Generar una imagen de código QR](/docs/developers/api/get-qr-image): su panel **Try it** envía la solicitud y muestra la imagen. Las imágenes no cuentan para ninguna cuota; el límite es de {facts.imageApiPerMinute} solicitudes por minuto por dirección IP.

## 2. Crea una clave de API [#create-an-api-key]

Todo lo demás en la API actúa sobre un espacio de trabajo: crear códigos dinámicos, cambiar su destino, leer sus escaneos. Esas solicitudes llevan una clave de API en el encabezado `Authorization`.

1. Abre [Ajustes → Claves de API y apps](/dashboard?to=settings/developers&new=1), iniciando sesión antes si hace falta. Se abre el formulario **Crear clave de API**.
2. Ponle un nombre a la clave, como el del servidor donde se ejecutará, deja **Acceso completo** y elige **Crear clave**. Es posible que QRdx te pida confirmar primero que eres tú.
3. Copia la clave desde el cuadro de diálogo **Copia tu clave de API**. Solo se muestra esta vez: QRdx guarda un hash de la clave y no puede mostrarla de nuevo. El cuadro de diálogo también muestra una solicitud curl que crea un código dinámico, con tu clave ya incluida, por si prefieres pegar esa.

<Shot id="create-key-dialog" />

<Shot id="api-key-copy-dialog" />

Exporta la clave para los siguientes pasos:

```bash title="Terminal"
export QRDX_API_KEY=qrdx_...
```

La clave actúa como tú en el espacio de trabajo que estaba abierto cuando la creaste, y las solicitudes hechas con ella cuentan para la cuota diaria de ese espacio de trabajo. [Claves de API](/docs/developers/api-keys) explica los permisos, los equipos, la caducidad y la revocación.

## 3. Crea un código dinámico [#3-create-a-dynamic-code]

Un código dinámico es un enlace corto que puedes redirigir a otro destino después de imprimirlo:

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -X POST https://api.qrdx.dev/v1/codes \
      -H "Authorization: Bearer $QRDX_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"destinationUrl": "https://example.com", "title": "My first code"}'
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="create.mjs"
    const response = await fetch("https://api.qrdx.dev/v1/codes", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.QRDX_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        destinationUrl: "https://example.com",
        title: "My first code",
      }),
    });
    const { data: code } = await response.json();
    console.log(response.status, code.id, code.shortLink);
    ```
  </Tab>
  <Tab value="Python">
    ```python title="create.py"
    import os
    import requests

    response = requests.post(
        "https://api.qrdx.dev/v1/codes",
        headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},
        json={"destinationUrl": "https://example.com", "title": "My first code"},
    )
    response.raise_for_status()
    code = response.json()["data"]
    print(response.status_code, code["id"], code["shortLink"])
    ```
  </Tab>
</Tabs>

La respuesta es `201 Created` con el código nuevo:

```json title="201 Created"
{
  "data": {
    "id": "cmwgwq0t80000iscg4ybn05kh",
    "slug": "l0q9fZn",
    "shortLink": "https://qrdx.dev/q/l0q9fZn",
    "defaultShortLink": "https://qrdx.dev/q/l0q9fZn",
    "nfcLink": "https://qrdx.dev/q/l0q9fZn?nfc",
    "domain": null,
    "destinationUrl": "https://example.com/",
    "title": "My first code",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-11-14T21:17:45.512Z",
    "updatedAt": "2026-11-14T21:17:45.512Z",
    "organizationId": "ws_ad2c5e1cce31ccf31535e78f08ab5b78",
    "preciseLocation": false
  }
}
```

Ahora importan dos campos. `shortLink` es lo que codifica el código QR: genera su imagen con la API de imágenes del paso 1, `https://api.qrdx.dev/v1/qr?data=https://qrdx.dev/q/l0q9fZn&format=png`, e imprímela. `id` es cómo te refieres al código a partir de ahora, así que guárdalo:

```bash title="Terminal"
export CODE_ID=cmwgwq0t80000iscg4ybn05kh
```

[Crear códigos](/docs/developers/api/create-codes) enumera todos los campos que puedes enviar, incluido un sufijo personalizado y un diseño.

## 4. Redirígelo a otro destino [#4-point-it-somewhere-else]

Cambia el destino cuando quieras; el código impreso sigue funcionando:

```bash title="Terminal"
curl -X PATCH https://api.qrdx.dev/v1/codes/$CODE_ID \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/new-page"}'
```

La respuesta `200 OK` es el mismo código con `"destinationUrl": "https://example.com/new-page"` y un nuevo `updatedAt`. Escanea el código con tu teléfono y luego lee sus analíticas:

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/codes/$CODE_ID/scans?range=7d" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

```json title="200 OK (before the first scan, trimmed)"
{
  "data": {
    "codeId": "cmwgwq0t80000iscg4ybn05kh",
    "range": "7d",
    "retentionDays": 365,
    "days": 7,
    "total": 0,
    "unique": 0,
    "interval": "day",
    "series": [{ "date": "2026-11-08", "count": 0 }, { "date": "2026-11-09", "count": 0 }],
    "countries": [],
    "devices": [],
    "sources": { "qr": 0, "nfc": 0 }
  }
}
```

Después de un escaneo, `total` aumenta y se rellenan `countries`, `cities`, `devices`, `os` y `browsers`. [Obtener analíticas de escaneos](/docs/developers/api/get-code-scans) explica los rangos y cómo paginar los escaneos individuales.

## Si algo sale mal [#if-something-goes-wrong]

Todos los errores son JSON con un `code` estable y un mensaje que indica qué hacer. Los dos que más probablemente encuentres en esta página:

```json title="401 Unauthorized: the header is missing"
{
  "code": "UNAUTHORIZED",
  "message": "Missing API key. Send an API key as \"Authorization: Bearer <key>\"; create one at https://qrdx.dev/dashboard?to=settings/developers. OAuth access tokens go in the same header.",
  "status": 401,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

```json title="400 Bad Request: the destination isn't a full URL"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "data": { "details": [{ "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }] },
  "status": 400
}
```

Un `401 INVALID_TOKEN` significa que la clave se copió incompleta, se revocó o caducó: crea una nueva. Un `403 INSUFFICIENT_SCOPE` significa que creaste una clave de **Solo lectura**; el paso 3 necesita `codes:write`. La [página de errores](/docs/developers/errors) enumera cada código con su solución.

## Actuar en nombre de otras personas [#get-an-access-token]

Una clave de API actúa como tú. Si tu producto llama a QRdx en nombre de otras personas, registra una app OAuth en su lugar: cada persona la aprueba una vez y tu servidor recibe un token de acceso para su cuenta, que se envía en el mismo encabezado `Authorization: Bearer`. Todas las solicitudes anteriores funcionan sin cambios con un token en lugar de la clave. Consulta [REST API y OAuth](/docs/developers/rest-api#get-an-access-token) y [Crea una integración](/docs/developers/build-an-integration).
