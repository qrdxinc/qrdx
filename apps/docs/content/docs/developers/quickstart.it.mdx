Alla fine di questa pagina avrai l'immagine di un QR code salvata da una sola richiesta, una chiave API per il tuo workspace, un QR code dinamico il cui QR stampato continua a funzionare anche dopo che cambi la destinazione, e una prima occhiata alle sue statistiche delle scansioni.

L'API ha due metà. Le immagini non richiedono nulla: né account né chiave. I QR code dinamici, le scansioni e i webhook appartengono a un workspace, quindi richiedono una chiave API.

## Prima di iniziare [#before-you-start]

- curl, Node.js 18 o successivo, oppure Python 3 con il pacchetto `requests`. Scegli la scheda di quello che usi; la scelta resta valida nelle altre pagine.
- Un account QRdx per i passaggi da 2 a 4. Ne basta uno gratuito: i workspace Gratuito hanno 10 QR code dinamici attivi e 1.000 richieste API al giorno.

## 1. Crea l'immagine di un QR code (senza chiave) [#1-make-a-qr-code-image-no-key]

Esegui questo comando. Salva un PNG di un QR code che apre qrdx.dev.

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl "https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&format=png" -o qr.png
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="qr.mjs"
    // Node 18 or later
    import { writeFile } from "node:fs/promises";

    const url = new URL("https://api.qrdx.dev/v1/qr");
    url.searchParams.set("data", "https://qrdx.dev");
    url.searchParams.set("format", "png");

    const response = await fetch(url);
    await writeFile("qr.png", Buffer.from(await response.arrayBuffer()));
    console.log(response.status, response.headers.get("content-type"));
    ```
  </Tab>
  <Tab value="Python">
    ```python title="qr.py"
    # pip install requests
    import requests

    response = requests.get(
        "https://api.qrdx.dev/v1/qr",
        params={"data": "https://qrdx.dev", "format": "png"},
    )
    response.raise_for_status()
    open("qr.png", "wb").write(response.content)
    print(response.status_code, response.headers["content-type"])
    ```
  </Tab>
</Tabs>

```txt title="Output"
200 image/png
qr.png: PNG image data, 512 x 512, 8-bit/color RGBA, non-interlaced
```

Questa è una vera chiamata API. L'URL stesso è l'immagine, quindi funziona anche direttamente in un tag `<img>`:

```html title="index.html"
<img src="https://api.qrdx.dev/v1/qr?data=https://qrdx.dev&fg=111111&body=circle" alt="QR code for qrdx.dev" />
```

Cambia colori, forme, dimensione e formato con i parametri della query, oppure provali nel browser nella pagina [Genera l'immagine di un QR code](/docs/developers/api/get-qr-image): il pannello **Try it** invia la richiesta e mostra l'immagine. Le immagini non contano per nessuna quota; il limite è di {facts.imageApiPerMinute} richieste al minuto per indirizzo IP.

## 2. Crea una chiave API [#create-an-api-key]

Tutto il resto dell'API agisce su un workspace: creare QR code dinamici, cambiare la loro destinazione, leggere le scansioni. Queste richieste portano una chiave API nell'header `Authorization`.

1. Apri [Impostazioni → Chiavi API e app](/dashboard?to=settings/developers&new=1), accedendo prima se serve. Si apre il modulo **Crea chiave API**.
2. Dai un nome alla chiave, per esempio il server su cui verrà usata, lascia **Accesso completo** e scegli **Crea chiave**. QRdx potrebbe chiederti prima di confermare la tua identità.
3. Copia la chiave dalla finestra **Copia la tua chiave API**. Viene mostrata solo questa volta: QRdx ne conserva un hash e non può mostrarla di nuovo. La finestra mostra anche una richiesta curl che crea un QR code dinamico, con la tua chiave già inserita, se preferisci incollare quella.

<Shot id="create-key-dialog" />

<Shot id="api-key-copy-dialog" />

Esporta la chiave per i passaggi successivi:

```bash title="Terminal"
export QRDX_API_KEY=qrdx_...
```

La chiave agisce come te nel workspace che era aperto quando l'hai creata, e le richieste fatte con essa contano sulla quota giornaliera di quel workspace. [Chiavi API](/docs/developers/api-keys) spiega ambiti, team, scadenza e revoca.

## 3. Crea un QR code dinamico [#3-create-a-dynamic-code]

Un QR code dinamico è un link breve che puoi far puntare altrove anche dopo la stampa:

<Tabs groupId="language" persist items={["curl", "JavaScript", "Python"]}>
  <Tab value="curl">
    ```bash title="Terminal"
    curl -X POST https://api.qrdx.dev/v1/codes \
      -H "Authorization: Bearer $QRDX_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"destinationUrl": "https://example.com", "title": "My first code"}'
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="create.mjs"
    const response = await fetch("https://api.qrdx.dev/v1/codes", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.QRDX_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        destinationUrl: "https://example.com",
        title: "My first code",
      }),
    });
    const { data: code } = await response.json();
    console.log(response.status, code.id, code.shortLink);
    ```
  </Tab>
  <Tab value="Python">
    ```python title="create.py"
    import os
    import requests

    response = requests.post(
        "https://api.qrdx.dev/v1/codes",
        headers={"Authorization": f"Bearer {os.environ['QRDX_API_KEY']}"},
        json={"destinationUrl": "https://example.com", "title": "My first code"},
    )
    response.raise_for_status()
    code = response.json()["data"]
    print(response.status_code, code["id"], code["shortLink"])
    ```
  </Tab>
</Tabs>

La risposta è `201 Created` con il nuovo codice:

```json title="201 Created"
{
  "data": {
    "id": "cmwgwq0t80000iscg4ybn05kh",
    "slug": "l0q9fZn",
    "shortLink": "https://qrdx.dev/q/l0q9fZn",
    "defaultShortLink": "https://qrdx.dev/q/l0q9fZn",
    "nfcLink": "https://qrdx.dev/q/l0q9fZn?nfc",
    "domain": null,
    "destinationUrl": "https://example.com/",
    "title": "My first code",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-11-14T21:17:45.512Z",
    "updatedAt": "2026-11-14T21:17:45.512Z",
    "organizationId": "ws_ad2c5e1cce31ccf31535e78f08ab5b78",
    "preciseLocation": false
  }
}
```

Ora contano due campi. `shortLink` è ciò che il QR code codifica: generalo con la Image API del passaggio 1, `https://api.qrdx.dev/v1/qr?data=https://qrdx.dev/q/l0q9fZn&format=png`, e stampalo. `id` è il modo in cui ti riferirai al codice d'ora in poi, quindi conservalo:

```bash title="Terminal"
export CODE_ID=cmwgwq0t80000iscg4ybn05kh
```

[Crea codici](/docs/developers/api/create-codes) elenca tutti i campi che puoi inviare, compresi un back-half personalizzato e un design.

## 4. Falli puntare altrove [#4-point-it-somewhere-else]

Puoi cambiare la destinazione in qualsiasi momento; il codice stampato continua a funzionare:

```bash title="Terminal"
curl -X PATCH https://api.qrdx.dev/v1/codes/$CODE_ID \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/new-page"}'
```

La risposta `200 OK` è lo stesso codice con `"destinationUrl": "https://example.com/new-page"` e un nuovo `updatedAt`. Fai una scansione del codice con il telefono, poi leggi le sue statistiche:

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/codes/$CODE_ID/scans?range=7d" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

```json title="200 OK (before the first scan, trimmed)"
{
  "data": {
    "codeId": "cmwgwq0t80000iscg4ybn05kh",
    "range": "7d",
    "retentionDays": 365,
    "days": 7,
    "total": 0,
    "unique": 0,
    "interval": "day",
    "series": [{ "date": "2026-11-08", "count": 0 }, { "date": "2026-11-09", "count": 0 }],
    "countries": [],
    "devices": [],
    "sources": { "qr": 0, "nfc": 0 }
  }
}
```

Dopo una scansione, `total` aumenta e `countries`, `cities`, `devices`, `os` e `browsers` si popolano. [Ottieni le statistiche delle scansioni](/docs/developers/api/get-code-scans) spiega gli intervalli e come scorrere le singole scansioni.

## Se qualcosa va storto [#if-something-goes-wrong]

Ogni errore è un JSON con un `code` stabile e un messaggio che dice cosa fare. I due che incontrerai più probabilmente in questa pagina:

```json title="401 Unauthorized: the header is missing"
{
  "code": "UNAUTHORIZED",
  "message": "Missing API key. Send an API key as \"Authorization: Bearer <key>\"; create one at https://qrdx.dev/dashboard?to=settings/developers. OAuth access tokens go in the same header.",
  "status": 401,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

```json title="400 Bad Request: the destination isn't a full URL"
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "data": { "details": [{ "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }] },
  "status": 400
}
```

Un `401 INVALID_TOKEN` significa che la chiave è stata copiata incompleta, revocata o scaduta: creane una nuova. Un `403 INSUFFICIENT_SCOPE` significa che hai creato una chiave **Sola lettura**; il passaggio 3 richiede `codes:write`. La [pagina degli errori](/docs/developers/errors) elenca ogni codice con la sua soluzione.

## Agire per conto di altri [#get-an-access-token]

Una chiave API agisce come te. Se il tuo prodotto chiama QRdx per conto di altre persone, registra invece un'app OAuth: ogni persona la approva una volta e il tuo server ottiene un token di accesso per il suo account, inviato nello stesso header `Authorization: Bearer`. Tutte le richieste sopra funzionano senza modifiche con un token al posto della chiave. Vedi [REST API e OAuth](/docs/developers/rest-api#get-an-access-token) e [Crea un'integrazione](/docs/developers/build-an-integration).
