QRdx 的 Slack 机器人可以直接在 Slack 中生成二维码。只要 Slack 工作区里安装了这个机器人，任何人都可以根据链接或任意文本生成二维码，通过消息下方的菜单调整样式，并下载二维码。关联了 QRdx 账户的用户还可以生成可追踪的（动态）二维码，这类二维码会统计扫描次数，之后还可以改为指向其他地址。如果团队经常在 Slack 中分享链接，又希望不离开对话就能得到二维码，可以使用它。

## 工作原理 [#how-it-works]

机器人不会存储消息文本，也不会上传任何图片。每个二维码都是 QRdx 通过 [image API](/docs/developers/image-api)，根据消息中的链接渲染出的二维码图片，内容和设计都包含在该链接里。重新设置二维码样式时，会从链接中读回这两部分信息，因此修改样式无需保存任何数据。

<IfAvailable feature="slackBot" id="add-the-bot-to-slack" title="将机器人添加到 Slack">

1. 在 QRdx 中打开 [设置 → 集成 → Slack](/settings/integrations/slack)，点击 **将机器人添加到 Slack**。任何 QRdx 账户都可以执行此操作，不限套餐。
2. 选择 Slack 工作区并授权。机器人会请求查看它的斜杠命令、对它的提及和发给它的私信，并请求发送消息的权限。
3. 你会回到设置页面，页面中列出了你已添加机器人的 Slack 工作区。

同一个 Slack 应用还会向频道发送[提醒](/docs/notifications#slack-and-discord)。添加机器人不会开启提醒，添加提醒也不会添加机器人。

</IfAvailable>

<IfAvailable feature="slackBot" id="make-a-qr-code" title="生成二维码">

| 位置 | 操作 | 二维码出现的位置 |
| --- | --- | --- |
| 任意频道 | `/qr` 后跟链接或文本 | 频道中 |
| 机器人所在的频道 | 提及机器人并附上链接或文本 | 在会话串中 |
| 机器人的私信 | 发送链接或文本 | 私信中 |
| 任意消息 | **更多操作** → **生成二维码** | 在该消息的会话串中 |

每次回复都是一张二维码图片，图片下方是其内容、三个按钮以及下文介绍的样式菜单。三个按钮分别是 **下载 PNG**（1024 像素）、**下载 SVG** 和 **在编辑器中打开**，你可以在编辑器中进一步修改设计。如果内容是链接，编辑器打开时会填入该链接；如果是文本，则打开空白的编辑器，因为文本不会放进链接中。

快捷方式会用消息中的第一个网址生成二维码；消息中没有网址时，则使用整条消息的文本。如果机器人不在该频道中，只有你能看到这个二维码，并附有提示：“Only you can see this. Add the QRdx app to this channel to reply in threads.”

单独输入 `/qr` 或 `/qr help` 会显示命令列表。内容过长、无法生成二维码时，只会向你显示一段简短的说明，不会生成图片。

</IfAvailable>

<IfAvailable feature="slackBot" id="style-your-code" title="设置二维码样式">

每个二维码下方有四个菜单：**外观**、**颜色**、**边框**和 **Logo**。选择任一项后，二维码会就地更新，并附上新的下载链接。每次选择都基于二维码当前的样子叠加。只有生成该二维码的人可以重新设置样式；其他人选择时，Slack 会向他们显示一条仅自己可见的提示，二维码保持不变。

这里的外观是编辑器内置设计中在小尺寸下依然易读的几款；**Plain** 是黑底白码的那一款。选择外观会改变形状和颜色，并保留你已选的边框和 Logo。选择颜色会把整个二维码设为该颜色，底色为白色。边框会添加“Scan me”标签，Logo 菜单提供编辑器中的七个快捷图标。

你也可以在生成二维码时，在链接或文本后面添加选项来设置样式，选项名称与 [QRdx CLI](/docs/developers/cli) 相同：

```text title="Slack message"
/qr qrdx.dev --look modern --fg 0051ff --frame banner-bottom --frame-text "Scan me"
```

第一个选项之前的所有内容都是二维码的内容。系统先应用外观，再在其基础上应用其他选项，因此 `--look royal --fg 0051ff` 会保留 Royal 的形状并改为蓝色。选项在提及和私信中同样有效。如果选项或取值有误，机器人会私下告知你，并列出可用的取值。

| 选项 | 作用 | 取值 |
| --- | --- | --- |
| `--look` | 整体设计，来自编辑器的某个预设 | `plain`、`classic`、`modern`、`royal`、`folio`、`caffeine`、`retro`、`bordeaux`、`blossom` |
| `--fg`（或 `--color`） | 圆点颜色；未单独设置时，角上的定位眼也使用该颜色 | 十六进制颜色，如 `0051ff`，或 `black`、`blue`、`green`、`red`、`purple`、`orange` |
| `--bg` | 背景 | 与 `--fg` 相同 |
| `--eye-color` | 三个角上的定位眼 | 与 `--fg` 相同 |
| `--dot-color` | 定位眼的中心 | 与 `--fg` 相同 |
| `--body` | 圆点的形状 | 编辑器的 {facts.bodyPatterns} 种圆点形状中的任意一种，如 `rounded`、`circle` 或 `classy` |
| `--eye` | 角上定位眼的形状 | {facts.eyeShapes} 种定位眼形状中的任意一种，如 `square`、`rounded` 或 `gear` |
| `--dot` | 定位眼中心的形状 | {facts.eyeCentres} 种中心形状中的任意一种，如 `square`、`rounded` 或 `circle` |
| `--frame` | 二维码周围的边框 | `none` 或 {facts.frameStyles} 种内置边框中的任意一种，如 `banner-bottom`、`banner-top`、`speech-bubble` 或 `polaroid` |
| `--frame-text` | 边框的标签，最多 24 个字符 | 任意文本，含空格时需加引号。未设置 `--frame` 时，文字会显示在二维码下方的横幅上 |
| `--template` | 以模板形式绘制的边框 | `Arrow`、`StandardBox`、`SquareBorder`、`StrikedBox`、`DotRing`、`Halloween` 或 `default`，不区分大小写 |
| `--logo` | 中间的图标 | `link`、`wifi`、`location`、`phone`、`email`、`whatsapp`、`instagram`、`file`、`calendar` 或 `none` |

发布带样式的二维码之前，QRdx 会用与编辑器相同的扫描评分对其进行检查。如果某个设计不便手机识别，QRdx 会自动调整（使用更深的颜色、更简单的形状或更高的纠错等级），并在二维码下方说明。如果这样仍然不够（通常是因为内容太长），你会收到黑底白码的二维码并附带说明。通过 `/qr` 生成的带样式二维码，会在你发送命令后稍等片刻才出现，因为需要先完成检查。

**在编辑器中打开**会以相同的设计打开编辑器：颜色、形状、边框和边距都会保留。Logo 图标不会包含在链接中，请在编辑器中重新选择。

通过快捷方式生成、仅你可见的二维码没有菜单，带追踪的二维码保持默认的简单设计。

</IfAvailable>

<IfAvailable feature="slackBot" id="tracked-codes" title="带追踪的二维码">

普通二维码直接包含链接本身。带追踪的二维码包含一个短链接（`https://qrdx.dev/q/<slug>`），该短链接会重定向到你的链接，因此 QRdx 可以统计扫描次数，你也可以更改它的跳转目标。要在 Slack 中生成这类二维码，需要先关联一次你的 QRdx 账户：

1. 运行 `/qr link`。一个仅你可见的 **关联 QRdx 账户** 按钮会打开 QRdx，该按钮的有效期为 10 分钟。
2. 如有提示，请先登录 QRdx。然后点击 **使用 Slack 登录**，并使用运行 `/qr link` 的同一个 Slack 账户登录。Slack 只会告知 QRdx 你的 Slack 用户和工作区，QRdx 会检查两者是否一致。如果你用其他 Slack 账户登录，则不会建立任何关联。
3. 选择用于存放带追踪二维码的 QRdx 工作区，然后点击 **确认**。除非你最近刚验证过，否则 QRdx 会先要求你[确认是你本人](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)，因为该关联允许这个 Slack 账户在你的工作区中生成二维码。
4. 回到 Slack 后，机器人会给你发一条私信，说明你关联的 QRdx 账户和工作区。如果这不是你本人关联的，请运行 `/qr unlink`。
5. 运行 `/qr track`，后面加上以 `https://` 或 `http://` 开头的链接。你也可以提及机器人，并附上 `track` 和链接。

二维码会出现在频道中，附带其短链接和所属 QRdx 工作区的名称。**在 QRdx 中打开**按钮会指向控制台中的该二维码，它出现在另一条仅你可见的消息里。二维码的名称由链接所在网站的名称加上“from Slack”组成，你可以像查找其他二维码一样，在该工作区的二维码中找到它。

带追踪的二维码与在控制台中生成的二维码遵循相同的规则：你的角色必须有权创建二维码；要求两步验证的工作区需要你的账户已开启两步验证；并且受你所在套餐对有效动态二维码数量的限制。达到上限时，机器人会提示，并附上套餐链接。这些条件每次都会检查，因此退出工作区或失去访问权限后，该关联在那里就不再有效。

每个 Slack 账户在每个 Slack 工作区中只有一个关联。如果你对已关联的 Slack 账户运行 `/qr link`，页面会说明它关联到哪个 QRdx 工作区，以及该工作区是否属于另一个 QRdx 账户。此时按钮会显示为 **替换关联**，在你点击之前不会有任何更改。`/qr unlink` 可以移除关联，在 [设置 → 集成 → Slack](/settings/integrations/slack) 中 **已关联的 Slack 账户** 下点击 **取消关联** 也可以。

QRdx 工作区的所有者和管理员可以在 **设置** → **API 密钥和应用** 的 **Slack 账户** 下看到关联到该工作区的所有 Slack 账户：Slack 工作区、Slack 用户 ID、其代表的成员以及关联时间。在那里点击 **撤销** 即可移除关联。如果工作区启用了[审计日志](/docs/help/teams/audit-log)，通过 `/qr track` 生成的二维码会显示成员姓名并标注“via Slack”，同时附有 Slack 用户和工作区 ID；撤销关联同样会被记录。

</IfAvailable>

## 机器人会保留哪些数据 [#what-the-bot-keeps]

只有在有人运行 `/qr`、提及机器人、直接给机器人发消息，或对某条消息使用快捷操作时，机器人才会读取该消息。它从不存储消息文本。二维码图片来自 QRdx 的 [Image API](/docs/developers/image-api)，由 Slack 通过消息中的链接加载，因此不会上传任何内容。

对于每个 Slack 工作区，QRdx 会保存其 ID 和名称、机器人的 Slack 用户 ID、已授予的权限范围、机器人的令牌（已加密）、由哪个 QRdx 账户添加以及添加时间。对于每个已关联的 Slack 账户，QRdx 会保存 Slack 用户 ID 和工作区 ID、你的 QRdx 账户、你选择的工作区以及关联时间。使用 Slack 登录来完成关联不会增加任何数据：QRdx 会比对 Slack 用户和工作区，然后丢弃登录信息。<IfAvailable feature="slackBot"> 你已关联的 Slack 账户包含在[数据导出](/docs/help/account-and-billing/export-your-data)中。</IfAvailable>

为避免有人在频道中刷屏，机器人会统计每个人每分钟生成或重新设置样式的二维码数量，以及每个 Slack 工作区和整个 QRdx 共同生成的二维码数量。当请求过多时，它会回复“QRdx is busy right now. Try again in a minute.”。这两项计数都不包含任何内容。

<IfAvailable feature="slackBot" id="remove-the-bot" title="移除机器人">

在 Slack 中打开该应用的页面，选择 **Remove App**（或请 Slack 管理员操作）。随后 QRdx 会删除该 Slack 工作区的机器人令牌，以及在该工作区建立的所有 Slack 账户关联。已生成的二维码会保留在 QRdx 中，带追踪的二维码仍可继续使用。

</IfAvailable>

## 面向开发者 [#for-developers]

该机器人是构建在两个公开工具之上的轻量层：[Image API](/docs/developers/image-api) 负责渲染每个二维码，而带追踪的二维码就是普通的动态二维码，你可以通过 [REST API](/docs/developers/api/list-codes) 读取。[CLI](/docs/developers/cli) 中也提供相同的样式选项。

## 自托管 [#self-hosting]

该机器人使用与“Add to Slack”提醒相同的 Slack 应用，并需额外加入其签名密钥。请设置 `SLACK_CLIENT_ID`、`SLACK_CLIENT_SECRET` 和 `SLACK_SIGNING_SECRET`，生产环境中还需设置 `INTEGRATION_ENCRYPTION_KEY`，用于加密机器人令牌。如果没有这些设置，机器人的页面和端点将不存在。仓库中的 `plugins/slack/manifest.json` 是该应用的清单，`plugins/slack/README.md` 会逐步说明如何根据它创建应用。清单中包含 `openid` 用户权限范围和重定向 URL `/api/integrations/slack/link/callback`，当有人关联自己的账户时，使用 Slack 登录需要它们。速率限制需要 Upstash Redis；没有它，速率限制将处于关闭状态。参见[自托管](/docs/self-hosting#optional-services)。
