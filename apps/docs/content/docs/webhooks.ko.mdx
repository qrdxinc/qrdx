이 페이지를 마치면 선택한 이벤트가 발생한 뒤 몇 분 안에 직접 관리하는 URL이 서명된 `POST` 요청을 받게 됩니다. 서버는 각 요청이 QRdx에서 왔는지 검증하고, 재시도와 중복, 전송 로그가 어떻게 동작하는지도 알게 됩니다.

웹훅은 워크스페이스의 이벤트를 발생하는 즉시 서버로 보냅니다. 누군가 폼을 작성하면 CRM을 업데이트하고, 코드가 1,000번 스캔되면 내부 도구에 알림을 보내고, 스캔 데이터의 사본을 직접 보관할 수 있습니다.

<Callout type="info" title="Business 플랜">
웹훅, Zapier 및 Make 훅, Slack 및 Discord 알림은 **Business** 플랜에 포함됩니다. 이메일 알림과 주간 요약은 Pro에 포함됩니다. 자세한 내용은 [알림](/docs/notifications)을 참고하세요. 플랜 비교는 [플랜 및 한도](/docs/plans-and-limits)에서 확인할 수 있습니다.
</Callout>

## 시작하기 전에 [#before-you-start]

- `POST` 요청에 응답하는 공개 `https://` URL이 필요합니다. IP 주소, `localhost`, 사설 네트워크로 확인되는 호스트 이름은 거부되며 리디렉션은 따라가지 않습니다. 로컬 개발에는 공개 호스트 이름을 제공하는 터널을 사용하세요.
- 워크스페이스의 소유자 또는 관리자 역할이 필요합니다. 멤버는 엔드포인트와 전송 로그를 볼 수 있지만 추가하거나 변경할 수는 없어요.

## 1. 엔드포인트 추가하기 [#1-add-an-endpoint]

1. 이벤트를 받을 워크스페이스에서 [설정 → 웹훅](/dashboard?to=settings/webhooks)을 여세요. 이 링크는 마지막으로 사용한 워크스페이스를 엽니다. 워크스페이스 전환기에서 다른 워크스페이스를 선택해도 같은 페이지에 머물러요.
2. **엔드포인트 추가**를 선택하고 **엔드포인트 URL**을 입력한 뒤 원하는 **이벤트**를 선택하고, 대화상자에서 **엔드포인트 추가**를 선택하세요. 먼저 QRdx가 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요청하며, 엔드포인트의 URL을 변경할 때마다 다시 요청합니다. 이벤트를 변경하거나 비활성화할 때는 요청하지 않아요.
3. 저장한 뒤 표시되는 **서명 시크릿**을 복사하세요. 소유자와 관리자는 엔드포인트의 **전송 내역** 페이지에서 다시 표시하거나 교체할 수 있어요.
4. **테스트 보내기**를 선택하세요. QRdx가 서명된 `ping` 이벤트를 보내고 전송 로그에 응답 상태를 표시합니다.

## 2. 이벤트 선택하기 [#2-pick-the-events]

| 이벤트 | 발생 시점 | 참고 |
| --- | --- | --- |
| `scan.created` | 동적 QR 코드가 스캔될 때 | 일괄 전송: 엔드포인트당 분당 최대 한 번, 스캔 최대 100건과 정확한 `count` 포함 |
| `scan.milestone` | 코드의 첫 번째 스캔, 그다음 10, 100, 500, 1,000, 5,000, 10,000, 50,000, 100,000, 500,000, 1,000,000번째 스캔, 이후 100만 번마다 | 마일스톤마다 한 번 발생 |
| `code.created` | 대시보드 또는 API에서 동적 QR 코드가 생성될 때 | 코드당 이벤트 하나, 일괄 생성 시에도 동일 |
| `code.updated` | 코드의 대상, 제목, 디자인 또는 짧은 링크 도메인이 변경될 때 | `changes`에 필드 목록 포함 |
| `form.submitted` | 호스팅 페이지에서 누군가 폼을 제출할 때 | 응답 내용 포함 |
| `ping` | **테스트 보내기**를 선택할 때 | |

봇, 링크 미리보기, 프리페치 도구에 의한 스캔과 한 방문자의 빠른 반복 스캔은 집계되지 않으며 이벤트도 발생시키지 않습니다. [스캔 분석](/docs/dynamic-qr-codes#scan-analytics)과 동일해요.

## 3. 페이로드 확인하기 [#payloads]

모든 요청은 JSON 본문과 다음 헤더가 포함된 `POST`입니다.

| 헤더 | 값 |
| --- | --- |
| `Content-Type` | `application/json` |
| `User-Agent` | `QRdx-Webhooks/1.0 (+https://qrdx.dev/docs/webhooks)` |
| `X-QRdx-Event` | `code.created`와 같은 이벤트 유형 |
| `X-QRdx-Delivery` | 전송 ID: 재시도할 때마다 동일하므로 중복을 무시할 수 있음 |
| `X-QRdx-Timestamp` | 이 시도에 서명한 시각(Unix 초) |
| `X-QRdx-Signature` | `t=<timestamp>,v1=<hex HMAC-SHA256>` |

본문은 항상 `id`, `type`, `created_at`, `data`를 담은 봉투 형태입니다.

```json title="code.created"
{
  "id": "evt_cm3x8c1a20001",
  "type": "code.created",
  "created_at": "2026-10-31T09:30:00.000Z",
  "data": {
    "code": {
      "id": "cm3x7q2l40000",
      "slug": "aB3dE5f",
      "title": "Spring menu",
      "short_link": "https://qrdx.dev/q/aB3dE5f",
      "destination_url": "https://example.com/menu",
      "status": "active",
      "scan_count": 0,
      "created_at": "2026-10-31T09:30:00.000Z",
      "updated_at": "2026-10-31T09:30:00.000Z"
    },
    "actor_id": "user_123"
  }
}
```

`scan.created` 일괄 전송 예시입니다.

```json title="scan.created"
{
  "id": "evt_cm3x9d0b10002",
  "type": "scan.created",
  "created_at": "2026-10-31T09:31:00.000Z",
  "data": {
    "window_started_at": "2026-10-31T09:31:00.000Z",
    "window_seconds": 60,
    "count": 2,
    "scans": [
      {
        "scan_id": "cm3x9d0b00001",
        "code": { "id": "cm3x7q2l40000", "slug": "aB3dE5f", "title": "Spring menu" },
        "scanned_at": "2026-10-31T09:31:00.000Z",
        "country": "DE",
        "region": "BE",
        "city": "Berlin",
        "device_type": "mobile",
        "os": "iOS",
        "browser": "Safari",
        "referer": null,
        "source": "qr"
      }
    ]
  }
}
```

1분 동안 스캔이 100건을 넘으면 `scans`에는 처음 100건이 담기고 `count`에는 정확한 총계가 담깁니다. `source`는 [NFC 태그](/docs/nfc)를 탭한 경우 `nfc`, QR 스캔인 경우 `qr`입니다. 스캔 페이로드에는 IP 주소나 방문자 해시가 포함되지 않아요.

다른 이벤트에는 다음이 포함됩니다.

- `scan.milestone`: `milestone`, `code`(`id`, `slug`, `title`, `scan_count`), 마일스톤에 도달시킨 `scan`.
- `code.updated`: `code.created`와 같고, `["destination_url"]` 같은 `changes`가 추가됩니다.
- `form.submitted`: `response_id`, `page`(`id`, `title`), `code`(`id`, `slug` 또는 `null`), `fields`(`name`, `label`, 텍스트 형태의 `value`), `submitted_at`.

실제 이벤트가 처음 도착하기 전에 내 데이터로 만든 이벤트별 페이로드를 보려면 [샘플 이벤트 가져오기](/docs/developers/api/get-hook-samples)를 호출하세요.

```bash title="Terminal"
curl "https://api.qrdx.dev/v1/hooks/sample?event=scan.created" \
  -H "Authorization: Bearer $QRDX_API_KEY"
```

## 4. 서명 검증하기 [#verify-signatures]

서명 시크릿으로 `<timestamp>.<raw body>`의 HMAC-SHA256을 계산하고 `X-QRdx-Signature`의 `v1` 값과 비교하세요. JSON 파싱 전의 원본 요청 본문을 사용하고, 5분보다 오래된 타임스탬프는 거부하세요.

```ts title="lib/qrdx-webhook.ts"
import { createHmac, timingSafeEqual } from "node:crypto";

export function isFromQRdx(rawBody: string, header: string, secret: string) {
  const parts = Object.fromEntries(
    header.split(",").map((part) => part.trim().split("=", 2)),
  );
  const timestamp = Number(parts.t);
  if (!timestamp || Math.abs(Date.now() / 1000 - timestamp) > 300) return false;

  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const received = Buffer.from(parts.v1 ?? "");
  return (
    received.length === expected.length &&
    timingSafeEqual(received, Buffer.from(expected))
  );
}
```

```python title="qrdx_webhook.py"
import hmac
import hashlib
import time


def is_from_qrdx(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(part.strip().split("=", 1) for part in header.split(","))
    timestamp = int(parts.get("t", "0"))
    if not timestamp or abs(time.time() - timestamp) > 300:
        return False
    expected = hmac.new(
        secret.encode(), f"{timestamp}.".encode() + raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(parts.get("v1", ""), expected)
```

시크릿 교체는 즉시 적용됩니다. 이전 시크릿은 더 이상 검증되지 않으므로 교체 직후 서버를 업데이트하세요.

## 5. 응답과 재시도 처리 [#5-respond-and-handle-retries]

10초 안에 아무 `2xx` 상태로 응답하세요. 그 외(오류 상태, 리디렉션, 시간 초과, 연결할 수 없는 호스트)는 실패로 간주되며, QRdx는 약 1분, 4분, 16분, 1시간, 4시간, 17시간, 24시간으로 늘어나는 간격으로 재시도합니다. 각 재시도는 대기 시간이 끝난 뒤 몇 분 안에 전송됩니다. 약 이틀에 걸쳐 총 8번 시도하며, 그 후에는 전송이 실패로 표시됩니다.

전송은 여러 번 도착할 수 있고(느린 응답 뒤의 재시도, 수동 재시도) 순서가 바뀔 수도 있습니다. `X-QRdx-Delivery` 또는 봉투의 `id`로 중복을 무시하고, 처리에 몇 초 넘게 걸린다면 `2xx`로 응답한 뒤에 작업하세요.

## 나중에 변경하기 [#change-it-later]

각 엔드포인트의 **전송 내역** 페이지에는 최근 50건의 전송이 이벤트, 상태, 시도 횟수, 페이로드와 함께 표시됩니다. **지금 재시도**는 실패했거나 대기 중인 전송을 즉시 다시 보내고, **다시 보내기**는 전달 완료된 전송을 다시 보냅니다. 전송 내역은 30일 동안 보관됩니다.

<Shot id="webhook-deliveries" />

엔드포인트 메뉴에서 URL과 이벤트를 **수정**하고, **엔드포인트 비활성화**(새 전송이 중단되며 **엔드포인트 활성화**로 다시 시작)하고, **서명 시크릿**을 표시하거나 **교체**하고, **삭제**할 수 있습니다. 삭제하면 로그도 함께 삭제돼요. 워크스페이스 플랜에 더 이상 웹훅이 포함되지 않으면 엔드포인트는 유지되지만 Business 플랜으로 돌아올 때까지 아무것도 전송되지 않습니다. QR 코드는 어느 경우에나 계속 작동해요.

## Zapier, Make, n8n(REST Hooks) [#zapier-make-and-n8n-rest-hooks]

자동화 도구는 REST Hooks API를 통해 스스로 구독하고 구독을 해지할 수 있습니다. [API 키](/docs/developers/api-keys) 또는 OAuth 액세스 토큰으로 인증하세요. 구독과 해지에는 `codes:write`, 목록 조회에는 `codes:read`가 필요합니다. 훅 URL은 비밀인 경우가 많아서 `codes:read`만 있으면 `target_url`에는 호스트(`https://hooks.zapier.com`)만 표시됩니다. 토큰 요청은 본인의 워크스페이스에서 동작하고, 키는 생성된 워크스페이스에서 동작합니다. 로그인한 브라우저 세션으로 구독하면 먼저 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요청하며, 최근 10분 안에 확인하지 않았다면 `403 CONFIRMATION_REQUIRED`로 응답합니다. 구독은 일반 엔드포인트와 같아서 **설정 → 웹훅**에 표시되며 그곳에서 삭제할 수도 있어요.

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| `POST` | `/v1/hooks` | 구독합니다. 본문: `target_url`(또는 Zapier의 `hookUrl`)과 `event`(또는 `events` 배열). 구독 `id`와 `secret`을 포함해 `201`을 반환합니다 |
| `DELETE` | `/v1/hooks/{id}` | 구독을 해지합니다(`204`) |
| `GET` | `/v1/hooks` | 구독과 엔드포인트 목록을 조회합니다 |
| `GET` | `/v1/hooks/{id}` | 구독 하나를 조회합니다 |
| `GET` | `/v1/hooks/sample?event=<event>` | `event`의 최근 예시 페이로드를 배열로 반환합니다(Zapier의 "perform list") |

```bash title="Terminal"
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $QRDX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://hooks.zapier.com/hooks/standard/123/abc/", "event": "form.submitted"}'
```

```json title="201 Created (fields)"
{
  "id": "<hook id>",
  "target_url": "https://hooks.zapier.com/hooks/standard/123/abc/",
  "events": ["form.submitted"],
  "event": "form.submitted",
  "active": true,
  "created_at": "<ISO 8601 time>",
  "secret": "whsec_<shown only here>"
}
```

Business 플랜이 아니면 구독 호출은 `402`를 반환합니다.

```json title="402 Payment Required"
{"code":"PLAN_REQUIRED","message":"Webhooks and Zapier/Make hooks are part of the Business plan.","status":402}
```

`scan.created` 전송은 일괄 전송 하나이므로 Zapier에서는 `data.scans` 라인 항목을 사용해 스캔별로 작업하세요. n8n에서는 [n8n용 QRdx 노드](/docs/developers/n8n)의 QRdx Trigger 노드가 이 호출을 대신 처리하고 각 서명도 확인해 줍니다. 일반 Webhook 노드도 다른 엔드포인트와 같은 방식으로 설정해 사용할 수 있어요. 참고 문서는 [이벤트 구독](/docs/developers/api/create-hook), [훅 목록 조회](/docs/developers/api/list-hooks), [구독 해지](/docs/developers/api/delete-hook)입니다.

## 문제가 생겼을 때 [#if-something-goes-wrong]

### 엔드포인트 URL이 거부돼요 [#the-endpoint-url-is-refused]

공개 `https://` 호스트 이름만 사용할 수 있어요. `http://`, IP 주소, `localhost`, 사설 네트워크로 연결되는 이름은 사용할 수 없어요. 개발 중에는 공개 호스트 이름을 제공하는 터널을 사용하세요.

### 모든 전송이 실패 상태로 표시돼요 [#every-delivery-shows-a-failed-status]

서버가 10초 안에 `2xx`가 아닌 응답을 보냈거나, 리디렉션했거나, 응답하지 않은 경우예요. 전송 상세 정보를 열어 정확한 HTTP 상태나 오류를 확인하고 문제를 해결한 다음 **지금 다시 시도**를 선택하세요. 핸들러가 느리다면 먼저 `2xx`로 응답하고 그 뒤에 처리하세요.

### 서명이 검증되지 않아요 [#signatures-dont-verify]

다시 직렬화한 JSON 객체가 아니라 원본 요청 본문을 해시하고 있는지 확인하세요. 서버가 현재 시크릿을 사용하고 있는지도 확인하세요. 시크릿을 교체하면 이전 시크릿은 즉시 무효가 돼요. 타임스탬프 검사는 5분까지 허용하므로 서버 시계도 확인하세요.

### 이벤트가 더 이상 도착하지 않아요 [#events-stopped-arriving]

워크스페이스가 Business 플랜에서 나가 엔드포인트가 유지되지만 일시 중지되었거나, 엔드포인트가 **비활성화**되었거나, 구독을 만든 Zap, 시나리오 또는 워크플로가 꺼지면서 구독이 해지되었을 수 있어요. **설정 → Webhooks**를 확인하세요.

### `POST /v1/hooks`에서 `403 CONFIRMATION_REQUIRED`가 반환돼요 [#403-confirmation_required-from-post-v1hooks]

브라우저 세션으로 구독했기 때문이에요. QRdx에서 본인임을 확인한 후 10분 안에 다시 시도하거나, 서버에서 API 키로 구독하세요.

## 셀프 호스팅 [#self-hosting]

전송은 즉시 이루어지고, 재시도와 해당 분이 끝난 스캔 배치는 예약된 작업이 전송해요. QRdx는 GitHub Actions 워크플로에서 이 작업을 5분마다 실행하며, 이 방식은 Vercel의 무료 Hobby 플랜에서도 동작해요. 또한 `apps/app/vercel.json`이 하루에 한 번 전체 작업을 실행해요. GitHub는 예약 실행을 늦게 시작할 수 있으므로, 재시도는 정확한 분이 아니라 몇 분 안에 이루어진다고 생각하세요.

같은 방식으로 설정하려면 `.github/workflows/webhook-worker.yml`을 복사하고, `CRON_SECRET`을 Actions 시크릿으로, 작업 URL을 `WEBHOOK_WORKER_URL` 변수로 추가하세요. 또는 환경에 설정한 `CRON_SECRET`을 사용해 아무 스케줄러에서나 작업을 호출할 수 있어요.

```bash title="crontab (every 1 to 5 minutes)"
curl -H "Authorization: Bearer $CRON_SECRET" https://your-host/api/cron/webhooks
```

URL에 `?source=github`를 추가하면, 작업은 먼저 Upstash Redis의 작은 마커를 확인하고 처리할 항목이 없을 때 데이터베이스를 조회하지 않고 `{"skipped": true}`를 반환해요. 덕분에 0으로 스케일되는 데이터베이스는 계속 잠든 상태로 있을 수 있어요(Upstash가 없으면 항상 전체 작업을 실행해요). 이 옵션 없이 하루에 한 번은 호출하세요. 그 실행은 항상 전체 작업을 수행하고 마커를 복구해요. 다른 예약 작업은 [셀프 호스팅](/docs/self-hosting#scheduled-jobs)에 나와 있어요.
