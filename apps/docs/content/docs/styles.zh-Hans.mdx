本页绘制了库中提供的每一种形状，并列出选项名称，以及可复制到 `bodyPattern`、`cornerEyePattern`、`cornerEyeDotPattern` 或 `frame.style` 的值。你可以在编写代码之前，先用它挑选外观。每个图块都由与下载文件相同的渲染器绘制，并在浏览器中用 jsQR 逐个解码，因此 **Scans** 徽章显示的是实时结果。

每个值也都在包内经过测试（`packages/qrdx/tests/catalog-*.test.ts`）：测试通过手机摄像头模型（对比度损失和四分之一模块的模糊）解码，每个模块 4、6 和 9 像素，与其他所有主体、定位点和中心搭配，纠错等级为 L、M、Q 和 H，尺寸为 148 px 和 1024 px，包括深底浅码、品牌颜色以及带中心 logo 的情况。少数组合搭配在一起效果较差，请参阅[应避免的搭配](#pairs-to-avoid)。

## 主体图案 [#body-patterns]

数据模块的形状（`bodyPattern`，默认值为 `circle`）。连接式样式（`liquid`、`classy`）会把相邻模块合并成一个轮廓。`random-dots` 和 `mosaic` 的每个模块各不相同，但结果是确定的：相同的值始终绘制出相同的二维码。

<QrCatalog kind="body" />

## 定位点外框 [#eye-frames]

三个角落标记的外环（`cornerEyePattern`，默认值为 `gear`）。`leaf`、`leaf-reverse`、`drop` 和 `petal` 会旋转每个定位点，使其朝向二维码的角。每个图块都将定位点与其推荐的中心搭配展示。

<QrCatalog kind="eye" />

## 定位点中心 [#eye-centers]

每个角落标记的实心中心（`cornerEyeDotPattern`，默认值为 `circle`），显示在方形定位点内部。

<QrCatalog kind="dot" />

## 边框 [#frames]

行动号召边框绘制在二维码周围，因此二维码及其静区不会被遮挡，下载的图片会相应变大以容纳边框。下面每个内置边框都是一份边框规格，与[官方和社区边框](/docs/features/frames)由同一引擎绘制。每个边框都支持 `text`（最多 24 个字符）、`color`、`textColor` 和 `fontScale`（0.5 到 1.5）。`banner-top-bottom`、`circle` 和 `menu-card` 还会显示 `secondaryText`；`gradient-border` 的颜色从 `color` 渐变到 `secondaryColor`。

<QrCatalog kind="frame" />

```tsx title="components/framed-code.tsx"
import { QRCode } from "qrdx";

export function FramedCode() {
  return (
    <QRCode
      value="https://example.com"
      bodyPattern="liquid"
      cornerEyePattern="leaf"
      cornerEyeDotPattern="leaf"
      frame={{ style: "circle", text: "Scan me", secondaryText: "example.com" }}
    />
  );
}
```

## 应避免的搭配 [#pairs-to-avoid]

有些单独使用时可以扫描的形状，组合在一起后未通过包内的解码测试。Playground 不允许同时选择这些组合，扫描评分也会对它们发出警告（`style-pair`）：

- `diamond` 主体搭配 `square` 定位点、`pacman` 搭配 `rounded`，以及 `small-square` 搭配 `square` 或 `rounded` 定位点，在近距离下会漏扫。

`circle` 定位点在测试使用的两个解码器（jsQR 和 ZXing）中都能读取，但被标记为 **caution**：部分扫描应用会漏扫。这些组合以 `WEAK_BODY_EYES` 的名称随包提供，`getStylePairRisk(props)` 会返回某个样式的警告。

## 已停用的形状 [#retired-shapes]

`curly` 定位点以及 `diamond`、`star` 和 `banner` 中心已被移除，因为它们无法可靠扫描：ZXing（大多数 Android 扫描器使用的解码器）在手机常见距离下会漏扫 curly 定位点以及 diamond 和 star 中心，而 jsQR 在所有清晰渲染中都会漏扫 banner 中心。使用它们保存的二维码仍可加载，渲染效果与之前完全一致，Image API 也仍会为现有链接绘制它们，但任何选择器、预设或 AI 主题都不再提供这些形状。它们的名称仅作为已弃用的值保留（`RETIRED_CORNER_EYE_PATTERNS`、`RETIRED_CORNER_EYE_DOT_PATTERNS`）。
