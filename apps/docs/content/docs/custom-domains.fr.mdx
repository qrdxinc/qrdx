---

Par défaut, un [QR code dynamique](/docs/dynamic-qr-codes) encode un lien court tel que `https://qrdx.dev/q/aB3dE5f`. Avec un domaine personnalisé, il encode à la place `https://go.yourbrand.com/aB3dE5f`, de sorte que les gens voient votre marque avant de faire un scan. Les redirections, la modification et les statistiques de scan fonctionnent de la même manière. Utilisez-en un lorsque le lien lui-même est imprimé, ou lorsque votre marque doit être le seul nom présent sur l'emballage.

<Callout type="info" title="Pro et Business">
  Les domaines personnalisés sont inclus dans Pro (jusqu'à 5 par espace de travail) et Business (jusqu'à 25). Voir [Offres et limites](/docs/plans-and-limits).
</Callout>

Pressé ? La page de tâche courte : [Utiliser votre propre domaine](/docs/help/domains/custom-domains).

## Fonctionnement [#how-it-works]

<Diagram id="custom-domain" />

Vous faites pointer un domaine (en général un sous-domaine comme `go.yourbrand.com`) vers QRdx avec un enregistrement DNS, puis vous prouvez que vous en êtes propriétaire. À partir de là, QRdx répond aux requêtes pour ce nom d'hôte avec les codes et les pages de votre espace de travail, et rien d'autre. Le domaine appartient à l'espace de travail dans lequel il a été ajouté : les propriétaires et les administrateurs l'ajoutent, le vérifient et le suppriment, et tous les membres peuvent l'utiliser pour leurs codes.

## Connecter un domaine [#connect-a-domain]

1. Ouvrez **Paramètres** → **Domaines** dans l'espace de travail et saisissez le domaine, par exemple `go.yourbrand.com`. Un sous-domaine est préférable, car votre site web principal reste là où il est.
2. Ajoutez les enregistrements DNS affichés pour le domaine chez votre fournisseur DNS (là où vous avez acheté le domaine, Cloudflare, ou l'endroit où se trouve son DNS) :
   - un sous-domaine reçoit un enregistrement `CNAME`,
   - un domaine racine (`yourbrand.com`) reçoit un enregistrement `A`,
   - un enregistrement `TXT` est également affiché lorsque la propriété doit être confirmée.

   Copiez les valeurs exactes depuis le tableau de bord. La plupart des fournisseurs attendent comme nom uniquement la partie située avant votre domaine (`go`, ou `@` pour la racine).
3. Cliquez sur **Vérifier**. Les modifications DNS apparaissent généralement en quelques minutes, mais peuvent prendre jusqu'à 48 heures : réessayez plus tard si les enregistrements ne sont pas encore trouvés.

<Shot id="custom-domains" />

Une fois vérifié, le domaine apparaît dans le sélecteur **Domaine du lien court** lorsque vous créez ou modifiez un code dynamique. Les domaines vérifiés le restent jusqu'à ce que vous les supprimiez, et **Vérifier le DNS** relit les enregistrements à tout moment.

<Callout type="info">
  Un domaine qui n'est pas vérifié dans les 3 jours peut être ajouté par un autre compte, afin que personne ne puisse garder un domaine qu'il ne contrôle pas.
</Callout>

<IfAvailable feature="domainConnect" id="one-click-dns-setup" title="Configuration DNS en un clic">

Certains fournisseurs DNS prennent en charge [Domain Connect](https://www.domainconnect.org), un standard ouvert qui permet à un service d'ajouter ses enregistrements à votre place. Lorsque votre fournisseur le prend en charge et propose la configuration de QRdx, un domaine en attente de DNS affiche un bouton **Configurer avec …** portant le nom de votre fournisseur.

1. Cliquez sur le bouton. Votre fournisseur DNS s'ouvre et liste les enregistrements dont QRdx a besoin.
2. Connectez-vous là-bas si on vous le demande, puis approuvez la modification. Rien ne change tant que vous ne l'avez pas fait.
3. Vous revenez à la page Domaines, qui vérifie le DNS immédiatement, puis à nouveau pendant la demi-minute suivante.

Le bouton apparaît uniquement pour les sous-domaines tels que `go.yourbrand.com`, et seulement si votre fournisseur peut ajouter exactement les enregistrements affichés. Sinon, ajoutez vous-même les enregistrements du tableau, comme indiqué plus haut.

</IfAvailable>

## L'utiliser pour des codes [#use-it-for-codes]

- **Nouveau code :** choisissez le domaine dans **Domaine du lien court** avant de créer le code.
- **Code existant :** choisissez le domaine dans **Modifier le lien**, enregistrez, puis téléchargez à nouveau le QR code, car le lien encodé change.

<Shot id="short-link-domain-picker" />

Chaque code continue aussi de fonctionner avec son lien par défaut `https://qrdx.dev/q/<slug>` : les QR codes que vous avez imprimés avant de déplacer un code vers votre domaine ne cessent donc jamais de fonctionner. En revanche, déplacer un code d'un domaine personnalisé vers un autre (ou revenir au domaine par défaut) invalide les QR codes imprimés avec l'ancien lien de domaine personnalisé ; la boîte de dialogue vous avertit avant l'enregistrement.

### Vos propres fins de lien [#your-own-back-halves]

Avec Pro et Business, vous pouvez choisir la [fin de lien](/docs/dynamic-qr-codes#custom-back-halves) d'un code sur votre domaine, par exemple `go.yourbrand.com/spring-menu`. Elle doit seulement être unique sur ce domaine : un autre client de QRdx qui utilise `spring-menu` n'a donc aucune importance, et seuls quelques mots techniques (`api`, `_next`, `null`, `undefined`) y sont réservés. Une fin de lien choisie sur votre domaine lui appartient et n'a pas de lien `qrdx.dev/q/`. Déplacer un tel code vers un autre domaine conserve la fin de lien si elle y est libre ; le ramener au lien par défaut la conserve si elle est libre sur `qrdx.dev`, sinon le code reçoit une nouvelle fin de lien générée.

## Ce que sert le domaine [#what-the-domain-serves]

- `https://go.yourbrand.com/<slug>` redirige pour les codes qui utilisent ce domaine. Les codes sur d'autres domaines, ou uniquement sur le lien par défaut, affichent ici une page « introuvable ».
- `https://go.yourbrand.com/p/<slug>` sert vos [pages hébergées](/docs/landing-pages), avec leurs formulaires, leurs fichiers de calendrier et leurs téléchargements **Enregistrer le contact**.
- `https://go.yourbrand.com/01/<GTIN>` ([GS1 Digital Link](/docs/product-pages#gs1-digital-link)) ouvre la page produit portant ce GTIN dont le code utilise le domaine.
- Avec Business, `https://go.yourbrand.com/stats/<token>` sert les [rapports clients](/docs/client-reports) que vous avez attribués au domaine.
- `https://go.yourbrand.com/` affiche une petite page indiquant que le domaine héberge des liens de QR codes. Tout autre chemin renvoie « introuvable » : le domaine ne sert jamais le tableau de bord, l'éditeur ni aucune autre partie de QRdx.

Un domaine qui n'est pas encore vérifié affiche à la place « Ce domaine n'est pas encore connecté ». Les changements (un domaine nouvellement vérifié ou supprimé) mettent jusqu'à une minute pour atteindre tous les serveurs.

## Limites et offres [#limits-and-plans]

| | Gratuit | Pro | Business |
| --- | --- | --- | --- |
| Domaines personnalisés par espace de travail | Aucun | 5 | 25 |
| Rapports clients sur votre domaine | Non | Non | Oui |

Le passage à une offre inférieure ne casse jamais rien : les domaines vérifiés continuent de servir les codes qui les utilisent. Sans Pro ni Business, vous ne pouvez pas ajouter ni vérifier de domaines, ni déplacer d'autres codes vers un domaine, mais vous pouvez toujours modifier ces codes et supprimer des domaines.

Supprimer un domaine remet ses codes sur leur lien par défaut `qrdx.dev/q/<slug>`. Les fins de lien choisies sur le domaine passent sur `qrdx.dev` lorsqu'elles y sont libres ; les autres reçoivent une nouvelle fin de lien générée. Les QR codes imprimés avec le lien du domaine personnalisé cessent de fonctionner : la boîte de dialogue indique donc d'abord combien de codes utilisent le domaine.

## Pour les développeurs [#for-developers]

L'[API des codes](/docs/developers/api/create-codes) accepte `domainId` (l'identifiant d'un domaine vérifié dans le même espace de travail) sur `POST /v1/codes` et `PATCH /v1/codes/{id}`. Envoyez `"domainId": null` dans un `PATCH` pour revenir au lien par défaut. Déplacer un code vers un domaine nécessite Pro ou Business, sinon la réponse est `402 PLAN_REQUIRED`.

Chaque code d'une réponse comprend :

| Champ | Description |
| --- | --- |
| `shortLink` | Le lien à encoder : sur le domaine personnalisé une fois celui-ci vérifié |
| `defaultShortLink` | `https://qrdx.dev/q/<slug>`, qui fonctionne toujours ; `null` pour une fin de lien choisie sur le domaine personnalisé |
| `domain` | `{ "id", "hostname", "verified" }`, ou `null` |

## Auto-hébergement [#self-hosting]

La façon dont les domaines sont connectés dépend de votre déploiement :

- **Sur Vercel :** définissez `VERCEL_API_TOKEN` (un jeton avec accès au projet), `VERCEL_PROJECT_ID` et, pour un projet d'équipe, `VERCEL_TEAM_ID`. Les domaines sont alors ajoutés au projet via l'API Vercel Domains, qui émet aussi les certificats TLS. Sans ces variables, la page Domaines explique que les domaines personnalisés ne sont pas configurés, car Vercel ne route que les domaines ajoutés au projet.
- **Partout ailleurs** (Docker, Node.js) : laissez ces variables non définies. Les domaines sont vérifiés manuellement :
  1. Faites pointer le domaine vers votre serveur avec un `CNAME` (vers le nom d'hôte de votre application) ou un enregistrement `A` (l'IP de votre serveur).
  2. Faites en sorte que votre reverse proxy accepte le domaine, serve du HTTPS pour celui-ci (par exemple avec le TLS à la demande de Caddy ou un certificat certbot) et transmette l'en-tête `Host` d'origine à l'application. Avec nginx, c'est `proxy_set_header Host $host;` ; Caddy le fait par défaut.
  3. Ajoutez le domaine sur la page Domaines, créez l'enregistrement `TXT` qu'elle affiche (`_qrdx-challenge.<your-domain>` avec la valeur `qrdx-verify=<token>`), puis cliquez sur **Vérifier**. L'application contrôle l'enregistrement par une requête DNS.

**La configuration DNS en un clic** (facultative) utilise [Domain Connect](https://www.domainconnect.org). Elle nécessite un modèle qui vous est propre, accepté par chaque fournisseur DNS que vous souhaitez prendre en charge, ainsi qu'une clé RSA qui signe les liens de configuration : définissez `DOMAIN_CONNECT_PROVIDER_ID`, `DOMAIN_CONNECT_SERVICE_ID` et `DOMAIN_CONNECT_PRIVATE_KEY` (PEM), et publiez la clé publique sous forme d'enregistrements `TXT` à `_dck1.<provider id>`. Le modèle propre à QRdx (`domain-connect/` dans le dépôt) ne fonctionne que pour qrdx.dev, car les fournisseurs vérifient la signature avec sa clé. Tant que la clé publiée ne correspond pas, aucun bouton n'est affiché et l'application consigne la raison dans ses journaux.

L'application reconnaît les domaines personnalisés grâce à l'en-tête `Host`. Les requêtes vers l'URL de votre propre application, `NEXT_PUBLIC_SHORT_LINK_BASE_URL`, `localhost` et `*.vercel.app` sont toujours traitées comme relevant de l'application principale. Voir [Auto-hébergement](/docs/self-hosting#optional-services).
