默认情况下,[动态二维码](/docs/dynamic-qr-codes)编码的是类似 `https://qrdx.dev/q/aB3dE5f` 的短链接。使用自定义域名后,编码的则是 `https://go.yourbrand.com/aB3dE5f`,这样用户在扫描之前就能看到你的品牌。跳转、编辑和扫描分析的工作方式保持不变。当链接本身需要印刷出来,或者包装上只应出现你的品牌名称时,可以使用自定义域名。

<Callout type="info" title="Pro 和 Business">
  自定义域名包含在 Pro(每个工作区最多 5 个)和 Business(最多 25 个)中。参见[套餐与限制](/docs/plans-and-limits)。
</Callout>

赶时间?请看简明的操作页面:[使用你自己的域名](/docs/help/domains/custom-domains)。

## 工作原理 [#how-it-works]

<Diagram id="custom-domain" />

你通过 DNS 记录将一个域名(通常是 `go.yourbrand.com` 这样的子域名)指向 QRdx,并证明你拥有该域名。此后,QRdx 会针对该主机名的请求返回你工作区的二维码和页面,不会返回其他任何内容。域名归属于添加它的工作区:所有者和管理员可以添加、验证和移除域名,所有成员都可以在自己的二维码中使用它。

## 连接域名 [#connect-a-domain]

1. 在工作区中打开 **Settings** → **Domains**,输入域名,例如 `go.yourbrand.com`。建议使用子域名,这样你的主网站不受影响。
2. 在你的 DNS 服务商(即你购买域名的地方、Cloudflare,或域名 DNS 所在的任何地方)处,添加该域名对应显示的 DNS 记录:
   - 子域名使用 `CNAME` 记录,
   - 根域名(`yourbrand.com`)使用 `A` 记录,
   - 需要确认所有权时,还会显示一条 `TXT` 记录。

   请从控制台复制准确的值。大多数服务商只需要填写域名之前的部分作为名称(`go`,根域名则填 `@`)。
3. 点击 **Verify**。DNS 变更通常几分钟内生效,但最长可能需要 48 小时,如果暂时找不到记录,请稍后再试。

<Shot id="custom-domains" />

验证通过后,在创建或编辑动态二维码时,该域名会出现在 **Short link domain** 选择器中。已验证的域名会一直保持已验证状态,直到你将其移除,**Check DNS** 可随时重新读取记录。

<Callout type="info">
  如果域名在 3 天内未通过验证,其他账户就可以添加该域名,因此没有人能占用自己并不控制的域名。
</Callout>

<IfAvailable feature="domainConnect" id="one-click-dns-setup" title="一键设置 DNS">

部分 DNS 服务商支持 [Domain Connect](https://www.domainconnect.org),这是一项开放标准,允许服务代你添加记录。如果你的服务商支持,并提供 QRdx 的设置模板,等待 DNS 的域名会显示一个以服务商命名的 **Set up with …** 按钮。

1. 点击该按钮。你的 DNS 服务商页面会打开,并列出 QRdx 所需的记录。
2. 如有提示,请在该页面登录并批准变更。在你批准之前不会有任何改动。
3. 你会回到 Domains 页面,页面会立即检查 DNS,并在接下来的半分钟内再次检查。

该按钮只会出现在 `go.yourbrand.com` 这样的子域名上,并且只有在你的服务商能够准确添加所示记录时才会出现。否则,请按上文所述自行添加表中的记录。

</IfAvailable>

## 在二维码中使用 [#use-it-for-codes]

- **新二维码:**在创建二维码之前,在 **Short link domain** 中选择该域名。
- **现有二维码:**在 **Edit link** 中选择该域名并保存,然后重新下载二维码,因为编码的链接已经改变。

<Shot id="short-link-domain-picker" />

每个二维码在其默认的 `https://qrdx.dev/q/<slug>` 链接上也始终有效,因此在将二维码迁移到你的域名之前印刷的二维码不会失效。将二维码从一个自定义域名迁移到另一个自定义域名(或迁回默认链接),会使使用旧自定义域名链接印刷的二维码失效;保存之前,对话框会给出警告。

### 自定义后缀 [#your-own-back-halves]

在 Pro 和 Business 上,你可以在自己的域名下为二维码选择[后缀](/docs/dynamic-qr-codes#custom-back-halves),例如 `go.yourbrand.com/spring-menu`。后缀只需在该域名下唯一即可,因此其他 QRdx 客户使用 `spring-menu` 并不影响你,并且在该域名下只保留了少数技术词汇(`api`、`_next`、`null`、`undefined`)。在你的域名下选择的后缀归该域名所有,没有对应的 `qrdx.dev/q/` 链接。将此类二维码迁移到另一个域名时,如果后缀在那里可用,则会保留;迁回默认链接时,如果后缀在 `qrdx.dev` 上可用,则会保留,否则二维码会获得一个新生成的后缀。

## 域名提供的内容 [#what-the-domain-serves]

- `https://go.yourbrand.com/<slug>` 会为使用该域名的二维码进行跳转。其他域名上的二维码,或仅使用默认链接的二维码,在这里会显示“未找到”页面。
- `https://go.yourbrand.com/p/<slug>` 提供你的[托管页面](/docs/landing-pages),包括其中的表单、日历文件和 **Save contact** 下载。
- `https://go.yourbrand.com/01/<GTIN>`([GS1 Digital Link](/docs/product-pages#gs1-digital-link))会打开具有该 GTIN 且其二维码使用此域名的产品页面。
- 在 Business 上,`https://go.yourbrand.com/stats/<token>` 提供你分配给该域名的[客户报告](/docs/client-reports)。
- `https://go.yourbrand.com/` 会显示一个简短页面,说明该域名用于托管二维码链接。其他所有路径都会返回“未找到”:该域名绝不会提供控制台、编辑器或 QRdx 的任何其他部分。

尚未验证的域名则会显示“This domain isn't connected yet”。变更(新验证或移除的域名)最多需要一分钟才能传播到所有服务器。

## 限制与套餐 [#limits-and-plans]

| | 免费版 | Pro | Business |
| --- | --- | --- | --- |
| 每个工作区的自定义域名数 | 无 | 5 | 25 |
| 你的域名上的客户报告 | 否 | 否 | 是 |

降级不会破坏任何内容:已验证的域名会继续为使用它们的二维码提供服务。没有 Pro 或 Business 时,你无法添加或验证域名,也无法将更多二维码迁移到域名上,但仍可以编辑这些二维码并移除域名。

移除域名会将其二维码切换回默认的 `qrdx.dev/q/<slug>` 链接。在该域名下选择的后缀,如果在 `qrdx.dev` 上可用,则会迁移过去;其余的会获得新生成的后缀。使用自定义域名链接印刷的二维码将停止工作,因此对话框会先显示有多少个二维码在使用该域名。

## 面向开发者 [#for-developers]

[二维码 API](/docs/developers/api/create-codes) 在 `POST /v1/codes` 和 `PATCH /v1/codes/{id}` 上接受 `domainId`(同一工作区中已验证域名的 ID)。在 `PATCH` 中发送 `"domainId": null` 可切换回默认链接。将二维码迁移到域名上需要 Pro 或 Business,否则会返回 `402 PLAN_REQUIRED`。

响应中的每个二维码都包含:

| 字段 | 说明 |
| --- | --- |
| `shortLink` | 要编码的链接:域名验证通过后使用自定义域名 |
| `defaultShortLink` | `https://qrdx.dev/q/<slug>`,始终有效;对于在自定义域名上选择的后缀,则为 `null` |
| `domain` | `{ "id", "hostname", "verified" }`,或 `null` |

## 自托管 [#self-hosting]

域名如何连接取决于你的部署方式:

- **在 Vercel 上:**设置 `VERCEL_API_TOKEN`(有权访问该项目的令牌)、`VERCEL_PROJECT_ID`,对于团队项目还需设置 `VERCEL_TEAM_ID`。之后域名会通过 Vercel Domains API 添加到项目中,同时由它签发 TLS 证书。如果没有这些变量,Domains 页面会说明尚未设置自定义域名,因为 Vercel 只会路由已添加到项目中的域名。
- **其他任何环境**(Docker、Node.js):不要设置这些变量。域名需要手动验证:
  1. 使用 `CNAME`(指向你应用的主机名)或 `A` 记录(你服务器的 IP)将域名指向你的服务器。
  2. 让你的反向代理接受该域名,为其提供 HTTPS(例如使用 Caddy 的按需 TLS 或 certbot 证书),并将原始 `Host` 头转发给应用。在 nginx 中是 `proxy_set_header Host $host;`;Caddy 默认就会这样做。
  3. 在 Domains 页面添加域名,创建其显示的 `TXT` 记录(`_qrdx-challenge.<your-domain>`,值为 `qrdx-verify=<token>`),然后点击 **Verify**。应用会通过 DNS 查询来检查该记录。

**一键 DNS 设置**(可选)使用 [Domain Connect](https://www.domainconnect.org)。它需要你自己的模板,并被你想支持的每个 DNS 服务商接受,还需要一个用于签名设置链接的 RSA 密钥:设置 `DOMAIN_CONNECT_PROVIDER_ID`、`DOMAIN_CONNECT_SERVICE_ID` 和 `DOMAIN_CONNECT_PRIVATE_KEY`(PEM),并将公钥以 `TXT` 记录的形式发布在 `_dck1.<provider id>`。QRdx 自己的模板(仓库中的 `domain-connect/`)仅适用于 qrdx.dev,因为服务商会用它的密钥校验签名。在发布的密钥匹配之前,不会显示按钮,应用会在日志中记录原因。

应用通过 `Host` 头识别自定义域名。对你自己的应用 URL、`NEXT_PUBLIC_SHORT_LINK_BASE_URL`、`localhost` 和 `*.vercel.app` 的请求,始终被视为主应用。参见[自托管](/docs/self-hosting#optional-services)。
