Les contrôles du code déterminent si le scan d'un [QR code dynamique](/docs/dynamic-qr-codes) aboutit ou non. Utilisez-les lorsqu'un code ne doit fonctionner que pendant un temps (un événement, une promotion), que pour certaines personnes (un mot de passe) ou qu'un nombre de fois défini, et lorsque vous voulez désactiver un code imprimé sans le réimprimer.

<Callout type="info" title="La pause est gratuite, le reste relève de Pro">
  La pause fonctionne avec tous les forfaits. Les mots de passe, les dates de début et de fin, les limites de scans et l'URL de secours font partie de Pro et Business. Voir [Forfaits et limites](/docs/plans-and-limits).
</Callout>

Pressé ? Consultez les pages de tâches courtes : [Mettre en pause, planifier ou limiter un code](/docs/help/dynamic-codes/pause-schedule-limit) et [Protéger un code par mot de passe](/docs/help/dynamic-codes/password).

## Fonctionnement [#how-it-works]

Chaque contrôle se trouve dans le panneau **Access & schedule** de l'onglet **Settings** du code (ouvrez le code depuis [Codes](/dashboard?to=codes)). À chaque scan, QRdx vérifie les contrôles dans l'ordre avant de rediriger : le code est-il en pause, a-t-il commencé, est-il terminé, a-t-il dépassé sa limite de scans, nécessite-t-il un mot de passe. La première vérification qui échoue détermine ce que voit la personne qui scanne. Les modifications s'appliquent dès le scan suivant ; vous n'avez jamais à réimprimer le code.

| Contrôle | Ce que voient les visiteurs | Forfait |
| --- | --- | --- |
| Pause | Votre URL de secours, ou une page neutre « This campaign is paused » | Tous les forfaits |
| Mot de passe | Un écran de mot de passe ; le bon mot de passe ouvre le code | Pro et Business |
| Début | Avant le début : « This campaign hasn't started yet » | Pro et Business |
| Fin | Après la fin : votre URL de secours, ou « This campaign has ended » | Pro et Business |
| Limite de scans | Une fois la limite atteinte : votre URL de secours, ou la page « terminé » | Pro et Business |
| URL de secours | Destination des codes en pause, terminés ou ayant atteint leur limite | Pro et Business |

## Pause [#pause]

Activez **Pause code** pour arrêter un code un temps, par exemple entre deux événements, et désactivez-le pour reprendre. Le menu **⋯** du code propose aussi **Pause** et **Resume**, et les actions groupées de la liste Codes permettent de mettre plusieurs codes en pause à la fois. Pendant la pause, les scans mènent à votre URL de secours si vous en avez défini une, sinon à une page simple indiquant que la campagne est en pause.

## Mot de passe [#password]

Définissez un mot de passe de 4 à 64 caractères : toute personne qui scanne le code voit d'abord un écran de mot de passe. Une fois le bon mot de passe saisi, ce navigateur reste déverrouillé pendant 6 heures, sur le lien court comme sur la page hébergée qu'il ouvre. Changer le mot de passe verrouille tous les navigateurs qui avaient débloqué l'ancien ; le supprimer rouvre le code à tout le monde.

<Shot id="scan-password" />

Les mots de passe sont stockés sous forme de hachages bcrypt : QRdx ne peut donc pas vous les afficher par la suite, seulement les remplacer. Les tentatives erronées répétées d'un même visiteur sont ralenties. Communiquez le mot de passe séparément du code : quiconque dispose des deux peut entrer.

## Dates de début et de fin [#start-and-end-dates]

- **Starts :** jusqu'à cette date, les scans affichent « This campaign hasn't started yet. Please scan this code again later. » L'URL de secours n'est pas utilisée avant le début.
- **Ends :** à partir de cette date, les scans mènent à votre URL de secours ou affichent « This campaign has ended ».

Les dates sont saisies dans votre fuseau horaire et enregistrées comme des instants exacts : un code se termine donc au même instant partout. La fin doit être postérieure au début.

## Limite de scans [#scan-limit]

La limite compte les scans de la même façon que vos statistiques : les robots et les aperçus de liens ne sont pas comptés, et les scans répétés depuis une même adresse en moins d'une minute comptent pour un seul. Une fois la limite atteinte, les scans suivants mènent à votre URL de secours ou à la page « terminé ». Augmentez ou supprimez la limite pour rouvrir le code.

## URL de secours [#fallback-url]

L'adresse vers laquelle sont redirigés les codes en pause, terminés ou ayant atteint leur limite, par exemple votre page d'accueil ou la campagne suivante. Sans URL de secours, les visiteurs voient une petite page neutre. Cette page n'affiche jamais de publicité, de promotion QRdx ni d'invitation à s'inscrire, seulement l'état de la campagne et un lien **Report abuse**. L'URL de secours passe par les mêmes contrôles de sécurité qu'une destination.

## Limites et forfaits [#limits-and-plans]

- La pause fonctionne avec tous les forfaits.
- Définir ou modifier un mot de passe, des dates, une limite de scans ou une URL de secours nécessite Pro ou Business.
- Une rétrogradation ne termine ni ne verrouille jamais un code. Les contrôles définis sous Pro continuent de fonctionner tels que configurés, et vous pouvez les supprimer avec n'importe quel forfait.

## Contrôles de sécurité des liens [#safety-checks-on-links]

QRdx vérifie chaque destination et chaque URL de secours à l'enregistrement :

- Les liens répertoriés par [Google Web Risk](https://cloud.google.com/web-risk) comme malware, hameçonnage ou logiciel indésirable sont refusés (lorsque le serveur dispose d'une clé Web Risk). Lorsque Web Risk ne répond pas à temps, comme cela peut arriver pour un grand lot, le code est créé et son lien est revérifié peu après ; si Web Risk le répertorie alors, le code est désactivé et un examinateur l'étudie.
- Les liens `javascript:`, `data:` et autres liens non web sont refusés.
- Pendant les 7 premiers jours d'un compte, les codes qui pointent vers des raccourcisseurs d'URL, des adresses IP brutes ou des domaines imitant d'autres domaines (homoglyphes) sont enregistrés désactivés et **mis en attente de révision**. Le panneau l'indique ; vous n'avez rien d'autre à faire, et un examinateur active le code une fois la vérification terminée.
- Les nouveaux comptes peuvent créer jusqu'à 30 codes dynamiques par heure, ou {facts.newPaidAccountHourlyCodes} dans un espace de travail sur un forfait payant. Au-delà, l'erreur indique combien de minutes attendre, et un import depuis le tableau de bord est suspendu jusque-là.

Chacun peut signaler un code sur [qrdx.dev/report-abuse](/report-abuse). Les codes désactivés après examen cessent de fonctionner pour tout le monde et leur propriétaire ne peut pas les réactiver. Voir [Signaler un QR code nuisible](/docs/help/privacy-and-security/report-abuse).

## Pour les développeurs [#for-developers]

La REST API crée, met à jour et supprime des codes, mais ne définit pas les contrôles ; ceux-ci se trouvent dans le tableau de bord. Le `status` d'un code dans les réponses de l'API indique s'il est actif ou archivé. Les scans bloqués par un contrôle ne sont pas envoyés comme événements `scan.created` des [webhooks](/docs/webhooks), car ils ne sont pas enregistrés comme des scans.

## Auto-hébergement [#self-hosting]

- `WEB_RISK_API_KEY` : une clé d'API Google Cloud avec l'API Web Risk activée. Sans elle, les liens ne sont vérifiés que par les règles hors ligne décrites ci-dessus.
- `SAFETY_YOUNG_ACCOUNT_DAYS`, `SAFETY_YOUNG_ACCOUNT_DYNAMIC_PER_HOUR` et `SAFETY_RECHECK_BATCH` modifient les 7 jours, les 30 codes par heure et la taille d'une revérification Web Risk.
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` et `TURNSTILE_SECRET_KEY` : Cloudflare Turnstile sur le formulaire public de signalement (facultatif).
- Les cookies de déverrouillage sont signés avec `BETTER_AUTH_SECRET`.

Voir [Auto-hébergement](/docs/self-hosting#optional-services).
