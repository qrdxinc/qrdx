`QRCode` ist die Komponente der Wahl: Sie unterstützt alle Stiloptionen und eine einfache `logo`-Prop und rendert auf dem Server. Diese Seite geht die Props durch, die du am häufigsten setzt. Alle Props findest du in der [API-Referenz der Bibliothek](/docs/api-reference).

<NpmStatus package="qrdx" />

## Komponente auswählen [#choose-a-component]

| Komponente | Was sie zeichnet | Wann du sie nutzt |
| --- | --- | --- |
| `QRCode` | Ein `<svg>` mit allen Stiloptionen sowie `logo`, `logoOptions`, `hideLogo` und `scale`. Nimmt keine weiteren Attribute an | Fast immer |
| `QRCodeSVG` | Dasselbe `<svg>`, wobei das Logo als rohe `imageSettings` in Pixeln angegeben wird. Jede weitere Prop (`aria-label`, `className`, `role`) landet auf dem `<svg>` | Du brauchst Attribute auf dem `<svg>`, du platzierst das Logo selbst oder du übernimmst Code aus einem anderen Renderer |
| `QRCodeCanvas` | Ein `<canvas>` mit einfachen quadratischen Modulen und einfarbigen Farben | Du brauchst ein Canvas-Element. Muster, Augenfarben, Verläufe und Vorlagen werden ignoriert |

`QRCode` und `QRCodeSVG` verwenden keine Hooks, die nur im Browser laufen, daher rendern sie in React Server Components und in statischem HTML. `QRCodeCanvas` wird mit `"use client"` ausgeliefert.

```tsx title="components/menu-code.tsx"
import { QRCode } from "qrdx";

export function MenuCode() {
  return (
    <div role="img" aria-label="QR code for the menu">
      <QRCode value="https://example.com/menu" size={256} margin={4} />
    </div>
  );
}
```

`value` wird genau so codiert, wie du es übergibst, daher funktionieren eine Wi-Fi-Payload, eine vCard, `mailto:` oder einfacher Text. `QRCode` akzeptiert nur die eigenen Props des Codes und `style`, sonst nichts: Gib ihm einen zugänglichen Namen, indem du ihn wie oben umschließt. `QRCodeSVG` setzt `aria-label`, `className`, `role` und jedes andere Attribut direkt auf das `<svg>`.

## Größe und Ruhezone [#size-and-quiet-zone]

- `size` ist Breite und Höhe in Pixeln (Standard 128). Unter etwa 128 px lässt sich ein dichter Code am Bildschirm schwer scannen.
- `margin` ist die Ruhezone um den Code, in Modulen (Standard 0). Der QR-Standard verlangt 4. Setze ihn, wenn der Code auf einem Foto, einem Muster oder einer dunklen Seite liegt; ein Code in einer weißen Karte mit eigenem Innenabstand kann bei 0 bleiben.
- `scale` multipliziert bei `QRCode` den Wert von `size`.

Ein Rahmen oder eine Vorlage verändert die Ausgabegröße. Siehe [Rahmen oder Vorlage](#frame-or-template).

## Farben [#colors]

```tsx title="components/brand-code.tsx"
import { QRCode } from "qrdx";

export function BrandCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      fgColor="#1d4ed8"
      bgColor="#f8fafc"
      eyeColor="#0f172a"
      dotColor="#1d4ed8"
    />
  );
}
```

- `fgColor` färbt die Datenmodule, `bgColor` den Hintergrund, `eyeColor` die drei Eckaugen und `dotColor` den Punkt in jedem Auge. Die Augenfarben übernehmen standardmäßig `fgColor`.
- Jede Prop akzeptiert eine beliebige CSS-Farbe (`#1d4ed8`, `rgb(29 78 216)`, einen Farbnamen) oder ein Verlaufsobjekt. [Farben und Verläufe festlegen](/docs/features/colors-gradients) behandelt Verläufe, transparente Farben und Bildfüllungen.
- Halte die Module dunkler als den Hintergrund. Scanner lesen dunkel auf hell; ein heller Code auf dunklem Hintergrund funktioniert in den meisten Handykameras, aber nicht in manchen älteren Apps.

## Formen [#shapes]

```tsx title="components/rounded-code.tsx"
import { QRCode } from "qrdx";

export function RoundedCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      bodyPattern="rounded"
      cornerEyePattern="extra-rounded"
      cornerEyeDotPattern="rounded"
    />
  );
}
```

- `bodyPattern` formt die Datenmodule (Standard `circle`). Es stehen {facts.bodyPatterns} zur Auswahl.
- `cornerEyePattern` formt die drei Eckaugen (Standard `gear`), eines von {facts.eyeShapes}.
- `cornerEyeDotPattern` formt den Punkt in jedem Auge (Standard `circle`), eines von {facts.eyeCentres}.

[Formen, Augen und Rahmen](/docs/styles) zeigt jeden Wert live. [Modul- und Augenformen wählen](/docs/features/patterns) erklärt Modulskalierung, geformte Codes und die wenigen Kombinationen, die sich schlecht scannen lassen.

## Logo [#logo]

```tsx title="components/logo-code.tsx"
import { QRCode } from "qrdx";

export function LogoCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      level="H"
      logo="/logo.png"
      logoOptions={{ size: 0.2, padding: 1 }}
    />
  );
}
```

`logo` akzeptiert einen Pfad in deiner App, eine URL oder eine Data-URL. Die Module dahinter werden freigestellt, der Code verlässt sich also beim Scannen auf die Fehlerkorrektur: Nutze `level="H"`. `logoOptions` legt die Breite des Logos als Anteil am Code fest (0.1 bis 0.3, Standard 0.25), seinen Freiraum in Modulen, seine Position und seinen Zuschnitt. Die Komponente zeichnet nie ein Logo, das größer ist, als der Code reparieren kann. Details findest du unter [Logo im Code hinzufügen](/docs/features/logos).

## Rahmen oder Vorlage [#frame-or-template]

```tsx title="components/framed-code.tsx"
import { QRCode } from "qrdx";

export function FramedCode() {
  return (
    <QRCode
      value="https://example.com"
      size={256}
      frame={{ style: "banner-bottom", text: "Scan me", color: "#0f172a" }}
    />
  );
}
```

- `frame` zeichnet einen Call-to-Action-Rahmen um den Code. Der Code bleibt `size` breit und die Ausgabe wächst, damit der Rahmen passt. Es gibt {facts.frameStyles} integrierte Stile sowie die offizielle Rahmenbibliothek und deine eigenen Rahmenspezifikationen. Siehe [Rahmen, Scan-Score und Druckdateien](/docs/features/frames).
- `templateId` zeichnet stattdessen eine Vorlage wie `Arrow` oder `StandardBox`. Eine Vorlage zeichnet ihr gesamtes Artwork in der Größe `size`, der Code ist darin kleiner. Siehe [Rahmenvorlage verwenden](/docs/features/templates).

Sind beide gesetzt, wird der Rahmen um das Artwork der Vorlage gezeichnet.

## Fehlerkorrektur [#error-correction]

| `level` | Darf beschädigt sein | Wofür |
| --- | --- | --- |
| `L` | etwa 7 % | Saubere Bildschirme, kurze Links, der kleinste Code |
| `M` | etwa 15 % | Lange Payloads wie vCards, bei denen ein kleinerer Code wichtiger ist |
| `Q` | etwa 25 % | Der Standard. Allgemeine Nutzung |
| `H` | etwa 30 % | Logos, Kunst, Drucke, die zerkratzt oder gefaltet werden |

Eine höhere Stufe fügt Module hinzu, der Code wird bei gleicher Größe also dichter. `autoLevel` hebt die Stufe von selbst auf `H` an, wenn ein Logo mehr als 7 % des Codes bedeckt; die Option ist standardmäßig aus, damit bestehende Codes ihr Aussehen behalten.
