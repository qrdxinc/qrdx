Os controles de código decidem se a leitura de um [QR code dinâmico](/docs/dynamic-qr-codes) é concluída ou não. Use quando um código deve funcionar só por um período (um evento, uma promoção), só para algumas pessoas (uma senha) ou só um número definido de vezes, e quando você quiser desativar um código impresso sem reimprimir.

<Callout type="info" title="Pausar é grátis, o resto é Pro">
  Pausar funciona em todos os planos. Senhas, datas de início e fim, limites de leituras e a URL de fallback fazem parte do Pro e do Business. Veja [Planos e limites](/docs/plans-and-limits).
</Callout>

Está com pressa? As páginas de tarefas rápidas: [Pausar, agendar ou limitar um código](/docs/help/dynamic-codes/pause-schedule-limit) e [Proteger um código com senha](/docs/help/dynamic-codes/password).

## Como funciona [#how-it-works]

Cada controle fica no painel **Access & schedule** na aba **Settings** do código (abra o código em [Códigos](/dashboard?to=codes)). A cada leitura, o QRdx verifica os controles em ordem antes de redirecionar: o código está pausado, já começou, já terminou, passou do limite de leituras, exige senha. A primeira verificação que falhar decide o que a pessoa vê. As mudanças valem a partir da próxima leitura; você nunca precisa reimprimir o código.

<Shot id="code-settings" />

| Controle | O que quem lê vê | Plano |
| --- | --- | --- |
| Pausa | Sua URL de fallback ou uma página neutra "Esta campanha está pausada" | Todos os planos |
| Senha | Uma tela de senha; a senha correta abre o código | Pro e Business |
| Início | Antes do início: "Esta campanha ainda não começou" | Pro e Business |
| Fim | Após o fim: sua URL de fallback ou "Esta campanha terminou" | Pro e Business |
| Limite de leituras | Ao atingir o limite: sua URL de fallback ou a página de "encerrada" | Pro e Business |
| URL de fallback | Para onde códigos pausados, encerrados e acima do limite levam as pessoas | Pro e Business |

## Pausa [#pause]

Ative **Pause code** para parar um código por um tempo, por exemplo entre dois eventos, e desative para retomar. O menu **⋯** do código também tem **Pause** e **Resume**, e as ações em massa na lista de Códigos pausam vários códigos de uma vez. Leituras de um código pausado vão para sua URL de fallback, se você definiu uma, ou então para uma página simples que informa que a campanha está pausada.

## Senha [#password]

Defina uma senha de 4 a 64 caracteres e quem ler o código verá primeiro uma tela de senha. Depois da senha correta, aquele navegador fica desbloqueado por 6 horas, no link curto e na página hospedada que ele abre. Trocar a senha bloqueia todos os navegadores que desbloquearam a antiga; removê-la abre o código para todos de novo.

<Shot id="scan-password" />

As senhas são armazenadas como hashes bcrypt, então o QRdx não consegue mostrar a senha depois, só substituí-la. Tentativas erradas repetidas de um mesmo visitante são desaceleradas. Compartilhe a senha separadamente do código: quem tiver os dois entra.

## Datas de início e fim [#start-and-end-dates]

- **Início:** até lá, as leituras mostram "Esta campanha ainda não começou. Leia este código novamente mais tarde." A URL de fallback não é usada antes do início.
- **Fim:** a partir daí, as leituras vão para sua URL de fallback ou mostram "Esta campanha terminou".

As datas são informadas no seu próprio fuso horário e armazenadas como momentos exatos, então um código termina no mesmo instante em qualquer lugar. O fim precisa ser depois do início.

## Limite de leituras [#scan-limit]

O limite conta as leituras do mesmo jeito que suas análises: bots e pré-visualizações de links não são contados, e leituras repetidas do mesmo endereço em um minuto contam uma vez. Quando o código atinge o limite, as próximas leituras vão para sua URL de fallback ou para a página de "encerrada". Aumente ou remova o limite para reabrir o código.

## URL de fallback [#fallback-url]

O endereço para onde códigos pausados, encerrados e acima do limite levam as pessoas, como sua página inicial ou a próxima campanha. Sem ele, quem lê vê uma pequena página neutra. Essa página nunca mostra anúncios, promoção do QRdx nem convite de cadastro, apenas o status da campanha e um link **Report abuse**. A URL de fallback passa pelas mesmas verificações de segurança que um destino.

## Limites e planos [#limits-and-plans]

- Pausar funciona em todos os planos.
- Definir ou alterar uma senha, datas, um limite de leituras ou uma URL de fallback exige Pro ou Business.
- Um downgrade nunca encerra nem bloqueia um código. Os controles definidos enquanto você estava no Pro continuam funcionando como configurados, e você pode remover qualquer um deles em qualquer plano.

## Verificações de segurança nos links [#safety-checks-on-links]

O QRdx verifica cada destino e URL de fallback quando você salva:

- Links listados pelo [Google Web Risk](https://cloud.google.com/web-risk) como malware, phishing ou software indesejado são rejeitados (quando o servidor tem uma chave do Web Risk). Quando o Web Risk não consegue responder a tempo, como pode acontecer em um lote grande, o código é criado e o link é consultado de novo logo depois; se o Web Risk o listar nesse momento, o código é desativado e um revisor o analisa.
- `javascript:`, `data:` e outros links que não são da web são rejeitados.
- Nos primeiros 7 dias de uma conta, códigos que apontam para encurtadores de URL, endereços IP puros ou domínios parecidos com outros (homóglifos) são salvos desativados e **retidos para revisão**. O painel avisa; você não precisa fazer mais nada, e um revisor ativa o código quando ele for aprovado.
- Contas novas podem criar até 30 códigos dinâmicos por hora, ou {facts.newPaidAccountHourlyCodes} em um workspace de plano pago. Acima disso, o erro informa quantos minutos esperar, e uma importação pelo painel é pausada até lá.

Qualquer pessoa pode denunciar um código em [qrdx.dev/report-abuse](/report-abuse). Códigos desativados após uma revisão deixam de funcionar para todos e não podem ser reativados pelo dono. Veja [Denunciar um QR code nocivo](/docs/help/privacy-and-security/report-abuse).

## Para desenvolvedores [#for-developers]

A REST API cria, atualiza e exclui códigos, mas não define controles; eles ficam no painel. O `status` de um código nas respostas da API indica se ele está ativo ou arquivado. Leituras bloqueadas por um controle não são entregues como eventos de [webhook](/docs/webhooks) `scan.created`, porque não são registradas como leituras.

## Hospedagem própria [#self-hosting]

- `WEB_RISK_API_KEY`: uma chave de API do Google Cloud com a Web Risk API ativada. Sem ela, os links são verificados apenas pelas regras offline acima.
- `SAFETY_YOUNG_ACCOUNT_DAYS`, `SAFETY_YOUNG_ACCOUNT_DYNAMIC_PER_HOUR` e `SAFETY_RECHECK_BATCH` alteram os 7 dias, os 30 códigos por hora e o tamanho de uma nova verificação do Web Risk.
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` e `TURNSTILE_SECRET_KEY`: Cloudflare Turnstile no formulário público de denúncia (opcional).
- Os cookies de desbloqueio são assinados com `BETTER_AUTH_SECRET`.

Veja [Hospedagem própria](/docs/self-hosting#optional-services).
