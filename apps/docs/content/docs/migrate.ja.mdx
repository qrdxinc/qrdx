title: "Bitly、Rebrandlyなどからの移行"
description: "短縮リンクと動的QRコードをQRdxにインポートし、印刷済みのコードを使い続けながら、ブランド付きのバックハーフも維持できます。"
---

QRdxでは、他のサービスのリンクや動的コードを一括でインポートできます。すでに出回っているコードを刷り直さずに移行できます。インポートの手順はどれも同じ3ステップです。取り込む対象を選び、プレビューを確認して、インポートします。他のサービスにあるコードを、QRdxで編集・トラッキングできるようにしたいときにお読みください。

<Callout type="info" title="プラン">
  インポートはすべてのプランで利用できます。ただし、プランのアクティブなコード数の上限内に限ります。元のバックハーフを維持するには Pro または Business が必要です。[プランと制限](/docs/plans-and-limits)をご覧ください。
</Callout>

お急ぎの方は、手順をまとめたページをご覧ください：[他のサービスからコードを取り込む](/docs/help/dynamic-codes/import)。

## 仕組み [#how-it-works]

<Diagram id="import-flow" />

[コード](/dashboard?to=codes)を開き、**⋯** メニュー → **コードをインポート** → **Bitlyなどのアプリから** の順に選びます。ソースは2種類あります。

- **連携済みアカウント：** Bitly、Rebrandly、Short.io。QRdxがプロバイダーのAPIを通じてリンクを一覧表示します。
- **エクスポートファイル：** QR Code Generator PRO、Uniqode (Beaconstac)、Flowcode、QR TIGER、ME-QR、TinyURL、Hovercode、Scanova、または遷移先URLを含む任意のCSV。

インポート中に、以前のアカウントで何かが変更されることはありません。

### インポートで作成されるもの [#what-an-import-creates]

各リンクまたはコードは、次の内容を持つ[動的QRコード](/docs/dynamic-qr-codes)になります。

- 遷移先とタイトル
- タグ（任意）と、「Imported from Bitly」のようなフォルダ（名前の変更やオフへの切り替えも可能）
- `Imported from Bitly bit.ly/3AbCdEf on 2026-11-01.` のようなメモと、リンクの元の作成日。新しいコードの作成日にはQRdx自身の日付が設定されます。

プレビューには、作成されるコードの数、新規のタグ、スキップされるものが表示されます。

- **インポート済み：** 以前に（過去のどの実行でも）インポートしたリンクは常にスキップされるため、インポートを2回実行しても重複は作成されません。
- **同じ遷移先が存在：** 遷移先にすでにQRdxのコードがあるリンクは、デフォルトでスキップされます。それでもインポートするには、オプションにチェックを入れてください。
- **プランの上限超過：** プランのアクティブなコード数に収まらないリンクです。プレビューでは、収まる分の先頭からインポートするか、アップグレードするかを選べます。
- **インポート不可：** 遷移先がない、または無効なもの、およびすでにQRdxの短縮リンクを指しているリンクです。

インポートは50件ずつのバッチで、進行状況バーを表示しながら実行されます。ダイアログを閉じても問題ありません。インポート機能をもう一度開くと、**最近のインポート**からインポートが再開されます。サマリーには、作成、スキップ、失敗したコードが理由とともに一覧表示されます。

## 連携済みアカウントから [#from-a-connected-account]

1. プロバイダーを選びます。まだ連携していない場合は、その場で連携します（サインイン、またはAPIキーやトークンの貼り付け）。トークンは暗号化して保存され、[設定 → 連携](/settings/integrations)でいつでも連携を解除できます。
2. 検索し、ドメインやタグで絞り込んで、リンクを選択します。**条件に一致するすべてのリンクを選択**では、1回のインポートで最大1,000件まで取り込めます。残りは再度実行してください。
3. プレビューを確認して、**インポート**をクリックします。

| プロバイダー | 連携方法 | リンクの一覧表示 | 印刷済みコードを使い続ける |
| --- | --- | --- | --- |
| Bitly | サインイン、または汎用アクセストークン | 可 | Bitlyの有料プランのみ：月あたりのリンクリダイレクトは Core で5件、Growth で20件、Premium で110件 |
| Rebrandly | APIキー | 可 | Rebrandlyの月間の遷移先編集回数の範囲内：Essentials で10回、Professional で50回、Growth で150回（フリーはなし） |
| Short.io | APIキー | 可（1回につき1ドメイン） | 可（すべてのプラン） |

プランの制限は各プロバイダー独自のもので、時とともに変わります。料金ページをご確認ください。

## 印刷済みコードを使い続ける [#keep-printed-codes-working]

他のプロバイダーで印刷したQRコードには、そのプロバイダーの短縮リンクがエンコードされています。連携済みアカウントからのインポート後、サマリーに**印刷済みコードを使い続ける**が表示されます。

1. **ドライラン**で、古いリンクそれぞれと、その遷移先になるQRdxのリンクが一覧表示されます。この時点では何も変更されません。
2. 確定すると、QRdxが古いリンクそれぞれの遷移先を、新しいQRdxのコードに変更します。訪問者はこれまでと同じページにたどり着き、すべてのスキャンがQRdxのアナリティクスに表示されるようになります。ただし、先に旧プロバイダー側でもクリックとして記録されます。
3. **元に戻す**と、インポート時にQRdxが保存しておいた元の遷移先に戻ります。

プロバイダーが変更を拒否した場合（たとえば、Bitlyのプランでリンクリダイレクトの残りがない場合など）、QRdxは処理を停止して理由を表示し、残りのリンクは変更しません。遷移先にすでにQRdxのコードがあったためスキップされたリンクは、その既存のコードを指します。<IfAvailable feature="customDomains"> バックハーフが独自ドメインとともに移るリンク（後述）は変更されません。DNSを切り替えた後は、それらがQRdxのリンクになります。</IfAvailable>

<Callout type="warn" title="古いアカウントはまだ残しておく">
  確信が持てるまで、プロバイダーの連携は維持してください。元に戻す操作には連携が必要です。また、リンクのリダイレクトを続けるには、古いアカウントも有効なままにしておく必要があります。
</Callout>

## 元のバックハーフを維持する [#keep-the-original-back-halves]

Pro と Business では、インポートのプレビューで**元のバックハーフを維持**にチェックを入れます。QRdxで維持できる場合、各コードにランダムなものではなく元のバックハーフが設定されるため、`bit.ly/spring-menu` は `qrdx.dev/q/spring-menu` になります。

- バックハーフが維持されるのは、3〜64文字の英字・数字・`-`・`_`で構成され、`-` で始まったり終わったりせず（[カスタムバックハーフ](/docs/dynamic-qr-codes#custom-back-halves)を参照）、予約されておらず、`qrdx.dev` 上でQRdxのどのコードにもまだ使われていない場合です<IfAvailable feature="customDomains">（独自ドメインでは、そこにある自分のコードにのみ使われていないこと）</IfAvailable>。
- それ以外の場合、コードには自動生成されたバックハーフが設定され、プレビューに変更内容が理由とともに表示されます。例：`spring-menu → Ab3xK9q · Another QRdx code already uses this back-half on qrdx.dev`。インポートでは、プレビューに表示されたとおりのバックハーフが使われます。
- バックハーフは、BitlyやShort.ioと同様に大文字と小文字が区別されます。

維持できなかったバックハーフには生成されたものが設定されます。そのリンクは、刷り直すか、旧プロバイダー側でリダイレクトを設定する必要があります。

<IfAvailable feature="customDomains" id="your-own-domain-go-yourbrand-com" title="独自ドメイン（go.yourbrand.com）">

リンクに独自ドメインを使っている場合は、そのドメインをQRdxに移してバックハーフを維持できます。これにより、DNSを切り替えた後も `go.yourbrand.com/spring-menu` が引き続き動作します。

1. まず、**設定** → **ドメイン**でドメインを追加します。この時点では未認証のままで構いません。その場合、バックハーフはドメイン自体で維持され、自分のコード間でのみ一意であればよく、予約されているのはいくつかの技術的な単語だけです。
2. インポートのプレビューで**元のバックハーフを維持**にチェックを入れ、**リンクの設置先**でドメインを選びます。プレビューに、維持されるバックハーフが表示されます。
3. インポートします。コードはそのドメイン上に作成され、バックハーフもすぐに確保されます。
4. ドメインのDNSをQRdxに向けて、認証します（[カスタムドメイン](/docs/custom-domains)を参照）。この作業は利用の少ない時間帯に行ってください。DNSが切り替わった時点でそのドメイン上のリンクは旧プロバイダーでは動作しなくなり、認証が完了するとQRdxで動作し始めます。

インポート時にドメインがまだQRdxにない場合、そのバックハーフは代わりに `qrdx.dev` 上で維持されます（QRdx全体で未使用である必要があります）。ドメインを追加して認証した後、インポートのサマリーで**コードを割り当てる**をクリックすると、それらのコードをドメインに移せます。

</IfAvailable>

## エクスポートファイルから移行する [#from-an-export-file]

1. ファイルを取得します（手順は以下を参照）。QRdx は 1 回の実行で最大 2 MB、1,000 行までの CSV を読み込めます。Excel ファイルの場合は、先に CSV として保存またはダウンロードしてください。
2. インポーターでプロバイダーを選び、ファイルをアップロードします。QRdx は可能な範囲でプロバイダーの列を自動的に認識し、マッピングは変更できます。必須なのは遷移先のみです。以前の短縮リンク（またはコード ID）があれば、再アップロード時にインポート済みのコードをスキップできます。
3. プレビューしてインポートし、**Copy all new links** または **Download mapping CSV**（以前のリンク → 新しい QRdx リンク）を使います。

QRdx では、プロバイダー自身のドメイン上にあるコードは変更できません。印刷済みのコードを使い続けるには、以前のプロバイダーで動的QRコードを 1 つずつ開き、遷移先をマッピングにある新しい QRdx リンクに設定してください。これらのコードがリダイレクトされ続けるには、以前のアカウントを有効にしておく必要があります。解約する前に、QRdx のコードで再印刷してください。<IfAvailable feature="customDomains"> ご自身が所有するドメイン上のコードは、再印刷なしでドメインごと移行できます。上記の [ご自身のドメイン](#your-own-domain-go-yourbrand-com) を参照してください。</IfAvailable>

### QR Code Generator PRO [#qr-code-generator-pro]

コード一覧の公式なエクスポート機能は用意されていません。各コードの **Name**、**Short URL**、**Destination URL** をまとめたスプレッドシートを作成してください。コードの遷移先を付け替えるには、コードを開き、**Details** → **Edit** の順に進んで URL を置き換え、保存します。コードが多い場合は、一括更新で新しい URL の CSV を使って最大 500 件のコードを更新できます。

### Uniqode (Beaconstac) [#uniqode-beaconstac]

**QR Codes → Dynamic** を開き、すべて選択して **⋯ → Export** を選びます。エクスポートは組織ごとまたはフォルダーごとに行います。エクスポートの列（QR Code Name、QR Code URL、Destination URL、Labels など）は認識されます。遷移先を付け替えるには、コードを開き、**Edit** → 新しい URL → **Next** → **Save** の順に操作します。

### Flowcode [#flowcode]

Flowcode がエクスポートできるのはフォルダー内のコードだけなので、先にコードをフォルダーへ移動してください。次に **Folder** セクションを開き、フォルダーにチェックを入れて **Download URLs** をクリックします。CSV の列（Flowcode Name、Short Links、Scan Destination）に加え、一括作成シートの列（Flowcode Name、Flowcode Scan URL）も認識されます。遷移先を付け替えるには、**Assets** → 対象のコード → **Overview** → **Destination** → **Save** の順に操作します。

### QR TIGER [#qr-tiger]

**My Account** → カテゴリ（例: URL）を選択 → **Download QR List** の順に進みます。この操作はカテゴリごとに 1 回ずつ行います。遷移先を付け替えるには、**My Account → Dashboard → URL** → 対象のキャンペーン → **Edit** → **Save** の順に操作します。

### ME-QR [#me-qr]

エクスポート機能はありません。各コードの Name、QR リンク、Destination URL を一覧にしてください。遷移先を付け替えるには、ME-QR のコード一覧でコードを編集します。

### TinyURL [#tinyurl]

TinyURL では、CSV エクスポートは有料プランの機能として案内されています。リンクを CSV でエクスポートするか、Alias と Long URL を一覧にしてください。TinyURL の遷移先を編集するには、TinyURL の有料プランが必要です。

### Hovercode、Scanova、その他 [#hovercode-scanova-and-others]

プロバイダーからコードを CSV でエクスポートし（Hovercode では CSV エクスポートが Business プランの機能として案内されており、Scanova ではダウンロードリンクがメールで届きます）、列のマッピングを確認してください。遷移先の列がある CSV であれば、**Another provider (CSV)** で利用できます。

静的QRコード（goQR.me、QR Code Monkey、Adobe Express などのツールで作成したもの）は遷移先そのものをエンコードしているため、ツールがなくても使い続けられます。新しく印刷するコードを編集可能でトラッキングできるものにしたい場合に限り、CSV から遷移先をインポートしてください。

## QRコードライブラリから移行する [#from-a-qr-code-library]

ライブラリが生成するのは静的コードのため、移行が必要なものはありません。印刷済みのコードはそのまま使えます。アプリ内の描画を切り替えるには、`qrdx` をインストールしてコンポーネントを置き換えます。

### qrcode.react から [#from-qrcode-react]

```tsx title="Before and after"
// Before
import { QRCodeSVG } from "qrcode.react";

<QRCodeSVG value="https://example.com" size={256} fgColor="#111827" />;

// After
import { QRCodeSVG } from "qrdx";

<QRCodeSVG
  value="https://example.com"
  size={256}
  fgColor="#111827"
  bodyPattern="rounded"
/>;
```

`value`、`size`、`level`、`fgColor`、`bgColor`、`marginSize`（`margin` として）、`imageSettings` は、そのまま引き継げます。qrdx ではさらに、パターン、グラデーション、テンプレートが使えます。[API リファレンス](/docs/api-reference)を参照してください。

### qr-code-styling から [#from-qr-code-styling]

```tsx title="Before and after"
// Before
import QRCodeStyling from "qr-code-styling";

const qr = new QRCodeStyling({
  data: "https://example.com",
  width: 256,
  dotsOptions: { type: "rounded", color: "#111827" },
  image: "/logo.png",
});
qr.append(ref.current);

// After
import { QRCodeSVG } from "qrdx";

<QRCodeSVG
  value="https://example.com"
  size={256}
  bodyPattern="rounded"
  fgColor="#111827"
  imageSettings={{ src: "/logo.png", width: 64, height: 64, excavate: true }}
/>;
```

qrdx は React コンポーネントのため、インスタンスを追加する必要はありません。ほかの要素と同じようにレンダリングします。ダウンロードには、[API リファレンス](/docs/api-reference)にあるヘルパーを使います。

## 開発者向け [#for-developers]

スクリプトでコードを移行する場合は、[コード API](/docs/developers/api/create-codes) でコードを作成します。Pro と Business では 1 リクエストあたり最大 {facts.apiBatchCodes} 件まで作成できます。残したい後半部分には `slug` を指定し、再試行してもバッチが重複しないように `Idempotency-Key` を付けてください。
