기본적으로 [동적 QR 코드](/docs/dynamic-qr-codes)는 `https://qrdx.dev/q/aB3dE5f` 같은 짧은 링크를 인코딩합니다. 사용자 지정 도메인을 쓰면 대신 `https://go.yourbrand.com/aB3dE5f`를 인코딩하므로, 사람들이 스캔하기 전에 브랜드를 먼저 볼 수 있습니다. 리디렉션, 편집, 스캔 분석은 동일하게 작동합니다. 링크 자체가 인쇄되는 경우나 포장에 브랜드 이름만 보여야 하는 경우에 사용하세요.

<Callout type="info" title="Pro와 Business">
  사용자 지정 도메인은 Pro(워크스페이스당 최대 5개)와 Business(최대 25개)에 포함됩니다. [요금제와 한도](/docs/plans-and-limits)를 참고하세요.
</Callout>

서두르고 계신가요? 간단한 작업 안내 페이지가 있습니다: [내 도메인 사용하기](/docs/help/domains/custom-domains).

## 작동 방식 [#how-it-works]

<Diagram id="custom-domain" />

DNS 레코드로 도메인(보통 `go.yourbrand.com` 같은 서브도메인)을 QRdx에 연결하고 소유권을 증명합니다. 그 후 QRdx는 해당 호스트 이름으로 들어오는 요청에 워크스페이스의 코드와 페이지만 응답하며, 다른 것은 제공하지 않습니다. 도메인은 추가한 워크스페이스에 속합니다. 도메인의 추가, 확인, 제거는 소유자와 관리자가 하고, 모든 멤버는 자신의 코드에 이 도메인을 사용할 수 있습니다.

## 도메인 연결하기 [#connect-a-domain]

1. 워크스페이스에서 **Settings** → **Domains**를 열고 `go.yourbrand.com` 같은 도메인을 입력하세요. 기존 웹사이트를 그대로 유지할 수 있으므로 서브도메인이 가장 좋습니다.
2. DNS 제공업체(도메인을 구입한 곳, Cloudflare 등 DNS가 있는 곳)에서 도메인에 표시된 DNS 레코드를 추가하세요.
   - 서브도메인에는 `CNAME` 레코드를 추가합니다.
   - 루트 도메인(`yourbrand.com`)에는 `A` 레코드를 추가합니다.
   - 소유권 확인이 필요하면 `TXT` 레코드도 표시됩니다.

   정확한 값은 대시보드에서 복사하세요. 대부분의 제공업체는 이름에 도메인 앞부분만(`go`, 루트는 `@`) 입력하도록 합니다.
3. **Verify**를 클릭하세요. DNS 변경은 보통 몇 분 안에 반영되지만 최대 48시간이 걸릴 수 있으니, 레코드가 아직 발견되지 않으면 나중에 다시 시도하세요.

<Shot id="custom-domains" />

확인이 끝나면 동적 코드를 만들거나 편집할 때 **Short link domain** 선택기에 도메인이 나타납니다. 확인된 도메인은 제거하기 전까지 확인된 상태로 유지되며, **Check DNS**로 언제든 레코드를 다시 읽을 수 있습니다.

<Callout type="info">
  3일 안에 확인되지 않은 도메인은 다른 계정이 추가할 수 있으므로, 직접 관리하지 않는 도메인을 계속 선점할 수 없습니다.
</Callout>

<IfAvailable feature="domainConnect" id="one-click-dns-setup" title="원클릭 DNS 설정">

일부 DNS 제공업체는 서비스가 대신 레코드를 추가할 수 있게 해 주는 개방형 표준인 [Domain Connect](https://www.domainconnect.org)를 지원합니다. 제공업체가 이를 지원하고 QRdx 설정을 제공하면, DNS를 기다리는 도메인에 제공업체 이름이 들어간 **Set up with …** 버튼이 표시됩니다.

1. 버튼을 클릭하세요. DNS 제공업체가 열리고 QRdx에 필요한 레코드가 나열됩니다.
2. 요청되면 로그인하고 변경을 승인하세요. 승인하기 전에는 아무것도 바뀌지 않습니다.
3. Domains 페이지로 돌아오면 바로 DNS를 확인하고, 이후 30초 정도 동안 다시 확인합니다.

이 버튼은 `go.yourbrand.com` 같은 서브도메인에만 표시되며, 제공업체가 표시된 레코드를 정확히 추가할 수 있을 때만 나타납니다. 그렇지 않으면 위에서 설명한 대로 표의 레코드를 직접 추가하세요.

</IfAvailable>

## 코드에 사용하기 [#use-it-for-codes]

- **새 코드:** 코드를 만들기 전에 **Short link domain**에서 도메인을 선택하세요.
- **기존 코드:** **Edit link**에서 도메인을 선택하고 저장한 다음, 인코딩된 링크가 바뀌므로 QR 코드를 다시 다운로드하세요.

<Shot id="short-link-domain-picker" />

모든 코드는 기본 링크 `https://qrdx.dev/q/<slug>`에서도 계속 작동하므로, 코드를 내 도메인으로 옮기기 전에 인쇄한 QR 코드는 깨지지 않습니다. 코드를 한 사용자 지정 도메인에서 다른 도메인으로(또는 기본 링크로) 옮기면 이전 사용자 지정 도메인 링크로 인쇄한 QR 코드는 작동하지 않게 됩니다. 저장하기 전에 대화상자에서 경고가 표시됩니다.

### 나만의 back-half [#your-own-back-halves]

Pro와 Business에서는 `go.yourbrand.com/spring-menu`처럼 내 도메인에서 코드의 [back-half](/docs/dynamic-qr-codes#custom-back-halves)를 직접 정할 수 있습니다. 해당 도메인 안에서만 고유하면 되므로 다른 QRdx 고객이 `spring-menu`를 쓰고 있어도 상관없고, 몇 가지 기술 용어(`api`, `_next`, `null`, `undefined`)만 예약되어 있습니다. 내 도메인에서 정한 back-half는 그 도메인에 속하며 `qrdx.dev/q/` 링크가 없습니다. 이런 코드를 다른 도메인으로 옮기면 그곳에서 사용 가능할 때 back-half가 유지됩니다. 기본 링크로 되돌릴 때는 `qrdx.dev`에서 사용 가능하면 유지되고, 아니면 새로 생성된 back-half가 부여됩니다.

## 도메인이 제공하는 것 [#what-the-domain-serves]

- `https://go.yourbrand.com/<slug>`는 해당 도메인을 사용하는 코드를 리디렉션합니다. 다른 도메인이나 기본 링크만 사용하는 코드는 여기서 "not found" 페이지가 표시됩니다.
- `https://go.yourbrand.com/p/<slug>`는 양식, 캘린더 파일, **Save contact** 다운로드가 포함된 [호스팅 페이지](/docs/landing-pages)를 제공합니다.
- `https://go.yourbrand.com/01/<GTIN>`([GS1 Digital Link](/docs/product-pages#gs1-digital-link))은 해당 GTIN의 제품 페이지 중 코드가 이 도메인을 사용하는 페이지를 엽니다.
- Business에서는 `https://go.yourbrand.com/stats/<token>`이 도메인에 지정한 [클라이언트 보고서](/docs/client-reports)를 제공합니다.
- `https://go.yourbrand.com/`에는 이 도메인이 QR 코드 링크를 호스팅한다는 간단한 페이지가 표시됩니다. 그 밖의 모든 경로는 "not found"를 반환합니다. 도메인은 대시보드, 에디터 등 QRdx의 다른 부분을 제공하지 않습니다.

아직 확인되지 않은 도메인에는 대신 "This domain isn't connected yet"가 표시됩니다. 변경 사항(새로 확인되거나 제거된 도메인)이 모든 서버에 반영되는 데 최대 1분이 걸립니다.

## 한도와 요금제 [#limits-and-plans]

| | 무료 | Pro | Business |
| --- | --- | --- | --- |
| 워크스페이스당 사용자 지정 도메인 | 없음 | 5 | 25 |
| 내 도메인의 클라이언트 보고서 | 아니요 | 아니요 | 예 |

요금제를 낮춰도 아무것도 깨지지 않습니다. 확인된 도메인은 계속 해당 코드를 제공합니다. Pro나 Business가 없으면 도메인을 추가하거나 확인할 수 없고 더 많은 코드를 도메인으로 옮길 수도 없지만, 해당 코드를 편집하고 도메인을 제거할 수는 있습니다.

도메인을 제거하면 그 코드는 기본 링크 `qrdx.dev/q/<slug>`로 되돌아갑니다. 도메인에서 정한 back-half는 `qrdx.dev`에서 사용 가능하면 그곳으로 옮겨지고, 나머지는 새로 생성된 back-half를 받습니다. 사용자 지정 도메인 링크로 인쇄한 QR 코드는 작동하지 않게 되므로, 대화상자에 먼저 해당 도메인을 사용하는 코드 수가 표시됩니다.

## 개발자용 [#for-developers]

[코드 API](/docs/developers/api/create-codes)는 `POST /v1/codes`와 `PATCH /v1/codes/{id}`에서 `domainId`(같은 워크스페이스에서 확인된 도메인의 id)를 받습니다. `PATCH`에서 `"domainId": null`을 보내면 기본 링크로 되돌아갑니다. 코드를 도메인으로 옮기려면 Pro나 Business가 필요하며, 그렇지 않으면 `402 PLAN_REQUIRED`를 반환합니다.

응답의 각 코드에는 다음이 포함됩니다.

| 필드 | 설명 |
| --- | --- |
| `shortLink` | 인코딩할 링크: 확인된 후에는 사용자 지정 도메인의 링크 |
| `defaultShortLink` | 항상 작동하는 `https://qrdx.dev/q/<slug>`. 사용자 지정 도메인에서 정한 back-half에는 `null` |
| `domain` | `{ "id", "hostname", "verified" }` 또는 `null` |

## 셀프 호스팅 [#self-hosting]

도메인 연결 방식은 배포 환경에 따라 다릅니다.

- **Vercel에서:** `VERCEL_API_TOKEN`(프로젝트에 접근할 수 있는 토큰), `VERCEL_PROJECT_ID`, 팀 프로젝트라면 `VERCEL_TEAM_ID`를 설정하세요. 그러면 Vercel Domains API를 통해 프로젝트에 도메인이 추가되고 TLS 인증서도 발급됩니다. 이 변수가 없으면 Vercel은 프로젝트에 추가된 도메인만 라우팅하므로, Domains 페이지에 사용자 지정 도메인이 설정되지 않았다는 안내가 표시됩니다.
- **그 외 환경**(Docker, Node.js): 이 변수들을 설정하지 마세요. 도메인은 수동으로 확인합니다.
  1. `CNAME`(앱의 호스트 이름으로) 또는 `A` 레코드(서버의 IP)로 도메인을 서버에 연결하세요.
  2. 리버스 프록시가 해당 도메인을 받아들이고, 이 도메인에 HTTPS를 제공하며(예: Caddy의 on-demand TLS나 certbot 인증서), 원래 `Host` 헤더를 앱에 전달하도록 설정하세요. nginx에서는 `proxy_set_header Host $host;`이며, Caddy는 기본적으로 그렇게 합니다.
  3. Domains 페이지에서 도메인을 추가하고, 표시된 `TXT` 레코드(`_qrdx-challenge.<your-domain>`, 값은 `qrdx-verify=<token>`)를 만든 다음 **Verify**를 클릭하세요. 앱은 DNS 조회로 레코드를 확인합니다.

**원클릭 DNS 설정**(선택 사항)은 [Domain Connect](https://www.domainconnect.org)를 사용합니다. 지원하려는 각 DNS 제공업체가 승인한 자체 템플릿과 설정 링크에 서명하는 RSA 키가 필요합니다. `DOMAIN_CONNECT_PROVIDER_ID`, `DOMAIN_CONNECT_SERVICE_ID`, `DOMAIN_CONNECT_PRIVATE_KEY`(PEM)를 설정하고, 공개 키를 `_dck1.<provider id>`의 `TXT` 레코드로 게시하세요. QRdx의 자체 템플릿(저장소의 `domain-connect/`)은 제공업체가 서명을 QRdx의 키와 대조해 확인하므로 qrdx.dev에서만 작동합니다. 게시된 키가 일치하기 전까지는 버튼이 표시되지 않으며, 앱이 그 이유를 로그에 남깁니다.

앱은 `Host` 헤더로 사용자 지정 도메인을 인식합니다. 앱 자체 URL, `NEXT_PUBLIC_SHORT_LINK_BASE_URL`, `localhost`, `*.vercel.app`으로 들어오는 요청은 항상 메인 앱으로 처리됩니다. [셀프 호스팅](/docs/self-hosting#optional-services)을 참고하세요.
